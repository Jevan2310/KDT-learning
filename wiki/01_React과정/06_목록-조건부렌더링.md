# 06. 목록과 조건부 렌더링 — 데이터에 따라 화면 표시하기

> 과정: React과정 · [노션 원문](https://app.notion.com/p/40c848f71c9b80a08468d1e7919ede94) · 최종 갱신일: 2026-11-12

## 한눈에 보기
- 프로필을 카드마다 직접 쓰지 않고 **객체 배열**에 모은 뒤 `map()`으로 카드 목록을 만든다.
- 목록의 각 항목에는 고유한 `key`(데이터의 `id`)를 붙여 React가 항목을 구분하게 한다.
- `&&`로 "참일 때만 표시", 삼항 연산자로 "둘 중 하나 표시"를 한다.
- 배열이 비어 있으면 안내 문구를 보여주고, `filter()`로 조건에 맞는 프로필만 골라 표시한다.
- 앞 회차의 `ProfileCard`([05_컴포넌트-props](05_컴포넌트-props.md))를 그대로 이어서 쓴다.

## 학습 목표
- `map()`으로 배열을 화면 요소로 바꾼다.
- `key`로 목록의 각 항목을 구분한다.
- 조건에 따라 다른 내용을 표시한다.
- 데이터가 없을 때 안내 문구를 표시한다.
- `filter()`로 조건에 맞는 항목만 선택한다.

## 핵심 개념

### 1. 데이터를 배열로 관리하기
카드가 늘 때마다 `<ProfileCard name="..." />`를 계속 쓰는 대신, 데이터를 배열에 모으고 배열의 각 항목을 카드로 표시한다.

```text
프로필 데이터 배열 → map() → 프로필 카드 목록
```

객체는 관련 정보를 묶고, 배열은 여러 값을 순서대로 담는다 ([03_JavaScript](03_JavaScript.md)의 객체·배열). 객체 하나가 프로필 하나다.

```javascript
const profiles = [
  {
    id: 1,
    name: "한코딩",
    introduction: "직접 사용하는 서비스를 만듭니다.",
    imageUrl: "/profile.png",
    interest: "웹 서비스",
    isLearning: true
  },
  // ... 같은 모양의 객체가 이어진다
];
```

| 속성 | 의미 |
|---|---|
| `id` | 프로필을 구분할 고유 값 |
| `name` | 이름 |
| `introduction` | 소개 |
| `imageUrl` | 이미지 경로 |
| `interest` | 관심사 |
| `isLearning` | 학습 중인지 나타내는 불리언 |

배열 개수는 `{profiles.length}`로 화면에 바로 표시할 수 있다.

### 2. `map()` — 각 항목을 새 값으로 바꾸기
`map()`은 각 항목에 함수를 적용하고, **반환한 값들로 새 배열**을 만든다. 원본 배열은 바꾸지 않는다.

```javascript
const numbers = [1, 2, 3];

const doubleNumbers = numbers.map((number) => {
  return number * 2;
});
// [2, 4, 6]
```

- `numbers`: 순회할 배열
- `number`: 현재 처리하는 항목의 이름 (직접 정한 매개변수 이름)
- `return`: 새 배열에 넣을 값

간단한 표현식이면 줄여 쓸 수 있다 (화살표 함수 축약은 [03_JavaScript](03_JavaScript.md) 13장).

```javascript
const doubledNumbers = numbers.map((number) => number * 2);
```

숫자를 문장(문자열)으로 바꿀 수도 있다 (템플릿 리터럴은 [03_JavaScript](03_JavaScript.md) 5장). 강의에서는 `App` 안에서 `console.log(doubleNumbers);`, `console.log(numberAndWords);`로 Console에 찍어 확인했다.

```javascript
const numberAndWords = numbers.map((n) => {
  return `제가 꺼낸 숫자는 ${n}입니다.`;
})
```

> 💡 보충: 결과는 `["제가 꺼낸 숫자는 1입니다.", "제가 꺼낸 숫자는 2입니다.", "제가 꺼낸 숫자는 3입니다."]`.

**JSX도 반환할 수 있다.** React는 JSX 요소의 배열을 목록으로 표시한다.

```jsx
const nameItems = profiles.map((profile) => {
  return <li key={profile.id}>{profile.name}</li>;
});

// return 안에서
<ul>
  {nameItems}
</ul>
```

### 3. 괄호 `( )`와 중괄호 `{ }` 구분하기

```jsx
// 소괄호: JSX를 바로 반환한다
profiles.map((profile) => (
  <ProfileCard key={profile.id} name={profile.name} />
));
```

```jsx
// 중괄호: 함수 본문이므로 return이 필요하다
profiles.map((profile) => {
  return (
    <ProfileCard key={profile.id} name={profile.name} />
  );
});
```

```jsx
// 잘못된 예: 카드가 반환되지 않습니다.
profiles.map((profile) => {
  <ProfileCard key={profile.id} name={profile.name} />;
});
```

### 4. `key` — 목록 항목의 정체성
목록에는 추가·삭제·순서 변경이 생길 수 있다. React는 `key`로 이전 목록과 다음 목록에서 **어떤 항목이 같은 항목인지 구분**한다.

```jsx
<ProfileCard key={profile.id} />
```

key의 기본 원칙:
- 같은 목록 안에서 **고유**해야 한다.
- 같은 항목이면 렌더링 사이에도 **유지**되어야 한다.
- `map()`이 직접 반환하는 **가장 바깥 요소**에 쓴다.

피해야 할 방식:
- `key={Math.random()}` — 렌더링마다 값이 달라져 항목을 안정적으로 구분할 수 없다.
- 배열 인덱스 — 추가·삭제·정렬이 있는 목록에서는 문제가 생길 수 있다. 이번 실습은 데이터의 고유 `id`를 쓴다.

**key는 일반 props가 아니다.** React가 목록 관리에만 쓰고 자식 컴포넌트에 전달하지 않는다. 자식에서도 ID가 필요하면 따로 넘긴다.

```jsx
<ProfileCard
  key={profile.id}
  id={profile.id}
  name={profile.name}
/>
```

### 5. 조건부 렌더링
데이터에 따라 화면 일부를 표시하거나 다른 문구를 보여주는 것. 예: 학습 중이면 배지 표시, 아니면 다른 문구, 프로필이 없으면 안내.

| 표현 | 사용 상황 |
|---|---|
| `조건 && JSX` | 참일 때만 표시 |
| `조건 ? A : B` | 두 결과 중 하나 표시 |

**`&&` — 참일 때만 표시**

```jsx
{isLearning && <span>학습 중</span>}
```

`isLearning`이 `true`면 배지를 표시하고, `false`면 그 자리에 아무것도 표시하지 않는다.

숫자를 `&&` 왼쪽에 그대로 두면 `0`이 화면에 표시될 수 있다. 비교식으로 쓴다.

```jsx
// profiles.length가 0이면 화면에 0이 표시될 수 있습니다.
{profiles.length && <p>프로필이 있습니다.</p>}

// 의도가 명확한 방식
{profiles.length > 0 && <p>프로필이 있습니다.</p>}
```

> 💡 보충: `A && B`는 A가 거짓 같은 값이면 **A 자체**를 돌려준다. React는 `false`·`null`·`undefined`는 그리지 않지만 숫자 `0`은 그대로 그리기 때문에 `0`이 화면에 나온다.

**삼항 연산자 — 둘 중 하나 표시**

```javascript
조건 ? 참일 때의 값 : 거짓일 때의 값
```

강의 화면에서는 브라우저 개발자 도구 Console에서 먼저 확인했다.

```text
> console.log(true? '사실입니다.' : '거짓입니다.');
사실입니다.
> console.log(false? '사실입니다.' : '거짓입니다.');
거짓입니다.
```

```jsx
<span className="status-badge">
{isLearning? "학습 중..." : "학습 예정"}
</span>
```

### 6. 빈 목록 안내
배열이 비어 있으면 카드가 하나도 안 보여서, 데이터가 없는 건지 화면이 고장 난 건지 알기 어렵다. 빈 목록에는 안내 문구를 보여준다.

```jsx
{profiles.length === 0 ? (
  <p>아직 등록된 프로필이 존재하지 않습니다.</p>
) : (
  <div className="profile-list">
    {profiles.map((profile) => (
      <ProfileCard key={profile.id} name={profile.name} />
    ))}
  </div>
)}
```

### 7. `filter()` — 조건에 맞는 항목만 고르기
`filter()`는 함수가 참으로 평가되는 값을 반환한 항목만 모아 **새 배열**을 만든다.

```javascript
const numbers = [1, 2, 3, 4];

const largeNumbers = numbers.filter((number) => number >= 3);

console.log(largeNumbers); // [3, 4]
```

학습 중인 프로필:

```javascript
const learningProfiles = profiles.filter(
  (profile) => profile.isLearning
);
```

학습 예정인 프로필 (두 방식 중 하나를 쓴다):

```javascript
// 이 방식도 실행에는 문제가 없다.
const waitingProfiles = profiles.filter(
  (profile) => profile.isLearning === false
);

// 좀 더 간결하게 적고 싶다면 !를 이용하자 (not 연산자)
const waitingProfiles = profiles.filter(
  (profile) => !profile.isLearning
);
```

관심사로 고르기:

```javascript
const webProfiles = profiles.filter((profile) => profile.interest === '웹 서비스')
```

| 메서드 | 역할 |
|---|---|
| `map()` | 각 항목을 다른 값으로 변환 |
| `filter()` | 조건에 맞는 항목 선택 |

둘 다 새 배열을 반환하고, 이 예제에서는 원본 배열을 바꾸지 않는다.

**목록 개수·빈 목록 조건·실제 카드가 모두 같은 배열(예: `learningProfiles`)을 기준으로 해야 한다.**

## 실습 정리

### 만든 것
프로필 데이터를 배열로 옮기고, 학습 중인 프로필만 카드로 보여주는 목록 화면. 카드에는 학습 중 배지와 상태 문구가 조건에 따라 나온다.

### 단계 흐름
1. `App` 안의 `profile` 객체 하나를 `profiles` 배열로 교체하고 `{profiles.length}`로 개수 표시.
2. `map()`으로 이름을 `<li>` 목록으로 표시 → 이어서 `ProfileCard` 목록으로 표시 (`key={profile.id}`).
3. `isLearning`을 props로 넘기고, `ProfileCard`에서 `&&`로 "학습 중" 배지 표시 (`.status-badge` CSS 추가).
4. 삼항 연산자로 학습 중/학습 예정 문구 표시.
5. `profiles.length === 0 ? 안내 : 목록`으로 빈 목록 안내.
6. `filter()`로 `learningProfiles`를 만들고, 개수·빈 목록 조건·카드 목록을 모두 이 배열로 바꿈.

> 💡 보충: 강의 4장 중간 코드에는 `name={profile.id}`로 적혀 있어 이름 대신 숫자 id가 보인다. 뒤의 코드처럼 `name={profile.name}`이 맞다.

### 수업 중 강사 화면 코드

강사 화면에서는 `profiles` 배열을 `App` 함수 밖(파일 맨 위)에 두고, `App`을 화살표 함수(`const App = () => { ... }`)로 썼다.

`src/components/ProfileCard.jsx`

```jsx
// 컴포넌트
const ProfileCard = (props) => {
  return (
    <div>
      <h1>내 이름은 {props.name}입니다.</h1>
      <p>내 취미는 {props.hobby}입니다.</p>
    </div>
  )
}

export function MyHobby() {
    return <div>취미 수정 후 컴포넌트입니다.</div>
```

같은 화면을 변수 없이 JSX 안에서 바로 `map()`으로 만들 수도 있다 (`App`의 `return` 부분).

```jsx
  return (
    <>
      {profiles.map((profile) => {
        return <ProfileCard name={profile.name} hobby={profile.interest} />
      })}
    </>
  )
```

- `map()` 결과를 변수(`names`, `nameComponent`)에 담아 `{names}`처럼 넣어도 되고, JSX 안에 `{profiles.map(...)}`을 바로 써도 된다.

> 💡 보충: 이 코드는 `<li>`와 `<ProfileCard>`에 `key`가 없어서 Console에 key 경고가 뜬다. `key={profile.id}`를 붙인다.

> 💡 보충: `export function MyHobby`, `export const MyMovie`는 이름을 붙여 내보내는 방식이라 `import { MyHobby, MyMovie } from ...`처럼 **중괄호 안에 같은 이름**으로 가져온다. `export default`(파일에 하나)는 중괄호 없이 원하는 이름으로 가져온다. 이 코드에서 `useState`·`MyHobby`·`MyMovie`는 가져오기만 하고 쓰지 않았다(실행에는 영향 없음).

- `const profiles = [];`로 비워 안내 문구가 나오는지 확인하고 복원한다.
- 학습 예정인 프로필만, 관심사가 "웹 서비스"인 프로필만 골라 표시해본다.
- 모든 프로필의 `isLearning`을 `false`로 바꿔 "학습 중인 프로필이 없습니다." 안내를 확인한다.
- 지금은 코드의 데이터를 고치고 저장해서 결과를 본다. 버튼으로 필터를 바꾸는 기능은 [07_이벤트-state](07_이벤트-state.md)에서 만든다.

## 헷갈리기 쉬운 점
- `map((p) => { <Card /> })`처럼 중괄호를 쓰고 `return`을 빼면 아무것도 표시되지 않는다.
- `key`는 `map()`이 반환하는 가장 바깥 요소에 붙인다. 자식에서 `props.key`로 읽을 수 없으니 필요하면 `id`를 따로 넘긴다.
- `&&` 왼쪽에 숫자(`profiles.length`)를 그대로 두면 `0`이 표시될 수 있다 → `> 0` 비교식으로 쓴다.
- 불리언 `false`와 문자열 `"false"`는 다르다. 비어 있지 않은 문자열 `"false"`는 조건식에서 참이라 배지가 계속 보인다. 상태 데이터에는 불리언을 쓴다.
  ```javascript
  isLearning: false   // 불리언
  isLearning: "false" // 문자열
  ```
- 필터한 배열로 바꿀 때 개수·빈 목록 조건·카드 목록 중 하나만 `profiles`로 남아 있으면 서로 안 맞는다.

오류가 나면 확인할 것:

| 증상 | 확인할 내용 |
|---|---|
| 목록이 표시되지 않음 | 배열 내용, `map()`의 반환값 |
| 항목이 `undefined`로 처리됨 | 속성 이름과 데이터 구조 |
| key 관련 경고 | `map()`이 반환하는 최상위 요소에 고유 `key`가 있는지 |
| 일부 카드만 표시됨 | `filter()` 조건과 데이터 |
| 배지가 모두 표시됨 | `true` 대신 문자열 `"false"`를 전달하지 않았는지 |
| 빈 목록인데 안내가 없음 | 조건에서 실제 표시할 배열을 확인하는지 |

## 빠른 참고 (치트시트)

| 하고 싶은 것 | 쓰는 것 | 예시 |
|---|---|---|
| 배열을 카드 목록으로 | `map()` | `{list.map((item) => <Card key={item.id} name={item.name} />)}` |
| 목록 항목 구분 | `key` (고유 id) | `key={profile.id}` |
| 참일 때만 표시 | `조건 && JSX` | `{isLearning && <span>학습 중</span>}` |
| 둘 중 하나 표시 | `조건 ? A : B` | `{isLearning ? "학습 중..." : "학습 예정"}` |
| 숫자 조건으로 표시 | 비교식 + `&&` | `{list.length > 0 && <p>있음</p>}` |
| 빈 목록 안내 | `length === 0` + 삼항 | `{list.length === 0 ? <p>없음</p> : <div>...</div>}` |
| 조건에 맞는 항목만 | `filter()` | `profiles.filter((p) => p.isLearning)` |

| 개수 표시 | `.length` | `{learningProfiles.length}개` |
| 이름 붙여 내보낸 컴포넌트 가져오기 | `import { }` | `import { MyHobby, MyMovie } from './components/ProfileCard'` |

## 확인 문제
이 강의에는 💬 확인하기가 없어서, 강의 본문의 질문과 "오류가 발생하면 확인하기" 표에서 문제를 뽑았다.

<details><summary>Q. <code>map()</code>은 무엇을 반환하나요? 원본 배열은 바뀌나요?</summary>

각 항목에 함수를 적용해 **반환한 값들로 만든 새 배열**을 반환한다. 원본 배열은 바꾸지 않는다.
</details>

<details><summary>Q. <code>profiles.map((profile) =&gt; { &lt;ProfileCard key={profile.id} /&gt;; })</code>로 썼더니 카드가 하나도 표시되지 않습니다. 이유는?</summary>

중괄호 `{ }`로 함수 본문을 만들었는데 `return`이 없어서 아무것도 반환하지 않는다. `return (...)`을 넣거나, 중괄호 대신 소괄호 `( )`로 JSX를 바로 반환한다.
</details>

<details><summary>Q. 목록에 <code>key</code>가 왜 필요한가요?</summary>

목록에는 추가·삭제·순서 변경이 생길 수 있다. React는 `key`로 이전 목록과 다음 목록에서 어떤 항목이 같은 항목인지 구분한다. 같은 목록 안에서 고유하고, 렌더링 사이에도 유지되는 값(데이터의 `id`)을 쓴다.
</details>

<details><summary>Q. <code>key={Math.random()}</code>를 쓰면 안 되는 이유는? 인덱스는?</summary>

`Math.random()`은 렌더링마다 값이 달라져 같은 항목을 안정적으로 구분할 수 없다. 인덱스는 추가·삭제·정렬이 있는 목록에서 문제가 생길 수 있어서, 이번 실습은 데이터의 고유 ID를 쓴다.
</details>

<details><summary>Q. 자식 컴포넌트 <code>ProfileCard</code>에서 <code>key</code> 값을 props로 읽을 수 있나요?</summary>

없다. `key`는 React가 목록 관리에만 쓰고 일반 props로 전달하지 않는다. 자식에서도 ID가 필요하면 `id={profile.id}`처럼 따로 넘긴다.
</details>

<details><summary>Q. <code>{profiles.length && &lt;p&gt;프로필이 있습니다.&lt;/p&gt;}</code>의 문제점과 고치는 방법은?</summary>

`profiles.length`가 0이면 화면에 `0`이 표시될 수 있다. `{profiles.length > 0 && <p>...</p>}`처럼 비교식으로 쓴다.
</details>

<details><summary>Q. <code>&&</code>와 삼항 연산자는 각각 언제 쓰나요?</summary>

- `조건 && JSX`: 참일 때만 표시하고, 거짓이면 아무것도 표시하지 않을 때
- `조건 ? A : B`: 조건에 따라 두 결과 중 하나를 표시할 때
</details>

<details><summary>Q. 데이터에 <code>isLearning: "false"</code>를 넣었더니 모든 카드에 "학습 중" 배지가 나옵니다. 왜?</summary>

`"false"`는 문자열이다. 비어 있지 않은 문자열은 조건식에서 참으로 평가된다. 상태 데이터에는 불리언 `false`를 쓴다.
</details>

<details><summary>Q. 학습 예정인 프로필(<code>isLearning</code>이 false)만 고르는 <code>filter()</code>를 간결하게 쓰면?</summary>

```javascript
const waitingProfiles = profiles.filter(
  (profile) => !profile.isLearning
);
```
`profile.isLearning === false`로 써도 동작한다. `!`는 불리언을 반대로 바꾼다.
</details>

<details><summary>Q. 학습 중인 프로필이 하나도 없는데 "학습 중인 프로필이 없습니다." 안내가 나오지 않습니다. 무엇을 확인하나요?</summary>

빈 목록 조건이 실제로 표시하는 배열을 확인하는지 본다. 개수 표시·`length === 0` 조건·`map()`하는 배열이 모두 `learningProfiles`처럼 같은 배열이어야 한다. 조건만 `profiles.length`로 남아 있으면 안내가 나오지 않는다.
</details>

<details><summary>Q. 자식에서 props.key로 id를 찍었는데 왜 화면에 안 나와요? <sub>2026-11-12</sub></summary>

**A.** `key`는 React가 목록 항목을 구분하는 데만 쓰는 특별한 속성이라 자식 컴포넌트에 props로 전달되지 않는다. 그래서 `props.key`는 `undefined`이고 화면에 아무것도 안 찍힌다 (Console에 경고도 뜸). 자식에서 id가 필요하면 다른 이름으로 한 번 더 넘긴다.

```jsx
<FruitItem key={fruit.id} id={fruit.id} name={fruit.name} price={fruit.price} />
// 자식: {props.id}번
```

(2026-11-12 보강) 왜 빼는지: JSX가 객체로 바뀔 때 React가 `key`를 props에서 꺼내 요소 바깥(`element.key`)에 따로 둔다. `key`는 형제 항목끼리 구분하는 "이름표"라서 React가 쓰고, 자식은 몰라도 되기 때문이다. 결과적으로 자식이 받는 props는 `{ name, price }`뿐이다.

(2026-11-12 보강) `{props.id}번`처럼 `li` 안에 쓴 글자는 내가 쓴 **내용**일 뿐이고, `ul`의 점·`ol`의 번호 같은 **목록 표시**와는 상관없다. `ul` 안에 `1번`이라고 쓰면 `• 1번 사과`처럼 둘 다 나온다.

관련: 이 파일의 "4. `key` — 목록 항목의 정체성" 섹션
</details>


<details><summary>Q. map()으로 컴포넌트를 그렸는데 화면에 하나도 안 나와요 <sub>2026-11-12</sub></summary>

**A.** 화살표 함수에 `{ }` 중괄호를 쓰고 `return`을 빼먹으면 `map()`이 `undefined`만 모은 배열을 돌려준다. React는 `undefined`를 아무것도 그리지 않으므로 오류도 없이 빈 화면이 된다. `( )` 괄호로 바로 반환하거나 `return`을 쓴다. 함께 자주 나는 실수: 콜백 안에서 `movie.id` 대신 배열 이름 `movies.id`를 쓰기 (→ `undefined`), 자식에서 `function Card(title, year)`처럼 props를 구조 분해 없이 받기 (→ `{ title, year }`로 받아야 함).

```jsx
{movies.map((movie) => (
  <MovieCard key={movie.id} title={movie.title} year={movie.year} />
))}
```

(2026-11-13 보강) JSX가 아닌 **값 계산**에서도 똑같다. `items.map((item) => { item.price * item.count })`는 계산만 하고 돌려주지 않아서 `console.log`에 `[undefined, undefined, …]`가 찍힌다. 중괄호면 `return item.price * item.count;`, 소괄호 없이 한 줄이면 `(item) => item.price * item.count`. 컴포넌트를 화살표 함수 `() => { <>…</> }`로 쓰고 `return`을 빼도 같은 이유로 빈 화면이 된다.

(2026-11-13 보강) `filter()`도 같다. `members.filter((member) => { member.isLearning === false; })`는 `return`이 없어 매번 `undefined`(거짓)를 돌려주므로 **하나도 안 골라** `[]`가 된다. `map()`은 `[undefined, …]`, `filter()`는 `[]` — 둘 다 오류 없이 "없음"처럼 보인다.

관련: 이 파일의 map() 렌더링 섹션, [05_컴포넌트-props](05_컴포넌트-props.md)의 구조 분해
</details>

<details><summary>Q. map()은 그냥 계속 중괄호 + return으로 써도 돼요? <sub>2026-11-13 · 연습 중</sub></summary>

**A.** 된다. 화면 결과는 소괄호 모양과 똑같다. 중괄호가 꼭 필요한 때는 `return` 앞에 다른 줄(변수 만들기, `console.log`, 조건 처리)을 넣을 때다. 08 강의의 `prevTasks.map((task) => { … })`가 그런 경우다. 중괄호 모양의 함정은 두 가지다: `return`을 빼먹으면 아무것도 안 나오고, `return` **다음 줄**에서 JSX를 시작해도 아무것도 안 나온다 (`return (`처럼 같은 줄에서 시작).

```jsx
{todos.map((todo) => {
  return <li key={todo.id}>{todo.title}</li>;
})}

{todos.map((todo) => (
  <li key={todo.id}>{todo.title}</li>
))}
```

다만 강의 코드는 JSX 안의 map을 대부분 소괄호로 쓴다 (06 최종 코드, 07, 08). 쓸 때는 중괄호로 통일해도 되지만, `=> (`를 보면 "이 JSX를 바로 돌려준다"로 읽을 수 있어야 한다.

관련: 이 파일의 "3. 괄호 `( )`와 중괄호 `{ }` 구분하기" 섹션
</details>

<details><summary>Q. const bookCards = books.map(...)처럼 map 결과를 변수에 왜 담아요? 어디에 써요? <sub>2026-11-13 · 연습 중</sub></summary>

**A.** `map()`은 새 **배열**을 돌려주는 값이라서 다른 값처럼 변수에 담을 수 있다. 카드 배열을 미리 만들어 두고 JSX에는 `{bookCards}`만 넣으면, `return`에는 화면 뼈대만 남아 읽기 쉽다. JSX 안에 `{books.map(...)}`을 바로 쓰는 것과 화면 결과는 같다 (강의: `nameItems`, "변수에 담아 넣어도 되고 바로 써도 된다"). 위치는 **컴포넌트 함수 안, 컴포넌트의 `return` 위**다. 이때 `return`이 두 개가 되는데, map 안의 `return`은 "책 하나 → 카드 하나", 아래 `return`은 "컴포넌트 화면 전체"다.

```jsx
const BookList = () => {
  const bookCards = books.map((book) => {
    return <BookCard key={book.id} title={book.title} />;   // ① map의 return
  });

  return <section>{bookCards}</section>;                   // ② BookList의 return
};
```

(강의 밖 비교) 파이썬의 리스트 컴프리헨션 `cards = [make_card(b) for b in books]`과 같은 생각이다.

관련: 이 파일의 "2. `map()`" 섹션 (`nameItems`), "수업 중 강사 화면 코드"의 `names`·`nameComponent`
</details>

<details><summary>Q. 화면이 하얗거나 글자가 빈칸으로 나와요 — 어디부터 봐요? <sub>2026-11-13 · 연습 중</sub></summary>

**A.** 먼저 **F12 → Console**의 빨간·노란 글씨를 읽는다. 컴포넌트에서 오류가 나면 React가 그리기를 멈춰서 제목까지 화면 전체가 하얗게 된다. 이번 연습에서 나온 메시지와 원인:

| Console 메시지 / 증상 | 원인 | 고치기 |
|---|---|---|
| `does not provide an export named 'TodoList'` (하얀 화면) | `export default`로 내보냈는데 `import { TodoList }`로 가져옴 | default는 `import TodoList`, 이름 export는 `import { TodoList }` |
| `title is not defined` (하얀 화면) | map 안에서 `{title}`만 씀. `title`은 `todo` 객체 안의 속성 | `{todo.title}` (구조 분해로 꺼낸 경우에만 `{title}`) |
| 글자 앞이 빈칸 + `Each child in a list should have a unique "key"` | `<li>{todo.key} …</li>`처럼 key를 **내용**으로 씀. 객체에 `key` 속성이 없어 `undefined` | `<li key={todo.id}>` — key는 태그에 붙이는 속성 |
| `isLearning is not defined` (하얀 화면, 2026-11-13) | `filter((member) => (isLearning))`처럼 매개변수 없이 속성 이름만 씀 | `member.isLearning` |
| `Adjacent JSX elements must be wrapped in an enclosing tag` (하얀 화면, 2026-11-13) | 삼항의 A·B 자리나 `return`에 요소 두 개를 나란히 씀 | 아래 "삼항으로 빈 목록 안내를 넣었더니 화면이 하얘요" 참고 |

오류 없이 그냥 비어 있으면 `return` 빠짐을 의심한다 (위 "map()으로 그렸는데 안 나와요" 참고). 터미널에서 `npx eslint src`를 돌려도 `'todo' is defined but never used`, `'title' is not defined`처럼 같은 원인을 알려 준다.

<details><summary>Q. 삼항으로 빈 목록 안내를 넣었더니 화면이 하얘요 (Adjacent JSX elements must be wrapped…) <sub>2026-11-13 · 연습 중</sub></summary>

**A.** 삼항 `조건 ? A : B`의 A·B 자리에는 **값 하나**만 들어간다. 그 자리에 `<h2>`와 `<ul>`처럼 요소 두 개를 나란히 쓰면 컴포넌트 `return`에 요소 두 개를 쓴 것과 같은 오류가 난다 (04의 "반환할 요소는 하나로 묶기"). 그래서 빌드가 멈추고 화면이 하얘진다.

```jsx
{list.length === 0 ? <p>없음</p> : <h2>제목</h2><ul>…</ul>}     // ❌ B 자리에 요소 2개
{list.length === 0 ? <p>없음</p> : <><h2>제목</h2><ul>…</ul></>} // 문법은 OK (Fragment로 하나로 묶음)
```

고치는 방법은 두 가지다. ① 비었든 아니든 **늘 보여야 하는 것**(개수 제목 등)은 삼항 **바깥**으로 빼서 B 자리에 하나만 남긴다. ② 정말 둘 다 바뀌어야 하면 `<>…</>`로 묶는다. 무엇이 "늘 보이는 것"인지 먼저 정하면 대개 ①이 된다.

관련: 이 파일의 빈 목록 안내 섹션, [04_React시작](04_React시작.md) "JSX 규칙 ① 반환할 요소는 하나로 묶기"
</details>
