# 비동기과정 — 동기·비동기와 블로킹·논블로킹

> 과정: 비동기과정 · [노션 원문](https://app.notion.com/p/416848f71c9b8068bd5bce75049286a3) · 최종 갱신일: 2026-11-18

## 과정 소개
시간이 걸리는 작업(타이머, 파일 읽기, 서버 요청)을 처리할 때 **코드가 어떤 순서로 실행되는지** 알아본다. Node.js에서 실행 순서를 비교하고, React에서 **느린 서버 응답을 기다리는 화면**을 만든다.

핵심 질문 두 가지를 나눠 본다.
- **동기·비동기**: 작업의 완료와 결과 처리가 어떻게 이어지는가?
- **블로킹·논블로킹**: 기다리는 동안 실행 스레드가 붙잡히는가?

## 학습 목표
노션 과정 페이지의 "완료 체크"를 목표로 옮겼다.
- 동기·비동기와 블로킹·논블로킹을 서로 다른 관점으로 구분할 수 있다.
- 타이머와 일반 코드의 실행 순서를 확인할 수 있다.
- Promise 결과를 `async/await`로 처리할 수 있다.
- 독립적인 작업의 순차 실행과 동시 진행을 비교할 수 있다.
- 블로킹 코드가 다른 작업에 미치는 영향을 확인할 수 있다.
- 느린 요청의 로딩·실패·중복 클릭을 처리할 수 있다.

## 실습 폴더 한눈에 보기
기존 서버·React 프로젝트와 구분하려고 새 폴더를 만든다. 강의에서 쓴 이름 기준이다.

```text
학습 폴더
├─ async-basic           ← 01~03회차: Node.js 파일 실행 (패키지 없음)
│   ├─ order.js, busy.js                         (01)
│   ├─ student-result.js, sequential.js, concurrent.js   (02)
│   └─ students.txt, read-sync.js, read-async.js, read-promise.js   (03)
├─ blocking-server       ← 03회차: server.js (express, 포트 3001)
├─ slow-student-server   ← 04회차: server.js (express, cors, 포트 3002)
└─ my-profile-react      ← 기존 Vite React 프로젝트 (04회차에 SlowStudentList.jsx 추가)
```

| 회차 | 폴더 | 준비 (처음 한 번) | 실행 | 결과 확인 |
|---|---|---|---|---|
| 01 | `async-basic` | 없음 | `node order.js`, `node busy.js` | 터미널 (출력 순서) |
| 02 | `async-basic` | 없음 | `node student-result.js`, `node sequential.js`, `node concurrent.js` | 터미널 (출력 순서·소요 시간) |
| 03 | `async-basic` + `blocking-server` | 서버: `npm init -y` → `npm install express` | `node read-sync.js` 등 / 서버 `node server.js` | 터미널 / 브라우저 탭 두 개(`http://localhost:3001/…`) + 서버 로그 |
| 04 | `slow-student-server` + React 프로젝트 | 서버: `npm init -y` → `npm install express cors` | 서버 `node server.js` + React `npm run dev` (터미널 2개) | 브라우저 `http://localhost:5173`, Network 탭 |

> 💡 보충: 04회차의 "기존 React 프로젝트"는 Node과정에서 쓴 Vite 프로젝트(`my-profile-react`)를 쓰면 된다. 포트 정리 — Node과정 학생 서버 3000, 블로킹 비교 서버 3001, 느린 학생 API 3002, React 5173.
