# 개발환경 — GitHub·블로그로 개발 기록 시작하기

> 과정: 개발환경 (오리엔테이션 2026-10-30) · [노션 원문](https://app.notion.com/p/409848f71c9b804a9dd2c5dd743c81fc) · 최종 갱신일: 2026-11-19

## 한눈에 보기
- 과정에서 작성한 코드와 문제를 해결한 경험은 성장 기록이 된다. **GitHub에는 코드와 변경 이력을, 블로그에는 이해한 내용과 해결 과정을** 남긴다.
- 준비 순서: **GitHub 계정·프로필 → 첫 저장소(`fullstack-study`) → 블로그(Velog 또는 티스토리 중 하나) 개설 → 첫 글**.
- 기록은 매번 수업 전체가 아니라 **오늘 이해한 개념 하나, 해결한 오류 하나**부터 시작한다.
- 내 컴퓨터의 폴더를 GitHub 저장소에 올리는 git 명령(`init → add → commit → push`)은 [git](git.md)에 정리했다.

## 도구별 역할

| 도구 | 기록할 내용 |
|---|---|
| GitHub | 실습 코드, 프로젝트, 변경 이력, 실행 방법 |
| 블로그 | 배운 개념, 오류 해결 과정, 기술을 선택한 이유 |

| 블로그 선택지 | 이런 방향으로 활용 |
|---|---|
| [Velog](https://velog.io/) | 개발 개념과 코드, 오류 해결 경험 중심으로 기록 |
| [티스토리](https://www.tistory.com/) | 개발 공부와 프로젝트 경험 등 다양한 글을 함께 기록 |

- 블로그는 둘 다 만들 필요 없다. 본인이 꾸준히 쓰기 편한 곳 하나를 고른다. 기존 블로그가 있으면 그대로 써도 된다.

> 💡 보충: Git은 내 컴퓨터에서 변경 이력을 기록·관리하는 프로그램이고, GitHub는 그 저장소를 인터넷에 올려 보관·공유하는 서비스다 ([git](git.md) "도구별 역할").

## 설치·확인 절차

### 1. GitHub 계정 만들기
[GitHub](https://github.com/)에 접속한다.
1. **Sign up**을 눌러 계정을 만든다.
2. 가입에 사용한 이메일을 인증한다.
3. 이미 계정이 있다면 기존 계정으로 로그인한다.

- **사용자 이름은 프로필 주소**(`https://github.com/<내 아이디>`)에 쓰인다. 앞으로 프로젝트와 이력서에도 연결되므로 계속 쓸 이름으로 정한다.

**프로필 설정** — 프로필 화면의 **Edit profile**에서 작성한다.

| 항목 | 쓸 내용 |
|---|---|
| Name | 이름 또는 사용할 닉네임 |
| Bio | 간단한 자기소개나 학습 목표 |
| 프로필 이미지 | 선택 사항 |
| Website | 블로그 개설 후 주소 추가 |

- **전화번호나 상세 주소 같은 개인정보는 적지 않아도 된다.**

### 2. 첫 번째 저장소 만들기
**저장소(Repository)는 프로젝트 파일과 변경 이력을 관리하는 공간**이다. GitHub에서 **New**를 눌러 아래처럼 설정한다.

| 항목 | 설정 |
|---|---|
| Repository name | `fullstack-study` |
| Description | 깃허브 연습용 저장소 |
| 공개 범위 | 공개할 학습 기록이라면 Public, 개인 기록이라면 Private |

> 💡 보충
> - **New** 버튼은 GitHub 첫 화면 왼쪽의 저장소 목록 옆, 또는 오른쪽 위 `+` → **New repository**에 있다.
> - 내 컴퓨터의 폴더를 이 저장소에 올릴 생각이면 README 추가(Add README) 같은 옵션은 켜지 않고 **빈 저장소로** 만든다. 만든 뒤 화면에 나오는 주소(`https://github.com/<내 아이디>/fullstack-study.git`)로 [git](git.md) "3. GitHub에 올리는 순서"를 따른다.

### 3. 학습 블로그 만들기
Velog 또는 티스토리 중 하나를 고른다 (위 "도구별 역할" 표).

1. 선택한 서비스에 가입하거나 로그인한다.
2. 안내에 따라 블로그를 개설한다.
3. 블로그 이름과 소개를 작성한다.
4. 내 블로그 주소를 확인한다.
5. GitHub 프로필과 README에 블로그 주소를 추가한다.

- 디자인 설정은 나중에 해도 된다. 오늘은 **글을 작성할 수 있는 상태까지** 준비한다.

> 💡 보충
> - 블로그 주소는 보통 Velog `https://velog.io/@<내 아이디>`, 티스토리 `https://<블로그 이름>.tistory.com` 형태다.
> - GitHub 프로필에는 **Edit profile → Website**에 넣는다.
> - README는 저장소의 `README.md`를 말한다. **내 아이디와 같은 이름의 Public 저장소**(`<내 아이디>/<내 아이디>`)를 만들고 `README.md`를 쓰면 GitHub 프로필 첫 화면에 그대로 보인다 (프로필 README).

### 4. 첫 글 작성하기
제목 예시: **풀스택 개발 공부를 시작하며**. 아래 질문에 짧게 답해 본다.
- 개발을 배우게 된 계기는 무엇인가?
- 지금까지 어떤 공부나 경험을 했나?
- 이번 과정에서 무엇을 배우고 싶나?
- 직접 만들어 보고 싶은 서비스가 있나?
- 앞으로 어떤 내용을 기록하고 싶나?

- 길고 멋진 글보다 **자신의 생각이 담긴 글**이면 충분하다. 공개가 부담스러우면 초안으로 저장해도 된다.

### 5. 앞으로 무엇을 기록할까
매번 수업 전체를 정리할 필요는 없다. **오늘 이해한 개념 하나, 해결한 오류 하나**부터 시작한다.

| 개념을 정리할 때 | 오류를 해결했을 때 |
|---|---|
| 어떤 문제를 해결하는 개념인가? | 무엇을 하려고 했는가? |
| 내 말로 어떻게 설명할 수 있는가? | 어떤 오류가 발생했는가? |
| 직접 실행한 예제는 무엇인가? | 원인은 무엇이었는가? |
| 아직 이해하지 못한 부분은 무엇인가? | 어떻게 해결하고 확인했는가? |

- 참고한 문서나 다른 사람의 글은 **링크**를 남긴다.
- AI를 활용했다면 설명과 코드를 직접 확인하고, 이해한 내용을 **자기 말로** 정리한다.
- **강의 자료나 타인의 코드를 그대로 공개하지 말고, 공유 가능한 범위를 확인한다. 비밀번호·API 키·개인정보도 올리지 않는다.**

> 💡 보충: 오류 해결 글은 위 네 질문을 소제목으로 쓰면 틀이 된다.
> ```markdown
> # [오류] <오류 메시지 한 줄>
> ## 하려던 것
> ## 발생한 오류 (메시지, 화면)
> ## 원인
> ## 해결하고 확인한 방법
> ## 참고한 글 (링크)
> ```

## 자주 쓰는 명령

> 💡 보충: 강의 원문에는 명령이 없다. GitHub·블로그 준비는 대부분 웹 화면에서 하므로, 자주 하는 일과 위치를 정리했다. 내 컴퓨터에서 올리는 명령은 [git](git.md) "자주 쓰는 명령" 표를 본다.

| 하고 싶은 것 | 어디서 |
|---|---|
| 새 저장소 만들기 | GitHub 첫 화면 **New** (또는 오른쪽 위 `+` → New repository) |
| 프로필 이름·소개·블로그 주소 바꾸기 | 내 프로필 → **Edit profile** |
| 저장소 주소 복사 | 저장소 화면의 초록색 **Code** 버튼 → HTTPS 주소 |
| 저장소 공개 범위 바꾸기 | 저장소 **Settings** → 맨 아래 Danger Zone → Change visibility |
| 내 폴더를 처음 올리기 / 그다음부터 올리기 | [git](git.md) 3장 / 4장 |

## 문제 생겼을 때

> 💡 보충: 강의 원문에는 없는, 처음 준비할 때 자주 만나는 상황
> - **인증 메일이 오지 않는다**: 스팸함을 확인하고, GitHub 화면의 안내에서 인증 메일을 다시 보낸다.
> - **`git push`가 `rejected`(`fetch first`)로 거절된다**: 저장소를 만들 때 README 등을 추가해서 GitHub 쪽에 이미 커밋이 있다. 처음이라면 저장소를 지우고 빈 저장소로 다시 만드는 것이 가장 쉽다. (push 할 때 로그인 창, `remote origin already exists` 같은 다른 오류는 [git](git.md) "문제 생겼을 때")
> - **Private 저장소 링크를 보냈는데 상대에게 404가 뜬다**: Private은 나와 초대한 사람만 볼 수 있다. 공유하려면 Public으로 바꾸거나 저장소 Settings → Collaborators에서 초대한다.
> - **비밀번호·API 키가 든 파일을 올렸다**: 파일을 지워도 커밋 기록에 남는다. 그 키·비밀번호는 바로 폐기하고 새로 발급·변경한다.
> - **GitHub가 2단계 인증(2FA) 설정을 요구한다**: 안내에 따라 인증 앱 등으로 설정한다. 복구 코드는 안전한 곳에 따로 보관한다.
