# 04. 폼으로 학생 등록하기 — GET 조회와 POST 등록

> 과정: Spring과정 · [노션 원문](https://app.notion.com/p/414848f71c9b80a39f50d112d4451e26) · 최종 갱신일: 2026-11-12

## 한눈에 보기
- 같은 `/students` 주소라도 **`GET`은 목록 조회, `POST`는 학생 등록**이다. Spring은 `@GetMapping`/`@PostMapping`으로 **경로 + 요청 메서드**를 함께 보고 처리할 메서드를 고른다.
- HTML **폼**(`action`·`method="post"`·입력창 `name`)으로 이름을 보내고, 컨트롤러는 **`@RequestParam(name = "name")`** 으로 받는다.
- 등록한 학생이 유지되도록 학생 목록을 메서드 안 지역 변수에서 **컨트롤러의 필드**(`private final List<Student> studentList`)로 옮긴다. 번호는 `nextId` 필드로 하나씩 늘린다.
- 이름은 `trim()` + `isEmpty()`로 **서버에서도 검사**하고, 비었으면 오류 문구를 Model에 담아 같은 화면을 다시 보여준다.
- 등록에 성공하면 **`return "redirect:/students";`** 로 브라우저가 목록을 다시 GET 요청하게 한다. 데이터는 메모리에 있어서 **서버를 재시작하면 초기화**된다.

> 💡 보충: 코드의 패키지는 `com.hancoding.student`다. 내 프로젝트 패키지(수업 화면은 `com.example.kdt`)에 맞춰 `package`·`import` 줄을 고친다 ([02_SpringBoot시작](02_SpringBoot시작.md) 맨 앞 참고).

## 학습 목표
- HTML 폼으로 서버에 데이터를 전송한다.
- GET 조회와 POST 등록을 구분한다.
- `@PostMapping`으로 등록 요청을 처리한다.
- `@RequestParam`으로 입력값을 받는다.
- 빈 이름은 등록하지 않도록 검사한다.
- 등록 후 목록 화면으로 리다이렉트한다.

## 핵심 개념

### 1. 입력한 학생을 서버로 보내려면?
[03](03_Thymeleaf-학생목록.md)에서는 컨트롤러 코드에 쓴 학생만 표시됐다. 이번에는 사용자가 입력한 이름을 받아 목록에 추가한다.

```text
학생 이름 입력
    ↓
등록 버튼 클릭
    ↓
POST /students 요청
    ↓
서버에서 입력값 검사
    ↓
학생 목록에 추가
    ↓
목록 화면으로 이동
```

- Thymeleaf와 HTML 폼만 쓴다. **React나 `fetch()`는 필요하지 않다.**

### 2. GET과 POST 구분하기

| 요청 | 역할 |
|---|---|
| `GET /students` | 학생 목록 화면 조회 |
| `POST /students` | 새로운 학생 등록 |

```java
@GetMapping("/students")
```

```java
@PostMapping("/students")
```

- **경로뿐 아니라 요청 메서드까지 함께 보고** 처리할 메서드를 찾는다.
- 브라우저 주소창에 `/students`를 입력하는 것은 **GET** 요청이다. 등록 기능은 **폼을 제출(POST)** 해서 확인한다.

### 3. 학생 목록의 위치 — 지역 변수 → 컨트롤러 필드
03의 코드는 요청 처리 메서드 **안에서** 목록을 만들었다.

```java
@GetMapping("/students")
public String students(Model model) {
    List<Student> students = new ArrayList<>();

    students.add(new Student(1, "한코딩", true));

    model.addAttribute("students", students);

    return "students";
}
```

- 요청할 때마다 새 목록을 만든다 → 다른 요청에서 학생을 등록해도 **다음 조회에서 목록을 다시 만들면 등록 내용이 사라진다.**

그래서 목록을 **메서드 바깥, 클래스 안의 필드**로 옮긴다.

```java
private final List<Student> studentList = new ArrayList<>();
```

| 선언 위치 | 이번 예제에서의 차이 |
|---|---|
| 메서드 안의 지역 변수 | 메서드가 실행될 때 생성 |
| 컨트롤러 객체의 필드 | 해당 객체가 유지되는 동안 사용 |

- 기본 설정에서 Spring은 **이 컨트롤러 객체를 하나 만들어 여러 요청에서 사용**한다. 그래서 필드에 담긴 목록도 요청 사이에 유지된다.
- **메모리 저장을 이해하기 위한 실습용**이다. 여러 사용자의 동시 등록을 처리할 저장 구조는 이후 DB 기반으로 바꾼다 (05장).
- **`final`** 은 다른 목록으로 재대입을 막을 뿐, `studentList.add(...)`는 된다 ([01_Java기초](01_Java기초.md) "final").

**생성자에서 초기 학생 등록하기**

```java
public StudentController() {
    studentList.add(new Student(1, "한코딩", true));
    studentList.add(new Student(2, "이학생", false));
    studentList.add(new Student(3, "박학생", true));
}
```

- Spring이 **컨트롤러 객체를 생성할 때** 생성자가 실행되어 초기 학생 세 명을 등록한다. **목록을 조회할 때마다 실행되는 코드가 아니다.**

### 4. HTML 폼 — `action`·`method`·`name`

| 속성 | 역할 |
|---|---|
| `action` | 제출할 주소 |
| `method` | 요청 메서드 |
| 입력 요소의 `name` | 서버에 전달할 데이터 이름 |

```html
<form th:action="@{/students}" method="post">
```

- 등록 버튼을 누르면 `/students`로 **POST** 요청을 보낸다.

**`id`와 `name`은 다르다**

```html
<input id="student-name" name="name" type="text">
```

| 속성 | 역할 |
|---|---|
| `id="student-name"` | label 연결, CSS·JavaScript 선택 등에 사용 |
| `name="name"` | 제출할 데이터의 이름 |

- **`id`만 있고 `name`이 없으면** 이 입력값은 폼 제출 데이터에 포함되지 않는다.
- 이름에 `한코딩`을 입력하면 서버에는 `name`이라는 항목으로 전달된다.

**`required`** — 브라우저가 빈 입력 제출을 막는다. 하지만 브라우저 검사는 우회할 수 있고, **공백만 있는 문자열**은 걸러내지 못한다. → **서버에서도 입력값을 검사한다.**

> 💡 보충: React 할 일 앱([08_폼-배열state-할일앱](../01_React과정/08_폼-배열state-할일앱.md))에서는 `preventDefault()`로 폼 제출을 막고 state에 추가했다. 이번에는 제출을 막지 않는다. 브라우저가 **폼 데이터를 서버로 보내고 페이지 전체를 새로 받는** HTML 폼 본래 동작을 그대로 쓴다. 그래서 JavaScript 코드가 필요 없다.

### 5. `@PostMapping`과 `@RequestParam`

```java
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestParam;
```

```java
@PostMapping("/students")
public String addStudent(
        @RequestParam(name = "name", defaultValue = "") String name
) {
    System.out.println("등록 요청 이름: " + name);

    return "redirect:/students";
}
```

- 처음에는 목록에 추가하지 않고, **입력이 도착했는지** 서버 콘솔에서 먼저 확인한다 → `등록 요청 이름: 한코딩`

| 코드 | 의미 |
|---|---|
| `name = "name"` | 읽어올 요청 항목 이름 |
| `defaultValue = ""` | 값이 없거나 빈 값일 때 사용할 기본값 |
| `String name` | 전달받은 값을 사용할 Java 변수 |

- **HTML의 `<input name="name">`과 `@RequestParam(name = "name")`의 이름이 연결되어야** 한다.

### 6. redirect는 무엇인가?

```java
return "redirect:/students";
```

브라우저에 **`/students` 주소로 다시 요청하라**고 응답한다.

```text
POST /students
    ↓
서버에서 등록 처리
    ↓
리다이렉트 응답
    ↓
브라우저가 GET /students 요청
    ↓
목록 화면 표시
```

| 반환값 | 의미 |
|---|---|
| `"students"` | 현재 요청에서 템플릿을 처리해 화면 응답 |
| `"redirect:/students"` | 브라우저가 해당 주소로 새 요청을 보내도록 안내 |

- 등록 후 GET 화면으로 이동하면, 그 화면을 **새로고침해도 직전 등록 POST를 다시 보내지 않는다** (학생 중복 추가 방지).

### 7. 학생 추가와 번호 부여 — `nextId`, `trim()`

```java
private int nextId = 4;
```

- 초기 학생 ID가 1~3이므로 다음 등록부터 4를 쓴다.

| 코드 | 역할 |
|---|---|
| `name.trim()` | 이름 양끝의 공백 제거 |
| `isEmpty()` | 빈 문자열인지 확인 |
| `new Student(...)` | 학생 객체 생성 |
| `studentList.add(student)` | 목록에 추가 |
| `nextId++` | 다음 학생에게 사용할 번호 증가 |

- 새 학생의 학습 여부는 우선 `false`로 등록한다.

### 8. 빈 이름 오류 안내 — `students(model)`
빈 이름이면 오류 문구를 Model에 담아 **같은 화면을 다시 표시**한다.

```java
return students(model);
```

- 같은 클래스의 목록 조회 메서드를 **일반 Java 메서드로 호출**한 것이다. 그 메서드가 학교 이름·학생 목록을 Model에 담고 `"students"`를 반환하므로, 오류 문구와 함께 템플릿이 표시된다.
- **이 호출 자체가 새로운 GET 요청을 보내는 것은 아니다.**

HTML(폼 위)에 오류 문구 영역을 추가한다. `error`가 있을 때만 표시된다.

```html
<p class="error-message"
   role="alert"
   th:if="${error != null}"
   th:text="${error}">
    오류 안내
</p>
```

> 💡 보충: `role="alert"`는 화면 낭독기가 이 문구를 바로 읽어 주게 하는 접근성 속성이다. `${error != null}`은 Model에 `error`를 넣지 않은 정상 조회 때는 거짓이라 문구가 숨겨진다.

### 9. 서버를 재시작하면 어떻게 될까?
새 학생을 등록하고 서버를 재시작하면 **추가한 학생은 사라지고 생성자의 초기 학생 세 명**만 보인다. 데이터가 컨트롤러 객체의 **메모리**에 있기 때문이다.

| 작업 | 결과 |
|---|---|
| 브라우저 새로고침 | 실행 중인 서버의 목록 유지 |
| 다른 브라우저로 접속 | 같은 서버의 목록 조회 |
| 서버 재시작 | 메모리 목록 초기화 |

- 현재 목록은 **모든 요청에서 공유**하며, 사용자별로 나뉜 목록이 아니다.

### 정리

| 개념 | 핵심 |
|---|---|
| `form` | 입력 데이터를 서버에 제출 |
| `action` | 요청할 주소 |
| `method` | 요청 메서드 |
| `name` | 제출할 데이터 이름 |
| `@PostMapping` | POST 요청 처리 |
| `@RequestParam` | 요청의 입력값 받기 |
| `trim()`·`isEmpty()` | 빈 이름 검사 |
| `redirect:` | 브라우저가 다른 주소로 다시 요청하도록 안내 |

## 실습 정리

### 만든 것
03의 학생 목록 화면 위에 **학생 이름 입력 폼**을 붙여, 이름을 등록하면 새 번호(4, 5, …)와 "학습 예정" 상태로 목록에 추가되는 기능. 공백만 입력하면 "학생 이름을 입력해주세요." 문구가 나온다.

### 단계 흐름
1. 학생 목록을 컨트롤러 **필드**로 옮기고, 초기 학생 3명은 **생성자**에서 등록 → 기존 목록이 그대로 보이는지 확인
2. `students.html`의 안내 문구 아래, 학생 수 표시 위에 **등록 폼** 추가
3. `@PostMapping` 메서드로 이름이 **서버 콘솔에 찍히는지** 확인 (`redirect:/students`)
4. `nextId` 필드 추가, `trim()`·`isEmpty()` 검사 후 **목록에 추가**
5. 빈 이름이면 `error`를 Model에 담고 `students(model)`로 **같은 화면 + 오류 문구** 표시
6. `students.css`에 **폼 스타일** 추가

#### 1단계 코드 — 목록을 필드로

```java
package com.hancoding.student.controller;

import com.hancoding.student.model.Student;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;

import java.util.ArrayList;
import java.util.List;

@Controller
public class StudentController {

    private final List<Student> studentList = new ArrayList<>();

    public StudentController() {
        studentList.add(new Student(1, "한코딩", true));
        studentList.add(new Student(2, "이학생", false));
        studentList.add(new Student(3, "박학생", true));
    }

    @GetMapping("/students")
    public String students(Model model) {
        model.addAttribute("schoolName", "한코딩 스쿨");
        model.addAttribute(
                "message",
                "함께 공부하는 학생들을 소개합니다."
        );
        model.addAttribute("students", studentList);

        return "students";
    }
}
```

#### 4단계 코드 — 목록에 추가 (오류 안내 전)

```java
private final List<Student> studentList = new ArrayList<>();
private int nextId = 4;
```

```java
@PostMapping("/students")
public String addStudent(
        @RequestParam(name = "name", defaultValue = "") String name
) {
    String trimmedName = name.trim();

    if (trimmedName.isEmpty()) {
        return "redirect:/students";
    }

    Student student = new Student(
            nextId,
            trimmedName,
            false
    );

    studentList.add(student);
    nextId++;

    return "redirect:/students";
}
```

- 이 단계에서는 빈 이름을 등록하지 않지만, 사용자에게 **이유를 보여주지 않는다** → 5단계에서 개선.

### 최종 코드

**`controller/StudentController.java`**

```java
package com.hancoding.student.controller;

import com.hancoding.student.model.Student;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestParam;

import java.util.ArrayList;
import java.util.List;

@Controller
public class StudentController {

    private final List<Student> studentList = new ArrayList<>();
    private int nextId = 4;

    public StudentController() {
        studentList.add(new Student(1, "한코딩", true));
        studentList.add(new Student(2, "이학생", false));
        studentList.add(new Student(3, "박학생", true));
    }

    @GetMapping("/students")
    public String students(Model model) {
        model.addAttribute("schoolName", "한코딩 스쿨");
        model.addAttribute(
                "message",
                "함께 공부하는 학생들을 소개합니다."
        );
        model.addAttribute("students", studentList);

        return "students";
    }

    @PostMapping("/students")
    public String addStudent(
            @RequestParam(name = "name", defaultValue = "") String name,
            Model model
    ) {
        String trimmedName = name.trim();

        if (trimmedName.isEmpty()) {
            model.addAttribute(
                    "error",
                    "학생 이름을 입력해주세요."
            );

            return students(model);
        }

        Student student = new Student(
                nextId,
                trimmedName,
                false
        );

        studentList.add(student);
        nextId++;

        return "redirect:/students";
    }
}
```

    public String getName() {

## 헷갈리기 쉬운 점
- **주소창에 `/students` 입력 = GET.** 등록(POST)은 폼 제출로만 확인한다.
- **같은 경로라도 GET과 POST는 다른 메서드가 처리한다.** `@PostMapping`이 없으면 제출 시 405 오류.
- **입력창에 `name`이 없으면 값이 전송되지 않는다.** `id`는 label·CSS용이고, 서버로 가는 이름은 `name`이다.
- **`<input name="name">` ↔ `@RequestParam(name = "name")` 이름이 같아야** 한다.
- **`required`만 믿지 않는다.** 공백만 입력하면 통과하므로 서버에서 `trim()` + `isEmpty()`로 다시 검사한다.
- **목록을 조회 메서드 안에서 만들면 등록이 유지되지 않는다.** 컨트롤러 필드에 둔다.
- **생성자는 컨트롤러 객체를 만들 때 한 번 실행된다.** 조회할 때마다 실행되는 게 아니다.
- **`"students"`(화면 응답) ≠ `"redirect:/students"`(다시 요청하라는 안내).** 등록 성공 후에는 redirect로 새로고침 중복 등록을 막는다.
- **`return students(model);`은 새 GET 요청이 아니라** 같은 클래스의 메서드를 그냥 호출한 것이다.
- **`redirect:/students`가 글자로 보이면 `@RestController`로 되어 있는 것**이다. `@Controller`여야 한다.
- **같은 `@PostMapping("/students")` 메서드를 두 개 남기면 매핑 중복 오류.** 단계별로 바꿀 때 기존 메서드를 교체한다.
- **지금 데이터는 메모리에 있다.** 서버를 재시작하면 초기화되고, 모든 사용자가 같은 목록을 공유한다.

**동작하지 않을 때 확인할 것**

| 증상 | 확인할 내용 |
|---|---|
| 등록 시 405 오류 | POST 요청을 처리할 `@PostMapping`이 있는지 |
| 이름이 전달되지 않음 | 입력창 `name`과 `@RequestParam` 이름 일치 여부 |
| 등록 후 목록이 초기화됨 | 조회 메서드 안에서 목록을 새로 만들고 있는지 |
| `redirect:/students`가 글자로 표시됨 | `@RestController` 대신 `@Controller`인지 |
| 서버에서 이름이 빈 값으로 처리됨 | 폼의 `name="name"` 속성 |
| 같은 요청 매핑 오류 | 기존 등록 메서드를 남겨 중복 작성했는지 |
| 수정한 기능이 반영되지 않음 | 저장 후 서버를 재시작했는지 |

## 빠른 참고 (치트시트)

| 하고 싶은 것 | 쓰는 것 | 예시 |
|---|---|---|
| POST로 폼 보내기 | `form` + `th:action` + `method` | `<form th:action="@{/students}" method="post">` |
| 서버로 보낼 값 이름 | 입력창 `name` | `<input id="student-name" name="name" type="text">` |
| 빈 입력 1차 차단 (브라우저) | `required` | `<input … required>` |
| POST 요청 처리 | `@PostMapping` | `@PostMapping("/students")` |
| 입력값 받기 | `@RequestParam` | `@RequestParam(name = "name", defaultValue = "") String name` |
| 양끝 공백 제거 | `trim()` | `String trimmedName = name.trim();` |
| 빈 문자열 검사 | `isEmpty()` | `if (trimmedName.isEmpty()) { … }` |
| 요청 사이에 유지되는 목록 | 컨트롤러 필드 | `private final List<Student> studentList = new ArrayList<>();` |
| 초기 데이터 넣기 | 컨트롤러 생성자 | `public StudentController() { studentList.add(…); }` |
| 번호 자동 증가 | 필드 + `++` | `private int nextId = 4;` … `nextId++;` |
| 등록 후 목록으로 | `redirect:` | `return "redirect:/students";` |
| 오류 문구 전달 | Model + 같은 화면 | `model.addAttribute("error", "…"); return students(model);` |
| 오류 있을 때만 표시 | `th:if` + `!= null` | `th:if="${error != null}" th:text="${error}"` |

## 확인 문제

<details><summary>Q. 같은 `/students` 경로에서 GET과 POST는 각각 무슨 일을 하고, Spring은 어떻게 구분하는가?</summary>

`GET /students`는 학생 목록 화면 조회, `POST /students`는 새 학생 등록이다. Spring은 `@GetMapping("/students")`와 `@PostMapping("/students")`로 **경로와 요청 메서드를 함께 보고** 처리할 메서드를 찾는다.
</details>

<details><summary>Q. 03처럼 학생 목록을 조회 메서드 안에서 만들면 왜 등록한 학생이 유지되지 않는가? 어떻게 고쳤는가?</summary>

요청할 때마다 `new ArrayList<>()`로 **새 목록을 만들기** 때문이다. 목록을 **컨트롤러의 필드**(`private final List<Student> studentList`)로 옮겼다. Spring은 컨트롤러 객체를 하나 만들어 여러 요청에서 쓰므로 필드의 목록이 요청 사이에 유지된다.
</details>

<details><summary>Q. 컨트롤러 생성자에 쓴 초기 학생 등록 코드는 언제 실행되는가?</summary>

Spring이 **컨트롤러 객체를 생성할 때 한 번** 실행된다. 목록을 조회할 때마다 실행되지 않는다.
</details>

<details><summary>Q. 폼의 `action`, `method`, 입력 요소의 `name`은 각각 무슨 역할인가?</summary>

`action` = 제출할 주소, `method` = 요청 메서드(`post`), `name` = 서버에 전달할 데이터 이름.
</details>

<details><summary>Q. `<input id="student-name">`처럼 `id`만 있고 `name`이 없으면 어떻게 되는가?</summary>

입력값이 폼 제출 데이터에 **포함되지 않는다.** `id`는 label 연결·CSS·JavaScript 선택용이고, 서버로 보내는 이름은 `name`이다.
</details>

<details><summary>Q. 입력창에 `required`가 있는데 왜 서버에서도 검사하는가?</summary>

브라우저 검사는 **우회할 수 있고**, **공백만 있는 문자열**은 `required`를 통과한다. 그래서 서버에서 `name.trim()`으로 공백을 지우고 `isEmpty()`로 다시 검사한다.
</details>

<details><summary>Q. `@RequestParam(name = "name", defaultValue = "") String name`의 각 부분은?</summary>

`name = "name"` = 읽어올 요청 항목 이름(HTML `name="name"`과 연결), `defaultValue = ""` = 값이 없거나 빈 값일 때 쓸 기본값, `String name` = 전달받은 값을 쓸 Java 변수.
</details>

<details><summary>Q. redirect는 무엇인가? `return "students";`와 `return "redirect:/students";`의 차이는?</summary>

`"students"`는 **현재 요청에서** 템플릿을 처리해 화면을 응답한다. `"redirect:/students"`는 브라우저에게 **`/students`로 새 요청(GET)을 보내라**고 안내한다. 등록 후 redirect하면 그 화면을 새로고침해도 POST가 다시 전송되지 않아 중복 등록을 막는다.
</details>

<details><summary>Q. 빈 이름일 때 `return students(model);`을 호출한 이유는? 이것은 새 GET 요청인가?</summary>

같은 클래스의 조회 메서드를 **일반 Java 메서드로 호출**해 학교 이름·학생 목록을 Model에 담고 `"students"`를 반환받기 위해서다. 그래서 오류 문구(`error`)와 함께 같은 화면이 표시된다. **새 GET 요청을 보내는 것이 아니다.**
</details>

<details><summary>Q. 새 학생의 번호는 어떻게 정하는가?</summary>

컨트롤러 필드 `private int nextId = 4;`(초기 학생이 1~3)를 새 학생의 ID로 쓰고, 추가한 뒤 `nextId++`로 다음 번호를 늘린다.
</details>

<details><summary>Q. 서버를 재시작하면 어떻게 될까? 다른 브라우저로 접속하면?</summary>

재시작하면 메모리 목록이 초기화되어 **추가한 학생은 사라지고** 생성자의 초기 학생 3명만 남는다. 다른 브라우저로 접속하면 **같은 서버의 목록**을 본다 (사용자별 목록이 아니라 모든 요청이 공유).
</details>

<details><summary>Q. 학생 등록 버튼을 눌렀더니 405 오류가 났다. 무엇을 확인하는가?</summary>

POST 요청을 처리할 **`@PostMapping("/students")` 메서드가 있는지** 확인한다 (GET 메서드만 있으면 405).
</details>
