# 02. 테이블 만들고 데이터 추가하기 — `CREATE TABLE`과 `INSERT`

> 과정: 데이터베이스과정 · [노션 원문](https://app.notion.com/p/41a848f71c9b80da8b84d1a6172d132d) · 최종 갱신일: 2026-11-18

## 한눈에 보기
- 테이블을 만들기 전에 **어떤 정보(열)를 저장하고 어떤 규칙을 적용할지** 정한다: 학생 번호 `id`, 이름 `name`, 이메일 `email`, 등록일 `registered_date`.
- **자료형**: `INT`(정수) · `VARCHAR(n)`(최대 n자 문자열) · `DATE`(연·월·일). 숫자로만 된 값이라도 전화번호처럼 계산하지 않는 값은 문자열로 저장한다.
- **제약 조건**: `PRIMARY KEY`(행을 구분, 중복·NULL 불가) · `AUTO_INCREMENT`(번호 자동 부여) · `NOT NULL`(NULL 금지) · `UNIQUE`(중복 금지).
- `INSERT INTO 테이블 (열 목록) VALUES (값 목록);` — **열과 값의 순서를 맞추고**, 문자열·날짜는 작은따옴표, 자동 번호 `id`는 생략. 추가한 뒤에는 `SELECT * FROM students;`로 확인한다.
- `NULL`(값 없음) ≠ `'NULL'`(글자 4개) ≠ `''`(빈 문자열). 일부러 중복 이메일·이름 NULL을 넣어 `Duplicate entry`, `cannot be null` 오류를 확인했다.

## 학습 목표
- 저장할 정보에 맞는 자료형을 선택한다.
- `CREATE TABLE`로 테이블을 만든다.
- 기본키·필수값·중복 제한의 역할을 이해한다.
- `INSERT`로 데이터를 추가한다.
- 잘못된 데이터를 입력했을 때 오류의 원인을 확인한다.

## 핵심 개념

### 1. 어떤 정보를 저장할까? — 열과 규칙 정하기
[01](01_DB이해-실습환경.md)에서 만든 `school` 데이터베이스에 학생 정보를 저장할 `students` 테이블을 만든다.

| 항목 | 열 이름 | 저장할 값의 예 |
|---|---|---|
| 학생 번호 | `id` | `1` |
| 이름 | `name` | `'한코딩'` |
| 이메일 | `email` | `'han@example.com'` |
| 등록일 | `registered_date` | `2026-11-16` |

이번 규칙:
- 학생 번호는 **자동으로 부여**한다. (auto increment)
- 이름과 이메일은 **반드시 입력**한다. (비워 둘 수 없다: not null)
- 서로 다른 학생이 **같은 이메일을 쓸 수 없다.** (중복 방지: unique)
- 등록일은 날짜로 저장하며, 모르면 **비워 둘 수 있다.**

- 실습에서는 실제 개인정보 대신 **가상의 이름과 이메일**을 쓴다.

### 2. 자료형 — 어떤 종류의 값을 저장할까?
자료형 = **각 열에 저장할 값의 종류**.

| 자료형 | 저장할 값 | 예 |
|---|---|---|
| `INT` | 정수 | `1`, `2`, `100` |
| `VARCHAR(n)` | 최대 길이를 지정한 문자열 | 이름, 이메일 |
| `DATE` | 날짜 | `'2026-11-16'` |

```sql
id INT
```

```sql
name VARCHAR(50)
```

- `VARCHAR(50)` = **최대** 50자까지 저장할 수 있는 문자열 열. 항상 50자를 채워야 한다는 뜻이 아니다 (`한코딩`, `김자바` 모두 저장 가능).
- 이메일은 이름보다 길 수 있으므로 넉넉하게 `email VARCHAR(100)`.
- **숫자로만 된 값이라고 무조건 `INT`를 쓰지 않는다.** 전화번호는 앞자리 `0`·하이픈을 유지해야 하고 계산할 값도 아니므로 문자열이 적절하다.

```sql
registered_date DATE
```

- SQL에서 날짜는 **작은따옴표로 감싼다**: `'2026-11-16'`
- `DATE`에는 **시각이 포함되지 않는다.** 연·월·일만 저장한다.

### 3. 기본키 — 각 학생을 어떻게 구분할까?
이름만으로 구분하면, 이름이 같은 다른 학생을 구분할 수 없다.

| name | email |
|---|---|
| 한코딩 | han1@example.com |
| 한코딩 | han2@example.com |

→ 학생마다 **고유한 번호**를 붙인다. 각 행을 구분하는 대표 기준을 **기본키(PRIMARY KEY)** 라고 한다.

```sql
id INT PRIMARY KEY
```

기본키 규칙:
- 같은 값을 **중복 저장할 수 없다.**
- 값이 없는 상태인 **`NULL`을 허용하지 않는다.**

### 4. `AUTO_INCREMENT` — 번호 자동 부여

```sql
id INT AUTO_INCREMENT PRIMARY KEY
```

> "학생 번호를 직접 입력하지 않아도 MySQL이 겹치지 않는 번호를 부여한다."

- 자동 번호는 **행을 구분하는 식별자**다. 삭제나 입력 실패 등으로 **중간 번호가 비어 있을 수 있다.** 학생 수나 연속된 출석번호로 생각하지 않는다.

### 5. 제약 조건 — `NOT NULL`, `UNIQUE`
자료형 외에 데이터가 지켜야 할 규칙을 **제약 조건**이라고 한다.

**`NOT NULL` — 값이 반드시 있어야 한다**

```sql
name VARCHAR(50) NOT NULL
```

- `NULL` = **값이 없거나 아직 정해지지 않은 상태**. (`'한코딩'` → 이름이 있음, `NULL` → 이름 값이 없음)
- **`NOT NULL`이 빈 문자열 `''`이나 공백 `'   '`까지 막지는 않는다.** 이 값들은 `NULL`과 다르다. 실제 서비스에서는 비었는지·공백뿐인지 따로 검사해야 한다.

> 💡 보충: Spring 학생 등록([04_폼-학생등록](../03_Spring과정/04_폼-학생등록.md))에서 `trim()` + `isEmpty()`로 서버에서 다시 검사한 이유와 같다.

**`UNIQUE` — 같은 값을 중복할 수 없다**

```sql
email VARCHAR(100) NOT NULL UNIQUE
```

- 이메일은 **반드시 입력**해야 하고, **이미 저장된 이메일과 겹칠 수 없다.**

| 설정 | 역할 |
|---|---|
| `PRIMARY KEY` | 각 행을 구분하는 기본키 |
| `AUTO_INCREMENT` | 번호 자동 부여 |
| `NOT NULL` | `NULL` 저장 금지 |
| `UNIQUE` | 값의 중복 제한 |

### 6. `CREATE TABLE` — 학생 테이블 만들기
먼저 사용할 DB를 고르고 확인한다 (`USE school;` → `SELECT DATABASE();`가 `school`).

```sql
CREATE TABLE students (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) NOT NULL UNIQUE,
    registered_date DATE
);
```

```text
CREATE TABLE students (
    열 이름  자료형  적용할 규칙,
    열 이름  자료형  적용할 규칙
);
```

- `students`는 테이블 이름, **괄호 안에서 열을 정의**한다.
- 열 정의 사이에는 **쉼표**를 넣고, **마지막 열 뒤에는 쉼표를 넣지 않는다.**

### 7. 테이블 구조 확인 — `SHOW TABLES`, `DESCRIBE`

```sql
SHOW TABLES;
```

```sql
DESCRIBE students;
```

| 표시 항목 | 의미 |
|---|---|
| `Field` | 열 이름 |
| `Type` | 자료형 |
| `Null` | `NULL` 허용 여부 |
| `Key` | 기본키·고유키 등의 정보 |
| `Extra` | 자동 번호 등 추가 설정 |

- DBeaver 왼쪽 목록을 새로고침하고 테이블을 열어 구조를 봐도 된다.
- `Table 'students' already exists` 오류 = 같은 이름의 테이블이 이미 있다. **삭제부터 하지 말고** `DESCRIBE students;`로 기존 구조를 확인한다.

> 💡 보충: MySQL에서 `DESCRIBE students;`를 실행하면 대략 이렇게 나온다.
>
> | Field | Type | Null | Key | Default | Extra |
> |---|---|---|---|---|---|
> | id | int | NO | PRI | NULL | auto_increment |
> | name | varchar(50) | NO | | NULL | |
> | email | varchar(100) | NO | UNI | NULL | |
> | registered_date | date | YES | | NULL | |

### 8. `INSERT INTO` — 데이터 추가
테이블은 저장할 **구조**일 뿐, 만들었다고 데이터가 생기지 않는다.

```sql
INSERT INTO students (name, email, registered_date)
VALUES ('한코딩', 'han@example.com', '2026-11-16');
```

| 코드 | 의미 |
|---|---|
| `INSERT INTO students` | `students` 테이블에 추가 |
| `(name, email, registered_date)` | 값을 넣을 열 목록 |
| `VALUES (...)` | 실제로 저장할 값 |

- **열 목록과 값의 순서를 맞춘다.**

```text
name             ← '한코딩'
email            ← 'han@example.com'
registered_date  ← '2026-11-16'
```

- `id`는 자동으로 부여되므로 **생략**한다.
- **문자열과 날짜는 작은따옴표**(`'한코딩'`, `'han@example.com'`), **일반 숫자는 따옴표 없이**(`1`).

### 9. `SELECT`로 추가한 데이터 확인

```sql
SELECT * FROM students;

SELECT name FROM students;

SELECT email FROM students;

SELECT name, email FROM students;
```

| 코드 | 의미 |
|---|---|
| `SELECT` | 조회 |
| `*` | 모든 열 |
| `FROM students` | `students` 테이블에서 |

새 테이블에 처음 추가했다면:

| id | name | email | registered_date |
|---|---|---|---|
| 1 | 한코딩 | han@example.com | 2026-11-16 |

- 확인할 것: 이름·이메일이 저장됐나? 날짜가 저장됐나? **직접 넣지 않은 `id`가 부여됐나?**
- **추가 명령을 실행한 뒤에는 조회해서 결과를 확인한다.** (조회는 [03](03_데이터조회.md)에서 자세히)

### 10. 여러 행 한 번에 추가
값 묶음을 **쉼표로 연결**한다.

```sql
INSERT INTO students (name, email, registered_date)
VALUES
    ('김자바', 'java@example.com', '2026-11-17'),
    ('이리액트', 'react@example.com', '2026-11-18');
```

- 여기까지 정상이면 총 세 명이 조회된다.
- **같은 `INSERT`를 다시 실행하면 이메일 중복 오류**가 날 수 있다. 이미 실행한 명령인지 확인하고, 새 학생은 다른 이메일을 쓴다.

### 11. 값이 없는 항목 저장 — `NULL`
등록일에는 `NOT NULL`을 걸지 않았으므로 모르면 `NULL`을 넣을 수 있다.

```sql
INSERT INTO students (name, email, registered_date)
VALUES ('박스프링', 'spring@example.com', NULL);
```

- 조회하면 박스프링 학생의 등록일이 `NULL`로 표시된다.
- **`NULL`에는 따옴표를 붙이지 않는다.**

| 표현 | 의미 |
|---|---|
| `NULL` | 값이 없거나 아직 정해지지 않음 |
| `'NULL'` | N·U·L·L 글자 네 개로 된 문자열 |
| `''` | 길이가 0인 빈 문자열 |

- **값이 없는 상태와 빈 문자열은 구분해야 한다.**

### 12. 일부러 오류 내 보기 — 제약 조건 확인
오류 확인용 SQL이다. **하나씩 선택해서** 실행한다.

**① 같은 이메일 추가**

```sql
INSERT INTO students (name, email, registered_date)
VALUES ('최노드', 'han@example.com', '2026-11-19');
```

- `email`에 `UNIQUE`가 있어 중복 오류 → 메시지에서 **`Duplicate entry`** 를 찾는다.
- **이름을 바꿔도 해결되지 않는다.** 중복이 금지된 항목은 **이메일**이다.

**② 이름에 NULL 넣기**

```sql
INSERT INTO students (name, email, registered_date)
VALUES (NULL, 'noname@example.com', '2026-11-19');
```

- `name`에 `NOT NULL`이 있어 오류 → 메시지에서 **`cannot be null`** 을 찾는다.

**③ 오류 후 확인** — `SELECT * FROM students;`로 **실패한 학생이 저장되지 않았는지** 본다.

- 실패한 입력에서도 **자동 번호가 소모**되어 다음 번호가 건너뛸 수 있다. 번호가 비었다고 오류로 판단하지 않는다.

> 💡 보충: MySQL 8.4.13에서 확인해 보니 (2026-11-24) 번호를 쓰고 실패하는 건 행을 넣으려다 막히는 **중복 오류(`1062`)** 와 **외래키 위반(`1452`, [05](05_테이블관계-JOIN.md))** 이었다. `NOT NULL` 위반(`1048`)·값 개수 불일치(`1136`)처럼 값을 검사하다 걸리는 오류는 번호를 쓰지 않았다. 그래서 이 강의 흐름대로 하면 마지막 학생이 6번이 된다 (최종 id 1, 2, 3, 4, 6).

### 정리

| 개념·명령 | 역할 |
|---|---|
| `INT` | 정수 저장 |
| `VARCHAR(n)` | 최대 길이를 지정한 문자열 저장 |
| `DATE` | 연·월·일 저장 |
| `PRIMARY KEY` | 각 행을 구분하는 기본키 |
| `AUTO_INCREMENT` | 번호 자동 부여 |
| `NOT NULL` | `NULL` 저장 금지 |
| `UNIQUE` | 값의 중복 제한 |
| `NULL` | 값이 없거나 아직 정해지지 않은 상태 |
| `CREATE TABLE` | 테이블 생성 |
| `DESCRIBE` | 테이블 구조 확인 |
| `INSERT INTO` | 데이터 추가 |
| `SELECT * FROM` | 테이블의 모든 열 조회 |

## 실습 정리

### 만든 것
`school` DB에 **`students` 테이블**을 만들고 가상의 학생 다섯 명을 추가했다. 이 데이터를 [03](03_데이터조회.md)~[06](06_Spring-MyBatis.md)에서 계속 쓴다.

### 단계 흐름
1. `USE school;` → `SELECT DATABASE();`로 DB 확인
2. `CREATE TABLE students (...)` → `SHOW TABLES;`, `DESCRIBE students;`로 구조 확인
3. 한 명 추가 → 조회
4. 두 명 한 번에 추가 → 조회 (3명)
5. 등록일 `NULL`인 학생 추가 → 조회 (4명)
6. 오류 확인: 중복 이메일, 이름 `NULL` → 저장 안 됐는지 조회
7. 직접 한 명 추가 → 조회 (5명)

### 전체 SQL (정상 입력만, 순서대로 한 번씩)

```sql
USE school;

SELECT DATABASE();

CREATE TABLE students (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) NOT NULL UNIQUE,
    registered_date DATE
);

SHOW TABLES;

DESCRIBE students;

INSERT INTO students (name, email, registered_date)
VALUES ('한코딩', 'han@example.com', '2026-11-16');

INSERT INTO students (name, email, registered_date)
VALUES
    ('김자바', 'java@example.com', '2026-11-17'),
    ('이리액트', 'react@example.com', '2026-11-18');

INSERT INTO students (name, email, registered_date)
VALUES ('박스프링', 'spring@example.com', NULL);

INSERT INTO students (name, email, registered_date)
VALUES ('정데이터', 'data@example.com', '2026-11-20');

SELECT * FROM students;
```

### 직접 학생 한 명 추가하기 (미션)
조건: 학생 번호는 입력하지 않는다 · 이름은 직접 정한다 · 이메일은 기존 학생과 겹치지 않게 · 등록일은 날짜 또는 `NULL`. 강의 예시는 위 전체 SQL의 `정데이터` 줄이다.

### 실습 후 데이터
정상 입력 예제를 한 번씩 실행했다면 다섯 명이 저장되어 있다. `id`는 실행 과정(실패한 입력 등)에 따라 다를 수 있다.

| name | email | registered_date |
|---|---|---|
| 한코딩 | han@example.com | 2026-11-16 |
| 김자바 | java@example.com | 2026-11-17 |
| 이리액트 | react@example.com | 2026-11-18 |
| 박스프링 | spring@example.com | NULL |
| 정데이터 | data@example.com | 2026-11-20 |

## 헷갈리기 쉬운 점
- **`VARCHAR(50)`은 "최대" 50자다.** 50자를 채워야 하는 게 아니다.
- **숫자로만 된 값 ≠ `INT`.** 전화번호처럼 앞자리 `0`·하이픈을 유지해야 하고 계산하지 않는 값은 문자열.
- **`DATE`는 시각이 없다.** 날짜는 작은따옴표로 감싼다.
- **`PRIMARY KEY`는 중복도 `NULL`도 안 된다.**
- **자동 번호가 건너뛰어도 정상이다.** 실패한 입력·삭제로 번호가 소모된다.
- **`NOT NULL`은 `''`·공백을 막지 않는다.** 빈 이름 검사는 따로 해야 한다.
- **`NULL`에 따옴표를 붙이면 `'NULL'`이라는 글자가 된다.**
- **열 목록과 값의 순서가 맞아야 한다.** `id`는 자동이므로 열 목록에서 뺀다.
- **문자열·날짜는 작은따옴표, 숫자는 따옴표 없이.**
- **열 정의 사이 쉼표, 마지막 열 뒤에는 쉼표 없음.**
- **같은 `INSERT`를 두 번 실행하면 `Duplicate entry`.** 이메일이 `UNIQUE`이기 때문이다. 이름을 바꿔도 해결되지 않는다.
- **`Table 'students' already exists`면 삭제부터 하지 말고** `DESCRIBE`로 기존 구조를 본다.
- **추가한 뒤에는 꼭 `SELECT`로 확인한다.**

## 빠른 참고 (치트시트)

| 하고 싶은 것 | 쓰는 것 | 예시 |
|---|---|---|
| 정수 열 | `INT` | `id INT` |
| 문자열 열 (최대 길이) | `VARCHAR(n)` | `name VARCHAR(50)` |
| 날짜 열 | `DATE` | `registered_date DATE` |
| 자동 번호 기본키 | `AUTO_INCREMENT PRIMARY KEY` | `id INT AUTO_INCREMENT PRIMARY KEY` |
| 필수값 | `NOT NULL` | `name VARCHAR(50) NOT NULL` |
| 필수 + 중복 금지 | `NOT NULL UNIQUE` | `email VARCHAR(100) NOT NULL UNIQUE` |
| 테이블 만들기 | `CREATE TABLE` | `CREATE TABLE students ( … );` |
| 테이블 목록 | `SHOW TABLES` | `SHOW TABLES;` |
| 테이블 구조 보기 | `DESCRIBE` | `DESCRIBE students;` |
| 한 행 추가 | `INSERT INTO … VALUES` | `INSERT INTO students (name, email, registered_date) VALUES ('한코딩', 'han@example.com', '2026-11-16');` |
| 여러 행 추가 | `VALUES (…), (…)` | `VALUES ('김자바', …), ('이리액트', …);` |
| 값 없음 저장 | `NULL` (따옴표 없이) | `VALUES ('박스프링', 'spring@example.com', NULL);` |
| 모두 조회 | `SELECT * FROM` | `SELECT * FROM students;` |
| 일부 열 조회 | `SELECT 열, 열 FROM` | `SELECT name, email FROM students;` |

## 확인 문제

<details><summary>Q. 테이블을 만들기 전에 무엇을 정해야 하는가? 이번 학생 테이블의 규칙은?</summary>

**어떤 정보(열)를 저장하고 어떤 규칙을 적용할지** 정한다. 이번 규칙: 학생 번호는 자동 부여, 이름·이메일은 필수, 이메일은 중복 금지, 등록일은 날짜이며 모르면 비워 둘 수 있다.
</details>

<details><summary>Q. 전화번호는 숫자로만 되어 있는데 왜 `INT`가 아니라 문자열로 저장하는가?</summary>

앞자리 `0`이나 하이픈을 **유지해야** 하고, **계산할 값도 아니기** 때문이다.
</details>

<details><summary>Q. `VARCHAR(50)` 열에는 항상 50자를 채워야 하는가?</summary>

아니다. **최대** 50자까지 저장할 수 있다는 뜻이다. `한코딩`처럼 짧은 값도 저장된다.
</details>

<details><summary>Q. 이름으로 학생을 구분하면 무엇이 문제인가? 기본키에는 어떤 규칙이 있는가?</summary>

이름이 같은 **다른 학생**을 구분할 수 없다. 그래서 고유 번호(`id`)를 기본키로 둔다. 기본키는 **중복 불가**, **`NULL` 불가**다.
</details>

<details><summary>Q. `AUTO_INCREMENT`로 받은 번호가 1, 2, 3, 5처럼 중간이 비었다. 오류인가?</summary>

아니다. 자동 번호는 행을 구분하는 **식별자**일 뿐이다. 삭제나 **입력 실패에서도 번호가 소모**되어 건너뛸 수 있다. 학생 수나 연속 번호로 생각하지 않는다.
</details>

<details><summary>Q. `NOT NULL`은 무엇을 막고, 무엇은 막지 못하는가?</summary>

`NULL`(값 없음) 저장을 막는다. 하지만 **빈 문자열 `''`이나 공백 `'   '`은 막지 못한다** (`NULL`과 다른 값이기 때문). 실제 서비스에서는 따로 검사한다.
</details>

<details><summary>Q. `email VARCHAR(100) NOT NULL UNIQUE`는 어떤 의미인가?</summary>

최대 100자 문자열이고, **반드시 입력**해야 하며(`NOT NULL`), **이미 저장된 이메일과 겹칠 수 없다**(`UNIQUE`).
</details>

<details><summary>Q. `CREATE TABLE` 괄호 안에서 쉼표는 어디에 넣는가?</summary>

**열 정의 사이**에 넣고, **마지막 열 뒤에는 넣지 않는다.**
</details>

<details><summary>Q. `INSERT INTO students (name, email, registered_date) VALUES (...)`에서 `id`를 빼도 되는 이유와 주의할 점은?</summary>

`id`는 `AUTO_INCREMENT`라 **MySQL이 자동으로 부여**하기 때문이다. 열 목록과 `VALUES`의 **값 순서를 맞춰야** 하고, 문자열·날짜는 작은따옴표로 감싼다.
</details>

<details><summary>Q. `NULL`, `'NULL'`, `''`은 각각 무엇인가?</summary>

`NULL` = 값이 없거나 아직 정해지지 않음, `'NULL'` = N·U·L·L 글자 네 개로 된 **문자열**, `''` = 길이 0인 **빈 문자열**. `NULL`에는 따옴표를 붙이지 않는다.
</details>

<details><summary>Q. 이미 있는 이메일로 학생을 추가하면 어떻게 되는가? 이름을 바꾸면 해결되는가?</summary>

`email`의 `UNIQUE` 때문에 **`Duplicate entry`** 오류가 나고 저장되지 않는다. 중복이 금지된 것은 **이메일**이므로 이름을 바꿔도 해결되지 않는다. 다른 이메일을 써야 한다.
</details>

<details><summary>Q. 이름에 `NULL`을 넣으면 어떤 오류가 나는가?</summary>

`name`에 `NOT NULL`이 있어 **`cannot be null`** 오류가 나고 저장되지 않는다.
</details>

<details><summary>Q. `Table 'students' already exists` 오류가 나면 어떻게 하는가?</summary>

같은 이름의 테이블이 이미 있다는 뜻이다. **삭제부터 하지 말고** `DESCRIBE students;`로 기존 구조를 확인한다.
</details>
