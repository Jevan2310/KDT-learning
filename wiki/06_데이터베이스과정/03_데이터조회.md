# 03. 필요한 데이터 조회하기 — `SELECT`·`WHERE`·`LIKE`·`ORDER BY`·`LIMIT`

> 과정: 데이터베이스과정 · [노션 원문](https://app.notion.com/p/41a848f71c9b801cac2fecd67800bd30) · 최종 갱신일: 2026-11-18

## 한눈에 보기
- **`SELECT 열 FROM 테이블`** — `*`는 모든 열, 필요한 열만 쉼표로 나열할 수 있다. 조회할 열을 바꿔도 **저장된 데이터는 바뀌지 않는다.**
- **`WHERE`** 로 조회할 **행**의 조건을 준다. SQL 조건의 `=`는 대입이 아니라 **비교**다. 비교 연산자 `=`, `<>`, `>`, `>=`, `<`, `<=`는 숫자·날짜에도 쓴다.
- **`AND`**(모두 만족) · **`OR`**(하나 이상 만족). `AND`가 먼저 처리되므로 섞어 쓸 때는 **괄호**로 묶는다. **`LIKE`** + `%`로 이름 일부를 검색한다.
- **`ORDER BY 열 ASC/DESC`** 로 정렬 (지정하지 않으면 순서 보장 없음), **`LIMIT n`** 으로 최대 개수 제한 (의미 있게 자르려면 정렬과 함께).
- `NULL`은 `= NULL`로 찾을 수 없다. **`IS NULL` / `IS NOT NULL`** 을 쓴다.
- 작성 순서: `SELECT → FROM → WHERE → ORDER BY → LIMIT`. 어렵다면 한 단계씩 붙이며 결과를 확인한다.

## 학습 목표
- 필요한 열만 선택해 조회한다.
- 조건에 맞는 데이터를 찾는다.
- 여러 조건을 조합하고 이름을 검색한다.
- 조회 결과를 정렬하고 개수를 제한한다.
- `NULL`인 데이터를 올바르게 조회한다.

## 핵심 개념

### 1. 실습 데이터 확인
[02](02_테이블-데이터추가.md)에서 저장한 학생을 조회한다.

- **MySQL**: 먼저 `USE school;`
- **H2**: `school` 실습 DB에 연결하고 `USE` 명령은 생략한다.

```sql
SELECT * FROM students;
```

| name | email | registered_date |
|---|---|---|
| 한코딩 | han@example.com | 2026-11-16 |
| 김자바 | java@example.com | 2026-11-17 |
| 이리액트 | react@example.com | 2026-11-18 |
| 박스프링 | spring@example.com | NULL |
| 정데이터 | data@example.com | 2026-11-20 |

- `id`는 각자의 실행 과정에 따라 다를 수 있다.
- 이번 조회 예제는 MySQL과 H2(기본 모드·MySQL 호환 모드)에서 함께 쓸 수 있다.

### 2. 필요한 열만 조회 — `SELECT`
`*`는 **테이블의 모든 열**이다. 이름과 이메일만 필요하면 열 이름을 직접 쓴다.

```sql
SELECT name, email
FROM students;
```

| name | email |
|---|---|
| 한코딩 | han@example.com |
| 김자바 | java@example.com |
| 이리액트 | react@example.com |
| 박스프링 | spring@example.com |
| 정데이터 | data@example.com |

```sql
SELECT 조회할_열
FROM 테이블_이름;
```

- 여러 열은 **쉼표**로 구분한다. **작성한 순서대로** 결과의 열이 표시된다 (`SELECT email, name` → 이메일이 먼저).
- **조회할 열을 바꿔도 저장된 테이블의 구조나 데이터는 바뀌지 않는다.**

### 3. 조건에 맞는 행 찾기 — `WHERE`

```sql
SELECT *
FROM students
WHERE name = '한코딩';
```

```text
students 테이블에서
이름이 '한코딩'인 행의
모든 열을 조회
```

- **문자열은 작은따옴표**로 감싼다: `WHERE email = 'java@example.com'`
- **숫자는 따옴표 없이**: `WHERE id = 1` — 그 번호가 없으면 결과가 비어 있을 수 있다. 내 데이터의 실제 번호를 확인한다.
- **SQL의 `=`는 비교다.** JavaScript에서는 `===`로 비교했지만 SQL 조건에서는 `=`를 쓴다. 이름을 바꾸는 명령이 아니라 **이름이 같은지 확인하는 조건**이다.

### 4. 비교 연산자로 범위 조회

| 연산자 | 의미 |
|---|---|
| `=` | 같다 |
| `<>` | 다르다 |
| `>` | 크다 |
| `>=` | 크거나 같다 |
| `<` | 작다 |
| `<=` | 작거나 같다 |

```sql
SELECT *
FROM students
WHERE name <> '한코딩';
```

```sql
SELECT *
FROM students
WHERE id >= 3;
```

**날짜도 비교할 수 있다**

```sql
SELECT *
FROM students
WHERE registered_date >= '2026-11-18';
```

- 등록일이 2026-11-18이거나 그 이후인 학생. **`registered_date`가 `NULL`인 학생(박스프링)은 포함되지 않는다.**

### 5. 여러 조건 연결 — `AND`, `OR`

**`AND` — 두 조건을 모두 만족**

```sql
SELECT *
FROM students
WHERE registered_date >= '2026-11-17'
  AND registered_date <= '2026-11-18';
```

**`OR` — 하나 이상의 조건을 만족**

```sql
SELECT *
FROM students
WHERE name = '한코딩'
   OR name = '김자바';
```

**`AND`와 `OR`를 함께 쓸 때 — 괄호로 묶는다**

```sql
SELECT *
FROM students
WHERE (name = '한코딩' OR name = '김자바')
  AND registered_date >= '2026-11-17';
```

```text
이름이 한코딩 또는 김자바인 학생 중에서
등록일이 2026년 11월 17일 이상인 학생
```

- **`AND`가 `OR`보다 먼저 처리**되므로, 괄호를 빼면 의도와 다른 결과가 나올 수 있다.

> 💡 보충: 괄호를 빼면 `name = '한코딩' OR (name = '김자바' AND registered_date >= '2026-11-17')`로 해석된다. 그래서 등록일이 11-16인 한코딩도 결과에 들어온다. 괄호가 있으면 한코딩은 빠지고 김자바만 나온다.

### 6. 이름 일부로 검색 — `LIKE`
`LIKE`는 문자열의 **패턴**을 비교한다. `%`는 **글자가 없거나 여러 글자가 올 수 있는 자리**다.

| 조건 | 의미 |
|---|---|
| `'김%'` | 김으로 시작 |
| `'%코딩'` | 코딩으로 끝남 |
| `'%리액트%'` | 리액트가 포함됨 |

```sql
SELECT *
FROM students
WHERE name LIKE '김%';
```

```sql
SELECT *
FROM students
WHERE name LIKE '%코딩';
```

```sql
SELECT *
FROM students
WHERE name LIKE '%리액트%';
```

**`=`와 `LIKE`는 다르다**

| 조건 | 의미 |
|---|---|
| `WHERE name = '김'` | 이름 **전체**가 `김`이어야 함 |
| `WHERE name LIKE '김%'` | 이름이 `김`으로 **시작**하면 됨 |

### 7. 정렬 — `ORDER BY`
**정렬 조건을 지정하지 않으면 조회 결과의 순서는 보장되지 않는다.**

```sql
SELECT *
FROM students
ORDER BY id ASC;
```

```sql
SELECT *
FROM students
ORDER BY id DESC;
```

| 정렬 | 숫자 | 날짜 |
|---|---|---|
| `ASC` (오름차순) | 작은 값 → 큰 값 | 이전 날짜 → 이후 날짜 |
| `DESC` (내림차순) | 큰 값 → 작은 값 | 이후 날짜 → 이전 날짜 |

- `ASC`는 생략할 수 있지만, 처음에는 의미를 익히려고 적는다.

**조건 + 정렬, 정렬 기준 여러 개**

```sql
SELECT *
FROM students
WHERE registered_date IS NOT NULL
ORDER BY registered_date DESC, id DESC;
```

```text
등록일이 늦은 학생부터 표시
          ↓
등록일이 같으면 id가 큰 학생부터 표시
```

- 정렬 기준이 여러 개면 **앞의 기준부터** 적용한다.
- **정렬은 결과의 순서만 바꾼다.** 저장된 데이터를 수정하지 않는다.

### 8. 일부만 조회 — `LIMIT`

```sql
SELECT *
FROM students
ORDER BY id DESC
LIMIT 3;
```

- 학생 번호가 큰 순서로 **최대** 세 명. 데이터가 세 명보다 적으면 있는 만큼만 반환한다.

```sql
SELECT *
FROM students
LIMIT 3;
```

- 실행은 되지만 **어떤 세 명이 나올지 기준이 보장되지 않는다.** 의미 있는 일부를 가져오려면 **정렬 기준을 함께** 지정한다.
- `id`가 크다고 등록일이 최근인 것은 아니다. **"최근 등록일" 기준이면 `registered_date`로 정렬**한다.

### 9. 값이 없는 데이터 찾기 — `IS NULL`

```sql
SELECT *
FROM students
WHERE registered_date = NULL;
```

- 이렇게 쓰면 **의도한 결과(박스프링)가 나오지 않는다.** `NULL`은 일반 값처럼 `=`로 비교하지 않는다.

```sql
SELECT *
FROM students
WHERE registered_date IS NULL;
```

```sql
SELECT *
FROM students
WHERE registered_date IS NOT NULL;
```

| 조건 | 의미 |
|---|---|
| `IS NULL` | 값이 없음 |
| `IS NOT NULL` | 값이 있음 |

> "NULL은 비교할 값 자체가 없는 상태이므로, 같은지 비교하는 대신 값이 없는 상태인지를 확인한다."

### 10. 배운 문법 조합하기
조건: 등록일 2026-11-17 이상 · 이름에 `자바` 또는 `리액트` 포함 · 등록일 늦은 순, 같으면 번호 큰 순 · 최대 두 명 · 이름·이메일·등록일 표시.

```sql
SELECT name, email, registered_date
FROM students
WHERE registered_date >= '2026-11-17'
  AND (
      name LIKE '%자바%'
      OR name LIKE '%리액트%'
  )
ORDER BY registered_date DESC, id DESC
LIMIT 2;
```

```sql
SELECT 조회할_열
FROM 테이블
WHERE 조건
ORDER BY 정렬_기준
LIMIT 최대_개수;
```

**한 번에 쓰기 어렵다면 단계를 나눈다** — 각 단계에서 결과를 보면 어느 조건 때문에 데이터가 줄었는지 알기 쉽다.

```text
전체 조회
    ↓
필요한 열 선택
    ↓
조건 추가
    ↓
정렬 추가
    ↓
개수 제한
```

> 💡 보충: 02의 데이터 그대로라면 결과는 `이리액트 | react@example.com | 2026-11-18`, `김자바 | java@example.com | 2026-11-17` 두 줄이다.

### 정리

| 문법 | 역할 | 예 |
|---|---|---|
| `SELECT` | 조회할 열 선택 | `SELECT name, email` |
| `FROM` | 조회할 테이블 지정 | `FROM students` |
| `WHERE` | 조회할 행의 조건 지정 | `WHERE id = 1` |
| `AND` | 조건을 모두 만족 | `조건1 AND 조건2` |
| `OR` | 하나 이상의 조건 만족 | `조건1 OR 조건2` |
| `LIKE` | 문자열 패턴 검색 | `LIKE '%코딩%'` |
| `ORDER BY` | 결과 정렬 | `ORDER BY id DESC` |
| `ASC` | 오름차순 | 작은 값부터 |
| `DESC` | 내림차순 | 큰 값부터 |
| `LIMIT` | 조회 개수 제한 | `LIMIT 3` |
| `IS NULL` | 값이 없는 행 조회 | `registered_date IS NULL` |
| `IS NOT NULL` | 값이 있는 행 조회 | `registered_date IS NOT NULL` |

## 실습 정리

### 한 일
02에서 만든 학생 다섯 명을 대상으로 열 선택, 조건, 검색, 정렬, 개수 제한, `NULL` 조회를 차례로 연습했다. **데이터는 바꾸지 않는다** (조회만).

### 섹션별 🛠️ 실습 SQL

```sql
-- 2. 학생 이름과 등록일만 조회
SELECT name, registered_date
FROM students;

-- 3. 이메일이 react@example.com인 학생
SELECT *
FROM students
WHERE email = 'react@example.com';

-- 4. 2026년 11월 18일 전에 등록한 학생의 이름과 등록일
SELECT name, registered_date
FROM students
WHERE registered_date < '2026-11-18';

-- 5. 이름이 이리액트 또는 정데이터인 학생
SELECT *
FROM students
WHERE name = '이리액트'
   OR name = '정데이터';

-- 6. 이름에 '데이터'가 포함된 학생
SELECT *
FROM students
WHERE name LIKE '%데이터%';

-- 7. 이름 오름차순, 같은 이름이면 번호 오름차순
SELECT *
FROM students
ORDER BY name ASC, id ASC;

-- 8. 번호가 작은 순서로 두 명의 이름과 이메일
SELECT name, email
FROM students
ORDER BY id ASC
LIMIT 2;

-- 9. 등록일이 없는 학생의 이름과 이메일
SELECT name, email
FROM students
WHERE registered_date IS NULL;
```

### 결과가 예상과 다를 때

| 상황 | 확인할 내용 |
|---|---|
| 결과가 한 건도 없음 | 조건에 맞는 데이터가 실제로 있는지 |
| 이름 검색이 안 됨 | 오타·공백, `=`와 `LIKE` 사용 |
| 일부 학생이 조건에서 빠짐 | 비교 대상이 `NULL`인지 |
| 정렬 순서가 일정하지 않음 | `ORDER BY`와 같은 값일 때의 추가 정렬 기준 |
| `LIMIT 3`인데 세 명보다 적음 | 조건을 만족하는 데이터가 세 명 이상인지 |
| 다른 데이터가 보임 | 접속한 서버와 데이터베이스 |

- 오류 없이 실행됐는데 결과가 비어 있으면, 문법이 틀렸다기보다 **조건을 만족하는 데이터가 없는 경우**일 수 있다. 먼저 전체 조회로 현재 데이터를 확인한다.

```sql
SELECT *
FROM students
ORDER BY id ASC;
```

## 헷갈리기 쉬운 점
- **`SELECT`로 고른 열은 결과에만 영향을 준다.** 테이블 구조·데이터는 그대로다.
- **SQL 조건의 `=`는 비교다** (JavaScript의 `===` 역할). 값을 바꾸는 것이 아니다.
- **문자열·날짜는 작은따옴표, 숫자는 따옴표 없이.**
- **"다르다"는 `<>`.**
- **날짜 비교 조건에는 `NULL`인 행이 포함되지 않는다.** 박스프링은 `>=`에도 `<`에도 안 나온다.
- **`AND`가 `OR`보다 먼저다.** 섞어 쓰면 괄호로 묶는다.
- **`= '김'`(전체 일치) ≠ `LIKE '김%'`(시작 일치).** `%`는 "0글자 이상".
- **`ORDER BY`가 없으면 순서가 보장되지 않는다.** 같은 값이 있으면 두 번째 기준(`id`)을 붙인다.
- **`LIMIT`만 쓰면 어떤 행이 나올지 모른다.** 정렬과 함께 쓴다.
- **`id`가 크다 ≠ 최근 등록.** 최근 등록이면 `registered_date`로 정렬한다.
- **`= NULL`은 안 된다. `IS NULL` / `IS NOT NULL`.**
- **결과가 비어도 오류가 아닐 수 있다.** 조건에 맞는 데이터가 없는 것일 수 있다.

## 빠른 참고 (치트시트)

| 하고 싶은 것 | 쓰는 것 | 예시 |
|---|---|---|
| 모든 열 | `*` | `SELECT * FROM students;` |
| 필요한 열만 | 열 이름 나열 | `SELECT name, email FROM students;` |
| 같은 값 찾기 | `WHERE 열 = 값` | `WHERE name = '한코딩'` |
| 다른 값 찾기 | `<>` | `WHERE name <> '한코딩'` |
| 범위 (숫자) | `>=`, `<` … | `WHERE id >= 3` |
| 범위 (날짜) | 날짜도 비교 | `WHERE registered_date >= '2026-11-18'` |
| 모두 만족 | `AND` | `WHERE registered_date >= '2026-11-17' AND registered_date <= '2026-11-18'` |
| 하나 이상 만족 | `OR` | `WHERE name = '한코딩' OR name = '김자바'` |
| AND·OR 섞기 | 괄호 | `WHERE (name = '한코딩' OR name = '김자바') AND registered_date >= '2026-11-17'` |
| ~로 시작 | `LIKE '김%'` | `WHERE name LIKE '김%'` |
| ~로 끝남 | `LIKE '%코딩'` | `WHERE name LIKE '%코딩'` |
| ~ 포함 | `LIKE '%리액트%'` | `WHERE name LIKE '%리액트%'` |
| 오름차순 정렬 | `ORDER BY 열 ASC` | `ORDER BY id ASC` |
| 내림차순 정렬 | `ORDER BY 열 DESC` | `ORDER BY id DESC` |
| 정렬 기준 여러 개 | 쉼표 | `ORDER BY registered_date DESC, id DESC` |
| 최대 n개 | `ORDER BY … LIMIT n` | `ORDER BY id DESC LIMIT 3` |
| 값 없는 행 | `IS NULL` | `WHERE registered_date IS NULL` |
| 값 있는 행 | `IS NOT NULL` | `WHERE registered_date IS NOT NULL` |

## 확인 문제

<details><summary>Q. `SELECT *`와 `SELECT name, email`의 차이는? `SELECT email, name`으로 쓰면 테이블의 열 순서가 바뀌는가?</summary>

`*`는 모든 열, `name, email`은 그 두 열만 조회한다. 결과의 열은 **작성한 순서**대로 표시될 뿐이고, **저장된 테이블의 구조나 데이터는 바뀌지 않는다.**
</details>

<details><summary>Q. `WHERE name = '한코딩'`의 `=`는 무엇인가?</summary>

이름이 `'한코딩'`과 **같은지 확인하는 비교**다 (JavaScript의 `===` 역할). 이름을 바꾸는 명령이 아니다.
</details>

<details><summary>Q. `WHERE email = 'java@example.com'`과 `WHERE id = 1`에서 따옴표를 다르게 쓰는 이유는?</summary>

문자열(·날짜)은 **작은따옴표**로 감싸고, 숫자는 일반적으로 **따옴표 없이** 쓴다.
</details>

<details><summary>Q. "한코딩이 아닌 학생"은 어떻게 조회하는가?</summary>

`WHERE name <> '한코딩'` — `<>`는 "다르다"이다.
</details>

<details><summary>Q. `WHERE registered_date >= '2026-11-18'`의 결과에 등록일이 `NULL`인 박스프링이 포함되는가?</summary>

포함되지 않는다. `NULL`인 행은 날짜 비교 조건을 만족하지 않는다.
</details>

<details><summary>Q. `AND`와 `OR`의 차이는? 둘을 함께 쓸 때 괄호가 필요한 이유는?</summary>

`AND`는 조건을 **모두** 만족, `OR`는 **하나 이상** 만족. **`AND`가 `OR`보다 먼저 처리**되므로 괄호 없이 섞으면 의도와 다른 결과가 나올 수 있다. `(name = '한코딩' OR name = '김자바') AND …`처럼 묶는다.
</details>

<details><summary>Q. `LIKE '김%'`, `LIKE '%코딩'`, `LIKE '%리액트%'`는 각각 무엇을 찾는가? `= '김'`과 `LIKE '김%'`의 차이는?</summary>

김으로 시작 / 코딩으로 끝남 / 리액트가 포함. `%`는 글자가 없거나 여러 글자가 올 수 있는 자리다. `= '김'`은 이름 **전체**가 `김`이어야 하고, `LIKE '김%'`는 `김`으로 **시작**하면 된다.
</details>

<details><summary>Q. `ORDER BY`를 쓰지 않으면 결과 순서는? `ORDER BY registered_date DESC, id DESC`는 어떻게 정렬하는가?</summary>

순서가 **보장되지 않는다.** 정렬 기준이 여러 개면 앞에서부터 적용한다: 등록일이 늦은 학생부터, **등록일이 같으면** id가 큰 학생부터.
</details>

<details><summary>Q. `ORDER BY` 없이 `LIMIT 3`만 쓰면 어떤 문제가 있는가?</summary>

실행은 되지만 **어떤 세 명이 선택될지 일정한 기준이 없다.** 의미 있는 일부를 가져오려면 정렬 기준을 함께 지정한다.
</details>

<details><summary>Q. "최근 등록한 학생 3명"을 구할 때 `ORDER BY id DESC LIMIT 3`이 맞는가?</summary>

아니다. `id`가 크다고 등록일이 최근인 것은 아니다. **`registered_date`를 기준으로 정렬**해야 한다.
</details>

<details><summary>Q. 등록일이 없는 학생을 찾을 때 왜 `= NULL`이 아니라 `IS NULL`을 쓰는가?</summary>

`NULL`은 **비교할 값 자체가 없는 상태**라서 `=`로 같은지 비교할 수 없다. 대신 값이 없는 상태인지 `IS NULL`로 확인한다 (값이 있는 행은 `IS NOT NULL`).
</details>

<details><summary>Q. SQL을 오류 없이 실행했는데 결과가 비어 있다. 무엇을 의심하는가?</summary>

문법 오류가 아니라 **조건을 만족하는 데이터가 없는 경우**일 수 있다. 전체 조회(`SELECT * FROM students ORDER BY id ASC;`)로 현재 데이터를 먼저 확인한다. 오타·공백, `=`/`LIKE`, `NULL`, 접속한 DB도 본다.
</details>

<details><summary>Q. `SELECT`·`FROM`·`WHERE`·`ORDER BY`·`LIMIT`의 작성 순서는?</summary>

`SELECT 조회할_열 FROM 테이블 WHERE 조건 ORDER BY 정렬_기준 LIMIT 최대_개수;`
</details>
