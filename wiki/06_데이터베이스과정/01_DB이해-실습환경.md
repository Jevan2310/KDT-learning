# 01. 데이터베이스 이해와 실습 환경 준비 — DB·DBMS·SQL과 `school` 데이터베이스

> 과정: 데이터베이스과정 · [노션 원문](https://app.notion.com/p/41a848f71c9b80a6bff5f6855a50d876) · 최종 갱신일: 2026-11-18

## 한눈에 보기
- 변수·배열에 담은 데이터는 **실행 중인 프로그램의 메모리**에 있어서, 프로그램을 끝내면 사라진다. **데이터베이스**에 저장하면 다시 실행해도 남고, 필요한 정보를 찾아 쓸 수 있다.
- **데이터베이스**(모아 관리하는 데이터 집합, 예: `school`) · **DBMS**(DB를 관리하는 프로그램, 예: MySQL) · **SQL**(DBMS에 작업을 요청하는 언어). → "MySQL에 SQL로 명령을 보내 DB의 정보를 다룬다."
- 관계형 DB는 데이터를 **테이블**(표)로 저장한다. **열** = 저장할 항목, **행** = 데이터 한 건. DB 하나에 테이블 여러 개.
- **MySQL**(저장·SQL 처리)과 **DBeaver**(접속해서 SQL 작성·결과 확인)는 다른 프로그램이다. 접속 정보는 **Host**(`localhost`) · **Port**(`3306`) · **Username**(`root`) · **Password**.
- `CREATE DATABASE IF NOT EXISTS school CHARACTER SET utf8mb4;` → `USE school;` → `SELECT DATABASE();`가 `school`이면 준비 완료.

> 설치·연결 절차(MySQL 8.4 MSI, MySQL Configurator, DBeaver 연결 테스트)는 [MySQL-DBeaver](../00_개발환경/MySQL-DBeaver.md)에 따로 정리했다. 이 파일은 개념과 SQL 중심이다.

## 학습 목표
- 데이터베이스가 필요한 이유를 이해한다.
- 데이터베이스·DBMS·SQL의 관계를 구분한다.
- 테이블·행·열의 의미를 설명한다.
- MySQL과 DBeaver를 설치하고 연결한다.
- SQL로 실습용 데이터베이스를 만든다.

## 핵심 개념

### 1. 반영구적인 데이터를 변수에 저장하면 안 될까?
앞에서 학생 관리 프로그램을 만들 때 배열에 학생 정보를 저장했다.

```javascript
const students = [
  { id: 1, name: "한코딩" },
  { id: 2, name: "김자바" },
];
```

- 이 배열은 **실행 중인 프로그램의 메모리**에 있다. 파일이나 DB에 따로 저장하지 않으면 **프로그램이 종료될 때 변경 내용이 사라진다.**
- 다시 실행하면 코드에 적힌 초기 데이터로 시작한다.

```text
프로그램 실행
     ↓
학생 추가
     ↓
프로그램 종료
     ↓
다시 실행하면 추가했던 정보가 없음
```

- 실제 서비스는 다시 실행해도 회원 정보·게시글이 남아 있어야 한다. → **데이터베이스를 이용하면 데이터를 지속적으로 저장하고 필요한 정보를 찾아 쓸 수 있다.**
- 파일에 저장하는 방법도 있다. 하지만 DBMS는 저장뿐 아니라 **검색, 동시 사용, 데이터 규칙, 거래(트랜잭션) 처리**까지 관리해 준다.

> 💡 보충: Node 콘솔 학생 관리([02_콘솔-학생관리](../02_Node과정/02_콘솔-학생관리.md))와 Spring 학생 등록([04_폼-학생등록](../03_Spring과정/04_폼-학생등록.md) "서버를 재시작하면")에서 데이터가 사라졌던 것이 바로 이 문제다.

### 2. 데이터베이스·DBMS·SQL

| 용어 | 의미 | 이번 수업의 예 |
|---|---|---|
| 데이터베이스(DB) | 체계적으로 모아 관리하는 데이터의 집합 | 학생·반 정보를 저장하는 `school` |
| DBMS (DataBase Management System) | 데이터베이스를 만들고 관리하는 프로그램(상품) | MySQL(MariaDB) |
| SQL | DBMS에 데이터 작업을 요청하는 언어 | 조회·추가·수정·삭제 명령 |

> "MySQL이라는 관리 프로그램에 SQL로 명령을 보내서, 데이터베이스에 저장된 정보를 다룬다."

```text
SQL로 요청
    ↓
MySQL이 요청 처리
    ↓
데이터 저장 또는 조회
```

- Spring 과정에서 쓴 **H2도 DBMS**다. 이번에는 MySQL을 **따로 실행**하고 외부 도구(DBeaver)에서 접속한다.

**MySQL과 SQL은 다른 것이다**
- **SQL**: 데이터 작업을 요청하는 **언어**
- **MySQL**: SQL을 이해하고 실행하는 **DBMS**
- 다른 DBMS도 SQL을 쓰지만, 일부 문법과 기능은 DBMS마다 다르다.

### 3. 테이블·행·열
MySQL은 **관계형 DBMS**다. 데이터를 **테이블이라는 표 형태로 저장**한다고 생각하면 쉽다.

| id | name | email |
|---|---|---|
| 1 | 한코딩 | han@example.com |
| 2 | 김자바 | java@example.com |
| 3 | 이리액트 | react@example.com |

| 용어 | 의미 | 위 표에서 |
|---|---|---|
| 테이블 (table) | 같은 종류의 데이터를 모아 놓는 구조 | 표 전체 = 학생 테이블 `students` |
| 열 (column) | 저장할 정보의 **항목**. 열마다 숫자·문자·날짜 등 값의 종류를 정할 수 있다 | `id`(학생 번호), `name`(이름), `email`(이메일) |
| 행 (row) | 실제로 저장된 **데이터 한 건** | `1 \| 한코딩 \| han@example.com` = 학생 한 명 |

**전체 구조** — **하나의 데이터베이스 안에 여러 테이블**을 만들 수 있다.

```text
MySQL
└─ school 데이터베이스
   ├─ students 테이블
   │  └─ 학생 정보
   └─ classes 테이블
      └─ 반 정보
```

### 4. MySQL과 DBeaver의 역할

| 프로그램 | 역할 |
|---|---|
| MySQL Community Server | 데이터를 저장하고 SQL을 처리 |
| DBeaver Community | MySQL에 접속해 SQL을 작성하고 결과를 확인 |

```text
DBeaver
"학생 목록을 조회해 주세요."
          ↓ SQL
MySQL
          ↓ 결과
DBeaver 화면에 표시
```

- **DBeaver를 설치했다고 MySQL까지 설치되는 것은 아니다.**
- 반대로 DBeaver를 종료해도 MySQL 서버가 실행 중이면 다른 프로그램에서 계속 접속할 수 있다.
- 나중에는 Spring도 MySQL에 접속한다 ([06](06_Spring-MyBatis.md)).

```text
DBeaver ──→ MySQL ←── Spring
```

### 5. 접속 정보 — 호스트·포트·사용자·비밀번호
DBeaver에서 MySQL에 연결할 때 입력하는 값이다.

| 항목 | 질문 | 이번 실습 |
|---|---|---|
| Host | 어디에 있는 DB인가? | `localhost` = **현재 내 컴퓨터** |
| Port | 어떤 접속 창구를 쓰는가? | `3306` (MySQL 기본 포트) |
| Username / Password | 누구의 권한으로 접속하는가? | 설치 때 정한 `root` 계정과 비밀번호 |
| Database | 처음 연결할 DB | 우선 비워 두기 |

- 같은 컴퓨터에서도 서버 프로그램이 여러 개 실행될 수 있다. **포트 번호로 접속 대상을 구분**한다.

| 프로그램 | 앞에서 쓴 포트 |
|---|---|
| Vite 개발 서버 | `5173` |
| Spring 서버 | `8080` |
| MySQL 서버 | `3306` |

- `root`는 MySQL의 **관리자 계정**이다. **MySQL 계정은 Windows 로그인 계정이나 MySQL 웹사이트 계정과 별개다.**
- **드라이버** = DBeaver가 MySQL과 통신하게 도와주는 연결용 라이브러리. 처음 연결 테스트 때 다운로드 안내가 나온다.

### 6. SQL 작성 기본 규칙
DBeaver에서 연결 → 마우스 오른쪽 → **SQL 편집기 → 새 SQL 스크립트**를 열고 실행한다.

```sql
SELECT VERSION(), CURRENT_USER();
```

- MySQL **버전**과 **현재 인증된 계정**을 조회한다. 테이블이 없어도 실행된다.
- 문장을 선택하고 **SQL 문 실행** 버튼이나 `Ctrl + Enter`로 실행한다. 결과 영역에 값이 나오면 SQL 요청과 응답이 정상이다.

```sql
SELECT VERSION();
```

- 명령문 끝에는 보통 세미콜론 `;`을 붙인다.
- 수업에서는 **SQL 키워드는 대문자**, **데이터베이스·테이블 이름은 소문자**로 쓴다.
- 여러 문장이 있으면 **실행할 문장을 선택해** 실행한다.

```sql
-- MySQL 버전 확인
SELECT VERSION();
```

- `--` 뒤에 **공백을 한 칸** 넣는다. 주석은 실행할 명령이 아니라 읽는 사람을 위한 설명이다.

### 7. 실습용 데이터베이스 만들기 — `CREATE DATABASE`·`USE`

```sql
CREATE DATABASE IF NOT EXISTS school
CHARACTER SET utf8mb4;
```

| 코드 | 의미 |
|---|---|
| `CREATE DATABASE` | 데이터베이스 생성 |
| `IF NOT EXISTS` | 같은 이름이 없을 때만 생성 |
| `school` | 만들 데이터베이스 이름 |
| `CHARACTER SET utf8mb4` | 한글·이모지 등을 저장할 수 있는 문자 집합 지정 |

- 이 명령을 **다시 실행해도 기존 `school`을 삭제하거나 초기화하지 않는다.**

| SQL | 하는 일 | 확인할 것 |
|---|---|---|
| `SHOW DATABASES;` | 데이터베이스 목록 | 목록에 `school`이 있는지 |
| `USE school;` | **현재 SQL 연결에서** 작업할 DB 선택 | - |
| `SELECT DATABASE();` | 지금 선택된 DB 확인 | 결과가 `school` |
| `SHOW TABLES;` | 현재 DB의 테이블 목록 | 방금 만든 DB면 **비어 있어도 정상** |

- `SHOW DATABASES;`에 다른 이름들도 보일 수 있다. **MySQL이 관리하는 기본 데이터베이스이므로 수정·삭제하지 않는다.**
- 새 연결이나 다른 SQL 편집기를 쓰면 선택 상태가 달라질 수 있다. **실행할 연결과 데이터베이스를 확인하는 습관**을 들인다.

> 💡 보충: 기본 데이터베이스는 보통 `information_schema`, `mysql`, `performance_schema`, `sys`다.

## 실습 정리

### 만든 것
MySQL 서버를 설치하고 DBeaver로 연결한 뒤, 학생·반 정보를 저장할 **`school` 데이터베이스**를 만들었다. 아직 테이블은 없다 (테이블은 [02](02_테이블-데이터추가.md)에서 만든다).

### 단계 흐름
1. MySQL Community Server 8.4 LTS 설치 → MySQL Configurator 설정 (포트 `3306`, `root` 비밀번호, Windows 서비스) — [MySQL-DBeaver](../00_개발환경/MySQL-DBeaver.md) 1~3
2. DBeaver Community 설치 → 새 데이터베이스 연결(MySQL, `localhost:3306`, `root`) → **연결 테스트** 성공 → 저장 — [MySQL-DBeaver](../00_개발환경/MySQL-DBeaver.md) 4~5
3. SQL 편집기에서 `SELECT VERSION(), CURRENT_USER();` 실행
4. `school` 데이터베이스 생성 → 목록 확인 → 선택 → 선택 확인 → 테이블 목록 확인

### 실행한 SQL (순서대로, 한 문장씩 선택해 실행)

```sql
-- 연결 확인
SELECT VERSION(), CURRENT_USER();

-- ① 데이터베이스 생성
CREATE DATABASE IF NOT EXISTS school
CHARACTER SET utf8mb4;

-- ② 생성 결과 확인
SHOW DATABASES;

-- ③ 사용할 데이터베이스 선택
USE school;

-- ④ 선택된 데이터베이스 확인 → school
SELECT DATABASE();

-- ⑤ 현재 테이블 확인 → 아직 비어 있음
SHOW TABLES;
```

```text
school 데이터베이스 생성 완료
            ↓
아직 테이블은 없음
```

- 왼쪽 목록에 `school`이 안 보이면 연결이나 데이터베이스 목록을 **새로고침**한다. DBeaver 버전에 따라 `Schemas` 또는 데이터베이스 항목 아래에 보인다.

## 헷갈리기 쉬운 점
- **SQL ≠ MySQL.** SQL은 언어, MySQL은 그 언어를 실행하는 DBMS다.
- **DBeaver ≠ MySQL.** DBeaver는 접속 도구일 뿐이다. MySQL을 따로 설치·실행해야 한다.
- **MySQL `root` 계정 ≠ Windows 로그인 계정 ≠ MySQL 웹사이트 계정.**
- **서버가 꺼져 있으면 비밀번호가 맞아도 접속할 수 없다.** 먼저 MySQL 서비스가 실행 중인지 본다.
- **`USE school;`은 지금 연결(편집기)에만 적용된다.** 새 편집기를 열면 다시 확인한다.
- **`SHOW TABLES;` 결과가 비어 있는 것은 오류가 아니다.** 아직 테이블을 안 만들었을 뿐이다.
- **`IF NOT EXISTS`가 있으면 다시 실행해도 기존 `school`이 지워지지 않는다.**
- **기본 데이터베이스(목록에 보이는 다른 이름들)는 건드리지 않는다.**
- **오류가 나면 재설치보다 오류 메시지와 연결 정보부터** 확인한다. 설치·접속 오류와 SQL 문법 오류는 구분한다.

**연결이 안 될 때 확인할 것**

| 증상 | 먼저 확인할 내용 |
|---|---|
| `Connection refused`, 연결 실패 | MySQL 서비스가 실행 중인지, 호스트와 포트가 맞는지 |
| `Access denied for user` | 사용자 이름, 비밀번호, 계정 권한 |
| `Unknown database 'school'` | DB를 생성했는지, 연결한 서버가 맞는지 |
| `No database selected` | `USE school;`을 실행했는지 |
| 드라이버 다운로드 실패 | 인터넷 연결과 다운로드 오류 내용 |
| SQL을 실행했는데 목록에 안 보임 | 왼쪽 목록 새로고침, 실제 실행한 연결 확인 |

| 내 컴퓨터의 MySQL에 접속 | Host + Port | `localhost` + `3306` |

## 확인 문제

<details><summary>Q. 배열에 저장한 학생 정보는 왜 프로그램을 다시 실행하면 사라지는가? 데이터베이스를 쓰면 무엇이 달라지는가?</summary>

배열은 **실행 중인 프로그램의 메모리**에 있어서, 파일이나 DB에 따로 저장하지 않으면 프로그램이 끝날 때 변경 내용이 사라지고 다시 실행하면 코드의 초기 데이터로 시작한다. 데이터베이스에 저장하면 프로그램을 다시 실행해도 데이터가 남고, 필요한 정보를 찾아 쓸 수 있다.
</details>

<details><summary>Q. 데이터 저장은 파일로도 할 수 있는데, DBMS는 무엇을 더 해 주는가?</summary>

저장뿐 아니라 **검색, 동시 사용, 데이터 규칙, 거래(트랜잭션) 처리** 등을 관리해 준다.
</details>

<details><summary>Q. 데이터베이스·DBMS·SQL을 구분하면? 이번 수업에서는 각각 무엇인가?</summary>

데이터베이스 = 체계적으로 모아 관리하는 데이터 집합(`school`), DBMS = DB를 만들고 관리하는 프로그램(MySQL), SQL = DBMS에 데이터 작업을 요청하는 언어(조회·추가·수정·삭제 명령). "MySQL에 SQL로 명령을 보내 DB의 정보를 다룬다."
</details>

<details><summary>Q. MySQL과 SQL은 같은 것인가?</summary>

다르다. **SQL은 언어**, **MySQL은 SQL을 이해하고 실행하는 DBMS**다. 다른 DBMS도 SQL을 쓰지만 일부 문법·기능이 다르다.
</details>

<details><summary>Q. 테이블·열·행은 각각 무엇인가? `1 | 한코딩 | han@example.com` 한 줄은 무엇인가?</summary>

테이블 = 같은 종류의 데이터를 모아 놓는 표 형태의 구조, 열 = 저장할 정보의 항목(`id`, `name`, `email`), 행 = 저장된 데이터 한 건. 그 한 줄은 **행**이고 학생 한 명의 정보다.
</details>

<details><summary>Q. MySQL과 DBeaver의 역할은? DBeaver를 설치하면 MySQL도 설치되는가?</summary>

MySQL은 데이터를 저장하고 SQL을 처리하는 서버(DBMS), DBeaver는 MySQL에 접속해 SQL을 작성하고 결과를 보는 도구다. **DBeaver를 설치해도 MySQL은 설치되지 않는다.** DBeaver를 꺼도 MySQL이 실행 중이면 Spring 같은 다른 프로그램은 계속 접속할 수 있다.
</details>

<details><summary>Q. 접속 정보의 Host `localhost`, Port `3306`, Username·Password는 각각 무엇을 뜻하는가?</summary>

Host = 어디에 있는 DB인가 (`localhost` = 현재 내 컴퓨터), Port = 어떤 접속 창구인가 (한 컴퓨터의 여러 서버 프로그램을 구분하는 번호, MySQL 기본 `3306`), Username·Password = 누구의 권한으로 접속하는가 (MySQL이 확인하는 계정 정보, 이번엔 `root`).
</details>

<details><summary>Q. `CREATE DATABASE IF NOT EXISTS school CHARACTER SET utf8mb4;`의 각 부분은? 다시 실행하면 어떻게 되는가?</summary>

`CREATE DATABASE` = DB 생성, `IF NOT EXISTS` = 같은 이름이 없을 때만, `school` = DB 이름, `CHARACTER SET utf8mb4` = 한글·이모지를 저장할 수 있는 문자 집합. 다시 실행해도 **기존 `school`을 삭제·초기화하지 않는다.**
</details>

<details><summary>Q. `USE school;`과 `SELECT DATABASE();`는 각각 무엇을 하는가?</summary>

`USE school;`은 **현재 SQL 연결에서** 작업할 DB를 선택하고, `SELECT DATABASE();`는 지금 선택된 DB를 확인한다 (결과 `school`이면 정상). 새 연결·편집기에서는 선택 상태가 달라질 수 있다.
</details>

<details><summary>Q. `school`을 만든 직후 `SHOW TABLES;` 결과가 비어 있다. 오류인가?</summary>

아니다. 아직 테이블을 만들지 않았기 때문에 **비어 있는 것이 정상**이다.
</details>

<details><summary>Q. `Connection refused`, `Access denied for user`, `No database selected`가 나면 각각 무엇을 먼저 확인하는가?</summary>

`Connection refused` = MySQL 서비스 실행 여부와 호스트·포트, `Access denied for user` = 사용자 이름·비밀번호·권한, `No database selected` = `USE school;`을 실행했는지.
</details>
