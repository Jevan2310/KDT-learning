# 03. 서버에서 데이터 보내기

> 과정: Node과정 · [노션 원문](https://app.notion.com/p/412848f71c9b80f68ef7da7842958383) · 최종 갱신일: 2026-11-12

## 한눈에 보기
- 콘솔 프로그램([02_콘솔-학생관리](02_콘솔-학생관리.md))의 "터미널 입력 → 처리 → 터미널 출력"을 **"브라우저 요청 → 서버 처리 → 브라우저에 응답"** 으로 바꿨다.
- **Express**(Node.js로 웹 서버·API를 쉽게 만드는 프레임워크)를 `npm install express`로 설치하고, `app.get(경로, (req, res) => {…})`로 경로마다 응답을 정한 뒤 `app.listen(3000)`으로 서버를 띄운다.
- 서버는 **종료할 때까지 계속 실행**된다. 코드를 고치면 `Ctrl + C` → `node server.js`로 **직접 재시작**해야 반영된다.
- `http://localhost:3000/students` = 통신 방식 + 내 컴퓨터 + 포트 + 경로. 주소창으로 열면 **GET 요청**이 간다.
- `console.log()`는 **서버 터미널**에, `res.send()`·`res.json()`은 **요청한 브라우저**에 간다. `res.json(students)`로 학생 목록을 **JSON**으로 보냈다. 없는 경로는 `Cannot GET /경로`(404).

## 학습 목표
- 콘솔 프로그램과 서버 프로그램의 차이를 이해한다.
- Express를 설치하고 서버를 실행한다.
- 주소와 포트의 의미를 알아본다.
- GET 요청에 응답한다.
- 학생 목록을 JSON으로 보낸다.

## 핵심 개념

### 1. 콘솔 프로그램에서 서버 프로그램으로

앞에서는 **터미널에서 메뉴를 선택**하고 학생 목록을 출력했다.

```text
사용자가 터미널에 입력
        ↓
프로그램에서 처리
        ↓
터미널에 결과 출력
```

이번에는 **브라우저가 요청**하고, **서버가 응답**하도록 바꾼다.

```text
브라우저에서 주소 접속
        ↓
서버에서 요청 처리
        ↓
브라우저에 결과 응답(Response)
```

| 구분 | 콘솔 학생 관리 | 이번 서버 |
|---|---|---|
| 입력받는 방법 | 터미널 입력 | 브라우저의 요청 |
| 처리할 데이터 | 학생 배열 | 학생 배열 |
| 결과 전달 | `console.log()` | 서버 응답 |

이번에는 입력 메뉴 대신 **미리 작성한 학생 목록을 조회하는 기능**에 집중한다. `readline-sync`는 쓰지 않는다.

### 2. Express란?
Express는 **Node.js에서 웹 서버와 API를 만들기 쉽게 도와주는 프레임워크**다. 👉 [Express 공식 설치 안내](https://expressjs.com/en/starter/installing/)

| 도구 | 역할 |
|---|---|
| JavaScript | 코드를 작성하는 언어 |
| Node.js | JavaScript를 실행하는 환경 |
| Express | 요청과 응답 처리 지원 |
| npm | Express 같은 패키지 설치 |

Node.js만으로도 서버를 만들 수 있지만, 이번에는 Express로 간단하게 작성한다.

### 3. 첫 번째 서버 코드 읽기

```javascript
const express = require("express");

const app = express();
const PORT = 3000;

app.get("/", (req, res) => {
  res.send("안녕하세요, 한코딩 서버입니다!");
});

app.listen(PORT, () => {
  console.log(`서버 실행 중: http://localhost:${PORT}`);
});
```

| 코드 | 역할 |
|---|---|
| `const express = require("express");` | 설치한 Express를 가져온다 (입력 패키지를 가져온 방식과 같다) |
| `const app = express();` | 요청을 처리할 **Express 애플리케이션**을 만든다 |
| `app.get("/", (req, res) => { … });` | `/` 경로로 **GET 요청**이 오면 함수를 실행한다 |
| `(req, res) => { … }` | 서버에 요청이 도착했을 때 실행할 함수 |
| `res.send("…")` | 요청한 쪽에 응답을 보낸다 |
| `app.listen(PORT, () => { … });` | 지정한 포트에서 **요청을 받기 시작**한다. 시작되면 함수 안의 로그를 출력 |

- 이번 프로젝트는 `require()`를 쓴다. `package.json`에 `"type": "module"`을 추가하지 않는다.

### 4. 서버는 계속 실행된다
`node hello.js`([01_백엔드-Node](01_백엔드-Node.md))는 실행 후 바로 끝났지만, 서버는 **한 번 응답한 뒤에도 다음 요청을 받아야** 하므로 계속 실행된다.
- 서버를 쓰는 동안 터미널을 열어 둔다.
- 종료: 그 터미널에서 `Ctrl + C`
- 다시 실행: `node server.js`
- **이번 실행 방식에서는 파일을 저장해도 서버가 자동으로 재시작되지 않는다.** 코드를 고친 뒤에는 ① `Ctrl + C`로 종료 ② `node server.js`로 다시 실행 ③ 브라우저 새로고침.

### 5. 접속 주소 읽기

```text
http://localhost:3000/students
```

| 부분 | 의미 |
|---|---|
| `http` | 통신 방식 |
| `localhost` | 현재 접속하는 내 컴퓨터 |
| `3000` | 연결할 프로그램을 구분하는 **포트** |
| `/students` | 요청 **경로** |

같은 컴퓨터에서도 React 개발 서버와 API 서버를 **포트로 구분해** 각각 실행할 수 있다.

| 주소 예시 | 역할 |
|---|---|
| `http://localhost:5173` | React 개발 서버 |
| `http://localhost:3000` | 학생 데이터를 제공하는 API 서버 |

`localhost`는 **접속하는 사람 자신의 컴퓨터**다. 다른 학생이 같은 주소를 입력하면 그 학생의 컴퓨터에 접속한다.

### 6. GET 요청과 경로 — 라우팅
- **GET**은 데이터를 **조회**할 때 쓰는 HTTP 요청 메서드다.
- 브라우저 주소창에 주소를 입력해 페이지를 열면 보통 그 주소로 GET 요청을 보낸다.

```javascript
app.get("/hello", (req, res) => {
  res.send("반갑습니다!");
});
```

이 코드는 `GET /hello` 요청을 처리한다. **요청 경로에 따라 실행할 함수를 연결하는 것을 라우팅**이라고 한다.

| 이름 | 역할 |
|---|---|
| `req` | 클라이언트가 보낸 **요청 정보** |
| `res` | **응답을 보내는** 데 쓰는 객체 |

`req`, `res`는 매개변수 이름이다. Express가 요청·응답 객체를 넣어 준다.

### 7. 터미널 출력과 응답 구분하기

```javascript
app.get("/hello", (req, res) => {
  console.log("GET /hello 요청이 들어왔습니다.");

  res.send("브라우저에 보내는 응답입니다.");
});
```

| 코드 | 확인하는 곳 |
|---|---|
| `console.log()` | **서버 터미널** |
| `res.send()` | **요청한 브라우저** |

- 브라우저를 새로고침하면 요청이 다시 가고, 터미널에도 로그가 하나 더 찍힌다.
- **`console.log()`만 써서는 브라우저에 응답을 보낼 수 없다.**

### 8. API와 JSON
**API**(Application Programming Interface): 프로그램이 다른 프로그램의 기능이나 데이터를 쓸 수 있도록 정한 인터페이스. 이번에는 **특정 주소로 요청하면 데이터를 보내주는 HTTP API**를 만든다.

```text
GET /students → 학생 목록 응답
```

**JSON**: 데이터를 주고받기 위한 **텍스트 형식**.

```json
{
  "id": 1,
  "name": "한코딩"
}
```

여러 학생은 배열로 표현한다.

```json
[
  {
    "id": 1,
    "name": "한코딩"
  },
  {
    "id": 2,
    "name": "이학생"
  }
]
```

JavaScript 객체와 비슷하지만 JSON은 규칙이 있다.
- **속성 이름은 큰따옴표**로 감싼다.
- **문자열은 큰따옴표**로 감싼다.
- **주석이나 함수는 쓰지 않는다.**

> 💡 보충: 과정 페이지의 JSON 예시 이미지처럼 객체 안에 배열(`"users": [ … ]`), 배열 안에 객체, 객체 안에 또 객체를 넣는 **중첩**도 된다. 숫자(`12`)는 따옴표 없이 쓴다.

**객체를 JSON으로 보내기: `res.json()`** — 서버 코드에서는 JavaScript 객체를 넘기고, Express가 JSON으로 바꿔 응답한다. 👉 [Express 응답 API 안내](https://expressjs.com/en/api/)

```javascript
res.json({
  id: 1,
  name: "한코딩"
});
```

### 9. 학생마다 고유 ID 붙이기
콘솔 실습에서는 이름만 배열에 저장했다.

```javascript
const students = ["한코딩", "이학생", "박학생"];
```

이번에는 학생마다 **고유 ID**를 함께 저장한다. 이름이 같아도 ID로 구분할 수 있다.

```javascript
const students = [
  { id: 1, name: "한코딩" },
  { id: 2, name: "이학생" },
  { id: 3, name: "박학생" }
];
```

> 💡 보충: 콘솔 실습의 "목록 번호"는 삭제하면 바뀌는 배열 위치였다. ID는 학생에게 붙은 고정 값이라 삭제·추가해도 바뀌지 않는다. React에서 목록의 `key`로 `student.id`를 쓰는 이유도 같다 ([06_목록-조건부렌더링](../01_React과정/06_목록-조건부렌더링.md) 4장).

### 10. 존재하지 않는 주소로 접속하면?

```text
http://localhost:3000/unknown
```

별도 설정이 없으면 Express가 다음을 응답한다. HTTP 응답 상태는 **`404`** 다.

```text
Cannot GET /unknown
```

| 상황 | 의미 |
|---|---|
| 서버에 연결할 수 없음 | 서버 실행 여부나 주소·포트 확인 필요 |
| `Cannot GET /unknown` | 서버에는 연결됐지만 **해당 GET 경로가 없음** |

이번에는 정상 응답 **`200`** 과 경로를 찾지 못한 **`404`** 정도만 구분하면 충분하다.

### 11. 데이터를 보낸 것과 저장한 것은 다르다

```javascript
res.json(students);
```

- 이 코드는 배열을 JSON으로 **응답**할 뿐이다. 데이터베이스에 저장하거나 React 화면을 직접 바꾸는 코드가 아니다.
- 지금 목록은 서버 코드에 적혀 있다. 학생을 추가·삭제하는 API는 아직 만들지 않았다.
- **서버가 데이터를 응답하면, 요청한 쪽에서 그 데이터를 사용한다** → [04_React-서버연결](04_React-서버연결.md).

### 정리

| 개념 | 핵심 |
|---|---|
| Express | Node.js에서 서버 작성을 돕는 프레임워크 |
| GET | 데이터 조회에 쓰는 요청 메서드 |
| 경로 | 어떤 요청인지 구분하는 주소 부분 |
| `req` | 요청 정보 |
| `res` | 응답을 보내는 객체 |
| `res.send()` | 이번 실습에서는 문자열 응답 |
| `res.json()` | 데이터를 JSON으로 응답 |
| `app.listen()` | 지정한 포트에서 요청 받기 |

### 실습 2. 첫 번째 서버 만들고 접속하기
`student-server/server.js`에 핵심 개념 3의 코드를 쓰고 실행한다.

```bash
node server.js
```

터미널에 다음이 나오면 서버가 켜진 것이다.

```text
서버 실행 중: http://localhost:3000
```

브라우저 주소창에 `http://localhost:3000/`을 입력하면 `안녕하세요, 한코딩 서버입니다!`가 보인다.

**직접 바꿔보기 (수업 코드)** — 응답 문장을 HTML 태그로 바꾸고 경로를 추가했다. 수업 화면에서는 `localhost:3000`에 `<h1>` 큰 제목으로 "안녕하세요, 한코딩 서버입니다!"가 표시됐다.

```javascript
const express = require('express');

const app = express();
const PORT = 3000;

app.get("/", (req, res) => {
    res.send("<h1>안녕하세요, 한코딩 서버입니다!</h1>");
});

app.get("/hello", (req, res) => {
    res.send("<h2>내일은 수요일입니다.</h2>");
});

app.listen(PORT, () => {
    console.log(`서버 실행 중: http://localhost:${PORT}`)
})
```

> 💡 보충: `res.send()`에 HTML 문자열을 넣으면 브라우저가 HTML로 해석해 화면에 그린다. 그래서 `<h1>`이 큰 제목으로 보인다.

백틱(템플릿 리터럴)은 여러 줄 문자열을 쓸 수 있어서 HTML 문서 전체를 한 번에 응답했다. 서버가 화면(HTML)을 통째로 보내는 방식이고, 이번 과정의 목표는 이와 달리 **데이터(JSON)만 보내고 화면은 React가 만드는 것**이다.
</details>

### 실습 3. `/hello` 경로 추가하고 로그 찍기
`app.listen()` **위에** 추가한다.

```javascript
app.get("/hello", (req, res) => {
  res.send("반갑습니다! 서버에 도착했습니다.");
});
```

서버를 재시작하고 `http://localhost:3000/hello`에 접속한다. 기존 `/`에도 다시 접속해 경로마다 응답이 다른지 본다.
이어서 `/hello`를 핵심 개념 7의 코드(`console.log` 추가)로 바꾸고, 새로고침할 때마다 **서버 터미널**에 로그가 쌓이는지 확인한다.

### 실습 4. 학생 목록을 JSON으로 응답하기
1. `app`과 `PORT` 선언 아래에 학생 배열(핵심 개념 9의 `{ id, name }` 배열)을 추가한다.
2. `app.listen()` 위에 다음을 추가한다.

```javascript
app.get("/students", (req, res) => {
  console.log("학생 목록을 요청받았습니다.");

  res.json(students);
});
```

3. 서버를 재시작하고 `http://localhost:3000/students`에 접속해 학생 목록이 JSON으로 나오는지 확인한다. 브라우저에 따라 들여쓰기나 접기 기능은 다르게 보일 수 있다.

**지금 보이는 것은 디자인된 학생 목록 화면이 아니라 서버가 보낸 데이터다.**

### 종합 실습 코드 — `server.js` (최종)

```javascript
const express = require("express");

const app = express();
const PORT = 3000;

const students = [
  { id: 1, name: "한코딩" },
  { id: 2, name: "이학생" },
  { id: 3, name: "박학생" }
];

app.get("/", (req, res) => {
  res.send("안녕하세요, 한코딩 서버입니다!");
});

app.get("/hello", (req, res) => {
  console.log("GET /hello 요청이 들어왔습니다.");

  res.send("브라우저에 보내는 응답입니다.");
});

app.get("/students", (req, res) => {
  console.log("학생 목록을 요청받았습니다.");

  res.json(students);
});

app.listen(PORT, () => {
  console.log(`서버 실행 중: http://localhost:${PORT}`);
});
```

```bash
node server.js
```

| 주소 | 결과 |
|---|---|
| `http://localhost:3000` | 서버 소개 |
| `http://localhost:3000/hello` | 인사 응답 (터미널에 로그) |
| `http://localhost:3000/students` | 학생 목록 **JSON** (터미널에 로그) |
| `http://localhost:3000/unknown` | `Cannot GET /unknown` (404) |

## 헷갈리기 쉬운 점
- **콘솔 프로그램은 실행 후 끝나지만, 서버는 `Ctrl + C`로 끌 때까지 계속 실행된다.**
- **파일을 저장해도 서버는 자동으로 재시작되지 않는다.** 수정 전 데이터가 보이면 재시작했는지 확인한다.
- **`console.log()`는 서버 터미널에, `res.send()`·`res.json()`은 브라우저에** 간다. `console.log()`만으로는 응답이 안 간다.
- **`app.get()`은 `app.listen()` 위에** 추가한다.
- **`localhost`는 접속하는 사람 자신의 컴퓨터다.** 다른 사람 컴퓨터에서 같은 주소를 열면 그 사람 컴퓨터로 간다.
- **포트로 프로그램을 구분한다.** React 개발 서버(5173)와 API 서버(3000)는 다른 프로그램이다.
- **`Cannot GET /경로`는 서버가 꺼진 게 아니라 그 경로가 없는 것**(404)이다. 서버가 꺼져 있으면 아예 연결이 안 된다.
- **JSON은 속성 이름·문자열 모두 큰따옴표**, 주석·함수 불가. 서버 코드에서는 JS 객체를 `res.json()`에 넘기면 Express가 바꿔 준다.
- **`res.json()`은 응답일 뿐 저장이 아니다.** 서버 배열은 재시작하면 코드에 적힌 상태로 돌아간다.

**실행이 안 될 때 확인할 것**

| 증상 | 확인할 내용 |
|---|---|
| Express를 찾을 수 없음 | 현재 프로젝트에서 설치했는지 |
| `server.js`를 찾을 수 없음 | 터미널 위치와 파일 이름 |
| `require is not defined` | 별도 서버 프로젝트인지, `"type": "module"` 설정이 있는지 |
| 브라우저에서 연결되지 않음 | 서버 실행 여부와 주소·포트 |
| `Cannot GET /students` | 경로 철자와 처리 코드, 서버 재시작 여부 |
| 수정 전 데이터가 보임 | 저장한 뒤 서버를 재시작했는지 |
| `EADDRINUSE` 오류 | 같은 포트를 다른 프로그램이 사용 중인지 |

같은 서버를 다른 터미널에서 이미 실행했다면 기존 서버를 먼저 종료한다. 포트를 바꿔야 하면 `const PORT = 3001;`로 고치고 접속 주소도 `http://localhost:3001/students`로 바꾼다.

## 확인 문제
강의에 별도 "💬 확인하기"는 없어서, 본문의 질문형 제목과 강조된 내용에서 뽑았다.

<details><summary>Q. 콘솔 학생 관리 프로그램과 이번 서버는 입력 방법·결과 전달이 어떻게 다른가?</summary>

콘솔: 터미널 입력 → `console.log()`로 터미널에 출력. 서버: **브라우저의 요청** → **서버 응답**(`res.send()`/`res.json()`)으로 브라우저에 전달. 처리할 데이터(학생 배열)는 같다.
</details>

<details><summary>Q. (강의 질문) Express는 무엇인가? JavaScript·Node.js·npm과 역할을 구분하라.</summary>

Express: Node.js에서 웹 서버와 API를 쉽게 만들도록 **요청·응답 처리를 돕는 프레임워크**. JavaScript는 코드를 쓰는 언어, Node.js는 실행 환경, npm은 Express 같은 패키지 설치 도구.
</details>

<details><summary>Q. `app.get("/", (req, res) => { res.send("…"); });`와 `app.listen(PORT, …)`는 각각 무엇을 하나?</summary>

`app.get`: `/` 경로로 GET 요청이 오면 함수를 실행해 응답을 보낸다. `app.listen`: 지정한 포트(3000)에서 요청을 받기 시작한다.
</details>

<details><summary>Q. (강의 질문) 서버 프로그램이 `node hello.js`와 달리 계속 실행되는 이유는? 코드를 고친 뒤 반영하려면?</summary>

서버는 한 번 응답한 뒤에도 **다음 요청을 받아야** 하기 때문이다. 저장만으로는 자동 재시작되지 않으므로 `Ctrl + C`로 종료 → `node server.js`로 다시 실행 → 브라우저 새로고침.
</details>

<details><summary>Q. `http://localhost:3000/students`의 네 부분은 각각 무엇인가?</summary>

`http` 통신 방식 / `localhost` 내 컴퓨터 / `3000` 연결할 프로그램을 구분하는 포트 / `/students` 요청 경로.
</details>

<details><summary>Q. React 개발 서버와 API 서버를 같은 컴퓨터에서 동시에 실행할 수 있는 이유는? 다른 학생이 내 `localhost` 주소를 열면?</summary>

**포트**가 달라서(React 5173, API 3000) 구분된다. `localhost`는 접속하는 사람 자신의 컴퓨터라서, 다른 학생이 열면 **그 학생의 컴퓨터**에 접속한다.
</details>

<details><summary>Q. GET 요청이란? 라우팅이란?</summary>

GET: 데이터를 **조회**할 때 쓰는 HTTP 요청 메서드. 주소창에 주소를 입력하면 보통 GET 요청이 간다. 라우팅: **요청 경로에 따라 실행할 함수를 연결**하는 것 (`app.get("/hello", …)`).
</details>

<details><summary>Q. `req`와 `res`는 각각 무엇인가?</summary>

`req`: 클라이언트가 보낸 요청 정보. `res`: 응답을 보내는 데 쓰는 객체. 둘 다 매개변수 이름이고 Express가 객체를 넣어 준다.
</details>

<details><summary>Q. `/hello` 처리 함수에서 `console.log()`와 `res.send()`의 결과는 각각 어디에서 보이나? `console.log()`만 쓰면?</summary>

`console.log()`: **서버 터미널**. `res.send()`: **요청한 브라우저**. `console.log()`만 쓰면 브라우저에 응답이 가지 않는다.
</details>

<details><summary>Q. API란? 이번에 만든 API는?</summary>

프로그램이 다른 프로그램의 기능·데이터를 쓸 수 있도록 정한 인터페이스. 이번에는 `GET /students` → 학생 목록을 응답하는 **HTTP API**를 만들었다.
</details>

<details><summary>Q. JSON이 JavaScript 객체와 다른 규칙 세 가지는? 서버에서 JSON으로 응답하려면?</summary>

① 속성 이름을 큰따옴표로 ② 문자열을 큰따옴표로 ③ 주석·함수를 쓰지 않는다. 서버 코드에서는 JS 객체·배열을 `res.json()`에 넘기면 Express가 JSON으로 바꿔 응답한다.
</details>

<details><summary>Q. 학생 배열을 `["한코딩", …]` 대신 `{ id: 1, name: "한코딩" }` 형태로 바꾼 이유는?</summary>

학생마다 **고유 ID**를 두면 이름이 같아도 ID로 구분할 수 있다.
</details>

<details><summary>Q. (강의 질문) 존재하지 않는 주소(`/unknown`)로 접속하면? 서버가 꺼진 것과 어떻게 다른가?</summary>

`Cannot GET /unknown`이 나오고 상태 코드는 **404**. 서버에는 연결됐지만 그 GET 경로가 없다는 뜻이다. 서버가 꺼져 있으면 아예 연결할 수 없다. 정상 응답은 200.
</details>

<details><summary>Q. `res.json(students)`를 실행하면 학생 목록이 DB에 저장되거나 React 화면이 바뀌나?</summary>

아니다. 배열을 JSON으로 **응답**할 뿐이다. 데이터를 받은 쪽(React 등)이 그 데이터를 사용한다.
</details>

<details><summary>Q. 서버를 실행하려는데 `EADDRINUSE` 오류가 나면?</summary>

같은 포트(3000)를 다른 프로그램이 이미 쓰고 있다. 다른 터미널에서 실행 중인 서버를 먼저 종료하거나, `const PORT = 3001;`로 바꾸고 접속 주소도 3001로 바꾼다.
</details>
