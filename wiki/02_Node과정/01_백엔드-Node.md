# 01. 백엔드와 Node.js 알아보기

> 과정: Node과정 · [노션 원문](https://app.notion.com/p/412848f71c9b80a7bf0eeaa7031ef57c) · 최종 갱신일: 2026-11-12

## 한눈에 보기
- React 할 일 앱의 state는 **사용자 브라우저의 메모리**에만 있다. 새로고침하면 사라지고, 다른 기기·다른 사용자와 공유할 수 없다 → **서버와 저장소**가 필요하다.
- **프론트엔드**(화면, React) · **백엔드**(요청 처리, Node.js) · **데이터베이스**(저장·조회)는 역할이 다르다. 프론트와 백엔드는 **요청(Request)과 응답(Response)** 으로 연결되고, 서버는 화면 대신 **데이터(JSON)만** 보낼 수도 있다.
- **Node.js = 브라우저 밖에서 JavaScript를 실행하는 환경**이다. 새 언어가 아니다. **npm**은 패키지 설치와 프로젝트 명령 실행을 맡는다.
- `node hello.js`로 JavaScript 파일을 터미널에서 실행했다. 결과는 **터미널**에 나오고, Node.js에는 `document` 같은 DOM이 없다.

## 학습 목표
- 프론트엔드·백엔드·데이터베이스의 역할을 구분한다.
- 클라이언트(프론트)의 요청과 서버(백엔드)의 응답을 이해한다.
- Node.js가 등장한 배경을 알아본다.
- Node.js와 npm의 역할을 구분한다.
- 터미널에서 JavaScript 파일을 실행한다.

## 핵심 개념

### 1. 지금까지 만든 앱은 어디에서 동작했을까?
React 할 일 앱([08_폼-배열state-할일앱](../01_React과정/08_폼-배열state-할일앱.md))에서는 입력값과 목록을 state로 관리했다.

```jsx
const [tasks, setTasks] = useState([]);
```

이 데이터는 현재 페이지를 실행하는 **사용자의 브라우저 메모리**에 있다. 그래서 한계가 있다.
- 새로고침하면 저장하지 않은 데이터가 사라진다.
- 다른 컴퓨터에서 같은 목록을 볼 수 없다.
- 다른 사용자와 목록을 공유할 수 없다.

새로고침 후에도 유지하는 방법으로 브라우저 저장소도 있다. 하지만 **계정별 데이터를 여러 기기에서 쓰거나 다른 사람과 공유하려면 서버와 저장소가 필요**하다.

### 2. 프론트엔드와 백엔드
강의 그림: 왼쪽 **프론트엔드**(React · 사용자 화면, 학생 목록과 "목록 보기" 버튼) → "요청: 학생 목록을 보내주세요" → 가운데 **백엔드**(Node.js · 요청 처리: 요청 확인 → 필요한 데이터 조회 → 결과 응답) → "조회 요청" → 오른쪽 **데이터베이스**(데이터 저장·조회). 돌아올 때는 "조회 결과" → "응답: 학생 목록 데이터". 아래에 "이번 실습에서는 DB 대신 서버의 배열을 사용합니다."

| 구분 | 담당 | 예 | 이번 과정 |
|---|---|---|---|
| 프론트엔드 | **사용자가 보고 조작하는 화면** | 입력창 보여주기, 버튼 클릭 처리, 목록·완료 상태 표시, 로딩·오류 메시지 | React |
| 백엔드 | 서버에서 요청을 받아 데이터를 처리하고 **결과를 돌려주는 부분** | 목록 조회, 전달받은 내용 검사, **권한 확인**, DB에 **저장·조회** | Node.js |

백엔드를 만드는 언어·프레임워크 예: 파이썬(Django) / 자바(Spring → Spring Boot) / JavaScript(Node.js) / PHP(라라벨)

| 상황 | 프론트엔드 | 백엔드 |
|---|---|---|
| 목록 열기 | 목록을 요청하고 화면에 표시 | 목록을 찾아 응답 |
| 할 일 추가 | 입력 내용을 전달 | 내용 검사 후 저장 |
| 완료 변경 | 체크 동작을 전달하고 화면 갱신 | 완료 상태 변경 |
| 로그인 | 입력창과 결과 표시 | 계정 확인과 인증 처리 |

**프론트엔드와 백엔드는 요청(Request, 줄여서 req)과 응답(Response, 줄여서 res)으로 연결된다.**

### 3. 서버는 특별한 컴퓨터일까?
'서버'는 상황에 따라 두 가지를 가리킨다.

| 구분 | 의미 |
|---|---|
| 서버 컴퓨터 | 서비스를 실행하는 컴퓨터 |
| 서버 프로그램 | 요청을 받아 응답하는 프로그램 |

반드시 특별한 장비가 필요한 것은 아니다. **수업에서는 내 컴퓨터에서 서버 프로그램을 실행**한다. 내 컴퓨터 안에서 브라우저와 서버가 통신한다.

```text
내 컴퓨터

브라우저의 React 화면
        ↓ 요청
Node.js로 실행한 API 서버
        ↑ 응답
```

실제 서비스에서는 서버 프로그램을 다른 컴퓨터나 클라우드에서 실행해 여러 사용자가 접속하게 한다.

### 4. 서버 프로그램(Node.js)과 데이터베이스(Oracle)는 다르다

| 구분 | 역할 |
|---|---|
| 서버 프로그램 | 요청을 받고, 필요한 작업을 수행하고, 응답 |
| 데이터베이스 | 데이터를 저장하고 조회하는 시스템 |

할 일 목록 조회 흐름:

```text
React: “내 할 일 목록을 보내주세요.”
    ↓
서버: 요청을 확인하고 DB에서 목록 조회
    ↓
데이터베이스: 저장된 목록 반환
    ↓
서버: 필요한 데이터를 응답 (json)
    ↓
React: 받은 목록을 화면에 표시
```

- 서버를 만든다고 데이터가 자동으로 영구 저장되지는 않는다.
- **서버의 배열에만 보관한 데이터도 서버 프로그램을 재시작하면 초기화된다.**
- 이번 실습에서는 구조를 단순하게 하려고 데이터베이스 대신 **서버 코드의 배열**을 쓴다.

### 5. 요청과 응답
브라우저나 앱처럼 서버에 요청하는 쪽을 **클라이언트**라고 한다.

| 용어 | 의미 |
|---|---|
| 요청(Request) | 클라이언트가 서버에 보내는 메시지 |
| 응답(Response) | 서버가 요청에 대해 돌려주는 메시지 |

```text
클라이언트 → “할 일 목록이 필요합니다.”
서버       → “여기 목록이 있습니다.”
```

서버는 화면 전체가 아니라 **데이터만 보낼 수도 있다.**

```json
[
  {
    "id": 1,
    "title": "React 복습하기",
    "completed": false
  }
]
```

이런 데이터 표현 형식이 **JSON**이다. JavaScript의 객체·배열과 닮았지만 **데이터를 교환하기 위한 별도의 형식**이다. JSON 규칙은 [03_서버-데이터보내기](03_서버-데이터보내기.md)에서 자세히 본다.

### 6. 백엔드는 왜 따로 필요할까?
화면의 JavaScript만으로 처리하면 안 되는 작업이 있다.

| 경우 | 이유 |
|---|---|
| 여러 사용자가 같은 데이터를 써야 할 때 | 게시글·공유 일정은 작성자 외의 사용자도 볼 수 있어야 한다 |
| 중요한 판단을 해야 할 때 | 사용자가 화면의 제한을 우회해 요청할 수 있으므로 **권한과 입력값은 서버에서도 확인**해야 한다 |
| 비밀 정보를 써야 할 때 | DB 접속 비밀번호나 비공개 API 키를 브라우저 코드에 넣으면 노출된다. 서버에서 관리한다 |

**화면에서 검사했다고 서버의 검사가 필요 없어지는 것은 아니다.**

### 7. Node.js란?
Node.js는 **브라우저 밖에서 JavaScript를 실행하는 환경**이다. '실행 환경'은 프로그램이 동작하도록 필요한 기능을 제공하는 환경이다.

| 환경 | JavaScript로 할 수 있는 일의 예 |
|---|---|
| 브라우저 | 화면 변경, 클릭 처리, 서버 요청 |
| Node.js | 파일 처리, 서버 실행, 개발 도구 실행 |

Node.js는 별개의 프로그래밍 언어가 아니다. **지금까지 배운 JavaScript를 다른 환경에서 쓰는 것**이다. 👉 [Node.js 공식 소개](https://nodejs.org/learn/getting-started/introduction-to-nodejs)

### 8. Node.js는 어떤 배경에서 등장했을까?
- JavaScript는 원래 **웹 브라우저에서 화면에 동작을 추가하는 용도**로 널리 쓰였다. 서버는 Java, PHP, Python 같은 다른 언어로 만드는 경우가 많았다.
- Node.js는 **2009년** 등장해 **V8 JavaScript 엔진을 브라우저 밖에서 활용하는 실행 환경**을 제공했다. 👉 [V8 엔진](https://nodejs.org/learn/getting-started/the-v8-javascript-engine)
- 특히 네트워크 요청처럼 **기다림이 생기는 작업을 비동기 방식으로 처리**하도록 설계되었다. 👉 [Node.js의 설계 방향](https://nodejs.org/en/about)
- 그 결과 JavaScript 개발자가 같은 언어로 **API 서버**, 파일 처리 프로그램, 터미널 도구, 프론트엔드 개발 도구 실행까지 할 수 있게 되었다.

**지금은 'JavaScript로 서버도 만들 수 있다'는 점만 이해하면 충분하다.**

> 💡 보충: V8은 Chrome 브라우저 안에서 JavaScript 코드를 실행하는 엔진이다. Node.js는 이 엔진을 브라우저에서 떼어 내 컴퓨터에서 바로 JavaScript를 돌릴 수 있게 만든 것이다.

### 9. 우리는 이미 Node.js를 사용했다
React 프로젝트에서 실행한 명령([04_React시작](../01_React과정/04_React시작.md)):

```bash
npm install
npm run dev
```

이때 Vite 같은 **개발 도구가 Node.js 위에서 실행**됐다. 다만 역할을 구분한다.

| 구분 | 역할 |
|---|---|
| React 코드 | **브라우저**에서 화면 구성 |
| Vite 개발 서버 | **개발 중 화면 제공과 코드 변경 반영 지원** |
| 이번에 만들 API 서버 | **데이터 요청을 받아 응답** |

**React 개발 서버와 데이터 API 서버는 역할이 다르다.** 수업에서는 두 프로그램을 각각 실행하고 연결한다 ([04_React-서버연결](04_React-서버연결.md)).

### 10. Node.js와 npm 구분하기

| 도구 | 역할 | 명령 예 |
|---|---|---|
| Node.js | JavaScript 코드 실행 | `node hello.js` |
| npm | 패키지 설치와 프로젝트 명령 실행 | `npm install 패키지이름`, `npm run dev` |

- 이번 회차에서는 `node 파일이름.js`만 쓴다. npm 명령은 지금 실행하지 않아도 된다.
- `npm run dev`는 모든 프로젝트에서 자동으로 되는 명령이 아니다. **프로젝트의 `package.json`에 정의된 `dev` 명령**을 실행한다.

### 11. 브라우저와 Node.js에서 다른 점
JavaScript 문법이 같아도 실행 환경이 제공하는 기능은 다르다.

| 기능 | 브라우저 | Node.js |
|---|---|---|
| 변수·함수·객체·배열 | 사용 가능 | 사용 가능 |
| `console.log()` | 개발자 도구 콘솔에 출력 | **터미널**에 출력 |
| `document.querySelector()` | 사용 가능 | 기본 제공되지 않음 |
| `window` | 제공 | 기본 제공되지 않음 |
| 파일·서버 처리 기능 | 브라우저의 권한과 API 범위로 제한 | Node.js가 관련 기능 제공 |

Node.js에는 **웹페이지의 DOM이 기본으로 없으므로** 다음 코드는 그대로 쓸 수 없다 (`document is not defined` 오류).

```javascript
document.querySelector("h1");
```

👉 [브라우저와 Node.js의 차이](https://nodejs.org/learn/getting-started/differences-between-nodejs-and-the-browser)

**화면 요소를 바꾸는 코드는 브라우저에서, 서버 작업은 Node.js에서 실행한다.**

### 정리

| 개념 | 핵심 |
|---|---|
| 프론트엔드 | 사용자가 보고 조작하는 화면 |
| 백엔드 | 서버에서 요청 처리와 데이터 작업 수행 |
| 서버 프로그램 | 요청을 받아 응답하는 프로그램 |
| 데이터베이스 | 데이터 저장과 조회 |
| Node.js | 브라우저 밖에서 JavaScript를 실행하는 환경 |
| npm | 패키지 설치와 프로젝트 명령 실행 |

## 실습 정리

### 실습 1. 터미널에서 JavaScript 파일 실행하기
**① 실습 폴더 만들기** — 기존 React 프로젝트와 별도로 `node-basic` 폴더를 만들고 VS Code로 연다.

```text
학습 폴더
├─ my-profile-react
└─ node-basic
```

**② 설치 확인** — VS Code 터미널에서 한 줄씩 입력한다. 버전 번호가 나오면 확인 완료 ([VS Code + Node.js](../00_개발환경/VSCode-Node.md)).

```bash
node -v
```

```bash
npm -v
```

**③ `node-basic/hello.js` 만들기**

```javascript
const userName = "한코딩";

console.log(`안녕하세요, ${userName}입니다!`);
console.log("브라우저 밖에서 JavaScript를 실행했습니다.");
```

**④ 실행하기** — 터미널의 현재 위치가 `node-basic`인지 확인하고 실행한다.

```bash
node hello.js
```

예상 결과 (터미널):

```text
안녕하세요, 한코딩입니다!
브라우저 밖에서 JavaScript를 실행했습니다.
```

- **실행 결과는 브라우저가 아니라 터미널에 나온다.**
- 이 프로그램은 코드를 실행한 뒤 **바로 종료**된다. 아직 요청을 기다리는 서버 프로그램은 아니다.
- **파일을 수정·저장하는 것만으로는 다시 실행되지 않는다.** 저장한 뒤 `node hello.js`를 다시 입력한다.

**다른 폴더에서 실행하면?** 수업 화면에서는 `hello.js`가 없는 상위 폴더에서 `node hello.js`를 실행해 다음 오류가 났다.

```text
Error: Cannot find module '…\hello.js'
  code: 'MODULE_NOT_FOUND',
```

→ 터미널 위치를 `hello.js`가 있는 폴더로 옮긴 뒤 다시 실행한다. 수업 화면에서는 `pwd`로 현재 위치를 확인했다.

> 💡 보충: 폴더 이동은 `cd node-basic`, 위로 한 칸은 `cd ..`이다. VS Code에서 `node-basic` 폴더 자체를 열면 터미널이 처음부터 그 위치에서 열린다.

### 실습 2. 할 일 데이터 다루기
같은 폴더에 `tasks.js`를 만든다.

```javascript
const tasks = [
  {
    id: 1,
    title: "React 복습하기",
    completed: true
  },
  {
    id: 2,
    title: "Node.js 실행하기",
    completed: false
  },
  {
    id: 3,
    title: "서버의 역할 이해하기",
    completed: false
  }
];

console.log("전체 할 일");
console.log(tasks);

const remainingTasks = tasks.filter(
  (task) => !task.completed
);

console.log(`남은 할 일은 ${remainingTasks.length}개입니다.`);
console.log(remainingTasks);
```


## 헷갈리기 쉬운 점
- **Node.js는 새로운 언어가 아니다.** JavaScript를 브라우저 밖에서 실행하는 환경이다.
- **서버 ≠ 데이터베이스.** 서버는 요청을 받아 처리·응답하고, DB는 저장·조회한다. 서버 배열에 넣은 데이터는 서버를 재시작하면 사라진다.
- **화면(프론트)에서 검사했어도 서버에서 다시 검사한다.** 사용자는 화면을 우회해 요청할 수 있다.
- **비밀번호·비공개 API 키는 브라우저 코드에 넣지 않는다.**
- **Vite 개발 서버와 API 서버는 다른 프로그램이다.** 둘 다 Node.js 위에서 돌지만 역할이 다르다.
- **`npm run dev`는 `package.json`에 `dev` 명령이 있을 때만** 된다.
- **`node 파일.js`는 파일이 있는 폴더에서 실행한다.** 다른 곳이면 `Cannot find module` 오류.
- **저장만으로는 다시 실행되지 않는다.** 수정 후 `node 파일.js`를 다시 입력한다.
- **`console.log()` 결과는 Node.js에서는 터미널에** 나온다 (브라우저 콘솔 아님).
- **Node.js에는 `document`·`window`가 없다.** `document is not defined`가 나오면 브라우저 전용 코드를 썼는지 본다.

**실행이 안 될 때 확인할 것**

| 증상 | 확인할 내용 |
|---|---|
| `node` 명령을 찾을 수 없음 | Node.js 설치 여부, 터미널 재실행 |
| 파일을 찾지 못함 | 현재 폴더와 파일 이름 |
| 수정 전 내용이 출력됨 | 저장 여부, 파일 재실행 |
| 문법 오류 발생 | 따옴표·괄호·중괄호, 오류의 줄 번호 |
| `document is not defined` | 브라우저 전용 코드를 사용했는지 |

터미널에 오류가 나오면 **파일 이름과 줄 번호부터** 확인한다.

## 확인 문제
강의에 별도 "💬 확인하기"는 없어서, 본문의 질문형 제목과 강조된 내용에서 뽑았다.

<details><summary>Q. (강의 질문) 지금까지 만든 React 할 일 앱의 데이터는 어디에 있었고, 어떤 한계가 있나?</summary>

사용자의 **브라우저 메모리**(state)에 있었다. 그래서 ① 새로고침하면 사라지고 ② 다른 컴퓨터에서 같은 목록을 볼 수 없고 ③ 다른 사용자와 공유할 수 없다. 여러 기기·여러 사람이 쓰려면 서버와 저장소가 필요하다.
</details>

<details><summary>Q. 할 일을 추가할 때 프론트엔드와 백엔드는 각각 무엇을 하나?</summary>

프론트엔드: 입력 내용을 (서버에) 전달한다. 백엔드: 내용을 검사한 뒤 저장한다. 둘은 요청(Request)과 응답(Response)으로 연결된다.
</details>

<details><summary>Q. (강의 질문) 서버는 특별한 컴퓨터인가? 수업에서는 서버를 어디서 실행하나?</summary>

아니다. '서버'는 서비스를 실행하는 **서버 컴퓨터**나, 요청을 받아 응답하는 **서버 프로그램**을 뜻한다. 수업에서는 **내 컴퓨터**에서 서버 프로그램을 실행하고, 같은 컴퓨터의 브라우저가 거기에 요청한다.
</details>

<details><summary>Q. 서버 프로그램과 데이터베이스의 차이는? 서버의 배열에 넣은 데이터는 서버를 재시작하면 어떻게 되나?</summary>

서버 프로그램은 요청을 받고 작업을 수행해 응답한다. 데이터베이스는 데이터를 저장·조회한다. 서버 배열에만 있는 데이터는 **재시작하면 초기화**된다 (영구 저장이 아님).
</details>

<details><summary>Q. 클라이언트란? 서버가 화면 대신 데이터만 보낼 때 자주 쓰는 형식은?</summary>

브라우저나 앱처럼 **서버에 요청하는 쪽**. 데이터만 보낼 때는 **JSON** 형식을 쓴다 (JS 객체·배열과 닮았지만 데이터 교환용 별도 형식).
</details>

<details><summary>Q. (강의 질문) 백엔드가 왜 별도로 필요한가? 세 가지 경우를 들어라.</summary>

① 여러 사용자가 같은 데이터를 써야 할 때(게시글·공유 일정) ② 권한·입력값처럼 중요한 판단을 할 때(사용자가 화면 제한을 우회할 수 있음) ③ DB 비밀번호·비공개 API 키 같은 비밀 정보를 쓸 때(브라우저 코드에 넣으면 노출).
</details>

<details><summary>Q. 화면(React)에서 입력값을 이미 검사했다면 서버 검사는 생략해도 될까?</summary>

안 된다. 사용자가 화면의 제한을 우회해 요청을 보낼 수 있으므로 **서버에서도 확인**해야 한다.
</details>

<details><summary>Q. (강의 질문) Node.js는 무엇인가? 새로운 프로그래밍 언어인가?</summary>

**브라우저 밖에서 JavaScript를 실행하는 환경**이다. 새로운 언어가 아니라 지금까지 배운 JavaScript를 다른 환경에서 쓰는 것이다.
</details>

<details><summary>Q. (강의 질문) Node.js는 어떤 배경에서 등장했나?</summary>

JavaScript는 브라우저에서 화면 동작용으로 쓰였고 서버는 Java·PHP·Python 등으로 만들었다. 2009년 Node.js가 **V8 JavaScript 엔진을 브라우저 밖에서 쓰는 실행 환경**을 제공해, JavaScript로 API 서버·파일 처리·터미널 도구 등을 만들 수 있게 되었다. 네트워크 요청처럼 기다림이 있는 작업을 비동기로 처리하도록 설계되었다.
</details>

<details><summary>Q. React 코드, Vite 개발 서버, 이번에 만들 API 서버의 역할을 구분하라.</summary>

- React 코드: **브라우저**에서 화면 구성
- Vite 개발 서버: 개발 중 화면 제공과 코드 변경 반영 지원
- API 서버: 데이터 요청을 받아 응답

React 개발 서버와 API 서버는 다른 프로그램이라 각각 실행하고 연결한다.
</details>

<details><summary>Q. Node.js와 npm의 역할은? `npm run dev`는 아무 폴더에서나 실행되나?</summary>

Node.js: JavaScript 코드 실행 (`node hello.js`). npm: 패키지 설치와 프로젝트 명령 실행. `npm run dev`는 그 프로젝트의 **`package.json`에 `dev` 명령이 정의돼 있어야** 실행된다.
</details>

<details><summary>Q. `hello.js`가 없는 폴더에서 `node hello.js`를 실행하면? `hello.js`를 수정·저장하면 결과가 자동으로 바뀌나?</summary>

`Error: Cannot find module …` (MODULE_NOT_FOUND) 오류가 난다. 터미널 위치를 파일이 있는 폴더로 옮겨 실행한다. 저장만으로는 다시 실행되지 않으므로 `node hello.js`를 다시 입력해야 바뀐 결과가 나온다.
</details>

<details><summary>Q. `tasks.js`를 실행하면 "남은 할 일은 몇 개"가 출력되나? 결과는 어디에 보이나?</summary>

`completed: false`인 2개(Node.js 실행하기, 서버의 역할 이해하기)라서 "남은 할 일은 2개입니다." 결과는 **터미널**에 출력된다 (아직 브라우저에 보내는 응답이 아님).
</details>

<details><summary>Q. Node.js 파일에서 `document.querySelector("h1");`을 실행하면?</summary>

`document is not defined` 오류. Node.js에는 웹페이지의 DOM(`document`, `window`)이 기본으로 없다. 화면 요소를 바꾸는 코드는 브라우저에서 실행한다.
</details>
