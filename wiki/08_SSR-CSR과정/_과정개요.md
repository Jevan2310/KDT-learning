# SSR-CSR과정 — 같은 화면, 다른 처리 방식

> 과정: SSR-CSR과정 · [노션 원문](https://app.notion.com/p/420848f71c9b809e9342ebf1cc58050c) · 최종 갱신일: 2026-11-24

## 과정 소개
Spring Boot와 JSP로 학생 목록을 만들고, React로 같은 기능을 구현하면서 **화면이 만들어지는 과정**을 비교한다. 마지막에는 JSP를 Thymeleaf로 바꿔서 **렌더링 방식(SSR·CSR)과 화면 기술(JSP·Thymeleaf·React)의 차이**를 정리한다.

- **SSR (Server-Side Rendering)**: 서버가 데이터를 넣은 HTML을 만들어 응답한다.
- **CSR (Client-Side Rendering)**: 서버는 데이터(JSON)를 주고, 브라우저의 JavaScript(React)가 화면을 만든다.

## 학습 목표
노션 과정 페이지의 학습 목표다.
- SSR과 CSR이 활용되는 배경을 설명할 수 있다.
- 서버의 HTML 응답과 JSON 응답을 구분할 수 있다.
- JSP와 React로 같은 데이터의 목록·검색 화면을 만들 수 있다.
- 브라우저 개발자 도구로 요청과 응답을 비교할 수 있다.
- JSP 화면을 Thymeleaf로 변경할 수 있다.
- 서비스의 특성에 따라 렌더링 방식을 선택할 수 있다.

## 공통 실습 기능
세 구현(JSP·React·Thymeleaf)에서 기능과 데이터를 똑같이 유지한다.

| 기능 | 구현할 내용 |
|---|---|
| 전체 목록 | 학생 이름·이메일·소속 반 표시 |
| 이름 검색 | 이름 일부가 포함된 학생 조회 |
| 검색어 없음 | 전체 학생 표시 |
| 검색 결과 없음 | 안내 문구 표시 |

DB 설정에 시간을 쓰지 않도록 학생 데이터는 먼저 Java 목록으로 준비한다. 화면의 차이를 데이터 저장 방식과 떼어서 비교하기 위해서다.

## 핵심 구분

| 구성 | 이번 실습의 렌더링 방식 | 학생 목록 HTML을 만드는 곳 |
|---|---|---|
| Spring Boot + JSP | SSR | 서버 |
| Spring Boot API + React | CSR | 브라우저 |
| Spring Boot + Thymeleaf | SSR | 서버 |

## 학습 흐름

```text
서버 중심 웹과 CSR 확산 배경 이해
        ↓
JSP로 SSR 구현
        ↓
문서 요청과 HTML 응답 확인
        ↓
React로 CSR 구현
        ↓
장점과 고려 사항 비교
        ↓
Thymeleaf로 SSR 템플릿 교체
```

### 01. 서버에서 화면을 만들던 웹과 CSR이 확산된 배경
- 브라우저의 요청과 서버의 응답
- 서버에서 HTML을 만드는 전통적인 웹의 흐름
- 페이지 이동과 폼 제출 시 문서를 다시 요청하는 방식
- 검색·알림·편집 등 상호작용이 많아진 웹
- JavaScript와 비동기 요청을 이용한 부분 갱신
- SPA와 CSR의 관계
- CSR의 장점과 추가로 고려할 점

> SSR 화면도 JavaScript로 부분 갱신할 수 있다. 부분 갱신과 CSR을 완전히 같은 뜻으로 쓰지 않는다. (강의)

## 실습 폴더 한눈에 보기
강의에서 쓴 이름 기준이다. Spring 프로젝트와 React 프로젝트를 같은 상위 폴더에 나란히 둔다.

```text
상위 폴더
├─ rendering-demo     ← 02회차: Spring Boot + JSP (포트 8080), 04회차에 StudentApiController 추가
└─ rendering-react    ← 04회차: Vite React (포트 5173, /api 요청을 8080으로 프록시)
```

| 회차 | 프로젝트 | 준비 (처음 한 번) | 실행 | 결과 확인 |
|---|---|---|---|---|
| 01 | — | 없음 (개념) | — | — |
| 02 | `rendering-demo` | start.spring.io: Gradle - Groovy, Java 17, Packaging War, Spring Web → `build.gradle`을 강의 코드로 교체(JSP·JSTL·MyBatis·DB 드라이버·Lombok) → Load Gradle Changes, `application.properties`(DB·MyBatis·`spring.mvc.view.prefix=/WEB-INF/views/`·`suffix=.jsp`), `src/main/webapp/WEB-INF/views/` 만들기 | `*Application` main ▶ 또는 `./gradlew bootRun` | `http://localhost:8080/students` (`?keyword=한`) |
| 03 | `rendering-demo` | 없음 | 02와 같음 | Chrome 개발자 도구 Network (Doc 필터, Headers·Payload·Response) |
| 04 | `rendering-demo` + `rendering-react` | `npm create vite@latest rendering-react -- --template react` → `npm install`, `vite.config.js`에 `/api` 프록시 | Spring 실행 + `npm run dev` (터미널 2개) | `http://localhost:5173`, Network의 Fetch/XHR |

> 💡 보충: 02회차 준비에서 막히기 쉬운 곳 (2026-11-24 확인)
> - 강의는 **Spring Boot 3.5.x**인데 지금 start.spring.io에는 4.x만 있다. 4.x로 만든 뒤 `build.gradle` 전체를 강의 코드로 바꾸면 된다.
> - `build.gradle`이 **Java 17 toolchain**이라 JDK 17이 있어야 한다. JDK 21만 있으면 `Cannot find a Java installation … languageVersion=17` 오류가 난다.
> - 수업 코드는 MyBatis로 MySQL/MariaDB의 `school` DB `students` 테이블을 읽는다 (데이터베이스과정 02·05). 강의 코드 그대로면 화면이 500 오류가 나는 곳이 있다 — [02_JSP-SSR화면](02_JSP-SSR화면.md)의 보충 참고.

> 💡 보충: 04회차는 Spring 06회차(`@CrossOrigin`)와 달리 **Vite 프록시**로 연결해서 Spring에 CORS 설정이 없다. `strictPort: true`라 다른 React 프로젝트가 5173을 쓰고 있으면 Vite가 뜨지 않는다. 자세한 건 [04_React-CSR화면](04_React-CSR화면.md).
