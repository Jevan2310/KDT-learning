# MSA과정 — React·Spring Boot·Express로 서비스 연결하기

> 과정: MSA과정 · [노션 원문](https://app.notion.com/p/422848f71c9b801ab043e3a0fe97ecce) · 최종 갱신일: 2026-11-27

## 과정 소개
MSA(Microservice Architecture)의 개념과 서비스를 나누는 이유를 이해하고, **서로 다른 기술로 만든 백엔드를 HTTP·JSON으로 연결**한다. React 공지 화면에서 Spring의 학생 정보와 Express의 공지 데이터를 함께 쓰고, 한 서비스가 멈췄을 때의 처리까지 해 본다.

- **모놀리식**: 모든 기능을 하나의 애플리케이션으로 만들고 함께 실행·배포한다.
- **MSA**: 업무 기능별로 서비스를 나누고, 서비스마다 따로 실행·배포한다. 서비스끼리는 API로 데이터를 주고받는다.

## 학습 목표
노션 과정 페이지의 학습 목표다.
- 모놀리식과 MSA의 차이를 설명할 수 있다.
- 업무 기능을 기준으로 서비스의 역할과 데이터 소유권을 구분한다.
- Spring Boot와 Express를 독립적으로 실행할 수 있다.
- HTTP와 JSON으로 서로 다른 서비스를 연결할 수 있다.
- React에서 목록·상세·등록 기능을 사용할 수 있다.
- MSA의 장점과 운영상의 어려움을 설명할 수 있다.

## 사용하는 기술

| 기술 | 역할 |
|---|---|
| React + Vite | 공지 목록·상세·등록 화면 |
| Spring Boot | 학생 정보를 관리하는 API |
| Express | 공지 관리와 학생 서비스 호출 |
| HTTP · JSON | 서비스 간 요청과 데이터 전달 |
| `fetch`·`async/await` | API 호출과 비동기 결과 처리 |
| Git | 단계별 코드 변경 기록 |

## 실습 프로젝트 — 학생 정보와 공지 서비스

### 서비스별 역할

| 구성 | 실행 주소 예 | 소유하는 데이터·기능 |
|---|---|---|
| React | `localhost:5173` | 화면과 사용자 입력 상태 |
| Express 공지 서비스 | `localhost:3000` | 공지 번호·제목·내용·작성자 번호 |
| Spring 학생 서비스 | `localhost:8081` | 학생 번호·이름·이메일 |

공지 서비스는 작성자 이름을 따로 저장하지 않고, `authorId`로 학생 서비스에 학생 정보를 요청한다.

> 💡 보충: 과정 페이지(와 01회차, 02회차 로그 설명)에는 Spring 학생 서비스가 **8081**로 적혀 있지만, 02회차 `application.properties`와 03·04회차 표는 **8080**이다 (2026-11-27 기준). 회차 코드를 따라 하면 8080이다. 05회차에서 Express가 Spring 주소를 쓸 때 어느 포트인지 다시 확인한다.

### 전체 연결 구조

```text
사용자
  ↓
React 공지 화면
  ↓ /api 요청
Express 공지 서비스
  ↓ 학생 정보 요청
Spring 학생 서비스
```

React의 `/api` 요청은 개발 중 Vite 프록시를 거쳐 Express로 전달된다.

### 구현할 화면

| 화면 | 주요 기능 |
|---|---|
| 공지 목록 | 공지 제목과 번호 표시 |
| 공지 상세 | 제목·내용·작성자 이름 표시 |
| 공지 등록 | 제목·내용·작성자 번호 입력 |
| 상태 안내 | 로딩·빈 결과·등록 실패 안내 |

### 상황별 처리 규칙

| 상황 | 기대 동작 |
|---|---|
| 공지와 작성자 조회 성공 | 작성자 이름을 포함한 공지 표시 |
| 작성자가 없는 공지 조회 | 작성자 없음 표시 |
| 학생 서비스 장애 중 공지 조회 | 공지는 표시하고 작성자 정보 확인 불가 안내 |
| 없는 작성자로 공지 등록 | 등록 거절과 안내 |
| 학생 서비스 장애 중 공지 등록 | 등록하지 않고 재시도 안내 |
| 존재하지 않는 공지 조회 | `404` 응답과 안내 |

조회는 공지를 계속 보여 주는 **대체 응답**을 쓰고, 등록은 **작성자 확인을 필수**로 한다. 이번 실습에서 정한 업무 규칙이다.

## 실습 범위
- DB 대신 Java 목록과 JavaScript 배열로 시작한다.
- React 기본 화면과 CSS는 제공된 틀을 쓴다.
- 프로세스를 재시작하면 메모리에서 바꾼 데이터가 초기화될 수 있다.
- 로그인·DB 연동·클라우드 배포는 확장 범위로 둔다.
- API Gateway·서비스 디스커버리·메시지 통신은 역할만 간단히 소개한다.

> 이번 예제는 MSA의 기본 원리를 경험하는 축소 실습이다. 프로젝트와 포트를 나누는 것만으로 MSA 설계가 완성되는 것은 아니다. (강의)

## 실습 폴더 한눈에 보기
강의에서 쓴 이름 기준이다. 세 프로젝트를 같은 상위 실습 폴더에 나란히 둔다.

```text
실습 폴더
├─ student-service   ← 02회차: Spring Boot 학생 서비스 (Jar, Java 21, 포트 8080 — 과정 페이지는 8081, 경로는 `/students`)
├─ notice-service    ← 03회차: Express 5 공지 서비스 (server.cjs, 포트 3000)
└─ notice-web        ← 04회차: Vite React 공지 화면 (포트 5173, /api 요청을 3000으로 프록시)
```

| 회차 | 프로젝트 | 준비 (처음 한 번) | 실행 | 결과 확인 |
|---|---|---|---|---|
| 01 | — | 없음 (개념) | — | — |
| 02 | `student-service` | start.spring.io: Gradle - Groovy, Group `com.hancoding`, Artifact `student-service`, Package `com.hancoding.studentservice`, Packaging Jar, Java 21, Spring Web + Lombok (강의 Boot 4.2.0), `application.properties`에 이름·포트 | `StudentServiceApplication` main ▶ 또는 `./gradlew bootRun` | `http://localhost:8080/students` (`/students/3`, 없는 번호 `/students/999` → 404) |
| 03 | `notice-service` | `mkdir notice-service` → `npm init -y` → `npm install express@5`, `server.cjs` 만들기 | `node server.cjs` | `http://localhost:3000/api/notices` |
| 04 | `notice-service` + `notice-web` | `npm create vite@latest notice-web -- --template react` → `npm install`, `vite.config.js`에 `/api` 프록시 | Express 실행 + `npm run dev` (터미널 2개) | `http://localhost:5173`, Network의 Fetch/XHR |

> 💡 보충: 02회차 학생 서비스 주소는 `/students`인데, 03회차 원문 끝의 **수업 중 바꾼 Spring 코드**는 `@RequestMapping("/api/students")`와 등록(`POST`)을 더했다. 그 코드를 쓰면 `/students`는 404가 되고 `/api/students`로 조회한다. 등록 코드의 문제는 [03_Express공지API](03_Express공지API.md)의 "참고: 수업 중 바꾼 Spring 학생 서비스" 참고.
