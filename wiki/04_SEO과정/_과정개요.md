# SEO과정 — 내가 만든 서비스를 검색에 알리기

> 과정: SEO과정 · [노션 원문](https://app.notion.com/p/41a848f71c9b800d9ac4c3f9334138aa) · 최종 갱신일: 2026-11-18

## 과정 소개
검색엔진이 웹페이지를 **발견하고 검색 결과에 표시하는 과정**을 알아본다.
페이지의 기본 정보(제목·설명)를 작성하고, **Google Search Console**과 **네이버 서치어드바이저**에 사이트를 등록한다. 수업일은 2026-11-17이다.

완성할 흐름: **페이지 기본 정보 작성 → 배포 → 사이트 등록·소유 확인 → 사이트맵 제출 → 검색 반영 상태 확인**

```text
01 SEO와 검색 과정 이해 (수집 → 색인 → 검색 결과 표시)
        ↓
02 검색엔진이 이해하기 쉬운 페이지 (title · description · h1~h3 · alt · robots.txt · noindex)
        ↓
03 구글·네이버에 사이트 등록 (HTML 확인 태그로 소유권 확인)
        ↓
04 사이트맵 제출과 검색 상태 확인 (sitemap.xml · URL 검사 · 수집 요청)
```

## 학습 목표
- SEO의 목적과 검색 반영 과정을 이해한다.
- 페이지 제목과 설명을 작성한다.
- 사이트 등록과 소유 확인을 진행한다.
- 사이트맵의 역할을 이해한다.
- 검색 반영 상태와 문제를 확인한다.

## 강의 목차
노션 과정 페이지 본문의 목차다. 이 과정은 목차 번호와 하위 페이지(회차) 번호가 같다.

### 01. SEO와 검색엔진 이해하기
- SEO란 무엇인가?
- 서비스를 만들고 검색에도 알려야 하는 이유
- 수집 → 색인 → 검색 결과 표시
- 사이트 배포와 검색 노출의 차이
- 사이트를 등록해도 즉시 검색되거나 상위에 표시되지 않는 이유

🛠️ 실습: 내 서비스 이름을 검색하고 현재 노출 상태 살펴보기

### 02. 검색엔진이 이해하기 쉬운 페이지 만들기
- 페이지의 내용을 설명하는 `title`
- 페이지 소개를 작성하는 `meta description`
- 내용에 맞는 제목 태그와 링크 문구
- 이미지의 `alt`
- 공개 URL과 검색로봇 접근 가능 여부
- `robots.txt`와 `noindex`의 기본 역할

🛠️ 실습: 서비스의 제목·설명·이미지 대체 텍스트 수정하기

### 03. 구글·네이버에 사이트 등록하기
- Google Search Console과 네이버 서치어드바이저의 역할
- 등록할 사이트 주소 확인
- 사이트 소유 확인이 필요한 이유
- HTML 확인 태그 적용과 배포
- 소유 확인 완료 여부 점검
- 구글의 도메인 속성과 URL 접두어 속성 차이

🛠️ 실습: 수정 권한이 있는 사이트를 등록하고 소유 확인하기

### 04. 사이트맵 제출과 검색 상태 확인하기
- 사이트맵이 알려주는 정보
- 사이트맵 주소 확인과 제출
- Google Search Console의 URL 검사
- 네이버 웹마스터 도구의 수집 요청
- 수집·색인 상태와 오류 확인
- 등록·요청 후에도 검색 반영에 시간이 필요한 이유

🛠️ 실습: 주요 페이지의 검색 반영 상태를 확인하고 사이트맵 제출하기

## 실습 준비 한눈에 보기
이번 과정은 새 프로젝트 폴더를 만들지 않는다. **이미 만든 서비스(React·Spring 프로젝트)의 HTML을 고치고 다시 배포**하는 실습이다.

| 회차 | 필요한 것 | 고치는 파일 | 확인하는 곳 |
|---|---|---|---|
| 01 | 브라우저 (관리 권한 없어도 됨) | 없음 | 구글·네이버 검색, `site:` 검색 |
| 02 | 내 프로젝트 또는 연습용 `index.html` + `profile.png` | Vite: `index.html` / Spring: 화면 템플릿 | 브라우저 탭 제목, **페이지 소스 보기** |
| 03 | 구글 계정, 네이버 계정, **외부에서 접속되는 내 사이트**, 다시 배포할 수 있는 환경 | 메인 페이지 HTML의 `<head>` (확인 태그 2개) | 배포된 사이트의 페이지 소스 → 관리 도구의 확인 버튼 |
| 04 | 03회차에서 소유 확인한 사이트 | Vite: `public/sitemap.xml` / Spring Boot: `src/main/resources/static/sitemap.xml` | `https://내주소/sitemap.xml`, Search Console(Sitemaps·URL 검사), 서치어드바이저(요청 메뉴) |

| 프로젝트 | 제목·설명·확인 태그 | 사이트맵 |
|---|---|---|
| 일반 HTML 사이트 | 메인 페이지 HTML | 메인 `index.html`과 같은 배포 폴더 |
| Vite React | 프로젝트 최상위 `index.html` | `public/sitemap.xml` |
| Spring + Thymeleaf | 메인 주소에서 응답하는 HTML 템플릿 | `src/main/resources/static/sitemap.xml` |

- **`localhost` 주소로는 03·04회차 실습을 할 수 없다.** 검색엔진과 관리 도구는 인터넷에 배포된 사이트만 읽는다.
- 아직 배포한 사이트가 없으면 강사 시연으로 과정을 먼저 본다.

## 개발환경
- 새로 설치할 프로그램은 없다. 기존 [VS Code + Node.js](../00_개발환경/VSCode-Node.md)(React), [IntelliJ IDEA + JDK](../00_개발환경/IntelliJ-JDK.md)(Spring) 환경에서 HTML만 고친다.
- 웹 도구 두 개를 브라우저에서 쓴다: [Google Search Console](https://search.google.com/search-console) (구글 계정), [네이버 서치어드바이저](https://searchadvisor.naver.com/) (네이버 계정).
- 배포 방법 자체는 이 과정에서 다루지 않는다. 평소 쓰는 배포 방식으로 "수정 → 저장 → 빌드·배포 → 실제 사이트 확인"을 한다.
