# 02. 검색엔진이 이해하기 쉬운 페이지 만들기 — title · description · 제목 구조 · alt · robots

> 과정: SEO과정 · [노션 원문](https://app.notion.com/p/41a848f71c9b8092a0c2d259c2324027) · 최종 갱신일: 2026-11-18

## 한눈에 보기
- 검색엔진은 화면 디자인이 아니라 **HTML에 담긴 제목·설명·본문·링크**로 페이지를 이해한다. SEO의 기본은 **페이지가 무엇을 제공하는지 명확하게 표현**하는 것이다.
- `<head>` 안의 **`<title>`**(문서 제목, 브라우저 탭)과 **`<meta name="description" content="…">`**(페이지 요약)을 서비스에 맞게 쓴다. 검색 결과의 제목·요약문에 참고되지만, 다른 문구가 표시될 수도 있다.
- 본문은 글자 크기가 아니라 **내용의 관계**로 `h1`(대표 제목 하나) → `h2` → `h3`를 고른다. 이미지 `alt`는 이미지 내용을, 링크 문구는 이동할 곳을 설명한다. 키워드 나열은 피한다.
- **`robots.txt`** 는 크롤러의 **수집 경로**를 안내하고, **`noindex`** 는 페이지를 **색인에서 빼 달라고** 요청한다. 둘 다 보안 기능이 아니다. 보호할 정보는 **로그인·접근 권한**으로 막는다.
- Vite React 프로젝트는 최상위 `index.html`의 제목·설명부터 고친다. 하지만 그것만으로 React 사이트의 SEO가 끝나지는 않는다.

## 학습 목표
- 페이지 제목과 설명을 작성할 수 있다.
- 제목 태그로 본문의 구조를 표현할 수 있다.
- 이미지와 링크에 의미 있는 설명을 넣을 수 있다.
- 검색을 막는 설정이 있는지 확인할 수 있다.

## 핵심 개념

### 1. 검색엔진도 페이지를 이해할 수 있어야 한다
사람은 화면의 디자인과 내용을 보고 판단하지만, 검색엔진은 **HTML에 담긴 제목, 설명, 본문, 링크 등의 정보**로 페이지를 이해한다.

```html
<title>Vite + React</title>
```

이 제목만으로는 어떤 서비스인지 알기 어렵다. 서비스를 설명하는 제목으로 바꾼다.

```html
<title>한코딩 | 웹 개발 기초와 실습 강의</title>
```

**SEO의 기본은 페이지가 어떤 내용을 제공하는지 명확하게 표현하는 것이다.**

### 2. 페이지 제목 — `title`
`<title>`은 HTML 문서의 제목이고 **`<head>` 안에** 쓴다 ([01_HTML](../01_React과정/01_HTML.md) 3장).

```html
<head>
  <meta charset="UTF-8" />
  <title>한코딩 | 웹 개발 기초와 실습 강의</title>
</head>
```

- 브라우저 **탭**에 표시된다.
- 검색엔진도 검색 결과의 제목을 만들 때 참고한다. 다만 본문 등을 바탕으로 **다른 제목이 표시될 수도 있다.** 👉 [Google 제목 작성 안내](https://developers.google.com/search/docs/appearance/title-link?hl=ko)

**작성법: 페이지의 핵심 내용과 서비스 이름을 함께 적는다.**

| 페이지 | 제목 예시 |
|---|---|
| 서비스 메인 | `한코딩 \| 웹 개발 기초와 실습 강의` |
| React 강의 소개 | `React 기초 강의 \| 한코딩` |
| 일정 관리 앱 소개 | `이니치니 \| 일정과 수입을 관리하는 캘린더` |

- 페이지가 여러 개면 **페이지마다 내용에 맞는 제목**을 쓴다.
- 같은 단어를 반복해 나열하지 않는다.

```html
<title>코딩 코딩강의 코딩교육 코딩공부 개발 개발자 한코딩</title>
```

> React의 `App.jsx`에 표시하는 큰 제목과 브라우저 탭의 제목은 서로 다른 내용이다 ([04_React시작](../01_React과정/04_React시작.md) 4장 "HTML은 어디에 있을까?").

### 3. 페이지 설명 — `meta description`
페이지 내용을 요약하는 설명이다. `<title>`처럼 **`<head>` 안에** 쓴다.

```html
<meta
  name="description"
  content="한코딩에서 HTML, CSS, JavaScript와 React를 예제로 배우고 직접 웹 서비스를 만들어 보세요."
/>
```

| 코드 | 의미 |
|---|---|
| `name="description"` | 페이지 설명이라는 뜻 |
| `content="..."` | 실제 설명 내용 |

검색엔진은 이 설명을 **검색 결과의 요약문**으로 쓸 수 있다. 검색어와 페이지 내용에 따라 본문의 다른 부분이 표시될 수도 있다. 👉 [Google 메타 설명 안내](https://developers.google.com/search/docs/appearance/snippet?hl=ko)

**설명에 넣을 것** — 짧고 자연스러운 문장으로: 어떤 서비스인지 / 누구에게 도움이 되는지 / 무엇을 할 수 있는지.

내용이 모호한 설명:

```html
<meta
  name="description"
  content="최고의 서비스입니다. 다양한 기능을 제공합니다."
/>
```

기능을 이해할 수 있는 설명:

```html
<meta
  name="description"
  content="반복되는 근무 일정과 약속을 캘린더로 관리하고, 등록한 근무를 바탕으로 수입을 확인할 수 있는 서비스입니다."
/>
```

- **설명은 실제 페이지가 제공하는 내용과 일치해야 한다.**
- 설명은 화면 본문에 나타나지 않는다. 브라우저의 **페이지 소스 보기**에서 `description`을 검색해 확인한다.

### 4. 본문의 제목 구조 — `h1`, `h2`, `h3`
다음은 글자가 커 보여도 HTML에서는 **일반 문단**이다.

```html
<p style="font-size: 32px;">한코딩 웹 개발 강의</p>
```

페이지의 대표 제목이라면 제목 태그를 쓴다.

```html
<h1>한코딩 웹 개발 강의</h1>
```

하위 내용은 `h2`, `h3`로 나눈다.

```html
<h1>한코딩 웹 개발 강의</h1>

<p>기초 문법부터 실제 서비스 제작까지 예제로 배웁니다.</p>

<h2>배우는 내용</h2>

<h3>프론트엔드</h3>
<p>HTML, CSS, JavaScript와 React를 배웁니다.</p>

<h3>백엔드</h3>
<p>Node.js와 Spring으로 서버를 만들어 봅니다.</p>

<h2>학습 방법</h2>
<p>개념을 배우고 예제를 실행한 뒤 직접 수정합니다.</p>
```

```text
h1: 페이지의 대표 제목
 ├─ h2: 배우는 내용
 │   ├─ h3: 프론트엔드
 │   └─ h3: 백엔드
 └─ h2: 학습 방법
```

- **제목 태그는 글자 크기가 아니라 내용의 관계로 고른다.** 디자인은 CSS로 조절한다 ([01_HTML](../01_React과정/01_HTML.md) 4장).
- 이번 실습에서는 **대표 제목을 `h1` 하나**로 정리하고, 주요 항목을 `h2`로 나눈다.

### 5. 이미지와 링크도 의미를 전달해야 한다

**이미지 설명 — `alt`**: 이미지가 전달하는 내용을 글로 설명하는 속성이다. 이미지를 볼 수 없는 상황이나 **화면 낭독기**를 쓸 때도 도움이 된다 ([01_HTML](../01_React과정/01_HTML.md) 6장).

```html
<img
  src="profile.png"
  alt="한코딩 강사의 프로필 사진"
/>
```

실제 이미지와 관계없는 검색어를 나열하지 않는다.

```html
<img
  src="profile.png"
  alt="코딩 개발자 취업 React Spring 무료 강의"
/>
```

- **이미지의 내용과 쓰임새를 설명하는 것이 기준**이다.
- 정보를 전달하지 않는 **단순 장식 이미지는 빈 설명**을 쓸 수 있다.

```html
<img src="decoration.png" alt="" />
```

**링크 설명 — `a`**: 눌렀을 때 무엇을 볼 수 있는지 알 수 있게 쓴다.

목적이 불분명한 링크:

```html
<a href="/courses">여기를 클릭하세요</a>
```

목적이 분명한 링크:

```html
<a href="/courses">웹 개발 강의 목록 보기</a>
```

`href`에는 **실제로 이동할 페이지 주소**를 넣는다. `/courses`는 예시이므로 프로젝트에 있는 주소로 바꾼다.

### 6. 검색을 막는 설정 — `robots.txt`와 `noindex`
제목·설명을 잘 써도 검색엔진이 페이지를 **읽지 못하거나**, **검색에 넣지 않도록** 설정되어 있을 수 있다. 여기서는 두 가지의 **역할 차이**만 알아둔다.

**`robots.txt` — 크롤러의 수집 접근 안내**
- 사이트의 **최상위 경로**에서 제공하는 텍스트 파일이다 (사이트 주소 뒤에 `/robots.txt`).
- 다음 설정은 이를 따르는 크롤러에게 **사이트 전체를 수집하지 말라고** 안내한다.

```text
User-agent: *
Disallow: /
```

| 항목 | 의미 |
|---|---|
| `User-agent: *` | 모든 크롤러를 대상으로 하는 규칙 |
| `Disallow: /` | 사이트 전체 경로의 수집을 제한 |

- 공개하려는 서비스에 이런 설정이 있다면 **의도한 설정인지** 확인한다.
- **`robots.txt`는 로그인·비밀번호처럼 접근을 막는 보안 기능이 아니다.** 수집을 막았다고 검색 결과에서 주소가 반드시 사라지는 것도 아니다. 👉 [Google robots.txt 안내](https://developers.google.com/search/docs/crawling-indexing/robots/intro?hl=ko)

**`noindex` — 검색 색인에 넣지 않도록 요청**

```html
<meta name="robots" content="noindex" />
```

- **검색에서 제외하려는 페이지의 예시**다. 검색에 알리고 싶은 공개 페이지에는 넣지 않는다.
- 검색엔진이 이 태그를 보려면 **페이지를 수집할 수 있어야** 한다. `robots.txt`로 수집을 막으면 페이지 안의 `noindex`도 읽지 못할 수 있다. 👉 [Google noindex 안내](https://developers.google.com/search/docs/crawling-indexing/block-indexing?hl=ko)

| 구분 | 역할 |
|---|---|
| `robots.txt` | 크롤러가 수집할 수 있는 경로 안내 |
| `noindex` | 페이지를 검색 색인에서 제외하도록 요청 |
| 로그인·접근 권한 | 허용된 사용자만 내용을 보도록 제한 |

학생 개인정보나 관리자 화면처럼 보호해야 하는 정보는 **로그인과 접근 권한으로 보호해야 한다.**

### 7. React 프로젝트에 적용할 때
Vite로 만든 React 프로젝트에서는 먼저 **`index.html`의 기본 제목과 설명**을 고친다.

```html
<title>한코딩 | 웹 개발 기초와 실습 강의</title>

<meta
  name="description"
  content="웹 개발 기초를 배우고 직접 사용하는 서비스를 만들어 보는 한코딩 강의 사이트입니다."
/>
```

- 다만 **제목과 설명을 넣는 것만으로 React 사이트의 SEO가 끝나지는 않는다.**
- React가 JavaScript를 실행한 뒤 본문을 만드는 경우, 검색엔진이 그 내용을 처리하는 방식도 고려해야 한다. 페이지가 여러 개면 페이지별 제목·설명과 본문 제공 방식도 함께 검토한다.
- 이번 실습은 **기본 정보를 정확하게 쓰고, 의미 있는 본문 구조를 만드는 것**에 집중한다.

> 💡 보충: Vite React 앱은 처음 받은 HTML에 `<div id="root"></div>`만 있고, 본문은 브라우저가 JavaScript를 실행한 뒤 채운다. 그래서 `index.html`의 `<head>`에 직접 쓴 `title`·`description`은 처음 HTML에 들어 있지만, `App.jsx`가 만든 본문은 그렇지 않다. 이 차이는 [03_사이트등록-소유확인](03_사이트등록-소유확인.md)의 "페이지 소스 보기 vs 개발자 도구"에서 다시 나온다.

### 정리

| 요소 | 역할 | 작성 기준 |
|---|---|---|
| `title` | 문서 제목 | 페이지의 핵심 내용과 서비스 이름 |
| `meta description` | 페이지 요약 | 실제 제공하는 내용을 자연스럽게 설명 |
| `h1`~`h3` | 본문 제목 구조 | 내용의 관계에 따라 구분 |
| `alt` | 이미지 대체 설명 | 이미지의 내용과 쓰임새 설명 |
| `a href` | 다른 위치로 이동하는 링크 | 이동 목적이 드러나는 문구와 유효한 주소 |
| `robots.txt` | 크롤러 수집 경로 안내 | 공개 페이지를 실수로 막지 않았는지 확인 |
| `noindex` | 검색 색인 제외 요청 | 검색에 포함할 페이지에 잘못 들어가지 않았는지 확인 |

## 실습 정리

### 실습 1. 내 페이지 제목 바꾸기
현재 프로젝트에서 `<title>`을 찾아 서비스에 맞게 고친다.

| 프로젝트 | 고칠 파일 |
|---|---|
| Vite로 만든 React 프로젝트 | 프로젝트 최상위의 `index.html` |
| Spring + Thymeleaf 프로젝트 | 현재 화면을 만드는 HTML 템플릿 |

고친 뒤 새로고침하고 **브라우저 탭의 제목이 바뀌었는지** 확인한다.

### 실습 2. 내 서비스 소개 문장 넣기
현재 페이지의 `<head>`에 설명을 추가한다.

```html
<head>
  <meta charset="UTF-8" />

  <title>한코딩 | 웹 개발 기초와 실습 강의</title>

  <meta
    name="description"
    content="한코딩에서 HTML, CSS, JavaScript와 React를 예제로 배우고 직접 웹 서비스를 만들어 보세요."
  />
</head>
```

설명은 화면에 안 보이므로 **페이지 소스 보기**에서 `description`을 검색해 확인한다.

### 실습 3. 배운 내용을 한 페이지에 적용하기 (종합 코드)
별도 폴더에 `index.html`을 만들고, 같은 폴더에 `profile.png`를 넣어 실행한다.

```html
<!DOCTYPE html>
<html lang="ko">
  <head>
    <meta charset="UTF-8" />

    <meta
      name="viewport"
      content="width=device-width, initial-scale=1.0"
    />

    <title>한코딩 | 웹 개발 기초와 실습 강의</title>

    <meta
      name="description"
      content="한코딩에서 HTML, CSS, JavaScript와 React를 예제로 배우고 직접 웹 서비스를 만들어 보세요."
    />
  </head>

  <body>
    <header>
      <h1>한코딩 웹 개발 강의</h1>
      <p>기초부터 배우고, 직접 사용하는 서비스를 만듭니다.</p>

      <nav>
        <a href="#learning">배우는 내용 살펴보기</a>
        <a href="#instructor">강사 소개 보기</a>
      </nav>
    </header>

    <main>
      <section id="learning">
        <h2>배우는 내용</h2>

        <h3>프론트엔드 개발</h3>
        <p>
          HTML, CSS, JavaScript와 React로
          사용자가 보는 화면을 만듭니다.
        </p>

        <h3>백엔드 개발</h3>
        <p>
          Node.js와 Spring으로 요청을 처리하고
          데이터를 보내는 서버를 만듭니다.
        </p>
      </section>

      <section id="instructor">
        <h2>강사 소개</h2>

        <img
          src="profile.png"
          alt="한코딩 강사의 프로필 사진"
          width="200"
        />

        <p>
          한코딩 강의 사이트와 앱을 운영하는
          한코딩 강사입니다.
        </p>
      </section>
    </main>
  </body>
</html>
```

> 💡 보충: `href="#learning"`은 같은 페이지 안에서 `id="learning"`인 요소로 이동하는 링크다. `header`·`nav`·`main`·`section`은 [01_HTML](../01_React과정/01_HTML.md) 8장의 시맨틱 태그다. 노션 페이지 맨 위에 노트북 앞에 앉은 고양이 캐릭터 그림이 있는데, 실습용 `profile.png`가 없으면 이런 그림을 써도 된다 (그때는 `alt`도 그림 내용에 맞게 바꾼다).

**실행 결과 확인하기**
1. 브라우저 탭에 작성한 제목이 표시되는지 본다.
2. 본문의 큰 제목(`h1`)과 하위 제목(`h2`·`h3`)을 확인한다.
3. 소개 링크를 눌러 해당 위치로 이동하는지 본다.
4. 이미지와 `alt` 설명이 실제 내용에 맞는지 본다.
5. 페이지 소스에서 `title`과 `description`을 찾아본다.

> 이 파일을 내 컴퓨터에서 열었다고 검색엔진에 공개되는 것은 아니다. 실제 검색 대상이 되려면 **외부에서 접근할 수 있는 주소로 배포**해야 한다 ([01_SEO-검색엔진](01_SEO-검색엔진.md) 5장).

## 헷갈리기 쉬운 점
- **`title`과 `meta description`은 `<head>` 안**에 쓴다. 화면 본문에 나오지 않는다 (탭 제목, 페이지 소스로 확인).
- **브라우저 탭 제목(`title`) ≠ `App.jsx`의 큰 제목(`h1`).** Vite React는 최상위 `index.html`에서 `title`을 고친다.
- **검색 결과의 제목·요약문은 내가 쓴 `title`·`description`과 다를 수 있다.** 검색엔진이 본문 등을 보고 바꿔 표시할 수 있다.
- **키워드를 반복 나열하지 않는다** — 제목, `alt` 모두. 실제 내용을 자연스럽게 설명한다. 설명은 실제 페이지 내용과 일치해야 한다.
- **글자를 크게 만든 `p`는 제목이 아니다.** 제목 태그는 크기가 아니라 내용 관계로 고르고, 대표 제목 `h1`은 하나로.
- **장식용 이미지는 `alt=""`**(빈 값). 의미 있는 이미지는 내용과 쓰임새를 설명한다.
- **"여기를 클릭하세요"는 목적이 불분명한 링크.** 이동할 곳이 드러나게 쓰고, `href`는 실제 존재하는 주소로.
- **`robots.txt` = 수집 경로 안내, `noindex` = 색인 제외 요청, 로그인 = 보호.** `robots.txt`·`noindex`는 보안 기능이 아니다.
- **`robots.txt`로 수집을 막으면 `noindex`를 못 읽을 수 있다.** 수집을 막았다고 주소가 검색에서 반드시 사라지지도 않는다.
- **`noindex`를 공개 페이지에 그대로 붙이지 않는다.**
- **제목·설명을 넣어도 검색 노출은 보장되지 않는다.** React 사이트는 본문 제공 방식도 고려해야 한다.

## 확인 문제
강의에 별도 "💬 확인하기"는 없어서, 본문의 질문형 제목과 강조된 내용, 실습 확인 항목에서 뽑았다.

<details><summary>Q. `<title>Vite + React</title>`를 그대로 두면 왜 아쉬운가? 어떻게 고치나?</summary>

어떤 서비스인지 알 수 없다. 검색엔진은 HTML의 제목·설명·본문으로 페이지를 이해하므로, `한코딩 | 웹 개발 기초와 실습 강의`처럼 **페이지의 핵심 내용과 서비스 이름**을 함께 적는다.
</details>

<details><summary>Q. (강의 질문) 제목은 어떻게 작성하면 좋을까? 피해야 할 방식은?</summary>

페이지의 핵심 내용 + 서비스 이름. 페이지가 여러 개면 페이지마다 내용에 맞는 제목. `코딩 코딩강의 코딩교육 …`처럼 같은 단어를 반복 나열하는 방식은 피한다.
</details>

<details><summary>Q. 내가 쓴 `title`이 검색 결과에 항상 그대로 나오나?</summary>

아니다. 검색엔진이 참고하지만, 본문 등의 정보를 바탕으로 다른 제목이 표시될 수 있다. `description`도 검색어·내용에 따라 본문의 다른 부분이 요약문으로 나올 수 있다.
</details>

<details><summary>Q. React의 `App.jsx`에 쓴 `<h1>`과 브라우저 탭 제목은 같은가? Vite 프로젝트에서 탭 제목은 어디서 고치나?</summary>

다르다. 탭 제목은 `<title>`이고, Vite 프로젝트에서는 **프로젝트 최상위 `index.html`** 의 `<head>`에서 고친다. Spring + Thymeleaf는 화면을 만드는 HTML 템플릿에서 고친다.
</details>

<details><summary>Q. `meta description`은 어디에 어떻게 쓰나? `name`과 `content`의 의미는?</summary>

`<head>` 안에 `<meta name="description" content="…" />`. `name="description"`은 페이지 설명이라는 뜻, `content`는 실제 설명 내용이다.
</details>

<details><summary>Q. (강의 질문) 설명에는 무엇을 넣을까? "최고의 서비스입니다. 다양한 기능을 제공합니다."는 왜 나쁜가?</summary>

어떤 서비스인지, 누구에게 도움이 되는지, 무엇을 할 수 있는지를 짧고 자연스러운 문장으로 쓴다. 예시 문장은 모호해서 기능을 알 수 없다. 설명은 실제 페이지 내용과 일치해야 한다.
</details>

<details><summary>Q. `description`을 넣었는데 화면에 안 보인다. 들어갔는지 어떻게 확인하나?</summary>

설명은 본문에 나타나지 않는 정보다. 브라우저의 **페이지 소스 보기**에서 `description`을 검색해 확인한다.
</details>

<details><summary>Q. `<p style="font-size: 32px;">한코딩 웹 개발 강의</p>`는 왜 제목으로 적절하지 않나?</summary>

글자만 클 뿐 HTML에서는 일반 문단이다. 대표 제목이면 `<h1>`을 쓴다. 제목 태그는 **글자 크기가 아니라 내용의 관계**로 고르고, 크기는 CSS로 조절한다. 대표 제목은 `h1` 하나, 주요 항목은 `h2`, 그 아래는 `h3`.
</details>

<details><summary>Q. `alt`는 무엇을 위해 쓰나? 장식용 이미지와 키워드 나열 `alt`는 어떻게 하나?</summary>

이미지가 전달하는 내용을 글로 설명한다. 이미지를 볼 수 없거나 화면 낭독기를 쓸 때도 도움이 된다. 이미지의 내용·쓰임새를 설명하고, 관계없는 검색어는 나열하지 않는다. 정보가 없는 장식 이미지는 `alt=""`.
</details>

<details><summary>Q. `<a href="/courses">여기를 클릭하세요</a>`를 고친다면?</summary>

`<a href="/courses">웹 개발 강의 목록 보기</a>`처럼 눌렀을 때 무엇을 볼 수 있는지 드러나게 쓴다. `href`에는 프로젝트에 실제로 있는 주소를 넣는다.
</details>

<details><summary>Q. 다음 `robots.txt`는 무슨 뜻인가? `robots.txt`로 개인정보를 보호할 수 있나?</summary>

```text
User-agent: *
Disallow: /
```

모든 크롤러(`*`)에게 사이트 전체(`/`)를 수집하지 말라고 안내한다. 보안 기능이 아니므로 개인정보는 보호할 수 없다. 수집을 막아도 주소가 검색 결과에서 반드시 사라지지도 않는다. 보호는 로그인·접근 권한으로 한다.
</details>

<details><summary>Q. `robots.txt`와 `noindex`의 역할 차이는? 둘을 함께 쓰면 생길 수 있는 문제는?</summary>

`robots.txt`: 크롤러가 **수집**할 수 있는 경로 안내. `noindex`(`<meta name="robots" content="noindex" />`): 페이지를 **색인에서 제외**하도록 요청. `noindex`를 읽으려면 페이지를 수집할 수 있어야 해서, `robots.txt`로 수집을 막으면 `noindex`를 못 읽을 수 있다.
</details>

<details><summary>Q. Vite React 프로젝트에서 `index.html`에 제목·설명을 넣으면 SEO가 끝나나?</summary>

아니다. React가 JavaScript를 실행한 뒤 본문을 만드는 경우 검색엔진이 그 내용을 처리하는 방식도 고려해야 하고, 페이지가 여러 개면 페이지별 제목·설명과 본문 제공 방식도 검토해야 한다.
</details>

<details><summary>Q. 내 컴퓨터에서 연 `index.html`은 검색엔진에 공개되나?</summary>

아니다. 실제 검색 대상이 되려면 외부에서 접근할 수 있는 주소로 배포해야 한다. 제목·설명을 잘 써도 검색 노출이 보장되지는 않는다.
</details>
