# 03. 구글·네이버에 사이트 등록하기 — HTML 태그로 소유권 확인

> 과정: SEO과정 · [노션 원문](https://app.notion.com/p/41a848f71c9b80e0a36ee1ba38a45570) · 최종 갱신일: 2026-11-18

## 한눈에 보기
- 사이트 운영자는 **검색 관리 도구**로 수집·색인 상태와 문제를 확인한다. 구글은 **Google Search Console(구글 서치 콘솔)**, 네이버는 **네이버 서치어드바이저의 웹마스터 도구**다. **등록만으로 검색 노출이나 순위는 보장되지 않는다.**
- 관리 도구는 "이 사이트를 실제로 관리할 수 있는 사람인가?"를 **소유권 확인**으로 묻는다. 이번에는 도구가 발급한 **확인용 메타 태그**를 메인 페이지 `<head>`에 넣어 증명한다.
- 흐름: **태그 발급 → `<head>`에 추가 → 다시 배포 → 페이지 소스 보기로 태그 확인 → 관리 도구에서 확인 버튼.** 저장만 하고 확인 버튼을 누르면 실패한다. 관리 도구는 내 컴퓨터가 아니라 **배포된 사이트**를 읽는다.
- 구글은 **URL 접두어** 속성(HTML 태그로 확인 가능)으로 등록한다. **도메인** 속성은 DNS 설정으로 확인한다.
- 네이버는 소유확인 때 **JavaScript를 실행하지 않는다.** 확인 태그는 React 코드(`App.jsx`)가 아니라 처음 전달되는 HTML(`index.html`)의 `<head>`에 직접 넣는다. 확인 후에도 두 태그는 **지우지 않는다.**

## 학습 목표
- 구글 서치 콘솔과 네이버 서치어드바이저의 역할을 이해한다.
- 사이트 소유권을 확인하는 이유를 설명할 수 있다.
- HTML 태그를 이용해 사이트 소유권을 확인할 수 있다.
- 소유권 확인이 실패했을 때 점검할 부분을 알 수 있다.

## 핵심 개념

### 1. 사이트를 등록하면 무엇이 좋을까?
배포하면 주소로 접속할 수 있지만, 운영자는 이런 것도 알고 싶다.
- 검색엔진이 우리 사이트를 수집하고 있을까?
- 검색에 포함된 페이지는 무엇일까?
- 검색 과정에서 문제가 생기지는 않았을까?
- 어떤 검색어로 사람들이 방문할까?

이를 확인하고 검색 상태를 관리하려고 **검색엔진이 제공하는 사이트 관리 도구**를 쓴다.

| 검색엔진 | 관리 도구 |
|---|---|
| 구글 | Google Search Console — 구글 서치 콘솔 |
| 네이버 | 네이버 서치어드바이저의 웹마스터 도구 |

> 네이버 검색 관련 사이트 등록은 **네이버 서치어드바이저**에서 한다. 네이버 클라우드 콘솔과는 다른 서비스다 ([01_SEO-검색엔진](01_SEO-검색엔진.md) 7장).

- **사이트 등록은 검색 상태를 관리하기 위한 과정이다. 등록만으로 검색 노출이나 상위 순위가 보장되지 않는다.**
- 네이버도 등록 없이 검색에 반영될 수 있고, 등록·소유확인을 거치면 수집·색인·노출 정보를 확인할 수 있다고 안내한다. 👉 [네이버 사이트 등록 안내](https://searchadvisor.naver.com/guide/faq-start-register)

### 2. 소유권 확인은 왜 필요할까?
다른 사람이 우리 사이트를 마음대로 관리하면 안 된다. 그래서 관리 도구는 확인한다.

> "이 사이트를 실제로 수정하거나 관리할 수 있는 사람인가요?"

이번에는 사이트 HTML에 **확인용 메타 태그**를 넣어 증명한다.

```text
관리 도구에서 확인용 태그 발급
              ↓
사이트 HTML에 태그 추가
              ↓
수정한 사이트 다시 배포
              ↓
관리 도구에서 확인 버튼 클릭
              ↓
관리 도구가 사이트의 태그를 확인
```

확인용 태그는 화면에 표시하는 문구가 아니다. **HTML의 `<head>` 안**에 넣는다.

> 💡 보충: HTML을 고칠 수 있다는 것 = 그 사이트를 관리할 수 있다는 증거다. 그래서 도구가 발급한 값(사람마다 다름)이 실제 사이트에 올라와 있는지 확인하는 방식으로 소유권을 증명한다.

### 3. 실습 전 준비

| 준비물 | 설명 |
|---|---|
| 구글 계정 | 서치 콘솔 로그인 |
| 네이버 계정 | 서치어드바이저 로그인 |
| 외부에서 접속할 수 있는 내 사이트 주소 | 배포된 사이트의 **메인 주소** |
| HTML을 수정하고 다시 배포할 수 있는 환경 | **수정 권한이 있는** 사이트여야 함 |

```text
https://my-service.example.com/
```

- 위 주소는 설명용 예시다. 실습할 때는 본인 주소로 바꾼다.
- 내 컴퓨터에서만 실행되는 주소로는 실습할 수 없다.

```text
http://localhost:5173/
http://localhost:8080/
```

- 사이트 주소를 **시크릿 창**에서 열어, 로그인하지 않아도 서비스 소개 화면이 정상적으로 보이는지 확인한다.
- 아직 배포하지 않았다면 강사 시연으로 과정을 먼저 본다. 실제 소유권 확인에는 외부에서 접근할 수 있는 사이트가 필요하다.

### 4. 구글의 속성 — 도메인 vs URL 접두어
**속성**은 서치 콘솔에서 관리할 사이트나 주소 범위를 뜻한다.

| 방식 | 관리 범위 | 확인 방법 |
|---|---|---|
| 도메인 | 여러 프로토콜과 하위 도메인을 포함하는 범위 | DNS 설정으로 확인 |
| URL 접두어 | 입력한 프로토콜·호스트·경로로 시작하는 범위 | HTML 태그 등으로 확인 가능 |

- 이번 실습은 **URL 접두어**를 선택한다. HTML을 고치는 방식이라 **DNS 설정은 바꾸지 않는다** (DNS는 도메인 주소와 관련된 설정).
- URL 접두어 속성은 **입력한 주소 범위**를 기준으로 관리하므로, `https://`와 `www` 유무까지 실제 주소와 맞춘다.
- HTML 태그 방식은 URL 접두어 속성에서 쓸 수 있다. 👉 [Google 소유권 확인 안내](https://support.google.com/webmasters/answer/9008080?hl=ko)

> 💡 보충: 예를 들어 URL 접두어로 `https://my-service.example.com/`을 등록하면 `http://…`나 `https://www.my-service.example.com/`은 다른 범위다. 도메인 속성(`example.com`)은 이런 변형과 하위 도메인을 한꺼번에 포함한다.

### 5. 확인 태그는 메인 페이지의 `<head>`에

```html
<meta name="google-site-verification" content="구글에서_발급받은_실제_확인값"/>
```

```html
<meta name="naver-site-verification" content="네이버에서_발급받은_실제_확인값"/>
```

- **예시 값을 그대로 쓰면 확인되지 않는다.** 본인 화면에서 발급된 **태그 전체**를 복사한다.
- **구글과 네이버의 확인 태그는 함께 넣어도 된다.**

| 프로젝트 | 수정할 위치 |
|---|---|
| 일반 HTML 사이트 | 메인 페이지의 HTML |
| Vite React 프로젝트 | 프로젝트 최상위의 `index.html` |
| Spring + Thymeleaf | 메인 페이지를 응답하는 HTML 템플릿 |

Spring 프로젝트에서는 **파일 이름보다 실제 메인 주소에서 어떤 HTML을 응답하는지**가 중요하다 ([03_Thymeleaf-학생목록](../03_Spring과정/03_Thymeleaf-학생목록.md)).

### 6. 저장 ≠ 배포
파일을 저장한 것만으로는 배포된 사이트가 바뀌지 않는다. 평소 쓰는 배포 방식으로 반영한다.

```text
코드 수정 → 저장 → 빌드·배포 → 실제 사이트 확인
```

**관리 도구는 내 컴퓨터의 코드를 읽지 않는다.** 인터넷에 배포된 사이트를 확인하므로 **배포를 마친 뒤** 확인 버튼을 누른다.

### 7. 페이지 소스 보기 vs 개발자 도구
개발자 도구에서 태그가 보여도, 서버가 처음 보낸 HTML에는 없을 수 있다.

| 확인 방법 | 확인하는 내용 |
|---|---|
| 페이지 소스 보기 | 서버에서 전달받은 HTML |
| 개발자 도구의 Elements | JavaScript 실행 후 변경된 현재 화면 구조 |

- 이번 실습은 **페이지 소스 보기**로 인증 태그를 확인한다. 크롬: 페이지 빈 곳을 마우스 오른쪽 클릭 → **페이지 소스 보기** → 검색으로 `google-site-verification`, `naver-site-verification`을 각각 찾는다.
- **코드 편집기에 태그가 있다 ≠ 실제 배포된 HTML에 태그가 있다.**
- 네이버는 소유확인 과정에서 **JavaScript를 실행하지 않는다.** 그래서 React 코드가 실행된 뒤 태그를 추가하는 방식이 아니라, **처음 전달되는 HTML의 `<head>`에 직접** 넣어야 한다. 👉 [네이버 소유확인 주의사항](https://searchadvisor.naver.com/guide/faq-start-register)

### 8. 확인 후에도 태그는 유지
**확인이 끝나도 인증 태그는 지우지 않는다.** Google이 소유권을 다시 확인할 수 있기 때문이다. 👉 [Google 소유권 유지 안내](https://support.google.com/webmasters/answer/9008080?hl=ko)

### 정리

| 항목 | 핵심 내용 |
|---|---|
| 구글 서치 콘솔 | 구글 검색에서 사이트 상태를 관리하는 도구 |
| 네이버 서치어드바이저 | 네이버 검색에서 사이트 상태를 관리하는 도구 |
| 소유권 확인 | 사이트를 관리할 수 있는 사람인지 확인하는 과정 |
| HTML 태그 방식 | 발급받은 메타 태그를 메인 페이지의 `<head>`에 추가 |
| 배포 | 수정한 태그를 외부에서 확인할 수 있도록 반영 |
| 페이지 소스 보기 | 실제 전달된 HTML에 인증 태그가 있는지 확인 |
| 등록 완료의 의미 | 사이트 관리 권한 확인 완료이며, 검색 노출 보장은 아님 |

## 실습 정리

### 실습 1. 구글 서치 콘솔에 등록하기
1. **접속** — 👉 [구글 서치 콘솔](https://search.google.com/search-console)에 구글 계정으로 로그인하고 사이트 추가 화면으로 간다. 이미 다른 사이트가 있으면 사이트 선택 메뉴에서 **속성 추가**.
2. **URL 접두어 선택** — 입력란에 실제 배포 주소를 넣는다 (`https://`, `www` 유무 확인).

```text
https://my-service.example.com/
```

3. **HTML 태그 복사** — 소유권 확인 방법 중 **HTML 태그** 항목에서 발급된 태그 전체를 복사한다.
4. **`<head>`에 붙여넣기** — 메인 페이지 HTML의 `<head>` 안에 넣는다.

```html
<head>
  <meta charset="UTF-8" />

  <title>한코딩 | 웹 개발 기초와 실습 강의</title>

  <meta
    name="description"
    content="웹 개발 기초를 배우고 직접 사용하는 서비스를 만드는 한코딩 강의 사이트입니다."
  />

  <meta
    name="google-site-verification"
    content="구글에서_발급받은_실제_확인값"
  />
</head>
```

5. **다시 배포** — 배포 후 사이트를 열고 **페이지 소스 보기**에서 `google-site-verification`을 검색해 태그가 보이는지 확인한다.
6. **확인 버튼** — 서치 콘솔로 돌아가 **확인**을 누른다. 완료되면 그 사이트의 관리 화면으로 들어갈 수 있다. **태그는 그대로 둔다.**

### 실습 2. 네이버 서치어드바이저에 등록하기
1. **접속** — 👉 [네이버 서치어드바이저](https://searchadvisor.naver.com/)에 네이버 계정으로 로그인 → **웹마스터 도구**.
2. **사이트 추가** — 사이트 등록 입력란에 배포된 사이트의 대표 주소를 넣는다. 추가하면 소유확인 방법 선택 화면으로 간다.

```text
https://my-service.example.com/
```

3. **HTML 태그 방식 선택** — 소유확인 방법에서 **HTML 태그**를 고르고, 발급된 태그 전체를 복사한다.
4. **`<head>`에 네이버 태그 추가** — 구글 태그는 그대로 두고 추가한다 (최종 `<head>`).

```html
<head>
  <meta charset="UTF-8" />

  <title>한코딩 | 웹 개발 기초와 실습 강의</title>

  <meta
    name="description"
    content="웹 개발 기초를 배우고 직접 사용하는 서비스를 만드는 한코딩 강의 사이트입니다."
  />

  <meta
    name="google-site-verification"
    content="구글에서_발급받은_실제_확인값"
  />

  <meta
    name="naver-site-verification"
    content="네이버에서_발급받은_실제_확인값"
  />
</head>
```

5. **다시 배포하고 소유확인** — 메인 페이지 **페이지 소스 보기**에서 `naver-site-verification`을 찾고, 보이면 서치어드바이저로 돌아가 **소유확인**을 진행한다. 완료되면 사이트 목록에서 그 사이트를 골라 관리 화면으로 들어간다. 👉 [네이버 HTML 태그 소유확인 안내](https://help.naver.com/service/30010/contents/17595?lang=ko&osType=PC)

> 💡 보충: 이 wiki는 공개 저장소에 올라가므로, 실제로 발급받은 확인값은 여기에 적지 않는다. 확인값은 내 프로젝트의 `index.html`(또는 템플릿)에만 둔다.

## 헷갈리기 쉬운 점
- **등록·소유 확인 완료 = 관리 권한 확인**일 뿐, 검색 노출·순위 보장이 아니다.
- **예제의 확인값(`구글에서_발급받은_실제_확인값`)을 그대로 쓰면 실패한다.** 내 계정에서 발급받은 태그 전체를 쓴다.
- **확인 태그는 `<head>` 안에.** `<body>`나 React 화면(`App.jsx`) 안에 넣지 않는다.
- **저장 ≠ 배포.** 관리 도구는 배포된 사이트를 읽는다. 배포를 마친 뒤 확인 버튼을 누른다.
- **확인은 "페이지 소스 보기"로.** 개발자 도구 Elements는 JavaScript 실행 후 화면이라, 거기서 보여도 처음 HTML에는 없을 수 있다. 네이버는 JavaScript를 실행하지 않는다.
- **URL 접두어 속성은 입력한 주소 범위 기준** — `https://`·`www` 유무까지 실제 주소와 맞춘다. 도메인 속성은 DNS로 확인한다.
- **구글·네이버 태그는 함께 넣어도 되고, 확인 후에도 지우지 않는다.**
- **Spring은 파일 이름보다 "메인 주소에서 응답하는 HTML"** 을 고쳐야 한다.

**자주 하는 실수** — ① 예제 확인값을 그대로 쓰기 ② `App.jsx` 본문에 넣기 ③ 저장만 하고 확인 버튼 누르기. ②는 이런 코드다 (이렇게 하지 않는다).

```jsx
function App() {
  return (
    <main>
      <meta
        name="naver-site-verification"
        content="실제_확인값"
      />
      <h1>한코딩</h1>
    </main>
  );
}
```

Vite 프로젝트에서는 `index.html`의 `<head>`를 고친다.

**소유권 확인이 실패하면 순서대로 확인**

| 확인할 내용 | 점검 방법 |
|---|---|
| 사이트 주소가 정확한가? | 등록한 주소와 실제 최종 접속 주소 비교 |
| 수정한 내용을 배포했는가? | 로컬 화면이 아닌 배포된 사이트에서 확인 |
| 메인 페이지를 수정했는가? | 등록한 대표 주소의 페이지 소스 확인 |
| 태그가 `<head>` 안에 있는가? | `<body>`나 React 화면 내부에 넣지 않았는지 확인 |
| 확인값이 정확한가? | 현재 계정에서 발급받은 태그와 비교 |
| 외부에서 접근할 수 있는가? | 시크릿 창에서 로그인 없이 접속 |
| JavaScript로만 태그를 추가했는가? | 페이지 소스에 태그가 있는지 확인 |

## 빠른 참고 (치트시트)

| 하고 싶은 것 | 쓰는 것 | 예시 |
|---|---|---|
| 구글 검색 상태 관리 | Google Search Console | `https://search.google.com/search-console` |
| 네이버 검색 상태 관리 | 네이버 서치어드바이저 → 웹마스터 도구 | `https://searchadvisor.naver.com/` |
| 구글에 HTML 태그로 등록 | **URL 접두어** 속성 | `https://my-service.example.com/` |
| 하위 도메인까지 한 번에 관리 | 도메인 속성 | DNS 설정으로 확인 |
| 구글 소유권 확인 태그 | `<head>` 안 메타 태그 | `<meta name="google-site-verification" content="<인증코드>"/>` |
| 네이버 소유확인 태그 | `<head>` 안 메타 태그 | `<meta name="naver-site-verification" content="<인증코드>"/>` |
| Vite React에서 넣을 곳 | 최상위 `index.html`의 `<head>` | `App.jsx` 아님 |
| 배포된 HTML에 태그가 있는지 | 페이지 소스 보기 → 검색 | `google-site-verification` |
| 외부 접근 확인 | 시크릿 창에서 로그인 없이 열기 | `localhost` 주소는 불가 |

## 확인 문제
강의에 별도 "💬 확인하기"는 없어서, 본문의 질문형 제목과 강조된 내용, "자주 하는 실수"에서 뽑았다.

<details><summary>Q. (강의 질문) 사이트를 검색 관리 도구에 등록하면 무엇이 좋을까? 구글·네이버의 도구 이름은?</summary>

검색엔진이 사이트를 수집하는지, 검색에 포함된 페이지는 무엇인지, 문제는 없는지, 어떤 검색어로 방문하는지를 확인하고 관리할 수 있다. 구글: Google Search Console, 네이버: 네이버 서치어드바이저의 웹마스터 도구. 등록만으로 노출·순위가 보장되지는 않는다.
</details>

<details><summary>Q. (강의 질문) 소유권 확인은 왜 필요할까? 이번 실습은 어떤 방법으로 증명하나?</summary>

다른 사람이 우리 사이트를 마음대로 관리하면 안 되므로, "이 사이트를 실제로 수정·관리할 수 있는 사람인가"를 확인한다. 이번에는 도구가 발급한 **확인용 메타 태그를 사이트 HTML의 `<head>`에 넣는** 방법으로 증명한다.
</details>

<details><summary>Q. 소유권 확인의 전체 흐름을 순서대로 말하라.</summary>

관리 도구에서 확인용 태그 발급 → 사이트 HTML `<head>`에 태그 추가 → 수정한 사이트 다시 배포 → (페이지 소스 보기로 태그 확인) → 관리 도구에서 확인 버튼 → 관리 도구가 배포된 사이트의 태그를 확인.
</details>

<details><summary>Q. 실습 전에 준비할 것은? `http://localhost:5173/`로 등록할 수 없는 이유는?</summary>

구글 계정, 네이버 계정, 외부에서 접속할 수 있는 내 사이트 주소, HTML을 고쳐 다시 배포할 수 있는 환경. `localhost`는 내 컴퓨터에서만 실행되는 주소라 관리 도구가 접근할 수 없다. 시크릿 창에서 로그인 없이 열리는지도 확인한다.
</details>

<details><summary>Q. 구글 서치 콘솔의 도메인 속성과 URL 접두어 속성의 차이는? 이번 실습은 무엇을 고르나?</summary>

도메인: 여러 프로토콜과 하위 도메인을 포함하는 범위, **DNS 설정**으로 확인. URL 접두어: 입력한 프로토콜·호스트·경로로 시작하는 범위, **HTML 태그** 등으로 확인 가능. 이번에는 HTML을 고치는 방식이므로 **URL 접두어**를 고르고, `https://`·`www` 유무까지 실제 주소와 맞춘다.
</details>

<details><summary>Q. 프로젝트 종류별로 확인 태그를 넣을 위치는?</summary>

일반 HTML 사이트: 메인 페이지 HTML. Vite React: 프로젝트 최상위 `index.html`의 `<head>`. Spring + Thymeleaf: 메인 페이지를 응답하는 HTML 템플릿 (파일 이름보다 실제 메인 주소에서 어떤 HTML을 응답하는지가 중요).
</details>

<details><summary>Q. 페이지 소스 보기와 개발자 도구 Elements는 무엇이 다른가? 인증 태그는 어디서 확인하나?</summary>

페이지 소스 보기: 서버에서 전달받은 HTML. Elements: JavaScript 실행 후 바뀐 현재 화면 구조. 인증 태그는 **페이지 소스 보기**에서 확인한다. Elements에서 보여도 처음 HTML에는 없을 수 있다.
</details>

<details><summary>Q. 네이버 확인 태그를 React 컴포넌트(`App.jsx`) 안에 넣으면 왜 안 되나?</summary>

네이버는 소유확인 때 **JavaScript를 실행하지 않는다.** React가 실행된 뒤 생기는 태그는 처음 HTML에 없으므로 확인되지 않는다. 또 `<head>`가 아닌 본문(`<main>`) 안이다. 처음 전달되는 HTML인 `index.html`의 `<head>`에 직접 넣는다.

> 💡 보충: React 19는 컴포넌트에 쓴 `<meta>`를 실행할 때 `<head>`로 옮긴다 (2026-11-24 jsdom으로 확인). 그래서 개발자 도구 Elements에서는 `<head>` 안에 있는 것처럼 보일 수 있다. 진짜 이유는 **처음 HTML(페이지 소스 보기)에 태그가 없다**는 것 하나다.
</details>

<details><summary>Q. 코드에 태그를 넣고 저장한 뒤 바로 확인 버튼을 눌렀더니 실패했다. 왜인가?</summary>

관리 도구는 내 컴퓨터의 코드를 읽지 않고 **인터넷에 배포된 사이트**를 확인한다. 저장만으로는 배포된 사이트가 바뀌지 않으므로, 빌드·배포를 마치고 페이지 소스에서 태그를 확인한 뒤 확인 버튼을 누른다.
</details>

<details><summary>Q. (강의 질문) 소유권 확인이 실패하면 무엇을 점검하나?</summary>

① 등록한 주소와 실제 최종 접속 주소가 같은지 ② 수정 내용을 배포했는지 ③ 메인 페이지를 수정했는지(대표 주소의 페이지 소스) ④ 태그가 `<head>` 안에 있는지 ⑤ 확인값이 현재 계정에서 발급받은 값인지 ⑥ 시크릿 창에서 로그인 없이 접속되는지 ⑦ JavaScript로만 태그를 추가하지 않았는지.
</details>

<details><summary>Q. 구글·네이버 태그를 함께 넣어도 되나? 소유권 확인이 끝나면 태그를 지워도 되나?</summary>

함께 넣어도 된다. 확인 후에도 **지우지 않고 유지**한다. Google이 소유권을 다시 확인할 수 있기 때문이다.
</details>

<details><summary>Q. 네이버 서치어드바이저와 네이버 클라우드 콘솔 중 사이트 등록은 어디서 하나?</summary>

네이버 서치어드바이저(웹마스터 도구). 클라우드 콘솔은 클라우드 서버 등 인프라를 관리하는 다른 서비스다.
</details>
