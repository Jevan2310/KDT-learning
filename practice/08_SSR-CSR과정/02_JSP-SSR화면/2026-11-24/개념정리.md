# 개념 정리 — SSR-CSR과정 02. Spring Boot와 JSP로 SSR 화면 만들기

> 날짜: 2026-11-24 · wiki: [02_JSP-SSR화면](../../../../wiki/08_SSR-CSR과정/02_JSP-SSR화면.md)
> 단계별 설명문으로 쓰고, 단계 끝마다 직접 해 보는 예시를 둔다. 쉬운 말, 비유 없이. 코드와 출력은 이 Mac(JDK 21, Spring Boot 3.5.16)에서 미리 실행해 확인했다.

## 들어가며

**🧭 맥락 — 지금 어디쯤**

Spring 과정 03회차에서 학생 목록 화면을 만들었어요. `@Controller`가 `Model`에 학생 목록을 담고 `return "students"`를 하면, Thymeleaf가 `templates/students.html`에 데이터를 채워 완성된 HTML을 브라우저로 보냈죠. 01회차에서는 이렇게 서버가 HTML을 다 만들어 보내는 방식을 **SSR**(Server-Side Rendering, 서버에서 화면 만들기)이라고 불렀어요. 서버는 JSON 데이터만 보내고 브라우저의 JavaScript(React)가 화면을 만드는 방식은 **CSR**이었고요.

오늘은 같은 SSR을 **JSP**로 해요. JSP(Jakarta Server Pages)는 HTML 안에 `${...}`와 `<c:forEach>` 같은 태그를 섞어 쓰고, 서버가 이것을 처리해서 완성된 HTML을 보내는 기술이에요. Thymeleaf보다 오래된 Java 화면 기술이라 기존 회사 코드에서 자주 만나요. 하는 일은 Thymeleaf와 같고, 문법과 준비 과정이 달라요. 파이썬으로 치면 Flask의 `render_template`과 Jinja 템플릿이 하는 일이에요.

이 과정은 프로젝트 하나(`rendering-demo`)를 계속 키워요. 02에서 JSP로 화면을 만들고, 03에서 브라우저 개발자 도구로 그 응답을 들여다보고, 04에서 같은 데이터를 JSON으로 내보내 React로 화면을 만들고, 06에서 JSP를 Thymeleaf로 바꿔요. 오늘 만들 화면은 이거예요.

- `http://localhost:8080/students` → 학생 4명이 든 표
- 이름 일부로 검색 → 이름에 그 글자가 든 학생만
- 검색어가 없거나 공백뿐 → 전체 학생
- 검색 결과가 없음 → "검색 결과가 없습니다."
- 검색한 뒤에도 입력창에 검색어가 남음

수업 화면의 코드는 학생을 MyBatis로 MySQL `school` DB에서 읽어요. 그런데 그대로 쓰면 문제가 세 가지 있어요 (wiki 보충에 정리). ① JSP는 `${student.className}`을 읽는데 `Student`에는 `classId`만 있어서 500 오류, ② `Student`에 기본 생성자가 없어서 MyBatis 조회 때 번호 칸이 비거나 오류, ③ Controller가 검색어를 `Model`에 담지 않아서 입력창에 검색어가 남지 않음. 과정 소개 페이지에 "DB 설정에 시간을 쓰지 않도록 학생 데이터는 먼저 Java 목록으로 제공"한다고 되어 있어서, 이 노트는 **DB 없이 Java 목록으로** 먼저 만들어요. ①과 ③은 5·6단계 바꿔 보기에서 일부러 일으켜 봐요.

## 1단계: JSP를 쓰려면 WAR 형식과 JSP 엔진이 필요하다

🧭 Spring 03에서는 Thymeleaf 스타터 한 줄이면 됐어요. JSP는 Spring Boot가 기본으로 챙겨 주지 않아서 `build.gradle`에서 준비할 게 많아요.

JSP 파일은 그 자체로 실행되지 않아요. 서버 안의 **JSP 엔진**이 JSP를 Java 코드로 바꾸고 컴파일해서 실행해요. 그 실행 결과가 HTML 글자예요. Spring Boot 안에 든 Tomcat(요청을 받아 응답하는 웹 서버)에는 이 엔진이 빠져 있어서, Tomcat의 JSP 엔진인 Jasper를 `tomcat-embed-jasper` 줄로 넣어요.

`<c:forEach>`, `<c:if>` 같은 태그는 **JSTL**(JSP 표준 태그 모음)이에요. 태그 규칙을 정한 API 한 줄과, 실제로 동작하는 구현체 한 줄을 함께 넣어요. 둘 다 `jakarta`로 시작하는 것을 써요. Spring Boot 3부터 Java 웹 기술의 패키지 이름이 `javax`에서 `jakarta`로 바뀌어서, 인터넷 옛 예제의 `javax.servlet:jstl`은 맞지 않아요. 버전을 안 적은 줄은 Spring Boot가 맞는 버전을 골라 줘요.

다음은 **패키징**이에요. 패키징은 프로젝트를 실행 파일 하나로 묶는 형식이에요. Spring Boot는 보통 **JAR**로 묶는데, JSP가 들어가는 `src/main/webapp` 폴더는 JAR에 들어가지 않아요. **WAR**(Web Application Archive)는 이 폴더까지 함께 묶어요. 그래서 Initializr에서 War를 골랐고, `plugins`에 `id 'war'`가 있어요. `providedRuntime '...tomcat'`은 "따로 설치된 Tomcat에 올리면 그 Tomcat을 쓴다"는 뜻이고, 지금처럼 직접 실행하면 안에 든 Tomcat을 써요. War를 고르면 생기는 `ServletInitializer.java`도 따로 설치된 Tomcat이 이 앱을 시작할 때 쓰는 파일이라 지우지 않아요.

JAR로 하면 어떻게 되는지 미리 확인해 봤어요. `id 'war'`를 빼고 JAR로 묶어 프로젝트 밖 폴더에서 `java -jar`로 실행하니 `/students`가 404였어요. WAR로 묶으면 200이었고요. 그런데 프로젝트 폴더 안에서 실행하면 JAR여도 화면이 나왔어요. Spring Boot가 실행한 위치의 `src/main/webapp`을 직접 읽기 때문이에요. IntelliJ ▶도 프로젝트 폴더에서 실행해요. 그래서 JAR로 만들면 개발 중에는 문제를 모르다가 배포할 때 404가 나요. 처음부터 WAR로 만드는 이유예요.

`build.gradle`은 강의 코드에서 두 군데를 바꿨어요. 첫째, MyBatis·DB 드라이버·Lombok 줄을 뺐어요. Java 목록을 쓰니 DB가 없어요. 둘째, `JavaLanguageVersion.of(17)`을 `21`로 바꿨어요. toolchain은 "이 버전의 JDK로 컴파일하라"는 설정이라, 이 Mac처럼 JDK 21만 있으면 17에서 빌드가 멈춰요. Spring Boot 3.5는 Java 17 이상이면 돼서 21로 써도 돼요. Spring Boot `3.5.16`은 강의 그대로예요. Initializr가 만든 4.x용 파일은 스타터 이름부터 달라서(`spring-boot-starter-webmvc` 등) 한 줄씩 고치지 말고 통째로 바꿔요.

## 2단계: JSP는 `webapp/WEB-INF/views`에 두고, 뷰 이름으로 찾는다

🧭 Spring 03에서는 `return "students"`만 하면 Spring Boot가 `templates/students.html`을 알아서 찾았어요. JSP는 어디서 찾을지 직접 알려 줘야 해요.

JSP 파일은 `src/main/resources` 안이 아니라 `src/main` 바로 아래의 **`webapp`** 폴더에 둬요. `webapp`은 웹 애플리케이션 파일을 두는 자리이고, Tomcat이 JSP를 여기서 찾아요.

`application.properties`에 **prefix**(앞에 붙일 글자) `/WEB-INF/views/`와 **suffix**(뒤에 붙일 글자) `.jsp`를 적어요. 그러면 Controller가 `"students"`를 돌려줄 때 Spring이 앞뒤를 붙여 `/WEB-INF/views/students.jsp`를 실행해요. Controller가 돌려주는 이 문자열을 **뷰 이름**이라고 해요. 화면에 찍히는 글자가 아니라 JSP를 고르는 이름이에요. 그래서 `.jsp`를 붙이지 않아요. 붙이면 `students.jsp.jsp`를 찾아요 (4단계에서 확인해요).

그 아래 `server.servlet.encoding` 세 줄은 요청과 응답의 글자 인코딩을 UTF-8로 맞춰요. 한글 검색어와 한글 화면이 깨지지 않게 하는 설정이에요.

그럼 `views` 앞의 `WEB-INF`는 왜 있을까요? `WEB-INF` 폴더 안의 파일은 **브라우저가 주소로 직접 열 수 없어요.** Tomcat이 404로 막아요. JSP를 여기에 두면 사용자는 꼭 Controller 주소(`/students`)로 들어와야 하고, Controller가 데이터를 준비한 다음에만 JSP가 실행돼요. Spring이 서버 안에서 JSP로 넘기는 것은 막지 않아요.

### ▶ 직접 해 보기 — `application.properties`와 시험용 `test.jsp`

`src/main/resources/application.properties`를 전부 바꿔요.

```properties
spring.application.name=rendering-demo

spring.mvc.view.prefix=/WEB-INF/views/
spring.mvc.view.suffix=.jsp

server.servlet.encoding.charset=UTF-8
server.servlet.encoding.enabled=true
server.servlet.encoding.force=true
```

JSP 엔진이 정말 서버에서 일하는지 작은 파일로 봐요. `src/main` 우클릭 → **New → Directory** → `webapp/WEB-INF/views`를 한 번에 입력하면 폴더 세 개가 같이 생겨요. 그다음 `webapp` 우클릭 → **New → File** → `test.jsp` (`WEB-INF` 밖, `webapp` 바로 아래예요).

```jsp
<%@ page contentType="text/html; charset=UTF-8" pageEncoding="UTF-8" %>
<p>1 + 2 = ${1 + 2}</p>
```

■ → ▶로 다시 켜고 `http://localhost:8080/test.jsp`를 열면 `1 + 2 = 3`이 보여요. 페이지 소스 보기(`Cmd + Option + U`)를 하면 빈 줄 하나 아래에 이 한 줄만 있어요. 첫 줄 `<%@ page %>`는 설정이라 빈 줄로 바뀌어요.

```html
<p>1 + 2 = 3</p>
```

`${1 + 2}`는 브라우저에 오지 않았어요. 서버가 계산해서 결과만 보냈어요.

이제 `test.jsp`를 `WEB-INF/views` 안으로 끌어다 옮기고 ■ → ▶ 해요. `http://localhost:8080/test.jsp`도, `http://localhost:8080/WEB-INF/views/test.jsp`도 1단계의 Whitelabel 404 화면이 나와요. `WEB-INF` 안은 주소로 열 수 없어요. `test.jsp`는 아래 바꿔 보기에서 한 번 더 쓰고 지워요.

**서버를 다시 켜지 않으면?** 서버가 켜진 채로 `${1 + 2}`를 `${2 + 3}`으로 고쳐 봤더니 계속 `1 + 2 = 3`이 나왔고, 파일을 `WEB-INF`로 옮긴 뒤에도 `/test.jsp`가 계속 열렸어요. Spring Boot는 처음 컴파일한 JSP를 계속 써요. JSP를 고친 뒤에는 꼭 ■ → ▶ 해요.

**바꿔 보기**
- `test.jsp`를 다시 `webapp` 바로 아래로 옮기고, `build.gradle`에서 `tomcat-embed-jasper` 줄을 지운 뒤 Load Gradle Changes → ■ → ▶. `/test.jsp`를 열면 화면 대신 **파일이 내려받아져요.** 열어 보면 `${1 + 2}`가 그대로 든 JSP 원본이에요. JSP 엔진이 없으니 Tomcat이 그냥 파일로 보냈어요. 줄을 되살려 Load Gradle Changes 하고, `test.jsp`는 지워요.

## 3단계: 학생 데이터와 검색 — `Student`와 `StudentService`

🧭 Spring 01에서 만든 `Student`(필드 + 생성자 + getter)와 같은 모양이에요. 검색은 Controller가 아니라 Service에 둬요. 04에서 React용 JSON API가 이 Service를 그대로 다시 써요.

`Student`는 학생 한 명의 정보예요. 번호·이름·이메일·소속 반 네 필드가 있고, 모두 `final`이라 처음 만들 때 넣은 값이 바뀌지 않아요. 바꿀 일이 없어서 setter도 없어요. 필드는 `private`이고 밖에서는 getter로 읽어요. 이 getter 이름이 5단계에서 중요해요. JSP의 `${student.name}`이 `getName()`을 부르거든요.

`id`가 `Long` 자료형이라 숫자를 `1L`처럼 써요. `L`은 "long 크기 정수"라는 표시예요. `L` 없이 `1`만 쓰면 `int`라서 `Long` 자리에 넣을 수 없다는 컴파일 오류가 나요.

`StudentService`에는 `@Service`를 붙여요. 그러면 Spring이 실행될 때 이 객체를 하나 만들어 보관하고, 필요한 곳(4단계 Controller)에 넣어 줘요. 학생 목록은 `List.of(...)`로 만든 고정 목록이에요. 실행 중에 추가·삭제할 수 없는 목록이고, DB 대신 이 목록이 데이터예요.

`findStudents(keyword)`가 검색이에요. 검색어가 `null`이거나 `isBlank()`(비었거나 공백뿐)이면 전체 목록을 돌려줘요. 아니면 이름에 검색어가 들어 있는(`contains`) 학생만 돌려줘요. `"한코딩".contains("한")`은 `true`예요.

걸러 내는 부분은 **stream**으로 썼어요. `students.stream()`은 목록의 학생을 하나씩 꺼내 다음 단계로 보내요. `.filter(student -> student.getName().contains(keyword))`는 괄호 안 조건이 `true`인 학생만 남겨요. `student -> ...`는 **람다**라는 이름 없는 짧은 함수로, 파이썬의 `lambda student: keyword in student.name`과 같아요. `.toList()`는 남은 학생을 다시 목록으로 모아요. 전체로 보면 파이썬의 `[s for s in students if keyword in s.name]`이에요. 강의 설명 표의 `results.add(...)`는 같은 검색을 for문으로 쓴 버전이에요 (바꿔 보기).

이 Service는 JSP도 `Model`도 HTML도 몰라요. 목록을 돌려줄 뿐이에요. 데이터 찾는 일과 화면 만드는 일을 나눠 두면, 화면 기술을 React(04)나 Thymeleaf(06)로 바꿔도 이 파일은 그대로예요.

### ▶ 직접 해 보기 — `Student.java`, `StudentService.java`

`com.example.renderingdemo` 패키지 우클릭 → **New → Java Class** → `Student`, 같은 방법으로 `StudentService`를 만들고 내용을 바꿔요.

```java
package com.example.renderingdemo;

public class Student {

    private final Long id;
    private final String name;
    private final String email;
    private final String className;

    public Student(Long id, String name, String email, String className) {
        this.id = id;
        this.name = name;
        this.email = email;
        this.className = className;
    }

    public Long getId() {
        return id;
    }

    public String getName() {
        return name;
    }

    public String getEmail() {
        return email;
    }

    public String getClassName() {
        return className;
    }
}
```

```java
package com.example.renderingdemo;

import java.util.List;

import org.springframework.stereotype.Service;

@Service
public class StudentService {

    private final List<Student> students = List.of(
            new Student(1L, "한코딩", "han@example.com", "풀스택 1반"),
            new Student(2L, "김자바", "kim@example.com", "풀스택 1반"),
            new Student(3L, "이스프링", "lee@example.com", "풀스택 2반"),
            new Student(4L, "박리액트", "park@example.com", "풀스택 2반")
    );

    public List<Student> findStudents(String keyword) {
        if (keyword == null || keyword.isBlank()) {
            return students;
        }

        return students.stream()
                .filter(student -> student.getName().contains(keyword))
                .toList();
    }
}
```

■ → ▶ 해서 Run 창에 `Started RenderingDemoApplication`이 나오면 두 파일이 오류 없이 컴파일된 거예요. 화면은 아직 그대로예요. `/students`를 맡은 Controller가 없어서 `http://localhost:8080/students`는 404예요.

**바꿔 보기**
- `new Student(1L, ...)`의 `1L`을 `1`로 → ▶ 하면 빌드가 멈추고 `incompatible types: int cannot be converted to Long`. 되돌려요.
- 6단계까지 만든 뒤, `findStudents`를 강의 표처럼 for문 + `results.add`로 바꿔 봐요. 파일 위쪽 import에 `import java.util.ArrayList;`도 넣어요. 6단계의 검색 결과가 하나도 달라지지 않아요.

```java
    public List<Student> findStudents(String keyword) {
        if (keyword == null || keyword.isBlank()) {
            return students;
        }

        List<Student> results = new ArrayList<>();
        for (Student student : students) {
            if (student.getName().contains(keyword)) {
                results.add(student);
            }
        }
        return results;
    }
```

## 4단계: Controller가 검색어를 받고 `Model`에 담는다

🧭 `@Controller`와 `Model`은 Spring 03과 같아요. 새로운 것은 주소의 검색어를 받는 `@RequestParam`이에요.

`@Controller`가 붙은 클래스의 메서드가 문자열을 돌려주면, Spring은 그것을 **뷰 이름**으로 보고 2단계 규칙대로 JSP를 실행해 HTML을 응답해요. `@RestController`는 돌려준 값을 그대로 응답 본문으로 보내요 (Spring 06에서 JSON을 보낼 때 썼어요). 화면을 보내는 오늘은 `@Controller`예요.

Controller는 학생을 찾으려면 3단계의 `StudentService`가 필요해요. 생성자의 매개변수로 `StudentService`를 받아 두면, Spring이 Controller를 만들 때 보관해 둔 Service 객체를 넣어 줘요. 이것을 **생성자 주입**이라고 해요. 직접 `new StudentService()`를 하지 않아요.

`@GetMapping("/students")`는 `GET /students` 요청을 이 메서드가 맡는다는 뜻이에요. `/students?keyword=한`처럼 `?` 뒤에 붙은 `이름=값`을 **쿼리 파라미터**라고 해요. `@RequestParam(name = "keyword", defaultValue = "") String keyword`는 쿼리 파라미터 `keyword`의 값을 꺼내 `keyword` 변수에 넣어요. 검색어 없이 `/students`로 들어오면 `defaultValue`인 빈 문자열이 들어가요. `defaultValue`가 없으면 검색어 없는 첫 접속부터 400 오류가 나요. 받은 검색어는 `trim()`으로 앞뒤 공백을 지운 다음 Service에 넘겨요.

`Model`은 JSP에 넘길 값을 이름표와 함께 담는 곳이에요. `model.addAttribute("students", students)`로 담으면 JSP에서 `${students}`로 꺼내요. 검색어도 `keyword`라는 이름으로 담아요. 6단계에서 입력창에 검색어를 다시 채울 때 써요. `Model`은 요청 한 번마다 새로 만들어지고 응답이 끝나면 사라져요. Flask의 `return render_template("students.html", students=students, keyword=keyword)` 한 줄을, Spring은 `Model`에 담기와 뷰 이름 돌려주기 두 단계로 나눠서 해요.

### ▶ 직접 해 보기 — `StudentPageController.java`

```java
package com.example.renderingdemo;

import java.util.List;

import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;

@Controller
public class StudentPageController {

    private final StudentService studentService;

    public StudentPageController(StudentService studentService) {
        this.studentService = studentService;
    }

    @GetMapping("/students")
    public String students(
            @RequestParam(name = "keyword", defaultValue = "") String keyword,
            Model model) {

        String searchKeyword = keyword.trim();

        List<Student> students =
                studentService.findStudents(searchKeyword);

        model.addAttribute("students", students);
        model.addAttribute("keyword", searchKeyword);

        return "students";
    }
}
```

■ → ▶ 후 `http://localhost:8080/students`를 열면 **아직 404**예요. Controller는 실행됐지만 `students.jsp`를 아직 안 만들었어요. Run 창에는 오류가 안 나와서 원인을 알기 어려워요. 이럴 때 `application.properties` 맨 아래에 이 줄을 잠깐 넣고 ■ → ▶ 해 봐요.

```properties
server.error.include-message=always
```

오류 화면 맨 아래에 Spring이 찾은 파일 경로가 나와요. prefix + 뷰 이름 + suffix 그대로예요.

```text
There was an unexpected error (type=Not Found, status=404).
JSP file [/WEB-INF/views/students.jsp] not found
```

**바꿔 보기** (하나씩 바꾸고 ■ → ▶, 확인하면 되돌려요)
- `return "students";`를 `return "students.jsp";`로 → `JSP file [/WEB-INF/views/students.jsp.jsp] not found`. 뷰 이름에는 `.jsp`를 붙이지 않아요.
- `@Controller`를 `@RestController`로 (import 줄도 `org.springframework.web.bind.annotation.RestController`로) → 화면에 `students` 글자만 나와요. 뷰 이름이 아니라 그냥 글자로 보냈어요.
- `defaultValue = ""`를 지워 `@RequestParam(name = "keyword")`로 → `/students`가 400 (`type=Bad Request, status=400`), Run 창에 `Required request parameter 'keyword' for method parameter type String is not present`. 검색어가 없으면 메서드까지 가지도 못해요. `/students?keyword=한`으로 열면 400이 아니라 위의 `JSP file … not found` 404가 나와요. 검색어가 있으면 메서드가 실행된다는 뜻이에요.

확인이 끝나면 `server.error.include-message=always` 줄은 지워요.

## 5단계: JSP가 `Model` 값으로 HTML을 만든다 — EL과 JSTL

🧭 Thymeleaf에서 `th:text`, `th:each`, `th:if`로 하던 일을 JSP에서는 `${...}`(EL)와 `<c:...>`(JSTL) 태그로 해요. 파이썬 Jinja의 `{{ ... }}`, `{% for %}`, `{% if %}`와 같은 역할이에요.

`students.jsp`를 위에서부터 읽어 볼게요. 맨 위 `<%@ page ... %>`는 이 JSP가 UTF-8 HTML을 응답한다고 정해요. `<%@ taglib prefix="c" uri="jakarta.tags.core" %>`는 JSTL의 기본 태그를 `c:`라는 앞글자로 쓰겠다는 선언이에요. 이 줄이 있어야 JSP 엔진이 `<c:...>`를 처리해요.

**EL**(Expression Language)은 `${...}` 표현이에요. `Model`에 담은 이름으로 값을 꺼내요. `${students}`는 학생 목록, `${keyword}`는 검색어예요. 점(`.`)을 찍으면 getter를 불러요. `${student.name}`은 `student.getName()`을 실행한 결과예요. `private` 필드를 직접 읽는 게 아니라서, getter 이름이 다르면 필드가 있어도 오류가 나요. 반대로 `Model`에 없는 이름(`${studens}` 같은 오타)은 오류 없이 빈 값이 돼요. 둘 다 바꿔 보기에서 확인해요.

`<c:forEach var="student" items="${students}">`는 `items` 목록의 학생 수만큼 안쪽을 반복해요. 한 번 돌 때마다 지금 학생을 `student`라는 이름으로 써요. Java의 `for (Student student : students)`, 파이썬의 `for student in students:`와 같아요. 결과 HTML에는 `<c:forEach>`가 없고, 그 안의 `<tr>…</tr>`이 학생 수만큼 반복돼 있어요.

`<c:if test="${empty students}">`는 조건이 참일 때만 안쪽을 출력해요. `empty`는 값이 없거나 빈 목록이면 참이에요. `<c:if>`에는 else가 없어서, 표는 반대 조건 `not empty students`로 한 번 더 써요. Thymeleaf의 `th:if`·`th:unless` 짝과 같아요.

`<c:out value="${student.name}" />`는 값을 출력해요. `${student.name}`만 써도 출력은 되는데, `<c:out>`은 `<`, `>`, `&`, `"` 같은 글자를 `&lt;`처럼 글자로 보이는 표현으로 바꿔서(**이스케이프**) 출력해요. 사용자가 입력한 값이 HTML 태그로 해석되지 않게 막아요. 6단계에서 확인해요.

`<c:url var="cssUrl" value="/css/students.css" />`는 주소를 만들어 `cssUrl`에 담아요. 앱이 `/`가 아닌 경로(예: `/jsp`)에 올라가면 그 경로를 앞에 붙여 줘요. 지금은 `/`라서 그대로예요. 그런데 처음 접속한 페이지의 소스를 보면 `/css/students.css;jsessionid=5C10…`처럼 뒤에 뭔가 붙어 있어요. JSP는 기본으로 **세션**(서버가 방문자를 구분하려고 붙이는 번호)을 만들어요. 첫 요청에서는 브라우저가 아직 이 번호를 쿠키(브라우저가 저장해 두었다가 요청마다 함께 보내는 값)로 보내지 않았으니 `<c:url>`이 주소에 붙여 준 거예요. 새로고침하면 사라지고, 오류가 아니에요.

CSS는 Spring 03과 같아요. `src/main/resources/static/css/students.css`에 두면 `/css/students.css` 주소로 열려요.

```jsp
<%@ page contentType="text/html; charset=UTF-8"

    <c:url var="cssUrl" value="/css/students.css" />
    <link rel="stylesheet" href="${cssUrl}">
</head>
<body>
    <main class="container">
        <header class="page-header">
            <p class="label">Spring Boot + JSP</p>
            <h1>학생 목록</h1>
            <p>이름의 일부를 입력하여 학생을 검색하세요.</p>
        </header>

        <c:url var="studentsUrl" value="/students" />

        <form class="search-form"
              action="${studentsUrl}"
              method="get">

            <label for="keyword">학생 이름</label>

            <div class="search-controls">
                <input
                    id="keyword"
                    type="text"
                    name="keyword"
                    placeholder="예: 한"
                    value="<c:out value='${keyword}' />"
                >

                <button type="submit">검색</button>

                <a href="${studentsUrl}">전체 보기</a>
            </div>
        </form>

        <c:if test="${not empty keyword}">
            <p class="search-summary">
                검색어:
                <strong><c:out value="${keyword}" /></strong>
            </p>
        </c:if>

        <c:if test="${empty students}">
            <p class="empty-message">
                검색 결과가 없습니다.
            </p>
        </c:if>

        <c:if test="${not empty students}">
            <div class="table-wrapper">
                <table>
                    <thead>
                        <tr>
                            <th scope="col">번호</th>
                            <th scope="col">이름</th>
                            <th scope="col">이메일</th>
                            <th scope="col">소속 반</th>
                        </tr>
                    </thead>

                    <tbody>
                        <c:forEach
                            var="student"
                            items="${students}">

                            <tr>
                                <td>
                                    <c:out value="${student.id}" />
                                </td>
                                <td>
                                    <c:out value="${student.name}" />
                                </td>
                                <td>
                                    <c:out value="${student.email}" />
                                </td>
                                <td>
                                    <c:out value="${student.className}" />
                                </td>
                            </tr>

                        </c:forEach>
                    </tbody>
                </table>
            </div>
        </c:if>
    </main>
</body>
</html>
```

머리줄 1개 + 학생 4명이에요.

**바꿔 보기** (하나씩 바꾸고 ■ → ▶, 확인하면 되돌려요)
- `Student.java`의 `getClassName()`을 `getClassNm()`으로 → 500 오류 화면(`type=Internal Server Error, status=500`). Run 창에는 `jakarta.el.PropertyNotFoundException: Property [className] not found on type [com.example.renderingdemo.Student]`가 나오고, 아래쪽 줄에 `students_jsp`라는 클래스 이름이 보여요 (JSP가 Java 코드로 바뀐 흔적이에요). 필드 `className`은 그대로인데도 오류예요. EL은 getter를 찾아요. 수업 코드 문제 ①이 이 오류예요.
- `items="${students}"`를 `items="${studens}"`로 → 오류 없이 **머리줄만 있는 빈 표**가 나와요. `Model`에 없는 이름은 빈 값이라 반복할 게 없어요. Run 창에도 아무 말이 없어서 찾기 어려운 실수예요.
- 맨 위 `taglib` 줄을 지우기 → 200으로 열리지만 "검색 결과가 없습니다."와 빈 표가 함께 나오고 CSS도 안 먹어요. 페이지 소스에는 `<c:if test="false">`, `<c:forEach … items="[com.example.renderingdemo.Student@19a97771, …]">`처럼 태그가 그대로 와 있고, `cssUrl`이 안 만들어져 `href=""`예요. `${...}`는 계산됐지만 `<c:...>` 태그는 처리되지 않고 브라우저로 갔어요. 브라우저는 모르는 태그를 무시하고 안쪽 내용을 다 보여 줘요.
- `students.jsp`를 `webapp` 바로 아래에도 복사하고 `http://localhost:8080/students.jsp`를 열기 → 화면은 열리지만 학생 없이 "검색 결과가 없습니다."만 나와요. `?keyword=한`을 붙여도 입력창이 비어 있어요. Controller를 거치지 않아서 `Model`이 비었어요. JSP를 `WEB-INF`에 두는 이유예요. 복사본은 지워요.

## 6단계: 검색 폼 — GET 요청 한 번에 새 HTML 한 장

🧭 01에서 본 "폼을 제출하면 새 문서를 요청한다"는 SSR 검색 흐름을 직접 돌려 봐요. 이 페이지에는 JavaScript가 한 줄도 없어요. 04에서는 같은 검색을 React가 `fetch`로 해요.

검색 폼은 `<form action="${studentsUrl}" method="get">` 안에 `<input name="keyword">`와 검색 버튼이 있는 모양이에요. 검색 버튼을 누르면 브라우저가 입력칸의 `name`과 값을 주소 뒤에 붙여 `GET /students?keyword=한`을 새로 요청해요. 주소창에는 `한`으로 보이지만 실제 요청에는 `%ED%95%9C`처럼 바뀐 글자가 가요 (URL 인코딩). 이 `name="keyword"`가 4단계 `@RequestParam(name = "keyword")`와 이어지는 지점이에요.

요청을 받은 서버는 4단계부터 다시 해요. Controller가 검색어를 받고, Service가 걸러 내고, `Model`에 담고, JSP가 **페이지 전체 HTML**을 새로 만들어요. 브라우저는 그 HTML로 화면을 통째로 다시 그려요. 표만 바뀐 것처럼 보여도 새 문서예요.

새 문서니까 내가 입력했던 입력창은 사라졌어요. 그런데도 입력창에 검색어가 남아 있는 건, 서버가 `Model`의 `keyword`를 `value="<c:out value='${keyword}' />"`로 **다시 써 넣었기** 때문이에요. 그래서 Controller가 `keyword`를 `Model`에 담지 않으면 검색은 돼도 입력창이 비어요 (수업 코드 문제 ③). "검색어: 한" 줄은 `<c:if test="${not empty keyword}">` 안에 있어서 검색어가 있을 때만 나와요.

공백만 입력하면 Controller의 `trim()`이 빈 문자열로 만들어요. Service는 전체 목록을 주고, `Model`의 `keyword`도 빈 문자열이라 입력창이 비고 "검색어:" 줄도 안 나와요. 검색 결과가 없으면 `students`가 빈 목록이라 `empty students`가 참이 되어 안내 문구가 나와요. "전체 보기" 링크는 검색어 없는 `/students`예요. 검색어가 주소에 들어 있어서, 결과 화면을 새로고침하거나 주소를 복사해 다른 탭에 붙여도 같은 검색이 다시 실행돼요.

마지막으로 `<c:out>`의 이스케이프예요. 검색창에 `<b>한</b>`을 넣으면 `<c:out>`이 `&lt;b&gt;한&lt;/b&gt;`로 바꿔 보내서 화면에 `<b>한</b>`이 글자 그대로 보여요. `<c:out>` 없이 `${keyword}`로 출력하면 브라우저가 진짜 `<b>` 태그로 읽어요. 이렇게 사용자가 넣은 글자가 HTML이나 스크립트로 실행되는 보안 문제를 **XSS**라고 해요. 사용자 입력은 `<c:out>`으로 출력해요.

### ▶ 직접 해 보기 — 검색해 보기

브라우저에서 해 봐요.
1. `한` 입력 → 검색 → 주소가 `http://localhost:8080/students?keyword=한`, 표에 한코딩만, 입력창에 `한`, 위에 "검색어: 한"
2. `자바` → 김자바만
3. `없는학생` → "검색 결과가 없습니다."
4. 공백만 입력 → 학생 4명, 입력창은 빈칸, "검색어:" 줄 없음
5. "전체 보기" → 학생 4명

터미널에서 받은 HTML로도 확인해요. 아래 `s` 함수는 검색어로 요청한 뒤 입력창 `value`, "검색어:" 줄의 `<strong>`, 학생 이메일, 안내 문구만 골라 보여 줘요. `--data-urlencode`가 한글을 `%ED%95%9C`처럼 바꿔 줘요. curl 주소에 한글을 그대로 넣으면 Tomcat이 400으로 거절해요.

```bash
s() { curl -s -G --data-urlencode "keyword=$1" http://localhost:8080/students | grep -E 'value=|<strong>|@example|결과가' | sed 's/^ *//'; }
```

```text
$ s 한
value="한"
<strong>한</strong>
han@example.com
$ s 없는학생
value="없는학생"
<strong>없는학생</strong>
검색 결과가 없습니다.
$ s "   "
value=""
han@example.com
kim@example.com
lee@example.com
park@example.com
$ s "<b>한</b>"
value="&lt;b&gt;한&lt;/b&gt;"
<strong>&lt;b&gt;한&lt;/b&gt;</strong>
검색 결과가 없습니다.
```

**바꿔 보기** (하나씩 바꾸고 ■ → ▶, 확인하면 되돌려요)
- Controller의 `model.addAttribute("keyword", searchKeyword);` 줄을 지우기 → `s 한`이 `value=""`와 `han@example.com`만 보여 줘요. 검색은 됐지만 입력창이 비고 "검색어:" 줄이 사라졌어요. 수업 코드 문제 ③이에요.
- JSP의 `<strong><c:out value="${keyword}" /></strong>`을 `<strong>${keyword}</strong>`로 → `s "<b>한</b>"`의 둘째 줄이 `<strong><b>한</b></strong>`가 돼요. 브라우저에서 `<b>한</b>`을 검색하면 "검색어:" 옆에 `<b>`, `</b>` 글자가 사라지고 `한`만 보여요. 브라우저가 태그로 읽은 거예요. 입력창 `value`는 여전히 `<c:out>`이라 글자 그대로예요.
- 폼의 `method="get"`을 `method="post"`로 → 검색하면 405 오류 화면(`type=Method Not Allowed, status=405`), Run 창에 `Request method 'POST' is not supported`. `@GetMapping`은 GET 요청만 받아요.

## 마무리: `/students?keyword=한` 요청 하나가 HTML이 되기까지

1. 브라우저가 폼을 제출해 `GET /students?keyword=%ED%95%9C`를 새로 요청해요.
2. 안에 든 Tomcat이 요청을 받아 Spring에 넘겨요.
3. Spring이 `@GetMapping("/students")`가 붙은 `students()` 메서드를 찾아요. `@RequestParam`으로 `keyword`에 `"한"`을 넣고, 빈 `Model`을 만들어 함께 넘기며 메서드를 불러요.
4. Controller가 `trim()`한 검색어로 `studentService.findStudents("한")`을 불러요. Service는 이름에 `한`이 든 학생만 걸러 `[한코딩]` 목록을 돌려줘요.
5. Controller가 `Model`에 `students`와 `keyword`를 담고 뷰 이름 `"students"`를 돌려줘요.
6. Spring이 prefix·suffix를 붙여 `/WEB-INF/views/students.jsp`를 정하고, `Model` 값을 요청에 실어 서버 안에서 JSP로 넘겨요. 서버 안에서 넘기는 거라 `WEB-INF` 안이어도 돼요.
7. JSP 엔진(Jasper)이 JSP를 실행해요. `${...}`를 계산하고, `<c:if>`로 "검색어:" 줄과 표를 고르고, `<c:forEach>`로 `<tr>`을 학생 수만큼 만들고, `<c:out>`으로 글자를 이스케이프해요. 결과는 JSP 태그가 하나도 없는 HTML 글자예요.
8. Tomcat이 `200`, `Content-Type: text/html;charset=UTF-8`과 함께 그 HTML을 응답해요.
9. 브라우저가 HTML을 화면에 그리고, `<link>`를 보고 `/css/students.css`를 따로 요청해서 꾸며요.
