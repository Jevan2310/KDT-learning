## 1단계: 사이트맵 — 검색엔진에 알려 주고 싶은 페이지 주소를 모은 파일

🧭 01회차 4단계에서 검색엔진이 페이지를 발견하는 세 경로 중 하나로 사이트맵을 말했어요. 오늘 그 파일을 직접 만들어요.

**사이트맵**은 검색엔진에 알려 주고 싶은 페이지 주소를 모아 둔 파일이에요. 보통 `sitemap.xml`이라는 이름을 써요. 검색엔진은 페이지 안의 링크를 따라가며 다른 페이지를 발견하는데, 사이트맵은 그 주소들을 **추가로** 알려 줘요. 메인에서 링크가 깊숙이 이어진 페이지나, 막 만든 페이지를 검색엔진이 빨리 알게 하는 데 도움이 돼요. 그래도 **발견을 돕는 것까지**예요. 사이트맵에 넣었다고 그 주소를 반드시 수집하거나 색인하지는 않아요.

사이트맵은 **XML** 형식으로 써요. XML은 정해진 태그로 데이터를 표현하는 형식이에요. 모양은 HTML처럼 `<태그>내용</태그>`인데, 태그 이름을 HTML처럼 미리 정해진 목록에서 고르지 않고 쓰임새에 맞는 규칙을 따라요. 사이트맵이라면 사이트맵 규칙이 정한 태그를 써요. Node 03회차의 JSON처럼 "데이터를 담는 글자 형식"의 한 종류라고 보면 돼요. 오늘은 XML 문법 전체가 아니라 사이트맵 틀 안에 주소를 넣는 것만 하면 돼요.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://my-service.example.com/</loc>
  </url>
</urlset>
```

첫 줄 `<?xml …?>`은 "이건 XML이고 UTF-8 글자로 썼다"는 선언이에요. 반드시 파일의 **맨 첫 글자**부터 시작해야 해요. `<urlset>`은 주소 목록 전체를 감싸요. 안의 `xmlns="http://www.sitemaps.org/schemas/sitemap/0.9"`는 "이 목록은 사이트맵 규칙을 따른다"는 표시라서, 이 줄은 글자 하나 바꾸지 말고 그대로 써요. `<url>`은 페이지 하나, `<loc>`은 그 페이지의 **전체 주소**예요. `/about`처럼 경로만 쓰지 않고 `https://`부터 다 써요.

XML은 HTML보다 엄격해요. HTML은 닫는 태그를 빠뜨려도 브라우저가 알아서 화면을 그려 주지만, XML은 한 군데만 틀려도 파일 전체를 읽지 못해요. 그래서 배포 전에 `xmllint`로 형식을 검사해요.

### ▶ 직접 해 보기 — 첫 사이트맵 쓰고 검사하기

`_seo연습장`에 `sitemap.xml`을 위 내용 그대로 만들어요. `example.com` 주소는 설명용이에요. 실제로 배포할 때는 내 사이트 주소로 바꿔요.

```bash
xmllint --noout sitemap.xml; echo "종료 코드: $?"
curl -i http://localhost:8000/sitemap.xml
```

```text
종료 코드: 0
HTTP/1.0 200 OK
Server: SimpleHTTP/0.6 Python/3.14.6
Date: Tue, 24 Nov 2026 07:00:28 GMT
Content-type: application/xml
Content-Length: 174
Last-Modified: Tue, 24 Nov 2026 07:00:28 GMT

<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://my-service.example.com/</loc>
  </url>
</urlset>
```

`--noout`은 "검사만 하고 내용은 다시 찍지 말라"는 옵션이에요. 문제가 없으면 **아무 말도 안 하고** 끝나요. `echo "종료 코드: $?"`는 바로 앞 명령이 성공(`0`)했는지 실패(`1` 이상)했는지 보여 줘요. 서버는 이 파일을 `application/xml`(XML 데이터)로 보내요. 02회차 `robots.txt`의 `text/plain`과 비교해 봐요.

**바꿔 보기** (하나씩 바꾸고 검사한 뒤 되돌려요)
- 파일 맨 위에 빈 줄을 하나 넣으면 선언이 첫 글자가 아니게 돼요.

  ```text
  sitemap.xml:2: parser error : XML declaration allowed only at the start of the document
  <?xml version="1.0" encoding="UTF-8"?>
       ^
  종료 코드: 1
  ```

  눈으로는 거의 안 보이는 빈 줄 하나로 파일 전체가 XML이 아니게 돼요. 복사해서 붙일 때 자주 생겨요.
- `</url>` 줄을 지우면 여는 태그와 닫는 태그 짝이 안 맞아요.

  ```text
  sitemap.xml:5: parser error : Opening and ending tag mismatch: url line 3 and urlset
  </urlset>
           ^
  sitemap.xml:6: parser error : Premature end of data in tag urlset line 2

  ^
  종료 코드: 1
  ```

  "3번째 줄에서 연 `url`이 닫히기 전에 `urlset`을 닫았다"는 뜻이에요.

## 2단계: 페이지 더 넣기 — 넣을 주소와 넣으면 안 되는 주소

🧭 1단계 틀에 페이지를 더해요. 01회차 5단계의 "공개할 페이지와 보호할 페이지 구분", 02회차 5단계의 `noindex`가 여기서 다시 나와요.

페이지가 더 있으면 `<url>…</url>` 묶음을 하나씩 더해요. 넣는 기준은 **실제로 존재하고, 공개 검색에 포함하고 싶은 페이지**예요. 반대로 넣지 않는 주소가 있어요. `localhost` 주소(검색로봇에게는 자기 컴퓨터), 존재하지 않는 페이지, 로그인해야 보이는 개인정보 페이지, 관리자 화면, `noindex`를 붙인 페이지, `#learning`처럼 같은 페이지 안의 위치를 가리키는 주소예요. `noindex` 페이지를 사이트맵에 넣으면 "색인해 주세요"(사이트맵)와 "색인하지 마세요"(`noindex`)를 동시에 말하는 셈이 돼요.

사이트를 만든 도구나 서비스가 사이트맵을 **자동으로** 만들어 주는 경우도 있어요. 이미 `sitemap.xml`이 있으면 새 파일로 덮어쓰지 말고, 먼저 지금 내용과 어떻게 만들어지는지 확인해요.

넣은 주소가 정말 넣어도 되는 주소인지는 `sitemap_check.py`로 점검해요. 사이트맵을 읽어서 주소마다 앞부분(`https://my-service.example.com`)을 내 컴퓨터 주소(`http://localhost:8000`)로 바꿔 열어 보고, 상태 코드와 `robots.txt`, `noindex`를 확인해요. 02회차의 두 점검을 사이트맵 주소 전체에 한 번에 하는 거예요.

<details><summary>sitemap_check.py 전체 코드 (예제 폴더에 있는 것과 같아요)</summary>

```python
# sitemap_check.py — 사이트맵에 넣은 주소를 하나씩 열어 보고, 검색에 알려도 되는 페이지인지 점검해요
# 배포 전 점검용이에요. 사이트맵의 실제 주소 앞부분을 내 컴퓨터 주소로 바꿔서 열어요.
# 실행: python3 sitemap_check.py http://localhost:8000 https://my-service.example.com
import sys
import xml.etree.ElementTree as ET
from urllib.request import urlopen
from urllib.error import HTTPError
from urllib.robotparser import RobotFileParser

local, real = sys.argv[1], sys.argv[2]
SITEMAP = "{http://www.sitemaps.org/schemas/sitemap/0.9}"  # xmlns에 적은 사이트맵 규칙 주소

with urlopen(local + "/sitemap.xml") as response:
    print("sitemap.xml:", response.status, response.headers["Content-Type"])
    root = ET.fromstring(response.read())  # XML 형식이 틀리면 여기서 오류가 나요

robots = RobotFileParser(local + "/robots.txt")
robots.read()

locs = root.findall(f"{SITEMAP}url/{SITEMAP}loc")
print("찾은 주소:", len(locs), "개")
for loc in locs:
    url = loc.text.strip()
    if not url.startswith(real):
        print(f"  {url} → 내 사이트 주소가 아니에요")
        continue
    if "#" in url:
        print(f"  {url} → # 뒤는 같은 페이지 안의 위치예요")
        continue
    local_url = local + url[len(real):]
    try:
        with urlopen(local_url) as page:
            status, html = page.status, page.read().decode("utf-8")
    except HTTPError as error:
        status, html = error.code, ""
    notes = []
    if not robots.can_fetch("Googlebot", local_url):
        notes.append("robots.txt가 수집을 막아요")
    if 'content="noindex"' in html:
        notes.append("noindex가 있어요")
    print(f"  {url} → {status}" + "".join(" / " + note for note in notes))
```
</details>

### ▶ 직접 해 보기 — 소개 페이지 더하고 점검하기

`sitemap.xml`을 이렇게 바꿔요. 강의 예시의 `/about`은 이 연습장에서는 파일 이름 그대로 `/about.html`이에요.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://my-service.example.com/</loc>
  </url>

  <url>
    <loc>https://my-service.example.com/about.html</loc>
  </url>
</urlset>
```

```bash
xmllint --noout sitemap.xml && echo "XML 형식 OK"
python3 sitemap_check.py http://localhost:8000 https://my-service.example.com
```

```text
XML 형식 OK
sitemap.xml: 200 application/xml
찾은 주소: 2 개
  https://my-service.example.com/ → 200
  https://my-service.example.com/about.html → 200
```

`&&`는 앞 명령이 성공했을 때만 뒤 명령을 실행해요. 두 주소 모두 `200`이고, 막는 설정도 없어요.

**바꿔 보기** (확인하면 위 두 주소 상태로 되돌려요)
- `</urlset>` 바로 위에 넣으면 안 되는 주소 네 개를 `<url><loc>…</loc></url>` 묶음으로 더해 봐요: `https://my-service.example.com/admin.html`, `https://my-service.example.com/courses`, `https://my-service.example.com/#learning`, `http://localhost:8000/`. `xmllint`는 `XML 형식 OK`예요. 형식은 맞으니까요. 점검 결과는 이래요.

  ```text
  sitemap.xml: 200 application/xml
  찾은 주소: 6 개
    https://my-service.example.com/ → 200
    https://my-service.example.com/about.html → 200
    https://my-service.example.com/admin.html → 200 / noindex가 있어요
    https://my-service.example.com/courses → 404
    https://my-service.example.com/#learning → # 뒤는 같은 페이지 안의 위치예요
    http://localhost:8000/ → 내 사이트 주소가 아니에요
  ```

  관리자 화면은 `noindex`와 부딪치고, `/courses`는 없는 페이지이고, `#learning`은 별도 페이지가 아니고, `localhost`는 검색로봇이 열 수 없는 주소예요. `xmllint`는 형식만 보고 내용은 보지 않아요. 내용은 사람이 (또는 이런 점검으로) 봐야 해요.
- `about.html` 주소를 `https://my-service.example.com/courses?page=1&sort=new`로 바꾸면 이번엔 `xmllint`가 멈춰요.

  ```text
  sitemap.xml:8: parser error : EntityRef: expecting ';'
      <loc>https://my-service.example.com/courses?page=1&sort=new</loc>
                                                             ^
  ```

  XML에서 `&`는 특수 문자라 주소 안에서는 `&amp;`로 써야 해요. `?page=1&amp;sort=new`로 고치면 `XML 형식 OK`가 나와요. 점검 스크립트도 `&` 그대로일 때는 `xml.etree.ElementTree.ParseError: not well-formed (invalid token): line 8, column 59`로 멈춰요.
- `<urlset>`의 ` xmlns="http://www.sitemaps.org/schemas/sitemap/0.9"`를 지우면 `xmllint`는 `XML 형식 OK`인데 점검 결과는 `찾은 주소: 0 개`예요. XML 형식은 맞지만 사이트맵 규칙의 표시가 없어서 사이트맵 목록으로 읽히지 않은 거예요. 이 줄을 그대로 복사해 쓰라는 이유예요.

## 3단계: 사이트맵 배포 위치 — 일반 HTML, Vite의 `public/`, Spring Boot의 `static/`

🧭 React 04회차에서 `public/profile.png`가 `/profile.png`로 열렸고, Spring 03회차에서 `static/css/students.css`가 `/css/students.css`로 열렸어요. 사이트맵도 같은 폴더에 둬요.

사이트맵이 내 컴퓨터에만 있으면 검색엔진이 읽을 수 없어요. 배포해서 외부에서 `https://내주소/sitemap.xml`로 열려야 해요. 어디에 두는지는 프로젝트마다 달라요. 일반 HTML 사이트는 메인 `index.html`과 같은 배포 폴더, Vite React 프로젝트는 **`public/sitemap.xml`**, Spring Boot 프로젝트는 **`src/main/resources/static/sitemap.xml`**이에요. Spring은 `templates/`가 아니라 `static/`이에요. 두 폴더 모두 "파일을 주소 그대로 내보내는 폴더"라서, 둘 다 `/sitemap.xml` 주소로 열려요. Spring Boot 4.2에서 `static` 폴더에 둔 `sitemap.xml`이 `/sitemap.xml`로 `200`, `application/xml`로 나가는 것도 확인했어요. 파일을 넣은 뒤에는 **다시 배포**해요.

배포한 뒤 브라우저로 `/sitemap.xml`을 열면 "이 XML 파일에는 스타일 정보가 없다"는 안내와 함께 태그 구조가 보일 수 있어요. XML에는 화면 꾸미기 정보가 없어서 나오는 안내라 오류가 아니에요. 정말 확인해야 할 건 따로 있어요. **열리는 내용이 정말 사이트맵인지**예요. React 프로젝트는 배포 설정에 따라 없는 주소로 요청해도 메인 화면(`index.html`)을 `200`으로 보내 주는 경우가 있어서, "열렸다"만 보고 넘어가면 안 돼요. 아래에서 직접 봐요.

### ▶ 직접 해 보기 — `_react연습장/public/`에 두고, 없을 때와 비교하기

1. `_seo연습장`의 사이트맵을 `_react연습장/public/`으로 복사하고 개발 서버를 켜요.

```bash
cp ~/personal/KDT학습/practice/04_SEO과정/_seo연습장/sitemap.xml ~/personal/KDT학습/practice/01_React과정/_react연습장/public/
cd ~/personal/KDT학습/practice/01_React과정/_react연습장
npm run dev
```

2. 다른 터미널에서 확인해요. 주소에 `public`은 쓰지 않아요.

```bash
curl -s -o /dev/null -w "%{http_code} %{content_type}\n" http://localhost:5173/sitemap.xml
curl -s http://localhost:5173/sitemap.xml | head -3
```

```text

<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
```

Vite는 `text/xml`, Python 서버는 `application/xml`로 보냈어요. 둘 다 XML이라는 뜻이라 어느 쪽이어도 괜찮아요.

3. 배포할 때 올라가는 `dist/`에도 들어가는지 봐요. 개발 서버를 `Ctrl + C`로 끄고 빌드해요.

```bash

```

```text

```

`public/` 안의 파일은 빌드할 때 `dist/` 최상위로 그대로 복사돼요. 그래서 배포한 사이트에서도 `/sitemap.xml`이에요.

**바꿔 보기** (확인하면 되돌려요)
- `public/sitemap.xml`의 이름을 `sitemap.bak`으로 바꾸고 `npm run dev` 상태에서 2번 명령을 다시 쳐요.

  ```text
  200 text/html
  <!doctype html>
  <html lang="en">
  ```

  파일이 없는데도 `404`가 아니라 `200`이에요. 내용은 `index.html`이에요. Vite는 모르는 주소가 오면 React 화면을 보여 주려고 `index.html`을 대신 보내요. 브라우저로 열면 사이트맵 대신 메인 화면이 보여요. 같은 상황에서 `_seo연습장`의 Python 서버는 `404 text/html;charset=utf-8`을 보내요. 그래서 상태 코드만이 아니라 **Content-Type이 XML인지, 내용이 `<urlset>`인지**까지 봐야 해요.
- 주소를 `/public/sitemap.xml`로 잘못 쓰면 개발 서버에서는 XML이 나오지만 개발 서버 터미널에 `Files in the public directory are served at the root path.` / `Instead of /public/sitemap.xml, use /sitemap.xml.`이 찍혀요. 빌드한 뒤 `npm run preview`로 띄운 `http://localhost:4173/public/sitemap.xml`은 `200 text/html`, 즉 메인 화면이에요. 배포한 사이트에서는 `/public/`을 붙이면 안 돼요.

## 4단계: 사이트맵 제출 = 사이트맵이 있는 주소를 알려 주기 — "성공"의 뜻

🧭 1~3단계로 `/sitemap.xml`이 제대로 열리게 만들었어요. 이제 03회차에서 소유 확인한 관리 도구에 그 **주소**를 알려 줘요.

사이트맵 제출은 파일을 관리 도구에 **업로드하는 게 아니에요.** "내 사이트맵은 이 주소에 있어요"라고 **주소를 알려 주는** 거예요. 검색엔진은 그 주소로 직접 와서 파일을 가져가요. 그래서 제출하기 전에 사이트맵이 배포되어 외부에서 열려야 해요. 구글과 네이버에는 같은 사이트맵 주소를 내도 돼요.

**구글 서치 콘솔** — 03회차에서 소유 확인한 사이트를 고르고, 왼쪽 메뉴에서 **Sitemaps**를 열어요. 사이트맵 주소를 넣는 칸이 있는데, 칸 앞에 내 사이트 주소(`https://my-service.example.com/`)가 이미 적혀 있으면 나머지인 `sitemap.xml`만 넣어요. 앞에 적힌 주소를 또 쓰면 주소가 두 번 붙어요. 칸이 전체 주소를 받는 모양이면 `https://my-service.example.com/sitemap.xml`을 다 넣어요. 제출하면 아래 목록에 사이트맵과 **상태**가 나와요.

상태는 이렇게 읽어요. **성공**은 구글이 사이트맵 파일을 가져와서 읽고 처리했다는 뜻이에요. **가져올 수 없음**은 파일을 받아 오지 못했다는 뜻이라 주소, 외부 접근, 서버 응답을 봐요. **형식 관련 오류**는 받아 왔지만 XML 구조가 틀렸다는 뜻이라 오류 세부정보와 XML을 봐요.

그리고 가장 중요한 점이에요. **사이트맵 처리 "성공" ≠ 사이트맵 안의 모든 페이지가 검색에 등록됨.** "성공"은 사이트맵이라는 **파일 한 장**에 대한 결과예요. 그 안의 주소들은 이제 구글이 "이런 주소가 있다"고 알게 된 것뿐이고, 주소 하나하나는 여전히 01회차의 수집 → 색인 단계를 따로 거쳐요. 수집하지 않을 수도, 수집하고 색인하지 않을 수도 있어요. 페이지 하나가 실제로 색인됐는지는 5단계의 URL 검사로 따로 봐요.

**네이버 서치어드바이저** — 웹마스터 도구에서 소유확인을 마친 사이트를 고르고, **요청 → 사이트맵 제출**로 가요. 배포된 사이트맵의 **전체 주소**(`https://my-service.example.com/sitemap.xml`)를 넣고 제출해요. 제출 목록에서 넣은 주소와 처리 결과를 봐요. 여기서도 제출이 접수됐다고 검색에 나오는 건 아니에요.

### ▶ 직접 해 보기 — 제출 전에 "가져올 수 있나, 형식이 맞나" 미리 보기

구글의 "가져올 수 없음"과 "형식 관련 오류"는 내 쪽에서 미리 확인할 수 있어요. 지금은 `_seo연습장`으로 하고, 배포한 뒤에는 주소만 `https://내주소/sitemap.xml`로 바꿔요.

```bash
curl -s -o /dev/null -w "%{http_code} %{content_type}\n" http://localhost:8000/sitemap.xml
curl -s http://localhost:8000/sitemap.xml | xmllint --noout - && echo "XML 형식 OK"
```

```text
200 application/xml
XML 형식 OK
```

첫 줄은 "가져올 수 있다"(`200`, XML 종류), 둘째 줄은 "형식이 맞다"예요. `xmllint --noout -`의 `-`는 파일 대신 앞 명령에서 받은 내용을 검사하라는 뜻이에요. 서버가 실제로 내보내는 내용을 검사하는 거라, 내 컴퓨터의 파일만 검사하는 것보다 배포 상태에 가까워요.

**바꿔 보기**
- `_seo연습장`의 `sitemap.xml` 이름을 잠깐 `sitemap.bak`으로 바꾸고 첫 명령을 치면 `404 text/html;charset=utf-8`이에요. 구글이 이 상태에서 가져가려 하면 "가져올 수 없음"이 나올 상황이에요. 이름을 되돌려요.

## 5단계: 페이지 하나씩 보기 — 구글 URL 검사와 네이버 웹 페이지 수집 요청

🧭 4단계의 사이트맵이 **여러 페이지의 목록**을 알려 준다면, 이번 단계는 **특정 페이지 하나**의 상태를 보고 요청하는 방법이에요. 4단계의 "성공"만 보고 끝내지 않고, 정말 중요한 페이지가 어떤 상태인지 여기서 확인해요.

**구글 URL 검사** — 서치 콘솔 맨 위 **URL 검사** 입력칸에 메인 페이지 주소(`https://my-service.example.com/`)를 넣어요. 결과는 두 가지로 나뉘어요. **기본 검사 결과**는 구글이 **이미 저장하고 있는** 그 페이지의 색인 정보예요. 구글에 등록되어 있는지, 아니면 아직 등록되지 않았는지가 나오고, 등록되지 않았으면 세부정보를 펼쳐 **이유**를 봐요. **실제 URL 테스트**는 버튼을 눌러 구글이 **지금 배포된** 페이지에 접근해 보고, 접근할 수 있는지와 색인될 수 있는 상태인지 검사하는 거예요. 그런데 실제 URL 테스트가 정상으로 나와도 "이미 색인됐다"거나 "반드시 색인된다"는 뜻은 아니에요. 지금 페이지에 문제가 없다는 뜻이에요.

새 페이지를 만들었거나 중요한 내용을 고쳤으면 **색인 생성 요청**을 누를 수 있어요. 순서는 "페이지 배포 → URL 검사 → 문제가 있으면 수정 → 색인 생성 요청"이에요. 같은 주소를 여러 번 요청해도 빨리 처리되지 않아요.

**네이버 웹 페이지 수집** — 웹마스터 도구에서 사이트를 고르고 **요청 → 웹 페이지 수집**으로 가요. 수집을 요청할 페이지 주소를 넣는데, 입력칸 앞에 사이트 주소가 이미 적혀 있으면 **경로만** 넣어요. 메인이면 `/`, 소개 페이지가 있으면 `/about`처럼요. 네이버는 수집 요청을 바로 처리하지 않고, 같은 URL을 매일 반복해서 요청할 필요는 없다고 안내해요.

여기서도 **수집 요청이 접수된 것과 검색에 노출된 것은 달라요.** 요청은 "봐 주세요"까지예요.

### ▶ 직접 해 보기 — 실제 URL 테스트 전에 내 쪽에서 보는 것

실제 URL 테스트가 보는 "접근할 수 있는가, 색인을 막는 설정이 있는가"는 02회차의 `seo_check.py`로 미리 볼 수 있어요. 메인 페이지와 관리자 화면을 비교해요.

```bash
python3 seo_check.py http://localhost:8000/ | head -4
python3 seo_check.py http://localhost:8000/admin.html | head -3
```

```text
상태 코드: 200 | Content-Type: text/html
title: 한코딩 | 웹 개발 기초와 실습 강의
meta viewport: width=device-width, initial-scale=1.0
meta description: 한코딩에서 HTML, CSS, JavaScript와 React를 예제로 배우고 직접 웹 서비스를 만들어 보세요.
상태 코드: 200 | Content-Type: text/html
title: 관리자 화면 | 한코딩
meta robots: noindex
```

메인은 `200`이고 `meta robots` 줄이 없어요. 색인을 막는 설정이 없어요. 관리자 화면은 `noindex`가 있어서, 구글에 색인 생성 요청을 해도 색인하지 말라는 페이지예요. 이런 페이지는 요청하지 않아요.

**바꿔 보기**
- 메인 `index.html`의 `<meta charset="UTF-8" />` 아래에 `<meta name="robots" content="noindex" />`를 넣고 첫 명령을 다시 치면 셋째 줄이 `meta robots: noindex`로 바뀌어요 (넣은 자리가 `viewport`보다 위라서요). 공개 페이지에 실수로 이 줄이 남아 있으면 색인 생성 요청을 몇 번 해도 소용이 없어요. 바로 지워요.

## 6단계: 검색에 안 나오면 — 상태부터 보고 원인에 맞게 고치기, 그리고 계속 관리하기

🧭 1~5단계에서 알려 주고 요청하는 방법을 다 봤어요. 그래도 검색에 안 나올 때 무엇부터 볼지 정리하고, SEO 과정을 마무리해요.

등록하고 사이트맵을 냈는데 검색에 안 나온다고 바로 오류로 판단하지 않아요. 수집·색인에는 시간이 걸리고, 검색엔진이 모든 페이지를 색인하지도 않아요. 먼저 확인할 것을 순서대로 보면 이래요. 외부에서 로그인 없이 공개 페이지에 들어갈 수 있는가, 페이지 주소가 실제로 있고 정상 내용을 보여 주는가, 정상 페이지가 HTTP `200`으로 응답하는가(개발자 도구 **Network**에서 문서 요청을 골라 Status를 봐요), `robots.txt`가 공개 페이지를 막고 있지 않은가, `noindex`가 잘못 붙어 있지 않은가, 본문이 서비스의 목적과 정보를 충분히 담고 있는가, 메인에서 중요한 페이지로 가는 링크가 있는가, 그리고 관리 도구에 표시된 사유와 검사 결과는 무엇인가예요.

검색에 없다고 무조건 코드를 고치는 것도 아니에요. 관리 도구의 사유에 따라 할 일이 달라요. 아직 발견하거나 수집하지 못한 상태면 발견 경로(링크, 사이트맵)와 처리 상태를 확인해요. 수집 오류면 서버나 접근 설정을 고쳐요. 중복 페이지로 판단됐으면 같은 내용을 주는 다른 주소가 있는지 봐요. 내용이 부족하다면 실제 사용자에게 필요한 설명과 정보를 보태요. **상태를 먼저 확인하고, 원인에 맞게 고쳐요.**

SEO는 등록 버튼을 누르면 끝나는 일이 아니에요. 운영하면서 새 공개 페이지가 사이트맵에 들어갔는지, 지운 페이지 주소가 사이트맵에 남아 있지 않은지, 주요 페이지가 잘 열리는지, 검색엔진이 알려 준 문제가 있는지, 사용자에게 필요한 정보가 충분한지 계속 봐요. 사이트맵을 손으로 썼다면 페이지가 바뀔 때마다 파일도 고쳐야 하고, 페이지가 많아지면 자동으로 만드는 방법을 생각해요. 검색으로 들어온 사람이 서비스가 무엇인지 알고 실제로 써 볼 수 있게 만드는 것까지가 운영이에요.

### ▶ 직접 해 보기 — 흔한 실수를 일부러 넣고 점검으로 찾기

1. 지금 상태를 점검하고, 메인에서 소개 페이지로 가는 내부 링크가 있는지도 봐요.

```bash
python3 sitemap_check.py http://localhost:8000 https://my-service.example.com
curl -s http://localhost:8000/ | grep -o 'href="/[^"#]*"'
```

```text
sitemap.xml: 200 application/xml
찾은 주소: 2 개
  https://my-service.example.com/ → 200
  https://my-service.example.com/about.html → 200
href="/about.html"
```

두 번째 명령은 `#`으로 시작하지 않는 사이트 안 링크만 골라요. 메인에 `/about.html` 링크가 있어요 (02회차 3단계에서 `nav`에 남긴 링크).

2. 실수 두 개를 한꺼번에 넣어요. 메인 `index.html`에 `<meta name="robots" content="noindex" />`를 넣고, `robots.txt`를 `User-agent: *` / `Disallow: /about.html`로 바꿔요. 다시 점검해요.

```text
sitemap.xml: 200 application/xml
찾은 주소: 2 개
  https://my-service.example.com/ → 200 / noindex가 있어요
  https://my-service.example.com/about.html → 200 / robots.txt가 수집을 막아요
```

두 페이지 모두 `200`으로 잘 열리고, 브라우저로 봐도 아무 이상이 없어요. 그래서 눈으로는 못 찾는 실수예요. 이 상태로 사이트맵을 제출하면 구글은 사이트맵을 "성공"으로 처리할 수 있지만, 메인은 색인하지 말라고 했고 소개 페이지는 수집하지 말라고 했으니 둘 다 검색에 들어가기 어려워요. **사이트맵 "성공"과 페이지 색인이 다른 이유**를 직접 만든 거예요.

3. 두 실수를 되돌리고(`noindex` 줄 삭제, `robots.txt`를 `Allow: /`로) 1번 결과가 다시 나오는지 확인해요.

**바꿔 보기**
- `about.html`의 이름을 `about-us.html`로 바꾸고 점검하면 `https://my-service.example.com/about.html → 404`예요. 페이지를 지우거나 이름을 바꾸고 사이트맵을 안 고친 상태예요. 이름을 되돌리거나, 이름을 바꿨다면 사이트맵과 메인의 링크도 같이 고쳐요.

## 마무리: 사이트맵 한 장이 검색 결과까지 가는 길

배포한 사이트에서 오늘 배운 순서를 처음부터 따라가면 이래요.

1. `sitemap.xml`에 공개할 페이지의 전체 주소를 `<urlset>` → `<url>` → `<loc>` 틀로 적어요. `xmllint --noout`으로 형식을 검사하고, `sitemap_check.py`로 넣으면 안 되는 주소가 없는지 봐요 (1·2단계).
2. Vite는 `public/`, Spring Boot는 `static/`에 두고 빌드·배포해요. `https://내주소/sitemap.xml`이 `200`, XML 종류, `<urlset>` 내용으로 열리는지 확인해요. 메인 화면이 대신 나오면 안 돼요 (3단계).
3. Search Console **Sitemaps**에 `sitemap.xml`을, 서치어드바이저 **요청 → 사이트맵 제출**에 전체 주소를 알려 줘요. 업로드가 아니라 주소를 알려 주는 거예요 (4단계).
4. 구글이 그 주소로 와서 파일을 가져가 읽어요. 성공하면 상태가 **성공**이 돼요. 이건 파일을 읽었다는 뜻이에요 (4단계).
5. 사이트맵 속 주소들이 발견돼요. 주소마다 수집 → 색인이 따로 진행돼요. 이때 `robots.txt`가 막으면 수집하지 않고, `noindex`가 있으면 색인하지 않아요 (2·6단계, 02회차 5단계).
6. 중요한 페이지는 **URL 검사**로 저장된 상태를 보고, **실제 URL 테스트**로 지금 상태를 보고, 필요하면 **색인 생성 요청**을 해요. 네이버는 **요청 → 웹 페이지 수집**이에요 (5단계).
7. 색인된 페이지 중에서 검색어에 맞는 것이 검색 결과에 나와요. 순서는 여러 요인으로 정해져요 (01회차 3단계).
8. 안 나오면 관리 도구의 사유를 먼저 보고 원인에 맞게 고쳐요. 페이지가 바뀌면 사이트맵도 고쳐요 (6단계).
