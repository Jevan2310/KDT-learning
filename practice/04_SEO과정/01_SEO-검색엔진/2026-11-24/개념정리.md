# 개념 정리 — SEO과정 01. SEO와 검색엔진 이해하기

> 날짜: 2026-11-24 · wiki: [01_SEO-검색엔진](../../../../wiki/04_SEO과정/01_SEO-검색엔진.md)
> 단계별 설명문으로 쓰고, 단계 끝마다 직접 해 보는 예시를 둔다. 쉬운 말, 비유 없이. 예시는 이 Mac에서 Python 3.14의 `http.server`와 `curl`로 미리 실행해 출력을 확인했다. 구글·네이버 검색 결과 화면은 검색 시점마다 달라서 적지 않았다.

## 들어가며

**🧭 맥락 — 지금 어디쯤**

React 과정에서는 화면을, Node·Spring 과정에서는 서버를 만들었어요. 그런데 만든 것은 모두 `http://localhost:5173`, `http://localhost:3000`, `http://localhost:8080`처럼 **내 컴퓨터 주소**에서만 열어 봤어요. 다른 사람이 이 서비스를 쓰려면 먼저 인터넷 주소로 배포해야 하고, 그다음에는 그 사람이 서비스를 **찾아낼 수** 있어야 해요. 검색은 사람들이 서비스를 찾아내는 대표적인 길이에요.

SEO 과정은 이 "찾아내게 하는 일"을 네 회차로 나눠서 해요.

```text
01 SEO와 검색 과정 이해 (수집 → 색인 → 검색 결과 표시)      ← 오늘
02 검색엔진이 이해하기 쉬운 페이지 (title · description · h1~h3 · alt · robots.txt · noindex)
03 구글·네이버에 사이트 등록 (HTML 확인 태그로 소유권 확인)
04 사이트맵 제출과 검색 상태 확인 (sitemap.xml · URL 검사 · 수집 요청)
```

오늘은 코드를 많이 쓰는 회차가 아니에요. 대신 서로 다른 상태 세 가지를 구분하는 게 목표예요. **주소로 접속할 수 있다(배포)**, **검색엔진이 페이지를 처리했다(검색 반영)**, **특정 검색어에 실제로 나온다(노출)**. 이 셋을 섞어 생각하면 "등록했는데 왜 안 나오지?", "사이트맵이 성공이라는데 왜 검색이 안 되지?" 같은 질문에서 계속 막혀요. 03·04회차에서 Search Console 화면을 볼 때도 이 구분이 그대로 쓰여요.

말로만 보면 헷갈리니까, 오늘은 `_seo연습장`이라는 작은 폴더를 만들어서 Python에 들어 있는 서버로 띄워요. 그리고 `curl`로 "검색로봇이 페이지를 가져가는 일"을 내 컴퓨터 안에서 흉내 내 봐요. 이 폴더는 02회차(제목·설명·robots.txt)와 04회차(sitemap.xml)에서 계속 키워요.

## 🛠 시작하기 — `_seo연습장` 만들고 서버 켜기

이번 과정은 npm이나 Spring 프로젝트가 필요 없어요. HTML 파일 몇 개와 Python만 있으면 돼요. 파이썬은 이미 설치되어 있어요 (`python3 --version`으로 확인).

1. 터미널에서 연습장 폴더를 만들어요. 한글 폴더 이름은 Tab 자동완성을 쓰면 편해요.

```bash
mkdir -p ~/personal/KDT학습/practice/04_SEO과정/_seo연습장
cd ~/personal/KDT학습/practice/04_SEO과정/_seo연습장
```

2. VS Code에서 **File → Open Folder**로 이 폴더를 열고, `index.html`을 새로 만들어 아래 내용을 붙여 넣어요. 제목이 `Vite + React`인 건 일부러예요. React 프로젝트를 처음 만들면 붙어 있는 기본 제목인데, 02회차에서 이걸 고쳐요.

```html
<!DOCTYPE html>
<html lang="ko">
  <head>
    <meta charset="UTF-8" />
    <title>Vite + React</title>
  </head>
  <body>
    <h1>한코딩 웹 개발 강의</h1>
    <p>기초부터 배우고, 직접 사용하는 서비스를 만듭니다.</p>
  </body>
</html>
```

3. VS Code 터미널(`Ctrl + ``)에서 서버를 켜요. `_seo연습장` 폴더 안에서 실행해야 해요.

```bash
python3 -m http.server 8000
```

```text
Serving HTTP on :: port 8000 (http://[::]:8000/) ...
```

`python3 -m http.server`는 파이썬에 들어 있는 작은 웹 서버예요. 지금 폴더의 파일을 주소 그대로 보내 줘요. `index.html`은 `/`, `about.html`은 `/about.html`로 열려요. Node 과정의 `express.static`이나 Spring의 `static` 폴더가 하던 일과 같아요.

4. 브라우저에서 `http://localhost:8000`을 열면 "한코딩 웹 개발 강의" 큰 제목이 보이고, 탭 제목은 `Vite + React`예요.

5. `curl` 명령은 **두 번째 터미널**에서 쳐요. VS Code 터미널 오른쪽 위 **+**를 누르면 새 터미널이 열려요. 첫 번째 터미널은 서버가 쓰고 있어서 명령을 받지 않아요.

서버를 끌 때는 서버 터미널에서 `Ctrl + C`를 눌러요. `Keyboard interrupt received, exiting.`이 나오면 꺼진 거예요.

`index.html`을 더블클릭해서 열지 않고 서버를 쓰는 이유가 있어요. 더블클릭하면 주소가 `file:///Users/...`가 되고, 서버를 거치지 않아요. 02·04회차에서 만들 `robots.txt`와 `sitemap.xml`은 **사이트 최상위 주소**(`/robots.txt`, `/sitemap.xml`)에서 서버가 보내 줘야 의미가 있어서, 처음부터 서버로 열어요.

## 1단계: 배포, 검색 반영, 검색어 노출은 서로 다른 상태예요

🧭 Node 03에서 `localhost`가 "접속하는 사람 자신의 컴퓨터"라는 걸 배웠어요. 오늘은 거기서 한 걸음 더 가서, 인터넷에 올린 뒤에도 바로 검색되지는 않는다는 걸 정리해요.

한코딩이 일정 관리 서비스를 만들어 인터넷에 배포했다고 해 봐요. 친구에게 주소를 알려 주면 친구는 접속할 수 있어요. 그런데 구글이나 네이버에서 서비스 이름을 검색하면 안 나올 수 있어요. 이상한 일이 아니에요. **주소로 접속할 수 있다는 것과 검색 결과에 나온다는 것은 다른 상태**이기 때문이에요.

상태를 세 개로 나눠 보면 이래요. **배포**는 사람들이 인터넷 주소로 접속할 수 있게 된 상태예요. **검색 반영**은 검색엔진이 그 페이지를 가져가서 처리했고, 검색 결과로 보여 줄 수 있는 상태예요. **특정 검색어에 노출**은 누군가 어떤 단어로 검색했을 때 결과 목록에 그 페이지가 실제로 나온 상태예요. 배포한 순간 검색엔진이 알아서 모든 페이지를 처리해 주지는 않아요. 그래서 배포 다음 날 검색해서 안 나와도 바로 오류라고 판단하지 않아요.

지금 `_seo연습장`은 이 세 상태 중 어디에도 없어요. `localhost`에서만 열리니까 배포조차 안 된 상태예요. 이 연습장으로는 "배포하면 어떤 요청이 오가는지"를 내 컴퓨터 안에서 미리 보는 거예요.

### ▶ 직접 해 보기 — 서버가 보내는 응답 보기

두 번째 터미널에서 쳐요. `-i`는 응답의 머리 부분(상태 코드, 파일 종류)도 같이 보여 달라는 옵션이에요.

```bash
curl -i http://localhost:8000/
```

```text
HTTP/1.0 200 OK
Server: SimpleHTTP/0.6 Python/3.14.6
Date: Tue, 24 Nov 2026 06:58:40 GMT
Content-type: text/html
Content-Length: 263
Last-Modified: Tue, 24 Nov 2026 06:58:38 GMT

<!DOCTYPE html>
<html lang="ko">
  <head>
    <meta charset="UTF-8" />
    <title>Vite + React</title>
  </head>
  <body>
    <h1>한코딩 웹 개발 강의</h1>
    <p>기초부터 배우고, 직접 사용하는 서비스를 만듭니다.</p>
  </body>
</html>
```

`200 OK`는 요청한 페이지를 정상으로 보냈다는 뜻이에요. `Content-type: text/html`은 보낸 것이 HTML이라는 뜻이고요. 아래쪽은 `index.html` 파일 내용 그대로예요. 브라우저도, 나중에 검색로봇도 이 응답을 받아요. Python 버전이 다르면 `Server:` 줄의 숫자와 날짜는 달라요.

**바꿔 보기**
- 서버 터미널에서 `Ctrl + C`로 서버를 끄고 같은 `curl`을 다시 쳐요. 서버가 없으니 요청을 받을 곳이 없어요.

  ```text
  curl: (7) Failed to connect to localhost port 8000 after 0 ms: Couldn't connect to server
  ```

  브라우저에서 새로고침하면 연결할 수 없다는 화면이 나와요. 사람도 검색로봇도 꺼진 서버의 페이지는 못 읽어요. `python3 -m http.server 8000`으로 다시 켜 둬요.

## 2단계: SEO는 검색엔진이 페이지를 발견하고 이해하기 쉽게 정리하는 일이에요

🧭 1단계에서 "배포해도 바로 검색되지 않는다"고 했어요. 그러면 검색에 잘 반영되도록 개발자가 할 수 있는 일이 무엇인지가 SEO예요.

**SEO**는 Search Engine Optimization의 줄임말이고, 우리말로는 검색엔진 최적화예요. 이름이 거창하지만 하는 일은 단순해요. 사이트 내용을 검색엔진이 **찾아내고 이해하기 쉽게** 정리하는 거예요. 예를 들면 이런 것들을 고쳐요. 페이지 내용을 설명하는 제목, 사람이 읽고 이해할 수 있는 본문과 링크 문구, 검색로봇이 들어올 수 있는 페이지 구조, 페이지끼리 이어 주는 링크, 그리고 수집이나 색인을 방해하는 설정이에요.

개발자가 SEO를 알아야 하는 이유는 서비스가 사용되기까지의 순서를 보면 알 수 있어요. 서비스를 만들고, 인터넷에 배포하고, 필요한 사람이 그 서비스를 **발견**하고, 방문해서 쓰고, 피드백을 받아 고쳐요. 기능을 아무리 잘 만들어도 발견되지 않으면 그 뒤 단계가 일어나지 않아요. 검색은 발견 경로 중 하나라서, SEO를 생각하면 "기능 만들기"뿐 아니라 "만든 것을 사용자에게 전달하기"도 같이 보게 돼요.

검색엔진은 사람처럼 화면 디자인을 보고 판단하지 않아요. 서버가 보낸 **HTML 글자**를 읽어요. 그래서 HTML에 "이 페이지가 무엇인지"가 잘 적혀 있어야 해요.

### ▶ 직접 해 보기 — 이 페이지는 자기를 어떻게 소개하고 있나

```bash
curl -s http://localhost:8000/ | grep -E "<title>|<h1>"
```

```text
    <title>Vite + React</title>
    <h1>한코딩 웹 개발 강의</h1>
```

`-s`는 진행 표시를 숨기는 옵션이고, `grep -E`는 `<title>`이나 `<h1>`이 들어 있는 줄만 골라 줘요. 본문 큰 제목은 서비스를 설명하지만, 문서 제목은 `Vite + React`예요. 이 제목만 봐서는 강의 사이트인지 알 수 없어요. 02회차에서 이 제목을 서비스에 맞게 고쳐요.

**바꿔 보기**
- `index.html`의 `<title>`을 `<title>한코딩 | 웹 개발 기초와 실습 강의</title>`로 바꾸고 저장한 뒤 같은 명령을 다시 쳐요. 서버를 다시 켤 필요는 없어요. `http.server`는 요청이 올 때마다 파일을 새로 읽어요. 첫 줄이 `<title>한코딩 | 웹 개발 기초와 실습 강의</title>`로 바뀌고, 브라우저 탭 제목도 새로고침하면 바뀌어요. 02회차는 `Vite + React`에서 시작하니까 확인했으면 되돌려 둬요.

## 3단계: 검색은 수집 → 색인 → 검색 결과 표시 순서로 일어나요

🧭 2단계에서 "검색엔진은 서버가 보낸 HTML을 읽는다"고 했어요. 그 읽는 과정을 세 단계로 나눠요. 04회차 Search Console 화면에 나오는 말이 모두 이 세 단계 중 하나예요.

**① 수집(크롤링)** — 검색엔진의 프로그램이 URL에 접속해서 페이지 내용을 가져와요. 이 프로그램을 **검색로봇** 또는 **크롤러**라고 하고, 가져오는 일을 **크롤링**이라고 해요. 실제로 하는 일은 우리가 1단계에서 친 `curl`과 같은 종류예요. 서버에 `GET` 요청을 보내고, 돌아온 HTML 글자를 받아 가요.

**② 색인** — 가져온 내용을 분석해요. 이 페이지는 무엇을 설명하는지, 어떤 내용이 있는지, 다른 페이지와 내용이 겹치지는 않는지를 봐요. 그리고 검색에 쓸 목록(**색인**)에 넣을지 정해요. 여기서 중요한 점은 **수집했다고 반드시 색인하지는 않는다**는 거예요. 내용이 다른 페이지와 같거나, 너무 적거나, 색인하지 말라는 설정이 있으면 빼요.

**③ 검색 결과 표시** — 누군가 검색하면, 색인에 있는 페이지 중 검색어와 관련 있는 것을 골라 순서를 정해 보여 줘요. 여기서도 **색인됐다고 모든 검색어에서 나오거나 항상 위쪽에 나오지는 않아요.**

세 단계를 구분해 두면, 나중에 "검색에 안 나와요"라는 문제를 만났을 때 어느 단계에서 멈췄는지부터 물어볼 수 있어요. 아직 수집을 안 했는지, 수집은 했는데 색인하지 않았는지, 색인은 됐는데 그 검색어로는 안 나오는지요.

### ▶ 직접 해 보기 — 서버 기록에 남는 수집 요청

두 번째 터미널에서 요청을 보내고, **서버 터미널**을 봐요.

```bash
curl -s http://localhost:8000/ > /dev/null
```

서버 터미널에 이 줄이 새로 생겨요.

```text
::1 - - [24/Nov/2026 15:58:40] "GET / HTTP/1.1" 200 -
```

앞에서부터 요청한 곳(`::1`), 받은 시각, 요청 내용(`GET /`), 응답 상태 코드(`200`)예요. `> /dev/null`은 받은 HTML을 화면에 찍지 않고 버리라는 뜻이에요. 실제 사이트를 검색로봇이 수집할 때도 서버 기록에 이런 `GET` 요청 줄이 남아요. 다른 점은 요청한 곳이 검색엔진 회사의 컴퓨터라는 것뿐이에요. 브라우저로 열면 `GET /favicon.ico ... 404` 줄도 같이 보일 수 있는데, 브라우저가 탭 아이콘을 찾는 요청이라 신경 쓰지 않아도 돼요.

**바꿔 보기**
- 없는 주소를 요청해 봐요.

  ```bash
  curl -s http://localhost:8000/courses > /dev/null
  ```

  서버 터미널에 이렇게 찍혀요.

  ```text
  ::1 - - [24/Nov/2026 15:58:40] code 404, message File not found
  ::1 - - [24/Nov/2026 15:58:40] "GET /courses HTTP/1.1" 404 -
  ```

  `404`는 "그런 페이지가 없다"는 응답이에요. 검색로봇이 이 응답을 받으면 가져갈 본문이 없어서 ① 수집에서 멈춰요. 색인이나 검색 결과 표시까지 가지 못해요.

## 4단계: 검색엔진은 링크, 사이트맵, 관리 도구 요청으로 페이지를 발견해요

🧭 3단계의 ① 수집은 "URL에 접속한다"에서 시작해요. 그런데 검색로봇은 그 URL을 어떻게 알까요? 이 단계가 01회차 "발견"이고, 04회차의 사이트맵과 수집 요청으로 이어져요.

검색로봇은 처음 보는 주소를 저절로 알지 못해요. 그래서 세 가지 길로 새 주소를 알아내요.

첫째는 **다른 페이지의 링크**예요. 이미 알고 있는 페이지를 수집했는데 그 HTML에 `<a href="/about.html">`가 있으면, 그 주소를 따라가서 새 페이지를 발견해요. 그래서 사이트 안에서도 메인 페이지에서 중요한 페이지로 링크가 이어져 있어야 해요. 그러면 사람도 이동하기 쉽고 검색로봇도 찾기 쉬워요.

둘째는 **사이트맵**이에요. `sitemap.xml`이라는 파일에 사이트의 주요 주소를 적어서 검색엔진에 알려 줘요. 04회차에서 직접 만들어요.

셋째는 **검색 관리 도구의 요청 기능**이에요. 사이트 주인이 Search Console이나 서치어드바이저에서 "이 페이지를 봐 주세요"라고 요청하는 거예요. 이것도 04회차에서 해요.

세 가지 모두 **발견을 도울 뿐**이에요. 사이트맵을 냈다고 모든 페이지를 수집하거나 색인하지는 않아요. 그리고 관리 도구 등록은 검색에 나오기 위한 필수 조건도 아니에요. 등록하지 않아도 링크로 발견되면 검색에 나올 수 있어요. 등록하면 상태를 확인하고 문제를 찾기 쉬워지는 거예요.

### ▶ 직접 해 보기 — 링크를 따라가며 발견하기

1. `_seo연습장`에 `about.html`을 새로 만들어요.

```html
<!DOCTYPE html>
<html lang="ko">
  <head>
    <meta charset="UTF-8" />
    <title>서비스 소개 | 한코딩</title>
  </head>
  <body>
    <h1>한코딩 서비스 소개</h1>
    <p>HTML부터 React, Node.js, Spring까지 예제로 배우는 강의 사이트입니다.</p>
    <a href="/">처음으로</a>
  </body>
</html>
```

2. `index.html`의 `<p>` 줄 바로 아래에 링크 한 줄을 넣어요. 링크 문구는 이동할 곳이 드러나게 써요 (02회차 4단계).

```html
    <p>기초부터 배우고, 직접 사용하는 서비스를 만듭니다.</p>
    <a href="/about.html">서비스 소개 보기</a>
```

3. 검색로봇처럼 메인 페이지에서 링크 주소만 뽑아 보고, 그 주소를 따라가 봐요. `grep -o`는 일치하는 부분만 보여 줘요.

```bash
curl -s http://localhost:8000/ | grep -o 'href="[^"]*"'
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8000/about.html
curl -s http://localhost:8000/about.html | grep -o 'href="[^"]*"'
```

```text
href="/about.html"
200
href="/"
```

메인에서 `/about.html`을 발견했고, 따라가니 `200`으로 열렸고, 소개 페이지에는 다시 메인으로 가는 링크가 있어요. 두 번째 명령의 `-o /dev/null`은 본문을 버리고, `-w "%{http_code}\n"`은 상태 코드만 찍으라는 뜻이에요.

**바꿔 보기**
- VS Code에서 `about.html`의 이름을 `about-us.html`로 바꾸고 두 번째 명령을 다시 쳐요. `404`가 나와요. 메인의 링크는 그대로 `/about.html`을 가리키는데 그 파일이 없어졌어요. 검색로봇은 링크로 주소를 발견했지만 가져갈 페이지가 없어요. 페이지 이름을 바꾸면 그 페이지를 가리키는 링크도 같이 고쳐야 해요. 확인했으면 `about.html`로 되돌려요.

## 5단계: 검색로봇이 들어올 수 있는 페이지여야 해요

🧭 4단계에서 발견한 주소를 3단계처럼 수집하려면, 검색로봇이 그 주소에 실제로 들어갈 수 있어야 해요. 02회차의 `robots.txt`·`noindex`, 03회차의 "외부에서 접속되는 주소"가 모두 이 이야기예요.

검색로봇이 페이지 내용을 가져가기 어려운 경우가 다섯 가지 있어요.

**`localhost`에서만 실행될 때** — `localhost`는 "지금 접속하는 사람 자신의 컴퓨터"예요. 검색로봇이 `http://localhost:8080/students`를 열면 검색로봇이 돌아가는 **검색엔진 회사의 컴퓨터**를 찾아요. 내 컴퓨터의 서버에 들어오는 게 아니에요. 그래서 SEO 등록 실습(03·04회차)에는 외부에서 접속되는 공개 주소가 꼭 필요해요.

**로그인한 뒤에만 보일 때** — 검색로봇은 내 계정으로 로그인하지 않아요. 로그인해야 보이는 화면은 로봇에게 로그인 화면이나 빈 화면으로 보여요.

**서버 오류가 날 때** — 3단계에서 본 `404`나, 서버가 고장 났을 때의 `500`이 돌아오면 가져갈 내용이 없어요.

**검색로봇의 접근을 막아 둘 때**, **색인에서 빼 달라고 설정했을 때** — `robots.txt`와 `noindex`라는 설정이에요. 02회차 5단계에서 직접 써 봐요.

구글은 공개적으로 접근할 수 있고 크롤링이 막혀 있지 않은 페이지를 검색 대상으로 처리한다고 안내해요. 하지만 이 조건을 다 갖춰도 색인이 **보장되지는 않아요.** 3단계에서 본 것처럼 색인 여부는 검색엔진이 정해요.

반대 방향도 생각해야 해요. **모든 페이지를 검색에 내보내는 게 SEO의 목표가 아니에요.** 학생 관리 서비스라면 서비스 소개 페이지는 검색에 나오면 좋지만, 학생 개인정보나 관리자 전용 목록은 공개 검색 대상이 되면 안 돼요. 공개할 페이지와 보호할 페이지를 먼저 나눠야 해요.

### ▶ 직접 해 보기 — `localhost`와 "주소만 알면 열리는 페이지"

1. 3단계 서버 기록 맨 앞의 `::1`을 다시 봐요. 이 주소는 IPv6 방식으로 쓴 "이 컴퓨터 자신"이에요. 같은 서버에 숫자 주소로도 요청해 봐요.

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/
```

```text
200
```

서버 터미널에는 이렇게 찍혀요.

```text
::ffff:127.0.0.1 - - [24/Nov/2026 15:58:54] "GET / HTTP/1.1" 200 -
```

`localhost`, `::1`, `127.0.0.1` 모두 "요청을 보낸 그 컴퓨터"를 가리켜요. 그래서 이 주소들은 다른 사람에게도, 검색로봇에게도 내 서버를 뜻하지 않아요.

2. 관리자 화면이라고 생각하고 `admin.html`을 만들어요. 실제 개인정보는 넣지 않고 글자만 써요.

```html
<!DOCTYPE html>
<html lang="ko">
  <head>
    <meta charset="UTF-8" />
    <title>관리자 화면 | 한코딩</title>
  </head>
  <body>
    <h1>관리자 화면</h1>
    <p>학생 연락처 목록 (연습용 가짜 화면)</p>
  </body>
</html>
```

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8000/admin.html
```

```text
200
```

메인 페이지에서 이 파일로 가는 링크는 없지만, 주소를 아는 사람은 누구나 열 수 있어요. 로그인 같은 확인 장치가 없으니까요. 이 사이트를 배포한다면 검색로봇도 이 주소를 알게 되는 순간 그대로 가져갈 수 있어요. 보호해야 할 화면은 **로그인과 접근 권한**으로 막아야 해요. 02회차 5단계에서 `robots.txt`와 `noindex`로는 이걸 막을 수 없다는 걸 직접 확인해요.

**바꿔 보기**
- 휴대폰이 같은 와이파이에 있으면 휴대폰 브라우저로 `http://localhost:8000`을 열어 봐요. 연습장 페이지가 아니라 연결할 수 없다는 화면이 나와요. 휴대폰에게 `localhost`는 휴대폰 자신이기 때문이에요. 검색로봇도 똑같아요.

## 6단계: 등록해도 1위가 되지는 않아요 — 검색 관리 도구와 지금 상태 살펴보기

🧭 1~5단계는 검색엔진 쪽에서 일어나는 일이었어요. 사이트 주인은 그 과정을 직접 보지 못해서, 검색엔진이 주는 **검색 관리 도구**로 상태를 확인해요. 03·04회차에서 쓸 도구를 미리 정리해요.

배우는 사람들이 많이 하는 오해가 몇 가지 있어요. 배포하면 바로 검색된다고 생각하지만, 실제로는 발견·수집·색인에 시간이 걸려요. 사이트맵을 내면 모든 페이지가 색인된다고 생각하지만, 사이트맵은 주소를 알려 주는 수단일 뿐이에요. 관리 도구에 등록하면 검색 1위가 된다고 생각하지만, 노출 순위는 여러 요인으로 정해져요. 검색에 안 나오면 코드가 틀렸다고 생각하지만, 새 사이트라서 아직 처리 중일 수도 있어요. SEO는 한 번 등록하면 끝난다고 생각하지만, 페이지와 검색 상태는 계속 관리해야 해요. 네이버도 사이트 최적화 리포트의 등급이 검색 상위를 뜻하지는 않는다고 안내해요. 검색에 나오는지와 몇 번째에 나오는지는 검색어, 시점, 검색하는 환경에 따라서도 달라요.

검색 관리 도구는 검색엔진마다 따로 있어요. 구글은 **Google Search Console**, 네이버는 **네이버 서치어드바이저**예요. 이 도구들로 할 수 있는 일은 사이트 소유·관리 권한 확인, 사이트맵 제출, 수집·색인 상태와 문제 확인, 수집 요청, 검색 관련 보고서 보기예요. 도구마다 기능과 보고서 이름은 조금씩 달라요. 하나 헷갈리기 쉬운 게 있어요. **네이버 서치어드바이저와 네이버 클라우드 콘솔은 다른 서비스예요.** 클라우드 콘솔은 서버 같은 인프라를 빌려 쓰는 곳이고, 검색 관리는 서치어드바이저에서 해요.

### ▶ 직접 해 보기 — 지금 검색 상태 살펴보기

이 실습은 검색만 하기 때문에 그 사이트의 관리 권한이 없어도 돼요. 내가 배포한 공개 사이트가 아직 없으니, 강사가 안내한 공개 사이트나 평소 아는 사이트 하나를 골라요. 검색 결과는 날마다 달라서 여기에는 결과를 적지 않았어요. 직접 보고 아래 다섯 가지를 메모해요.

1. 구글과 네이버에서 서비스 이름으로 검색해요.

```text
한코딩
```

2. 그 사이트 도메인으로 범위를 좁혀 검색해요. `example.com`은 설명용 주소라서 실제 확인할 도메인으로 바꿔요. **`site:` 뒤에 공백을 넣지 않아요.**

```text
site:example.com
```

3. 메모할 것
   - 사이트 주소
   - 사용한 검색어
   - 검색 결과에 나온 제목
   - 검색 결과에 나온 설명 문구
   - 원하는 페이지가 보이는지

검색 결과에는 광고나 이름이 비슷한 다른 서비스가 섞일 수 있어서, 제목만 보지 말고 **주소도** 같이 확인해요. 결과에 나온 제목·설명이 그 사이트 HTML의 `<title>`·`description`과 다를 수도 있어요. 02회차에서 이유를 봐요.

결과를 해석할 때는 조심해요. 일부 페이지가 나오면 "이 검색에서 확인되는 페이지가 있다"는 뜻일 뿐이에요. 원하는 페이지가 안 나오면 수집·색인·공개 상태를 더 확인해야 해요. 결과가 하나도 없어도 검색만으로는 원인을 정할 수 없어요. **`site:` 검색은 색인된 전체 목록이나 정확한 개수를 보장하지 않아요.** 특정 페이지의 정확한 상태는 소유 확인을 마친 관리 도구의 보고서와 URL 검사로 봐요 (04회차 5단계).

**바꿔 보기**
- Search Console(`https://search.google.com/search-console`)과 서치어드바이저(`https://searchadvisor.naver.com/`)를 브라우저로 열어만 봐요. 로그인하면 사이트를 추가하라는 화면이 나와요. 아직 배포한 주소가 없으니 여기서 멈추고, 03회차에서 이어 가요.

## 마무리: 오늘 연습장에서 한 일을 순서대로 따라가기

1. `_seo연습장` 폴더를 만들고 `python3 -m http.server 8000`으로 서버를 켰어요. 이 서버는 폴더의 파일을 주소 그대로 보내 줘요.
2. `curl -i`로 `/`를 요청해서 `200 OK`와 HTML을 받았어요. 하지만 `localhost` 주소라서 배포된 상태가 아니에요. 배포, 검색 반영, 검색어 노출은 서로 다른 상태예요 (1단계).
3. HTML의 `<title>`이 `Vite + React`라서 페이지가 무엇인지 설명하지 못한다는 걸 봤어요. 검색엔진은 화면이 아니라 HTML 글자를 읽어요 (2단계).
4. 서버 기록에 `GET / ... 200` 줄이 남는 걸 봤어요. 검색로봇의 수집도 이런 요청이에요. 수집 다음에 색인, 그다음에 검색 결과 표시가 있고, 앞 단계를 통과해도 다음 단계는 보장되지 않아요 (3단계).
5. 메인 페이지의 링크로 `about.html`을 발견하고 따라갔어요. 링크, 사이트맵, 관리 도구 요청이 발견 경로예요 (4단계).
6. `localhost`는 요청한 컴퓨터 자신이라 검색로봇이 들어올 수 없고, 로그인 없는 `admin.html`은 주소만 알면 누구나 열린다는 걸 봤어요 (5단계).
7. 검색 관리 도구(Search Console, 서치어드바이저)의 역할과, 검색·`site:` 검색으로 지금 상태를 관찰하는 방법을 정리했어요 (6단계).

서버는 `Ctrl + C`로 꺼요. `_seo연습장`의 `index.html`, `about.html`, `admin.html`은 02회차에서 그대로 써요.

| `curl: (7) Failed to connect to localhost port 8000 ... Couldn't connect to server` | 서버 터미널에서 `python3 -m http.server 8000`이 켜져 있는지 (시작하기, 1단계) |
| `OSError: [Errno 48] Address already in use` | 8000번을 이미 다른 서버가 쓰고 있음 → 그 터미널에서 `Ctrl + C`, 또는 `python3 -m http.server 8001` (시작하기) |
| 서버는 켜졌는데 `/`가 `404`이거나 파일 목록이 보임 | 서버를 `_seo연습장` 폴더 안에서 켰는지, `index.html` 이름이 맞는지 (시작하기) |
| 터미널에 명령을 쳐도 반응이 없음 | 그 터미널은 서버가 쓰는 중 → 두 번째 터미널에서 치기 (시작하기) |
| 파일을 고쳤는데 `curl` 결과가 그대로 | 파일을 저장했는지 (`http.server`는 매번 새로 읽어서 다시 켤 필요 없음) (2단계) |
| 서버 기록에 `GET /favicon.ico ... 404` | 브라우저가 탭 아이콘을 찾는 요청, 무시해도 됨 (3단계) |
| 링크를 눌렀더니 `404` | 링크의 `href`와 실제 파일 이름이 같은지 (4단계) |
| 휴대폰이나 다른 컴퓨터에서 `localhost:8000`이 안 열림 | 정상. `localhost`는 그 기기 자신 (5단계) |
| `site:` 검색 결과가 없음 | 검색만으로 원인을 정할 수 없음. `site:` 뒤에 공백이 없는지, 관리 도구로 확인 (6단계) |
| 배포했는데 검색에 안 나옴 | 바로 오류로 보지 않기. 발견·수집·색인 중 어디서 멈췄는지 04회차 도구로 확인 (1·3단계) |
