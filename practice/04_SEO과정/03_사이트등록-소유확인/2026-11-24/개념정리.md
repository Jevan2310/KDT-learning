# 개념 정리 — SEO과정 03. 구글·네이버에 사이트 등록하기

> 날짜: 2026-11-24 · wiki: [03_사이트등록-소유확인](../../../../wiki/04_SEO과정/03_사이트등록-소유확인.md)
> 단계별 설명문으로 쓰고, 단계 끝마다 직접 해 보는 예시를 둔다. 쉬운 말, 비유 없이. 예시는 이 Mac에서 `_seo연습장`(Python 3.14 `http.server`)과 `_react연습장` 복사본(Vite 8, React 19 — `vite build`·`vite preview`, jsdom으로 JavaScript 실행 뒤 화면)으로 미리 확인했다. 아직 배포한 사이트가 없어서 Search Console·서치어드바이저의 실제 소유 확인 화면은 확인하지 못했고, 그 부분은 강의 순서대로 무엇을 누르면 무엇이 나오는지 설명만 한다.

## 들어가며

**🧭 맥락 — 지금 어디쯤**

01회차에서 검색 관리 도구로 구글은 **Google Search Console**, 네이버는 **네이버 서치어드바이저**를 쓴다고 했어요. 02회차에서는 `<head>`에 `title`과 `description`을 정리했고, React 페이지는 처음 받은 HTML에 `<head>`만 있고 본문은 JavaScript가 만든다는 것도 봤어요.

오늘은 그 관리 도구에 내 사이트를 등록해요. 등록하려면 먼저 "내가 이 사이트의 주인"이라는 걸 증명해야 하는데, 이걸 **소유권 확인**이라고 해요. 오늘 쓰는 방법은 도구가 발급한 **확인용 meta 태그**를 메인 페이지의 `<head>`에 넣는 거예요. 02회차에서 고친 바로 그 `<head>`예요.

이 방법에는 중요한 조건이 하나 있어요. 확인 버튼을 누르면 도구가 **인터넷에 배포된 내 사이트**를 직접 열어서 태그를 찾아요. 내 컴퓨터의 파일을 보는 게 아니에요. 그래서 HTML 태그 방식의 소유 확인은 **배포가 끝나야만** 성공해요. 파일에 태그를 넣고 저장만 한 상태, `localhost`에서만 열리는 상태로는 성공하지 않아요.

아직 배포한 사이트가 없으니 오늘은 두 부분으로 나눠요. 1~6단계는 지금 내 컴퓨터에서 할 수 있는 것들이에요. 태그를 `<head>`에 넣고, 처음 받는 HTML에 정말 들어 있는지 확인하고, "저장"과 "배포될 파일"이 어떻게 다른지, React 컴포넌트에 넣으면 왜 안 되는지를 직접 봐요. 7단계는 배포한 뒤에 도구에서 무엇을 누르는지 순서대로 정리해요. 배포 방법은 강의에서 다루지 않아서, 실제로 배포할 때 따로 정해요.

## 🛠 시작하기

새로 만들 프로젝트는 없어요. 두 연습장을 그대로 써요.

- `_seo연습장` — 02회차를 마친 상태 (`index.html`은 강의 종합 코드, `seo_check.py` 있음). 첫 번째 터미널에서 `python3 -m http.server 8000`으로 켜요.

## 1단계: 검색 관리 도구에 등록하는 이유 — 등록은 관리를 위한 것이에요

🧭 01회차 6단계에서 도구 이름과 하는 일을 정리했어요. 오늘은 실제로 그 도구에 사이트를 넣는 회차예요.

사이트를 배포하면 사람들은 주소로 들어올 수 있어요. 그런데 운영하는 사람은 그 너머가 궁금해요. 검색엔진이 우리 사이트를 수집하고 있는지, 검색에 들어간 페이지는 어떤 건지, 수집하다가 오류가 나지는 않았는지, 사람들이 어떤 검색어로 들어오는지요. 이런 건 검색엔진 안에서 일어나는 일이라 사이트 주인이 직접 볼 수 없어요. 그래서 검색엔진이 주인에게 보여 주는 관리 도구를 써요. 구글은 **Google Search Console**(구글 서치 콘솔), 네이버는 **네이버 서치어드바이저의 웹마스터 도구**예요. 네이버 클라우드 콘솔과는 다른 서비스예요.

여기서 01회차에 말한 구분을 다시 붙잡아야 해요. **사이트 등록은 검색 상태를 확인하고 관리하기 위한 과정이에요.** 등록했다고 검색에 노출되거나 순위가 올라가지 않아요. 네이버도 등록하지 않은 사이트가 검색에 반영될 수 있고, 등록·소유 확인을 하면 수집·색인·노출 정보를 **볼 수 있게 된다**고 안내해요. 등록과 소유 확인이 끝났다는 건 "이 사이트의 관리 화면을 볼 권한이 생겼다"는 뜻이에요.

### ▶ 직접 해 보기 — 두 도구 둘러보기

계정만 있으면 돼요. 아직 배포한 주소가 없으니 **주소를 넣기 전까지만** 가 봐요. 화면 문구는 계정과 시점에 따라 조금 다를 수 있어서 여기에 그대로 옮기지 않았어요.

1. `https://search.google.com/search-console`에 구글 계정으로 들어가요. 처음이면 **속성 유형 선택** 화면이 나와요. 왼쪽이 **도메인**, 오른쪽이 **URL 접두어**예요. 이미 다른 사이트가 있으면 왼쪽 위 사이트 선택 메뉴에서 **속성 추가**를 누르면 같은 화면이에요. 3단계에서 둘의 차이를 봐요.
2. `https://searchadvisor.naver.com/`에 네이버 계정으로 들어가서 **웹마스터 도구**를 눌러요. 사이트 주소를 넣는 입력칸이 있는 사이트 관리 화면이 나와요.

**바꿔 보기**
- 네이버 검색창에 "네이버 클라우드 콘솔"을 검색해서 들어가 보면, 서버·스토리지 같은 상품을 고르는 화면이에요. 사이트 등록 메뉴는 서치어드바이저 쪽에 있어요.

## 2단계: 소유권 확인 — 도구가 배포된 HTML에서 내 태그를 찾는 일

🧭 1단계의 관리 화면은 아무에게나 보여 주면 안 돼요. 그래서 등록할 때 주인인지 먼저 확인해요.

다른 사람이 우리 사이트의 관리 도구 화면을 보거나 설정을 바꾸면 안 되겠죠. 그래서 관리 도구는 "이 사이트를 실제로 수정하고 관리할 수 있는 사람인가요?"를 확인해요. 방법은 간단해요. 도구가 **사람마다 다른 값**이 든 태그를 발급해 주고, "이걸 사이트 HTML에 넣어 보세요"라고 해요. 그 사이트의 HTML을 고쳐서 배포할 수 있는 사람만 이걸 해낼 수 있으니, 태그가 실제 사이트에 올라와 있으면 주인이라고 인정하는 거예요.

순서는 이래요.

```text
관리 도구에서 확인용 태그 발급
              ↓
사이트 HTML의 <head>에 태그 추가
              ↓
수정한 사이트 다시 배포
              ↓
배포된 사이트의 페이지 소스에서 태그 확인
              ↓
관리 도구에서 확인 버튼
              ↓
관리 도구가 배포된 사이트 HTML을 받아 태그를 찾음
```

확인 태그는 화면에 보이는 글자가 아니에요. `<head>` 안에 넣는 meta 태그예요.

준비물은 구글 계정, 네이버 계정, **외부에서 접속되는 내 사이트의 메인 주소**, 그리고 그 사이트의 HTML을 고쳐 **다시 배포할 수 있는 환경**이에요. 수정 권한이 없는 남의 사이트로는 할 수 없어요. `http://localhost:5173/`이나 `http://localhost:8080/` 같은 주소도 안 돼요. 01회차 5단계에서 본 것처럼 `localhost`는 요청한 컴퓨터 자신이라, 관리 도구가 그 주소를 열면 도구 회사의 컴퓨터를 찾아요. 배포한 뒤에는 사이트 주소를 **시크릿 창**에서 열어서, 로그인하지 않아도 메인 화면이 정상으로 보이는지도 확인해요. 관리 도구도 로그인 없이 들어오니까요.

### ▶ 직접 해 보기 — 도구가 하는 일을 `curl`로 흉내 내기

확인 버튼을 누르면 도구가 하는 일은 결국 "메인 주소의 HTML을 받아서 확인 태그를 찾는 것"이에요. 지금 `_seo연습장`에 대고 해 봐요. `grep -c`는 찾은 줄의 개수를 세요.

```bash
curl -s http://localhost:8000/ | grep -c "google-site-verification"
```

```text
0
```

아직 태그를 넣지 않았으니 `0`이에요. 실제 도구라면 여기서 "확인 실패"가 나와요. 4단계에서 태그를 넣고 다시 쳐 봐요.

**바꿔 보기**
- 브라우저 시크릿 창(`Cmd + Shift + N`)에서 `http://localhost:8000`을 열면 잘 열려요. 하지만 이건 내 컴퓨터라서 "외부에서 접속된다"는 조건을 채운 게 아니에요. 시크릿 창 확인은 배포한 주소로 해야 의미가 있어요.

## 3단계: 구글의 두 가지 속성 — 도메인과 URL 접두어

🧭 1단계에서 본 "속성 유형 선택" 화면이에요. 어떤 것을 고르느냐에 따라 확인 방법이 달라져요.

Search Console에서 **속성**은 "관리할 사이트나 주소의 범위"를 뜻해요. 두 종류가 있어요.

**도메인** 속성은 `example.com`처럼 도메인 이름 하나를 넣어요. `http://`와 `https://`, `www.`나 `blog.` 같은 하위 도메인까지 그 도메인 아래 주소를 전부 한꺼번에 관리해요. 대신 확인은 **DNS 설정**으로만 해요. DNS는 도메인 이름이 어느 서버를 가리키는지 정하는 설정이라, 도메인을 산 곳의 관리 화면에서 바꿔야 해요.

**URL 접두어** 속성은 `https://my-service.example.com/`처럼 주소 앞부분을 넣어요. 이름 그대로 **입력한 주소로 시작하는 주소만** 관리해요. HTML 태그로 확인할 수 있어요.

이번 실습은 HTML을 고치는 방식이라 **URL 접두어**를 골라요. DNS는 바꾸지 않아요. 그런데 "입력한 주소로 시작하는 것만"이라는 규칙 때문에 주의할 점이 생겨요. `https://`와 `http://`는 다른 시작이고, `www`가 있고 없고도 다른 시작이에요. 그래서 입력칸에는 **사람들이 실제로 접속하는 최종 주소**를 `https://`와 `www` 유무까지 똑같이 넣어야 해요.

### ▶ 직접 해 보기 — 어떤 주소가 범위에 들어가는지 파이썬으로 보기

"입력한 주소로 시작한다"는 건 파이썬의 `startswith`와 같은 판단이에요. `_seo연습장`에 `prefix_check.py`를 만들어 돌려 봐요.

```python
# prefix_check.py — URL 접두어 속성에 어떤 주소가 들어가는지 확인해요
# 속성 주소로 "시작하는" 주소만 그 속성의 범위예요
prefix = "https://my-service.example.com/"

urls = [
    "https://my-service.example.com/",
    "https://my-service.example.com/about.html",
    "http://my-service.example.com/",
    "https://www.my-service.example.com/",
    "https://blog.my-service.example.com/",
]
for url in urls:
    print(url, "→", "포함" if url.startswith(prefix) else "포함 안 됨")
```

```bash
python3 prefix_check.py
```

```text
https://my-service.example.com/ → 포함
https://my-service.example.com/about.html → 포함
http://my-service.example.com/ → 포함 안 됨
https://www.my-service.example.com/ → 포함 안 됨
https://blog.my-service.example.com/ → 포함 안 됨
```

`https://my-service.example.com/`으로 등록하면 그 아래 페이지(`/about.html`)는 들어가지만, `http://`, `www.`, `blog.`로 시작하는 주소는 다른 범위예요. 도메인 속성(`example.com`)이었다면 다섯 개 모두 들어가요.

**바꿔 보기**
- `prefix`를 `"http://my-service.example.com/"`(s 없음)으로 바꾸고 다시 돌려요. 이번에는 `http://my-service.example.com/ → 포함`만 남고 나머지는 모두 `포함 안 됨`이에요. 사이트가 실제로는 `https://`로 열리는데 `http://`로 등록하면, 사람들이 보는 페이지가 전부 범위 밖이 돼요. 확인했으면 되돌려요.

## 4단계: 확인 태그는 메인 페이지의 `<head>` 안에 넣어요

🧭 2단계 순서의 둘째 칸 "사이트 HTML의 `<head>`에 태그 추가"예요. 02회차 1·2단계에서 `title`·`description`을 넣은 그 자리예요.

도구에서 발급받는 태그는 이런 모양이에요.

```html
<meta name="google-site-verification" content="구글에서_발급받은_실제_확인값"/>
```

```html
<meta name="naver-site-verification" content="네이버에서_발급받은_실제_확인값"/>
```

`content` 안의 값은 사람마다 달라요. 위 예시 값을 그대로 쓰면 확인되지 않아요. 내 화면에서 발급된 **태그 전체**를 복사해서 넣어요. 구글 태그와 네이버 태그는 **같이 넣어도 돼요.** 둘 다 `<head>` 안에 나란히 두면 돼요.

넣을 파일은 프로젝트마다 달라요. 일반 HTML 사이트는 메인 페이지 HTML, Vite React 프로젝트는 최상위 `index.html`, Spring + Thymeleaf는 메인 주소에서 응답하는 HTML 템플릿이에요. Spring은 파일 이름보다 "메인 주소로 요청했을 때 실제로 어떤 HTML이 나가는지"가 중요해요. 도구는 등록한 대표 주소 하나만 열어 보니까, 그 주소에서 나가는 HTML에 태그가 있어야 해요.

### ▶ 직접 해 보기 — `_seo연습장`에 두 태그 넣기

연습장은 배포하지 않으니 예시 값 그대로 넣어 봐요. 실제 확인값은 나중에 **배포할 프로젝트에만** 넣어요. `index.html`의 `description` meta 바로 아래, `</head>` 위에 넣어요.

```html
    <meta
      name="description"
      content="한코딩에서 HTML, CSS, JavaScript와 React를 예제로 배우고 직접 웹 서비스를 만들어 보세요."
    />

    <meta
      name="google-site-verification"
      content="구글에서_발급받은_실제_확인값"
    />

    <meta
      name="naver-site-verification"
      content="네이버에서_발급받은_실제_확인값"
    />
  </head>
```

```bash
python3 seo_check.py http://localhost:8000/ | head -7
curl -s http://localhost:8000/ | grep -c "site-verification"
```

```text
상태 코드: 200 | Content-Type: text/html
title: 한코딩 | 웹 개발 기초와 실습 강의
meta viewport: width=device-width, initial-scale=1.0
meta description: 한코딩에서 HTML, CSS, JavaScript와 React를 예제로 배우고 직접 웹 서비스를 만들어 보세요.
meta google-site-verification: 구글에서_발급받은_실제_확인값
meta naver-site-verification: 네이버에서_발급받은_실제_확인값
h1 개수: 1
2
```

`head -7`은 앞 7줄만 보여 줘요. 두 태그가 모두 `<head>` 안에 들어 있고, 2단계의 `grep -c`가 이제 `2`예요. 브라우저에서는 화면이 하나도 달라지지 않아요. 페이지 소스 보기에서 `Cmd + F`로 `site-verification`을 찾으면 두 줄이 보여요.

**바꿔 보기**
- 네이버 태그 다섯 줄을 잘라서 `<body>` 바로 아래로 옮기고 점검해요.

  ```text
  meta naver-site-verification: 네이버에서_발급받은_실제_확인값   ← <head> 밖
  ```

  `seo_check.py`가 `<head>` 밖이라고 표시해 줘요. 태그는 HTML 안에 있지만 강의가 정한 자리(`<head>`)가 아니에요. 확인 태그는 `<head>` 안에 넣어야 해요. 다시 `<head>` 안으로 옮겨요.

## 5단계: 저장 ≠ 배포 — 도구는 배포된 파일을 읽어요

🧭 2단계 순서의 셋째 칸 "다시 배포"예요. 많이 헷갈리는 부분이라, 저장한 것과 배포된 것이 왜 다른지 React 연습장으로 직접 봐요.

파일을 저장하면 내 컴퓨터의 파일만 바뀌어요. 인터넷에 올라가 있는 사이트는 그대로예요. 그래서 평소 쓰는 방법으로 "코드 수정 → 저장 → 빌드·배포 → 실제 사이트 확인"을 다 해야 해요. **관리 도구는 내 컴퓨터의 코드를 읽지 않고, 인터넷에 배포된 사이트를 읽어요.** 태그를 넣고 저장만 한 채 확인 버튼을 누르면 실패해요.

Vite 프로젝트는 이 차이가 특히 잘 보여요. `npm run dev` 개발 서버는 내가 저장한 `index.html`을 요청이 올 때마다 새로 읽어서, 저장하자마자 바뀐 걸 보여 줘요. 그런데 배포할 때 올라가는 건 `npm run build`가 만든 **`dist/` 폴더**예요. 빌드를 다시 하지 않으면 `dist/index.html`은 예전 그대로예요. `npm run preview`는 이 `dist/` 폴더를 배포된 사이트처럼 띄워 주는 명령이라, "배포하면 어떻게 보일지"를 내 컴퓨터에서 미리 볼 수 있어요. `dist/`는 `.gitignore`에 들어 있어서 GitHub에는 올라가지 않아요.

## 6단계: 페이지 소스 보기 vs 개발자 도구 — 확인 태그를 React 컴포넌트에 넣으면

🧭 02회차 6단계에서 React 페이지의 본문은 처음 HTML에 없고 JavaScript 실행 뒤에 생긴다고 봤어요. 확인 태그를 그쪽에 넣으면 어떻게 되는지 봐요.

브라우저에서 HTML을 보는 방법은 두 가지예요. **페이지 소스 보기**는 서버가 처음 보낸 HTML을 그대로 보여 줘요. **개발자 도구의 Elements**는 JavaScript가 실행된 뒤 지금 화면의 구조를 보여 줘요. 둘이 다를 수 있어요. Elements에 태그가 보여도, 처음 보낸 HTML에는 없을 수 있어요.

관리 도구가 읽는 건 처음 보낸 HTML 쪽이에요. 특히 **네이버는 소유 확인 때 JavaScript를 실행하지 않는다**고 안내해요. 그래서 React 코드(`App.jsx`나 컴포넌트)가 실행된 뒤에 생기는 태그는 네이버가 볼 수 없어요. 확인 태그는 처음 보내는 HTML, Vite라면 `index.html`의 `<head>`에 **직접** 넣어요. 4·5단계에서 한 방법이 맞는 방법이에요. 이번 실습의 확인도 그래서 **페이지 소스 보기**로 해요. 코드 편집기에 태그가 있다고, Elements에 태그가 보인다고, 배포된 처음 HTML에 태그가 있는 건 아니에요.

### ▶ 직접 해 보기 — 컴포넌트에 넣은 태그는 소스에 없어요

강의의 "자주 하는 실수"를 일부러 해 봐요.

1. `_react연습장/index.html`에서 네이버 태그 다섯 줄을 지워요 (구글 태그는 둬요).
2. `src/components/SeoIntro.jsx`의 `<header>` 바로 위에 네이버 태그를 넣어요.

```jsx
    <>
      <meta
        name="naver-site-verification"
        content="네이버에서_발급받은_실제_확인값"
      />
      <header>
```

3. `npm run dev`를 켜고 처음 HTML을 점검해요.

```bash
python3 ~/personal/KDT학습/practice/04_SEO과정/_seo연습장/seo_check.py http://localhost:5173/
```

```text
상태 코드: 200 | Content-Type: text/html
title: 한코딩 | 웹 개발 기초와 실습 강의
meta viewport: width=device-width, initial-scale=1.0
meta description: 웹 개발 기초를 배우고 직접 사용하는 서비스를 만들어 보는 한코딩 강의 사이트입니다.
meta google-site-verification: 구글에서_발급받은_실제_확인값
h1 개수: 0
```

`naver-site-verification` 줄이 없어요. 페이지 소스 보기에서 `naver`를 찾아도 없어요.

4. 이번에는 브라우저의 개발자 도구 **Elements**에서 `<head>`를 펼쳐 봐요. `naver-site-verification` meta가 `<head>` 안에 **들어 있어요.** React 19는 컴포넌트에 쓴 `<meta>`를 화면을 그릴 때 `<head>`로 옮겨 주기 때문이에요. 그래서 Elements만 보면 제대로 넣은 것처럼 보여요. 하지만 이건 JavaScript가 실행된 뒤의 모습이고, JavaScript를 실행하지 않는 네이버 소유 확인에는 이 태그가 없어요. 3번의 점검 결과가 네이버가 보게 될 모습이에요.

5. 확인했으면 되돌려요. `SeoIntro.jsx`의 meta 네 줄을 지우고, 네이버 태그를 `index.html`의 구글 태그 아래에 다시 넣어요. `seo_check.py`를 다시 돌리면 두 태그가 모두 나와요.

**바꿔 보기**
- 2번에서 넣은 태그를 그대로 두고 `npm run build` → `npm run preview` → `curl -s http://localhost:4173/ | grep -c "naver-site-verification"`을 쳐도 `0`이에요. 빌드한 `dist/index.html`에도 없어요. 컴포넌트 안의 태그는 HTML 파일이 아니라 JavaScript 파일 속에 들어가기 때문이에요.

## 7단계: 배포한 뒤에 할 일 — 구글·네이버 등록 순서와 실패했을 때 점검

🧭 1~6단계로 태그를 올바른 자리에 넣는 방법을 확인했어요. 이제 남은 건 배포한 사이트로 도구에서 실제 버튼을 누르는 일이에요. 배포한 뒤 이 순서대로 해요.

**구글 서치 콘솔**
1. `https://search.google.com/search-console`에 로그인하고 **속성 유형 선택** 화면으로 가요 (이미 속성이 있으면 사이트 선택 메뉴 → **속성 추가**).
2. **URL 접두어** 칸에 실제 배포 주소를 넣어요. `https://`와 `www` 유무를 실제 최종 주소와 맞춰요 (3단계).
3. 소유권 확인 방법 중 **HTML 태그**를 골라 발급된 태그 전체를 복사해요.
4. 메인 페이지 HTML의 `<head>`에 붙여 넣어요 (4단계).
5. 다시 빌드·배포해요 (5단계). 배포된 사이트를 열고 **페이지 소스 보기**에서 `google-site-verification`을 찾아요.
6. 서치 콘솔로 돌아가 **확인**을 눌러요. 확인되면 그 사이트의 관리 화면으로 들어갈 수 있어요.

**네이버 서치어드바이저**
1. `https://searchadvisor.naver.com/`에 로그인 → **웹마스터 도구**.
2. 사이트 등록 입력칸에 배포된 사이트의 대표 주소를 넣고 추가해요. 소유확인 방법을 고르는 화면으로 넘어가요.
3. **HTML 태그**를 골라 발급된 태그 전체를 복사해요.
4. `<head>`에 넣어요. 구글 태그는 그대로 두고 그 아래에 더해요.
5. 다시 배포하고, 메인 페이지 소스에서 `naver-site-verification`을 찾은 뒤 **소유확인**을 눌러요. 완료되면 사이트 목록에서 그 사이트를 골라 관리 화면으로 들어가요.

**확인이 끝나도 두 태그는 지우지 않아요.** 구글은 소유권을 나중에 다시 확인할 수 있어서, 태그를 지우면 확인이 풀릴 수 있어요.

**실패하면 이 순서로 점검해요.** 도구가 하는 일(주소를 열어 `<head>`에서 태그 찾기)을 거꾸로 따라가는 순서예요.
1. 등록한 주소와 실제 최종 접속 주소가 같은가? (`http`/`https`, `www`)
2. 수정한 내용을 정말 배포했는가? 로컬 화면이 아니라 배포된 사이트에서 봤는가?
3. 등록한 대표 주소(메인 페이지)를 수정했는가?
4. 태그가 `<head>` 안에 있는가? `<body>`나 React 컴포넌트 안이 아닌가?
5. 확인값이 지금 계정에서 발급받은 값과 같은가? 예시 값을 그대로 쓰지 않았는가?
6. 시크릿 창에서 로그인 없이 메인 화면이 열리는가?
7. 페이지 소스에 태그가 있는가? JavaScript로만 넣지 않았는가?

### ▶ 직접 해 보기 — 배포 후 터미널로 점검하는 명령 미리 익히기

배포한 뒤에는 아래 두 명령의 주소만 내 사이트로 바꿔 치면 돼요. 지금은 `_seo연습장`으로 연습해요.

첫째, 태그가 처음 HTML에 있는지 (점검 4·5·7번).

```bash
curl -s http://localhost:8000/ | grep -c "site-verification"
```

```text
2
```

배포한 사이트에서도 `2`가 나와야 해요. `0`이면 배포가 안 됐거나 태그가 JavaScript 쪽에 있는 거예요.

둘째, 주소창에 친 주소와 최종 주소가 같은지 (점검 1번). `-L`은 다른 주소로 넘겨주면(리다이렉트) 따라가라는 옵션이고, `%{url_effective}`는 마지막에 도착한 주소예요. 연습장에 `blog` 폴더를 만들고 그 안에 아무 `index.html`이나 하나 넣은 뒤 쳐 봐요.

```bash
curl -s -o /dev/null -w "%{http_code} %{redirect_url}\n" http://localhost:8000/blog
curl -s -o /dev/null -L -w "%{http_code} %{url_effective}\n" http://localhost:8000/blog
```

```text
301 http://localhost:8000/blog/
200 http://localhost:8000/blog/
```

`/blog`로 요청했더니 서버가 `301`로 `/blog/`(끝에 `/`)로 넘겨줬어요. 실제 사이트도 `http://`를 `https://`로, `www` 없는 주소를 `www` 있는 주소로 넘겨주는 경우가 많아요. 배포한 뒤 `http://내주소/`로 두 번째 명령을 쳐서 나온 최종 주소를 서치 콘솔 URL 접두어 칸에 넣어요. 확인했으면 `blog` 폴더는 지워요.

**바꿔 보기**
- 첫 번째 명령의 `site-verification`을 `google-site-verificaton`(i 하나 빠짐)으로 바꿔 치면 `0`이에요. 태그가 없어서가 아니라 찾는 글자가 틀려서예요. `0`이 나오면 찾는 글자부터 확인해요.

## 마무리: 확인 버튼을 눌렀을 때 일어나는 일

배포한 뒤 서치어드바이저에서 **소유확인**을 누르면 이런 순서로 진행돼요.

1. 나는 웹마스터 도구에 `https://my-service.example.com/`을 등록하고, HTML 태그 방식에서 내 계정용 확인값이 든 태그를 받았어요 (2·4단계).
2. 그 태그를 Vite 프로젝트의 최상위 `index.html` `<head>`에 넣었어요. React 컴포넌트가 아니에요 (4·6단계).
3. `npm run build`로 `dist/`를 새로 만들고 배포했어요. 저장만 하면 배포된 파일은 그대로예요 (5단계).
4. 배포된 주소의 페이지 소스 보기(또는 `curl … | grep -c`)로 태그가 처음 HTML에 있는 걸 확인했어요 (6·7단계).
5. 소유확인 버튼을 누르면 네이버가 `https://my-service.example.com/`에 요청을 보내 HTML을 받아요. JavaScript는 실행하지 않아요.
6. 받은 HTML의 `<head>`에서 `naver-site-verification` 태그를 찾고, `content` 값이 내 계정에 발급한 값과 같은지 봐요.
7. 같으면 소유 확인이 끝나고 관리 화면이 열려요. 이건 "관리 권한이 생겼다"는 뜻이지, 검색에 나온다는 뜻이 아니에요 (1단계). 태그는 지우지 않아요.

구글도 같은 흐름이고, 등록 단계에서 **URL 접두어** 속성을 고르고 주소 범위를 맞추는 것만 더 신경 써요 (3단계).

## 오류가 날 때 찾아보기

| 오류 문장 · 증상 | 먼저 볼 곳 |
|---|---|
| 서치 콘솔·서치어드바이저에 `localhost` 주소를 넣으려 함 | 등록에는 외부에서 접속되는 배포 주소가 필요 (2단계) |
| HTML 태그 방법이 안 보임 | 도메인 속성을 골랐는지 → URL 접두어로 (3단계) |
| 확인은 됐는데 일부 페이지가 그 속성에 없음 | `http`/`https`, `www` 유무가 실제 주소와 같은지 (3단계) |
| `grep -c "site-verification"`이 `0` | 태그를 넣고 저장했는지, `<head>` 안인지, 찾는 글자 철자 (4·7단계) |
| 점검 결과에 `← <head> 밖` | 태그를 `<body>`에 넣음 → `<head>` 안으로 (4단계) |
| 저장했는데 `npm run preview`에서 태그가 안 보임 | `npm run build`를 다시 해야 `dist/`가 바뀜 (5단계) |
| `npm run dev`에서는 보이는데 확인 실패 | 개발 서버는 내 컴퓨터. 빌드·배포했는지 (5단계) |
| `Port 4173 is in use, trying another one...` | 다른 미리보기가 켜져 있음 → 끄거나 터미널에 나온 새 주소로 (5단계) |
| Elements에는 태그가 있는데 페이지 소스에는 없음 | 태그를 React 컴포넌트에 넣음 → `index.html`의 `<head>`로 (6단계) |
| 예시 값 그대로 넣고 확인 실패 | 내 계정에서 발급받은 태그 전체로 바꾸기 (4·7단계) |
| 확인 후 한참 뒤 소유권이 풀림 | 태그를 지웠는지 → 다시 넣고 배포 (7단계) |
| 최종 주소가 등록한 주소와 다름 | `curl -L -w "%{url_effective}"`로 본 주소로 등록 (7단계) |
