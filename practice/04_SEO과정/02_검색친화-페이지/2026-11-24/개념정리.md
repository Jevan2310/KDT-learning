# 개념 정리 — SEO과정 02. 검색엔진이 이해하기 쉬운 페이지 만들기

> 날짜: 2026-11-24 · wiki: [02_검색친화-페이지](../../../../wiki/04_SEO과정/02_검색친화-페이지.md)
> 단계별 설명문으로 쓰고, 단계 끝마다 직접 해 보는 예시를 둔다. 쉬운 말, 비유 없이. 예시는 이 Mac에서 Python 3.14 `http.server`와 `예제/`의 점검 스크립트(파이썬 표준 라이브러리만 씀)로 미리 실행했고, React 부분은 `_react연습장` 복사본(Vite 8, React 19)에서 eslint·`vite build`·jsdom으로 JavaScript 실행 전후 HTML을 확인했다.

## 들어가며

**🧭 맥락 — 지금 어디쯤**

01회차에서 검색은 **수집 → 색인 → 검색 결과 표시** 순서로 일어나고, 검색엔진은 화면 디자인이 아니라 서버가 보낸 **HTML 글자**를 읽는다고 했어요. 그리고 `_seo연습장`의 제목이 `Vite + React`라서 이 페이지가 무엇인지 설명하지 못한다는 것도 봤어요.

오늘은 그 HTML을 고쳐요. 페이지가 "나는 이런 페이지예요"라고 분명하게 말하도록 만드는 회차예요. 고칠 곳은 `<head>` 안의 문서 제목 `<title>`과 페이지 설명 `<meta name="description">`, 본문의 제목 구조 `h1` → `h2` → `h3`, 이미지 설명 `alt`와 링크 문구, 그리고 검색로봇에게 주는 설정 `robots.txt`와 `noindex`예요. 다섯 가지 모두 HTML 과정 01회차에서 한 번씩 본 태그예요. 새로운 건 "검색엔진이 이걸 어떻게 읽는가"라는 눈으로 다시 보는 거예요. 03회차에서는 오늘 고친 `<head>`에 소유 확인 태그를 더 넣고, 04회차에서는 `robots.txt`와 `noindex`가 사이트맵 점검에 다시 나와요.

먼저 하나 기억해 둘 게 있어요. 오늘 쓰는 `title`과 `description`은 검색 결과에 나올 제목과 요약의 **후보**예요. 검색엔진은 이걸 참고하지만, 검색어와 페이지 내용에 따라 본문의 다른 문구를 대신 보여 줄 수 있어요. 잘 써도 그대로 나온다는 보장은 없고, 잘 쓰면 좋은 후보를 주는 거예요.

## 1단계: 페이지 제목 `title` — 이 페이지가 무엇인지 한 줄로

🧭 01회차 2단계에서 본 `<title>Vite + React</title>`를 고쳐요. HTML 01회차에서 `<head>` 안에 쓴다고 배운 그 태그예요.

`<title>`은 HTML 문서의 제목이에요. `<head>` 안에 쓰고, 화면 본문에는 나오지 않아요. 대신 두 곳에 쓰여요. 하나는 브라우저 **탭**에 보이는 글자예요. 다른 하나는 검색엔진이 검색 결과의 **제목을 만들 때 참고하는 정보**예요.

"참고한다"는 말이 중요해요. 검색엔진은 `<title>`을 먼저 보지만, 본문의 큰 제목이나 다른 정보를 보고 **다른 제목을 보여 줄 수도 있어요.** 그래서 `title`은 검색 결과 제목의 후보이지, 내가 쓴 그대로 나온다는 약속이 아니에요.

좋은 제목은 **페이지의 핵심 내용과 서비스 이름**을 같이 적어요. 메인 페이지라면 `한코딩 | 웹 개발 기초와 실습 강의`, React 강의 소개 페이지라면 `React 기초 강의 | 한코딩`처럼요. 페이지가 여러 개면 페이지마다 내용에 맞는 제목을 따로 써요. 반대로 `코딩 코딩강의 코딩교육 코딩공부 개발 개발자 한코딩`처럼 검색될 만한 단어를 늘어놓는 건 피해요. 사람이 읽어도 무슨 페이지인지 모르고, 검색엔진도 이런 제목을 그대로 쓰지 않을 수 있어요.

하나 헷갈리기 쉬운 게 있어요. React의 `App.jsx`에 쓴 `<h1>` 큰 제목과 브라우저 탭 제목(`<title>`)은 **다른 것**이에요. 6단계에서 직접 확인해요.

### ▶ 직접 해 보기 — 제목 바꾸고 점검하기

먼저 지금 상태를 봐요.

```bash
python3 seo_check.py http://localhost:8000/
```

```text
상태 코드: 200 | Content-Type: text/html
title: Vite + React
h1 개수: 1
h1 한코딩 웹 개발 강의
a /about.html → 서비스 소개 보기
```

`index.html`의 `<title>` 줄을 바꾸고 저장해요.

```html
    <title>한코딩 | 웹 개발 기초와 실습 강의</title>
```

같은 명령을 다시 치면 둘째 줄이 바뀌어요. 서버는 다시 켤 필요 없어요.

```text
상태 코드: 200 | Content-Type: text/html
title: 한코딩 | 웹 개발 기초와 실습 강의
```

브라우저에서 새로고침하면 탭 제목도 바뀌어요.

**바꿔 보기**
- `<title>` 줄을 통째로 지우고 다시 점검하면 `title: (없음)`이 나와요. 탭에는 제목 대신 페이지 주소가 보여요. 되돌려요.
- 제목을 `<title>코딩 코딩강의 코딩교육 코딩공부 개발 개발자 한코딩</title>`로 바꾸면 `title: 코딩 코딩강의 코딩교육 코딩공부 개발 개발자 한코딩`이 그대로 나와요. 문법 오류가 아니라서 어떤 도구도 막아 주지 않아요. 사람이 직접 판단해야 하는 부분이에요. 되돌려요.

## 2단계: 페이지 설명 `meta description` — 검색 결과 요약의 후보

🧭 1단계의 `title`이 "무슨 페이지인지 한 줄"이라면, `description`은 "조금 더 긴 소개 한두 문장"이에요. 같은 `<head>` 안에 써요.

```html
<meta
  name="description"
  content="한코딩에서 HTML, CSS, JavaScript와 React를 예제로 배우고 직접 웹 서비스를 만들어 보세요."
/>
```

`name="description"`은 "이 meta는 페이지 설명이다"라는 뜻이고, `content`에 실제 설명 문장을 적어요. `name`의 철자가 틀리면 검색엔진은 이게 설명인지 알 수 없어요.

검색엔진은 이 설명을 검색 결과 **요약문**으로 쓸 수 있어요. 여기서도 "쓸 수 있다"예요. 검색어와 페이지 내용에 따라 본문의 다른 부분을 요약으로 보여 줄 때도 있어요. `title`처럼 **후보**예요.

설명에는 짧고 자연스러운 문장으로 세 가지를 담아요. 어떤 서비스인지, 누구에게 도움이 되는지, 무엇을 할 수 있는지요. "최고의 서비스입니다. 다양한 기능을 제공합니다."는 어느 사이트에 붙여도 맞는 말이라 아무것도 설명하지 못해요. "반복되는 근무 일정과 약속을 캘린더로 관리하고, 등록한 근무를 바탕으로 수입을 확인할 수 있는 서비스입니다."처럼 기능이 보이게 써요. 그리고 설명은 **실제 페이지 내용과 맞아야** 해요.

설명은 화면 본문에 나오지 않아요. 그래서 넣었는지 확인하려면 페이지 소스 보기에서 `description`을 찾아요.

### ▶ 직접 해 보기 — 설명 넣고 소스에서 찾기

`index.html` 전체를 이렇게 맞춰요 (01회차 내용에 1단계 제목과 설명을 더한 것).

```html
<!DOCTYPE html>
<html lang="ko">
  <head>
    <meta charset="UTF-8" />
    <title>한코딩 | 웹 개발 기초와 실습 강의</title>
    <meta
      name="description"
      content="한코딩에서 HTML, CSS, JavaScript와 React를 예제로 배우고 직접 웹 서비스를 만들어 보세요."
    />
  </head>
  <body>
    <h1>한코딩 웹 개발 강의</h1>
    <p>기초부터 배우고, 직접 사용하는 서비스를 만듭니다.</p>
    <a href="/about.html">서비스 소개 보기</a>
  </body>
</html>
```

```bash

curl -s http://localhost:8000/ | grep -n -A1 'name="description"'
```

```text

`grep -n -A1`은 찾은 줄의 번호와 그 아래 한 줄을 같이 보여 줘요. 브라우저 화면에는 설명 문장이 어디에도 없지만, 페이지 소스 보기에서 `Cmd + F`로 `description`을 찾으면 7~8번째 줄에 있어요.

**바꿔 보기**
- `name="description"`을 `name="discription"`으로 바꾸고 점검하면 `meta discription: 한코딩에서 …`이 나와요. 브라우저도 서버도 아무 오류를 내지 않아요. 하지만 검색엔진이 아는 이름이 아니라서 설명으로 쓰이지 않아요. 철자를 되돌려요.

## 3단계: 본문 제목 구조 — `h1` 하나, 그 아래 `h2`, 그 아래 `h3`

🧭 1·2단계는 `<head>`, 여기부터는 `<body>`예요. HTML 01회차 4장에서 "제목 태그는 크기가 아니라 중요도로 고른다"고 배운 내용을 검색엔진 쪽에서 다시 봐요.

`<p style="font-size: 32px;">한코딩 웹 개발 강의</p>`는 화면에서는 큰 제목처럼 보여요. 하지만 HTML에서는 그냥 문단이에요. 검색엔진은 글자 크기가 아니라 태그를 읽기 때문에, 이 줄을 페이지의 대표 제목으로 알아보지 못해요. 대표 제목이면 `<h1>`을 써요.

제목 태그는 **내용의 관계**로 골라요. 페이지 전체를 대표하는 제목이 `h1`, 그 아래 큰 항목이 `h2`, `h2` 안의 작은 항목이 `h3`예요. 이번 실습에서는 대표 제목을 **`h1` 하나**로 정리하고, 주요 항목을 `h2`로 나눠요. 크기가 마음에 안 들면 태그를 바꾸지 말고 CSS로 조절해요.

이렇게 쓰면 HTML만 읽어도 페이지의 목차가 나와요. "한코딩 웹 개발 강의" 아래에 "배우는 내용"과 "강사 소개"가 있고, "배우는 내용" 안에 "프론트엔드 개발"과 "백엔드 개발"이 있다는 구조가 태그로 드러나요.

### ▶ 직접 해 보기 — 강의 종합 코드로 바꾸기

강의 실습 3의 종합 코드로 `index.html`을 통째로 바꿔요. 4단계의 `alt`와 링크도 이 안에 들어 있어요. `nav`의 세 번째 링크(`/about.html`)만 01회차에서 만든 소개 페이지로 가는 길을 남기려고 더한 줄이에요.

a #instructor → 강사 소개 보기
a /about.html → 서비스 소개 보기
```

`h1` 아래 줄은 들여쓰기로 단계를 보여 줘요. 이 들여쓰기는 스크립트가 태그 숫자를 보고 붙인 거예요. HTML만 읽어도 페이지 목차가 이렇게 나온다는 뜻이에요. `meta viewport`는 휴대폰 화면 폭에 맞추라는 설정이라 SEO와는 관계없어요.

**바꿔 보기** (하나씩 바꾸고 확인한 뒤 되돌려요)
- `<h1>한코딩 웹 개발 강의</h1>`를 `<p style="font-size: 32px;">한코딩 웹 개발 강의</p>`로 → 브라우저에서는 여전히 크게 보이지만, 점검 결과는 `h1 개수: 0`이고 목차가 `h2 배우는 내용`부터 시작해요. 검색엔진 입장에서는 대표 제목이 없는 페이지예요.
- `<h2>강사 소개</h2>`를 `<h1>강사 소개</h1>`로 → `h1 개수: 2`가 나오고, "강사 소개"가 대표 제목과 같은 높이로 올라가요. 페이지 안의 한 항목일 뿐인데 페이지 전체 제목처럼 표시된 거예요.

## 4단계: 이미지 `alt`와 링크 문구 — 이미지와 링크도 글로 설명해요

🧭 3단계 코드의 `<img>`와 `<a>`를 봐요. HTML 01회차 6장의 `alt`, 01회차 4단계에서 검색로봇이 따라가던 `<a href>`예요.

**`alt`**는 이미지가 전달하는 내용을 글로 적는 속성이에요. 검색엔진은 그림을 사람처럼 보지 않고 이 글을 읽어요. 이미지가 안 보이는 상황이나, 화면을 소리로 읽어 주는 **화면 낭독기**를 쓰는 사람에게도 이 글이 대신 전달돼요. 기준은 **이미지의 내용과 쓰임새**예요. 프로필 사진이면 `한코딩 강사의 프로필 사진`처럼요. 사진과 상관없는 `코딩 개발자 취업 React Spring 무료 강의` 같은 검색어를 넣지 않아요. 정보 없이 꾸미기만 하는 장식 이미지는 `alt=""`처럼 **빈 값**을 써요. 아예 `alt`를 빼는 것과 빈 값은 달라요. 빼면 "설명을 안 썼다", 빈 값이면 "설명할 게 없는 장식이다"라는 뜻이 돼요.

**링크 문구**는 눌렀을 때 무엇을 볼 수 있는지 알 수 있게 써요. `여기를 클릭하세요`는 링크만 따로 모아 보면 어디로 가는지 알 수 없어요. `웹 개발 강의 목록 보기`처럼 목적이 드러나게 써요. `href`에는 실제로 있는 주소를 넣어요. 01회차 4단계에서 본 것처럼 없는 주소면 `404`예요.

`href="#learning"`은 다른 페이지가 아니라 같은 페이지 안에서 `id="learning"`인 곳으로 이동하는 링크예요. 04회차 사이트맵에 이런 `#` 주소는 넣지 않아요.

### ▶ 직접 해 보기 — 이미지와 링크 확인

3단계 점검 결과의 `img`, `a` 줄이 이 단계의 내용이에요. 이미지 파일도 제대로 나가는지 확인해요.

```bash
curl -s -o /dev/null -w "%{http_code} %{content_type}\n" http://localhost:8000/profile.png
```

```text
200 image/png
```

브라우저에서는 "배우는 내용 살펴보기"를 누르면 그 부분으로 내려가고, "강사 소개 보기"를 누르면 사진이 있는 곳으로 가요. 주소창 끝에 `#learning`, `#instructor`가 붙어요.

**바꿔 보기** (하나씩 바꾸고 확인한 뒤 되돌려요)
- `alt="한코딩 강사의 프로필 사진"` 줄을 지우면 → `img profile.png → alt: (alt 없음)`
- `alt=""`로 바꾸면 → `img profile.png → alt: ""`. 장식 이미지라고 표시한 거예요. 이 사진은 정보가 있는 사진이라 맞지 않아요.
- `>서비스 소개 보기</a>`를 `>여기를 클릭하세요</a>`로 → `a /about.html → 여기를 클릭하세요`. 링크 목록만 보고는 어디로 가는지 알 수 없어요.

## 5단계: 검색을 막는 설정 — `robots.txt`와 `noindex`

🧭 01회차 5단계에서 검색로봇이 못 읽는 경우로 "접근 차단"과 "색인 제외"를 말로만 봤어요. 그게 이 두 설정이에요. 그리고 01회차에서 만든 `admin.html`이 "주소만 알면 열린다"는 문제를 이 설정으로 막을 수 있는지도 확인해요.

1~4단계를 잘해도, 검색엔진이 페이지를 **읽지 못하게** 되어 있거나 **검색에 넣지 말라고** 되어 있으면 소용이 없어요. 오늘은 두 설정의 역할 차이만 정확히 알면 돼요.

**`robots.txt`**는 사이트 **최상위 경로**(`/robots.txt`)에 두는 글자 파일이에요. 크롤러(검색로봇)에게 "이 경로는 수집하지 마세요"라고 안내해요. 크롤러는 사이트를 수집하기 전에 이 파일을 먼저 받아 보고 규칙을 따라요. 최상위가 아닌 폴더 안에 두면 읽지 않아요.

```text
User-agent: *
Disallow: /
```

`User-agent: *`는 "모든 크롤러에게 하는 말"이고, `Disallow: /`는 "`/`로 시작하는 모든 경로, 즉 사이트 전체를 수집하지 마세요"예요. 공개하려는 서비스에 이 두 줄이 들어 있으면 검색로봇이 아무 페이지도 가져가지 않아요. 그래서 내 사이트에 이런 설정이 있으면 **일부러 넣은 건지** 꼭 확인해요.

여기서 꼭 알아야 할 점이 두 가지예요. 첫째, `robots.txt`는 **규칙을 따르는 크롤러에게 하는 안내**일 뿐이에요. 로그인이나 비밀번호처럼 접근을 막는 **보안 기능이 아니에요.** 사람이나 규칙을 안 따르는 프로그램은 그대로 열 수 있어요. 둘째, 수집을 막았다고 그 주소가 검색 결과에서 반드시 사라지지는 않아요.

**`noindex`**는 페이지 HTML의 `<head>`에 넣는 태그예요.

```html
<meta name="robots" content="noindex" />
```

"이 페이지는 검색 색인에 넣지 마세요"라고 **요청**하는 거예요. 검색에서 빼고 싶은 페이지에만 붙이고, 검색에 알리고 싶은 공개 페이지에는 붙이지 않아요. 그런데 검색로봇이 이 태그를 보려면 먼저 **페이지를 수집할 수 있어야** 해요. `robots.txt`로 그 페이지의 수집을 막으면, 로봇은 페이지 안의 `noindex`를 읽을 기회가 없어요. 그래서 두 설정을 같은 페이지에 겹쳐 쓰면 `noindex`가 동작하지 않을 수 있어요.

정리하면 `robots.txt`는 **수집**할 경로 안내, `noindex`는 **색인** 제외 요청, 로그인과 접근 권한은 **보호**예요. 학생 개인정보나 관리자 화면은 로그인과 접근 권한으로 막아야 해요.

점검에는 `robots_check.py`를 써요. 파이썬에 들어 있는 `urllib.robotparser`(robots.txt 규칙을 읽는 모듈)로, 규칙을 따르는 크롤러가 각 경로를 수집할지 판단하는 걸 흉내 내요.

```python
# robots_check.py — robots.txt 규칙을 따르는 크롤러라면 각 경로를 수집할지 알려 줘요
# 실행: python3 robots_check.py http://localhost:8000 / /admin.html
import sys
from urllib.robotparser import RobotFileParser

site = sys.argv[1]
robots = RobotFileParser(site + "/robots.txt")
robots.read()  # 사이트 최상위의 /robots.txt를 받아 와요 (없으면 모두 허용)
for path in sys.argv[2:]:
    allowed = robots.can_fetch("Googlebot", site + path)
    print(path, "→", "수집해요" if allowed else "수집하지 않아요")
```

## 6단계: React 프로젝트에 적용하기 — `index.html`의 `<head>`와 처음 받은 HTML

🧭 React 04회차에서 `index.html`에는 `<div id="root"></div>`라는 빈 자리 하나만 있고, `main.jsx`가 `App`을 그 자리에 붙인다고 배웠어요. 이 구조가 SEO에서 어떤 뜻인지 봐요. 03회차의 "페이지 소스 보기 vs 개발자 도구"와 08 SSR-CSR 과정이 이 내용에서 이어져요.

Vite로 만든 React 프로젝트에서 탭 제목과 설명은 **프로젝트 최상위의 `index.html`**에서 고쳐요. `App.jsx`가 아니에요. `index.html`의 `<head>`는 서버가 처음 보내는 HTML에 그대로 들어 있어서, `seo_check.py`처럼 JavaScript를 실행하지 않는 프로그램도 읽을 수 있어요.

본문은 사정이 달라요. 처음 받은 HTML의 `<body>`에는 `<div id="root"></div>`와 `<script>` 줄뿐이에요. 브라우저가 JavaScript를 받아 실행한 **뒤에야** `App.jsx`가 만든 `<h1>`, `<section>`이 `#root` 안에 생겨요. 그래서 3단계에서 정성껏 만든 제목 구조가 처음 HTML에는 없어요. 이렇게 브라우저의 JavaScript가 화면을 만드는 방식을 **CSR**(Client-Side Rendering)이라고 해요.

이게 강의에서 "제목과 설명을 넣는 것만으로 React 사이트의 SEO가 끝나지는 않는다"고 한 이유예요. JavaScript를 실행해야 본문이 생기는 페이지는, 검색엔진이 그 내용을 어떻게 처리하는지까지 생각해야 해요. 페이지가 여러 개면 페이지마다 제목·설명을 어떻게 줄지도 따로 고민해야 하고요. 이번 회차는 `index.html`의 기본 정보를 정확히 쓰고, 컴포넌트 안의 본문 구조를 의미 있게 만드는 데까지 해요.

### ▶ 직접 해 보기 — `_react연습장`에서 처음 HTML과 실행 뒤 화면 비교하기

`_react연습장`에 새 프로젝트를 만들지 않아요. 기존 연습장에 컴포넌트 하나를 더해요.

1. `_react연습장/index.html`의 `<title>react-practice</title>` 줄을 아래 다섯 줄로 바꿔요. 제목을 바꾸고 바로 밑에 설명을 더하는 거예요. 나머지 줄은 그대로 둬요.

## 마무리: 완성한 `_seo연습장` 페이지가 읽히는 순서

1. 규칙을 따르는 크롤러는 사이트에 오면 먼저 `/robots.txt`를 받아요. 지금은 `Allow: /`라서 모든 경로를 수집해도 돼요 (5단계).
2. 크롤러가 `GET /`을 보내면 Python 서버가 `index.html`을 `200`, `text/html`로 보내요.
3. `<head>`의 `<title>`과 `meta description`을 읽어요. 검색 결과에 쓸 제목과 요약의 **후보**예요. 그대로 나온다는 보장은 없어요 (1·2단계).
4. `<body>`에서 `h1` 하나 → `h2` 두 개 → `h3` 두 개의 구조로 페이지 내용을 파악해요 (3단계).
5. `<img>`의 `alt`로 사진 내용을 알고, `<a>`의 문구와 `href`로 링크를 알아요. `/about.html`은 따라가서 새 페이지로 발견하고, `#learning`은 같은 페이지 안의 위치예요 (4단계).
6. `/admin.html`을 수집하면 `noindex`를 보고 색인에서 빼 달라는 요청으로 받아들여요. 하지만 사람과 `curl`은 여전히 열 수 있어요. 보호는 로그인으로 해요 (5단계).
7. React 연습장의 페이지는 처음 HTML에 `title`·`description`만 있고, 본문은 JavaScript를 실행해야 생겨요 (6단계). 서버는 `Ctrl + C`로 꺼요.

| 설명을 넣었는데 화면에 안 보임 | 정상. 페이지 소스 보기에서 `description` 검색 (2단계) |

| `h1 개수: 0` (일반 HTML) | 큰 글자를 `<p style>`로 만들었는지 → `<h1>` (3단계) |

| 사진이 깨져 보임 | `profile.png`를 `_seo연습장`에 복사했는지, `curl`로 `200 image/png`가 나오는지 (4단계) |
| `alt: (alt 없음)` | `<img>`에 `alt` 속성 (4단계) |
| `robots.txt`를 만들었는데 크롤러 판단이 안 바뀜 | 파일이 최상위(`/robots.txt`)에 있는지, `Disallow` 철자 (5단계) |
