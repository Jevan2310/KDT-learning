## 정답

- 문제 1: `.tip` 3개 (p "선택자는 세 종류다", h2 "우선순위", p "id는 하나만") / `p` 3개 / `#main-title` / `tip { }`은 **tip이라는 태그**를 찾는다 → 그런 태그가 없어 아무것도 안 바뀐다. 클래스는 `.tip`
- 문제 2:
  - A: navy / 16px — `p` 규칙 두 개는 구체성이 같아서 뒤에 쓴 navy가 이김. 크기는 직접 규칙이 없어 `body`에서 상속
  - B: green / 20px — `.note`(클래스)가 `p`(태그)보다 구체적이라 순서와 상관없이 이김
  - C: black / 16px — `div`에 걸린 규칙이 없어 `body`에서 둘 다 상속
  - D: green / 20px — `.note` 규칙

- 문제 5:
  1. `.intro`(클래스)가 `p`(태그)보다 구체적이라서, **순서와 상관없이** 클래스가 이긴다. "뒤에 쓴 게 이긴다"는 구체성이 **같을 때**(태그끼리, 클래스끼리)만 맞는 말이다
  2. `class`는 **HTML 속성**이다. 태그 안에서 **요소에 이름표**를 붙인다 (`<p class="intro">`). 이름표만으로는 모양이 안 바뀐다. `color`는 **CSS 속성**이다. 규칙의 `{ }` 안에서 **모양(글자색)**을 바꾼다 (`.intro { color: blue; }`). class는 "누구에게", color는 "어떻게"

## 잘한 점
- **선택자 세 종류를 첫 제출부터 정확히 연결**: 코드 작성에서 id·class·태그 선택자 모두 HTML ↔ CSS가 맞았고, `.highlight`가 `p`를 이기는 화면까지 만듦
- **우선순위 함정 통과**: 문제 2 B(뒤에 `p { navy }`가 있어도 클래스가 이김)를 첫 제출에 맞힘, 상속(A·C의 16px)도 정확
- 🔁 **`</link>` 해결**: 버그 찾기에서 첫 제출에 찾고, 직접 쓸 때도 안 씀 (어제 두 번 놓친 것)
- 🔁 **모양 vs 태그 해결**: 버튼처럼 꾸민 이동 링크를 처음부터 `a`로 만듦
- 버그 찾기를 **표로** 쓰고, 2차에는 규칙까지 이유로 씀 (어제보다 큰 변화)
- 모르는 것을 "잘 모르겠어, 설명해줘"라고 바로 물어서 3차에 맞힘
