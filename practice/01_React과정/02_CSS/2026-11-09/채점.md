- 문제 4: 제출한 `index.html`, `style.css` 최종본 (요구사항 모두 채움)
- 문제 5:
  1. `color`는 **CSS 속성**이다. `h1`이 알아듣는 **HTML 속성이 아니라서** 브라우저가 무시한다 (`p`에 `href`를 써도 이동하지 않는 것과 같다). CSS를 태그 안에 직접 쓰려면 HTML의 **`style` 속성** 안에 `속성: 값;` 모양으로 넣어야 한다.
  2. 인라인 `<h1 style="color: blue;">안녕하세요</h1>` / 내부 `<style> h1 { color: blue; } </style>` / 외부 `<link rel="stylesheet" href="style.css">` + `h1 { color: blue; }`
  3. 외부 스타일: 여러 페이지를 CSS 파일 하나로 한 번에 바꿀 수 있고, HTML(내용)과 CSS(모양)가 나뉘어 읽고 고치기 쉽다
- 문제 6:
  1. `a`는 누르면 `href`의 **주소로 이동**한다. `button`은 누르면 지금 페이지에서 **동작을 실행**한다
  2. 장바구니 담기 `button`(담는 동작) / 회사 소개 `a`(다른 페이지로 이동) / 게시글 삭제 `button`(삭제 동작)
  3. 바꾸지 않는다. 이동하는 링크이므로 `a`를 유지하고 버튼 모양은 CSS로 만든다 (강의 방식: 배경색·padding·border-radius — CSS #9)

- **CSS 문법이 첫 제출부터 정확**: 코드 작성에서 콜론·세미콜론·중괄호 실수 0, 버그 찾기에서 CSS 문법 버그 5개(주석, 세미콜론, `=`, 중괄호, 따옴표)를 모두 첫 제출에 고침
- **세 가지 방법과 적용 범위**를 정확히 구분, 외부 스타일을 쓰는 이유(유지보수)를 스스로 설명
- 🔁 **`https://` 누락을 처음으로 힌트 없이 찾음** (HTML 1·2·3회차 모두 힌트 후에 찾던 것)
- 🔁 **label `for` ↔ input `id`** 연결을 첫 제출에 맞힘 (3회차에 틀린 것)
- 🔁 button을 "박스"가 아니라 **동작**으로 설명, 이유도 "하는 일" 기준으로 씀
- 고친 파일을 직접 만들어 브라우저로 확인함 (`버그확인/`, `test.html`)
