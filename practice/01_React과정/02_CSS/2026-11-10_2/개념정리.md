## 1부

### ① 박스 모델 — 모든 요소는 상자다

**무엇인지**
화면에 그려지는 HTML 요소는 모두 **네모난 상자**다. 제목도, 문단도, 링크도 상자다. 이 상자는 안쪽부터 4겹으로 되어 있다.

```text
margin   바깥 여백 — 다른 요소와의 거리 (투명, 배경색이 안 칠해진다)
└ border   테두리 — 상자의 선
  └ padding  안쪽 여백 — 내용과 테두리 사이 (배경색이 칠해진다)
    └ content  내용 — 글자·이미지가 놓이는 곳
```

**왜 필요한지**
"카드 안쪽이 너무 답답해", "문단끼리 너무 붙어 있어"를 고치려면 **어느 겹**을 바꿀지 알아야 한다. 안쪽을 넓히는 것(padding)과 바깥 거리를 넓히는 것(margin)은 다르다.

🖼️ **비유: 벽에 건 액자**
- content = **그림**
- padding = 그림과 액자 틀 사이의 **흰 여백** (액자 안쪽)
- border = **액자 틀**
- margin = 이 액자와 옆 액자 사이의 **벽 간격** (액자 바깥)

**어떻게 쓰는지** — 강의의 카드
```css
.profile-card {
  padding: 32px;
  border: 1px solid #e2e8f0;
  border-radius: 20px;
  background-color: white;
}
```
| 코드 | 뜻 |
|---|---|
| `padding: 32px` | 안쪽 여백 32px (위·아래·왼쪽·오른쪽 모두) |
| `border: 1px solid #e2e8f0` | 테두리. **두께 · 종류 · 색** 순서로 쓴다. `solid`는 실선 |
| `border-radius: 20px` | 모서리를 둥글게 |
| `background-color: white` | 배경색 — content와 **padding까지** 칠해진다 |

**값을 몇 개 쓰느냐에 따라**
- `padding: 32px` → 네 방향 모두 32px
- `padding: 10px 16px` → **위아래** 10px, **좌우** 16px
- 한쪽만: `margin-top: 28px`, `margin-bottom: 8px` (`-top`, `-bottom`을 붙인다)

**화면에서 padding과 margin 구분하기**
- **padding**을 키우면 → 테두리·배경이 함께 **커진다** (상자 안이 넓어짐)
- **margin**을 키우면 → 상자 크기는 그대로, **주변과의 거리**만 멀어진다

**영역 사이 간격** — 강의 예제
```css
section {
  margin-top: 28px;
}

li {
  margin-bottom: 8px;
}
```
→ 영역(section)끼리는 위쪽으로 28px, 목록 항목끼리는 아래쪽으로 8px씩 떨어진다. 모두 **바깥** 거리라서 margin이다.

> 💡 보충: 브라우저는 몇몇 요소에 기본 margin을 준다. `body`에는 8px 정도, `p`·`h1`에는 위아래 여백이 있다. 문단 사이가 저절로 떨어져 보이는 이유다. 수업 예제의 `body { margin: 0; }`은 body의 기본 바깥 여백을 없앤 것이다.

**모서리 둥글게 / 원 만들기**
```css
.profile-image {
  width: 160px;
  height: 160px;
  border-radius: 50%;
}
```
- `border-radius: 20px` → 모서리만 살짝 둥글게
- `border-radius: 50%` → **정사각형**이면 원이 된다 (가로·세로가 다르면 타원)

**흔한 실수**
- 상자 **안쪽**을 넓히고 싶은데 margin을 쓰거나, 반대로 쓴다
- `border: 1px #e2e8f0;`처럼 **종류(solid)를 빠뜨림** → 테두리가 안 보인다
- `padding: 32 px` — 숫자와 단위 띄어 쓰기 (2부 복습 대기열과 같은 실수)

> 💡 보충: 개발자 도구(F12)에서 요소에 마우스를 올리면 margin(주황)·padding(초록)이 색으로 보인다. 오른쪽 `Computed` 탭에는 4겹 상자 그림이 있다.

### ② 크기와 가운데 배치

**너비·높이 — `width`, `height`**
```css
.profile-image {
  width: 160px;
  height: 160px;
}
```
- 이미지 크기는 HTML의 `width="200"` 속성을 **지우고** CSS에서 관리한다. 크기도 "모양"이니까 CSS 담당이다 (HTML은 내용, CSS는 모양).

**최대 너비 — `max-width`**
```css
.profile-card {
  max-width: 560px;
}
```
- "**아무리 넓어도** 560px까지만". 화면이 넓으면 560px에서 멈추고, 화면이 좁으면(휴대폰) 그에 맞춰 줄어든다.
- `width: 560px`로 고정하면 화면이 560px보다 좁을 때 상자가 화면 밖으로 넘친다. 카드처럼 큰 상자에는 `max-width`가 편하다.

**상자를 가운데 놓기 — `margin: 24px auto`**
```css
.profile-card {
  max-width: 560px;
  margin: 24px auto;
}
```
- 값 2개 → **위아래 24px, 좌우 auto**
- `auto` = "남는 공간을 **양쪽에 똑같이** 나눠 가져라" → 상자가 가운데 온다
- **조건**: 상자가 화면보다 **좁아야** 남는 공간이 생긴다. 그래서 `max-width`(또는 `width`)와 **같이** 쓴다. 너비 제한이 없으면 블록 상자는 원래 가로 한 줄을 다 차지하므로 남는 공간이 없어 가운데로 가지 않는다.

| 하고 싶은 것 | 쓰는 것 |
|---|---|
| 상자 **안의 글**을 가운데로 | `text-align: center` (1회차 ⑥) |
| **상자 자체**를 가운데로 | 너비 제한 + `margin` 좌우 `auto` |

**크기 계산을 쉽게 — `box-sizing: border-box`**

기본 상태에서는 `width`가 **content의 너비만** 뜻한다. padding과 border는 그 **바깥에 더해진다.**
```text
width: 300px; padding: 20px; border: 1px;
→ 실제 상자 너비 = 300 + 20 + 20 + 1 + 1 = 342px   (생각보다 커진다)
```
`border-box`로 바꾸면 `width`가 **테두리까지 포함한** 너비가 된다.
```text
box-sizing: border-box; width: 300px; padding: 20px; border: 1px;
→ 실제 상자 너비 = 300px   (안쪽 content가 258px로 줄어든다)
```
그래서 CSS **맨 위**에 모든 요소(`*`)에 적용해 둔다.
```css
* {
  box-sizing: border-box;
}
```
"내가 쓴 width = 화면에 보이는 상자 크기"가 되어 예측하기 쉬워진다.

> 💡 보충: 기본값의 이름은 `content-box`다.

**흔한 실수**
- `margin: 0 auto`를 줬는데 가운데로 안 감 → 너비 제한(`max-width`)이 없다
- 상자를 가운데로 옮기려고 `text-align: center`를 씀 → 안의 글만 가운데로 간다
- `box-sizing` 없이 `width` + `padding`을 써서 상자가 예상보다 커짐

### ③ display — 표시 방식 바꾸기

**무엇인지**
요소가 화면에 **어떤 방식으로 놓일지** 정하는 속성이다. 🔗 HTML 2회차에서 `div`는 블록(새 줄), `span`은 인라인(문장 안)이라고 배웠다. 그건 **기본값**이고, CSS `display`로 바꿀 수 있다.

| 기본이 블록 | 기본이 인라인 |
|---|---|
| `div`, `p`, `h1`~`h6`, `ul`, `li`, `section` | `span`, `a`, `strong` |

**값 4가지**

| 값 | 놓이는 방식 | width·height | 예 |
|---|---|---|---|
| `block` | **새 줄**에 놓이고, 가로 한 줄을 다 차지 | 적용됨 | 카드, 영역 |
| `inline` | **문장 흐름 안**에 놓이고, 내용만큼만 차지 | **적용 안 됨** | 문장 속 링크, 강조 |
| `inline-block` | 문장 흐름 안(옆으로 나란히) **+** 크기·여백이 제대로 | 적용됨 | 버튼처럼 꾸민 링크 |
| `none` | 화면에서 **사라짐**, 자리도 차지하지 않음 | — | 숨기기 |

**화면 — 수업 예제**
```css
div {
  background-color: yellow;
}

a {
  background-color: pink;
}
```
→ 블록인 `div`는 노란 배경이 **줄 전체**로 칠해지고, 인라인인 `a`는 분홍 배경이 **글자 있는 부분만** 칠해진다.

**바꿔 보기**
```css
span {
  display: block;
}
```
→ 모든 `span`이 블록처럼 **새 줄**에 놓인다.

**왜 필요한지 — 인라인의 한계**
- 인라인 요소에는 `width`, `height`를 줘도 **바뀌지 않는다.**
- 위아래 `padding`을 주면 배경은 커지지만, **줄 간격을 밀어내지 않아서** 위아래 글과 겹칠 수 있다. (어제 2부 문제 4에서 `a`에 `padding: 10px`를 준 경우)
- 그래서 링크(`a`, 인라인)를 버튼처럼 만들 때는 `display: inline-block`으로 바꾼다. 옆 글과 나란히 놓이면서 padding이 제대로 자리를 차지한다 (2부 ④에서 자세히).

> 💡 보충: `img`는 인라인이지만 예외로 `width`·`height`가 적용된다 (이미지는 크기를 가진 요소라서). 그래서 `.profile-image`에 width가 먹는다.

**흔한 실수**
- 인라인 요소(`a`, `span`)에 `width`를 줬는데 안 바뀌어서 오타를 찾는다 → `display`부터 확인
- `display: none`은 "투명하게"가 아니라 **아예 없는 것처럼** 자리까지 사라진다
- 모양 때문에 태그를 바꾸려 한다 (`a` → `div`) → 태그는 그대로 두고 `display`로 바꾼다 (🔁 모양 vs 태그)

### 🔁 복습 포인트 (복습 대기열)

- **HTML 속성 vs CSS 속성** (CSS #2): `class`는 HTML 속성 — 태그 안, `class="card"`(`=`). `padding`, `margin`은 CSS 속성 — `{ }` 안, `padding: 32px;`(`:`).
- **속성 값 버그** (CSS #5): 숫자와 단위는 붙여 쓴다 (`32px`), 색상 코드는 `#`, 속성 이름 철자 (`pading`, `boder` → 조용히 무시된다). 의도와 코드를 한 줄씩 대조.
- **"왜"까지** (공통): "무엇이 틀렸다" → "그래서 화면이 어떻게 되는지"까지 한 문장.
- **마무리 확인** (공통): 요구사항 한 줄씩 대조, 파일 이름·철자, 버그 개수 세기.
