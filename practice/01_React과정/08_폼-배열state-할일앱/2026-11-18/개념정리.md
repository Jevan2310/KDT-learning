## ① 입력창을 state와 연결 — 제어 컴포넌트

**무엇**: 입력창에 쓴 글자를 state에 담아요. 그래야 그 글자를 미리보기나 제출에 쓸 수 있어요.

```jsx
<input
  value={title}                                       // 입력창에 보일 값 = state
  onChange={(event) => setTitle(event.target.value)}  // 글자가 바뀔 때마다 state 갱신
/>
```
- `event.target.value`는 지금 입력창에 들어 있는 글자예요. `event`는 `e`로 줄여 써도 돼요.
- `<label htmlFor="이름">`의 `htmlFor`는 HTML의 `for`예요. JSX에서 `class` 대신 `className`을 쓰는 것과 같은 이유로 이름이 달라요. 입력창 `id`와 맞추면 이름표를 눌러도 입력창이 선택돼요.
- 흐름: 키 입력 → `onChange` → `setTitle` → 다시 그림 → 입력창과 미리보기에 새 글자

> 💬 **쉽게 말하면** — 이렇게 연결하면 입력창은 **state를 비추는 화면**이 돼요. 키보드를 누르면 React가 `onChange`로 "이 글자로 바꾸고 싶대요"라고 알려 줘요. 내가 `setTitle`로 state를 바꿔야 화면에 글자가 나타나요. `value`만 달고 `onChange`를 빼면 state가 그대로라서, 아무리 쳐도 글자가 안 써져요.

### ▶ 붙여 넣어 보기 — `src/components/InputDemo.jsx`
```jsx
import { useState } from "react";

function InputDemo() {
  const [name, setName] = useState("");

  return (
    <section>
      <h2>① 입력창과 state 연결</h2>

      <label htmlFor="demo-name">이름 </label>
      <input
        id="demo-name"
        type="text"
        placeholder="아무거나 입력해 보세요"
        value={name}
        onChange={(event) => setName(event.target.value)}
      />

      <p>미리보기: {name}</p>
      <p>글자 수: {name.length}자</p>
      {name === "" ? <p>아직 비어 있어요</p> : <p>안녕하세요, {name}님!</p>}

      <button type="button" onClick={() => setName("")}>지우기</button>
      <button type="button" onClick={() => setName("한코딩")}>"한코딩" 넣기</button>

      <hr />
      <label htmlFor="demo-locked">onChange 없는 입력창 </label>
      <input id="demo-locked" type="text" value="여기는 안 써져요" />
    </section>
  );
}

export default InputDemo;
```
**해 볼 것**
- 글자를 치면 미리보기, 글자 수, 인사말이 **한 글자마다 같이** 바뀌어요. state가 바뀔 때마다 다시 그리기 때문이에요.
- "이름" 글자를 눌러 보세요. 입력창에 커서가 가요 (`htmlFor` = `id`).
- "한코딩" 넣기 버튼을 누르면 **입력창 글자도** 바뀌어요. state → 입력창 방향이에요. `value`가 연결돼 있어서 돼요.
- 맨 아래 입력창에는 글자가 안 써져요. Console에 `You provided a value prop to a form field without an onChange handler` 경고가 떠요.

- ⚠️ `value`만 쓰고 `onChange`를 빼면 입력이 안 돼요.
- 팀 프로젝트: 로그인, 회원가입, 검색창, 글쓰기 입력창이 전부 이 모양이에요.

## ② 폼 제출 — `onSubmit` + `preventDefault()`

**무엇**: 입력을 "제출"하는 단위가 `form`이에요. **버튼 클릭과 Enter** 둘 다 제출로 처리돼요.

```jsx
function handleSubmit(event) {
  event.preventDefault();            // 새로고침 막기
  const trimmed = text.trim();       // 양끝 공백 제거
  if (trimmed === "") return;        // 비었으면 여기서 끝
  // … 처리
  setText("");                       // 입력창 비우기
}

<form onSubmit={handleSubmit}> … <button type="submit">보내기</button></form>
```
- `onSubmit`은 버튼이 아니라 **`form`에** 달아요. 그래야 Enter도 같이 잡혀요.
- 브라우저는 폼을 제출하면 원래 **페이지를 새로 불러와요**. 그러면 state가 다 날아가요. `preventDefault()`는 "원래 하던 동작은 하지 마"라는 뜻이에요.
- `trim()`은 파이썬의 `strip()`과 같아요. 공백만 친 입력도 이걸로 막아요.
- 폼 안의 버튼은 `type`을 꼭 적어요. 제출 버튼은 `"submit"`, 다른 일을 하는 버튼은 `"button"`이에요. 안 적으면 `submit`으로 취급돼요.

> 💬 **쉽게 말하면** — 폼 제출은 원래 "편지를 부치고 다른 페이지로 넘어가는" 동작이에요. React에서는 편지를 내가 직접 처리할 거라서, 먼저 "부치지 마"(`preventDefault`)라고 말하고 내용을 꺼내 써요.

### ▶ 붙여 넣어 보기 — `src/components/SubmitDemo.jsx`
```jsx
import { useState } from "react";

function SubmitDemo() {
  const [message, setMessage] = useState("");
  const [result, setResult] = useState("아직 제출 안 함");

  function handleSubmit(event) {
    event.preventDefault();

    const trimmedMessage = message.trim();
    if (trimmedMessage === "") {
      setResult("⚠️ 빈 내용은 보낼 수 없어요");
      return;
    }

    setResult("보낸 메시지: " + trimmedMessage);
    setMessage("");
  }

  return (
    <section>
      <h2>② 폼 제출</h2>

      <form onSubmit={handleSubmit}>
        <label htmlFor="demo-message">한 줄 메시지 </label>
        <input
          id="demo-message"
          type="text"
          value={message}
          onChange={(event) => setMessage(event.target.value)}
        />
        <button type="submit">보내기</button>
        <button type="button" onClick={() => setMessage("")}>지우기</button>
      </form>

      <p>{result}</p>
    </section>
  );
}

export default SubmitDemo;
```
**해 볼 것**
- "보내기" 버튼과 **Enter** 둘 다 제출되는지 보세요.
- 스페이스만 치고 보내기 → ⚠️ 문구가 나와요. `  안녕  `처럼 앞뒤에 공백을 넣고 보내면 → "보낸 메시지: 안녕" (공백 제거), 입력창은 비워져요.
- "지우기"는 입력창만 비워요. 제출은 안 돼요 (`type="button"`).
- **바꿔 보기 1**: `event.preventDefault();` 앞에 `//`를 붙이고 저장한 뒤 보내기 → 페이지가 새로고침되고 주소 끝에 `?`가 붙어요. 결과 문구는 "아직 제출 안 함"으로 돌아가요. 확인한 뒤 `//`를 지워 되돌리세요.
- **바꿔 보기 2**: "지우기" 버튼의 `type="button"`을 지우고, 글자를 쓴 뒤 "지우기"를 눌러 보세요. 지우려고 눌렀는데 **메시지가 보내져요**. 되돌리세요.

- ⚠️ `preventDefault()`를 빼면 처리하자마자 새로고침돼서 결과가 사라져요.
- 팀 프로젝트: 로그인 버튼, 글 등록, 댓글 등록이 다 `form` + `onSubmit`이에요.

## ③ 배열 state 바꾸기 — 고치지 말고 새로 만들기

**왜**: React는 배열 속을 하나하나 비교하지 않고 **"새 배열인가?"**로 바뀐 걸 알아채요. `tasks.push(…)`나 `task.completed = true`처럼 원본을 고치면 React가 몰라서 화면이 안 바뀌어요.

> 💬 **쉽게 말하면** — React는 공책 내용을 한 줄씩 읽어 보지 않고 **"공책이 새 것인가"**만 봐요. 같은 공책에 몰래 한 줄 덧써도(`push`) 못 알아채요. 그래서 내용을 옮겨 적고 바꿀 곳만 바꾼 **새 공책**을 건네요.

| 하고 싶은 것 | React 코드 | 파이썬으로 치면 |
|---|---|---|
| 추가 | `setItems((prev) => [...prev, newItem])` | `prev + [new_item]` |
| 삭제 | `setItems((prev) => prev.filter((item) => item.id !== itemId))` | `[i for i in prev if i["id"] != item_id]` |
| 하나 수정 | `setItems((prev) => prev.map((item) => item.id === itemId ? { ...item, liked: !item.liked } : item))` | `[{**i, "liked": not i["liked"]} if i["id"] == item_id else i for i in prev]` |

- `...`는 **펼치기**예요. `[...prev, newItem]`은 기존 항목을 늘어놓고 새 항목을 붙인 새 배열이에요.
- `{ ...item, liked: true }`는 기존 속성을 복사한 다음 **뒤에 쓴 값으로 덮어쓴** 새 객체예요. 파이썬의 `{**i, "liked": True}`와 같아요.
- 새 항목의 `id`는 `crypto.randomUUID()`로 만들어요. 겹치지 않는 문자열을 만들어 줘요 (파이썬 `uuid.uuid4()`). 항목을 **만들 때 한 번만** 불러요.
- 삭제는 "지울 것 **빼고** 남기기"라서 `!==`예요.
- 버튼에서 id를 넘길 때는 화살표 함수로 감싸요: `onClick={() => handleDelete(item.id)}` (07 1부).

### ▶ 붙여 넣어 보기 — `src/components/ArrayDemo.jsx`
```jsx
import { useState } from "react";

function ArrayDemo() {
  const [snacks, setSnacks] = useState([
    { id: "snack-1", name: "초코칩", liked: false },
    { id: "snack-2", name: "감자칩", liked: true },
  ]);

  // 추가: 기존 항목을 펼치고 새 항목을 붙인 새 배열
  function handleAdd() {
    const newSnack = {
      id: crypto.randomUUID(),
      name: "새 과자 " + (snacks.length + 1),
      liked: false,
    };
    setSnacks((prevSnacks) => [...prevSnacks, newSnack]);
  }

  // 삭제: 그 id만 빼고 남긴 새 배열
  function handleDelete(snackId) {
    setSnacks((prevSnacks) =>
      prevSnacks.filter((snack) => snack.id !== snackId)
    );
  }

  // 수정: 그 id만 새 객체로 바꾼 새 배열
  function handleLike(snackId) {
    setSnacks((prevSnacks) =>
      prevSnacks.map((snack) => {
        if (snack.id === snackId) {
          return { ...snack, liked: !snack.liked };
        }
        return snack;
      })
    );
  }

  // 틀린 방법: 원본 배열을 직접 고침
  function handleWrongAdd() {
    snacks.push({ id: crypto.randomUUID(), name: "push로 넣은 과자", liked: false });
    setSnacks(snacks);
    console.log("push 후 배열:", snacks);
  }

  const likedCount = snacks.filter((snack) => snack.liked).length;

  return (
    <section>
      <h2>③ 배열 state 바꾸기</h2>
      <p>전체 {snacks.length}개 · 좋아요 {likedCount}개</p>

      <button type="button" onClick={handleAdd}>과자 추가</button>
      <button type="button" onClick={handleWrongAdd}>push로 추가 (틀린 방법)</button>

      {snacks.length === 0 ? (
        <p>과자가 하나도 없어요.</p>
      ) : (
        <ul>
          {snacks.map((snack) => (
            <li key={snack.id}>
              {snack.liked ? "❤️" : "🤍"} {snack.name}{" "}
              <button type="button" onClick={() => handleLike(snack.id)}>좋아요</button>
              <button type="button" onClick={() => handleDelete(snack.id)}>삭제</button>
            </li>
          ))}
        </ul>
      )}
    </section>
  );
}

export default ArrayDemo;
```
**해 볼 것**
- "과자 추가" → 끝에 새 과자가 붙고 전체 개수가 늘어요.
- "좋아요" → **그 과자만** ❤️/🤍가 바뀌고, 좋아요 개수도 따라 바뀌어요.
- "삭제" → 그 과자만 사라져요. 다 지우면 "과자가 하나도 없어요."가 나와요.
- **틀린 방법 확인**: 새로고침한 뒤 "push로 추가"를 **한 번** 눌러 보세요. 화면은 그대로인데 Console에는 배열에 3개가 들었다고 찍혀요. 원본은 바뀌었는데 React가 모르는 거예요. 이어서 아무 과자의 "좋아요"를 누르면, 숨어 있던 "push로 넣은 과자"가 **갑자기** 나타나요. 화면과 데이터가 어긋나는 버그예요.
- **바꿔 보기 1**: 삭제의 `!==`를 `===`로 바꾸고 삭제를 눌러 보세요. 누른 과자**만** 남아요.
- **바꿔 보기 2**: `return snack;` 앞에 `//`를 붙이고 "좋아요"를 눌러 보세요. 나머지 항목이 `undefined`가 돼서 **화면이 하얘지고**, Console에 `Cannot read properties of undefined (reading 'liked')`가 떠요. 확인한 뒤 되돌리고 새로고침하세요.

- 팀 프로젝트: 댓글·장바구니 추가(펼침), 삭제(`filter`), 좋아요·완료·수량 변경(`map` + 객체 펼침)이 모두 이 패턴이에요.

## ④ 계산과 저장 + 전부 합친 할 일 앱

```jsx
const remainingCount = tasks.filter((task) => !task.completed).length;
```
- 남은 개수는 `tasks`로 계산할 수 있으니 **state로 만들지 않아요** (07 ⑨ 파생 데이터). ③의 좋아요 개수도 같은 방식이었어요.
- "할 일이 없음"(`tasks.length === 0`)과 "모두 완료"(`remainingCount === 0`)는 다른 조건이에요. 안내 문구를 따로 써요.
- 체크박스는 `value`가 아니라 **`checked`**로 연결해요: `checked={task.completed}` + `onChange`.

**새로고침하면 왜 사라지나**: state는 페이지가 열려 있는 동안만 있는 값이에요. 페이지를 새로 열면 초기값부터 다시 시작해요.

| 저장 위치 | 언제 쓰나 |
|---|---|
| React state | 지금 보고 있는 화면 |
| 브라우저 저장소 (`localStorage`) | 같은 브라우저에서 새로고침해도 남기기 |
| 서버·데이터베이스 | 다른 사람·다른 기기와 공유 (팀 프로젝트의 백엔드) |

> 💬 **쉽게 말하면** — 지난번 비유로 하면 state는 요리사의 **메모장**이에요. 가게 문을 닫았다 열면 새 메모장으로 바뀌어요. 오래 남기려면 가게 금고(`localStorage`)나 본사 창고(서버 DB)에 넣어야 해요. 본사 창고와 연결하는 방법은 Node·Spring 과정에서 배워요.

### ▶ 붙여 넣어 보기 — `src/components/TaskApp.jsx` (강의 최종 코드)
```jsx
import { useState } from "react";

function TaskApp() {
  const [title, setTitle] = useState("");
  const [tasks, setTasks] = useState([
    { id: "task-1", title: "HTML 복습하기", completed: true },
    { id: "task-2", title: "React 입력 폼 만들기", completed: false },
  ]);

  function handleSubmit(event) {
    event.preventDefault();

    const trimmedTitle = title.trim();
    if (trimmedTitle === "") {
      return;
    }

    const newTask = {
      id: crypto.randomUUID(),
      title: trimmedTitle,
      completed: false,
    };

    setTasks((prevTasks) => [...prevTasks, newTask]);
    setTitle("");
  }

  function handleDelete(taskId) {
    setTasks((prevTasks) => prevTasks.filter((task) => task.id !== taskId));
  }

  function handleToggle(taskId) {
    setTasks((prevTasks) =>
      prevTasks.map((task) => {
        if (task.id === taskId) {
          return { ...task, completed: !task.completed };
        }
        return task;
      })
    );
  }

  const remainingCount = tasks.filter((task) => !task.completed).length;

  return (
    <section>
      <h2>④ 할 일 앱 (전부 합친 것)</h2>

      <form onSubmit={handleSubmit}>
        <label htmlFor="task-title">새로운 할 일 </label>
        <input
          id="task-title"
          type="text"
          placeholder="예: React 복습하기"
          value={title}
          onChange={(event) => setTitle(event.target.value)}
        />
        <button type="submit">추가</button>
      </form>

      <p>전체 {tasks.length}개 · 남은 할 일 {remainingCount}개</p>

      {tasks.length === 0 ? (
        <p>등록된 할 일이 없습니다. 첫 번째 목표를 추가해 보세요.</p>
      ) : (
        <ul>
          {tasks.map((task) => (
            <li key={task.id}>
              <label>
                <input
                  type="checkbox"
                  checked={task.completed}
                  onChange={() => handleToggle(task.id)}
                />
                {task.completed ? <s>{task.title}</s> : task.title}
              </label>{" "}
              <button type="button" onClick={() => handleDelete(task.id)}>삭제</button>
            </li>
          ))}
        </ul>
      )}

      {tasks.length > 0 && remainingCount === 0 && (
        <p>모든 학습 목표를 완료했습니다! 🎉</p>
      )}
    </section>
  );
}

export default TaskApp;
```
강의 코드와 다른 점은 하나예요. 강의는 CSS 클래스(`completed`)로 완료 항목에 줄을 그었는데, 여기서는 CSS 없이 붙여 넣기만 해도 보이게 `<s>` 태그(취소선)를 썼어요. 강의 CSS는 wiki 08 "최종 코드"에 있어요.

**해 볼 것**
- 할 일을 버튼과 Enter로 각각 추가해 보세요. 공백만 치면 추가가 안 되고, 추가한 뒤에는 입력창이 비워져요.
- 체크박스를 누르거나 **할 일 글자**를 눌러 보세요. 둘 다 완료가 바뀌어요. `label`이 체크박스와 글자를 같이 감싸고 있어서예요. 줄이 그어지고 남은 개수가 바뀌어요.
- 같은 제목을 두 번 추가하고 하나만 삭제해 보세요. `id`가 달라서 하나만 지워져요.
- 전부 체크하면 "모든 학습 목표를 완료했습니다! 🎉", 전부 삭제하면 빈 목록 안내가 나와요. 두 문구는 조건이 달라요.
- **새로고침**해 보세요. 추가한 할 일이 사라지고 처음 2개로 돌아가요. state는 저장되지 않기 때문이에요.

## 팀 프로젝트에서 AI가 짠 코드가 이상할 때 볼 곳

| 증상 | 먼저 볼 곳 |
|---|---|
| 입력창에 글자가 안 써짐 | `value`에 `onChange`가 연결됐나 |
| 제출하면 새로고침됨 | `onSubmit`에서 `preventDefault()` 했나 |
| 다른 버튼을 눌렀는데 제출됨 | 폼 안 버튼에 `type="button"`을 적었나 |
| 추가해도 목록이 그대로 | `push`처럼 원본을 고쳤나 |
| 삭제하면 그 항목만 남음 | `filter` 조건이 `!==`인가 |
| 수정 버튼을 누르면 화면이 하얘짐 | `map`에서 나머지 항목도 `return` 했나 |
| 클릭 전에 삭제가 실행됨 | `onClick={() => …}`로 감쌌나 |
| 체크박스가 안 바뀜 | `checked` + `onChange` 연결 |
| 여러 항목이 같이 바뀜 | `id`가 겹치지 않나 |

## 🔁 이어지는 개념
- **07 ⑥ 함수형 업데이트** — `setTasks((prev) => …)`로 그대로 써요.
- **07 ⑨ 파생 데이터** — 남은 개수를 state로 만들지 않는 이유예요.
- **06 #2 중괄호와 `return`** — 수정용 `map`을 중괄호로 쓰면 `return`이 두 군데 필요해요.

**08 한 줄 정리**
- 입력창은 `value` + `onChange`, 체크박스는 `checked` + `onChange`
- 제출은 `form`의 `onSubmit` + `preventDefault()` + `trim()` 검사
- 배열은 고치지 말고 새로: 추가 `[...prev, new]`, 삭제 `filter(!==)`, 수정 `map` + `{ ...item }`
- 계산되는 값은 state가 아니고, state는 새로고침하면 사라짐
