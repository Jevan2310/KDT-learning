## 1부

### ① React는 왜 쓸까?

JavaScript 2부 ⑨에서 응원 버튼을 만들 때 **두 번** 바꿨다.
```javascript
cheerCount += 1;                                                  // 1. 데이터 바꾸기
cheerMessage.textContent = `응원을 ${cheerCount}번 받았습니다.`;   // 2. 화면 찾아서 바꾸기
```
- 화면이 작을 때는 괜찮다.
- 목록, 입력창, 완료 개수처럼 연결된 곳이 많아지면 "**데이터가 바뀌면 화면 어디어디를 고쳐야 하지?**"를 관리하기 어려워진다.

| | 지금까지 (JavaScript) | React |
|---|---|---|
| 화면 바꾸는 법 | 요소를 **찾아서 직접** 고친다 (`querySelector`, `textContent`) | "데이터가 이러면 화면은 이렇게"를 **써 두면** React가 화면에 반영한다 |
| 화면 나누기 | 한 HTML 파일 | **컴포넌트**(부품)로 나눈다 |

- React는 **화면(UI)을 만드는 JavaScript 라이브러리**다. 새 언어가 아니다 — 지금까지 배운 HTML·CSS·JS를 그대로 쓴다.
- React를 쓴다고 웹사이트가 자동으로 빨라지지는 않는다.
- 데이터를 바꾸면 화면이 따라 바뀌게 하는 **state**는 07회차에서 배운다.

### ② 프로젝트 만들고 실행하기

**쓰는 도구**

| 도구 | 하는 일 |
|---|---|
| Node.js | Vite 같은 개발 도구를 실행하는 환경 |
| npm | 필요한 패키지를 설치하고, 프로젝트 명령(`npm run dev`)을 실행 |
| Vite | 개발 서버를 띄워 주는 도구 (배포용 파일 만들기도 함) |
| React | 화면을 만드는 라이브러리 |

**순서** (VS Code 터미널에서)
```bash
node -v                  # 1. Node.js 설치 확인 (버전이 나오면 OK)
npm create vite@latest   # 2. 프로젝트 만들기 → 이름 my-profile, React, JavaScript 선택
cd my-profile            # 3. 프로젝트 폴더로 이동
npm install              # 4. 패키지 설치 (2번에서 Yes로 설치했으면 생략)
npm run dev              # 5. 개발 서버 실행 → 터미널에 나온 주소를 브라우저로 연다
```
- 주소 예: `http://localhost:5173/` — 숫자(포트)는 바뀔 수 있으니 **터미널에 나온 주소**를 쓴다.
- 서버를 켜 둔 동안 파일을 저장하면 브라우저에 바로 반영된다.
- 끄기: 그 터미널에서 **`Ctrl + C`** / 다시 켜기: 프로젝트 폴더에서 `npm run dev`
- 지금까지처럼 `index.html`을 더블클릭해서 열지 않는다. **개발 서버 주소로** 확인한다.

**흔한 실수**
- `my-profile` 폴더로 들어가지 않고(`cd` 안 함) `npm run dev` → 실행 안 됨 (`package.json`이 있는 폴더에서만 된다)
- 서버가 돌던 터미널을 닫아서 화면이 안 열린다

### ③ 파일 구조 — 꼭 알 것 4개

| 파일 | 역할 |
|---|---|
| `index.html` | `<div id="root"></div>` — React 화면이 들어갈 **빈 자리** 하나 |
| `src/main.jsx` | 시작 코드. `App`을 가져와 `#root` 자리에 붙인다 (건드리지 않음) |
| `src/App.jsx` ★ | **우리가 화면을 쓰는 곳** (`App.css`는 그 스타일) |
| `public/` | 이미지 같은 파일을 두는 곳 → 2부 ⑧ |

흐름: `App.jsx`의 `App` → `main.jsx`가 가져와서 → `index.html`의 `#root`에 넣는다 → 화면에 보인다.

- `node_modules/`는 설치된 패키지 폴더 — 직접 고치지 않는다.
- ⚠️ 예전 `index.html` 전체(`html`, `head`, `body`)를 `App.jsx`에 복사하지 않는다. **본문 내용만** 옮긴다.

### ④ 컴포넌트 — 화면을 그리는 함수

**무엇인지**
화면의 일부를 맡는 **부품**이다. 레고 블록처럼 만들어 두고 조립한다. 모양은 **JSX(화면)를 `return`하는 JavaScript 함수**다.
```jsx
import "./App.css";

function App() {
  return (
    <div>
      <h1>안녕하세요, 한코딩입니다!</h1>
      <p>React로 첫 화면을 만들었습니다.</p>
    </div>
  );
}

export default App;
```

| 코드 | 뜻 | JS에서 배운 것 |
|---|---|---|
| `import "./App.css"` | CSS 파일 불러오기 | (HTML의 `link` 역할) |
| `function App()` | `App` 컴포넌트 만들기 | 함수 선언 (2부 ⑦) |
| `return ( ... )` | 화면에 보일 내용을 돌려준다 | `return` (2부 ⑦) |
| `export default App` | 다른 파일(`main.jsx`)이 가져갈 수 있게 **내보내기** | (새로 배움) |

- 직접 만드는 컴포넌트 이름은 **대문자로 시작**한다 (`App`, `ProfileCard`).
- 수업에서는 화살표 함수로도 썼다 (2부 ⑩): `const App = () => { return ( ... ); };`

**흔한 실수**
- `export default App`을 빼먹는다 → `main.jsx`가 가져가지 못해 오류
- 이름을 소문자로 시작한다 (`app`)

### ⑤ JSX — HTML과 다른 4가지

**JSX**는 JavaScript 안에서 HTML처럼 화면을 쓰는 문법이다. 거의 HTML과 같지만 4가지가 다르다.

| 규칙 | HTML | JSX |
|---|---|---|
| ① 하나로 묶기 | 여러 요소를 나란히 써도 됨 | `return`은 **부모 하나**로 감싼다 (`<div>` 또는 `<>...</>`) |
| ② 모든 태그 닫기 | `<img>`, `<br>`, `<input>` | `<img ... />`, `<br />`, `<input />` |
| ③ 클래스 | `class="card"` | **`className`**`="card"` |
| ④ 주석 | `<!-- 주석 -->` | `{/* 주석 */}` |

**① 하나로 묶기**
```jsx
// ❌ 나란히 두 개 → 오류
return (
  <h1>한코딩</h1>
  <p>반갑습니다!</p>
);

// ⭕ 부모 하나로 감싸기
return (
  <div>
    <h1>한코딩</h1>
    <p>반갑습니다!</p>
  </div>
);
```
`div`를 하나 더 만들고 싶지 않으면 **Fragment** `<>...</>`로 감싼다 (화면에 요소가 추가되지 않는다).

**③ `className`** — CSS 파일은 그대로 `.card { ... }`로 쓰고, JSX에서만 `className`으로 붙인다.

**흔한 실수**
- HTML 습관대로 `class`를 쓴다
- `<img>`, `<br>`를 닫지 않아 JSX 오류가 난다

### 1부 한 줄 정리
- React는 "데이터에 따른 화면"을 써 두는 **화면 라이브러리** — 요소를 직접 찾아 고치지 않는다
- `npm run dev`로 개발 서버를 켜고, **터미널에 나온 주소**로 확인, 끄기는 `Ctrl + C`
- 화면은 `src/App.jsx`에 쓴다. 컴포넌트 = **JSX를 `return`하는 함수** + `export default`
- JSX는 **하나로 묶기, 모두 닫기, `className`, `{/* */}`**

## 2부

### ⑥ `{}`로 JavaScript 값 표시하기

**무엇인지**
JSX 안에서 변수 값을 보여 주려면 **중괄호 `{}`**로 감싼다. 변수는 컴포넌트 함수 안, `return` 위에 만든다.
```jsx
function App() {
  const userName = "한코딩";
  const goalCount = 3;

  return (
    <div>
      <h1>안녕하세요, {userName}입니다!</h1>
      <p>학습 목표는 {goalCount}개입니다.</p>
      <p>하나 더하면 {goalCount + 1}개입니다.</p>
    </div>
  );
}
```
→ 화면: "안녕하세요, 한코딩입니다!" / "학습 목표는 3개입니다." / "하나 더하면 4개입니다."

| 작성 | 화면 |
|---|---|
| `<p>userName</p>` | userName (글자 그대로) |
| `<p>{userName}</p>` | 한코딩 (변수 값) |

> 💡 보충: JS의 템플릿 리터럴 `` `${userName}님` ``과 비슷하다. JSX에서는 `$` 없이 `{}`만 쓴다.

- `{}` 안에는 **값이 되는 것**만 넣는다: 변수, 계산(`goalCount + 1`), 객체 속성(`profile.name`)
- `if`문이나 `const` 선언은 `{}` 안에 넣지 않는다

**흔한 실수**
- `{}`를 빼서 변수 이름이 글자 그대로 나온다
- JS 습관대로 `${userName}`이라고 써서 화면에 `$`가 같이 나온다

### ⑦ 객체 값 표시와 속성에 변수 넣기

**객체 값 표시** — 관련 정보는 객체로 묶고 `{객체.이름}`으로 꺼낸다 (JS 2부 ⑩).
```jsx
const profile = {
  name: "한코딩",
  introduction: "직접 사용하는 서비스를 만들고 싶습니다.",
  imageUrl: "/profile.png"
};
```
```jsx
<h1>{profile.name}</h1>
<p>{profile.introduction}</p>
```

**태그 속성에 변수 넣기** — `src`, `alt`, `href` 같은 태그 속성 값에 변수를 쓸 때는 **따옴표 대신 `{}`**
```jsx
<img src={profile.imageUrl} alt={`${profile.name}의 프로필 이미지`} />
```

| 작성 | 뜻 |
|---|---|
| `src="/profile.png"` | 따옴표 → 이 **글자 그대로** 경로로 씀 ⭕ |
| `src={profile.imageUrl}` | 중괄호 → **변수에 담긴 값**(`/profile.png`)을 씀 ⭕ |
| `src="profile.imageUrl"` | ❌ `profile.imageUrl`이라는 **글자**를 경로로 씀 → 이미지가 안 나온다 |

- 글자와 변수를 섞을 때(`alt`)는 `{}` 안에 **템플릿 리터럴**(백틱 + `${}`)을 쓴다.
- 용어 구분: `profile.name`의 name은 **객체의 속성**, `src`·`alt`는 **태그의 속성**이다.

---

### ⑧ public 이미지 경로

이미지 파일을 프로젝트의 **`public/` 폴더**에 넣으면 **`/파일이름`**으로 쓴다.
```text
_react연습장/
└─ public/
   └─ profile.png     →  <img src="/profile.png" alt="…" />
```
- 경로에 `public`은 **쓰지 않는다**: `/public/profile.png` ❌ → `/profile.png` ⭕
- `img`는 JSX라서 꼭 닫는다 (`/>`, 1부 ⑤)

**흔한 실수**
- 이미지를 `src/`나 다른 폴더에 넣고 `/profile.png`로 부른다 → 안 보인다
- 파일 이름 철자·확장자(`.png` / `.jpg`)가 다르다

---

### ⑨ 기존 `script.js`는 옮기지 않는다

JS 때처럼 요소를 직접 찾아 고치는 코드는 **React 화면에 붙이지 않는다.**
```javascript
const introMessage = document.querySelector("#intro-message");
introMessage.textContent = "새로운 소개입니다.";   // ← React에서는 이렇게 안 한다
```
- React가 화면을 관리하고 있는데 옆에서 직접 고치면 **충돌**할 수 있다.
- **일반 변수를 바꿔도 React 화면은 자동으로 바뀌지 않는다.** (JS 2부 ⑨와 같은 문제)
- 버튼을 눌러 화면을 바꾸는 방법은 **이벤트와 state**로 07회차에서 배운다.

지금 단계의 흐름: **데이터 작성 → JSX에서 `{}`로 사용 → React가 화면에 표시**

---

### 2부 한 줄 정리
- JSX에서 값 보여 주기는 **`{}`** (`$` 없이), 안에는 값이 되는 것만
- 객체는 `{profile.name}`, 태그 속성에 변수는 **따옴표 대신 `{}`**
- `public/profile.png` → **`/profile.png`**
- `querySelector`로 직접 고치지 않는다 — 화면 변경은 07회차 state
