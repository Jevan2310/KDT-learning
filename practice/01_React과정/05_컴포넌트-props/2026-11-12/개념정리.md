## 1부

### ① 왜 컴포넌트로 나눌까?

프로필 카드를 3개 보여 주려고 카드 코드를 **3번 복사**하면, 카드 모양을 바꿀 때 **3군데를 모두** 고쳐야 한다.
카드를 **컴포넌트 하나**로 만들어 두면 **한 곳만** 고치면 되고, 여러 번 가져다 쓸 수 있다.

| 구분 | 역할 | 붕어빵으로 보면 |
|---|---|---|
| 컴포넌트 | 반복해서 쓸 **화면 구조** | 붕어빵 **틀** |
| props | 컴포넌트마다 넣을 **데이터** | 안에 넣는 **팥, 슈크림** |

틀(구조)은 같고 속(이름, 소개)만 다르게 — 이것이 05회차의 핵심이다.

---

### ② 컴포넌트 정의와 사용

```jsx
// 정의 — App 바깥에, 이름은 대문자로
function ProfileCard() {
  return (
    <div className="card">
      <h2>한코딩</h2>
      <p>프론트엔드를 공부합니다.</p>
    </div>
  );
}

function App() {
  return (
    <div>
      <ProfileCard />    {/* 사용 — 태그처럼 쓴다 */}
      <ProfileCard />
    </div>
  );
}

export default App;
```
→ 화면에 같은 카드가 **2개** 나온다. `ProfileCard` 안의 문장을 바꾸면 **두 카드 모두** 바뀐다.

| 작성 | 뜻 |
|---|---|
| `<main>`, `<div>` (소문자) | HTML 요소 |
| `<ProfileCard />` (대문자) | 내가 만든 컴포넌트 |

- 컴포넌트는 `App` 함수 **바깥**에, `App`과 나란히 정의한다. (`App` 안에 넣지 않는다)
- 정의 모양은 `function ProfileCard()`와 `const ProfileCard = () =>` 둘 다 된다 (04회차와 같음).

**흔한 실수**
- 소문자로 쓴다 (`<profileCard />`) → HTML 태그로 여겨서 카드가 안 나온다
- `App` 함수 안에 컴포넌트를 정의한다

---

### ③ 파일 분리 — `export` / `import`

컴포넌트가 많아지면 파일로 나눈다. `src` 안에 `components` 폴더를 만들어 모은다.
```text
src/
├─ components/
│  └─ ProfileCard.jsx   ← 컴포넌트 파일 (내보내기)
├─ App.jsx              ← 가져와서 사용
└─ App.css
```

`src/components/ProfileCard.jsx` — **내보내기**
```jsx
function ProfileCard() {
  return (
    <div className="card">
      <h2>한코딩</h2>
    </div>
  );
}

export default ProfileCard;
```

`src/App.jsx` — **가져오기**
```jsx
import "./App.css";
import ProfileCard from "./components/ProfileCard.jsx";

function App() {
  return <ProfileCard />;
}

export default App;
```

| 코드 | 뜻 |
|---|---|
| `export default ProfileCard` | 이 파일에서 `ProfileCard`를 **내보낸다** |
| `import ProfileCard from "…"` | 다른 파일에서 내보낸 것을 **가져온다** |
| `./` | 지금 파일(`App.jsx`)이 있는 폴더(`src`) 기준 |

- 04회차의 `App.jsx`의 `export default App` ↔ `main.jsx`의 `import App from './App.jsx'`와 **같은 짝**이다.
- 파일로 옮긴 뒤에는 `App.jsx`에 있던 `ProfileCard` 함수를 **지운다** (같은 이름을 두 번 만들면 오류).
- CSS는 `App.jsx`에서 불러오고 있으면 `ProfileCard`에도 그대로 적용된다.

**흔한 실수**
- `export default`를 빼먹는다
- 경로 철자가 다르다 (`./component/…`, `profileCard.jsx` — 폴더·파일 이름과 대소문자까지 같아야 한다)

### ④ props — 부모가 자식에게 건네는 값

같은 틀에 **다른 내용**을 넣고 싶을 때 props를 쓴다.

부모(`App`) — **태그 속성처럼** 값을 건넨다
```jsx
<ProfileCard name="한코딩" />
<ProfileCard name="파이썬" />
```

자식(`ProfileCard`) — **`props` 객체**로 받아서 읽는다
```jsx
function ProfileCard(props) {
  return (
    <div className="card">
      <h2>{props.name}</h2>
    </div>
  );
}
```
→ 카드 2개: "한코딩", "파이썬"

- `props`는 객체다: `{ name: "한코딩" }` → `props.name`으로 꺼낸다 (JS 2부 ⑩, 04회차 ⑦).
- JS 함수의 매개변수와 같은 원리다: `greet("한코딩")` ↔ `<ProfileCard name="한코딩" />`
- 흐름: **App → props 전달 → ProfileCard에서 읽기 → 화면 표시**
- 각 카드는 **자기에게 온 props만** 읽는다. 두 번째 카드의 `name`을 바꿔도 첫 번째는 그대로다.

**흔한 실수**
- `{}` 없이 `<h2>props.name</h2>` → 글자 그대로 나온다
- 보내는 이름과 받는 이름이 다르다 (`name="한코딩"`으로 보내고 `props.userName`으로 읽음 → 값이 없어서 빈칸)

---

### 1부 한 줄 정리
- 컴포넌트 = **틀**(구조), props = **속**(데이터) → 같은 틀, 다른 내용
- 정의는 `App` **바깥**에 **대문자**로, 사용은 `<ProfileCard />`
- 파일로 나누면 `export default` ↔ `import … from "./components/…"`
- 부모는 `<ProfileCard name="한코딩" />`로 건네고, 자식은 `{props.name}`으로 읽는다

## 2부

### ⑤ 문자열 vs JavaScript 값 전달

props를 보낼 때도 04회차 ⑧과 같은 규칙이다: **따옴표는 글자 그대로, 중괄호는 JavaScript 값.**

| 보낼 값 | 쓰는 법 | 예시 |
|---|---|---|
| 고정된 글자 | 따옴표 | `name="한코딩"` |
| 변수 | 중괄호 | `name={userName}` |
| 숫자 | 중괄호 | `goalCount={3}` |
| 불리언 (참·거짓) | 중괄호 | `isLearning={true}` |

```jsx
function App() {
  const userName = "한코딩";

  return <ProfileCard name={userName} goalCount={3} />;
}
```

**`"3"`은 문자열, `{3}`은 숫자다.** 계산하면 차이가 보인다 (JS 1부의 `"10" + 5` → `105`와 같은 원리).
```jsx
// ProfileCard 안
<p>다음 목표: {props.goalCount + 1}개</p>
```
| 부모가 보낸 값 | 화면 |
|---|---|
| `goalCount={3}` | 다음 목표: **4**개 |
| `goalCount="3"` | 다음 목표: **31**개 (글자 이어 붙이기) |

**흔한 실수**
- `name="userName"` → 변수 값이 아니라 글자 `userName`이 그대로 나온다
- 숫자를 `"3"`으로 보내고 더한다 → 이어 붙여진다

### ⑥ 구조 분해 할당 — props에서 꺼내 쓰기

- **무엇**: 객체에서 필요한 속성을 **같은 이름의 변수로 꺼내는** 문법
- **왜**: `props.`를 매번 안 써도 되고, 첫 줄만 보면 이 컴포넌트가 어떤 props를 받는지 보인다

먼저 일반 JS 객체로 보면:
```javascript
const profile = { name: "한코딩", intro: "프론트엔드 개발자" };

const { name, intro } = profile;
// 아래 두 줄과 같다
// const name = profile.name;
// const intro = profile.intro;

console.log(name);  // 한코딩
```

컴포넌트에서는 **매개변수 자리**에 바로 쓴다. 1부에서 쓴 `ProfileCard`를 바꾸면:
```jsx
// 전 — props로 받기
function ProfileCard(props) {
  return (
    <div className="card">
      <h2>{props.name}</h2>
      <p>{props.intro}</p>
    </div>
  );
}

// 후 — 구조 분해로 받기
function ProfileCard({ name, intro }) {
  return (
    <div className="card">
      <h2>{name}</h2>
      <p>{intro}</p>
    </div>
  );
}
```
- 두 방식은 **같은 props를 읽는다.** 화면도 같다.
- 부모 쪽 `<ProfileCard name="한코딩" intro="…" />`는 **바꾸지 않는다.**
- `{ }` 안의 이름은 부모가 보낸 props 이름과 같아야 한다.

**흔한 실수**
- `{ }`를 빼고 `function ProfileCard(name)` → `name`에 props 객체 전체가 들어가서 오류
- 구조 분해로 받고 `{props.name}`으로 읽는다 → `props`라는 변수가 없어서 오류
- 꺼내는 이름이 다르다 (`{ title }`로 꺼냈는데 부모는 `name`으로 보냄) → 빈칸

### ⑦ props는 읽기 전용

- **무엇**: 자식 컴포넌트는 받은 props를 **읽기만** 하고 바꾸지 않는다
- **왜**: 값을 정하는 건 보내는 쪽(부모)이다. 자식이 바꾸기 시작하면 값이 어디서 바뀌었는지 찾기 어렵다. 개발 중에는 React가 props를 바꾸지 못하게 막아 두어서 오류가 난다

```jsx
// ❌ 자식이 직접 바꿈
function ProfileCard(props) {
  props.name = "새 이름";
  return <h2>{props.name}</h2>;
}
```
```jsx
// ✅ 보내는 쪽(부모)에서 바꾼다
<ProfileCard name="새 이름" />
```

| 역할 | 담당 |
|---|---|
| 데이터 정하기·보내기 | 부모 (`App`) |
| 받은 값으로 화면 그리기 | 자식 (`ProfileCard`) |

- 버튼 클릭처럼 사용자 동작으로 값을 바꾸는 방법은 07회차 **state**에서 배운다.

---

### ⑧ props 기본값

- **무엇**: 부모가 그 props를 **안 보냈을 때** 대신 쓸 값
- **왜**: 안 보낸 props는 `undefined`라서 화면에 빈칸이 된다 (1부 문제 1의 빈 배지). 기본값을 두면 빈칸 대신 안내 문구가 나온다

구조 분해에서 `= 기본값`을 붙인다.
```jsx
function ProfileCard({ name, intro = "소개를 준비하고 있습니다." }) {
  return (
    <div className="card">
      <h2>{name}</h2>
      <p>{intro}</p>
    </div>
  );
}
```
```jsx
<ProfileCard name="한코딩" intro="프론트엔드 개발자" />  {/* → 프론트엔드 개발자 */}
<ProfileCard name="파이썬" />                          {/* → 소개를 준비하고 있습니다. */}
```

| 부모가 보낸 값 | 화면 |
|---|---|
| 안 보냄 (`undefined`) | **기본값** |
| `intro=""` (빈 글자) | 빈칸 — 기본값 **안 나옴** |
| `intro={null}` | 빈칸 — 기본값 **안 나옴** |

- 기본값은 **값이 없을 때(`undefined`)만** 쓰인다. `""`와 `null`은 "빈 값을 일부러 보냈다"로 본다.

**흔한 실수**
- `intro=""`를 보내 놓고 기본값이 나오길 기대한다

---

### ⑨ 어디까지 컴포넌트로 나눌까?

모든 태그를 컴포넌트로 만들 필요는 없다. 아래 질문에 "예"가 많으면 나눈다.

| 질문 | "예"인 예 |
|---|---|
| 같은 구조를 여러 곳에서 쓰나? | 프로필 카드 3장 |
| 하나의 역할·내용으로 묶이나? | 카드 하나 = 한 사람의 정보 |
| 코드가 길어 읽기 어렵나? | `App` 하나에 수십 줄 |
| 이름만 보고 역할을 알 수 있나? | `ProfileCard` ✅ / `Box1` ❌ |

- 이번 회차는 **카드 단위**로만 나눈다. `<h2>` 하나, `<p>` 하나를 각각 파일로 만들 필요는 없다.

---

### 🔁 복습 포인트 (1부 채점에서)
- **props 용어**: 객체는 `props` 하나이고, `name`·`intro`는 그 안의 **이름(속성)**이다 → `props = { name: "한코딩", intro: "…" }`
- **대문자 이유**: 소문자 `<movieCard />`는 React가 HTML 태그로 본다
- **나누는 이유 두 가지**: 고칠 때 한 곳만 + props로 같은 틀·다른 내용

### 2부 한 줄 정리
- 글자는 `"…"`, 변수·숫자·불리언은 `{…}` — `"3"`은 문자열, `{3}`은 숫자
- `function ProfileCard({ name, intro })`로 꺼내 쓴다. 부모 쪽은 그대로
- props는 읽기만 한다. 바꾸려면 부모가 보내는 값을 바꾼다
- `{ intro = "기본값" }`은 안 보냈을 때(`undefined`)만 쓰인다
- 반복되거나 역할이 분명한 덩어리(카드)만 컴포넌트로 나눈다
