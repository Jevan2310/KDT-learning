## 1부

### ① 왜 컴포넌트로 나눌까?

프로필 카드를 3개 보여 주려고 카드 코드를 **3번 복사**하면, 카드 모양을 바꿀 때 **3군데를 모두** 고쳐야 한다.
카드를 **컴포넌트 하나**로 만들어 두면 **한 곳만** 고치면 되고, 여러 번 가져다 쓸 수 있다.

| 구분 | 역할 | 붕어빵으로 보면 |
|---|---|---|
| 컴포넌트 | 반복해서 쓸 **화면 구조** | 붕어빵 **틀** |
| props | 컴포넌트마다 넣을 **데이터** | 안에 넣는 **팥, 슈크림** |

틀(구조)은 같고 속(이름, 소개)만 다르게 — 이것이 05회차의 핵심이다.

---

### ② 컴포넌트 정의와 사용

```jsx
// 정의 — App 바깥에, 이름은 대문자로
function ProfileCard() {
  return (
    <div className="card">
      <h2>한코딩</h2>
      <p>프론트엔드를 공부합니다.</p>
    </div>
  );
}

function App() {
  return (
    <div>
      <ProfileCard />    {/* 사용 — 태그처럼 쓴다 */}
      <ProfileCard />
    </div>
  );
}

export default App;
```
→ 화면에 같은 카드가 **2개** 나온다. `ProfileCard` 안의 문장을 바꾸면 **두 카드 모두** 바뀐다.

| 작성 | 뜻 |
|---|---|
| `<main>`, `<div>` (소문자) | HTML 요소 |
| `<ProfileCard />` (대문자) | 내가 만든 컴포넌트 |

- 컴포넌트는 `App` 함수 **바깥**에, `App`과 나란히 정의한다. (`App` 안에 넣지 않는다)
- 정의 모양은 `function ProfileCard()`와 `const ProfileCard = () =>` 둘 다 된다 (04회차와 같음).

**흔한 실수**
- 소문자로 쓴다 (`<profileCard />`) → HTML 태그로 여겨서 카드가 안 나온다
- `App` 함수 안에 컴포넌트를 정의한다

### ③ 파일 분리 — `export` / `import`

컴포넌트가 많아지면 파일로 나눈다. `src` 안에 `components` 폴더를 만들어 모은다.
```text
src/
├─ components/
│  └─ ProfileCard.jsx   ← 컴포넌트 파일 (내보내기)
├─ App.jsx              ← 가져와서 사용
└─ App.css
```

`src/components/ProfileCard.jsx` — **내보내기**
```jsx
function ProfileCard() {
  return (
    <div className="card">
      <h2>한코딩</h2>
    </div>
  );
}

export default ProfileCard;
```

`src/App.jsx` — **가져오기**
```jsx
import "./App.css";
import ProfileCard from "./components/ProfileCard.jsx";

function App() {
  return <ProfileCard />;
}

export default App;
```

| 코드 | 뜻 |
|---|---|
| `export default ProfileCard` | 이 파일에서 `ProfileCard`를 **내보낸다** |
| `import ProfileCard from "…"` | 다른 파일에서 내보낸 것을 **가져온다** |
| `./` | 지금 파일(`App.jsx`)이 있는 폴더(`src`) 기준 |

- 04회차의 `App.jsx`의 `export default App` ↔ `main.jsx`의 `import App from './App.jsx'`와 **같은 짝**이다.
- 파일로 옮긴 뒤에는 `App.jsx`에 있던 `ProfileCard` 함수를 **지운다** (같은 이름을 두 번 만들면 오류).
- CSS는 `App.jsx`에서 불러오고 있으면 `ProfileCard`에도 그대로 적용된다.

**흔한 실수**
- `export default`를 빼먹는다
- 경로 철자가 다르다 (`./component/…`, `profileCard.jsx` — 폴더·파일 이름과 대소문자까지 같아야 한다)

### ④ props — 부모가 자식에게 건네는 값

같은 틀에 **다른 내용**을 넣고 싶을 때 props를 쓴다.

부모(`App`) — **태그 속성처럼** 값을 건넨다
```jsx
<ProfileCard name="한코딩" />
<ProfileCard name="파이썬" />
```

자식(`ProfileCard`) — **`props` 객체**로 받아서 읽는다
```jsx
function ProfileCard(props) {
  return (
    <div className="card">
      <h2>{props.name}</h2>
    </div>
  );
}
```
→ 카드 2개: "한코딩", "파이썬"

- `props`는 객체다: `{ name: "한코딩" }` → `props.name`으로 꺼낸다 (JS 2부 ⑩, 04회차 ⑦).
- JS 함수의 매개변수와 같은 원리다: `greet("한코딩")` ↔ `<ProfileCard name="한코딩" />`
- 흐름: **App → props 전달 → ProfileCard에서 읽기 → 화면 표시**
- 각 카드는 **자기에게 온 props만** 읽는다. 두 번째 카드의 `name`을 바꿔도 첫 번째는 그대로다.

**흔한 실수**
- `{}` 없이 `<h2>props.name</h2>` → 글자 그대로 나온다
- 보내는 이름과 받는 이름이 다르다 (`name="한코딩"`으로 보내고 `props.userName`으로 읽음 → 값이 없어서 빈칸)

---

### 1부 한 줄 정리
- 컴포넌트 = **틀**(구조), props = **속**(데이터) → 같은 틀, 다른 내용
- 정의는 `App` **바깥**에 **대문자**로, 사용은 `<ProfileCard />`
- 파일로 나누면 `export default` ↔ `import … from "./components/…"`
- 부모는 `<ProfileCard name="한코딩" />`로 건네고, 자식은 `{props.name}`으로 읽는다
