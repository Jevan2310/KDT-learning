## 2부

1부에서 배운 건 "**버튼을 누르면 → `set`으로 값을 바꾸고 → 화면이 다시 그려진다**"였다. 2부는 이걸 실제로 쓸 때 생기는 질문들이다.
"한 번에 여러 번 바꾸면?"(⑥), "켜고 끄는 건?"(⑦), "같은 컴포넌트를 두 번 쓰면 값도 같이 바뀌나?"(⑧), "무엇을 state로 만들어야 하나?"(⑨·⑩).

> 💬 **쉽게 말하면** — 1부에서 전광판 만드는 법을 배웠다면, 2부는 **전광판을 잘 쓰는 법**이다. 숫자를 여러 번 올리는 요령, 켜고 끄는 스위치, 전광판 여러 대를 따로 돌리기, 그리고 "굳이 전광판에 따로 적어 둘 필요 없는 것"을 가려내는 눈이다.

### ⑥ 함수형 업데이트 — "지금 값에서 +1"을 정확하게

- **무엇**: `set` 함수에 **값 대신 함수**를 넘기는 방법이다. React가 **바로 직전 값**을 넣어 주고, 그 함수가 돌려준 값이 다음 값이 된다
- **왜**: 1부 ⑤ 스냅샷 때문에, 한 핸들러 안에서 `setCount(count + 1)`을 여러 번 써도 모두 **같은 사진 속 `count`**로 계산된다

```jsx
setCount((prevCount) => prevCount + 1);
```

- `prevCount`는 내가 정하는 매개변수 이름이다 (`prev`, `c` 다 된다). React가 "직전 값"을 넣어 준다
- 화살표 뒤가 소괄호 모양(괄호 없이 바로 값)이라 `return`이 없어도 값이 돌아간다

**두 방식을 한 번 클릭으로 비교** (`count`가 0일 때)

```jsx
function handleCheer() {
  setCount(count + 1);
  setCount(count + 1);
  setCount(count + 1);
}
// 세 줄 모두 "0 + 1" → 다음 화면 1 (1만 오름)
```

```jsx
function handleCheer() {
  setCount((prevCount) => prevCount + 1);
  setCount((prevCount) => prevCount + 1);
  setCount((prevCount) => prevCount + 1);
}
// 0 → 1 → 2 → 3 차례로 → 다음 화면 3 (3 오름)
```

| 코드 | 무엇을 기준으로 계산하나 |
|---|---|
| `setCount(count + 1)` | 지금 화면(사진)의 `count` — 몇 번을 써도 같은 값 |
| `setCount((prev) => prev + 1)` | 앞에 예약된 변경까지 반영한 **직전 값** |

> 💬 **쉽게 말하면** — `setCount(count + 1)`은 "**1로 해 주세요**"라는 주문서를 세 장 내는 것이다. 세 장 모두 사진 속 0을 보고 썼으니 셋 다 "1로"라고 적혀 있다. 결과는 1.
> `setCount((prev) => prev + 1)`은 "**지금 몇이든 거기서 1 올려 주세요**"라는 주문서다. React가 한 장씩 처리하면서 앞 장의 결과를 다음 장에 넘겨 준다. 0 → 1 → 2 → 3. 결과는 3.

> (강의 밖 비교) 파이썬으로 치면 `count = 1; count = 1; count = 1`과 `count += 1; count += 1; count += 1`의 차이와 같다.

**언제 무엇을 쓰나**
- 새 값이 **이전 값에 따라** 정해지면 (`+1`, 뒤집기) → 함수형 업데이트 습관
- 이전 값과 **상관없는 고정 값**이면 (초기화) → 그냥 `setCount(0)`

**흔한 실수**
- 핸들러 안의 `console.log(count)`는 함수형 업데이트를 써도 **여전히 사진 속 값**이다. 함수형 업데이트가 바꾸는 건 **다음 화면의 값**이지, 지금 함수 안의 `count`가 아니다 (1부 ⑤)
- 중괄호로 쓰면 `return`이 필요하다: `setCount((prev) => { prev + 1 })` ❌ → `undefined`가 다음 값이 된다 (🔁 06 #2와 같은 규칙)

### ⑦ 불리언 state로 펼치고 접기

- **무엇**: `true`/`false` 하나로 "열림/닫힘"을 기억하고, 그 값에 따라 버튼 글자와 영역 표시를 바꾼다
- **왜**: "소개 펼치기", "메뉴 열기"처럼 **두 상태를 오가는** 화면은 불리언 하나면 충분하다

```jsx
import { useState } from "react";

const IntroToggle = () => {
  const [isOpen, setIsOpen] = useState(false);   // 처음엔 닫힘

  function handleToggle() {
    setIsOpen((prevIsOpen) => !prevIsOpen);       // 반대로 뒤집기
  }

  return (
    <section>
      <h2>한코딩 소개</h2>
      <button type="button" onClick={handleToggle} aria-expanded={isOpen}>
        {isOpen ? "소개 접기" : "소개 펼치기"}
      </button>
      <div hidden={!isOpen}>
        <p>직접 사용하는 서비스를 만들고 있습니다.</p>
      </div>
    </section>
  );
};
```

| 클릭 | `isOpen` | 버튼 글자 | 소개 `<div>` |
|---|---|---|---|
| 처음 | `false` | 소개 펼치기 | 숨김 (`hidden={true}`) |
| 1번 | `true` | 소개 접기 | 보임 |
| 2번 | `false` | 소개 펼치기 | 숨김 |

- `!`는 불리언을 **반대로** 바꾼다: `!true` → `false`, `!false` → `true` (파이썬의 `not`)
- `hidden`은 HTML 속성이다. **참이면 숨긴다**. 그래서 "열려 있지 **않으면** 숨겨라" → `hidden={!isOpen}`
- 버튼 글자는 06의 **삼항**으로 고른다. state 하나(`isOpen`)가 버튼 글자와 영역을 **같이** 움직인다
- `aria-expanded={isOpen}`은 화면 읽기 프로그램에 "지금 펼쳐져 있다/아니다"를 알려 주는 속성이다 (화면 모양은 안 바뀜)

> 💬 **쉽게 말하면** — `isOpen`은 **방 전등 스위치**다. 누를 때마다 켜짐 ↔ 꺼짐이 바뀐다(`!`). 스위치 하나에 전등(소개 영역)과 스위치 옆 표시("켜기"/"끄기" 글자)가 같이 연결돼 있어서, 스위치만 바꾸면 둘 다 알아서 따라 바뀐다.
> `hidden={!isOpen}`이 헷갈리면 이렇게 읽는다: "**숨겨라 = 안 열렸으면**".

**흔한 실수**
- `hidden={isOpen}` — 반대로 써서 열렸을 때 숨는다
- 뒤집을 때 `setIsOpen(!isOpen)`도 동작은 하지만, **이전 값에 따라 정해지는 값**이라 강의는 함수형(`(prev) => !prev`)을 쓴다 (⑥)

### ⑧ 컴포넌트마다 state가 따로 있다

```jsx
<CheerCounter />   {/* 첫 번째 */}
<CheerCounter />   {/* 두 번째 */}
```

- 같은 컴포넌트를 두 번 쓰면 **state도 두 개**가 생긴다. 첫 번째 버튼을 눌러도 두 번째 숫자는 그대로다
- 코드(설계도)를 **재사용**하는 것과 값을 **공유**하는 것은 다르다

> 💬 **쉽게 말하면** — `CheerCounter`는 **카운터 기계의 설계도**고, `<CheerCounter />`를 쓸 때마다 **기계가 한 대씩** 만들어진다. 기계마다 숫자 칸(state)이 따로 달려 있어서, 1번 기계 버튼을 눌러도 2번 기계 숫자는 안 바뀐다. 05에서 같은 `ProfileCard` 틀에 다른 내용을 넣었던 것처럼, 틀은 같아도 **각자 따로 산다**.

> (강의 밖 비교) 파이썬 클래스로 객체를 두 개 만들면 `a.count`와 `b.count`가 따로인 것과 같다.

### ⑨ 계산할 수 있는 값은 state로 만들지 않는다 — 파생 데이터

- **무엇**: 이미 있는 데이터와 state로 **계산하면 나오는 값**을 **파생 데이터**라고 한다. 이런 값은 state로 따로 저장하지 않고 **그때그때 계산**한다
- **왜**: 같은 내용을 두 군데 저장하면 한쪽만 바뀌는 순간 **서로 어긋난다** (개수는 3인데 목록은 2개, 같은 버그)

```jsx
const [showLearningOnly, setShowLearningOnly] = useState(false);  // 저장할 것: "학습 중만 보기" 스위치 하나

const visibleProfiles = showLearningOnly                          // 계산할 것: 보여 줄 목록
  ? profiles.filter((profile) => profile.isLearning)
  : profiles;
```

| `showLearningOnly` | `visibleProfiles` |
|---|---|
| `false` | 전체 `profiles` |
| `true` | `filter()`로 고른 학습 중인 프로필 |

- 버튼은 스위치만 바꾼다: `onClick={() => setShowLearningOnly(true)}`
- 스위치가 바뀌면 컴포넌트가 다시 실행되면서 `visibleProfiles`도 **자동으로 다시 계산**된다
- 개수(`visibleProfiles.length`), 빈 목록 조건, 목록(`visibleProfiles.map`)은 **모두 같은 변수**를 쓴다 (06 2부 "같은 배열 기준"과 같은 원칙)

> 💬 **쉽게 말하면** — 필터 버튼은 **안경**이다. "학습 중만 보는 안경을 썼나/안 썼나"(스위치)만 기억하면 된다. 안경을 쓰면 보이는 목록은 **그 자리에서 걸러서** 보면 되지, 걸러진 목록을 공책에 따로 베껴 둘 필요가 없다. 베껴 두면 원본이 바뀔 때 공책도 고쳐야 하고, 깜빡하면 둘이 달라진다.

**고르는 기준**: "이 값을 **다른 값으로 계산할 수 있나?**" → 계산할 수 있으면 state가 아니라 `const` 변수

### ⑩ props vs state

| 구분 | props | state |
|---|---|---|
| 누가 정하나 | **부모**가 전달 | **컴포넌트 자신**이 관리 |
| 예시 | 이름, 소개, 이미지 경로 | 응원 횟수, 펼침 여부, 필터 스위치 |
| 바꾸는 법 | 자식은 **바꾸지 않음** (읽기 전용, 05 #8) | **`set` 함수**로 |
| 쓰는 곳 | 받은 정보로 화면 구성 | 사용자 동작에 따라 바뀌는 화면 |

- 강의 실습에서 `ProfileCard`는 **props**(이름·소개)를 받아 보여 주고, `CheerCounter`는 자기 응원 횟수를 **state**로 관리하고, `App`은 필터 **state**로 보여 줄 목록을 **계산**한다
- **모든 값을 state로 만들 필요는 없다.** 사용자 동작으로 바뀌어야 하는 것만 state, 나머지는 props나 계산

> 💬 **쉽게 말하면** — props는 **부모가 써 준 이름표**다. 달고 다니며 보여 줄 수는 있지만 내가 고쳐 쓰지 않는다. state는 **내 주머니 속 메모장**이다. 버튼이 눌릴 때마다 내가(`set` 함수로) 고쳐 쓴다. 이름표는 부모가 바꿔 줘야 바뀌고, 메모장은 나만 고친다.

**고르는 질문 세 개**
1. 부모가 정해서 넘겨주나? → props
2. 사용자 동작으로 바뀌고, 다시 그려도 기억해야 하나? → state
3. 다른 값으로 계산할 수 있나? → state도 props도 아닌 그냥 계산 (⑨)

### 🔁 복습 포인트

- **06 #2 중괄호와 `return`** — 함수형 업데이트도 화살표 함수다. `(prev) => prev + 1`은 바로 돌려주고, `(prev) => { return prev + 1; }`은 `return`이 있어야 한다. 06 map 다시 풀기의 `totals`처럼 중괄호 안에 `console.log`만 있으면 `undefined`
- **06 #5 `&&`와 숫자 `0`** — `{count && "🎉"}`는 `count`가 `0`이면 **`0`이 찍힌다**. 숫자로 조건을 걸 땐 `count > 0 &&`처럼 비교식으로
- **05 #7 props 구조 분해** — 자식은 `({ name, intro })`처럼 **중괄호**로 꺼낸다. props는 객체 하나로 온다 (⑩ props와 연결)

### 2부 한 줄 정리
