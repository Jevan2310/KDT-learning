## 1부

지금까지 만든 화면은 **처음 그린 모양 그대로**였다. 07부터는 버튼을 누르면 숫자가 오르고, 소개가 펼쳐지는 것처럼 **사용자 동작에 따라 화면이 바뀐다**.
필요한 건 두 가지다. **클릭을 받는 방법**(`onClick`)과 **바뀌는 값을 보관하는 곳**(state).

> 💬 **쉽게 말하면** — 지금까지의 React 화면은 **인쇄된 종이**였다. 한 번 찍으면 끝. 07부터는 **전광판**을 만든다. 전광판이 되려면 ① 누가 버튼을 눌렀는지 알아야 하고(`onClick`), ② 바뀐 숫자를 어딘가에 기억해 두었다가 다시 띄워야 한다(state). 1부는 이 두 가지의 기본이다.

### ① `onClick` — 함수를 "전달"한다

- **무엇**: 버튼을 클릭했을 때 실행할 함수를 JSX 속성으로 넘긴다
- **왜**: 03 JavaScript에서는 `querySelector`로 찾고 `addEventListener`로 등록했다. React는 JSX에 바로 적는다

> 💬 **쉽게 말하면** — 버튼에게 "누가 너를 누르면 이 함수를 실행해"라고 **함수를 맡겨 두는** 것이다. `onClick={handleCheer}`는 버튼에게 **전화번호를 알려 주는 것**이고, `onClick={handleCheer()}`는 **지금 당장 전화를 거는 것**이다. 괄호를 붙이면 아무도 버튼을 누르지 않았는데, 화면을 그리는 순간 전화가 걸려 버린다.
> 값을 넣어서 실행해야 할 때 `() => setCount(0)`로 감싸는 건, "누르면 `setCount(0)` 해 줘"라고 적은 **메모(새 함수)**를 버튼에 맡기는 것이다. 메모를 맡겼을 뿐이니 누르기 전에는 실행되지 않는다.

```javascript
// 03 JavaScript
button.addEventListener("click", handleCheer);
```

```jsx
// React
<button type="button" onClick={handleCheer}>응원 보내기</button>
```

- 클릭에 반응하는 함수를 **이벤트 핸들러**라고 하고, 이름은 보통 `handle…`으로 짓는다
- 속성 이름은 `onclick`이 아니라 **`onClick`** (C 대문자)

**흔한 실수 — `()`를 붙이면 "호출"이 된다**

```jsx
<button onClick={handleCheer}>   // ✅ 함수를 넘김 → 클릭할 때 실행
<button onClick={handleCheer()}> // ❌ 지금 바로 실행 → 화면을 그리는 중에 실행됨
```

> (강의 밖 비교) 파이썬의 `sorted(words, key=len)`과 같다. `key=len()`이라고 쓰지 않는다. **함수 이름만 = 함수 자체를 넘김**, **`()` = 지금 실행**.

**값을 넣어서 실행해야 하면** 화살표 함수로 감싼다 → "클릭하면 이걸 실행해"라는 **새 함수**를 넘기는 것

```jsx
<button onClick={() => setCount(0)}>초기화</button>
```

### ② 일반 변수로는 화면이 바뀌지 않는다

```jsx
function CheerCounter() {
  let count = 0;

  function handleCheer() {
    count = count + 1;
    console.log("현재 응원 횟수:", count); // 1, 2, 3 … 오른다
  }

  return (
    <section>
      <p>응원을 {count}번 받았습니다.</p>  {/* 계속 0 */}
      <button type="button" onClick={handleCheer}>응원 보내기</button>
    </section>
  );
}
```

| 버튼을 3번 누르면 | 결과 |
|---|---|
| Console | `1`, `2`, `3` |
| 화면 | 응원을 **0**번 받았습니다. |

이유 두 가지:
1. 일반 변수를 바꿔도 React는 모른다 → **화면을 다시 그리지 않는다**
2. 다시 그리더라도 컴포넌트 함수가 처음부터 다시 실행되면서 `let count = 0`이 또 실행된다 → **값이 사라진다**

> (강의 밖 비교) 파이썬 함수 안의 지역 변수가 호출할 때마다 새로 만들어지는 것과 같다. React 컴포넌트는 **화면을 그릴 때마다 다시 호출되는 함수**다.

→ 화면에 보여야 하고, 다시 그려도 **유지돼야 하는 값**은 state에 둔다.

> 💬 **쉽게 말하면** — 칠판(화면)에 "0번"이라고 적어 두고, 내 **수첩**(일반 변수)의 숫자만 1, 2, 3으로 고치는 상황이다. 수첩은 바뀌었지만 아무도 "칠판 다시 써 주세요"라고 하지 않았으니 칠판은 그대로 0이다.
> 게다가 React는 화면을 다시 그릴 때마다 컴포넌트 함수를 **처음부터 다시 실행**한다. 그때마다 `let count = 0`이 또 실행되니 수첩도 매번 **새 수첩**으로 바뀐다. 그래서 일반 변수는 "알려 주지도 못하고, 기억하지도 못한다". 이 두 가지를 해결하는 게 state다.

### ③ `useState` — 화면과 연결된 값 만들기

```jsx
import { useState } from "react";   // 06의 이름 붙인 export → { } 로 가져옴

function CheerCounter() {
  const [count, setCount] = useState(0);
  // ...
}
```

| 부분 | 역할 |
|---|---|
| `count` | 지금 화면에서 쓰는 값 (state) |
| `setCount` | 값을 바꿔 달라고 **요청**하는 함수 |
| `0` | 처음 값 (초기값) |

- `useState`는 **값과 변경 함수 두 개를 묶어서** 돌려준다. `[ , ]`로 하나씩 꺼내 이름을 붙인다 (배열 구조 분해, 05의 `{ }` 구조 분해와 같은 생각)
- 이름은 자유. 보통 `이름` + `set이름` 짝 (`isOpen` / `setIsOpen`)
- 숫자뿐 아니라 문자열·불리언·배열도 담을 수 있다
- **어디에**: 컴포넌트 함수의 **맨 위**(최상위). `if`문 안, 핸들러 함수 안에서 부르지 않는다
- `use`로 시작하는 React 함수를 **Hook**이라고 부른다

> (강의 밖 비교) 파이썬의 튜플 언패킹 `count, set_count = use_state(0)`과 같은 모양이다.

> 💬 **쉽게 말하면** — `useState`는 React에게 "이 값 좀 **대신 보관**해 줘"라고 맡기는 **보관함**이다. 맡기면 React가 두 가지를 돌려준다. 지금 보관함에 든 값(`count`)과, 값을 바꿔 달라고 부탁할 때 누르는 **요청 버튼**(`setCount`). 컴포넌트 함수가 처음부터 다시 실행돼도 보관함은 React가 들고 있으니 값이 사라지지 않는다. ②의 "기억 못 함" 문제가 이렇게 풀린다.
> `useState(0)`의 `0`은 보관함을 **처음 만들 때 한 번만** 넣는 값이다. 다시 그릴 때는 0이 아니라 보관해 둔 값을 준다.

**실행 흐름**

```text
클릭 → 핸들러 실행 → setCount로 변경 요청 → React가 컴포넌트를 다시 실행(렌더링) → 새 count로 화면 반영
```

- **렌더링** = React가 컴포넌트 함수를 호출해서 그릴 화면을 계산하는 것. 페이지 새로고침과 다르다 (바뀐 부분만 고친다)

### ④ state는 `set` 함수로만 바꾼다

```jsx
count = count + 1;     // ❌ 직접 대입 — const라서 오류, let이어도 화면은 안 바뀜
setCount(count + 1);   // ✅ 변경 함수로 요청
```

- `count`는 `const`인데 어떻게 바뀔까? → 값은 **React가 보관**하고 있다가, 다시 렌더링할 때 **새 값으로 `count`를 새로 만들어** 준다
- 그래서 바꾸는 방법은 `setCount`에게 부탁하는 것 하나뿐이다

> 💬 **쉽게 말하면** — 보관함의 값은 React 것이라서 내가 직접 고쳐 쓰면 안 되고, `setCount`로 "이 값으로 바꿔 주세요"라고 **신청**해야 한다. 신청을 받은 React가 값을 바꾸고 **화면도 다시 그려 준다**. `count = count + 1`은 신청서 없이 몰래 고치는 것이라 React가 모르고, 화면도 안 바뀐다. (`const`라서 고칠 수도 없다.)

**흔한 실수 — 컴포넌트 본문에서 바로 `set` 호출**

```jsx
function CheerCounter() {
  const [count, setCount] = useState(0);
  setCount(count + 1);   // ❌ 렌더링 → 변경 → 렌더링 → 변경 … 끝없이 반복 (오류)
  return <p>{count}</p>;
}
```

→ 상태 변경은 **이벤트 핸들러 안에서** 한다

> 💬 **쉽게 말하면** — 본문에 `setCount`를 두면 "그릴 때마다 신청 → 신청을 받으면 다시 그림 → 다시 그리면 또 신청 …"이 된다. 꼬리를 무는 무한 반복이다. 신청은 **사용자가 버튼을 눌렀을 때**(핸들러 안)만 한다.

### ⑤ 스냅샷 — `set` 바로 다음 줄의 값은 그대로

```jsx
function handleCheer() {
  setCount(count + 1);
  console.log(count);   // count가 0이었으면 → 0 이 찍힘 (1이 아님)
}
```

- `setCount`는 "**다음 렌더링 때** 이 값으로 해 줘"라는 **예약**이다. 지금 이 함수 안의 `count`는 안 바뀐다
- 지금 렌더링의 `count`는 **사진(스냅샷)**처럼 고정돼 있다고 생각한다
- 새 값은 다시 그려진 **다음 화면**에서 보인다

> 💬 **쉽게 말하면** — 화면 한 장 한 장을 **사진**이라고 생각한다. 지금 사진 속 `count`는 찍힌 순간의 값(0)으로 고정돼 있다. `setCount(count + 1)`은 "**다음 사진**은 1로 찍어 주세요"라는 **예약**이지, 지금 사진 속 숫자를 고치는 게 아니다. 그래서 바로 다음 줄의 `console.log(count)`는 **지금 사진의 값 0**을 보여 준다. 1은 다음 사진(다음 렌더링)에서 보인다.

| 클릭 횟수 | Console (`set` 다음 줄) | 화면 |
|---|---|---|
| 1번 | 0 | 1 |
| 2번 | 1 | 2 |

> 💡 이 규칙 때문에 2부의 **함수형 업데이트**(`setCount((prev) => prev + 1)`)가 필요해진다. 2부에서 본다.

### 🔁 복습 포인트

- **06 #2 중괄호와 `return`** — `return`이 필요한 건 **값을 돌려줘야 할 때**다 (`map`, `filter`, 컴포넌트). 클릭 핸들러는 돌려줄 값이 없어서 `() => { setCount(0); }`처럼 중괄호에 `return`이 없어도 된다
  ```jsx
  items.map((item) => { return <li key={item.id}>{item.name}</li>; }) // 값을 돌려줘야 함 → return 필수
  onClick={() => { setCount(0); }}                                    // 실행만 하면 됨 → return 없어도 OK
  ```
- **06 #8 `filter()` 결과** — `filter()`는 **통과한 것만 담은 새 배열**. `.length`는 원본 길이가 아니라 통과한 개수

### 1부 한 줄 정리

클릭은 `onClick={함수}` (괄호 없이) · 화면에 보일 바뀌는 값은 `useState` · 바꿀 때는 `setX(새 값)` · `set` 직후 값은 그대로, 새 값은 다음 화면에서
