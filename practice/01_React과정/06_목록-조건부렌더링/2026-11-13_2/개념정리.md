## 2부

**조건부 렌더링**이란 데이터에 따라 화면의 일부를 **보여 주거나, 숨기거나, 다른 문구로 바꾸는 것**이다.
예: 학습 중인 사람에게만 "학습 중" 배지, 목록이 비었으면 "아직 없습니다" 안내.

> 💬 **쉽게 말하면** — 조건부 렌더링은 화면에 **스위치**를 다는 것이다. 데이터를 보고 어떤 부분을 **켜고 끄거나**(`&&`), 두 가지 중 **하나로 바꾸거나**(삼항), 그 둘을 써서 **빈 목록일 때 안내**를 띄운다. 그리고 스위치에 넣을 명단을 **골라 내는** 도구가 `filter()`다.

> 💡 보충: JSX의 `{ }` 안에는 **값**만 들어갈 수 있어서 `if`문을 쓸 수 없다. 그래서 값이 되는 식인 `&&`와 `? :`를 쓴다.

### ⑥ `&&` — 참일 때만 표시

- **무엇**: `조건 && JSX` → 조건이 참이면 JSX를 보여 주고, 거짓이면 **아무것도 안 보인다**
- **왜**: "있을 때만 보이는 것"(배지, 알림 문구)을 만들 때

> 💬 **쉽게 말하면** — `&&`는 **문지기가 있는 문**이다. 문지기(왼쪽 조건)가 "통과"라고 하면 뒤의 JSX가 화면에 나간다. "불통"이면 뒤의 JSX 대신 **문지기가 손에 든 값**을 그대로 내놓는다. 손에 든 게 `false`면 React가 무시해서 아무것도 안 보이지만, **숫자 `0`이면 React가 "숫자네" 하고 화면에 `0`을 찍는다**. 그래서 숫자는 `> 0`으로 미리 "예/아니오"(`true`/`false`)로 바꿔서 문지기 손에 `false`를 쥐여 준다.

```jsx
const isLearning = true;

<h3>
  한코딩 {isLearning && <span>학습 중</span>}
</h3>
```

| `isLearning` | 화면 |
|---|---|
| `true` | 한코딩 학습 중 |
| `false` | 한코딩 |

> (강의 밖 비교) 파이썬의 `and`와 같다. 앞이 거짓이면 뒤를 보지 않고 **앞의 값을 그대로** 돌려준다.

**흔한 실수 — 숫자 `0`이 화면에 나온다**

```jsx
{todos.length && <p>할 일이 있어요</p>}      // 배열이 비면 화면에 0이 나옴
{todos.length > 0 && <p>할 일이 있어요</p>}  // 비교식으로 → 결과가 true / false
```

- `&&`는 왼쪽이 거짓 같은 값이면 **그 값**을 돌려준다. `length`가 `0`이면 `0`을 돌려준다
- React는 `false`·`undefined`는 그리지 않지만 **숫자 `0`은 그린다** → 화면에 `0`
- 그래서 숫자는 `> 0`처럼 **비교식**으로 써서 결과를 `true`/`false`로 만든다

### ⑦ 삼항 연산자 — 둘 중 하나 표시

- **무엇**: `조건 ? 참일 때 값 : 거짓일 때 값`
- **왜**: `&&`는 "보여 주거나 / 안 보여 주거나", 삼항은 "**A 아니면 B**"

> 💬 **쉽게 말하면** — 삼항은 **갈림길 표지판**이다. `조건 ? 왼쪽 길 : 오른쪽 길` — 어느 쪽이든 **반드시 한 길로** 간다. `&&`가 "들어갈까 말까"(문)라면, 삼항은 "이쪽이냐 저쪽이냐"(갈림길)다. 갈림길이라 두 길이 다 있어야 해서 `:`를 빼면 오류가 난다. 그리고 각 길에는 **하나만** 놓을 수 있다 — 요소 두 개를 나란히 두면 오류가 나니, 늘 보여야 하는 것은 갈림길 밖으로 빼거나 `<>…</>`로 묶는다.

```jsx
<span className="status-badge">
  {isLearning ? "학습 중..." : "학습 예정"}
</span>
```

| `isLearning` | 화면 |
|---|---|
| `true` | 학습 중... |
| `false` | 학습 예정 |

> (강의 밖 비교) 파이썬의 `"학습 중..." if is_learning else "학습 예정"`과 같다. 자바스크립트는 **조건이 맨 앞**이다.

| 하고 싶은 것 | 쓰는 것 |
|---|---|
| 참일 때만 보이기 | `조건 && JSX` |
| 둘 중 하나 보이기 | `조건 ? A : B` |

- 흔한 실수: `?`만 쓰고 `:` 뒤(거짓일 때)를 빼먹기 → 문법 오류. 삼항은 `?`와 `:`가 꼭 짝으로 다닌다

### ⑧ 빈 목록 안내

- **왜**: 배열이 비면 `map()` 결과도 빈 배열이라 화면에 **아무것도 안 나온다**. 데이터가 없는 건지, 화면이 고장 난 건지 알 수 없다
- **어떻게**: 삼항 연산자 + `length === 0` (`===`는 03 JavaScript의 "값과 자료형이 같은가")

> 💬 **쉽게 말하면** — 식당 메뉴판이 **백지**면 손님은 "재료가 다 떨어졌나? 인쇄가 잘못됐나?" 알 수가 없다. "오늘은 준비된 메뉴가 없습니다" 한 줄만 있으면 고장이 아니라 **비어 있다**는 걸 안다. 빈 목록 안내가 이 한 줄이다. 삼항으로 "비었으면 안내문, 아니면 목록" 갈림길을 만든다. 개수 제목(`학습 중 0명`)처럼 **비어도 보여야 하는 것**은 갈림길 밖에 둔다.

```jsx
{todos.length === 0 ? (
  <p>오늘 할 일이 없습니다.</p>
) : (
  <ul>
    {todos.map((todo) => (
      <li key={todo.id}>{todo.title}</li>
    ))}
  </ul>
)}
```

- 비었으면 → 안내 문구, 아니면 → 목록
- A·B 자리에 여러 줄 JSX가 들어가면 `( )`로 감싸서 보기 좋게 쓴다

### ⑨ `filter()` — 조건에 맞는 것만 고르기

- **무엇**: 함수가 **참**을 돌려준 항목만 모아 **새 배열**을 만든다. 원본 배열은 그대로
- **왜**: "학습 중인 사람만", "웹 서비스에 관심 있는 사람만"처럼 일부만 보여 줄 때

> 💬 **쉽게 말하면** — `filter()`는 **체(거름망)**다. 명단을 체에 붓고 한 명씩 "조건 맞아?"라고 물어서, **"예"인 사람만 아래 새 그릇에 떨어진다**. 원래 명단은 그대로다. 그래서 새 그릇의 `.length`는 **떨어진 사람 수**지 원래 명단 수가 아니다.
> `map()`은 "모두를 **다른 모양으로** 바꾸기"(인원 그대로), `filter()`는 "**일부만 고르기**"(인원이 줄 수 있음, 모양 그대로). 중괄호에 `return`이 없으면 체가 대답을 못 들어서(`undefined` = 아니오) **아무도 통과 못 한다** → 빈 그릇 `[]`.

```javascript
const numbers = [1, 2, 3, 4];
const largeNumbers = numbers.filter((number) => number >= 3);
console.log(largeNumbers); // [3, 4]
```

```javascript
const learningProfiles = profiles.filter((profile) => profile.isLearning);   // 학습 중인 사람만
const waitingProfiles  = profiles.filter((profile) => !profile.isLearning);  // 반대 (! = 아니다)
```

| 메서드 | 하는 일 | 결과 배열 |
|---|---|---|
| `map()` | 각 항목을 **다른 모양으로** 바꾼다 | 개수 그대로 |
| `filter()` | 조건에 맞는 항목만 **고른다** | 개수가 줄 수 있음, 모양 그대로 |

> (강의 밖 비교) 파이썬의 `[p for p in profiles if p["isLearning"]]`와 같은 생각이다. `!`는 파이썬의 `not`이다.

**고른 다음 그리기** — `filter()`로 먼저 고르고, 고른 배열로 `map()`

```jsx
const learningProfiles = profiles.filter((profile) => profile.isLearning);

<p>학습 중 {learningProfiles.length}명</p>
{learningProfiles.map((profile) => (
  <ProfileCard key={profile.id} name={profile.name} />
))}
```

- 흔한 실수: **개수·빈 목록 조건·카드 목록이 같은 배열**을 봐야 한다. 개수는 `learningProfiles.length`인데 카드는 `profiles.map()`이면 "2명"이라 써 놓고 카드가 4장 나온다

### ⑩ 불리언 `false` vs 문자열 `"false"`

```javascript
isLearning: false    // 불리언 — 거짓
isLearning: "false"  // 문자열 — 글자 5개짜리 문자열
```

> 💬 **쉽게 말하면** — `false`는 **꺼진 스위치**, `"false"`는 **"꺼짐"이라고 적힌 종이**다. JavaScript는 종이에 뭐라고 적혔는지 읽지 않고 "**종이에 글자가 있나?**"만 본다. 글자가 있으면 참이다. 그래서 "꺼짐"이라고 적힌 종이도 참 → 배지가 켜지고 `filter()`도 통과한다. 빈 종이 `""`만 거짓이다. 상태는 종이 말고 **진짜 스위치**(따옴표 없는 `true`/`false`)로 둔다.

- 조건식에서 **비어 있지 않은 문자열은 참**으로 취급된다 → `"false"`도 참!
- 그래서 `"false"`로 적으면 `&&` 배지가 계속 보이고, `filter()`에서도 "학습 중"으로 골라진다
- 05에서 배운 `"3"` vs `{3}`과 같은 함정이다. props로 보낼 때도 `isLearning="false"`는 문자열, `isLearning={false}`가 불리언

> (강의 밖 비교) 파이썬도 같다. `bool("False")`는 `True`다.

- 규칙: 참·거짓 상태는 **따옴표 없이** `true` / `false`

### 🔁 복습 포인트 — 06 #2 중괄호에는 `return`

`filter()`도 화살표 함수라서 규칙이 똑같다.

```javascript
numbers.filter((number) => number >= 3);              // [3, 4]
numbers.filter((number) => { return number >= 3; });  // [3, 4]
numbers.filter((number) => { number >= 3 });          // [] ← return이 없어서 전부 탈락
```

`map()`에서 `return`을 빼면 `[undefined, …]`였는데, `filter()`에서 빼면 **빈 배열**이 된다 (`undefined`는 거짓 → 하나도 안 고름).

### 2부 한 줄 정리

있을 때만 → `&&` (숫자는 `> 0`) · 둘 중 하나 → `? :` · 비었으면 → `length === 0 ? 안내 : 목록` · 골라내기 → `filter()` · 참·거짓은 따옴표 없이
