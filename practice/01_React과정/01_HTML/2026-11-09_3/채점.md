## 정답

- 문제 1: button O · input X · label O · img X · a O · br X · li O · meta X
  - **기준: 태그 사이에 감쌀 내용(화면에 보일 글자)이 있으면 종료 태그가 있고, 자리만 차지하는 요소(이미지 자리, 입력 칸, 줄바꿈, 가로줄, 문서 정보)는 없다**
- 문제 2: 안쪽 `ul`이 안 닫힘 → `<li>박스 모델</li>` 뒤, `</li>` 앞에 `</ul>`. 지금 코드대로면 git push는 CSS 예습의 하위 항목(선택자·박스 모델과 같은 단계)으로 보인다
- 문제 3:
  ```html
  <h1>나의 개발 공부</h1>

  <section>
    <h2>구독 신청</h2>
    <label for="email">이메일</label>
    <input type="email" id="email">
    <button>구독하기</button>
    <a href="https://github.com/">내 GitHub</a>
  </section>

  <section>
    <h2>추천 링크</h2>
    <ul>
      <li><a href="https://developer.mozilla.org">MDN 문서</a></li>
      <li><a href="https://www.naver.com">네이버로 이동</a></li>
    </ul>
    <img src="study.png" alt="공부하는 모습">
    <p>오늘도 <strong>열심히</strong></p>
  </section>
  ```
- 문제 4: 제출한 `index.html` 최종본 (for = id 연결 정확)
- 문제 5:
  - `a`는 누르면 `href`에 적힌 **주소로 이동**한다
  - `button`은 누르면 지금 페이지에서 **동작을 실행**한다 (추가, 삭제, 로그인, 보내기)
  - 이동 버튼을 `button`으로 만들면 `href`가 없어서 **눌러도 아무 데도 가지 않는다** (JavaScript를 따로 써야 함). 또 "이동"이라는 의미가 드러나지 않아, 코드를 읽는 사람과 화면 낭독기가 역할을 잘못 이해한다
  - 화면에서 상자 모양으로 보이는 것과 태그의 역할은 별개다. 태그는 모양이 아니라 하는 일로 고른다

## 잘한 점
- **button = 종료 태그 있음**: 1·2회차 연속 오답을 첫 제출에 바로잡음, O/X 8개 모두 정답
- **버그 찾기 8/8**: `buton`, `herf` 철자를 찾고, 세 번째 나온 `https://` 누락도 체크리스트로 찾음
- **근거 없는 수정 안 함**: 멀쩡한 `h1`, `h2`를 건드리지 않음
- 안 닫힌 `ul`과 그 결과(화면 위치)를 test.html로 확인하며 정확히 예측
- label `for` / input `id`를 질문으로 이해하고 바로 적용
