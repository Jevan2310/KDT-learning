## 1단계: API 컨트롤러 — `@RestController`가 목록을 JSON으로 보낸다

🧭 02회차의 `/hello`는 `@RestController`가 돌려준 문자열을 글자 그대로 보냈어요. 03회차의 `@Controller`는 돌려준 문자열을 템플릿 이름으로 썼고요. 오늘은 `@RestController`에서 문자열이 아니라 **학생 목록**을 돌려줘요.

`@RestController`가 붙은 클래스의 메서드가 값을 돌려주면, Spring은 그 값을 응답 본문으로 바꿔 보내요. 문자열이면 글자 그대로, `List<Student>` 같은 객체면 JSON으로 바꿔요. 이 변환은 Spring Boot에 들어 있는 Jackson이라는 라이브러리가 해요. Jackson은 `Student`의 **getter**를 찾아서 이름을 정해요. `getId()` → `"id"`, `getName()` → `"name"`, `isLearning()` → `"learning"`이에요. 필드를 직접 읽지 않아요. 그래서 getter가 없는 값은 JSON에 나오지 않아요(바꿔 보기). 목록은 JSON 배열 `[ ... ]`, 학생 한 명은 객체 `{ ... }`가 돼요. 파이썬 Flask에서 `return jsonify([...])`를 하는 것과 같아요.

학생 목록은 05의 `StudentRepository.findAll()`로 꺼내요. Repository는 05처럼 생성자로 전달받아요. Spring은 Repository 객체를 하나만 만들어 두고 필요한 컨트롤러마다 같은 객체를 넣어 줘요. 화면용 `StudentController`와 오늘 만드는 `StudentApiController`가 같은 Repository, 같은 DB를 써요.

화면용 컨트롤러를 고치지 않고 클래스를 **새로** 만드는 이유가 있어요. `@Controller`나 `@RestController`는 클래스 전체에 붙어서 그 안의 모든 메서드에 적용돼요. `StudentController`를 `@RestController`로 바꾸면 `/students`도 `"students"`라는 글자를 보내게 돼요. 그래서 화면은 `@Controller` 클래스, 데이터는 `@RestController` 클래스로 나눠요. 주소도 `/api/...`로 시작하게 해서 "이건 데이터를 주는 주소"라는 걸 구분해요.

### ▶ 직접 해 보기 — `controller/StudentApiController.java`

`controller` 패키지 우클릭 → **New → Java Class** → `StudentApiController`. CORS 설정(`@CrossOrigin`)은 4단계에서 더해요.

```java
package com.example.springpractice.controller;

import com.example.springpractice.model.Student;
import com.example.springpractice.repository.StudentRepository;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

import java.util.List;

@RestController
public class StudentApiController {

    private final StudentRepository studentRepository;

    public StudentApiController(
            StudentRepository studentRepository
    ) {
        this.studentRepository = studentRepository;
    }

    @GetMapping("/api/students")
    public List<Student> getStudents() {
        return studentRepository.findAll();
    }
}
```

■ → ▶ 후 Chrome 주소창에 `http://localhost:8080/api/students`를 열어요. 학생이 없으면 빈 배열이 보여요.

```json
[]
```

`http://localhost:8080/students`에서 `한코딩`, `이학생`을 등록하고 `/api/students`를 새로고침하면 이렇게 보여요(한 줄로 나와요).

```json
[{"name":"한코딩","learning":false,"id":1},{"name":"이학생","learning":false,"id":2}]
```

wiki에는 `id`, `name`, `learning` 순서로 적혀 있는데, 이 Mac의 Spring Boot 4.1.3(4.2.0도 같아요)에서는 `name`, `learning`, `id` 순서로 나왔어요. JSON 객체는 이름으로 값을 찾기 때문에 순서는 상관없어요. React도 `student.name`처럼 이름으로 읽어요.

**바꿔 보기** (하나씩 바꾸고 ■ → ▶, 확인하면 되돌려요)
- `@RestController`를 `@Controller`로 (import도 `org.springframework.stereotype.Controller`로) → `/api/students`가 500 오류, Run 창에 `Error resolving template [api/students], template might not exist or might not be accessible by any of the configured Template Resolvers`. `@Controller`는 돌려준 값을 화면으로 만들려고 해서, 주소 이름대로 `templates/api/students.html`을 찾다가 실패했어요.
- `model/Student.java`에서 `isLearning()` 메서드를 지우기 → `/api/students`가 `[{"name":"한코딩","id":1}]`처럼 `learning` 없이 나와요. getter가 없으니 JSON에서 빠졌어요. 같은 이유로 `/students` 화면은 500 오류이고 Run 창에 `EL1008E: Property or field 'learning' cannot be found on object of type 'com.example.springpractice.model.Student' - maybe not public or not valid?`가 나와요. Thymeleaf의 `${student.learning}`도 getter를 쓰기 때문이에요.

## 2단계: 같은 DB, 다른 응답 — HTML과 JSON 비교

🧭 이제 같은 학생 목록이 두 주소에서 나와요. 두 응답이 실제로 어떻게 다른지 터미널로 비교해요.

`/students`의 응답은 Thymeleaf가 만든 HTML이고, 응답 헤더의 `Content-Type`이 `text/html`이에요. `/api/students`의 응답은 Jackson이 만든 JSON이고 `Content-Type`이 `application/json`이에요. `Content-Type`은 "본문이 어떤 형식인지" 알려 주는 헤더예요. 브라우저나 React는 이걸 보고 본문을 어떻게 다룰지 정해요.

데이터는 같아요. 두 컨트롤러가 각자 목록을 따로 갖고 있는 게 아니라, 요청이 올 때마다 같은 H2 테이블을 `findAll()`로 읽어요. 그래서 한쪽에서 바뀐 데이터가 다른 쪽에도 그대로 보여요. 05의 H2 Console로 DB를 직접 고쳐서 확인해 볼 수 있어요. 지금까지 폼으로 등록한 학생은 모두 "학습 예정"(`false`)이라 "학습 중"을 볼 기회가 없었는데, DB 값을 바꾸면 두 화면 모두에 "학습 중"이 나와요.

### ▶ 직접 해 보기 — `curl -i`로 두 응답 비교, H2 Console로 값 바꾸기

터미널(Vite가 켜진 터미널 말고 새 탭 `Cmd + T`)에서:

```bash
curl -i http://localhost:8080/students
curl -i http://localhost:8080/api/students
```

첫 번째는 `HTTP/1.1 200`, `Content-Type: text/html;charset=UTF-8` 아래에 `<!DOCTYPE html>`로 시작하는 HTML이 와요. 두 번째는 이래요.

```text
HTTP/1.1 200
Content-Type: application/json
Content-Length: 91

[{"name":"한코딩","learning":false,"id":1},{"name":"이학생","learning":false,"id":2}]
```

이제 `http://localhost:8080/h2-console`에 05처럼 로그인해요(JDBC URL은 내 `application.properties`의 주소와 똑같이). 아래 SQL을 실행하면 `Update count: 1`이 나와요.

```sql
UPDATE students SET learning = TRUE WHERE id = 1;
```

`/students`를 새로고침하면 1번 한코딩이 "학습 중"이 되고, `/api/students`에서는 `"learning":true`가 돼요.

```json
[{"name":"한코딩","learning":true,"id":1},{"name":"이학생","learning":false,"id":2}]
```

**바꿔 보기**: 주소창에서 `/students` 페이지의 소스 보기(`Cmd + Option + U`)를 하면 학생 이름이 HTML 안에 다 들어 있어요. 3단계를 마친 뒤 React 화면(`http://localhost:5173`)에서 소스 보기를 하면 학생 이름은 하나도 없고 `<div id="root"></div>`만 있어요. React 화면의 목록은 브라우저가 JSON을 받아 나중에 만든 거라서예요.

## 3단계: React의 `StudentList.jsx`가 Spring API를 부른다

🧭 Node 04의 `StudentList.jsx`는 `http://localhost:3000/students`(Node 서버)에서 학생 목록을 받았어요. 같은 컴포넌트를 Spring 주소로 바꿔요.

컴포넌트가 하는 일은 Node 04와 같아요([Node 04 개념 정리](../../../02_Node과정/04_React-서버연결/2026-11-19/개념정리.md)). 다시 짧게 따라가면 이래요. `useEffect(..., [])` 안의 함수는 컴포넌트가 화면에 처음 나타날 때 한 번 실행돼요. 그 안에서 `fetch`로 요청을 보내고 `await`로 응답을 기다려요. `response.ok`로 상태 코드가 200번대인지 보고, 아니면 오류를 던져요. `response.json()`으로 JSON 글자를 JavaScript 배열로 바꾸고 `setStudents(data)`로 state에 넣으면 화면이 다시 그려져요. 실패하면 `catch`에서 오류 문구를 state에 넣고, 성공이든 실패든 `finally`에서 로딩 표시를 끝내요. `ignore`는 화면에서 컴포넌트가 사라진 뒤 늦게 도착한 응답으로 state를 바꾸지 않게 막는 표시예요. 요청 자체를 취소하지는 않아요.

바뀌는 곳은 네 군데예요. ① 요청 주소가 `http://localhost:8080/api/students`예요. **포트(3000 → 8080)와 경로(`/students` → `/api/students`)가 둘 다** 바뀌어요. ② 제목이 "Spring Boot에서 받은 학생 목록"이에요. ③ `response.ok`가 아닐 때 문구가 "학생 목록 요청에 실패했습니다."예요. ④ 이름 옆에 `student.learning`으로 "학습 중"/"학습 예정"을 보여 줘요. `{student.learning ? "학습 중" : "학습 예정"}`은 삼항 연산자로, 파이썬의 `"학습 중" if learning else "학습 예정"`이에요. `{" "}`는 JSX에서 공백 한 칸을 넣는 방법이에요. 줄을 바꿔 쓴 JSX 사이의 공백은 사라져서 이름과 "—" 사이를 띄우려고 넣었어요.

이 단계까지만 하면 화면에 목록이 **안 나와요.** 4단계의 CORS 설정이 아직 없어서예요. 어떤 문장이 나오는지 먼저 봐 두면 4단계가 왜 필요한지 보여요.

### ▶ 직접 해 보기 — `src/components/StudentList.jsx` (전체 바꾸기)

```jsx
import { useEffect, useState } from "react";

function StudentList() {
  const [students, setStudents] = useState([]);
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError] = useState("");

  useEffect(() => {
    let ignore = false;

    async function loadStudents() {
      try {
        const response = await fetch(
          "http://localhost:8080/api/students"
        );

        if (!response.ok) {
          throw new Error(
            "학생 목록 요청에 실패했습니다."
          );
        }

        const data = await response.json();

        if (!ignore) {
          setStudents(data);
        }
      } catch (error) {
        console.error(error);

        if (!ignore) {
          setError(
            "학생 목록을 불러오지 못했습니다. 서버와 주소를 확인해주세요."
          );
        }
      } finally {
        if (!ignore) {
          setIsLoading(false);
        }
      }
    }

    loadStudents();

    return () => {
      ignore = true;
    };
  }, []);

  return (
    <section className="student-list">
      <h2>Spring Boot에서 받은 학생 목록</h2>

      {isLoading ? (
        <p role="status">학생 목록을 불러오는 중입니다.</p>
      ) : error ? (
        <p role="alert">{error}</p>
      ) : students.length === 0 ? (
        <p>등록된 학생이 없습니다.</p>
      ) : (
        <>
          <p>전체 학생: {students.length}명</p>

          <ul>
            {students.map((student) => (
              <li key={student.id}>
                <strong>{student.name}</strong>

                <span>
                  {" "}
                  — {student.learning ? "학습 중" : "학습 예정"}
                </span>
              </li>
            ))}
          </ul>
        </>
      )}
    </section>
  );
}

export default StudentList;
```

저장하면 Vite가 바로 반영해요. `http://localhost:5173` 화면은 "Spring Boot에서 받은 학생 목록" 아래에 이 문구가 나와요.

```text
학생 목록을 불러오지 못했습니다. 서버와 주소를 확인해주세요.
```

Console(`Cmd + Option + J`)을 열면 빨간 줄이 보여요. 같은 쌍이 두 번 나오는 건 개발 중 Strict Mode가 Effect를 한 번 더 실행해서예요(4단계에서 확인해요).

```text
Access to fetch at 'http://localhost:8080/api/students' from origin 'http://localhost:5173' has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present on the requested resource.
TypeError: Failed to fetch
```

`TypeError: Failed to fetch`는 `catch`의 `console.error(error)`가 찍은 거예요. 주소창에서 `/api/students`는 잘 열렸는데 React에서는 막혔어요. 다음 단계에서 이유를 봐요.

## 4단계: CORS — 다른 출처의 응답을 읽어도 된다고 허락하기

🧭 Node 04에서도 같은 오류를 만났고, Express 서버에 `app.use(cors({ origin: "http://localhost:5173" }))`를 넣어 풀었어요. Spring에서는 어노테이션 한 줄로 해요.

**출처**(origin)는 주소의 앞부분인 `프로토콜 + 호스트 + 포트`예요. React 화면은 `http://localhost:5173`, Spring은 `http://localhost:8080`이라 포트가 달라서 다른 출처예요. 브라우저는 한 출처의 JavaScript가 다른 출처의 응답을 읽는 것을 기본으로 막아요. 다른 사이트의 JavaScript가 내 정보를 몰래 읽어 가지 못하게 하려는 브라우저의 규칙이에요.

막는 방식을 순서대로 보면 이래요. `fetch`를 하면 브라우저가 요청에 `Origin: http://localhost:5173` 헤더를 붙여 Spring에 보내요. Spring은 요청을 처리하고 JSON을 응답해요. 브라우저는 응답 헤더에 `Access-Control-Allow-Origin: http://localhost:5173`이 있는지 봐요. 있으면 JavaScript에 응답을 넘겨주고, 없으면 응답을 버리고 `fetch`를 실패시켜요. 이 "다른 출처에 응답을 읽게 해 주는 규칙"이 **CORS**예요. 주소창에 직접 친 요청은 다른 출처의 JavaScript가 읽는 게 아니라서 이 검사를 하지 않아요. 그래서 주소창에서는 JSON이 보였던 거예요.

헤더를 붙이는 쪽은 서버예요. API 컨트롤러 클래스에 `@CrossOrigin(origins = "http://localhost:5173")`을 붙이면 Spring이 그 출처에서 온 요청의 응답에 `Access-Control-Allow-Origin` 헤더를 넣어 줘요. 이 클래스의 주소에만 적용돼서 화면용 `StudentController`(`/students`)에는 붙지 않아요. 출처는 **글자 그대로** 맞아야 해요. `localhost`와 `127.0.0.1`은 같은 컴퓨터지만 다른 출처예요. 그리고 CORS는 브라우저에서 읽기를 허락하는 설정일 뿐, 로그인이나 권한 검사가 아니에요. `curl`이나 주소창으로는 언제든 JSON을 받을 수 있어요.

### ▶ 직접 해 보기 — `@CrossOrigin` 추가

먼저 지금(설정 전) 응답을 터미널에서 봐요. `-H "Origin: ..."`은 브라우저처럼 출처 헤더를 붙여 보내는 옵션이에요.

```bash
curl -i -H "Origin: http://localhost:5173" http://localhost:8080/api/students
```

```text
HTTP/1.1 200
Content-Type: application/json
```

그 아래 본문은 2단계와 같은 학생 JSON이에요. 서버는 200과 JSON을 보냈어요. `Access-Control-Allow-Origin` 줄이 없어서 브라우저가 막은 거예요. 이제 `StudentApiController.java`에 import 한 줄과 어노테이션 한 줄을 더해요.

```java
import org.springframework.web.bind.annotation.CrossOrigin;
```

```java
@RestController
@CrossOrigin(origins = "http://localhost:5173")
public class StudentApiController {
```

Spring을 ■ → ▶ 하고 같은 `curl`을 다시 하면 헤더가 생겼어요.

```text
HTTP/1.1 200
Vary: Origin
Vary: Access-Control-Request-Method
Vary: Access-Control-Request-Headers
Access-Control-Allow-Origin: http://localhost:5173
Content-Type: application/json
```

React 화면을 새로고침하면 목록이 나와요(학생 두 명이 있고 1번을 2단계에서 "학습 중"으로 바꾼 경우).

```text
Spring Boot에서 받은 학생 목록
전체 학생: 2명
• 한코딩 — 학습 중
• 이학생 — 학습 예정
```

Console의 빨간 줄도 사라져요. IntelliJ Run 창을 보면 React를 한 번 새로고침할 때마다 `Hibernate: select ...` 줄이 **두 개씩** 늘어요. `main.jsx`의 `<StrictMode>`가 개발 중에만 Effect를 한 번 더 실행해서 요청이 두 번 가기 때문이에요. 오류가 아니에요.

**바꿔 보기** (하나씩 바꾸고 Spring ■ → ▶, 확인하면 되돌려요)
- `origins = "http://127.0.0.1:5173"`으로 바꾸고 React(`http://localhost:5173`)를 새로고침 → 다시 오류 문구, Console에 3단계와 같은 `Access to fetch at ... from origin 'http://localhost:5173' has been blocked by CORS policy: ...`. 이번에는 Run 창에 `select` 줄이 늘지 않아요. 출처가 허락 목록에 없으면 Spring이 컨트롤러를 실행하기 전에 거절해요. 터미널로 보면 `curl -i -H "Origin: http://127.0.0.1:5173" http://localhost:8080/api/students`가 `HTTP/1.1 403`과 본문 `Invalid CORS request`예요.
- `@CrossOrigin` 줄을 지우고 `curl -i -H "Origin: http://localhost:5173" ...` → `Access-Control-Allow-Origin` 줄이 다시 사라져요. React는 3단계 상태로 돌아가요.

## 5단계: 두 화면에서 같은 데이터 확인하고, 안 보일 때 찾는 순서

🧭 이제 등록은 Thymeleaf 폼에서, 보기는 Thymeleaf와 React 둘 다에서 해요. 한쪽에서 등록한 학생이 다른 쪽에 언제 보이는지 확인해요.

`http://localhost:8080/students`에서 학생을 등록하면 H2에 저장돼요. 그런데 이미 열려 있는 React 화면에는 바로 나타나지 않아요. `StudentList`는 `useEffect(..., [])`라서 **화면에 처음 나타날 때 한 번만** 요청해요. 다른 탭에서 DB가 바뀌었다고 React가 알 방법이 없어요. React 탭을 새로고침하면 컴포넌트가 처음부터 다시 나타나면서 요청을 다시 보내고, 새 학생이 보여요. Thymeleaf 화면은 원래 요청할 때마다 서버가 HTML을 새로 만드니 새로고침하면 항상 최신이에요. 오늘 React는 목록 보기만 해요. React에서 등록·수정·삭제하는 기능은 아직 없어요.

React에 목록이 안 나올 때는 앞에서부터 하나씩 확인해요. ① Chrome 주소창에서 `http://localhost:8080/api/students`를 열어 JSON이 나오는지 봐요. 안 나오면 React가 아니라 Spring 문제예요(서버가 켜졌는지, 경로가 맞는지). ② JSON이 나오면 React 화면에서 개발자 도구를 열고 **Console**의 빨간 줄을 읽어요. CORS 문장이면 `@CrossOrigin`의 출처를, 다른 문장이면 아래 바꿔 보기를 봐요. ③ **Network** 탭을 열고 새로고침해서 `students` 요청을 눌러요. Request URL이 `http://localhost:8080/api/students`인지, Method가 `GET`인지, Status가 200인지 봐요.

### ▶ 직접 해 보기 — Thymeleaf에서 등록, React에서 확인

1. Chrome 탭 두 개를 열어요. 한쪽은 `http://localhost:8080/students`, 다른 쪽은 `http://localhost:5173`.
2. Thymeleaf 탭에서 `정학생`을 등록해요. 표에 3번 정학생이 생겨요.
3. React 탭은 그대로 두면 2명이에요. 새로고침하면 "전체 학생: 3명"이 되고 `정학생 — 학습 예정`이 생겨요.

**바꿔 보기** — 흔한 실수를 `StudentList.jsx`에서 일으켜 봐요 (확인하면 `http://localhost:8080/api/students`로 되돌려요)
- 주소를 `"http://localhost:8080/students"`로 → 화면은 오류 문구, Console에 `Access to fetch at 'http://localhost:8080/students' from origin 'http://localhost:5173' has been blocked by CORS policy: ...`. HTML을 받아서 JSON 변환이 실패할 것 같지만, 그 전에 CORS에서 막혀요. `/students`는 `@CrossOrigin`이 없는 화면용 컨트롤러예요.
- 주소를 앞을 빼고 `"/api/students"`로 → 요청이 Spring이 아니라 Vite(5173)로 가요. Vite는 모르는 주소에 `index.html`을 보내서 Console에 `SyntaxError: Unexpected token '<', "<!doctype "... is not valid JSON`. HTML의 첫 글자 `<`를 JSON으로 읽으려다 실패했어요.
- (주소는 원래대로 두고) IntelliJ에서 Spring을 ■로 끈 뒤 React 새로고침 → 화면은 오류 문구, Console에는 CORS 문장 없이 `TypeError: Failed to fetch`만 나와요. 서버에 연결 자체를 못 했어요. 다시 ▶로 켜요.

## 마무리: React 화면을 새로고침하면 일어나는 일

1. 브라우저가 Vite(5173)에서 `index.html`과 JavaScript를 받아요. HTML에는 `<div id="root"></div>`만 있어요.
2. React가 `App` → `StudentList`를 처음 그려요. state가 `isLoading = true`라서 "학생 목록을 불러오는 중입니다."가 보여요.
3. 처음 나타났으니 `useEffect`가 실행되고, `fetch`가 `Origin: http://localhost:5173` 헤더를 붙여 `GET http://localhost:8080/api/students`를 보내요(개발 중에는 Strict Mode 때문에 한 번 더).
4. Spring이 주소와 GET을 보고 `StudentApiController.getStudents()`를 골라요. `@CrossOrigin`에 적힌 출처와 요청의 `Origin`이 같은지 먼저 확인해요.
5. `studentRepository.findAll()`이 Hibernate를 통해 `select ... from students`를 실행하고 `List<Student>`를 돌려줘요.
6. Jackson이 getter를 읽어 `[{"name":"한코딩","learning":true,"id":1}, ...]` JSON을 만들고, Spring이 `Content-Type: application/json`과 `Access-Control-Allow-Origin: http://localhost:5173`을 붙여 200으로 응답해요.
7. 브라우저가 `Access-Control-Allow-Origin`을 확인하고 응답을 JavaScript에 넘겨요.
8. `response.ok`가 `true`라서 `response.json()`으로 배열을 만들고 `setStudents(data)`, `finally`에서 `setIsLoading(false)`를 해요.
9. state가 바뀌어 다시 그려지면서 `students.map`이 학생마다 `<li>`를 만들고, `learning` 값에 따라 "학습 중"/"학습 예정"을 붙여요.

## 다음 회차와 연결

Spring 과정은 여기까지예요. 정리하면 같은 H2 데이터를 Thymeleaf는 서버에서 HTML로 만들어 보냈고(SSR), React는 JSON을 받아 브라우저에서 그렸어요(CSR). 이 두 방식은 SSR·CSR 과정에서 다시 비교해요. 그 과정 04회차는 Spring에 `StudentApiController`를 더하는 오늘과 같은 구조인데, `@CrossOrigin` 대신 Vite의 **프록시** 설정으로 요청을 넘겨서 CORS 문제가 생기지 않게 해요([08 SSR·CSR 04](../../../../wiki/08_SSR-CSR과정/04_React-CSR화면.md)). 데이터베이스 과정 06회차에서는 H2·JPA 대신 MySQL과 MyBatis로 SQL을 직접 쓰는 방식을 봐요([DB 06](../../../../wiki/06_데이터베이스과정/06_Spring-MyBatis.md)).
