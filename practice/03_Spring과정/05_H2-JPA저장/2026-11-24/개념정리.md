## 들어가며

**🧭 맥락 — 지금 어디쯤**

04회차에서 폼으로 학생을 등록했어요. 등록한 학생은 컨트롤러 필드의 `List`, 즉 서버 프로그램의 메모리에 있었어요. 그래서 서버를 껐다 켜면 처음 세 명만 남고 나머지는 사라졌죠.

오늘은 학생을 **데이터베이스**에 저장해요. 데이터베이스(DB)는 데이터를 정해진 모양으로 저장하고 꺼내 주는 프로그램이에요. 이번에 쓰는 DB는 **관계형 DB**라서 데이터를 **테이블**(표)로 저장해요. 학생 한 명이 테이블의 **행**(가로줄) 하나이고, 번호·이름·학습 여부가 **열**(세로줄)이에요. 행마다 겹치지 않는 값을 하나 정해 그 행을 찾는 데 쓰는데, 이것을 **기본 키**(PK)라고 해요. 오늘은 학생 번호 `id`가 기본 키예요. 테이블과 SQL은 데이터베이스 과정에서 MySQL로 자세히 다뤄요.

DB는 **H2**를 써요. H2는 Java로 만든 작은 DB라서 따로 설치하지 않아요. `build.gradle`에 한 줄 넣으면 Spring 서버가 켜질 때 서버 안에서 함께 실행돼요. 처음에는 데이터를 메모리에 두는 방식(메모리 모드)으로 시작하고, 6단계에서 파일에 저장하는 방식(파일 모드)으로 바꿔 서버를 껐다 켜도 남는지 확인해요.

DB에 저장하려면 원래 SQL(`INSERT`, `SELECT` 같은 DB 명령)을 써야 해요. 오늘은 SQL을 직접 쓰지 않아요. **JPA**는 "Java 객체와 DB 테이블을 연결하는 방법"을 정한 표준이고, **Hibernate**는 그 표준대로 실제로 동작하는 라이브러리예요. **Spring Data JPA**는 그 위에서 `save()`, `findAll()` 같은 메서드를 바로 쓰게 해 줘요. 우리가 `studentRepository.save(student)`를 부르면 Hibernate가 `insert` SQL을 만들어 H2에 보내요. SQL이 없어지는 게 아니라 Hibernate가 대신 쓰는 거예요. 4단계에서 그 SQL을 Run 창으로 직접 봐요. 파이썬으로 치면 SQLAlchemy ORM으로 클래스를 테이블에 연결하고 `session.add()`로 저장하는 것과 같은 방식이에요.

화면은 바뀌지 않아요. 04의 폼과 `students.html`, CSS를 그대로 쓰고, **데이터를 넣고 꺼내는 곳만** `List`에서 DB로 바꿔요. 06회차에서는 이 DB의 학생 목록을 JSON으로도 보내 React 화면에 띄워요.

## 1단계: H2와 JPA를 프로젝트에 넣고 연결 설정을 쓴다

🧭 02회차에서 프로젝트를 만들 때 Spring Web과 Thymeleaf만 골랐어요. DB를 쓰려면 라이브러리가 더 필요해요. Node에서 `npm install express`로 패키지를 넣었듯이, Gradle에서는 `build.gradle`의 `dependencies`에 줄을 더해요.

더할 줄은 세 개예요. `spring-boot-starter-data-jpa`는 JPA, Hibernate, Spring Data JPA를 한 번에 넣어 줘요. `com.h2database:h2`는 H2 DB 자체예요. 앞의 `runtimeOnly`는 "실행할 때만 필요하다"는 뜻이에요. 우리 코드가 H2를 직접 import하지 않고, Hibernate가 실행 중에 H2와 연결하기 때문이에요. `spring-boot-h2console`은 브라우저에서 DB 안을 들여다보는 **H2 Console** 기능이에요. Spring Boot 3.x까지는 따로 넣지 않아도 됐는데, 4.x부터 별도 모듈로 나뉘어서 이 줄이 있어야 `/h2-console`이 열려요. 내 버전은 `build.gradle` 맨 위 `plugins`의 `org.springframework.boot` 줄에서 확인해요(02에서 고른 `4.1.3`). 버전 번호는 적지 않아요. Spring Boot가 자기 버전에 맞는 것을 골라 줘요.

다음은 `application.properties`에 어느 DB에 어떻게 연결할지 적어요. `spring.datasource.url=jdbc:h2:mem:studentdb`는 "H2의 **메모리 모드**로, 이름이 `studentdb`인 DB에 연결한다"는 주소예요. `jdbc:`로 시작하는 이 주소를 **JDBC URL**이라고 하는데, Java 프로그램이 DB에 연결할 때 쓰는 주소예요. `username=sa`와 빈 `password=`는 H2의 기본 계정이에요. `ddl-auto=update`는 "Entity 클래스(2단계)를 보고 테이블이 없으면 만들고, 모양이 바뀌었으면 고친다"는 설정이에요. 테이블을 직접 만들지 않아도 되는 학습용 설정이에요. `show-sql=true`는 Hibernate가 실행하는 SQL을 Run 창에 찍어 줘요. 마지막 두 줄은 H2 Console을 켜고 주소를 `/h2-console`로 정해요.

이 단계에서는 연결만 해요. 아직 `Student`가 DB와 연결되지 않아서 화면은 04의 메모리 목록 그대로예요.

### ▶ 직접 해 보기 — `build.gradle`, `application.properties`

`build.gradle`의 `dependencies { ... }` 안 **맨 위에** 세 줄을 넣어요. 넣고 나면 이런 모양이에요(아래 다섯 줄은 Initializr가 만든 그대로예요).

```groovy
dependencies {
	implementation 'org.springframework.boot:spring-boot-starter-data-jpa'
	runtimeOnly 'com.h2database:h2'
	runtimeOnly 'org.springframework.boot:spring-boot-h2console'
	implementation 'org.springframework.boot:spring-boot-starter-thymeleaf'
	implementation 'org.springframework.boot:spring-boot-starter-webmvc'
	testImplementation 'org.springframework.boot:spring-boot-starter-thymeleaf-test'
	testImplementation 'org.springframework.boot:spring-boot-starter-webmvc-test'
	testRuntimeOnly 'org.junit.platform:junit-platform-launcher'
}
```

**Load Gradle Changes**를 누르고 다운로드가 끝날 때까지 기다려요. 그다음 `src/main/resources/application.properties`를 이렇게 만들어요. 02·03에서 따로 넣은 줄이 있으면 그 줄은 남겨 두고, 같은 키는 한 번만 써요.

```properties
spring.application.name=_spring-practice

server.port=8080

spring.datasource.url=jdbc:h2:mem:studentdb
spring.datasource.username=sa
spring.datasource.password=

spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true

spring.h2.console.enabled=true
spring.h2.console.path=/h2-console
```

■ → ▶ 하면 Run 창에 전에 없던 줄이 생겨요(줄 앞 날짜·로그 이름은 줄였어요).

```text
HikariPool-1 - Added connection conn0: url=jdbc:h2:mem:studentdb user=SA
H2 console available at '/h2-console'. Database available at 'jdbc:h2:mem:studentdb'
Tomcat started on port 8080 (http) with context path '/'
```

첫 줄은 서버가 H2의 `studentdb`에 연결했다는 뜻이고, 둘째 줄은 H2 Console이 켜졌다는 뜻이에요. `http://localhost:8080/students`는 아직 04처럼 학생 3명이에요.

**바꿔 보기**: `spring-boot-h2console` 줄을 지우고 Load Gradle Changes → ■ → ▶. Run 창에 `H2 console available` 줄이 없고, `http://localhost:8080/h2-console`은 Whitelabel 오류 화면 `(type=Not Found, status=404)`예요. Spring Boot 4.x에서는 이 줄이 꼭 필요해요. 되살리고 다시 Load Gradle Changes 해요.

## 2단계: `Student`를 Entity로 바꾼다

🧭 01회차부터 쓴 `Student`는 번호·이름·학습 여부를 담는 보통 Java 클래스였어요. 이 클래스를 DB의 `students` 테이블과 연결해요.

JPA가 DB와 연결해 관리하는 클래스를 **Entity**라고 해요. 클래스 위에 `@Entity`를 붙이면 Hibernate가 서버를 켤 때 이 클래스를 찾아 "이 클래스의 객체 하나 = 테이블의 행 하나, 필드 하나 = 열 하나"로 연결해요. `@Table(name = "students")`는 테이블 이름을 정해요. 없으면 클래스 이름을 따라 `student`가 돼요.

`@Id`는 이 필드가 기본 키라는 표시예요. Entity에는 꼭 하나 있어야 해요. `@GeneratedValue(strategy = GenerationType.IDENTITY)`는 번호를 DB가 붙이게 해요. DB가 행을 넣을 때 1, 2, 3…을 자동으로 늘려 줘요. 그래서 04의 `nextId` 필드가 필요 없어져요.

`id`의 자료형은 `int`가 아니라 `Long`이에요. 새 학생 객체를 만든 직후에는 아직 DB에 들어가지 않아서 번호가 없어요. `Long`은 참조형이라 "아직 없음"을 `null`로 둘 수 있어요. 기본형 `long`은 `null`을 담지 못해요(01회차의 기본형·참조형).

생성자는 두 개가 돼요. `Student(String name, boolean learning)`은 우리가 새 학생을 만들 때 쓰는 생성자예요. 번호는 DB가 붙이니 받지 않아요. `protected Student() {}`는 매개변수가 없는 생성자로, **Hibernate가 쓰는** 거예요. Hibernate는 DB에서 행을 읽어 객체로 만들 때 먼저 빈 객체를 만들고 필드에 값을 하나씩 채워요. 그래서 매개변수 없는 생성자가 꼭 필요해요. `protected`로 두면 Hibernate는 쓸 수 있고, 다른 패키지의 우리 코드에서 실수로 `new Student()`를 부르는 것은 막을 수 있어요.

생성자가 바뀌었으니 04 컨트롤러의 `new Student(1, "한코딩", true)`는 더 이상 맞지 않아요. 이 단계가 끝나면 빌드 오류가 나는 게 정상이에요. 3단계에서 컨트롤러를 바꾸면 사라져요.

### ▶ 직접 해 보기 — `model/Student.java`

파일 내용을 전부 바꿔요.

```java
package com.example.springpractice.model;

import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.persistence.Table;

@Entity
@Table(name = "students")
public class Student {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;

    private boolean learning;

    protected Student() {
    }

    public Student(String name, boolean learning) {
        this.name = name;
        this.learning = learning;
    }

    public Long getId() {
        return id;
    }

    public String getName() {
        return name;
    }

    public boolean isLearning() {
        return learning;
    }
}
```

▶를 누르면 빌드가 멈추고 `StudentController.java`의 `new Student(...)` 네 곳에서 이런 오류가 나요. `Student(int,String,boolean)`에 맞는 생성자가 없고, 있는 생성자 두 개(`Student()`, `Student(String,boolean)`)는 값 개수가 다르다는 뜻이에요.

```text
error: no suitable constructor found for Student(int,String,boolean)
        studentList.add(new Student(1, "한코딩", true));
                        ^
    constructor Student.Student() is not applicable
      (actual and formal argument lists differ in length)
    constructor Student.Student(String,boolean) is not applicable
      (actual and formal argument lists differ in length)
```

3단계로 넘어가요.

## 3단계: Repository를 만들고 컨트롤러가 전달받는다

🧭 04에서는 컨트롤러가 `studentList.add()`로 직접 넣고 꺼냈어요. 이제 넣고 꺼내는 일은 **Repository**가 맡아요. Repository는 DB에 저장하고 조회하는 일을 맡는 객체예요.

`repository` 패키지에 `StudentRepository`를 만드는데, `class`가 아니라 `interface`예요. 인터페이스는 "이런 메서드가 있다"는 목록만 있고 내용(실제 코드)이 없는 형태예요. `extends JpaRepository<Student, Long>`이라고 쓰면 `save()`, `findAll()`, `count()`, `findById()` 같은 메서드를 물려받아요. `< >` 안의 `Student`는 다룰 Entity, `Long`은 그 Entity의 `@Id` 자료형이에요. 내용이 없는데 어떻게 실행될까요? 서버가 켜질 때 Spring Data JPA가 이 인터페이스를 찾아서 **실제로 동작하는 객체를 만들어** 둬요. 그 객체의 `save()`가 Hibernate를 통해 `insert`를 실행해요. 그래서 우리는 인터페이스 선언 세 줄만 써요.

컨트롤러는 그 객체를 어떻게 얻을까요? 직접 `new StudentRepository()`를 할 수 없어요. 인터페이스는 내용이 없어서 객체를 만들 수 없거든요. 대신 컨트롤러 생성자의 매개변수로 `StudentRepository`를 받게 써 둬요. Spring이 컨트롤러 객체를 만들 때 생성자를 보고, 미리 만들어 둔 Repository 객체를 넣어 줘요. 필요한 객체를 직접 만들지 않고 밖에서 전달받는 것을 **의존성 주입(DI)**이라고 해요. 생성자가 하나뿐이면 `@Autowired` 같은 표시도 필요 없어요.

컨트롤러는 이렇게 바뀌어요. `studentList` 필드, `nextId` 필드, 학생 3명을 넣던 생성자는 지워요. 목록 조회는 `studentList` 대신 `studentRepository.findAll()`, 등록은 `studentList.add(student)` + `nextId++` 대신 `studentRepository.save(student)` 한 줄이에요. `new Student(trimmedName, false)`처럼 번호 없이 만들어요. 빈 이름 검사, 오류 문구, `redirect`는 04 그대로예요.

### ▶ 직접 해 보기 — `repository/StudentRepository.java`, `controller/StudentController.java`

`com.example.springpractice` 패키지를 우클릭 → **New → Package** → `repository`, 그 패키지를 우클릭 → **New → Java Class** → 종류에서 **Interface**를 고르고 `StudentRepository`.

```java
package com.example.springpractice.repository;

import com.example.springpractice.model.Student;
import org.springframework.data.jpa.repository.JpaRepository;

public interface StudentRepository
        extends JpaRepository<Student, Long> {
}
```

`StudentController.java`는 내용을 전부 바꿔요.

```java
package com.example.springpractice.controller;

import com.example.springpractice.model.Student;
import com.example.springpractice.repository.StudentRepository;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestParam;

@Controller
public class StudentController {

    private final StudentRepository studentRepository;

    public StudentController(
            StudentRepository studentRepository
    ) {
        this.studentRepository = studentRepository;
    }

    @GetMapping("/students")
    public String students(Model model) {
        model.addAttribute("schoolName", "한코딩 스쿨");
        model.addAttribute(
                "message",
                "데이터베이스에 저장된 학생 목록입니다."
        );
        model.addAttribute(
                "students",
                studentRepository.findAll()
        );

        return "students";
    }

    @PostMapping("/students")
    public String addStudent(
            @RequestParam(name = "name", defaultValue = "") String name,
            Model model
    ) {
        String trimmedName = name.trim();

        if (trimmedName.isEmpty()) {
            model.addAttribute(
                    "error",
                    "학생 이름을 입력해주세요."
            );

            return students(model);
        }

        Student student = new Student(
                trimmedName,
                false
        );

        studentRepository.save(student);

        return "redirect:/students";
    }
}
```

■ → ▶ 후 `http://localhost:8080/students`를 열면 안내 문구가 "데이터베이스에 저장된 학생 목록입니다."로 바뀌고, "전체 학생: 0명"과 "등록된 학생이 없습니다."가 보여요. 04의 학생 3명은 메모리 목록에 있던 것이라 DB로 옮겨지지 않았고, 그 학생들을 넣던 생성자도 지웠어요. 빈 DB에서 시작하는 게 정상이에요.

**바꿔 보기**
- 생성자 안을 `this.studentRepository = new StudentRepository();`로 → 빌드 오류 `StudentRepository is abstract; cannot be instantiated`. 인터페이스는 `new`로 만들 수 없어요. 되돌려요.
- `"message"`를 수업 코드처럼 `"msg"`로 → 오류는 없고 제목 아래 안내 문구 자리가 빈 `<p></p>`가 돼요. 템플릿은 `${message}`를 읽어서 이름이 어긋났어요. 되돌려요.

## 4단계: `save()`와 `findAll()`이 실행하는 SQL을 본다

🧭 3단계에서 화면은 비어 있지만 DB와 연결은 끝났어요. 학생을 등록하면서 Hibernate가 실제로 어떤 SQL을 보내는지 Run 창으로 봐요. `show-sql=true`를 넣어 둔 이유예요.

먼저 서버가 켜질 때 일어나는 일이에요. Hibernate가 `@Entity`가 붙은 `Student`를 찾고, `ddl-auto=update` 설정에 따라 `students` 테이블이 없으니 `create table`을 실행해요. `id`는 자동 증가 기본 키, `learning`은 `boolean not null`(Java의 기본형 `boolean`은 `null`이 될 수 없어서), `name`은 최대 255글자 문자열이 돼요.

그다음 요청마다 SQL이 하나씩 나가요. `findAll()`은 `select`예요. `s1_0`은 Hibernate가 붙인 테이블 별명이에요. `save()`는 `insert`예요. `values (?,?,default)`의 `?` 자리에는 학습 여부와 이름이 따로 전달돼요. 값을 SQL 글자 안에 직접 끼워 넣지 않는 방식이라 로그에는 `?`로 보여요. `id` 자리의 `default`는 "번호는 DB가 정해라"라는 뜻이에요.

### ▶ 직접 해 보기 — 등록하며 Run 창 보기

■ → ▶ 하면 Tomcat이 뜨기 전에 이 줄이 보여요.

```text
Hibernate: create table students (id bigint generated by default as identity, learning boolean not null, name varchar(255), primary key (id))
```

`spring.jpa.open-in-view is enabled by default...`로 시작하는 노란 WARN 줄도 하나 보이는데, 이번 실습과 관계없는 안내라 그냥 둬요.

브라우저에서 목록을 열고 → `한코딩` 등록 → `이학생` 등록 → 스페이스만 쳐서 등록, 순서로 해요. Run 창에는 이렇게 쌓여요.

```text
Hibernate: select s1_0.id,s1_0.learning,s1_0.name from students s1_0
Hibernate: insert into students (learning,name,id) values (?,?,default)
Hibernate: select s1_0.id,s1_0.learning,s1_0.name from students s1_0
Hibernate: insert into students (learning,name,id) values (?,?,default)
Hibernate: select s1_0.id,s1_0.learning,s1_0.name from students s1_0
Hibernate: select s1_0.id,s1_0.learning,s1_0.name from students s1_0
```

첫 `select`는 목록을 연 것, 다음 `insert` + `select` 두 쌍은 등록(`save`) 뒤 redirect로 목록을 다시 연 것이에요. 마지막 `select` 하나는 빈 이름이라 `insert` 없이 `students(model)`만 부른 것이에요. 화면의 표는 이래요. 번호는 DB가 1부터 붙였어요.

```text
1  한코딩  학습 예정
2  이학생  학습 예정
```

새로고침해도 그대로예요. 데이터가 `List`가 아니라 H2에 있고, 매번 `select`로 꺼내 와요.

**바꿔 보기** — 2단계의 Entity 규칙을 하나씩 어겨 봐요 (확인하면 되돌려요)
- `@Entity` 줄을 지우기 → 서버가 켜지지 않아요. Run 창 끝쪽에 `Not a managed type: class com.example.springpractice.model.Student`. Hibernate가 `Student`를 Entity로 모르니 `JpaRepository<Student, Long>`을 만들 수 없어요.
- `@Id` 줄을 지우기 → 서버가 켜지지 않아요. `Entity 'com.example.springpractice.model.Student' has no identifier (every '@Entity' class must declare or inherit at least one '@Id' or '@EmbeddedId' property)`.
- `protected Student() {}`를 지우기 → 서버는 켜지고 Run 창에 `HHH000182: No default (no-argument) constructor for class [...Student]` 안내만 나와요. 빈 목록도 열리고 등록도 돼요. 그런데 등록한 뒤 목록을 열면 500 오류, Run 창에 `No default constructor for entity 'com.example.springpractice.model.Student'`. DB에서 읽은 행을 객체로 만들 때 이 생성자를 쓰기 때문에, 읽을 행이 생기고 나서야 터져요.

## 5단계: H2 Console로 테이블을 직접 본다

🧭 지금까지는 화면과 Run 창으로만 DB를 봤어요. H2 Console은 브라우저에서 DB에 접속해 SQL을 직접 실행해 보는 **개발용** 화면이에요. 데이터베이스 과정에서 DBeaver로 하는 일과 같은 종류예요.

`http://localhost:8080/h2-console`을 열면 로그인 화면이 나와요. 여기서 가장 많이 틀리는 곳이 **JDBC URL**이에요. 처음 칸에는 `jdbc:h2:~/test`가 들어 있어요. 이건 H2가 기본으로 채워 둔 예시 주소라서, 그대로 Connect하면 우리 서버의 `studentdb`가 아닌 다른 DB를 찾아요. `application.properties`의 `spring.datasource.url`과 **글자 하나까지 똑같이** 바꿔야 해요. 한 번 접속에 성공하면 H2가 그 주소를 기억해서(홈 폴더의 `.h2.server.properties` 파일), 다음부터는 마지막에 쓴 주소가 채워져 있어요. 6단계에서 주소를 바꾸면 이 칸도 다시 바꿔야 해요.

H2 Console은 Spring 서버 안에서 실행되고, 메모리 모드 DB는 그 서버 안에만 있어요. 그래서 H2 Console도 서버가 켜져 있을 때만 열리고, 서버를 끄면 DB도 함께 사라져요.

### ▶ 직접 해 보기 — 로그인과 SQL 실행

4단계에서 두 명을 등록한 서버가 켜진 상태에서 `http://localhost:8080/h2-console`을 열어요. 로그인 칸을 이렇게 맞춰요. Saved Settings는 `Generic H2 (Embedded)` 그대로 둬요.

| 칸 | 처음 값 | 넣을 값 |
|---|---|---|
| Driver Class | `org.h2.Driver` | 그대로 |
| JDBC URL | `jdbc:h2:~/test` | `jdbc:h2:mem:studentdb` |
| User Name | `sa` | 그대로 |
| Password | (빈칸) | 그대로 빈칸 |

**Connect**를 누르면 SQL 입력 화면이 나와요. 아래를 쓰고 **Run**(`Ctrl + Enter`)을 눌러요.

```sql
SELECT * FROM students ORDER BY id;
```

결과는 이래요. 열 이름은 대문자로 나와요.

```text
ID  LEARNING  NAME
1   FALSE     한코딩
2   FALSE     이학생
(2 rows, …ms)
```

브라우저 폼으로 등록한 학생이 정말 `students` 테이블의 행으로 들어가 있어요. 번호(ID)는 학생을 구분하는 값일 뿐이라, 나중에 지우거나 하면 1, 2, 4처럼 빈 번호가 생길 수도 있어요.

**바꿔 보기**
- JDBC URL을 처음 값 `jdbc:h2:~/test` 그대로 두고 Connect → 로그인 화면에 빨간 오류 `Database "/Users/…/test" not found, either pre-create it or allow remote database creation (not recommended in secure environments) [90149-240]`. 없는 DB라고 접속을 거절해요.
- JDBC URL을 `jdbc:h2:mem:testdb`처럼 이름만 다르게 → 같은 오류 `Database "mem:testdb" not found, ...`. 이름 하나만 달라도 다른 DB예요.

## 6단계: 메모리 모드와 파일 모드

🧭 DB를 쓰는 이유는 서버를 꺼도 데이터가 남게 하려는 거였어요. 그런데 지금 주소는 `jdbc:h2:mem:`, 즉 메모리 모드예요. 서버를 껐다 켜면 어떻게 될까요?

메모리 모드 H2는 DB 전체를 서버 프로그램의 메모리에 둬요. 서버가 꺼지면 메모리가 비워지니 DB도 사라져요. 다시 켜면 `ddl-auto=update`가 빈 `students` 테이블을 새로 만들어요. 결국 04와 같은 결과예요. DB를 써도 저장 위치가 메모리면 남지 않아요.

남기려면 **파일 모드**로 바꿔요. 주소를 `jdbc:h2:file:./data/studentdb;DB_CLOSE_ON_EXIT=FALSE`로 바꾸면 H2가 DB를 파일에 저장해요. `./data/studentdb`는 서버를 실행한 폴더 기준 경로예요. IntelliJ ▶는 보통 프로젝트 폴더에서 실행해서 `_spring-practice/data/studentdb.mv.db` 파일이 생겨요. `DB_CLOSE_ON_EXIT=FALSE`는 DB를 닫는 시점을 H2가 아니라 Spring Boot가 정하게 하는 옵션이에요. 서버를 ■로 정상 종료하면 Spring Boot가 DB를 닫으며 파일에 마무리해서 써요.

파일 모드에서도 데이터가 지워지는 경우가 있어요. `ddl-auto=create`는 서버를 켤 때마다 테이블을 지우고(`drop table`) 새로 만들어요. 그리고 H2 파일은 한 서버만 열 수 있어서, 같은 파일을 쓰는 서버를 두 개 켜면 두 번째 서버가 시작하지 못해요.

`data/` 안의 `.mv.db` 파일은 GitHub에 올리지 않아요. KDT학습 저장소의 `.gitignore`에 `*.mv.db`가 이미 들어 있어요.

### ▶ 직접 해 보기 — 재시작과 파일 모드

1. 지금(메모리 모드) 학생이 두 명 있는 상태에서 ■ → ▶ 하고 새로고침 → "전체 학생: 0명", "등록된 학생이 없습니다."
2. ■로 멈추고 `application.properties`의 주소 줄만 바꿔요. `//`로 시작하는 설명 줄은 붙여 넣지 않아요. `.properties` 파일의 주석은 `#`이에요.

```properties
spring.datasource.url=jdbc:h2:file:./data/studentdb;DB_CLOSE_ON_EXIT=FALSE
```

3. ▶ 하면 Run 창의 연결 주소가 바뀌어 있어요. 처음 켤 때는 파일이 새로 생겨서 `create table` 줄도 다시 나와요.

```text
H2 console available at '/h2-console'. Database available at 'jdbc:h2:file:./data/studentdb'
```

4. `한코딩`, `이학생`을 등록해요. 프로젝트 폴더에 `data/studentdb.mv.db` 파일이 생겨요.
5. ■ → ▶. 이번에는 테이블이 이미 있어서 `create table` 줄이 나오지 않아요. 새로고침하면 두 명이 그대로 있어요.

```text
1  한코딩  학습 예정
2  이학생  학습 예정
```

6. H2 Console에서도 JDBC URL을 바꾼 주소와 똑같이 `jdbc:h2:file:./data/studentdb;DB_CLOSE_ON_EXIT=FALSE`로 넣고 Connect → `SELECT * FROM students ORDER BY id;` → 같은 두 줄이 나와요.

**바꿔 보기**
- `ddl-auto=update`를 `create`로 바꾸고 ■ → ▶ → Run 창에 `Hibernate: drop table if exists students cascade`와 `create table` 줄이 나오고, 목록은 "등록된 학생이 없습니다." 파일 모드여도 지워졌어요. `update`로 되돌려요.
- 서버가 켜진 채로 같은 프로젝트의 서버를 하나 더 켜면(예: IntelliJ에서 켜 둔 채 터미널에서 한 번 더 실행) 두 번째 서버가 시작하지 못하고 `Database may be already in use: "…/data/studentdb.mv.db". Possible solutions: close all other connection(s); use the server mode [90020-240]`가 나와요. 같은 DB 파일은 한 서버만 열 수 있어요. 둘 다 8080이어도 포트 오류보다 이 오류가 먼저 나요. 두 번째 것만 멈추면 돼요.

이 노트 다음부터(06회차)는 파일 모드로 두는 게 편해요. 서버를 다시 켜도 학생이 남아서 React 화면에서 바로 볼 수 있어요.

## 마무리: 학생 한 명을 등록하고 목록을 보기까지

1. 서버가 켜질 때 H2가 `studentdb`를 열고, Hibernate가 `@Entity` 클래스 `Student`를 찾아 `students` 테이블이 없으면 `create table`을 실행해요.
2. Spring Data JPA가 `StudentRepository` 인터페이스로 실제 동작하는 객체를 만들어요.
3. Spring이 `StudentController`를 만들면서 생성자에 그 Repository 객체를 넣어 줘요(의존성 주입).
4. 브라우저가 폼으로 `POST /students`를 보내요. `addStudent()`가 이름을 `trim()`하고 검사한 뒤 `new Student("한코딩", false)`를 만들어요. 이때 `id`는 `null`이에요.
5. `studentRepository.save(student)`가 불리면 Hibernate가 `insert into students (learning,name,id) values (?,?,default)`를 실행하고, H2가 번호 1을 붙여 행을 저장해요.
6. `"redirect:/students"` → 302 → 브라우저가 `GET /students`를 새로 보내요.
7. `students()`가 `studentRepository.findAll()`을 불러요. Hibernate가 `select ... from students`를 실행하고, 받은 행마다 `protected Student()`로 빈 객체를 만들어 필드를 채운 뒤 `List<Student>`로 돌려줘요.
8. 그 목록을 `Model`에 담고 `"students"`를 돌려주면, Thymeleaf가 04와 같은 `students.html`로 표를 만들어 보내요.
