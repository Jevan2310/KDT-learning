## 들어가며

**🧭 맥락 — 지금 어디쯤**

03회차에서 `GET /students`로 학생 목록 화면을 만들었어요. 컨트롤러가 `Model`에 학생 목록을 담고 `"students"`를 돌려주면, Thymeleaf가 `templates/students.html`에 값을 채워 완성된 HTML을 보냈죠. 그런데 그 학생 세 명은 코드에 직접 쓴 값이었어요. 화면에서 학생을 추가할 방법이 없었어요.

오늘은 **브라우저에서 서버로 데이터를 보내는 것**을 처음 해요. Node 과정에서는 서버가 데이터를 보내기만 했고(GET), React 할 일 앱(React 08)에서는 입력값을 브라우저의 state에만 넣었어요. 오늘은 HTML 폼에 이름을 쓰고 버튼을 누르면, 그 이름이 서버로 가서 서버의 학생 목록에 들어가요. 파이썬 Flask로 치면 `@app.post("/students")`와 `request.form.get("name", "")`, `redirect("/students")`를 쓰는 일이에요.

오늘 만들 기능은 이거예요.

- 목록 위에 이름 입력 폼이 있어요.
- 이름을 쓰고 등록하면 새 번호(4, 5, …)와 "학습 예정"으로 목록에 추가돼요.
- 공백만 쓰면 추가하지 않고 "학생 이름을 입력해주세요."를 보여 줘요.
- 등록한 뒤 새로고침해도 학생이 두 번 들어가지 않아요.

오늘 학생 목록은 아직 서버 **메모리**에 있어요. 그래서 서버를 껐다 켜면 등록한 학생이 사라져요(6단계에서 확인해요). 05회차에서 이 목록을 H2 데이터베이스로 옮기고, 06회차에서 같은 목록을 JSON으로 보내 React 화면에 띄워요. 오늘 만든 폼과 화면은 05·06에서도 그대로 써요.

## 1단계: 학생 목록을 컨트롤러의 필드로 옮긴다

🧭 03의 `students()` 메서드는 요청이 올 때마다 `new ArrayList<>()`로 학생 목록을 새로 만들었어요. 등록 기능을 만들기 전에 이것부터 고쳐야 해요.

왜 문제인지 순서대로 볼게요. 학생을 등록하면 어떤 목록에 `add`를 해야 해요. 그런데 목록이 `students()` 안의 지역 변수라면, 메서드가 끝날 때 그 목록도 버려져요. 다음에 `GET /students`가 오면 메서드가 처음부터 다시 실행되면서 세 명짜리 새 목록을 만들어요. 등록한 학생은 어디에도 남지 않아요.

그래서 목록을 메서드 밖, 클래스 안으로 옮겨서 **필드**로 만들어요. `private final List<Student> studentList = new ArrayList<>();`예요. 필드는 객체가 살아 있는 동안 계속 남아 있어요. 그럼 컨트롤러 객체는 언제 만들어지고 언제 사라질까요? Spring은 서버가 켜질 때 `@Controller`가 붙은 클래스의 객체를 **하나** 만들어 두고, 서버가 꺼질 때까지 모든 요청에 그 객체를 다시 써요. 요청마다 새로 만들지 않아요. 그래서 필드에 담긴 목록이 요청과 요청 사이에 유지돼요.

처음 세 학생은 **생성자**에서 넣어요. 생성자는 객체를 만들 때 한 번 실행되는 특별한 메서드예요(01회차, 파이썬의 `__init__`). 컨트롤러 객체가 한 번만 만들어지니 생성자도 서버가 켜질 때 한 번만 실행돼요. 목록을 볼 때마다 실행되는 코드가 아니에요. 아래 바꿔 보기에서 직접 확인해요.

`final`은 `studentList`에 다른 목록을 다시 대입하지 못하게 막아요. 같은 목록에 `add`하는 것은 막지 않아요(01회차 6단계). 파이썬으로 보면 모듈 맨 위에 `student_list = []`를 두고 함수 안에서 `append`하는 것과 비슷하게, 함수가 끝나도 목록이 남는 자리에 둔 거예요.

### ▶ 직접 해 보기 — `StudentController.java` 1단계

파일 내용을 전부 바꾸고 ■ → ▶ 해요.

```java
package com.example.springpractice.controller;

import com.example.springpractice.model.Student;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;

import java.util.ArrayList;
import java.util.List;

@Controller
public class StudentController {

    private final List<Student> studentList = new ArrayList<>();

    public StudentController() {
        studentList.add(new Student(1, "한코딩", true));
        studentList.add(new Student(2, "이학생", false));
        studentList.add(new Student(3, "박학생", true));
    }

    @GetMapping("/students")
    public String students(Model model) {
        model.addAttribute("schoolName", "한코딩 스쿨");
        model.addAttribute("message", "함께 공부하는 학생들을 소개합니다.");
        model.addAttribute("students", studentList);

        return "students";
    }
}
```

`http://localhost:8080/students`를 열면 03과 똑같이 학생 3명이 보여요. 화면은 그대로이고 목록이 있는 자리만 바뀌었어요.

**바꿔 보기**: 생성자 첫 줄에 `System.out.println("StudentController 생성자 실행");`, `students()` 첫 줄에 `System.out.println("목록 조회: " + studentList.size() + "명");`을 넣고 ■ → ▶. 서버가 켜질 때 Run 창에 생성자 줄이 한 번 찍히고, 브라우저에서 새로고침할 때마다 조회 줄만 늘어나요. 두 번 새로고침했을 때 이렇게 나왔어요.

```text
StudentController 생성자 실행
목록 조회: 3명
목록 조회: 3명
```
확인하면 두 줄을 지워요.

## 2단계: 등록 폼 — `action`, `method`, `name`

🧭 React에서는 `<form onSubmit>` 안에서 `preventDefault()`로 제출을 막고 state에 넣었어요. 오늘은 제출을 막지 않아요. HTML 폼이 원래 하는 일, 즉 입력값을 서버로 보내고 새 페이지를 받는 동작을 그대로 써요. 그래서 JavaScript가 필요 없어요.

폼에는 세 가지를 정해요. `action`은 **어느 주소로** 보낼지, `method`는 **어떤 요청 메서드로** 보낼지, 입력창의 `name`은 그 값을 **어떤 이름으로** 보낼지예요. `<form th:action="@{/students}" method="post">`는 "`/students`로 POST 요청을 보낸다"는 뜻이에요. `th:action="@{...}"`는 03의 `th:href="@{/css/students.css}"`와 같은 URL 표현식이라, 서버가 처리하면 그냥 `action="/students"`가 돼요.

버튼을 누르면 브라우저는 폼 안 입력창 중 `name`이 있는 것만 모아 `name=입력값` 모양의 글자로 요청 본문에 담아 보내요. 한글은 `name=%EC%B5%9C...`처럼 바꿔서(인코딩) 보내요. 그래서 **`name`이 없는 입력창의 값은 서버로 가지 않아요.** `id="student-name"`은 `<label for="student-name">`과 입력창을 이어 주는 용도이고(글자 "학생 이름"을 누르면 입력창에 커서가 가요), 서버로 가는 이름과는 관계없어요.

`required`는 입력창이 비어 있으면 브라우저가 제출을 막고 안내 말풍선을 띄우게 해요. 하지만 스페이스만 친 값은 비어 있지 않다고 보고 통과시켜요. 브라우저 검사는 `curl`처럼 브라우저 밖에서 보내는 요청에는 아예 적용되지 않고요. 그래서 4단계에서 서버도 다시 검사해요.

폼만 만들고 서버 쪽은 아직 손대지 않았어요. 이 상태로 제출하면 어떻게 되는지 먼저 봐요.

## 3단계: `@PostMapping`과 `@RequestParam`으로 값을 받는다

🧭 03에서 `@GetMapping("/students")`는 "`GET /students` 요청을 이 메서드가 맡는다"였어요. 같은 주소의 POST 요청을 맡을 메서드를 하나 더 만들어요.

Spring은 요청이 오면 **주소와 요청 메서드를 함께 보고** 처리할 메서드를 골라요. 주소창에 `/students`를 치거나 새로고침하는 것은 GET이라 `students()`가, 폼을 제출하는 것은 POST라 `@PostMapping("/students")`가 붙은 메서드가 실행돼요. 주소가 같아도 서로 다른 메서드예요.

POST 메서드는 폼이 보낸 `name` 값을 받아야 해요. 매개변수 앞에 `@RequestParam(name = "name")`을 붙이면 Spring이 요청 본문에서 `name` 항목을 찾아 `String name` 변수에 넣어 줘요. 괄호 안의 `"name"`은 **요청에서 찾을 이름**(입력창의 `name` 속성)이고, 뒤의 `String name`은 **Java 변수 이름**이에요. 둘은 달라도 돼요. `@RequestParam(name = "hello") String name`이라고 쓰면 요청의 `hello` 값을 변수 `name`에 넣어요. 이때 입력창은 `name="hello"`여야 맞아요. 수업 코드가 이 모양이라 폼과 이름이 어긋났어요(바꿔 보기에서 일으켜 봐요).

`@RequestParam`은 기본으로 그 값이 **꼭 있어야** 해요. 요청에 그 이름이 없으면 메서드를 실행하지도 않고 400 오류(잘못된 요청)를 돌려줘요.

등록이 끝나면 `return "redirect:/students";`를 해요. `redirect:`로 시작하는 반환값은 템플릿 이름이 아니에요. Spring이 브라우저에게 "**`/students`로 다시 요청해**"라는 응답을 보내라는 뜻이에요. 실제 응답은 상태 코드 302와 `Location: http://localhost:8080/students` 헤더뿐이고 본문이 없어요. 브라우저는 이 응답을 받으면 스스로 `GET /students`를 새로 보내서 목록 화면을 받아요. 그래서 버튼을 누른 뒤에도 주소창은 `/students`이고 목록이 보여요.

이 단계에서는 이름이 제대로 도착하는지만 Run 창에 찍어 봐요. 아직 목록에 넣지는 않아요.

### ▶ 직접 해 보기 — `StudentController.java` 3단계

1단계 코드에 import 두 줄과 `addStudent` 메서드를 더해요. 아래는 파일 전체예요.

```java
package com.example.springpractice.controller;

import com.example.springpractice.model.Student;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestParam;

import java.util.ArrayList;
import java.util.List;

@Controller
public class StudentController {

    private final List<Student> studentList = new ArrayList<>();

    public StudentController() {
        studentList.add(new Student(1, "한코딩", true));
        studentList.add(new Student(2, "이학생", false));
        studentList.add(new Student(3, "박학생", true));
    }

    @GetMapping("/students")
    public String students(Model model) {
        model.addAttribute("schoolName", "한코딩 스쿨");
        model.addAttribute("message", "함께 공부하는 학생들을 소개합니다.");
        model.addAttribute("students", studentList);

        return "students";
    }

    @PostMapping("/students")
    public String addStudent(@RequestParam(name = "name") String name) {
        System.out.println("등록 요청 이름: " + name);

        return "redirect:/students";
    }
}
```

■ → ▶ 후 `최학생`을 등록하면 화면은 다시 학생 3명 목록이고, Run 창에 이 줄이 찍혀요.

```text
등록 요청 이름: 최학생
```

터미널에서 보면 302와 `Location`이 보여요. `--data-urlencode`는 브라우저처럼 한글을 인코딩해서 POST 본문으로 보내요.

```bash
curl -i --data-urlencode "name=최학생" http://localhost:8080/students
```

```text
HTTP/1.1 302
Location: http://localhost:8080/students
Content-Language: ko-KR
Content-Length: 0
```

`-L`을 붙이면 `curl`도 브라우저처럼 `Location`을 따라가서 `HTTP/1.1 302` 다음에 `HTTP/1.1 200`과 목록 HTML을 받아요.

**바꿔 보기** (하나씩 바꾸고 ■ → ▶, 확인하면 되돌려요)
- `@RequestParam(name = "name")`을 수업 코드처럼 `@RequestParam(name = "hello")`로 → 등록하면 `There was an unexpected error (type=Bad Request, status=400).`, Run 창에 `Required request parameter 'hello' for method parameter type String is not present`. 폼은 `name`을 보냈는데 서버는 `hello`를 찾았어요. 입력창을 `name="hello"`로 바꾸면 다시 돼요.
- `students.html`의 입력창에서 `name="name"` 줄을 지우고 등록 → 같은 400, 이번에는 `Required request parameter 'name' ...`. 이름을 쳐도 `name`이 없는 입력창의 값은 아예 보내지 않아요.
- 위 상태(입력창 `name` 없음)에서 `@RequestParam(name = "name")`을 지우고 `String name`만 남기면 → 400 대신 `등록 요청 이름: null`. `@RequestParam`을 생략하면 매개변수 이름과 같은 항목을 찾되, 없으면 `null`을 넣어요(수업 4장 코드 방식). 입력창의 `name`을 되살리면 다시 `최학생`이 찍혀요.

## 4단계: 목록에 추가하고 번호를 붙인다 — `nextId`, `trim()`

🧭 3단계에서 이름이 도착하는 것을 확인했어요. 이제 그 이름으로 `Student` 객체를 만들어 1단계의 필드 목록에 넣어요.

새 학생에게는 번호가 필요해요. 처음 세 명이 1~3번이니 다음은 4번이에요. 번호도 요청과 요청 사이에 기억해야 하니 필드로 둬요. `private int nextId = 4;`로 시작하고, 학생을 추가할 때 `nextId`를 번호로 쓴 뒤 `nextId++`로 하나 늘려요. 그러면 다음 학생은 5번이에요. 새 학생의 학습 여부는 우선 `false`(학습 예정)로 넣어요.

이름은 넣기 전에 검사해요. `name.trim()`은 앞뒤 공백을 지운 문자열을 돌려줘요(파이썬의 `strip()`). `"  정학생  "`은 `"정학생"`이 되고, `"   "`는 `""`가 돼요. 그다음 `isEmpty()`로 빈 문자열인지 봐요. 2단계에서 `required`가 공백만 있는 값을 통과시켰는데, 그 값을 여기서 걸러요. 브라우저를 거치지 않은 요청도 여기서 걸러져요. 서버는 어떤 요청이 와도 스스로 검사해야 해요.

`@RequestParam`에 `defaultValue = ""`도 더해요. 요청에 `name`이 아예 없으면 400을 내는 대신 빈 문자열을 넣으라는 뜻이에요. 그러면 빈 이름과 같은 길로 처리돼요.

이제 3단계의 `redirect`가 왜 중요한지 보여요. 등록 POST가 끝나고 브라우저가 마지막으로 받은 것은 `GET /students`의 화면이에요. 그래서 새로고침(F5)을 누르면 GET이 다시 가고, 학생이 또 추가되지 않아요. 만약 POST의 응답으로 바로 목록 화면을 돌려줬다면, 브라우저의 마지막 요청이 POST라서 새로고침할 때 그 POST를 다시 보내 같은 학생이 한 번 더 들어가요. 등록·수정처럼 데이터를 바꾸는 요청 뒤에는 이렇게 redirect로 GET 화면에 보내는 것이 기본이에요.

### ▶ 직접 해 보기 — `StudentController.java` 4단계

필드 한 줄을 더하고 `addStudent` 메서드를 통째로 바꿔요.

```java
    private final List<Student> studentList = new ArrayList<>();
    private int nextId = 4;
```

```java
    @PostMapping("/students")
    public String addStudent(
            @RequestParam(name = "name", defaultValue = "") String name
    ) {
        String trimmedName = name.trim();

        if (trimmedName.isEmpty()) {
            return "redirect:/students";
        }

        Student student = new Student(
                nextId,
                trimmedName,
                false
        );

        studentList.add(student);
        nextId++;

        return "redirect:/students";
    }
```

■ → ▶ 후 브라우저에서 차례로 등록해요: `최학생` → `  정학생  `(앞뒤에 스페이스) → 스페이스만 세 번. 표는 이렇게 돼요. "전체 학생: 5명"이고, 스페이스만 보낸 것은 추가되지 않았어요. 정학생의 앞뒤 공백도 지워졌어요.

```text
1  한코딩  학습 중
2  이학생  학습 예정
3  박학생  학습 중
4  최학생  학습 예정
5  정학생  학습 예정
```

이 상태에서 새로고침을 여러 번 눌러도 5명 그대로예요.

**바꿔 보기**
- `addStudent` 첫 줄에 `System.out.println("등록 요청 이름: [" + name + "]");`을 넣고 같은 순서로 등록 → Run 창에 `[최학생]`, `[  정학생  ]`, `[   ]`가 찍혀요. 서버에 도착한 값에는 공백이 그대로 있고, `trim()`이 지운 거예요.
- `nextId++;` 줄을 지우고 두 명 등록 → 두 학생 모두 번호가 `4`예요. 번호를 늘리지 않으면 계속 같은 값을 써요.
- 입력창의 `name="name"`을 지우고 등록 → 3단계와 달리 400이 아니에요. `defaultValue = ""` 덕분에 빈 이름으로 처리돼 아무도 추가되지 않고 목록으로 돌아와요.

## 5단계: 빈 이름이면 오류 문구와 함께 같은 화면을 보여 준다

🧭 4단계는 빈 이름을 조용히 무시해요. 사용자는 왜 추가가 안 됐는지 몰라요. 이유를 화면에 보여 줘요.

빈 이름일 때는 redirect하지 않고 바로 목록 화면을 돌려줘요. 먼저 `model.addAttribute("error", "학생 이름을 입력해주세요.")`로 오류 문구를 담아요. 그래서 `addStudent`도 매개변수로 `Model model`을 받아요. 그다음 `return students(model);`을 해요. 이것은 같은 클래스의 `students()` 메서드를 **보통 Java 메서드처럼 부른 것**이에요. 새 GET 요청을 보내는 게 아니에요. `students()`가 같은 `model`에 학교 이름·안내 문구·학생 목록을 더 담고 `"students"`를 돌려주니, 그 값을 그대로 돌려주면 오류 문구가 담긴 목록 화면이 만들어져요.

템플릿에는 오류 문구 자리를 만들어요. `th:if="${error != null}"`이라서 `Model`에 `error`가 있을 때만 이 `<p>`가 HTML에 들어가요. 정상적인 `GET /students`에서는 `error`를 넣지 않으니 아예 안 보여요. `role="alert"`는 화면 낭독기가 이 문구를 바로 읽어 주게 하는 속성이에요.

한 가지 주의할 점이 있어요. `return "students";`만 쓰면 안 돼요. 그러면 템플릿 이름은 맞지만, `students()`를 거치지 않아서 `Model`에 학생 목록이 없어요. 템플릿의 `#lists.size(students)`가 빈 값을 받아 500 오류가 나요(바꿔 보기).

### ▶ 직접 해 보기 — 강의 최종 코드

`StudentController.java` 전체예요.

```java
package com.example.springpractice.controller;

import com.example.springpractice.model.Student;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestParam;

import java.util.ArrayList;
import java.util.List;

@Controller
public class StudentController {

    private final List<Student> studentList = new ArrayList<>();
    private int nextId = 4;

    public StudentController() {
        studentList.add(new Student(1, "한코딩", true));
        studentList.add(new Student(2, "이학생", false));
        studentList.add(new Student(3, "박학생", true));
    }

    @GetMapping("/students")
    public String students(Model model) {
        model.addAttribute("schoolName", "한코딩 스쿨");
        model.addAttribute(
                "message",
                "함께 공부하는 학생들을 소개합니다."
        );
        model.addAttribute("students", studentList);

        return "students";
    }

    @PostMapping("/students")
    public String addStudent(
            @RequestParam(name = "name", defaultValue = "") String name,
            Model model
    ) {
        String trimmedName = name.trim();

        if (trimmedName.isEmpty()) {
            model.addAttribute(
                    "error",
                    "학생 이름을 입력해주세요."
            );

            return students(model);
        }

        Student student = new Student(
                nextId,
                trimmedName,
                false
        );

        studentList.add(student);
        nextId++;

        return "redirect:/students";
    }
}
```

`students.html`에서 안내 문구 `<p th:text="${message}">` 바로 아래, `<form` 위에 넣어요.

```html
    <p class="error-message"
       role="alert"
       th:if="${error != null}"
       th:text="${error}">
        오류 안내
    </p>
```

■ → ▶ 후 스페이스만 치고 등록하면 입력창 위에 빨간 "학생 이름을 입력해주세요."가 나오고, 목록은 그대로 3명이에요. 이번에는 redirect가 아니라 POST의 응답으로 화면이 바로 와요. 터미널로 보면 302가 아니라 200이고, 받은 HTML에 이 부분이 들어 있어요.

```bash
curl -i --data-urlencode "name=   " http://localhost:8080/students
```

```text
HTTP/1.1 200
...
    <p class="error-message"
       role="alert">학생 이름을 입력해주세요.</p>
```

주소창으로 `http://localhost:8080/students`를 다시 열면 오류 문구는 없어요. 받은 HTML에 `error-message`가 아예 없어요.

**바꿔 보기** (하나씩 바꾸고 ■ → ▶, 확인하면 되돌려요)
- `return students(model);`을 `return "students";`로 → 스페이스만 등록하면 500 오류 화면. Run 창에 `Exception evaluating SpringEL expression: "#lists.size(students)" (template: "students" - line 42, col 17)`와 `Cannot get list size of null`. `students()`를 부르지 않아 `Model`에 학생 목록이 없어요.
- 3단계의 메서드를 지우지 않고 남겨 둔 것처럼, `@PostMapping("/students")` 메서드를 하나 더 붙여 넣기 → 서버가 켜지지 않아요. Run 창에 `Ambiguous mapping. Cannot map 'studentController' method ... to {POST [/students]}: There is already 'studentController' bean method ... mapped.` 같은 주소·메서드를 맡는 메서드는 하나만 있어야 해요.
- `@Controller`를 `@RestController`로 (import도 `org.springframework.web.bind.annotation.RestController`로) → 등록하면 화면에 `redirect:/students` 글자만, 목록 주소에는 `students` 글자만 나와요. `@RestController`는 돌려준 문자열을 그대로 응답 본문으로 보내요(03회차).

## 6단계: 서버를 다시 켜면 — 메모리에 있는 목록의 한계

🧭 1단계에서 목록이 "컨트롤러 객체가 살아 있는 동안" 유지된다고 했어요. 그럼 객체가 사라지면 어떻게 될까요?

서버를 멈추면 서버 프로그램이 쓰던 메모리가 모두 비워져요. 컨트롤러 객체도, 그 안의 `studentList`도, `nextId`도 사라져요. 다시 켜면 Spring이 컨트롤러 객체를 새로 만들고, 생성자가 처음 세 명만 다시 넣어요. 그래서 등록한 학생은 모두 사라져요.

반대로 서버가 켜져 있는 동안에는 이 목록 하나를 모든 요청이 함께 써요. 다른 브라우저(예: Safari)로 접속해도 Chrome에서 등록한 학생이 보여요. 사용자마다 따로 있는 목록이 아니에요.

### ▶ 직접 해 보기 — 재시작

1. `최학생`, `정학생`을 등록해서 "전체 학생: 5명"을 확인해요.
2. ■로 멈추고 ▶로 다시 켜요.
3. 새로고침하면 "전체 학생: 3명", 1~3번만 남아요.

```text
1  한코딩  학습 중
2  이학생  학습 예정
3  박학생  학습 중
```

서버를 꺼도 남게 하려면 데이터를 메모리가 아닌 곳에 저장해야 해요. 05회차에서 데이터베이스(H2)에 저장해요.

## 마무리: 이름 하나를 등록하면 일어나는 일

1. 서버가 켜질 때 Spring이 `StudentController` 객체를 하나 만들어요. 생성자가 학생 3명을 `studentList` 필드에 넣고, `nextId`는 4예요.
2. 브라우저가 `GET /students`를 보내요. `students()`가 `Model`에 학교 이름·안내 문구·목록을 담고 `"students"`를 돌려줘요. Thymeleaf가 `students.html`로 폼과 표가 있는 HTML을 만들어 보내요.
3. 사용자가 입력창에 `최학생`을 쓰고 **학생 등록**을 눌러요. 브라우저가 `required`를 검사하고, 통과하면 `name=%EC%B5%9C...` 본문과 함께 `POST /students`를 보내요.
4. Spring이 주소와 POST를 보고 `addStudent()`를 골라요. `@RequestParam`이 본문의 `name` 값을 꺼내 `name` 변수에 넣어요.
5. `trim()`으로 공백을 지우고 `isEmpty()`로 검사해요. 비었으면 `error`를 담고 `students(model)`을 불러 오류 문구가 있는 화면을 200으로 바로 돌려줘요(여기서 끝).
6. 비어 있지 않으면 `new Student(4, "최학생", false)`를 만들어 목록에 넣고 `nextId`를 5로 늘려요.
7. `"redirect:/students"`를 돌려주면 Spring이 302와 `Location: http://localhost:8080/students`를 보내요.
8. 브라우저가 `GET /students`를 새로 보내고, 2번과 같은 과정으로 4명짜리 목록 화면을 받아요. 이제 새로고침해도 GET만 다시 가요.

## 다음 회차와 연결

오늘 목록은 컨트롤러 필드, 즉 서버 메모리에 있어서 재시작하면 사라졌어요. 05회차에서는 이 목록을 **H2 데이터베이스**로 옮겨요. 폼과 `students.html`, CSS는 오늘 것 그대로 쓰고, 컨트롤러의 `studentList.add(...)`가 `studentRepository.save(...)`로, `studentList`가 `studentRepository.findAll()`로 바뀌어요. 번호도 데이터베이스가 붙여 줘서 `nextId`와 생성자의 학생 3명은 지워요. `trim()` 검사와 오류 문구, `redirect`는 그대로 남아요.

## 오류가 날 때 찾아보기

| 오류 문장 · 증상 | 먼저 볼 곳 |
|---|---|
| 등록 버튼을 누르면 405, `Request method 'POST' is not supported` | `@PostMapping("/students")` 메서드가 있는지 (2·3단계) |
| 400, `Required request parameter 'hello' ... is not present` | `@RequestParam(name = "…")`의 이름과 입력창 `name`이 같은지 (3단계) |
| 400, `Required request parameter 'name' ... is not present` | 입력창에 `name="name"`이 있는지, `defaultValue = ""` (3·4단계) |
| Run 창에 `등록 요청 이름: null` | `@RequestParam` 없이 받는데 입력창 `name`이 없음 (3단계) |
| 등록했는데 목록에 안 보임 | 목록을 `students()` 안에서 새로 만들고 있지 않은지, `studentList.add` (1·4단계) |
