## 들어가며

Node 과정에서는 JavaScript로 서버를 만들었어요. 학생 배열을 JSON으로 돌려주는 서버와, 그걸 받아 목록을 그리는 React 화면이었죠.

Spring 과정에서는 같은 서버를 Java로 만들어요. React 쪽은 그대로이고, Spring 06에서는 Node 04의 `StudentList.jsx`를 주소만 바꿔 다시 써요. 같은 서버를 또 만드는 이유는 두 가지예요. 국내 회사 백엔드는 Java + Spring을 많이 쓰고, Spring 과정에서는 Node 과정에 없던 폼으로 학생 등록하기(04)와 데이터베이스에 저장하기(05)도 해요.

Spring은 Java로 서버를 만들 때 쓰는 도구(프레임워크)라서, 먼저 Java 문법을 알아야 해요. 그래서 01에서는 서버 없이, 콘솔에 글자를 출력하는 Java 프로그램으로 문법만 익혀요. Node 02에서 서버 전에 콘솔 프로그램을 먼저 만든 것과 같은 순서예요.

목표는 하나예요. 학생 정보를 담는 `Student`를 만들고, 학생 여러 명을 목록에 담아 출력하는 거예요. 이 `Student`는 02~06에서 계속 쓰여요.

파이썬을 알고 있으니 개념은 대부분 익숙할 거예요. 변수, 함수, 클래스, 리스트, 반복문, 조건문 모두 파이썬에 있던 것들이에요. 달라지는 건 쓰는 방법이에요. 단계마다 파이썬과 무엇이 같고 무엇이 다른지 같이 설명할게요.

팀 프로젝트(실시간 채팅)는 Node.js라서 Java는 직접 쓰지 않아요. 다만 "데이터에 어떤 값이 있는지 먼저 정한다"는 오늘의 생각은, 팀에서 메시지·채팅방 데이터 모양을 정할 때도 똑같이 해요.

## 1단계: Java 프로그램이 실행되는 과정

파이썬은 `python 파일.py`를 치면 파일을 위에서부터 한 줄씩 읽으면서 바로 실행해요. Node도 같았어요.

Java는 실행 전에 **컴파일**이라는 단계를 먼저 거쳐요. 컴파일러가 `.java` 파일 전체를 읽고 문법과 자료형이 맞는지 검사해요. 문제가 없으면 JVM이 실행할 수 있는 형태(바이트코드, `.class` 파일)로 바꿔요. 그다음 **JVM**이 그 파일을 실행해요.

이 순서 때문에 중요한 차이가 생겨요. 파이썬은 10번째 줄에 오류가 있어도 1~9번째 줄은 실행돼요. 오류가 있는 줄에 도착해야 멈추니까요. Java는 컴파일 단계에서 오류를 발견하면 실행 자체를 하지 않아요. 오류가 한 군데라도 있으면 한 줄도 실행되지 않아요. 대신 실행하기 전에 실수를 알 수 있어요.

도구 이름도 정리해 둘게요. **JDK**는 컴파일러와 실행 프로그램이 들어 있는 Java 개발 도구 모음이에요. **JVM**은 컴파일된 파일을 실행하는 프로그램이에요. **IntelliJ**는 코드를 쓰는 편집기인데, ▶ 버튼을 누르면 컴파일과 실행을 한 번에 해 줘요. 실행 전에도 틀린 곳에 빨간 밑줄을 그어 줘요.

Java 프로그램의 가장 작은 모양은 아래 예시와 같아요. 파이썬이라면 `print("안녕하세요")` 한 줄이면 되는데, Java는 감싸는 줄이 많아요. Java의 규칙 세 가지 때문이에요.

첫째, Java에서는 모든 코드가 **클래스** 안에 있어야 해요. 파이썬처럼 파일 맨 위에 바로 명령을 쓸 수 없어요. 그래서 `public class Main { }`으로 감싸요. 이때 `public` 클래스의 이름은 **파일 이름과 같아야** 해요. `Main.java` 파일 안에는 `public class Main`이 있어야 하고, 다르면 컴파일 오류가 나요.

둘째, 프로그램은 `main`이라는 메서드에서 시작해요. `public static void main(String[] args)`가 그 시작점이에요. 이 줄의 단어들은 뒤에서 조금씩 나오니까, 지금은 "시작점은 이렇게 쓴다"로 외워 두면 돼요.

셋째, 파이썬은 들여쓰기로 블록을 나눴지만 Java는 `{ }`로 나눠요. 들여쓰기는 보기 좋으라고 하는 것이고 문법에는 영향이 없어요. 그리고 문장이 끝날 때마다 `;`를 붙여요. 빠뜨리기 쉬운데, IntelliJ에서 `Cmd + Shift + Enter`를 누르면 그 줄 끝에 `;`를 붙여 줘요.

`System.out.println(...)`은 파이썬의 `print`예요. 출력하고 줄을 바꿔요. 줄을 바꾸지 않으려면 `System.out.print(...)`를 써요.

### ▶ 직접 해 보기 — `Main.java`
IntelliJ가 만들어 준 `Main.java`의 내용을 전부 바꾸고 실행해요.
```java
public class Main {
    public static void main(String[] args) {
        System.out.println("안녕하세요, 한코딩입니다!");
    }
}
```
```text
안녕하세요, 한코딩입니다!
```
**바꿔 보기**: `public class Main`을 `public class Hello`로 바꾸고 실행하면, 파일 이름과 클래스 이름이 달라서 이 오류가 나요. 확인하고 되돌려요.
```text
class Hello is public, should be declared in a file named Hello.java
```

## 2단계: 변수에 자료형을 적는다

파이썬에서는 `age = 25`라고 쓰면 변수가 생기고, 나중에 `age = "스물다섯"`처럼 문자열을 넣어도 괜찮았어요.

Java에서는 변수를 만들 때 그 변수에 **어떤 종류의 값을 넣을지** 먼저 적어요. 이 종류를 **자료형**이라고 해요. `String`은 문자열, `int`는 정수, `double`은 소수가 있는 실수, `boolean`은 참·거짓이에요. 파이썬의 `str`, `int`, `float`, `bool`에 해당해요. 참·거짓은 `true`, `false`처럼 소문자로 써요.

한 번 `int`로 만든 변수에는 정수만 넣을 수 있어요. `age = "스물여섯";`이라고 쓰면 컴파일러가 "String을 int로 바꿀 수 없다"는 오류를 내고, 프로그램은 실행되지 않아요. 파이썬이었다면 이 줄은 그냥 지나가고, 나중에 `age + 1`을 계산할 때가 돼서야 오류가 났을 거예요. Java가 자료형을 적게 하는 이유가 이거예요. 서버는 많은 데이터를 다루기 때문에, 값의 종류가 섞이는 실수를 실행 전에 잡는 게 중요해요.

이미 만든 변수의 값을 바꿀 때는 자료형을 다시 쓰지 않아요. `age = 26;`처럼 써요. `int age = 26;`이라고 또 쓰면 같은 이름의 변수를 한 번 더 만들려는 것이 되어 "이미 있는 변수"라는 오류가 나요.

문자열은 반드시 큰따옴표로 감싸요. 파이썬은 작은따옴표도 문자열이었지만, Java에서 작은따옴표는 글자 하나(`char`)를 뜻해요. `'한코딩'`이라고 쓰면 오류예요.

문자열과 다른 값을 `+`로 이으면 Java가 알아서 글자로 바꿔서 이어 줘요. `"나이: " + 25`는 `"나이: 25"`가 돼요. 파이썬에서는 이렇게 하면 `TypeError`가 나서 `str(25)`로 바꿔야 했죠. 이 부분은 Java가 더 편해요.

마지막으로 `final`이 있어요. 변수 앞에 `final`을 붙이면 처음 넣은 값을 다시 바꿀 수 없어요. JavaScript의 `const`와 같아요. 파이썬에는 이렇게 막아 주는 기능이 없어요. 바뀌면 안 되는 값에 붙여 두면, 실수로 바꾸는 코드를 썼을 때 컴파일 오류가 나요.

### ▶ 직접 해 보기 — `Basics.java`
```java
public class Basics {
    public static void main(String[] args) {
        String name = "한코딩";    // 문자열
        int age = 25;              // 정수
        boolean learning = true;   // 참·거짓
        double pi = 3.14;          // 실수

        System.out.println("이름: " + name);
        System.out.println("나이: " + age);
        System.out.println("학습 중: " + learning);
        System.out.println("원주율: " + pi);

        age = 26;                  // 값 바꾸기: 자료형을 다시 쓰지 않아요
        System.out.println("내년 나이: " + age);

        final String schoolName = "한코딩 스쿨";   // 다시 대입할 수 없어요
        System.out.println("학교: " + schoolName);
    }
}
```
```text
이름: 한코딩
나이: 25
학습 중: true
원주율: 3.14
내년 나이: 26
학교: 한코딩 스쿨
```
**바꿔 보기**: 하나씩 바꿔서 실행하고, 오류를 확인한 뒤 되돌려요. 오류가 나면 위쪽의 정상 출력도 하나도 안 나와요. 컴파일에서 멈췄기 때문이에요.
- `age = 26;`을 `age = "스물여섯";`으로 → `incompatible types: String cannot be converted to int`
- `int age = 25;`의 `;`를 지우기 → `';' expected`
- `age = 26;`을 `int age = 26;`으로 → `variable age is already defined in method main(String[])`
- `"한코딩"`을 `'한코딩'`으로 → `unclosed character literal`
- 마지막 `println` 줄을 `schoolName = "다른 학교";`로 → `cannot assign a value to final variable schoolName`

## 3단계: 메서드 — 받는 값과 돌려주는 값의 자료형을 적는다

Java에서는 함수를 **메서드**라고 불러요. 모든 코드가 클래스 안에 있으니 함수도 클래스 안에 있고, 클래스 안의 함수를 메서드라고 부르는 거예요. 하는 일은 파이썬의 `def`와 같아요.

차이는 2단계와 같은 이유로 생겨요. 메서드도 **무엇을 받고 무엇을 돌려주는지** 자료형을 적어요. `public static int add(int num1, int num2)`에서 이름 `add` 앞의 `int`는 "이 메서드는 정수를 돌려준다"는 뜻이에요. 괄호 안의 `int num1, int num2`는 "정수 두 개를 받는다"는 뜻이고요. 파이썬의 `def add(num1, num2): return num1 + num2`와 같은 메서드예요.

자료형을 적어 두었기 때문에 Java가 검사해 줘요. `add("10", 20)`처럼 문자열을 넘기면 컴파일 오류가 나요. 파이썬에서는 `add("10", "20")`이 오류 없이 `"1020"`을 돌려줬을 거예요. `return "합계";`처럼 약속과 다른 종류의 값을 돌려주려 해도 오류가 나요.

돌려줄 값이 없는 메서드는 자료형 자리에 `void`를 써요. 메뉴를 출력만 하는 메서드처럼요. 1단계의 `main`에도 `void`가 붙어 있었죠. `main`도 돌려주는 값이 없는 메서드이기 때문이에요.

꼭 구분해야 할 것이 있어요. **`return`은 값을 돌려줄 뿐 출력하지 않아요.** `String message = createGreeting("한코딩");`으로 받은 다음 `System.out.println(message);`를 해야 화면에 보여요. `createGreeting("한코딩");`만 쓰면 메서드는 실행되지만, 돌려받은 문장을 아무 데도 쓰지 않았으니 아무것도 출력되지 않아요. 파이썬 스크립트에서 `add(1, 2)`만 쓰면 아무것도 안 보이는 것과 같아요.

메서드 앞의 `static`은 지금 단계에서는 "`main`과 같은 클래스 안에 만들고 `main`에서 바로 부를 때 붙인다"고만 알아 두면 돼요. `main`이 `static`이라서 같이 붙여야 해요.

나중에 Spring에서는 "이 주소로 요청이 오면 이 메서드를 실행한다"는 식으로 메서드를 써요. Node에서 `app.get("/students", 함수)`의 함수 자리에 해당하는 것이 Spring에서는 메서드예요.

### ▶ 직접 해 보기 — `Methods.java`
```java
public class Methods {

    // 두 정수를 받아 합을 돌려줘요
    public static int add(int num1, int num2) {
        return num1 + num2;
    }

    // 이름을 받아 인사 문장을 돌려줘요
    public static String createGreeting(String name) {
        return name + "님, 반갑습니다!";
    }

    // 돌려줄 값이 없어요 (void). 출력만 해요
    public static void printMenu() {
        System.out.println("1. 학생 등록");
        System.out.println("2. 학생 목록");
        System.out.println("0. 프로그램 종료");
    }

    public static void main(String[] args) {
        int result = add(10, 20);
        System.out.println(result);

        String message = createGreeting("한코딩");
        System.out.println(message);

        createGreeting("이학생");   // 돌려받은 값을 쓰지 않으면 아무것도 안 보여요

        printMenu();
    }
}
```
```text
30
한코딩님, 반갑습니다!
1. 학생 등록
2. 학생 목록
0. 프로그램 종료
```
`createGreeting("이학생");` 줄도 실행은 되지만, 출력에는 아무것도 나오지 않은 걸 확인해요.

**바꿔 보기**
- `return num1 + num2;`를 `return "합계";`로 → `incompatible types: String cannot be converted to int` (약속한 `int`가 아니라서)
- `add(10, 20)`을 `add("10", 20)`으로 → 같은 오류

## 4단계: 클래스로 학생의 모양을 정한다

Node에서는 학생을 `{ id: 1, name: "한코딩" }`처럼 바로 만들었어요. Java에서는 객체를 만들기 전에 먼저 **클래스**로 "학생은 이런 값들을 가진다"를 정해야 해요. 파이썬의 `class`와 같은 생각이에요.

파이썬이라면 이렇게 썼을 거예요.

```python
class Student:
    def __init__(self, id, name, learning):
        self.id = id
        self.name = name
        self.learning = learning
```

Java로 쓰면 이렇게 돼요.

```java
public class Student {
    private int id;
    private String name;
    private boolean learning;

    public Student(int id, String name, boolean learning) {
        this.id = id;
        this.name = name;
        this.learning = learning;
    }
}
```

위에서부터 차례로 볼게요.

맨 위 세 줄이 **필드**예요. 학생 객체 하나하나가 가지는 값이에요. 파이썬에서는 `__init__` 안에서 `self.id = id`를 할 때 필드가 생겼지만, Java에서는 클래스 맨 위에 **자료형과 함께 미리** 적어 둬요. 2단계에서 변수에 자료형을 적었던 것과 같은 이유예요.

필드 앞의 `private`은 "이 클래스 밖에서는 이 필드를 직접 읽거나 바꿀 수 없다"는 뜻이에요. 파이썬에도 `_name`처럼 밑줄을 붙여 "건드리지 말자"고 표시하는 관례가 있지만, 그건 약속일 뿐 실제로 막지는 않아요. Java의 `private`은 컴파일러가 실제로 막아요. 다른 클래스에서 `student.name`을 읽으려 하면 컴파일 오류가 나요.

그 아래 `public Student(...)` 부분이 **생성자**예요. 객체를 만들 때 한 번 실행되는 특별한 메서드로, 파이썬의 `__init__`과 같은 역할을 해요. 생성자는 두 가지가 일반 메서드와 달라요. 이름이 클래스 이름과 똑같고, 앞에 돌려줄 값의 자료형(`int`, `void` 등)을 쓰지 않아요.

생성자 안의 `this.id = id;`는 파이썬의 `self.id = id`와 같아요. 왼쪽 `this.id`는 "지금 만들어지고 있는 이 객체의 id 필드"이고, 오른쪽 `id`는 생성자가 받은 값이에요. 받은 값을 객체의 필드에 저장하는 거예요. 파이썬은 `self`를 매개변수에 직접 적었지만, Java의 `this`는 적지 않아도 항상 쓸 수 있어요.

클래스를 만들었으면 `new`로 객체를 만들어요. `Student s1 = new Student(1, "한코딩", true);`에서 `Student s1`은 "`Student` 자료형의 변수 `s1`"이에요. 직접 만든 클래스도 `int`나 `String`처럼 자료형으로 쓸 수 있어요. `new Student(1, "한코딩", true)`는 생성자를 실행해서 새 객체를 만들어요. 파이썬에서는 `Student(1, "한코딩", True)`처럼 `new` 없이 썼죠.

같은 클래스로 객체를 여러 개 만들면, 각 객체는 자기 필드 값을 따로 가져요. `s1`의 이름을 바꿔도 `s2`의 이름은 그대로예요.

생성자에 넘기는 값은 개수, 순서, 자료형이 생성자와 정확히 맞아야 해요. 하나를 빼먹으면 "생성자에 맞지 않는다"는 오류가 나요. 오류 아래에 `required`(필요한 것)와 `found`(넣은 것)가 나오니까, 두 줄을 비교하면 뭐가 빠졌는지 알 수 있어요.

하나 더 알아 둘 것이 있어요. 생성자를 직접 만들면 `new Student()`처럼 빈 괄호로는 객체를 만들 수 없어요. Java는 클래스에 생성자가 하나도 없을 때만 빈 생성자를 자동으로 만들어 주기 때문이에요.

직접 해 보기는 5단계에서 getter까지 넣은 다음에 해요.

## 5단계: getter·setter로 필드를 다룬다

4단계에서 필드를 `private`으로 막았으니, 밖에서 학생의 이름을 알 방법이 없어요. 그래서 필드를 읽고 바꾸는 **메서드**를 클래스 안에 따로 만들어요.

```java
public String getName() {
    return name;
}

public void setName(String name) {
    this.name = name;
}
```

`getName()`처럼 필드 값을 돌려주는 메서드를 **getter**, `setName()`처럼 필드 값을 바꾸는 메서드를 **setter**라고 해요. 밖에서는 `s1.getName()`으로 이름을 읽고, `s1.setName("파이썬")`으로 이름을 바꿔요.

필드를 그냥 열어 두지 않고 이렇게 하는 이유가 있어요. 메서드를 거치게 하면 그 안에서 검사를 할 수 있어요. 예를 들어 setter 안에 "번호가 음수면 저장하지 않는다"는 `if`를 넣을 수 있어요. 필드를 직접 바꾸게 두면 이런 검사를 할 곳이 없어요. 이렇게 필드는 막아 두고 메서드로만 다루게 하는 것을 **캡슐화**라고 해요.

이름 짓는 규칙이 정해져 있어요. getter는 `get` + 필드 이름(첫 글자 대문자)이에요. `getId`, `getName`처럼요. 단, `boolean` 필드는 `get` 대신 `is`를 붙여서 `isLearning`이라고 써요. setter는 `set` + 필드 이름으로 `setName`처럼 써요.

이 규칙은 Spring에서도 중요해요. Spring은 학생 객체를 JSON으로 바꾸거나 화면에 이름을 넣을 때, 이 이름 규칙에 맞는 getter를 찾아서 써요. 강의 코드 중에 `getLearning()`을 부른 곳이 있는데, 클래스에는 `isLearning()`만 있어서 `cannot find symbol`(그런 메서드가 없다) 오류가 나요.

getter와 setter를 일일이 쓰는 건 번거로워요. IntelliJ에서 클래스 안에 커서를 두고 `Cmd + N`을 누른 뒤 Getter and Setter를 고르면 자동으로 만들어 줘요.

마지막으로 `toString()`이에요. 객체를 `System.out.println(s1)`처럼 그대로 출력하면 `Student@5cad8086` 같은 알아보기 힘든 글자가 나와요. Java의 모든 객체에는 기본 `toString()` 메서드가 있는데, 기본 버전은 클래스 이름과 알 수 없는 숫자를 돌려주기 때문이에요. 클래스 안에 `toString()`을 직접 만들어 두면 `println`이 그걸 써서 `Student{id=1, name='한코딩', learning=true}`처럼 보여 줘요. 파이썬의 `__str__`과 같아요. 직접 만든 `toString()` 위에 붙는 `@Override`는 "원래 있던 메서드를 내가 새로 정의한다"는 표시예요.

### ▶ 직접 해 보기 — `Student.java`, `StudentTest.java`
4단계의 필드·생성자에 5단계의 getter, setter, `toString()`을 합친 학생 클래스예요. `main`이 없어서 혼자서는 실행할 수 없어요.
```java
// 학생 한 명의 정보를 담는 클래스
public class Student {

    // 필드: 객체마다 따로 갖는 값
    private int id;
    private String name;
    private boolean learning;

    // 생성자: new Student(...)를 할 때 실행돼요
    public Student(int id, String name, boolean learning) {
        this.id = id;              // this.id = 이 객체의 필드, id = 전달받은 값
        this.name = name;
        this.learning = learning;
    }

    // getter: 필드 값을 밖에서 읽게 해 줘요
    public int getId() {
        return id;
    }

    public String getName() {
        return name;
    }

    public boolean isLearning() {  // boolean은 get 대신 is로 시작해요
        return learning;
    }

    // setter: 필드 값을 밖에서 바꾸게 해 줘요
    public void setName(String name) {
        this.name = name;
    }

    // System.out.println(객체)를 할 때 보여 줄 글자
    @Override
    public String toString() {
        return "Student{id=" + id + ", name='" + name + "', learning=" + learning + "}";
    }
}
```
이 클래스로 객체를 만들어 보는 파일이에요. 이걸 실행해요.
```java
public class StudentTest {
    public static void main(String[] args) {
        Student s1 = new Student(1, "한코딩", true);
        Student s2 = new Student(2, "이학생", false);

        System.out.println("번호: " + s1.getId());
        System.out.println("이름: " + s1.getName());
        System.out.println("학습 중: " + s1.isLearning());

        System.out.println("두 번째 학생: " + s2.getName());   // 객체마다 값이 따로예요

        s1.setName("파이썬");
        System.out.println("바꾼 이름: " + s1.getName());

        System.out.println(s1);   // toString()이 돌려준 글자가 찍혀요
    }
}
```
```text
번호: 1
이름: 한코딩
학습 중: true
두 번째 학생: 이학생
바꾼 이름: 파이썬
Student{id=1, name='파이썬', learning=true}
```
`s1`의 이름을 바꿨는데 `s2`는 그대로인 것도 확인해요.

**바꿔 보기**
- `StudentTest`에서 `s1.getId()`를 `s1.name`으로 → `name has private access in Student`
- `new Student(2, "이학생", false)`에서 `, false`를 빼기 → `constructor Student in class Student cannot be applied to given types;` 아래에 `required: int,String,boolean` / `found: int,String`
- `s1.isLearning()`을 `s1.getLearning()`으로 → `cannot find symbol` / `symbol: method getLearning()`
- `Student.java`에서 `@Override`부터 `toString` 끝까지 지우고 `StudentTest` 실행 → 마지막 줄이 `Student@5cad8086`처럼 바뀌어요 (숫자는 매번 달라요)

## 6단계: 학생 여러 명을 List에 담는다

학생이 여러 명이면 목록이 필요해요. 파이썬은 `list`, JavaScript는 배열을 썼죠. Java에서는 `List`를 써요.

```java
List<Student> students = new ArrayList<>();
```

`List<Student>`는 "`Student` 객체만 담는 목록"이라는 자료형이에요. `< >` 안에 담을 자료형을 적어요. 파이썬 리스트에는 숫자, 문자열, 객체를 섞어 넣을 수 있었지만, Java의 `List<Student>`에는 학생 객체만 넣을 수 있어요. 2단계부터 계속 나온 "자료형을 정해 두고 그 종류만 받는다"는 규칙이 목록에도 적용되는 거예요.

오른쪽의 `new ArrayList<>()`는 실제로 빈 목록을 만드는 코드예요. `List`는 "목록이라면 이런 기능이 있어야 한다"는 규칙이고, `ArrayList`는 그 규칙대로 만들어진 실제 목록이에요. 지금은 깊이 알 필요 없이 "List를 만들 때는 `new ArrayList<>()`를 쓴다"고 외워 두면 돼요.

`List`와 `ArrayList`는 Java에 기본으로 들어 있지만 `java.util`이라는 묶음 안에 있어요. 그래서 쓰려면 파일 맨 위에 `import java.util.ArrayList;`, `import java.util.List;`를 써야 해요. 파이썬의 `import`와 같아요. 이 줄을 빼먹으면 "List가 뭔지 모르겠다"는 오류가 나요. IntelliJ에서 빨간 `List` 위에 커서를 두고 `Option + Enter`를 누르면 import 줄을 자동으로 넣어 줘요.

목록을 다루는 메서드는 파이썬과 하나씩 짝이 맞아요.

| 하는 일 | 파이썬 | Java |
|---|---|---|
| 추가 | `append` | `add` |
| 개수 | `len()` | `size()` |
| 0번 꺼내기 | `[0]` | `get(0)` |
| 0번 지우기 | `pop(0)` | `remove(0)` |

인덱스가 0부터 시작하는 것도 같아요. `remove(0)`은 "id가 0인 학생"이 아니라 "목록의 0번째 자리"를 지워요.

2단계에서 본 `final`을 목록에 붙이면 어떻게 될까요? `final List<Student> students`라고 쓰면 `students`에 **다른 목록을 대입하는 것**은 막혀요. 하지만 같은 목록에 학생을 `add`하거나 `remove`하는 건 돼요. `final`은 변수가 가리키는 대상을 바꾸지 못하게 할 뿐, 그 대상의 내용까지 막지는 않기 때문이에요. JavaScript에서 `const arr = []`에 `push`는 되던 것과 같아요.

## 7단계: 목록을 하나씩 돌면서 처리한다

목록에 담긴 학생을 하나씩 출력할 때는 **향상된 for문**을 써요.

```java
for (Student student : students) {
    System.out.println(student.getId() + ". " + student.getName());
}
```

"`students`에서 하나씩 꺼내 `student`라는 이름으로 쓴다"로 읽어요. 파이썬의 `for student in students:`와 같아요. `in` 자리에 `:`를 쓰고, 꺼낸 값의 자료형(`Student`)을 앞에 적는 것만 달라요.

조건문 `if`는 조건을 괄호로 감싸고, 실행할 코드를 `{ }`로 감싸요. 학습 중인 학생만 출력하려면 for문 안에 `if (student.isLearning()) { … }`를 넣어요.

목록이 비어 있는지는 `students.isEmpty()`로 확인해요. 비었으면 `true`를 돌려줘요. 파이썬에서 `if not students:`로 확인하던 것과 같아요.

### ▶ 직접 해 보기 — `StudentApp.java` (강의 최종 코드)
6단계와 7단계를 모두 쓰는 강의 최종 프로그램이에요. 강의의 `Main.java`와 같고, 1단계의 `Main.java`를 남겨 두려고 클래스 이름만 `StudentApp`으로 바꿨어요. 5단계의 `Student.java`를 그대로 써요.
```java
import java.util.ArrayList;
import java.util.List;

public class StudentApp {

    public static String createGreeting(String name) {
        return name + "님, 반갑습니다!";
    }

    public static void printStudents(List<Student> students) {
        System.out.println("\n[학생 목록]");

        if (students.isEmpty()) {
            System.out.println("등록된 학생이 없습니다.");
            return;
        }

        for (Student student : students) {
            System.out.println(
                    student.getId() + ". " + student.getName()
            );
        }
    }

    public static void main(String[] args) {
        final List<Student> students = new ArrayList<>();

        students.add(new Student(1, "한코딩", true));
        students.add(new Student(2, "이학생", false));
        students.add(new Student(3, "박학생", true));

        String message = createGreeting("한코딩");

        System.out.println(message);

        printStudents(students);

        System.out.println("\n[학습 중인 학생]");

        for (Student student : students) {
            if (student.isLearning()) {
                System.out.println(student.getName());
            }
        }

        System.out.println("\n전체 학생: " + students.size() + "명");
    }
}
```
```text
한코딩님, 반갑습니다!

[학생 목록]
1. 한코딩
2. 이학생
3. 박학생

[학습 중인 학생]
한코딩
박학생

전체 학생: 3명
```
`\n`은 줄바꿈이라서 제목 앞에 빈 줄이 생겨요.

**바꿔 보기**
- `String message = ...` 줄 바로 위에 `students.remove(0);`을 넣기 → 목록이 `2. 이학생`, `3. 박학생`이 되고 `전체 학생: 2명`. `final` 목록인데도 지울 수 있어요.
- `students.add(new Student(4, "최학생", true));`를 추가하기 → 학습 중 목록과 전체 수가 함께 바뀌어요.
- `import java.util.List;` 줄을 지우기 → `cannot find symbol` / `symbol: class List`. `Option + Enter`로 되살려요.

## 8단계: 문자열 비교와 입력

파이썬과 크게 다른 점이 하나 더 있어요. **문자열 내용을 비교할 때 `==`를 쓰지 않아요.**

파이썬에서는 `name == "한코딩"`으로 문자열 내용이 같은지 비교했어요. Java의 `==`는 내용이 아니라 **두 변수가 같은 객체를 가리키는지**를 비교해요. 문자열도 객체라서, 내용이 같아도 따로 만들어진 문자열이면 `==`가 `false`를 돌려줄 수 있어요. 키보드로 입력받은 문자열이 그런 경우예요. 입력할 때마다 새 문자열 객체가 만들어지기 때문에, `한코딩`을 입력해도 `name == "한코딩"`은 `false`가 나와요.

내용을 비교할 때는 `"한코딩".equals(name)`처럼 `equals()`를 써요. 비교할 글자를 앞에 쓰는 데도 이유가 있어요. `name`에 아무 객체도 없으면(`null`, 파이썬의 `None`) `name.equals(...)`는 오류가 나요. 반대로 `"한코딩".equals(name)`은 오류 없이 `false`를 돌려줘요.

키보드 입력은 `Scanner`로 받아요. 강의 중간에 추가된 내용이에요. `Scanner scn = new Scanner(System.in);`으로 만들고, `scn.nextLine()`으로 Enter를 칠 때까지 한 줄을 문자열로 읽어요. 파이썬의 `input()`이에요. `scn.nextInt()`는 정수를 읽어요. 파이썬의 `int(input())`처럼 숫자로 바꾸는 것까지 해 줘요. 쓰려면 `import java.util.Scanner;`가 필요해요.

`nextInt()`에는 주의할 점이 있어요. `25`를 입력하고 Enter를 치면, `nextInt()`는 `25`만 가져가고 Enter는 남겨 둬요. 그 바로 다음에 `nextLine()`을 부르면 남아 있던 Enter를 읽어서, 사용자에게 묻지도 않고 빈 문자열을 돌려줘요. 그래서 `nextInt()` 다음에 `nextLine()`을 쓸 때는 중간에 `scn.nextLine();`을 한 번 넣어서 남은 Enter를 버려요. 수업 코드에 `scn.nextLine(); // enter`가 있던 이유예요.

### ▶ 직접 해 보기 — `NameCheck.java`
```java
import java.util.Scanner;

public class NameCheck {
    public static void main(String[] args) {
        Scanner scn = new Scanner(System.in);   // 키보드 입력을 읽는 객체

        System.out.print("이름: ");
        String name = scn.nextLine();           // 한 줄 읽기 (파이썬 input())

        System.out.println("== 로 비교: " + (name == "한코딩"));
        System.out.println("equals로 비교: " + "한코딩".equals(name));

        System.out.print("나이: ");
        int age = scn.nextInt();                // 정수 읽기 (파이썬 int(input()))
        System.out.println("내년 나이: " + (age + 1));
    }
}
```
실행하면 Run 창이 입력을 기다려요. Run 창을 클릭하고 `한코딩` Enter, `25` Enter를 쳐요.
```text
이름: 한코딩
== 로 비교: false
equals로 비교: true
나이: 25
내년 나이: 26
```
같은 `한코딩`인데 `==`는 `false`, `equals`는 `true`인 걸 확인해요. IntelliJ가 `==` 줄에 노란 경고를 띄울 수 있는데, 문자열을 `==`로 비교하지 말라는 경고예요.

**바꿔 보기**: 마지막 줄 아래에 이 세 줄을 넣고 실행해요.
```java
System.out.print("학교: ");
String school = scn.nextLine();
System.out.println("입력한 학교: [" + school + "]");
```
나이 `25`를 입력하자마자 학교는 묻지도 않고 `입력한 학교: []`가 찍혀요. `nextInt()`가 남긴 Enter를 `nextLine()`이 읽었기 때문이에요. `int age = scn.nextInt();` 바로 아래에 `scn.nextLine();`을 넣으면 학교를 제대로 입력받아요.

## 마무리: 강의 최종 프로그램이 하는 일

지금까지 배운 것이 7단계의 강의 최종 프로그램에 모두 들어 있어요. 파일은 두 개예요. `Student.java`에는 4~5단계의 학생 클래스가 있고, 실행하는 파일에는 `main`이 있어요.

실행하면 이런 순서로 일이 일어나요.

1. 컴파일러가 두 파일을 검사해요. 오류가 없으면 JVM이 `main` 메서드부터 실행해요.
2. `final List<Student> students = new ArrayList<>();`로 빈 학생 목록을 만들어요.
3. `students.add(new Student(...))`를 세 번 해서 학생 객체 세 개를 만들고 목록에 넣어요.
4. `createGreeting("한코딩")` 메서드가 `"한코딩님, 반갑습니다!"`를 돌려주고, `main`이 그걸 받아 출력해요.
5. `printStudents(students)` 메서드에 목록을 넘겨요. 이 메서드는 목록이 비었는지 먼저 보고, 비어 있지 않으니 for문으로 학생마다 `번호. 이름`을 출력해요. 돌려줄 값이 없어서 `void` 메서드예요.
6. 다시 for문으로 목록을 돌면서 `isLearning()`이 `true`인 학생(한코딩, 박학생)만 출력해요.
7. `students.size()`로 학생 수를 구해 `전체 학생: 3명`을 출력해요.
8. `main`의 끝에 도착하면 프로그램이 끝나요.

## 다음 회차와 연결

01의 프로그램은 실행하면 출력하고 끝나요. 02부터는 Spring Boot가 이 Java 코드를 **서버**로 만들어요. 서버는 Node 때처럼 끝나지 않고 계속 켜져서 요청을 기다려요. 주소로 요청이 오면 Spring이 그 주소에 맞는 메서드를 불러 주고, 메서드가 돌려준 값이 브라우저로 가요. 03에서는 `List<Student>`를 HTML 화면으로, 06에서는 JSON으로 바꿔 보내요.

## 오류가 날 때 찾아보기

AI가 짠 Java 코드나 내 코드에서 오류가 나면, 오류 문장으로 여기서 찾아봐요.

| 오류 문장 | 먼저 볼 곳 |
|---|---|
| `';' expected` | 그 줄이나 바로 위 줄 끝에 `;`가 있는지 (1단계) |
| `incompatible types: A cannot be converted to B` | 변수·매개변수·반환형의 자료형과 넣은 값의 종류 (2·3단계) |
| `variable x is already defined` | 같은 변수를 자료형을 붙여 두 번 선언함 (2단계) |
| `cannot assign a value to final variable` | `final` 변수에 다시 대입함 (2단계) |
| `class X is public, should be declared in a file named X.java` | 파일 이름과 클래스 이름 (1단계) |
| `xxx has private access in Student` | 필드를 직접 읽고 있음 → getter 사용 (4·5단계) |
| `constructor Student ... cannot be applied to given types` | `new Student(...)`의 값 개수·순서·자료형, `required`와 `found` 비교 (4단계) |
| `cannot find symbol` + `symbol: method getXxx()` | 메서드 이름 철자, boolean getter는 `isXxx` (5단계) |
| `cannot find symbol` + `symbol: class List` | `import`가 빠졌는지 (6단계) |
| 출력이 `Student@5cad8086` | `toString()`이 없음 (5단계) |
| 문자열이 같은데 조건이 `false` | `==` 대신 `equals()` (8단계) |
| `nextLine()`이 입력을 기다리지 않고 빈 글자 | 바로 앞의 `nextInt()`가 남긴 Enter (8단계) |
