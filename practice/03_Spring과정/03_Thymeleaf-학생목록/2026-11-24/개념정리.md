# 개념 정리 — Spring과정 03. Thymeleaf로 학생 목록 화면 만들기

> 날짜: 2026-11-24 · wiki: [03_Thymeleaf-학생목록](../../../../wiki/03_Spring과정/03_Thymeleaf-학생목록.md)
> 단계별 설명문으로 쓰고, 단계 끝마다 직접 해 보는 예시를 둔다. 쉬운 말, 비유 없이, React·파이썬과 비교한다. 예시는 02 노트의 `_spring-practice`(Spring Boot 4.1.3, JDK 21)와 같은 프로젝트를 이 Mac에서 실행해, 서버가 보낸 HTML과 오류 문장을 확인했다 (확인할 때만 다른 포트를 썼다).

## 들어가며

**🧭 맥락 — 지금 어디쯤**

02에서는 `@RestController`로 `/hello`에 글자를 돌려줬어요. 7단계에서는 `@Controller`로 `/hi`에 `Hi.html` 화면을 돌려주는 것도 봤어요. 그런데 `Hi.html`은 내용이 고정된 HTML이었어요. 학생이 바뀌어도 화면은 그대로예요.

03에서는 **데이터에 따라 내용이 바뀌는 HTML**을 서버에서 만들어요. 01에서 만든 `Student` 클래스와 `List<Student>`를 다시 가져와요. 컨트롤러가 학생 목록을 준비해서 넘기면, **Thymeleaf**가 HTML 파일의 정해진 자리에 학생 이름을 채워 넣어 완성된 HTML을 만들어요. 브라우저는 그 완성된 HTML만 받아요.

이렇게 서버에서 화면(HTML)을 완성해서 보내는 방식을 **SSR**(Server-Side Rendering, 서버에서 화면 만들기)이라고 해요. React 과정에서는 반대였어요. 서버는 데이터만 주고, 브라우저에서 React가 `map()`으로 화면을 만들었죠. 이건 **CSR**(Client-Side Rendering)이에요. 오늘은 같은 학생 목록을 SSR로 만들어요. 06에서는 같은 데이터를 JSON으로 보내 React로도 만들어 보고, SSR-CSR 과정에서 두 방식을 비교해요.

파이썬 Flask를 써 봤다면 `render_template("students.html", schoolName="한코딩 스쿨")`로 값을 넘기고, HTML에서 `{{ schoolName }}`으로 꺼내던 것과 같은 일이에요. Spring에서는 `Model`로 넘기고 `th:text="${schoolName}"`으로 꺼내요.

오늘 끝나면 `http://localhost:8080/students`에 파란 제목 "한코딩 스쿨", 안내 문구, "전체 학생: 3명", 번호 · 이름 · 상태 표 3줄(상태는 초록 "학습 중", 회색 "학습 예정")이 나와요. 학생이 없으면 표 대신 "등록된 학생이 없습니다."가 나와요. 학생은 아직 컨트롤러 코드에 적어 둔 3명뿐이고, 화면에서 추가하는 건 04에서 해요.

## 1단계: `@Controller`가 돌려준 문자열은 템플릿 이름이다

🧭 02 7단계의 `HiController`와 같은 방식이에요. 이번에는 학생 목록 화면용 컨트롤러를 따로 만들어요.

`@RestController`는 메서드가 돌려준 문자열을 **글자 그대로** 응답으로 보내요. `@Controller`는 그 문자열을 **뷰 이름**(화면 파일 이름)으로 써요. `return "students";`라고 쓰면 `students`라는 글자를 보내는 게 아니라, Thymeleaf가 `src/main/resources/templates/students.html`을 찾아서 HTML로 만들어 보내요. 앞에 `templates/`, 뒤에 `.html`을 Thymeleaf가 붙이기 때문에 반환값에는 이름만 써요.

`templates` 폴더의 HTML을 **템플릿**이라고 불러요. 그냥 HTML 파일이 아니라 "데이터를 채워 넣을 자리가 표시된 HTML"이라는 뜻이에요. 데이터를 넣는 자리는 `th:`로 시작하는 속성으로 표시해요. 그래서 `<html>` 태그에 `xmlns:th="http://www.thymeleaf.org"`를 적어요. "`th:` 속성은 Thymeleaf 것"이라는 선언이에요. 이 선언은 IntelliJ가 `th:` 속성을 알아보고 자동 완성해 주는 데 쓰여요. 빠져도 Thymeleaf는 동작해요 (7단계에서 확인해요).

수업에서는 처음에 02의 `HelloController`를 `@Controller`로 바꾸고 `templates/hello.html`을 만들어 봤어요. 그런데 어노테이션은 **클래스 전체**에 붙어요. `HelloController`를 `@Controller`로 바꾸면 `/school`의 `return "한코딩 스쿨입니다.";`도 템플릿 이름으로 쓰여서 오류가 나요 (아래 바꿔 보기). 그래서 이 노트는 글자 응답용(`HelloController`)과 화면 응답용(`StudentController`) 컨트롤러를 나눠 둬요.

반환값에 `.html`을 붙이지 않는 것도 약속이에요. `return "Hi.html";`처럼 붙여 봤더니 이 버전에서는 화면이 나오긴 했어요. Thymeleaf가 이미 `.html`로 끝나는 이름에는 다시 붙이지 않기 때문이에요. 하지만 강의와 대부분의 코드가 이름만 쓰니 이름만 써요.

### ▶ 직접 해 보기 — 화면 연결만 먼저

`controller` 우클릭 → **New → Java Class** → `StudentController`.

```java
package com.example.springpractice.controller;

import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.GetMapping;

@Controller
public class StudentController {

    @GetMapping("/students")
    public String students() {
        return "students";
    }
}
```

`resources/templates` 우클릭 → **New → HTML File** → `students`. 내용을 전부 바꿔요.

```html
<!DOCTYPE html>
<html lang="ko" xmlns:th="http://www.thymeleaf.org">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>학생 목록</title>
</head>
<body>
    <h1>학생 목록</h1>
    <p>Thymeleaf 화면 연결에 성공했습니다.</p>
</body>
</html>
```

■ → ▶ 하고 `http://localhost:8080/students`를 열면 "학생 목록" 제목과 "Thymeleaf 화면 연결에 성공했습니다."가 보여요. 페이지 소스 보기를 하면 파일과 거의 같은데, `<html>` 줄이 `<html lang="ko">`로 바뀌어 있어요. Thymeleaf가 처리하면서 `xmlns:th`를 지웠어요.

**바꿔 보기** — 하나씩 바꾸고 ■ → ▶ 한 뒤 `/students`를 열어 봐요. 확인하면 되돌려요.
- `@Controller`를 `@RestController`로 (import도 `org.springframework.web.bind.annotation.RestController`로) → 화면에 `students`라는 글자만 보여요.
- `templates`의 `students.html` 이름을 `student.html`로 바꾸기(우클릭 → **Refactor → Rename**) → Whitelabel `status=500`, Run 창에 `Error resolving template [students], template might not exist or might not be accessible by any of the configured Template Resolvers`.
- 수업 따라 하기: `HelloController`의 `@RestController`를 `@Controller`로(import도), `hello()`의 `return`을 `return "hello";`로 바꾸고, `templates`에 `hello.html`(본문 `<h1>학생 목록</h1>`)을 만들어요. `/hello`는 HTML 화면이 나와요. 그런데 `/school`은 Whitelabel `status=500`이고 Run 창에 이 문장이 나와요. `"한코딩 스쿨입니다."`라는 이름의 템플릿을 찾았기 때문이에요. 확인하면 `HelloController`를 02의 모양으로 되돌리고 `hello.html`은 지워요.
```text
Error resolving template [한코딩 스쿨입니다.], template might not exist or might not be accessible by any of the configured Template Resolvers
```

## 2단계: `Model`로 값을 넘기고 `th:text`로 표시한다

🧭 1단계의 HTML은 아직 고정된 글자예요. 컨트롤러에 있는 값을 HTML로 옮기는 통로가 필요해요.

그 통로가 **`Model`**이에요. 컨트롤러 메서드의 매개변수에 `Model model`을 적으면, 요청이 올 때 Spring이 빈 `Model` 객체를 만들어 넣어 줘요. 메서드 안에서 `model.addAttribute("이름", 값)`으로 값을 담으면, Thymeleaf가 HTML을 만들 때 그 값을 꺼내 쓸 수 있어요. 파이썬 dict에 `{"schoolName": "한코딩 스쿨"}`을 넣어 넘기는 것과 비슷해요. 첫 번째 인자가 키, 두 번째가 값이에요.

HTML에서는 **`${이름}`**으로 Model의 값을 읽어요. 그리고 **`th:text`** 속성에 넣으면 그 태그 안의 글자를 그 값으로 바꿔요. `<h1 th:text="${schoolName}">학교 이름</h1>`은 서버에서 `<h1>한코딩 스쿨</h1>`이 돼요. 태그 안에 적어 둔 `학교 이름`은 바뀌어 없어지는 **예시 글자**예요. HTML 파일을 브라우저로 직접 열면 Thymeleaf가 일하지 않으니 이 예시 글자가 보여요. 그래서 예시 글자를 적어 두면 파일만 열어도 화면 모양을 알 수 있어요.

`addAttribute`의 이름과 `${...}` 안의 이름은 **글자 하나까지 같아야** 해요. 다르면 오류가 나지 않고 **빈 값**이 들어가요. 화면에 제목이 안 보이는데 오류는 없을 때 가장 먼저 볼 곳이에요.

`Model`에 넣었다고 어딘가에 저장되는 건 아니에요. 이번 요청의 화면을 만드는 데만 쓰고, 응답을 보내면 사라져요 (데이터베이스 저장은 05). `${...}`는 `th:` 속성 안에서만 계산돼요. 태그 안에 그냥 `<h1>${schoolName}</h1>`처럼 쓰면 Thymeleaf가 건드리지 않아서 `${schoolName}` 글자가 그대로 화면에 나와요. React JSX에서는 `<h1>{schoolName}</h1>`처럼 태그 안에 바로 썼던 것과 다른 점이에요.

### ▶ 직접 해 보기 — 학교 이름과 안내 문구

`StudentController.java`를 바꿔요. `Model`을 쓰려면 `import org.springframework.ui.Model;`이 필요해요.

```java
package com.example.springpractice.controller;

import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;

@Controller
public class StudentController {

    @GetMapping("/students")
    public String students(Model model) {
        model.addAttribute("schoolName", "한코딩 스쿨");
        model.addAttribute("message", "함께 공부하는 학생들을 소개합니다.");

        return "students";
    }
}
```

`students.html`을 바꿔요 (바꿔 보기에서 줄 번호가 나오니 그대로 붙여 넣어요).

```html
<!DOCTYPE html>
<html lang="ko" xmlns:th="http://www.thymeleaf.org">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>학생 목록</title>
</head>
<body>
<h1 th:text="${schoolName}">학교 이름</h1>
<p th:text="${message}">안내 문구</p>
</body>
</html>
```

■ → ▶ 하고 `/students`의 페이지 소스를 보면 `<body>` 부분이 이래요. `th:text`가 사라지고 글자가 Model 값으로 바뀌었어요.

```html
<body>
<h1>한코딩 스쿨</h1>
<p>함께 공부하는 학생들을 소개합니다.</p>
</body>
```

**바꿔 보기** — 하나씩, 확인하면 되돌려요.
- 컨트롤러의 `"schoolName"`을 `"schoolNam"`으로 → 오류 없이 제목만 비어요. 소스에는 `<h1></h1>`.
- HTML의 `th:text`를 `th:txt`로 → 예시 글자 `학교 이름`이 그대로 보여요. 소스는 `<h1 txt="한코딩 스쿨">학교 이름</h1>`. Thymeleaf는 모르는 `th:이름` 속성을 "`이름` 속성에 값을 넣으라"로 읽어서 `txt` 속성을 만들었어요.
- `${schoolName}`의 `}`를 지워 `th:text="${schoolName"`으로 → Whitelabel `status=500`, Run 창에 `Could not parse as expression: "${schoolName" (template: "students" - line 9, col 5)`. `line 9`가 `students.html`의 9번째 줄이에요.
- `<h1 th:text="${schoolName}">학교 이름</h1>`을 `<h1>${schoolName}</h1>`로 → 화면에 `${schoolName}` 글자가 그대로 나와요.

## 3단계: `Student`를 `model` 패키지에 두고 목록을 넘긴다

🧭 01에서 만든 `Student`(번호·이름·학습 여부)를 Spring 프로젝트로 가져와요. 01에서는 `main`에서 목록을 만들어 콘솔에 출력했고, 오늘은 컨트롤러에서 목록을 만들어 `Model`에 담아요.

학생 클래스는 `model`이라는 패키지에 둬요. 데이터 모양을 정하는 클래스를 모아 두는 곳이에요. 이 **`model` 패키지와 2단계의 `Model` 객체는 이름만 비슷하고 서로 관계없어요.** `Student`는 우리가 만든 평범한 Java 클래스이고, 아직 데이터베이스와도 연결되지 않았어요.

컨트롤러에서는 01과 같은 방법으로 `List<Student>`를 만들고 학생 세 명을 넣은 뒤, `model.addAttribute("students", students)`로 넘겨요. 앞의 `"students"`는 HTML에서 쓸 이름, 뒤의 `students`는 Java 변수예요. 같은 글자라 헷갈리지만 둘은 다른 것이에요. `model.addAttribute("studentList", students)`로 넘겼다면 HTML에서는 `${studentList}`로 읽어요.

HTML에서 목록을 하나씩 꺼내 반복할 때는 **`th:each`**를 써요. `th:each="student : ${students}"`는 "`students` 목록에서 하나씩 꺼내 `student`라는 이름으로 쓴다"는 뜻이에요. 01의 `for (Student student : students)`, 파이썬의 `for student in students:`와 같은 모양이에요. `th:each`를 붙인 **태그 자체가 학생 수만큼 반복돼요.** `<li>`에 붙이면 `<li>`가 3개 생겨요. React에서 `students.map(s => <li key={s.id}>{s.name}</li>)`로 하던 일인데, Thymeleaf는 서버에서 HTML을 한 번 만들고 끝이라 `key`가 필요 없어요.

`${student.name}`은 `Student`의 `name` 필드를 직접 읽는 게 아니에요. 필드는 `private`이라 밖에서 못 읽으니까요. Thymeleaf는 01 5단계의 이름 규칙대로 **getter `getName()`**을 찾아서 불러요. `${student.learning}`은 `boolean`이라 `isLearning()`을 불러요. 그래서 getter가 없거나 이름 규칙이 다르면 오류가 나요.

### ▶ 직접 해 보기 — `Student.java`, 목록, `<li>` 반복

`com.example.springpractice` 우클릭 → **New → Package** → `model`. `model` 우클릭 → **New → Java Class** → `Student`.

```java
package com.example.springpractice.model;

public class Student {
    private int id;
    private String name;
    private boolean learning;

    public Student(int id, String name, boolean learning) {
        this.id = id;
        this.name = name;
        this.learning = learning;
    }

    public int getId() {
        return id;
    }

    public String getName() {
        return name;
    }

    public boolean isLearning() {
        return learning;
    }
}
```

`StudentController.java`는 강의 최종 코드와 같아요. 다른 패키지의 `Student`를 쓰니 `import com.example.springpractice.model.Student;`가 맨 위에 있어요. 이 줄이 없으면 `cannot find symbol` / `symbol: class Student` 컴파일 오류가 나요.

```java
package com.example.springpractice.controller;

import com.example.springpractice.model.Student;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;

import java.util.ArrayList;
import java.util.List;

@Controller
public class StudentController {

    @GetMapping("/students")
    public String students(Model model) {
        List<Student> students = new ArrayList<>();

        students.add(new Student(1, "한코딩", true));
        students.add(new Student(2, "이학생", false));
        students.add(new Student(3, "박학생", true));

        model.addAttribute("schoolName", "한코딩 스쿨");
        model.addAttribute("message", "함께 공부하는 학생들을 소개합니다.");
        model.addAttribute("students", students);

        return "students";
    }
}
```

## 4단계: `th:each`를 `tr`에 써서 표로 만든다

🧭 3단계의 `<li>` 목록에는 이름만 있어요. 번호와 학습 여부까지 보여 주려면 표가 편해요. 반복하는 방법은 그대로이고, 반복할 태그만 바뀌어요.

표는 `<table>` 안에 머리 영역 `<thead>`와 데이터 영역 `<tbody>`를 두고, 한 줄은 `<tr>`, 제목 칸은 `<th>`, 데이터 칸은 `<td>`로 만들어요. `<th scope="col">`의 `scope="col"`은 "이 제목 칸은 세로줄(열)의 제목"이라는 표시예요.

학생 한 명이 표의 한 줄이 되어야 하니까 `th:each`를 **`<tr>`에** 붙여요. 그러면 `<tr>`과 그 안의 `<td>` 세 칸이 학생마다 통째로 반복돼요. 각 `<td>`는 `th:text`로 번호·이름·학습 여부를 채워요. `th:each`를 붙인 태그 **안쪽**에서만 `student`라는 이름을 쓸 수 있어요. 어느 태그에 붙이느냐에 따라 반복되는 덩어리도 달라져요. `<table>`에 붙이면 표 전체(제목 줄 포함)가 학생 수만큼 생겨요. 상태 칸에는 아직 `true`/`false`가 그대로 나와요. 5단계에서 "학습 중"/"학습 예정"으로 바꿔요.

### ▶ 직접 해 보기 — 표로 바꾸기

`students.html`의 `<ul> … </ul>` 세 줄을 이 표로 바꿔요.

```html
<table>
    <thead>
    <tr>
        <th scope="col">번호</th>
        <th scope="col">이름</th>
        <th scope="col">상태</th>
    </tr>
    </thead>

    <tbody>
    <tr th:each="student : ${students}">
        <td th:text="${student.id}">1</td>
        <td th:text="${student.name}">한코딩</td>
        <td th:text="${student.learning}">true</td>
    </tr>
    </tbody>
</table>
```

■ → ▶ 하면 제목 줄 아래에 3줄짜리 표가 보여요. 페이지 소스의 `<tbody>` 부분이에요.

```html
        <td>true</td>
```

## 5단계: `th:if`·`th:unless`·`#lists`로 필요한 것만 보여 준다

🧭 React 06에서 `{learning && <span>학습 중</span>}`처럼 조건에 따라 보여 줄지 말지를 정했어요. Thymeleaf에서는 속성으로 해요.

**`th:if`**는 조건이 참일 때만 그 태그를 남기고, 거짓이면 태그를 통째로 지워요. **`th:unless`**는 반대로 조건이 거짓일 때만 남겨요. 상태 칸에 `<span th:if="${student.learning}">학습 중</span>`과 `<span th:unless="${student.learning}">학습 예정</span>`을 나란히 두면, 같은 조건을 반대로 쓴 것이라 **둘 중 하나만** 남아요. 파이썬의 `if … else`를 태그 두 개로 나눠 쓴 모양이에요.

학생이 한 명도 없을 때도 생각해야 해요. 빈 표만 덩그러니 있으면 사용자는 무슨 상황인지 몰라요. **`#lists`**는 Thymeleaf가 주는 목록 도구예요. `${#lists.isEmpty(students)}`는 목록이 비었으면 참, `${#lists.size(students)}`는 학생 수예요. 파이썬의 `not students`, `len(students)`와 같아요. 안내 문구에 `th:if="${#lists.isEmpty(students)}"`, 표에 같은 조건의 `th:unless`를 붙이면 목록 상태에 따라 둘 중 하나만 보여요.

여기서 흔한 실수가 두 태그 모두에 `th:if`를 쓰는 거예요. 학생이 있으면 둘 다 조건이 거짓이라 **안내 문구도 표도 안 보여요.** 오류가 없어서 찾기 어려워요. `#lists`를 `#list`로 잘못 쓰면, Thymeleaf는 `#list`라는 도구가 없어서 "빈 것(`null`)의 `isEmpty`를 불렀다"는 오류를 내요.

### ▶ 직접 해 보기 — 강의 최종 `students.html`

`students.html`을 강의 최종 코드로 통째로 바꿔요. `<head>`의 `<link>` 줄은 6단계에서 만들 CSS를 미리 연결한 거라, 지금은 CSS 없이 보여요.

```html

<html lang="ko" xmlns:th="http://www.thymeleaf.org">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">

    <title>학생 목록</title>

    <link rel="stylesheet" th:href="@{/css/students.css}">
</head>
<body>
<main class="container">
    <h1 th:text="${schoolName}">학교 이름</h1>

    <p th:text="${message}">안내 문구</p>

    <p>
        전체 학생:
        <strong th:text="${#lists.size(students)}">0</strong>명
    </p>

    <p th:if="${#lists.isEmpty(students)}">
        등록된 학생이 없습니다.
    </p>

    <table th:unless="${#lists.isEmpty(students)}">
        <thead>
        <tr>
            <th scope="col">번호</th>
            <th scope="col">이름</th>
            <th scope="col">상태</th>
```

## 6단계: `static` 폴더의 CSS를 `@{...}`로 연결한다

🧭 React 과정에서는 CSS 파일을 `import`해서 썼어요. 서버가 HTML을 보내는 방식에서는 HTML의 `<link>`가 CSS 주소를 가리키고, 브라우저가 그 주소로 CSS를 따로 요청해요.

`src/main/resources/static` 폴더의 파일은 Spring Boot가 **그대로** 보내 줘요. 컨트롤러가 필요 없어요. 이런 파일을 **정적 파일**이라고 해요. 주소는 `static`을 뺀 나머지 경로예요. `static/css/students.css`는 `http://localhost:8080/css/students.css`로 열려요. **주소에 `static`을 넣으면 404**예요.

HTML에서는 `<link rel="stylesheet" th:href="@{/css/students.css}">`로 연결해요. **`@{...}`**는 Thymeleaf의 URL 표현식이에요. 서버가 HTML을 만들 때 `th:href`가 보통 `href="/css/students.css"`로 바뀌어요. 지금은 `href="/css/students.css"`라고 직접 써도 결과가 같지만, 프로그램이 `/`가 아닌 다른 경로 아래에서 돌 때 `@{...}`는 앞부분을 알아서 붙여 줘요. 그래서 Thymeleaf 템플릿에서는 주소를 `@{...}`로 쓰는 습관을 들여요.

CSS가 안 먹을 때는 페이지 소스에서 `href` 주소를 클릭해 보면 돼요. CSS 글자가 보이면 연결은 된 거고, Whitelabel 404면 파일 위치나 주소가 틀린 거예요.

### ▶ 직접 해 보기 — `students.css`

`resources/static` 우클릭 → **New → Directory** → `css`. `css` 우클릭 → **New → File** → `students.css`. IntelliJ 프로젝트 창에는 `static.css`처럼 한 줄로 보일 수 있어요. 하위 폴더가 하나뿐이면 합쳐 보여 주는 것이고, 실제로는 `static` 안에 `css` 폴더가 있는 거예요. 폴더 이름을 `static.css`로 만들면 안 돼요.

## 7단계: 브라우저는 완성된 HTML만 받는다

🧭 1~6단계에서 계속 본 페이지 소스를 한 번 정리해요. React와 가장 크게 다른 점이에요.

브라우저는 Java 코드를 실행하지 않고, `th:text`나 `${...}`를 계산하지도 않아요. 서버에서 Thymeleaf가 템플릿을 읽고, `Model`의 값으로 `th:` 속성을 모두 처리한 뒤, **`th:`가 하나도 없는 HTML**을 보내요. 페이지 소스 보기에 `th:`가 없고 `한코딩`, `3` 같은 실제 값만 있는 이유예요. React 화면의 페이지 소스에는 비어 있는 `<div id="root"></div>`와 JavaScript 파일만 있었던 것과 비교해 보면 차이가 보여요.

그래서 `students.html`을 Finder에서 더블클릭해 브라우저로 직접 열면, 서버를 거치지 않으니 브라우저는 모르는 `th:` 속성을 무시하고 파일에 적힌 글자를 그대로 보여 줘요. "학교 이름", "안내 문구", "전체 학생: 0명", 둘 중 하나만 나와야 할 "등록된 학생이 없습니다."와 표가 함께, 표에는 `1 | 한코딩 | 학습 중 학습 예정` 한 줄이 보여요. `th:href`도 무시되니 CSS도 없어요. 화면은 꼭 서버 주소로 열어요.

하나 더 알아 둘 게 있어요. 학생 목록은 `students()` 메서드 **안에서** `new ArrayList<>()`로 만들어요. 그래서 `/students` 요청이 올 때마다 목록을 새로 만들고, 응답을 보내면 버려요. 지금은 학생을 추가할 방법도 없지만, 만약 추가하더라도 다음 요청에서 목록을 다시 만드니 사라져요. 04에서 이 목록을 메서드 밖(컨트롤러의 필드)으로 옮기는 이유예요.

### ▶ 직접 해 보기 — 페이지 소스 다시 보기


## 마무리: `/students` 요청 하나가 화면이 되기까지

1. 서버가 켜질 때 Spring이 `controller` 패키지의 `StudentController`(`@Controller`)를 찾아 "`GET /students` → `students()`"를 등록해요 (1단계).
2. 브라우저가 `GET /students`를 보내면 Spring이 빈 `Model`을 만들어 `students(Model model)`을 실행해요 (2단계).
3. 메서드 안에서 `new ArrayList<>()`로 학생 목록을 새로 만들고 `Student` 세 명을 넣은 뒤, `addAttribute`로 `schoolName`, `message`, `students`를 `Model`에 담아요 (2·3단계).
4. `return "students";` → `@Controller`라서 Thymeleaf가 `templates/students.html`을 찾아요 (1단계).
5. Thymeleaf가 템플릿을 위에서부터 읽으며 `th:href`를 `/css/students.css`로, `th:text`를 Model 값으로 바꾸고, `#lists.size`로 3을 넣어요 (2·5·6단계).
6. `th:if`/`th:unless`로 안내 문구는 지우고 표는 남겨요. `<tr th:each>`를 학생 수만큼 반복하면서 `getId()`, `getName()`, `isLearning()`을 불러 칸을 채우고, 상태 `<span>`은 둘 중 하나만 남겨요 (3·4·5단계).
7. `th:`가 모두 사라진 완성 HTML이 브라우저로 가요 (7단계).
8. 브라우저가 HTML을 그리다가 `<link href="/css/students.css">`를 보고 CSS를 한 번 더 요청해요. `static/css/students.css`가 그대로 와서 화면이 꾸며져요 (6단계).
9. 응답이 끝나면 학생 목록과 `Model`은 버려져요. 다음 요청 때 3번부터 다시 만들어요 (7단계).

## 오류가 날 때 찾아보기

| 오류 문장 · 증상 | 먼저 볼 곳 |
|---|---|
| 화면에 `students` 같은 글자만 보임 | 컨트롤러가 `@RestController`인지 → `@Controller` (1단계) |
| `status=500` + `Error resolving template [students]` | `templates/students.html` 위치·파일 이름(대소문자)과 `return` 문자열 (1단계) |
| `Error resolving template [한코딩 스쿨입니다.]` | 글자를 돌려주는 메서드가 `@Controller` 클래스에 들어 있음 (1단계) |
| 고친 HTML이 반영 안 됨 | 서버 ■ → ▶ 했는지 (시작하기) |
| 오류 없이 값만 비어 있음 (`<h1></h1>`) | `addAttribute`의 이름과 `${…}`의 이름이 같은지 (2단계) |
| 예시 글자(`학교 이름`)가 그대로 보임 | `th:text` 철자, 서버 주소로 열었는지 (2·7단계) |
| 화면에 `${schoolName}` 글자가 그대로 나옴 | `${...}`를 `th:` 속성 밖에 씀 (2단계) |
| `Could not parse as expression: "…" (template: "students" - line N …)` | 그 줄의 `${ }` 괄호·따옴표 짝 (2단계) |
| `EL1008E: Property or field 'xxx' cannot be found on object of type '…Student'` | `${student.xxx}` 철자, `Student`에 `getXxx()`/`isXxx()` getter가 있는지 (3단계) |
| `cannot find symbol` + `class Student` (컴파일 오류) | 컨트롤러의 `import com.example.springpractice.model.Student;` (3단계) |
| 표가 여러 개 생기거나 제목 줄이 반복됨 | `th:each`를 `<tr>`에 붙였는지 (4단계) |
| 상태 칸에 `true`/`false`가 나옴 | `th:if`/`th:unless` `<span>`으로 바꿨는지 (5단계) |
| 학생이 있는데 안내 문구도 표도 안 보임 | 표가 `th:unless`인지 (5단계) |
| `EL1011E: … on null context object` | `#lists` 철자 (5단계) |
| CSS가 적용되지 않음 | 파일이 `static/css/students.css`인지, 주소가 `@{/css/students.css}`인지(`static` 빼기) (6단계) |
