## 1단계: `@Controller`와 `GET /` — 화면부터 연결한다

🧭 02 3단계(`@GetMapping`)와 03 1단계(`@Controller`의 반환값 = 템플릿 이름)를 다시 써요.

`@GetMapping("/")`의 `/`는 주소의 맨 처음, 즉 `http://localhost:8080/`이에요. 02에서 아무 컨트롤러도 없을 때 Whitelabel 404가 나던 그 주소예요. 이제 이 주소를 `MainController`의 `index()`가 맡아요.

`MainController`에는 `@Controller`가 붙어 있으니 `return "index";`는 글자가 아니라 템플릿 이름이에요. Thymeleaf가 `templates/index.html`을 찾아 HTML을 보내요. 수업 코드의 주석 "문자열에 들어가 있는 HTML 이름을 찾아서 해당 HTML을 반환한다"가 이 뜻이에요. `@RestController`였다면 화면에 `index` 다섯 글자가 나와요.

`index.html`이라는 이름에는 하나 더 있는 게 있어요. Spring Boot는 `templates/index.html`이 있으면 이것을 **첫 화면(welcome page)**으로 등록해요. 서버를 켤 때 Run 창에 `Adding welcome page template: index`가 찍혀요. 그래서 `/`를 맡은 컨트롤러가 없어도 `/`에서 `index.html`이 보여요. 지금은 컨트롤러가 있어서 컨트롤러가 먼저 맡지만, 3·4단계 바꿔 보기에서 이 때문에 헷갈리는 상황을 직접 봐요.

### ▶ 직접 해 보기 — 화면 연결만

`controller` 우클릭 → **New → Java Class** → `MainController`.

```java
package com.example.springpractice.controller;

import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.GetMapping;

@Controller
public class MainController {

    @GetMapping("/")
    public String index() {
        return "index";
    }
}
```

`resources/templates` 우클릭 → **New → HTML File** → `index`. 내용을 바꿔요.

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>메인 페이지</title>
</head>
<body>
<h1>오늘은 금요일입니다</h1>
</body>
</html>
```

■ → ▶ 하고 `http://localhost:8080/`을 열면 탭 제목 "메인 페이지", 큰 제목 "오늘은 금요일입니다"가 보여요. 02에서 404가 나던 주소에 이제 화면이 나와요. Run 창 시작 로그에는 이 줄이 있어요 (앞부분은 뺐어요).

```text
o.s.b.w.a.WelcomePageHandlerMapping      : Adding welcome page template: index
```

**바꿔 보기** — 하나씩, 확인하면 되돌려요.
- `@Controller`를 `@RestController`로 (import도) → 화면에 `index` 글자만 보여요.
- `index.html` 이름을 `main.html`로 → Whitelabel `status=500`, Run 창에 `Error resolving template [index]`. 02 7단계·03 1단계와 같은 오류예요.

## 2단계: 목록은 컨트롤러 필드에 두고, 생성자에서 채운다

🧭 04 1단계에서 학생 목록을 메서드 안(03)에서 컨트롤러의 필드로 옮긴 이유를 다시 봐요. → [04 개념 정리 1단계](../../04_폼-학생등록/2026-11-24/개념정리.md)

이 회차의 목록은 `List<String> nameList = new ArrayList<>();`예요. 03·04는 `Student` 객체를 담았지만, 여기서는 이름 글자만 담아요. 01의 `List<Student>`처럼 `< >` 안에 담을 자료형을 적은 거예요.

이 목록은 메서드 **밖**, 클래스 바로 안에 있어요. 즉 컨트롤러 객체의 **필드**예요. Spring은 서버를 켤 때 `MainController` 객체를 **하나** 만들고, 모든 요청에서 그 객체를 계속 써요. 그래서 필드에 담긴 목록은 요청이 끝나도 남아 있어요. 03처럼 메서드 안에서 `new ArrayList<>()`를 했다면 요청마다 새 목록이 생겼을 거예요.

`public MainController() { … }`는 **생성자**예요 (01 4단계). Spring이 컨트롤러 객체를 만들 때 **한 번** 실행돼서 처음 이름 세 개를 넣어요. 요청이 올 때마다 실행되는 코드가 아니에요. 바꿔 보기에서 `println`으로 직접 확인해요.

04는 필드를 `private final List<Student> studentList`로 썼고, 여기서는 앞에 아무것도 없어요. 둘 다 동작은 같아요. `private`은 다른 클래스가 이 목록을 직접 못 건드리게 막고, `final`은 다른 목록을 다시 대입하는 걸 막아요 (01 2·6단계). 붙여 두는 쪽이 안전해서 04가 그렇게 썼어요.

`index()`는 이제 `Model model`을 받아 `model.addAttribute("list", nameList)`로 목록을 넘겨요. 템플릿에서는 첫 번째 인자인 **`"list"`**로 읽어요. 변수 이름 `nameList`가 아니에요 (03 2·3단계). `th:each="name : ${list}"`로 하나씩 꺼내고, 꺼낸 `name`이 글자 자체라서 `th:text="${name}"`으로 바로 써요. 03처럼 `${student.name}`(getter 부르기)이 아니에요.

### ▶ 직접 해 보기 — 필드 목록과 `th:each`

`MainController.java`를 바꿔요.

```java
package com.example.springpractice.controller;

import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;

import java.util.ArrayList;
import java.util.List;

@Controller
public class MainController {

    List<String> nameList = new ArrayList<>();

    public MainController() {
        nameList.add("한코딩");
        nameList.add("파이썬");
        nameList.add("자바");
    }

    @GetMapping("/")
    public String index(Model model) {

        model.addAttribute("list", nameList);

        return "index";
    }
}
```

`index.html`의 `<h1>` 아래에 목록을 더해요.

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>메인 페이지</title>
</head>
<body>
<h1>오늘은 금요일입니다</h1>
<ul>
    <li th:each="name : ${list}" th:text="${name}"></li>
</ul>
</body>
</html>
```

■ → ▶ 하고 `/`의 페이지 소스(`Cmd + Option + U`)를 보면 `<body>`가 이래요.

```html
<body>
<h1>오늘은 금요일입니다</h1>
<ul>
    <li>한코딩</li>
    <li>파이썬</li>
    <li>자바</li>
</ul>
</body>
```

**바꿔 보기** — 하나씩, 확인하면 되돌려요.
- 생성자 첫 줄에 `System.out.println("MainController 생성자 실행");`, `index()` 첫 줄에 `System.out.println("GET / 요청");`을 넣고 ■ → ▶, `/`를 세 번 새로고침 → Run 창에 `MainController 생성자 실행`은 서버가 켜질 때 **한 번**(`Started …` 줄보다 위), `GET / 요청`은 **세 번** 찍혀요.
- `model.addAttribute("list", nameList);`의 `"list"`를 `"names"`로 → 오류 없이 이름이 하나도 안 나와요. 소스에는 빈 `<ul>`만 남아요. 03 2단계처럼 이름이 다르면 빈 값이에요.

## 3단계: 비었을 때와 있을 때 — `th:if`·`th:unless`

🧭 03 5단계에서 "등록된 학생이 없습니다."와 표 중 하나만 보여 준 방법 그대로예요.

목록이 비어 있으면 빈 `<ul>`만 남아서 화면에 아무것도 없어요. 사용자는 고장인지 학생이 없는 건지 알 수 없죠. 그래서 같은 조건 `${#lists.isEmpty(list)}`를 두 번, 한 번은 `th:if`, 한 번은 `th:unless`로 써요. 비었으면 `<div>` 안내 문구만, 아니면 `<ul>` 목록만 HTML에 남아요. 둘이 동시에 나오거나 둘 다 안 나오는 일은 없어요.

강의 코드의 `<html>`에는 `xmlns:th`가 없어요. 03 7단계에서 본 것처럼 이 선언은 IntelliJ용이라 없어도 `th:` 속성은 동작해요. IntelliJ에서 `th:` 속성에 노란 밑줄이 보일 수 있지만 실행에는 문제가 없어요. 03처럼 넣어 두면 자동 완성이 돼서 편해요.

### ▶ 직접 해 보기 — 안내 문구 더하기

`index.html`의 `<ul>` 부분을 이렇게 바꿔요.

```html
<div th:if="${#lists.isEmpty(list)}">학생이 존재하지 않습니다.</div>
<ul th:unless="${#lists.isEmpty(list)}">
    <li th:each="name : ${list}" th:text="${name}"></li>
</ul>
```

■ → ▶ 하면 화면은 2단계와 같아요. 소스에는 `<div>`가 있던 자리에 빈 줄만 남아요.

```html
<h1>오늘은 금요일입니다</h1>

<ul>
    <li>한코딩</li>
```

**바꿔 보기**
- 생성자의 `nameList.add(...)` 세 줄 앞에 `//` → 목록 대신 "학생이 존재하지 않습니다."가 나와요. 소스의 `<body>` 안은 `<h1>`과 `<div>학생이 존재하지 않습니다.</div>`뿐이고 `<ul>`이 없어요. 되돌려요.

## 4단계: 폼으로 보내고 `@PostMapping`으로 받는다

🧭 04 2·3단계의 폼(`action`·`method`·`name`)과 `@PostMapping`이에요. → [04 개념 정리 2·3단계](../../04_폼-학생등록/2026-11-24/개념정리.md)

폼은 `<form th:action="@{/insert}" method="post">`예요. 전송 버튼을 누르면 브라우저가 **`POST /insert`** 요청을 보내고, 요청 안에 `입력창의 name=입력한 값`, 여기서는 `hello=스프링` 같은 데이터를 담아요. `th:action`의 `@{/insert}`는 03 6단계의 URL 표현식이라 서버에서 `action="/insert"`로 바뀌어요.

서버에서는 `@PostMapping("/insert")`가 붙은 `nameInsert`가 이 요청을 맡아요. 같은 `/insert`라도 GET은 맡지 않아요. 그래서 주소창에 `http://localhost:8080/insert`를 치면(GET) **405**(허용하지 않는 요청 방식)가 나요. 등록은 폼 전송으로만 확인해요.

입력값은 매개변수 `String hello`로 들어와요. 04에서는 `@RequestParam(name = "name")`으로 "요청의 `name` 항목을 받아라"를 적었는데, 여기서는 생략했어요. 생략하면 Spring은 **매개변수 이름과 같은 항목**을 찾아요. 입력창이 `name="hello"`이고 매개변수가 `hello`라서 값이 들어가요. 이게 되려면 컴파일된 코드에 매개변수 이름(`hello`)이 남아 있어야 하는데, Spring Boot의 Gradle 설정이 `-parameters`라는 컴파일 옵션으로 이름을 남겨 줘요. 이 옵션을 일부러 빼고 실행해 봤더니 전송할 때 500 오류와 `Name for argument of type [java.lang.String] not specified, and parameter name information not available via reflection. Ensure that the compiler uses the '-parameters' flag.`가 나왔어요. 받을 이름을 코드에 분명히 적어 두려면 04처럼 `@RequestParam(name = "hello")`를 써요.

생략했을 때 이름이 안 맞으면 오류가 나지 않고 `null`이 들어가요. 그 `null`이 그대로 목록에 추가되고, `th:text`는 `null`을 빈 글자로 보여 줘서 **빈 `<li>`**가 생겨요. 빈 칸으로 전송해도 `""`(빈 글자)가 들어가 빈 `<li>`가 생겨요. 입력창에 `required`도 없고 서버 검사도 없기 때문이에요. 04 4·5단계의 `trim()` + `isEmpty()` 검사가 이걸 막아요.

### ▶ 직접 해 보기 — 강의 최종 코드

`MainController.java`를 강의 최종 코드로 바꿔요 (`package` 줄만 우리 것).

```java
package com.example.springpractice.controller;

import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;

import java.util.ArrayList;
import java.util.List;

@Controller // -> 문자열에 들어가 있는 HTML 이름을 찾아서 해당 HTML을 반환한다.
public class MainController {

    List<String> nameList = new ArrayList<>();

    public MainController() {
        nameList.add("한코딩");
        nameList.add("파이썬");
        nameList.add("자바");
    }

    @GetMapping("/")
    public String index(Model model) {

        model.addAttribute("list", nameList);

        return "index";
    }

    @PostMapping("/insert")
    public String nameInsert(String hello) {
        nameList.add(hello);
        return "redirect:/";
    }
}
```

`index.html`도 강의 최종 코드로 바꿔요. 3단계 아래에 폼이 붙었어요.

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>메인 페이지</title>
</head>
<body>
<h1>오늘은 금요일입니다</h1>
<div th:if="${#lists.isEmpty(list)}">학생이 존재하지 않습니다.</div>
<ul th:unless="${#lists.isEmpty(list)}">
    <li th:each="name : ${list}" th:text="${name}"></li>
</ul>

<form th:action="@{/insert}" method="post">
    이름 <input name="hello" />
    <button type="submit">전송</button>
</form>
</body>
</html>
```

■ → ▶ 하고 `/`에서 입력창에 `스프링`을 쓰고 **전송** → 목록 끝에 `스프링`이 붙어요. 페이지 소스의 폼은 `<form action="/insert" method="post">`로 바뀌어 있어요. 폼 없이 터미널로 같은 요청을 보낼 수도 있어요. `--data-urlencode`가 `hello=스프링`을 폼과 같은 모양으로 보내요.

```bash
curl -i -X POST --data-urlencode "hello=스프링" http://localhost:8080/insert
```

그다음 `/`를 새로고침하면 소스의 목록이 이래요.

```html
<ul>
    <li>한코딩</li>
    <li>파이썬</li>
    <li>자바</li>
    <li>스프링</li>
</ul>
```

**바꿔 보기** — 하나씩, 확인하면 되돌려요.
- `nameInsert` 첫 줄에 `System.out.println("받은 값: [" + hello + "]");`를 넣고 ■ → ▶. `스프링` 전송 → Run 창 `받은 값: [스프링]`. 빈 칸 그대로 전송 → `받은 값: []`, 목록 끝에 빈 줄(소스는 `<li></li>`).
- 위 상태에서 `index.html`의 `<input name="hello" />`를 `<input name="name" />`으로 → 무엇을 써도 `받은 값: [null]`, 목록 끝에 빈 `<li></li>`. 입력창 `name`과 매개변수 이름이 달라서예요.
- 주소창에 `http://localhost:8080/insert`를 치고 Enter → Whitelabel `(type=Method Not Allowed, status=405)`. Run 창에 `Request method 'GET' is not supported`.
- `MainController`의 `@Controller` 줄 앞에 `//` → `/`는 404가 아니라 화면이 나와요. 1단계의 welcome page라서요. 그런데 컨트롤러가 없으니 `Model`에 `list`가 없어서, 이름 대신 "학생이 존재하지 않습니다."가 나와요. 전송하면 `/insert`를 맡은 곳이 없어 Whitelabel 404예요. "화면은 나오는데 목록이 비었다"면 컨트롤러가 일하고 있는지부터 봐요.

## 5단계: `redirect:/` — 등록한 뒤 목록 화면으로 돌아간다

🧭 04 3·4단계의 `redirect:/students`와 같아요. 주소만 `/`예요. → [04 개념 정리 3·4단계](../../04_폼-학생등록/2026-11-24/개념정리.md)

`nameInsert`는 `"redirect:/"`를 돌려줘요. `redirect:`로 시작하면 템플릿 이름이 아니에요. Spring은 브라우저에게 상태 코드 **302**와 `Location: /` 헤더만 보내요. "`/`로 다시 요청해"라는 뜻이에요. 브라우저는 곧바로 `GET /`를 보내고, `index()`가 늘어난 목록을 `Model`에 담아 화면을 만들어요. 그래서 전송한 뒤 주소창이 `/`예요.

순서로 쓰면 이래요.

```text
이름 입력 → 전송
    ↓
POST /insert → nameList.add(hello) → "redirect:/"
    ↓
302 응답 (Location: /)
    ↓
브라우저가 GET / 요청 → index() → index.html에 목록 표시
```

이렇게 하는 이유는 두 가지예요. 첫째, 브라우저가 마지막으로 보낸 요청이 `GET /`가 되어서 새로고침해도 POST가 다시 가지 않아요. 같은 이름이 두 번 들어가지 않아요. 둘째, 목록 화면을 만드는 일을 `index()` 한 곳에서만 해요.

`redirect:/` 대신 `return "index";`를 하면 어떻게 될까요? `nameInsert`는 `Model`에 `list`를 담지 않았어요. 그래서 템플릿의 `${list}`는 비어 있고, `#lists.isEmpty`가 참이 되어 방금 이름을 넣었는데도 "학생이 존재하지 않습니다."가 나와요. 주소창도 `/insert`로 남아서, 새로고침하면 브라우저가 같은 POST를 다시 보낼지 물어요.

### ▶ 직접 해 보기 — 302 응답 보기

브라우저는 302를 받자마자 바로 `/`로 가서 눈에 안 보여요. 4단계의 `curl -i` 명령으로 보면 응답이 이것뿐이에요 (`Date` 줄은 뺐어요). 본문이 없어요(`Content-Length: 0`).

```text
HTTP/1.1 302
Location: http://localhost:8080/
Content-Language: ko-KR
Content-Length: 0
```

**바꿔 보기**
- `return "redirect:/";`를 `return "index";`로 → `스프링` 전송 → 응답은 200이고 화면에 "학생이 존재하지 않습니다."와 폼만 나와요. 그런데 `/`를 다시 열면 `스프링`이 목록 끝에 들어 있어요. 추가는 됐고 화면만 잘못 만든 거예요. 되돌려요.

## 6단계: 목록은 메모리에 있다 — 재시작하면 처음 3개

🧭 04 6단계와 같은 결과예요. 05에서 데이터베이스로 바꾸는 이유예요. → [04 개념 정리 6단계](../../04_폼-학생등록/2026-11-24/개념정리.md)

`nameList`는 컨트롤러 객체의 필드라서, 서버가 켜져 있는 동안에는 요청이 몇 번 와도 남아 있어요. 다른 브라우저로 열어도 같은 목록이 보여요. 서버 하나에 컨트롤러 객체가 하나이고, 모두 그 목록을 같이 쓰기 때문이에요.

하지만 이 목록은 서버 프로그램의 **메모리**에 있어요. ■로 서버를 끄면 프로그램과 함께 사라지고, ▶로 다시 켜면 Spring이 컨트롤러를 새로 만들면서 생성자가 다시 실행돼요. 그래서 처음 세 이름만 남아요. 05에서는 목록을 H2 데이터베이스에 저장해서 재시작해도 남게 해요. 수업에서는 이 `www` 프로젝트의 `MainController`를 그대로 고쳐서 05를 진행했어요.

04와 비교하면 이 회차 코드에 빠진 것이 보여요.

- 빈 이름 검사가 없어요 → 빈 칸·공백도 목록에 들어가요 (4단계). 04는 `trim()` + `isEmpty()`로 막고 오류 문구를 보여 줘요.
- `@RequestParam`이 없어요 → 이름이 안 맞으면 오류 없이 `null`이 들어가요 (4단계). 04처럼 이름을 적어 두면 빠졌을 때 400 오류로 바로 알 수 있어요.
- 이름 글자만 담아요 → 번호나 학습 여부가 없어요. 04는 `Student` 객체와 `nextId`로 번호를 붙여요.

### ▶ 직접 해 보기 — 재시작

`/`에서 이름 두어 개를 전송해 목록을 늘린 다음 ■ → ▶ 하고 `/`를 새로고침해요. 소스의 목록이 처음으로 돌아가 있어요.

```html
<ul>
    <li>한코딩</li>
    <li>파이썬</li>
    <li>자바</li>
</ul>
```

## 마무리: 이름 하나를 등록하면 일어나는 일

1. ▶를 누르면 Spring이 `MainController` 객체를 하나 만들고, 생성자가 `nameList`에 "한코딩·파이썬·자바"를 넣어요 (2단계). "`GET /` → `index()`, `POST /insert` → `nameInsert()`"도 등록해요.
2. 브라우저가 `GET /`를 보내면 `index()`가 `nameList`를 `"list"`라는 이름으로 `Model`에 담고 `"index"`를 돌려줘요 (1·2단계).
3. `@Controller`라서 Thymeleaf가 `templates/index.html`을 찾아요. 목록이 비지 않았으니 `<div>`는 지우고 `<ul>`을 남기고, `th:each`로 이름마다 `<li>`를 만들어요. `th:action`은 `action="/insert"`가 돼요 (1·3·4단계).
4. 사용자가 입력창에 `스프링`을 쓰고 전송하면, 브라우저가 `POST /insert`에 `hello=스프링`을 담아 보내요 (4단계).
5. Spring이 `nameInsert(String hello)`를 찾아 매개변수 이름 `hello`와 같은 항목의 값 `스프링`을 넣어 실행해요. `nameList.add(hello)`로 목록 끝에 붙어요 (4단계).
6. `"redirect:/"`라서 302와 `Location: /`가 가고, 브라우저가 `GET /`를 다시 보내요. 2~3번이 다시 일어나 네 이름이 보여요 (5단계).
7. 서버를 껐다 켜면 1번부터 다시 시작해서 세 이름만 남아요 (6단계).

## 다음 회차와 연결

05에서는 이 메모리 목록을 **H2 데이터베이스**로 옮겨요. 수업 코드는 이 회차의 `www` 프로젝트에서 이어져서, `MainController`가 `StudentRepository`를 받아 `save()`로 저장하고 `findAll()`로 읽어요. 이 노트를 `_spring-practice`에서 따라 했다면 05는 05 노트의 안내를 따라요. 폼 → `@PostMapping` → 저장 → `redirect` → 목록 화면이라는 오늘의 흐름은 그대로이고, "저장" 자리만 데이터베이스로 바뀌어요.

## 오류가 날 때 찾아보기

| 오류 문장 · 증상 | 먼저 볼 곳 |
|---|---|
| 화면에 `index`나 `redirect:/` 글자만 보임 | `@RestController` 대신 `@Controller` (1단계) |
| `status=500` + `Error resolving template [index]` | `templates/index.html` 파일 이름 (1단계) |
| 오류 없이 목록이 비어 있음 (빈 `<ul>`) | `addAttribute`의 이름(`"list"`)과 `${list}` (2단계) |
| 이름이 있어야 하는데 "학생이 존재하지 않습니다." | 생성자의 `add`, `@Controller`가 붙었는지(welcome page) (3·4단계) |
| 전송했더니 Whitelabel 404 | `@PostMapping("/insert")`와 `th:action="@{/insert}"` 철자, `@Controller` (4단계) |
| 주소창에 `/insert`를 쳤더니 405 | 정상이에요. 등록은 폼으로 (4단계) |
| 목록에 빈 줄이 생김, Run 창 `받은 값: [null]` | 입력창 `name`과 매개변수 이름이 같은지 (4단계) |
| 목록에 빈 줄이 생김, `받은 값: []` | 빈 칸 전송. 빈 이름 검사가 없음 → 04 4·5단계 (4단계) |
| `Name for argument of type [java.lang.String] not specified … '-parameters' flag` | 컴파일 옵션 `-parameters`가 빠짐 → `@RequestParam(name = "hello")`로 적기 (4단계) |
| 전송 뒤 "학생이 존재하지 않습니다.", 주소창이 `/insert` | `return "redirect:/"` 대신 `"index"`를 돌려줌 (5단계) |
| 서버를 다시 켰더니 추가한 이름이 사라짐 | 정상이에요. 메모리 목록이라서 → 05 (6단계) |
