## 1단계: 타이머 콜백 안의 `return`은 바깥 함수의 값이 아니다

학생 정보를 가져오는 데 1초가 걸린다고 해 볼게요. 01회차의 `setTimeout`으로 1초 뒤에 `"한코딩"`을 `return`하면 될 것 같아요. 그런데 `getStudent()`의 결과를 찍어 보면 `undefined`가 나와요. 1초를 기다려도 `한코딩`은 나오지 않아요.

이유는 `return`이 **어느 함수 안에** 있느냐에 있어요. `return "한코딩"`은 `setTimeout`에 넘긴 화살표 함수(콜백) 안에 있어요. 그래서 이 값은 콜백의 반환값이에요. 그 콜백을 부르는 건 1초 뒤의 타이머이고, 타이머는 이 값을 어디에도 쓰지 않아요.

바깥의 `getStudent()`는 타이머를 예약하고 바로 끝나요. `getStudent` 자체에는 `return`이 없어서 `undefined`를 돌려줘요. 파이썬 함수가 `return` 없이 끝나면 `None`을 돌려주는 것과 같아요. `student`에는 `undefined`가 들어가고, 다음 줄이 그걸 찍어요. 1초 뒤에 콜백이 실행될 때는 이미 늦었어요. 결과가 나중에 준비되는 작업에는 결과를 넘겨줄 다른 방법이 필요해요.

### ▶ 직접 해 보기 — `student-result.js`
```javascript
function getStudent() {
  setTimeout(() => {
    return "한코딩";
  }, 1000);
}

const student = getStudent();

console.log(student);
```
```text
undefined
```
`undefined`가 바로 찍히고, 프로그램은 타이머가 끝나는 1초 뒤에 끝나요.

**바꿔 보기**: `return "한코딩";` 바로 위에 `console.log("타이머 콜백 실행");`을 넣어요. → `undefined`가 먼저, 약 1초 뒤 `타이머 콜백 실행`이 찍혀요. 콜백은 실행됐지만 `student`는 이미 `undefined`로 정해진 뒤예요.

## 2단계: Promise를 돌려주고 `.then()`으로 결과 받기

**Promise**는 나중에 끝나는 작업의 결과를 담는 객체예요. 함수가 결과를 바로 줄 수 없을 때, 결과 대신 Promise를 먼저 돌려줘요. 결과가 준비되면 Promise 안에 들어가고, 받는 쪽은 그때 실행할 함수를 미리 등록해 둬요.

Promise에는 상태가 세 가지 있어요. **대기(pending)**는 아직 결과를 기다리는 중, **이행(fulfilled)**은 성공 결과가 들어온 상태, **거부(rejected)**는 실패 이유가 들어온 상태예요. 대기에서 이행이나 거부 중 하나로 한 번 정해지면 다시 바뀌지 않아요.

Promise는 `new Promise((resolve, reject) => { … })`로 만들어요. 안에 넣은 함수는 바로 실행되고, JavaScript가 그 함수에 `resolve`와 `reject`라는 함수 두 개를 넘겨줘요. 작업이 성공하면 `resolve(결과)`를 불러 결과를 넣고, 실패하면 `reject(오류)`를 불러요. 이름은 마음대로 지어도 되지만, 첫 번째가 성공, 두 번째가 실패 역할이에요. 아래 코드에서 `getStudent()`는 Promise를 `return`해요. 1단계와 달리 타이머 콜백은 값을 `return`하지 않고 `resolve("한코딩")`을 불러서 Promise 안에 결과를 넣어요.

받는 쪽은 `.then(함수)`로 "성공 결과가 들어오면 이 함수를 실행해 줘"라고 등록해요. `.then`에 넘긴 함수도 01회차의 콜백처럼 나중에 실행돼요. 그래서 `요청 후 다른 작업`이 먼저 찍히고, 1초 뒤 `resolve`가 불린 다음에 `받은 학생: 한코딩`이 찍혀요.

**Promise를 받은 것과 결과를 받은 것은 달라요.** `getStudent()`가 돌려주는 건 Promise이고, `"한코딩"`은 `.then()`이나 `await`로 꺼내야 해요. Promise를 그대로 `console.log`에 넣으면 결과 대신 `Promise { <pending> }`처럼 Promise 객체가 찍혀요.

### ▶ 직접 해 보기 — `student-result.js`
파일 내용을 전부 바꿔요 (강의 3장 코드).
```javascript
function getStudent() {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve("한코딩");
    }, 1000);
  });
}

console.log("학생 정보 요청");

getStudent().then((student) => {
  console.log("받은 학생:", student);
});

console.log("요청 후 다른 작업");
```
```text
학생 정보 요청
요청 후 다른 작업
```
약 1초 뒤:
```text
받은 학생: 한코딩
```

**바꿔 보기**
- (강의의 직접 바꿔보기) `1000`을 `2000`으로 바꾸고, 마지막 줄 아래에 `console.log("하나 더 추가한 작업");`을 넣어요. → `학생 정보 요청`, `요청 후 다른 작업`, `하나 더 추가한 작업`이 바로 찍히고, 약 2초 뒤 `받은 학생: 한코딩`. 되돌려요.
- Promise의 상태를 직접 봐요. `console.log("학생 정보 요청");`부터 끝까지를 아래로 바꿔요.
  ```javascript
  const promise = getStudent();

  console.log("바로 찍은 promise:", promise);

  setTimeout(() => {
    console.log("2초 뒤 찍은 promise:", promise);
  }, 2000);
  ```
  ```text
  바로 찍은 promise: Promise { <pending> }
  2초 뒤 찍은 promise: Promise { '한코딩' }
  ```
  처음에는 대기 상태라 결과가 없고, `resolve` 뒤에는 결과가 들어 있어요. Promise 객체가 찍히는 건 이렇게 Promise 자체를 `console.log`에 넣었을 때예요. 원래 코드로 되돌려요.
- `return new Promise(`에서 `return`을 지워요. → `학생 정보 요청` 다음에 `TypeError: Cannot read properties of undefined (reading 'then')`. `getStudent()`가 아무것도 돌려주지 않아서 `undefined.then(…)`을 부른 셈이에요. 되돌려요.

## 3단계: 실패는 `reject`, 받는 곳은 `.catch()` — 거부되면 `.then()`은 건너뛴다

실제 요청은 실패할 수 있어요. 서버가 꺼져 있거나 없는 데이터를 찾을 때요. 실패는 `reject(new Error("문장"))`으로 알려요. `new Error("문장")`은 오류 정보를 담는 객체를 만들고, 넣은 문장은 `error.message`로 꺼낼 수 있어요.

받는 쪽은 `.catch(함수)`로 실패를 처리해요. `.then()`과 `.catch()`는 둘 다 Promise를 돌려줘서 `getStudent().then(…).catch(…)`처럼 줄줄이 이어 쓸 수 있어요. 이렇게 이은 것을 **체인**이라고 해요.

체인에서 실패가 어떻게 흐르는지가 중요해요. Promise가 **거부되면 `.then()`에 넘긴 함수는 실행되지 않아요.** `.then()`은 성공 결과를 받는 자리라서 실패는 그냥 지나가요. 실패는 체인을 따라 내려가다가 처음 만나는 `.catch()`에서 처리돼요. `.then()`이 두 개, 세 개 있어도 모두 건너뛰어요. 반대로 성공하면 `.catch()`를 건너뛰어요. `.catch()`의 함수가 받는 값은 `reject()`에 넣은 Error 객체예요. 그래서 `error.message`를 찍으면 Error를 만들 때 넣은 문장만 나와요. 거부된 Promise를 `.catch()`로 처리하면 Promise 객체(`Promise { … }`)는 찍히지 않아요.

`reject()`를 불러도 그 함수의 나머지 줄은 계속 실행돼요. 강의 코드가 `reject` 다음에 `return`을 쓴 이유예요. `return`이 없으면 아래의 `resolve`까지 실행돼요. 다만 Promise는 이미 거부로 정해져서 그 `resolve`는 무시돼요.

### ▶ 직접 해 보기 — `student-result.js`
강의 4장 코드예요. 수업 코드는 `resolve`·`reject` 자리에 `성공`·`실패`라는 이름을 붙였어요. `shouldSuccess`가 `true`면 성공, `false`면 실패예요.
```javascript
function getStudent(shouldSuccess) {
  return new Promise((성공, 실패) => {
    setTimeout(() => {
      if (!shouldSuccess) {
        실패(new Error("학생 정보를 가져오지 못했습니다."));
        return;
      }

      성공("한코딩");
    }, 3000);
  });
}

getStudent(false)
  .then((student) => {
    console.log("받은 학생:", student);
  })
  .catch((error) => {
    console.log("오류:", error.message);
  });
```
약 3초 뒤:
```text
오류: 학생 정보를 가져오지 못했습니다.
```
`받은 학생:` 줄은 찍히지 않아요. 노션에는 "약 1초 뒤"라고 되어 있지만 지연이 `3000`이라 3초 뒤에 나와요.

**바꿔 보기**: 실행 전에 출력을 먼저 적어 보고 실행해요.
- (강의의 직접 바꿔보기) `getStudent(false)`를 `getStudent(true)`로 → 3초 뒤 `받은 학생: 한코딩`만 찍혀요. 이번에는 `.catch()`를 건너뛰었어요. 노션 안내는 `true`·`false`를 반대로 적었는데, 이 함수는 `shouldSuccess`라서 `true`가 성공이에요. `false`로 되돌려요.
- `.then()`을 하나 더 잇고, 체인 앞뒤에 출력문을 넣어요. 호출 부분을 아래로 바꿔요.
  ```javascript
  console.log("요청 시작");

  getStudent(false)
    .then((student) => {
      console.log("받은 학생:", student);
    })
    .then(() => {
      console.log("두 번째 then");
    })
    .catch((error) => {
      console.log("오류:", error.message);
    });

  console.log("체인 등록 끝");
  ```
  ```text
  요청 시작
  체인 등록 끝
  오류: 학생 정보를 가져오지 못했습니다.
  ```
  `.then()` 두 개를 모두 건너뛰고 `.catch()`만 실행됐어요. 체인을 등록하는 줄은 바로 지나가서 `체인 등록 끝`이 먼저 찍혀요. `true`로 바꾸면 `요청 시작`, `체인 등록 끝`, `받은 학생: 한코딩`, `두 번째 then`이에요. 아래 바꿔 보기는 이 코드(`false`)로 이어서 해요.
- `error.message`를 `error`로 → `오류: Error: 학생 정보를 가져오지 못했습니다.` 아래에 `at Timeout._onTimeout (…/student-result.js:5:12)` 같은 줄이 몇 개 더 나와요. Error 객체 전체(오류 종류, 문장, 오류가 난 위치)가 찍힌 거예요. 화면에 보여 줄 문장만 필요하면 `.message`를 써요. 되돌려요.
- `실패(…);` 아래의 `return;`을 `console.log("실패 다음 줄도 실행돼요");`로 바꿔요. → `요청 시작`, `체인 등록 끝`, `실패 다음 줄도 실행돼요`, `오류: 학생 정보를 가져오지 못했습니다.` `실패` 뒤의 줄과 `성공("한코딩")`까지 실행됐지만, 이미 거부로 정해져서 `.then()`은 실행되지 않았어요. 되돌려요.
- `.catch((error) => { … });` 세 줄을 지우고, `두 번째 then` 블록 끝 `})` 뒤에 `;`를 붙여요.
  ```text
  요청 시작
  체인 등록 끝
  Error: 학생 정보를 가져오지 못했습니다.
      at Timeout._onTimeout (…/student-result.js:5:12)
  ```
  실패를 받을 `.catch()`가 없으면 처리되지 않은 오류로 프로그램이 멈춰요. `Error:` 위에는 파일 경로와 `실패(…)` 줄이 `^` 표시와 함께 나와요. 되돌려요.

## 4단계: `async/await`로 같은 결과 받기

`.then()` 대신 `await`로 Promise의 결과를 받을 수도 있어요. 3단계 `student-result.js`의 `getStudent()`는 그대로 두고, 아래쪽 호출 부분만 바꿔요.

`const student = await getStudent(true);`는 "이 Promise에 성공 결과가 들어올 때까지 이 함수의 다음 줄로 가지 않고, 들어오면 그 값을 `student`에 넣는다"는 뜻이에요. `.then((student) => { … })` 안에 쓰던 코드를 `await` 아래에 위에서부터 차례로 쓰면 돼요. 하는 일은 같고, 흐름이 위에서 아래로 읽혀서 알아보기 쉬워요.

`await`는 `async`를 붙인 함수 안에서 써요. `async`를 붙인 함수는 **항상 Promise를 돌려줘요.** `async function getNumber() { return 10; }`을 부르고 그 값을 찍으면 `Promise { 10 }`이 나와요. 그래서 `main()`처럼 `async` 함수를 부르는 줄도 결과를 바로 받지 않아요. Promise가 거부되면 `await`한 그 줄에서 오류가 나요. 처리하는 코드가 없으면 3단계에서 `.catch()`를 지웠을 때처럼 프로그램이 멈춰요. 처리 방법은 6단계에서 봐요.

### ▶ 직접 해 보기 — `student-result.js`
`console.log("요청 시작");`부터 끝까지(체인)를 지우고 아래로 바꿔요 (강의 5장 코드).
```javascript
async function main() {
  const student = await getStudent(true);

  console.log("받은 학생:", student);
}

main();
```
약 3초 뒤:
```text
받은 학생: 한코딩
```

**바꿔 보기**
- `getStudent(true)`를 `getStudent(false)`로 바꿔요. 노션의 `await` 설명 코드가 이렇게 적혀 있어요. → 3초 뒤 `Error: 학생 정보를 가져오지 못했습니다.`와 `at …` 줄이 나오고 프로그램이 멈춰요. `true`로 되돌려요.
- `await`를 지워요. → 3초를 기다리지 않고 바로 `받은 학생: Promise { <pending> }`이 찍혀요. `await`가 없으면 결과가 아니라 Promise 자체가 `student`에 들어가요. Node 04회차에서 `response.json()` 앞의 `await`를 지웠을 때와 같은 실수예요. 되돌려요.

## 5단계: `await`는 그 함수 안의 다음 줄만 기다린다

`await`에서 무엇이 멈추는지 정확히 알아야 출력 순서를 맞힐 수 있어요. `async` 함수를 부르면 이런 순서로 실행돼요.

1. 첫 `await`를 만나기 전까지의 줄은 **부르자마자 바로** 실행돼요. 보통 함수를 부를 때와 같아요.
2. `await`를 만나면 그 함수는 거기서 멈추고, 함수를 부른 자리로 돌아가요. 함수의 나머지 줄은 미뤄 둬요.
3. 부른 자리의 다음 줄부터 **바깥 코드가 끝까지** 실행돼요.
4. 기다리던 결과가 준비돼 있고 지금 코드가 끝났으면, 함수가 멈췄던 다음 줄부터 이어서 실행돼요.

중요한 건 2번이에요. **결과가 이미 준비돼 있어도** `await`를 만나면 함수는 한 번 멈추고 바깥으로 돌아가요. "기다릴 게 없으니 바로 다음 줄로 가겠지"라고 예상하면 틀려요. 01회차의 0초 타이머가 바로 실행되지 않았던 것과 같아요. 미뤄 둔 줄은 지금 실행 중인 코드가 끝난 다음에 실행돼요. 결과가 이미 있는 Promise에 `.then()`을 붙여도 마찬가지로, 넘긴 함수는 지금 코드가 끝난 뒤에 실행돼요. 그래서 `await`는 프로그램 전체를 멈추지 않아요. 멈추는 건 그 `async` 함수 하나예요. 그동안 바깥 코드는 계속 실행되고, 스레드도 붙잡혀 있지 않아요. 반대로 `async`를 붙였다고 함수 안의 계산이 다른 스레드에서 실행되는 것도 아니에요. 함수 안에 01회차의 긴 `while` 반복을 넣으면 여전히 스레드를 붙잡아요. 이건 03회차에서 서버로 확인해요.

### ▶ 직접 해 보기 — `student-result.js`
`async function main()`부터 끝까지를 아래로 바꿔요 (강의 6장 코드). `getStudent()`는 그대로예요.
```javascript
async function main() {
  console.log("1. 학생 정보 요청");

  const student = await getStudent(true);

  console.log("3. 받은 학생:", student);
}

main();

console.log("2. main 함수 밖의 작업");
```
```text

2. main 함수 밖의 작업
```
약 3초 뒤:

### ▶ 직접 해 보기 — `ready.js`
이번에는 기다릴 시간이 없는 작업이에요. `Promise.resolve(값)`은 **이미 성공 결과가 들어 있는** Promise를 바로 만들어요. 실행 전에 네 줄의 순서를 먼저 적어 봐요.
```javascript
async function loadSavedStudent() {
  console.log("함수 안: 저장해 둔 학생 꺼내기");

  const student = await Promise.resolve("한코딩"); // 이미 결과가 들어 있는 Promise

  console.log("함수 안: 받은 학생:", student);
}

console.log("부르기 전");

loadSavedStudent();

console.log("부른 뒤");
```
```text
부르기 전
함수 안: 저장해 둔 학생 꺼내기
부른 뒤
함수 안: 받은 학생: 한코딩
```
결과가 이미 있었는데도 `함수 안: 받은 학생`이 `부른 뒤`보다 늦게 찍혔어요. `await`에서 함수가 멈추고 바깥의 `부른 뒤`가 먼저 실행됐기 때문이에요. 위의 1~4번 순서 그대로예요.

**바꿔 보기**
- `await`를 지워요. → `부르기 전`, `함수 안: 저장해 둔 학생 꺼내기`, `함수 안: 받은 학생: Promise { '한코딩' }`, `부른 뒤`. 멈추는 곳이 없어서 함수가 끝까지 바로 실행되고, `student`에는 결과가 아니라 Promise가 들어가요. 되돌려요.
- `console.log("부르기 전");` 바로 아래에 `setTimeout(() => { console.log("0초 타이머"); }, 0);`을 넣어요. → `부르기 전`, `함수 안: 저장해 둔 학생 꺼내기`, `부른 뒤`, `함수 안: 받은 학생: 한코딩`, `0초 타이머`. 타이머를 먼저 예약했는데도 `await` 다음 줄이 먼저예요. 지금 코드가 끝나면 Node는 Promise 결과로 이어지는 코드를 타이머 콜백보다 먼저 처리해요. 자세한 단계는 강의 범위 밖이라 결과만 봐 두면 돼요. 타이머를 지워요.
- `await`를 함수 밖, 파일 맨 바깥에 쓰면 어떻게 될까요? 파일 내용을 아래로 바꿔요.
  ```javascript
  console.log("파일 맨 바깥: await 전");

  const student = await Promise.resolve("한코딩");

  console.log("파일 맨 바깥: 받은 학생:", student);

  console.log("파일 맨 바깥: 마지막 줄");
  ```
  ```text
  파일 맨 바깥: await 전
  파일 맨 바깥: 받은 학생: 한코딩
  파일 맨 바깥: 마지막 줄
  ```
  이번에는 적은 순서 그대로예요. 함수 안의 `await`는 그 함수만 멈추고 바깥으로 돌아가지만, 파일 맨 바깥의 `await`는 돌아갈 바깥이 없어서 **파일의 나머지 줄 전체**가 기다려요. 단, 파일 맨 바깥 `await`는 프로젝트 설정에 따라 결과가 달라요. 지금은 `_async연습장`에 `package.json`이 없어서 그냥 실행돼요. 03회차에서 `package.json`을 만든 뒤에는 `[MODULE_TYPELESS_PACKAGE_JSON] Warning: …` 경고가 먼저 찍히고, `package.json`에 `"type": "commonjs"`가 적힌 프로젝트(요즘 `npm init -y`가 만드는 모양)에서는 `SyntaxError: await is only valid in async functions and the top level bodies of modules`로 아예 실행되지 않아요. 그래서 강의처럼 `await`는 `async` 함수 안에 써요. `ready.js`를 원래 코드로 되돌려요.

## 6단계: `try/catch/finally`로 성공·실패·마무리 처리하기

4단계에서 `getStudent(false)`를 `await`하자 프로그램이 멈췄어요. `await`로 받을 때는 실패를 `try/catch`로 처리해요. 파이썬의 `try/except/finally`와 같은 구조예요.

- `try { … }`: 시도할 코드예요. 거부된 Promise를 `await`한 줄에서 오류가 나면, `try` 안의 **나머지 줄은 건너뛰고** 바로 `catch`로 가요. 3단계에서 거부되면 `.then()`을 건너뛰고 `.catch()`로 간 것과 같은 흐름이에요.
- `catch (error) { … }`: 오류가 났을 때 실행돼요. `error`는 `reject()`에 넣은 Error 객체라서 `error.message`로 문장을 꺼내요.
- `finally { … }`: 성공이든 실패든 **마지막에 항상** 실행돼요.

`catch`가 실패를 받으려면 `await`가 반드시 **`try` 안에** 있어야 해요. `try` 밖에서 `await`하면 오류가 `try`에 들어오기 전에 나서 `catch`가 받지 못해요. `await`를 빠뜨려도 받지 못해요. 그 줄에서는 Promise만 받고 넘어가서, 나중에 Promise가 거부될 때는 이미 `try`를 지나간 뒤이기 때문이에요. React에서 이 구조로 `finally`에서 로딩 상태를 끝냈어요. 요청이 성공해도 실패해도 로딩 표시는 꺼야 하니까요. 04회차의 느린 API 화면에서 다시 써요.

### ▶ 직접 해 보기 — `student-result.js` (강의 최종 코드)
파일 내용을 전부 바꿔요. **이 코드의 매개변수는 `shouldFail`이라서 3·4단계와 반대예요.** `true`면 실패, `false`면 성공이에요. 지연도 `1000`이에요.
```javascript
function getStudent(shouldFail) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (shouldFail) {
        reject(new Error("학생 정보를 가져오지 못했습니다."));
        return;
      }

      resolve("한코딩");
    }, 1000);
  });
}

async function main() {
  console.log("학생 정보를 불러오는 중입니다.");

  try {
    const student = await getStudent(false);

    console.log("받은 학생:", student);
  } catch (error) {
    console.log("오류:", error.message);
  } finally {
    console.log("학생 정보 요청 처리를 마쳤습니다.");
  }
}

main();
```
```text
학생 정보를 불러오는 중입니다.
받은 학생: 한코딩
학생 정보 요청 처리를 마쳤습니다.
```

**바꿔 보기**
- (강의의 직접 바꿔보기) `getStudent(false)`를 `getStudent(true)`로 → `학생 정보를 불러오는 중입니다.`, `오류: 학생 정보를 가져오지 못했습니다.`, `학생 정보 요청 처리를 마쳤습니다.` `await` 다음의 `받은 학생:` 줄은 건너뛰고 `catch`로 갔어요. 두 경우 모두 `finally`의 마지막 문장이 찍혀요. `true`로 둔 채 다음 두 개를 해 봐요.
- `const student = await getStudent(true);` 줄을 `try {` 바로 위로 옮겨요 (`try` 밖). → `학생 정보를 불러오는 중입니다.` 다음에 `Error: 학생 정보를 가져오지 못했습니다.`가 나고 프로그램이 멈춰요. `catch`도 `finally`도 실행되지 않아요. 줄을 다시 `try` 안으로 옮겨요.
- `try` 안에서 `await`만 지워요.
  ```text
  학생 정보를 불러오는 중입니다.
  받은 학생: Promise { <pending> }
  학생 정보 요청 처리를 마쳤습니다.
  Error: 학생 정보를 가져오지 못했습니다.
  ```
  기다리지 않아서 Promise가 그대로 찍히고 `finally`까지 끝나요. 1초 뒤 Promise가 거부될 때는 받을 곳이 없어서 프로그램이 멈춰요. `await`를 되살리고 `false`로 되돌려요.

## 7단계: 차례로 기다리기와 `Promise.all()`로 함께 시작하기

학생 두 명의 정보를 가져오는데 각각 1초가 걸린다고 해 볼게요. `await`를 두 번 차례로 쓰면 두 번째 요청은 첫 번째 `await`가 끝난 뒤에야 **시작**돼요. 그래서 1초 + 1초, 약 2초가 걸려요. 이걸 **순차 실행**이라고 해요.

두 학생 정보가 서로 관계없다면 함께 시작해도 돼요. `Promise.all([Promise1, Promise2])`는 Promise 배열을 받아서, **모두 성공하면** 결과 배열이 들어가는 Promise를 하나 돌려줘요. 배열을 만드는 순간 `getStudent()`를 두 번 부르니까 타이머 두 개가 거의 동시에 시작돼요. 그다음 `await`가 둘 다 끝나기를 기다려요. 기다리는 시간이 겹쳐서 약 1초면 끝나요. 파이썬 `asyncio`의 `gather`와 같은 일을 해요. 여기서 "함께"는 기다리는 시간이 겹친다는 뜻이에요. `Promise.all()`이 함수를 다른 스레드에서 실행해 주는 게 아니에요. 계산을 CPU 여러 개로 나눠 하는 것도 아니고요.

결과 배열의 순서는 **끝난 순서가 아니라 넣은 순서**예요. 그리고 넣은 Promise 중 **하나라도 거부되면** `Promise.all()`도 바로 거부돼요. 이때 다른 작업이 자동으로 취소되지는 않아요.

시간은 `console.time("이름")`으로 재기 시작하고 `console.timeEnd("이름")`으로 끝내요. 두 이름이 같아야 해요. 1초가 넘으면 `2.006s`처럼 초로, 1초가 안 되면 `511.327ms`처럼 밀리초로 찍혀요.

### ▶ 직접 해 보기 — `sequential.js`
```javascript
function getStudent(name, delay) {
  return new Promise((resolve) => {
    setTimeout(() => {
      console.log(`${name} 정보 준비 완료`);
      resolve(name);
    }, delay);
  });
}

async function main() {
  console.time("순차 실행");

  const first = await getStudent("한코딩", 1000);
  const second = await getStudent("이학생", 1000);

  console.log("결과:", first, second);

  console.timeEnd("순차 실행");
}

main();
```
```text
한코딩 정보 준비 완료
이학생 정보 준비 완료
결과: 한코딩 이학생
순차 실행: 2.006s
```
두 번째 실행에서는 `2.007s`였어요. 숫자는 실행할 때마다 몇 ms씩 달라요.

### ▶ 직접 해 보기 — `concurrent.js`
`sequential.js`를 복사해 `concurrent.js`를 만들고 `main()`만 바꿔요.
```javascript
async function main() {
  console.time("동시 진행");

  const results = await Promise.all([
    getStudent("한코딩", 1000),
    getStudent("이학생", 1000)
  ]);

  console.log("결과:", results);

  console.timeEnd("동시 진행");
}

main();
```
```text
한코딩 정보 준비 완료
이학생 정보 준비 완료
결과: [ '한코딩', '이학생' ]
동시 진행: 1.009s
```
같은 작업 두 개인데 순차는 약 2초, `Promise.all()`은 약 1초 걸렸어요.

**바꿔 보기**
- 세 번째 학생을 넣어요. `sequential.js`에는 `const third = await getStudent("박학생", 1000);`을 넣고 결과 줄을 `console.log("결과:", first, second, third);`로, `concurrent.js`에는 배열에 `getStudent("박학생", 1000)`을 넣어요 (앞 줄 끝에 `,`). → `순차 실행: 3.012s`, `동시 진행: 1.008s`. 작업이 늘수록 순차는 1초씩 늘고, 함께 시작하면 가장 긴 작업 하나만큼 걸려요. 둘 다 되돌려요.
- (강의 10장) `concurrent.js`에서 `"한코딩", 1000`을 `"한코딩", 2000`으로, `"이학생", 1000`을 `"이학생", 500`으로 바꿔요. → `이학생 정보 준비 완료`, `한코딩 정보 준비 완료`, `결과: [ '한코딩', '이학생' ]`, `동시 진행: 2.002s`. `이학생`이 먼저 끝났지만 결과 배열은 넣은 순서예요. 전체 시간은 가장 긴 2초예요. 되돌려요.
- `sequential.js`의 `const first`·`const second` 두 줄을 아래처럼 바꿔요. 작업을 먼저 시작해 두고 결과는 나중에 받는 모양이에요.
  ```javascript
  const firstPromise = getStudent("한코딩", 1000);  // 작업 시작, Promise 받기
  const secondPromise = getStudent("이학생", 1000); // 작업 시작, Promise 받기

  const first = await firstPromise;   // 결과 받기
  const second = await secondPromise; // 결과 받기
  ```
  → `순차 실행: 1.005s`. `await`가 두 번이어도 두 작업이 `await`보다 먼저 시작돼서 기다림이 겹쳤어요. 8단계에서 이유를 봐요. 되돌려요.

### ▶ 직접 해 보기 — `all-fail.js`
하나가 실패하면 어떻게 되는지 봐요. `getStudent`에 실패 여부를 받는 세 번째 값을 더했어요.
```javascript
function getStudent(name, delay, shouldFail) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (shouldFail) {
        console.log(`${name} 정보 실패`);
        reject(new Error(`${name} 정보를 가져오지 못했습니다.`));
        return;
      }

      console.log(`${name} 정보 준비 완료`);
      resolve(name);
    }, delay);
  });
}

async function main() {
  console.time("동시 진행");

  try {
    const results = await Promise.all([
      getStudent("한코딩", 1000, false),
      getStudent("이학생", 500, true)
    ]);

    console.log("결과:", results);
  } catch (error) {
    console.log("오류:", error.message);
  } finally {
    console.timeEnd("동시 진행");
  }
}

main();
```
```text
이학생 정보 실패
오류: 이학생 정보를 가져오지 못했습니다.
동시 진행: 511.327ms
한코딩 정보 준비 완료
```
`이학생`이 0.5초에 실패하자 `Promise.all()`이 바로 거부돼서 `catch`와 `finally`가 실행됐어요. `결과:` 줄은 건너뛰었어요. 그런데 `한코딩` 타이머는 취소되지 않고 1초에 끝나서 `한코딩 정보 준비 완료`가 맨 뒤에 찍혔어요.

## 8단계: 순서를 지켜야 할 때, `fetch` 코드 다시 읽기, Promise와 `await`의 역할

7단계를 보면 모든 작업을 `Promise.all()`로 함께 시작하고 싶어져요. 하지만 **앞 작업의 결과가 다음 작업에 필요하면** 함께 시작할 수 없어요. 로그인해서 사용자 번호를 받아야 그 사용자의 게시글을 조회할 수 있는 경우가 그래요. 게시글 조회를 시작하려는 시점에는 사용자 번호가 아직 없어요. 그래서 빠른 방법부터 고르지 말고 **어떤 데이터가 어디에 필요한지(의존 관계)**를 먼저 봐요. 서로 관계없으면 `Promise.all()`, 앞 결과가 필요하면 `await`를 차례로 써요.

Node 04회차의 `fetch` 코드도 같은 이유로 `await`를 두 번 차례로 써요. `fetch()`는 요청을 보내고 Promise를 돌려줘요. 첫 `await`로 응답 객체(`response`)를 받아요. `response.json()`은 응답 본문을 읽어 JSON을 해석하는 작업이라 이것도 Promise를 돌려주고, `response`가 있어야 부를 수 있어요. 그래서 두 번째 `await`가 첫 번째 뒤에 와요.

`fetch()`에는 주의할 점이 있어요. 서버가 404나 500으로 응답해도 응답은 온 것이라서 Promise가 **거부되지 않아요.** 그래서 `response.ok`(상태 코드가 200번대면 `true`)를 직접 검사하고, 아니면 `throw new Error(…)`로 오류를 일으켜 `catch`로 보내요. `throw`도 `try` 안에서 나면 나머지 줄을 건너뛰고 `catch`로 가요. 서버가 꺼져 있어서 연결 자체를 못 하면 그때는 `fetch()`의 Promise가 거부돼요.

마지막으로 역할을 나눠 볼게요. `const promise = getStudent(…)`처럼 **함수를 부르는 순간 작업이 시작**되고, 그 자리에서 Promise를 받아요. `await promise`는 그 Promise의 결과를 받아 쓸 뿐이에요. `await`가 비동기 작업을 만들어 주는 게 아니에요. 7단계 마지막 바꿔 보기에서 작업 두 개를 먼저 불러 두고 나중에 하나씩 `await`했을 때 약 1초면 끝난 이유예요. 두 작업은 `await`를 만나기 전에 이미 함께 시작했어요.

### ▶ 직접 해 보기 — `fetch-check.js` (Node 과정 서버와 함께)

```javascript
    console.log("응답 상태:", response.status, "/ response.ok:", response.ok);
```

## 마무리: 최종 `student-result.js`가 실행되는 순서

6단계의 강의 최종 코드(`getStudent(false)`)를 실행하면 이 순서로 일이 일어나요.

1. `getStudent`와 `main` 함수를 정의해요. 아직 아무것도 실행되지 않아요.
2. 맨 아래 `main()`을 불러요. `async` 함수라서 Promise를 돌려주지만, 그 값은 쓰지 않아요.
3. `main` 안에서 `학생 정보를 불러오는 중입니다.`를 찍어요. 첫 `await` 앞이라 바로 실행돼요 (5단계).
4. `try`에 들어가 `getStudent(false)`를 불러요. `new Promise` 안의 함수가 바로 실행되어 1초 타이머를 예약하고, 대기 상태의 Promise를 돌려줘요 (2단계).
5. `await`에서 `main`이 멈추고 부른 자리로 돌아가요. 파일에 더 실행할 줄이 없으니 지금 코드가 끝나요 (5단계).
6. 1초 뒤 타이머 콜백이 실행돼요. `shouldFail`이 `false`라서 `resolve("한코딩")`이 불리고, Promise가 이행 상태가 돼요.
7. `main`이 `await` 다음 줄부터 이어서 실행돼요. `student`에 `"한코딩"`이 들어가고 `받은 학생: 한코딩`을 찍어요.
8. 오류가 없었으니 `catch`는 건너뛰고, `finally`의 `학생 정보 요청 처리를 마쳤습니다.`를 찍어요 (6단계).
9. 남은 예약이 없으니 프로그램이 끝나요.

`getStudent(true)`였다면 6번에서 `reject`가 불려 Promise가 거부되고, 7번에서 `await` 줄이 오류를 내서 `받은 학생:` 줄을 건너뛰고 `catch`로 가요. 8번의 `finally`는 똑같이 실행돼요.

## 오류가 날 때 찾아보기

| 오류 문장 · 증상 | 먼저 볼 곳 |
|---|---|
| 결과가 `undefined` | 타이머 콜백 안에서만 `return`했는지. 결과는 `resolve`로 넘김 (1·2단계) |
| `Promise { <pending> }`이나 `Promise { '…' }`가 찍힘 | 결과를 `await`나 `.then()`으로 꺼냈는지 (2·4·5단계) |
| `TypeError: Cannot read properties of undefined (reading 'then')` | `return new Promise(…)`의 `return`이 있는지 (2단계) |
| `.then()` 안의 코드가 실행되지 않음 | Promise가 거부됐는지. 거부되면 `.then()`은 건너뛰고 `.catch()`로 감 (3단계) |
| `Error: …`와 함께 프로그램이 멈춤 | `.catch()`가 연결됐는지, `await`가 `try` 안에 있는지 (3·4·6단계) |
| 오류 문장 아래에 `at …` 줄이 길게 찍힘 | `error` 대신 `error.message`를 찍기 (3단계) |
| `catch`가 있는데도 오류를 못 받음 | `await`가 `try` 밖에 있거나 빠졌는지 (6단계) |
| 성공·실패가 반대로 나옴 | 매개변수가 `shouldSuccess`인지 `shouldFail`인지 (3·6단계) |
| `SyntaxError: await is only valid in async functions and the top level bodies of modules` | `await`를 쓴 함수에 `async`가 있는지. 파일 맨 바깥 `await`는 `package.json` 설정에 따라 안 됨 (5단계) |
| `await` 다음 줄이 함수 밖 코드보다 늦게 찍힘 | 정상. 결과가 이미 있어도 `await`에서 함수가 한 번 멈춤 (5단계) |
| 독립된 작업 두 개에 약 2초 | 두 번째 작업을 첫 `await` 뒤에 시작했는지 (7·8단계) |
| `fetch`가 404인데 `catch`로 안 감 | `response.ok` 검사와 `throw`가 있는지 (8단계) |
| `오류: fetch failed` | 서버가 켜져 있는지, 주소·포트 (8단계) |
| `받은 학생 수: undefined` | `response.json()` 앞에 `await`가 있는지 (8단계) |
