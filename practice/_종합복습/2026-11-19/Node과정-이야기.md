# Node 과정 이야기 — 무슨 일이 어떤 순서로 일어나나

> 날짜: 2026-11-19 (목) · 범위: Node 01~04 · 사용자 요청: 이야기처럼 읽히게, 쉬운 말로, **비유 없이**, 코드는 최소한

## 시작: React 앱의 한계

React 과정 마지막에 할 일 앱을 만들었어요. 할 일을 적으면 화면에 나오고, 지울 수도 있었어요.

그런데 새로고침하면 할 일이 전부 사라졌어요. 이유는 데이터가 있던 곳에 있어요. 할 일 목록은 React의 state에 들어 있었고, state는 **지금 열려 있는 브라우저 탭의 메모리**에만 있어요. 새로고침하면 그 메모리가 비워지고, 목록도 같이 사라져요. 같은 이유로 다른 사람 컴퓨터에서는 내 목록을 볼 수 없어요. 데이터가 내 브라우저 안에만 있으니까요.

이 문제를 풀려면 데이터를 브라우저 밖에 둬야 해요. **계속 켜져 있는 별도의 프로그램**이 데이터를 갖고 있고, 화면은 필요할 때 그 프로그램에서 데이터를 받아 오는 거예요. 그 별도의 프로그램이 **서버**예요.

Node 과정은 이 서버를 만들고, React 화면과 연결하는 과정이었어요.

## 01: 역할 나누기와 Node.js

웹 서비스는 보통 세 부분으로 나눠요.
- **프론트엔드**: 사용자가 보는 화면이에요. 사용자의 브라우저에서 실행돼요. (React)
- **백엔드**: 화면 뒤에서 데이터를 처리하는 프로그램이에요. 서버에서 실행돼요. (이번에는 Node.js)
- **데이터베이스**: 데이터를 오래 저장하는 곳이에요. (나중 과정)

프론트엔드와 백엔드는 서로 메시지를 주고받아요.
- 프론트엔드가 "학생 목록을 주세요"라고 보내는 메시지가 **요청**이에요.
- 백엔드가 학생 목록을 담아 돌려보내는 메시지가 **응답**이에요.
- 주고받는 데이터는 **JSON**이라는 글자 형식으로 써요. JavaScript 객체와 거의 같은 모양인데, 속성 이름에도 큰따옴표를 붙인 글자예요. 어떤 언어로 만든 프로그램이든 읽을 수 있어서 이 형식을 써요.
- "이 주소로 요청하면 이런 데이터를 돌려준다"고 정해 둔 규칙을 **API**라고 해요.

화면에서 다 처리하지 않고 백엔드를 따로 두는 이유는 세 가지예요.
1. 여러 사용자가 같은 데이터를 봐야 해요. 데이터가 한 사람의 브라우저에만 있으면 다른 사람은 못 봐요.
2. 브라우저에서 실행되는 코드는 사용자가 열어 보고 바꿀 수 있어요. 그래서 입력값 검사나 권한 확인은 서버에서 한 번 더 해야 해요.
3. 비밀번호나 API 키 같은 비밀 정보를 브라우저 코드에 넣으면 누구나 볼 수 있어요. 비밀 정보는 서버에만 둬요.

백엔드는 이미 아는 JavaScript로 만들었어요. 원래 JavaScript는 브라우저 안에서만 실행됐어요. **Node.js**는 JavaScript를 브라우저 밖, 내 컴퓨터의 터미널에서 실행하게 해 주는 프로그램이에요. 파이썬의 `python 파일.py`처럼 `node 파일.js`로 실행해요.

Node.js에는 화면이 없어요. 그래서 화면을 다루는 `document` 같은 기능은 쓸 수 없고, 쓰면 오류가 나요. `console.log`의 결과도 브라우저가 아니라 터미널에 찍혀요.

다른 사람이 만든 코드 묶음(**패키지**)은 **npm**으로 설치해요. 파이썬의 `pip`과 같아요.

## 02: 서버가 하는 일을 터미널에서 먼저 연습

바로 서버를 만들지 않고, 터미널에서 도는 학생 관리 프로그램을 먼저 만들었어요. 서버가 하는 일과 순서가 같기 때문이에요.

프로그램은 이렇게 돌아요.
1. 메뉴를 보여 주고 사용자의 입력을 받아요.
2. 입력이 올바른지 검사해요.
3. 학생 배열에 추가하거나, 목록을 보여 주거나, 삭제해요.
4. 결과를 출력해요.
5. 1번으로 돌아가요. 0을 입력하면 끝나요.

이 과정은 `while (true)`로 계속 반복했어요.

터미널에서 입력을 받으려고 `readline-sync` 패키지를 썼어요. 이때 처음으로 npm을 써 봤어요.
- `npm install readline-sync`로 설치하면 `package.json` 파일에 "이 프로젝트는 readline-sync를 쓴다"가 기록돼요.
- 코드에서는 `require("readline-sync")`로 가져와요. 파이썬의 `import`와 같아요.
- 폴더 이름(`_node연습장`)에 한글과 `_`가 들어 있어서 `npm init -y`가 실패했어요. 그래서 `package.json`을 직접 만들었어요.

여기서 배운 중요한 점이 두 가지 있어요.
- **입력은 항상 문자열이에요.** `20`을 입력해도 숫자 20이 아니라 문자열 `"20"`이에요. 숫자로 쓰려면 `Number()`로 바꿔야 해요. 숫자가 아닌 값(`NaN`)이나 범위를 벗어난 값은 검사해서 막아야 해요.
- **서버도 이 프로그램처럼** "입력 받기 → 검사 → 처리 → 결과 보내기"를 반복해요. 차이는 입력이 키보드가 아니라 다른 프로그램이 보낸 요청이라는 것뿐이에요.

## 03: 진짜 서버 만들기

이제 입력을 키보드 대신 브라우저의 요청으로 받는 진짜 서버를 만들었어요. Node.js만으로도 서버를 만들 수 있지만 코드가 길어져서 **Express** 패키지를 썼어요 (`npm install express`).

서버 코드는 세 부분으로 되어 있어요.
1. `const app = express();`로 서버를 하나 만들어요.
2. `app.get("/students", 함수)`로 "`/students` 주소로 GET 요청이 오면 이 함수를 실행한다"를 등록해요. 이걸 **라우팅**이라고 해요. 함수 안의 `res.json(students)`가 학생 배열을 JSON 글자로 바꿔서 응답으로 보내요.
3. `app.listen(3000)`으로 3000번 포트에서 요청을 기다리기 시작해요.

`node server.js`로 실행하면 프로그램이 끝나지 않고 계속 켜져 있어요. 요청이 올 때마다 Express가 주소에 맞는 함수를 실행해요. 02에서 `while (true)`로 직접 하던 반복을 Express가 대신 해 주는 거예요. 끄려면 `Ctrl + C`를 눌러요.

`http://localhost:3000/students`라는 주소는 세 부분으로 나눠 읽어요.
- `localhost`: 지금 이 컴퓨터
- `3000`: **포트** 번호. 한 컴퓨터에서 여러 프로그램이 동시에 통신할 수 있도록 프로그램마다 번호를 하나씩 정해요. 이 서버는 3000번을 써요.
- `/students`: **경로**. 서버 안에서 어떤 데이터를 원하는지 나타내요.

브라우저 주소창에 이 주소를 입력하면 브라우저가 서버에 GET 요청을 보내요. 그러면 화면에 `[{"id":1,"name":"한코딩"}, …]`이 보이고, 서버 터미널에는 서버 코드의 `console.log` 결과가 찍혀요. `console.log`는 서버 터미널에만 나와요. 브라우저로 가는 건 `res.json`이나 `res.send`로 보낸 것뿐이에요.

서버를 다루면서 이런 일들을 겪었어요.
- 코드를 고치고 저장해도 결과가 그대로였어요. 실행 중인 서버는 켤 때 읽은 코드로 계속 돌아가요. 끄고 다시 켜야 바뀐 코드가 적용돼요.
- 등록하지 않은 경로로 요청하면 `Cannot GET /경로`가 와요. 상태 코드는 404예요.
- 함수 안에서 `res.json`을 빼먹으면 응답이 없어서 브라우저가 계속 기다려요.
- 서버를 끈 상태에서 요청하면 "사이트에 연결할 수 없음"이 나와요.
- 3000번 서버가 이미 켜져 있는데 하나 더 켜면, 두 번째 서버는 "서버 실행 중"만 찍고 바로 끝나요 (Express 5).

그래도 문제가 두 가지 남았어요.
- 브라우저에 보인 건 JSON 글자 그대로였어요. 사람이 보기 좋은 화면이 아니었어요.
- 학생 배열은 서버 프로그램의 메모리에 있어요. 그래서 서버를 껐다 켜면 처음 상태로 돌아가요. `res.json`은 데이터를 보낼 뿐 저장하지 않아요. 오래 저장하려면 데이터베이스가 필요해요.

## 04: React 화면과 서버 연결하기

첫 번째 문제(JSON 글자 그대로)를 해결하려고, React 코드가 서버에 요청을 보내고 받은 데이터로 목록 화면을 만들게 했어요.

이제 프로그램 두 개가 동시에 실행돼요.
- **서버**: `_node연습장`에서 `node server.js`로 켜요. 3000번 포트를 써요.
- **React 개발 서버**: `_react연습장`에서 `npm run dev`로 켜요. 5173번 포트를 써요. 브라우저는 여기서 React 화면을 받아요.

### 파일 이름 오류

처음에는 화면이 아예 안 나왔어요. `App.jsx`는 `./components/StudentList` 파일을 가져오려고 하는데, 실제 파일 이름은 `StudentsList.jsx`였어요. 이름이 달라서 Vite가 파일을 못 찾았고, `Failed to resolve import` 오류를 냈어요. 파일 이름을 `StudentList.jsx`로 바꾸니 화면이 나왔어요. import 경로와 파일 이름은 글자 하나까지 같아야 해요.

### CORS

React 화면에서 버튼을 눌러 서버에 요청했어요. 그런데 CORS를 설정하기 전에는 응답을 받을 수 없어요.

브라우저는 **출처**라는 기준으로 보안을 지켜요. 출처는 프로토콜(`http`), 호스트(`localhost`), 포트를 합친 거예요. React 화면은 `http://localhost:5173`, 서버는 `http://localhost:3000`이에요. 포트가 다르니 브라우저는 둘을 다른 출처로 봐요.

브라우저에는 이런 규칙이 있어요. 어떤 출처에서 실행 중인 JavaScript가 다른 출처에 요청해서 받은 응답은, **그 서버가 허락했을 때만** 읽을 수 있어요. 서버는 응답에 `Access-Control-Allow-Origin: http://localhost:5173`이라는 헤더를 붙여서 허락해요. 이 규칙이 **CORS**예요.

여기서 알아 둘 점이 두 가지 있어요.
- **요청은 서버까지 도착해요.** 서버는 함수를 실행하고 응답도 보내요. 그래서 서버 터미널에는 로그가 찍혀요. 브라우저가 막는 건 그 응답을 React 코드에 넘겨주는 것이에요.
- **주소창에 직접 주소를 입력하면 이 검사를 하지 않아요.** 다른 출처의 JavaScript가 응답을 읽으려 할 때만 검사해요. 그래서 03에서는 문제가 없었어요.

해결 방법은 이래요. 서버에 `cors` 패키지를 설치하고(`npm install cors`), 라우트보다 앞에 `app.use(cors({ origin: "http://localhost:5173" }))`를 넣어요. `app.use`는 모든 요청에 공통으로 적용할 처리를 등록해요. 이제 서버의 모든 응답에 허락 헤더가 붙어요.

CORS는 브라우저가 응답을 넘겨줄지 정하는 규칙일 뿐이에요. 로그인이나 권한 검사가 아니라서, 서버를 보호하는 검사는 따로 해야 해요.

### Console의 다른 오류들

Console에 `content.js`, `chrome-extension://`에서 나온 빨간 오류가 많이 보였어요. 크롬에 설치된 확장 프로그램이 모든 페이지에 넣는 코드가 낸 오류라서 내 코드와는 관계없어요. 오류마다 오른쪽에 있는 파일 이름을 보면 구별할 수 있어요. 시크릿 창에서는 확장 프로그램이 꺼져 있어서 내 코드의 메시지만 보여요. 거기서 학생 배열이 찍힌 걸 확인했어요.

### fetch와 async/await

React에서 서버에 요청할 때는 `fetch(주소)`를 써요. 브라우저에 들어 있는 기능이라 설치할 필요가 없고, 기본으로 GET 요청을 보내요.

서버 응답은 바로 오지 않아요. 짧더라도 시간이 걸려요. 그래서 `fetch`는 결과 대신 **Promise**를 바로 돌려줘요. Promise는 아직 끝나지 않은 작업의 결과를 나중에 받을 수 있게 해 주는 객체예요.

`await`를 붙이면 Promise가 끝나 결과가 나올 때까지 그 함수의 실행이 멈췄다가, 결과를 받으면 다음 줄로 가요. 멈추는 건 그 함수뿐이고, 화면이나 다른 코드는 계속 동작해요. `await`는 `async`가 붙은 함수 안에서만 쓸 수 있어요.

결과는 두 단계로 받아요.
1. `const response = await fetch(주소);`에서 `response`는 **응답 객체**예요. 상태 코드(`status`, 예: 200), 성공 여부(`ok`), 본문이 들어 있어요. 학생 배열이 아니에요.
2. `const data = await response.json();`은 응답 본문(JSON 글자)을 읽어서 JavaScript 배열로 바꿔요. 본문을 읽는 데도 시간이 걸려서 `await`를 붙여요. 이제 `data`가 학생 배열이에요.

파이썬 `requests`로 보면 `r = requests.get(url)` 다음에 `data = r.json()`과 같은 흐름이에요. 다른 점은 `requests.get`은 응답이 올 때까지 프로그램 전체를 멈춘다는 거예요. 브라우저에서 그러면 화면이 멈추기 때문에, JavaScript는 `await`로 그 함수만 기다리게 해요.

### state에 저장해서 화면 그리기

`data`를 `console.log`로 찍으면 Console에만 보여요. 화면에 표시하려면 state에 저장해요.
- `const [students, setStudents] = useState([]);`로 state를 만들어요.
- 받은 배열을 `setStudents(data)`로 저장해요.
- 그러면 React가 컴포넌트를 다시 실행해서 화면을 다시 그려요.
- `students.map(...)`이 학생마다 `<li>`를 하나씩 만들어요.

처음 값을 빈 배열 `[]`로 두는 이유가 있어요. 응답이 오기 전에도 화면은 먼저 그려지고 `students.map`이 실행돼요. 처음 값이 없으면(`undefined`) `map`을 쓸 수 없어서 오류가 나요.

서버의 데이터가 바뀌어도 이미 그려진 화면은 바뀌지 않아요. 서버가 React에 변경을 알려 주지 않기 때문이에요. 다시 요청해야 새 데이터를 받아요.

### useEffect: 화면이 처음 나타날 때 요청하기

버튼을 누르지 않아도 화면이 나타나자마자 목록을 불러오려고 `useEffect`를 썼어요.

컴포넌트 함수 안에서 바로 요청하면 안 돼요. React는 state가 바뀔 때마다 컴포넌트 함수를 다시 실행해요. 함수 안에서 바로 요청하면 요청 → `setStudents` → 함수 다시 실행 → 또 요청… 이 끝없이 반복돼요.

`useEffect(함수, [])`는 컴포넌트가 화면에 처음 나타난 뒤에 함수를 실행해요. 두 번째 인자 `[]`는 **의존성 배열**이에요. 이 배열 안의 값이 바뀔 때만 함수를 다시 실행하는데, 비어 있으니 처음 한 번만 실행돼요. `[]`를 빼면 화면이 다시 그려질 때마다 실행돼서 위의 끝없는 요청이 생겨요. 시험해 보니 1초에 수천 번 요청이 갔어요.

`useEffect`에 넘기는 함수에는 `async`를 붙이지 않아요. 대신 그 안에 `async function loadStudents() {…}`를 만들고 바로 `loadStudents()`로 불러요. `async`를 직접 붙이면 React가 오류를 내고 화면이 비어요.

개발 중에는 요청이 두 번씩 가요. `main.jsx`의 `<StrictMode>`가 개발할 때만 Effect를 한 번 더 실행해서, 정리 코드가 제대로 동작하는지 확인하기 때문이에요. 오류가 아니에요.

### 로딩·오류·빈 목록

요청이 항상 성공하지는 않아요. 그래서 최종 코드는 state를 세 개 써요.
- `students`: 받은 학생 목록
- `isLoading`: 요청 중인지 여부 (처음 값 `true`)
- `error`: 화면에 보여 줄 오류 문구 (처음 값 `""`)

실패는 `try / catch / finally`로 처리해요. 파이썬의 `try / except / finally`와 같아요.
- `try`: 요청하고, 성공했는지 확인하고, 데이터를 저장해요.
- `catch`: 오류가 나면 오류 문구를 저장해요.
- `finally`: 성공이든 실패든 `isLoading`을 `false`로 바꿔요.

여기서 조심할 점이 있어요. `fetch`는 서버가 404나 500으로 응답해도 오류를 내지 않아요. 응답을 받는 것 자체는 성공했기 때문이에요. `fetch`가 오류를 내는 건 서버가 꺼져 있거나 CORS로 막혀서 응답 자체를 못 받았을 때뿐이에요.
- 그래서 `response.ok`를 직접 확인해요. 상태 코드가 200~299면 `true`예요.
- `false`면 `throw new Error(...)`로 오류를 만들어 `catch`로 보내요.
- 파이썬 `requests`에서 `r.raise_for_status()`를 부르는 것과 같아요.

`ignore` 변수도 있어요. 컴포넌트가 화면에서 사라지거나 Effect가 다시 시작된 뒤에 이전 요청의 응답이 늦게 도착할 수 있어요. 그 응답으로 state를 바꾸지 않도록, Effect가 정리될 때 `ignore = true`로 바꿔 둬요. 요청을 취소하지는 않아요. 늦게 온 결과를 무시할 뿐이에요.

화면은 조건을 위에서부터 차례로 검사해서 하나만 보여 줘요.
1. `isLoading`이 `true`면 "불러오는 중입니다"
2. `error`가 있으면 오류 문구
3. 학생이 0명이면 "등록된 학생이 없습니다"
4. 나머지는 "전체 학생: n명"과 목록

## 정리: 한 번의 요청이 처리되는 순서

React 페이지를 열면 이 순서로 일이 일어나요.

1. 브라우저가 5173번에서 React 화면을 받아 실행해요. `StudentList` 컴포넌트가 화면에 나타나요.
2. `isLoading`이 `true`라서 "불러오는 중입니다"가 보여요.
3. `useEffect`가 실행돼서 `fetch`로 `http://localhost:3000/students`에 GET 요청을 보내요.
4. 요청이 3000번 포트의 서버에 도착해요.
5. Express가 경로 `/students`에 등록된 함수를 찾아 실행해요.
6. 서버 터미널에 "학생 목록을 요청받았습니다."가 찍혀요.
7. `res.json(students)`가 배열을 JSON 글자로 바꿔 보내요. `cors`가 허락 헤더를 붙여요.
8. 브라우저가 헤더를 확인하고 응답을 React 코드에 넘겨줘요.
9. `await fetch`가 끝나 `response`를 받아요. `response.ok`를 확인하고, `await response.json()`으로 배열을 꺼내요.
10. `setStudents(data)`로 저장하고, `finally`에서 `isLoading`을 `false`로 바꿔요.
11. React가 화면을 다시 그리고 `map`으로 목록을 만들어요. "전체 학생: 3명"이 보여요.

문제가 생기면 **서버 터미널에 로그(6번)가 찍혔는지**부터 봐요.
- 찍혔으면 요청은 서버에 도착했어요. 문제는 7번 이후에 있어요 (`res.json` 누락, CORS 설정, React 코드).
- 안 찍혔으면 요청이 서버까지 오지 못했어요. 문제는 6번 이전에 있어요 (React 코드, 서버가 꺼짐, 포트나 경로가 틀림).

## 다음 과정에서 이어지는 것

- 서버를 껐다 켜면 데이터가 사라져요. 데이터베이스 과정에서 데이터를 저장하는 법을 배워요.
- 지금은 목록 조회(GET)만 할 수 있고, 학생을 추가하는 요청은 아직 없어요. Spring 과정에서 Java로 서버를 만들면서 등록과 저장까지 해요. Spring 06에서는 이번에 만든 `StudentList.jsx`를 주소만 바꿔 다시 써요.
- Promise와 `await`가 안에서 어떻게 동작하는지는 비동기 과정에서 배워요.
- 지금은 서버 데이터가 바뀌어도 다시 요청해야만 알 수 있어요. 서버가 새 데이터를 먼저 보내 주는 방법(소켓)은 팀 프로젝트(실시간 채팅)에서 써요.
