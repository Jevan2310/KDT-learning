# 종합 복습 — Node과정 전체 그림 (01~04)

> 날짜: 2026-11-19 (목) · 범위: [Node 01~04](../../../wiki/02_Node과정/_과정개요.md)
> 사용자 요청: 쉬운 말로 쭉, 코드는 최소한, **전체 흐름**이 보이게. 문제 없이 설명만.

## 0. 한 장으로 보기

Node 과정 네 번의 수업은 결국 **이 그림 하나**를 만드는 과정이었어요.

```text
[React 화면 · 5173번]  ── ① 요청: "학생 목록 주세요" ──▶  [Node 서버 · 3000번]
                                                             ② 배열에서 꺼내 JSON으로 바꿈
[React 화면 · 5173번]  ◀── ③ 응답: [{"id":1,"name":"한코딩"}, …] ──
④ 받은 목록을 화면에 그림
```

| 회차 | 이 그림에서 배운 부분 | 식당으로 치면 |
|---|---|---|
| 01 | 그림에 나오는 **이름들** (프론트·백엔드·요청·응답·JSON) | 홀, 주방, 주문서가 뭔지 |
| 02 | 오른쪽 서버가 **일하는 순서** (받기 → 검사 → 처리 → 내보내기) | 주방 리허설 |
| 03 | 오른쪽 **진짜 서버** (주소로 주문 받고 JSON으로 내주기) | 가게 문 열기 |
| 04 | 왼쪽과 오른쪽을 **연결** (주문 넣기, 허락 도장, 화면에 차리기) | 홀과 주방 연결 |

## 1단계 (01) — 왜 서버가 필요할까?

**출발점**: React 할 일 앱은 새로고침하면 다 사라졌어요. 데이터가 **내 브라우저 안에만** 있었기 때문이에요. 다른 사람과 같이 볼 수도 없었고요.

**해결 방향**: 데이터를 맡아 줄 **다른 프로그램**을 따로 둬요. 그게 서버(백엔드)예요.

| 식당 | 웹 | 하는 일 |
|---|---|---|
| 홀 | 프론트엔드 (React) | 손님이 보는 화면 |
| 주방 | 백엔드 (Node 서버) | 주문을 받아 처리 |
| 창고 | 데이터베이스 | 오래 보관 (나중 과정) |

홀과 주방 사이에서 쓰는 말이에요.
- **요청**: 주문서 ("학생 목록 주세요")
- **응답**: 나온 음식
- **JSON**: 음식을 담는 정해진 그릇 모양. 홀과 주방이 둘 다 읽을 수 있는 글자 형식이에요
- **API**: 메뉴판. "이 주소로 주문하면 이걸 줄게요"라는 약속이에요

**주방을 꼭 따로 두는 이유 3가지**
1. 여러 사람이 **같은 데이터**를 봐야 해서
2. 중요한 **검사**는 손님 손이 닿지 않는 곳에서 해야 해서
3. **비밀**(비밀번호, 키)은 손님에게 보이면 안 돼서

**도구 두 개**
- **Node.js**: JavaScript를 브라우저 밖(터미널)에서 돌려 주는 프로그램이에요. 파이썬의 `python 파일.py`처럼 `node 파일.js`로 실행해요.
- **npm**: 남이 만든 도구(패키지)를 받아 오는 가게예요. 파이썬의 `pip`과 같아요.
- 브라우저 밖이라서 화면 도구(`document`)는 없어요.

## 2단계 (02) — 주방 리허설: 터미널 학생 관리

**왜 했나**: 진짜 손님(브라우저)을 받기 전에, 주방이 일하는 **순서**를 터미널에서 먼저 연습했어요. 서버가 하는 일과 모양이 똑같거든요.

```text
입력 받기 → 검사하기 → 배열에 추가·조회·삭제 → 결과 보여 주기 → 다시 처음으로
```

- 입력은 `readline-sync` 패키지로 받았어요. 처음으로 `npm install`로 설치하고 `require`로 가져왔죠.
- **입력은 언제나 글자**예요. `"20"`은 숫자 20이 아니에요. 숫자가 필요하면 바꾸고, 이상한 값은 검사로 막아요.
- `while (true)`로 0을 누를 때까지 계속 돌았어요.

**여기서 가져갈 것**
- 서버도 **"받기 → 검사 → 처리 → 내보내기"**를 끝없이 반복해요.
- **들어온 값은 믿지 않아요.** 그래서 서버에서 검사해요 (1단계 이유 2번).

## 3단계 (03) — 가게 문 열기: Express 서버

**왜 했나**: 2단계는 내가 직접 입력했죠. 이제 **브라우저가 주소로 주문**을 넣어요.

**Express**는 주문 받기와 음식 내주기를 쉽게 해 주는 패키지예요.

```javascript
app.get("/students", (req, res) => {   // 메뉴판 한 줄: 이 주소로 오면
  res.json(students);                  // 학생 배열을 JSON으로 내준다
});
```
- `app.get("/주소", …)`: 메뉴판 한 줄이에요. "이 주소로 오면 이 일을 해요."
- `res.json(…)`: 쟁반에 담아 내주기예요. 배열을 JSON 글자로 바꿔서 보내요.
- `app.listen(3000)`: 3000번 창구 문을 열고 계속 기다려요.

**주소 읽기**: `http://localhost:3000/students`
→ 우리 집(`localhost`)의 3000번 창구(`3000`)에서 학생 목록 메뉴(`/students`)를 달라는 뜻이에요.

| 02 터미널 프로그램 | 03 서버 |
|---|---|
| `while (true)`로 내가 반복 | `app.listen`이 알아서 계속 기다림 |
| `if (입력 === "2")`로 할 일 고르기 | `app.get("/students")`처럼 **주소**로 고르기 |
| `console.log`로 터미널에 출력 | `res.json`으로 **브라우저에** 응답 |

**기억할 것**
- 서버는 `Ctrl + C`를 누를 때까지 켜져 있어요. 코드를 고치면 **껐다 켜야** 해요.
- `console.log`는 주방 메모(서버 터미널)예요. 손님에게 가는 건 `res.json`이에요.
- 응답을 안 보내면 손님은 하염없이 기다려요 (계속 로딩).
- 보내는 건 저장이 아니에요. 서버를 껐다 켜면 배열은 처음으로 돌아가요. 진짜 보관은 창고(DB) 과정에서 해요.

## 4단계 (04) — 홀과 주방 연결: React가 손님

**왜 했나**: 3단계에서는 내가 주소창에 쳐서 JSON 글자만 봤어요. 진짜 서비스는 **React 화면이 대신 주문**하고, 받은 걸 **목록 화면**으로 보여 줘요.

이제 프로그램이 둘이에요. 서버(3000)와 React(5173)를 터미널 두 개로 같이 켜요.

**연결하는 다섯 조각**
1. **CORS (경비원 도장)**: 5173과 3000은 포트가 달라서 브라우저가 "다른 집"으로 봐요. 서버가 "5173은 읽어도 돼요"라는 도장(`cors`)을 찍어 줘야 React가 응답을 받아요. 도장이 없어도 주문은 주방까지 가요. 막히는 건 음식 전달이에요.
2. **fetch + await (진동벨)**: `fetch`로 주문하면 진동벨을 받고, `await`로 울릴 때까지 기다려요. 받은 건 포장 상자(`response`)라서 `.json()`으로 한 번 더 뜯어야 배열이 나와요.
3. **state (테이블에 올리기)**: 배열을 `setStudents`로 state에 넣으면 React가 화면을 다시 그려요. `map`으로 목록을 만들어요.
4. **useEffect (앉자마자)**: 버튼을 누르지 않아도 화면이 뜨자마자 한 번 주문해요. `[]`는 "처음 한 번만"이라는 뜻이에요.
5. **로딩·오류·빈 목록 (손님 응대)**: 기다리는 중에는 "잠시만요", 실패하면 "죄송합니다", 0명이면 "아직 없어요"를 보여 줘요. `fetch`는 404에도 성공이라고 하니까 `response.ok`로 직접 확인해요.

```jsx
useEffect(() => {
  async function load() {
    const response = await fetch("http://localhost:3000/students"); // 주문하고 기다리기
    const data = await response.json();                             // 상자 뜯기
    setStudents(data);                                              // 테이블에 올리기
  }
  load();
}, []);                                                             // 처음 한 번만
```

## 5. 주문 하나를 처음부터 끝까지 따라가 보기

React 페이지를 열면 이 순서로 일이 일어나요. 괄호는 배운 회차예요.

1. 브라우저에서 `localhost:5173`을 열면 React 화면이 뜨고 학생 목록 칸이 나타나요 (React 과정)
2. 처음에는 "불러오는 중입니다"가 보여요 (04 로딩)
3. `useEffect`가 바로 실행돼서 `fetch`로 주문서를 보내요 (04)
4. 주문서가 3000번 창구에 도착해요 (03 포트)
5. Express가 주소 `/students`를 보고 메뉴판에서 맞는 줄을 찾아요 (03)
6. 서버 터미널에 "학생 목록을 요청받았습니다."가 찍혀요 (03 주방 메모)
7. `res.json`이 배열을 JSON 글자로 바꿔 쟁반에 담고, `cors`가 도장을 찍어요 (03, 04)
8. 브라우저(경비원)가 도장을 확인하고 React에 넘겨줘요 (04 CORS)
9. 진동벨이 울려 `await`가 끝나요. 상자를 열어 배열을 꺼내요 (04)
10. `setStudents`로 테이블에 올리고 로딩을 끝내요 (04, React 07)
11. React가 다시 그리면서 `map`으로 목록을 만들어요. "전체 학생: 3명"이 보여요 (React 06)

개발 중에는 3~11이 두 번 일어나요. Strict Mode가 "정리가 잘 되나" 확인하려고 한 번 더 해 보는 거예요.

## 6. 어디서 끊기면 무엇이 보일까

같은 흐름에서 **몇 번 칸이 고장 났는지**에 따라 보이는 게 달라요. 오류를 보면 어디서 끊겼는지 알 수 있어요.

| 끊긴 칸 | 원인 | 보이는 것 |
|---|---|---|
| 1번 | 파일 이름과 import가 다름 (오늘 겪은 것) | 화면 대신 빨간 `Failed to resolve import` |
| 4번 | 서버가 꺼짐, 포트가 틀림 | `Failed to fetch` (주소창이면 "연결할 수 없음") |
| 5번 | 주소 경로 오타 | `404`, `Cannot GET /…` |
| 7번 | `res.json`을 빠뜨림 | 계속 로딩 |
| 8번 | `cors`가 없음, 허락한 주소가 다름 | `blocked by CORS policy` |
| 9번 | `await`를 빠뜨림 | `Promise {<pending>}` |
| 11번 | 받은 게 배열이 아님, state 처음 값이 없음 | `map is not a function`, 하얀 화면 |
| 아무 데나 | 서버 코드를 고치고 재시작 안 함 | 바뀐 게 안 보임 |

**반으로 가르는 요령**: 서버 터미널에 로그(6번)가 **찍혔는지** 먼저 봐요.
- 찍혔으면 주문은 주방에 도착했어요. 문제는 그 뒤(7~11번: 응답, 도장, React 쪽)예요.
- 안 찍혔으면 주문이 주방까지 못 왔어요. 문제는 그 앞(1~5번: React 코드, 서버 꺼짐, 주소)이에요.

## 7. 파이썬으로 다시 보면

| Node 과정 | 파이썬이라면 |
|---|---|
| `node 파일.js` | `python 파일.py` |
| `npm install express` | `pip install flask` |
| `require("express")` | `import flask` |
| `readline.question()` | `input()` |
| `app.get("/students")` + `res.json(…)` | `@app.get("/students")` + `return jsonify(…)` |
| `await fetch(url)` → `await response.json()` | `requests.get(url).json()` |
| `try / catch / finally` | `try / except / finally` |

## 8. Node 과정에서 아직 비어 있는 칸 (다음 과정이 채워요)

| 비어 있는 칸 | 지금 상태 | 채워 주는 곳 |
|---|---|---|
| 오래 보관하기 | 서버를 끄면 사라짐 (배열) | 데이터베이스 과정 |
| 추가·수정·삭제 주문 | 목록 보기(GET)만 함 | Spring 과정 (폼으로 등록, 저장) |
| 같은 주방을 Java로 | Node(JavaScript)로만 만듦 | Spring 과정 |
| 기다림의 원리 | `await`를 "모양만" 씀 | 비동기 과정 |
| 바뀌면 바로 알려 주기 | 다시 주문해야 바뀜 | 팀 프로젝트 (소켓) |

## 한 문단 요약

화면(React)은 데이터를 갖고 있지 않아요. 필요할 때 서버에 **주소로 주문**해요. 서버(Node + Express)는 주소를 보고 맞는 데이터를 **JSON으로 내줘요**. 둘의 포트가 다르면 서버가 **CORS 도장**을 찍어 줘야 화면이 받을 수 있어요. 화면은 받은 데이터를 **state에 넣어 다시 그리고**, 기다리는 동안과 실패했을 때도 손님에게 알려 줘요.
