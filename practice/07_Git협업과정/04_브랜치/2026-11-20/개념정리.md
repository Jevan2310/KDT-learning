# 개념 정리 — Git협업과정 04. 브랜치

> 날짜: 2026-11-20 · wiki: [04_브랜치](../../../../wiki/07_Git협업과정/04_브랜치.md)
> 단계별 설명문으로 쓰고, 단계 끝마다 터미널에 직접 쳐 보는 명령을 둔다. 쉬운 말, 비유 없이. 명령과 출력은 이 Mac의 Git 2.50.1(zsh)로 미리 실행해 확인했다. 버전 번호(7글자)는 매번 다르다.

## 들어가며

02~03회차에서는 커밋이 한 줄로만 쌓였어요. 새 커밋은 항상 바로 앞 커밋 다음에 붙었죠.

그런데 실제 개발에서는 이러면 곤란해요. 로그인 기능을 만드는 중인데 아직 반쯤 됐다고 해 볼게요. 그 상태로 커밋하면 `main`에 덜 된 코드가 섞여요. 그사이 급한 버그를 고쳐야 하면, 덜 된 로그인 코드와 버그 수정이 같은 줄에 뒤섞여요. 팀이면 더 심해요. 다섯 명이 한 줄에 동시에 커밋하면 서로의 미완성 코드가 계속 끼어들어요.

**브랜치**는 커밋 줄기를 나눠서 이 문제를 풀어요. 로그인은 `login` 줄기에서, 버그 수정은 `hotfix` 줄기에서 따로 쌓고, 다 된 것만 `main`에 합쳐요. 06회차의 팀 작업 순서도 "작업용 브랜치를 만들어 작업 → `main`에 합치기"예요. 오늘이 그 바탕이에요.

---

## 🛠 시작하기

오늘은 결과를 똑같이 보려고 03회차 폴더 대신 새 폴더를 써요. GitHub는 쓰지 않아요.

```bash
mkdir -p ~/git-practice/branch-test
cd ~/git-practice/branch-test
git init
```

`git log` 출력이 화면보다 길면 아래에 `:`가 보이고 멈춰요. `q`를 누르면 빠져나와요.

## 1단계: 브랜치는 갈라져 나온 커밋 줄기다

브랜치를 만들면 **지금 커밋에서 갈라지는 새 줄기**가 생겨요. 새 줄기에서 커밋하면 그 커밋은 그 줄기에만 쌓여요. `main`에서는 보이지 않아요. 그래서 새 브랜치에서 무엇을 해도 `main`은 그대로예요. 강의가 "독립적인 작업 공간, 원본을 유지할 수 있다"고 한 게 이 뜻이에요.

다 만들면 그 줄기를 `main`에 **합쳐요(merge)**. 그때서야 `main`에도 그 커밋이 들어가요.

강의 그림을 글로 옮기면 이래요.

```text
main   ●───●───●───●───●───
        \           /
login    ───●───●───
```

`main`의 첫 커밋에서 `login`이 갈라져 커밋 두 개를 쌓고, `main`의 네 번째 커밋 자리에서 다시 합쳐져요. 그동안 `main`에도 다른 커밋이 쌓였어요. 두 번째 그림에는 `board` 브랜치가 하나 더 있고, `board`에서 또 `QnA`가 갈라졌다가 `board`로 합쳐져요. 브랜치에서 브랜치를 만들 수도 있고, 꼭 `main`으로만 합치는 것도 아니에요.

`git init`을 하면 첫 브랜치 `main`이 생겨요(01회차의 `init.defaultBranch`). 단, 브랜치는 커밋에서 갈라지기 때문에 **커밋이 하나도 없으면 브랜치를 만들 수 없어요.**

**지금 있는 브랜치**가 중요해요. 커밋은 지금 있는 브랜치에 쌓이고, 합치기도 지금 있는 브랜치로 가져와요. Git은 지금 있는 위치를 `HEAD`라고 불러요. `git log`에서 `HEAD -> main`이 보이면 "지금 `main`에 있다"는 뜻이에요. 05회차의 충돌 표시에도 `HEAD`가 나와요.

## 2단계: 브랜치 만들고 이동하기

| 명령 | 하는 일 |
|---|---|
| `git branch` | 브랜치 목록. 지금 있는 브랜치 앞에 `*` |
| `git branch 이름` | 새 브랜치를 만들기만 한다 (이동은 안 함) |
| `git checkout 이름` | 그 브랜치로 이동 |
| `git checkout -b 이름` | 만들면서 바로 이동 |

브랜치를 옮기면 **폴더 안의 파일이 그 브랜치의 마지막 커밋 상태로 바뀌어요.** `login`에서만 만든 파일은 `main`으로 옮기면 폴더에서 사라지고, 다시 `login`으로 오면 생겨요. 파일이 지워진 게 아니라, 그 브랜치의 기록대로 폴더를 바꿔 보여 주는 거예요.

> 요즘 Git에는 이동 전용 명령 `git switch 이름`, `git switch -c 이름`도 있어요. 강의의 `checkout`과 같은 일을 해요.

### ▶ 직접 해 보기 — 강의 기초 예제 앞부분

`main`에 커밋을 하나 만들어 두고 시작해요.

```bash
echo "회사 웹 사이트 코드" > main.txt
git add main.txt
git commit -m "웹 사이트 첫 버전"
git branch
```

```text
* main
```

```bash
git branch login
git branch
```

```text
  login
* main
```

`login`이 생겼지만 `*`는 아직 `main`에 있어요. 만들기만 했어요.

```bash
git checkout login
echo "로그인 기능" > login.txt
git add login.txt
git commit -m "로그인 기능 추가"
ls
```

```text
Switched to branch 'login'
[login 87e43a8] 로그인 기능 추가
 1 file changed, 1 insertion(+)
 create mode 100644 login.txt
login.txt	main.txt
```

커밋 줄의 `[login …]`은 이 커밋이 `login` 브랜치에 쌓였다는 뜻이에요.

```bash
git checkout main
ls
git log --oneline --graph --all
```

```text
Switched to branch 'main'
main.txt
* 87e43a8 (login) 로그인 기능 추가
* 58129dc (HEAD -> main) 웹 사이트 첫 버전
```

`main`으로 오니 `login.txt`가 폴더에서 사라졌어요. 그래프에서 `main`은 아래 커밋에, `login`은 그 위 커밋에 있어요. `--all`은 모든 브랜치를 보여 주는 옵션이에요.

**바꿔 보기**
- `git log --oneline`을 `--all` 없이 쳐요. `main`의 커밋 하나만 보여요. `--all`이 없으면 지금 브랜치의 기록만 나와요.
- `git checkout login` → `ls` → `git checkout main` → `ls`를 반복해서 파일이 생겼다 사라지는 걸 봐요.
- `git branch login`을 또 쳐요. `fatal: a branch named 'login' already exists`가 나와요.

---

## 3단계: 합치기 — `git merge`와 브랜치 지우기

`git merge 브랜치이름`은 그 브랜치의 커밋을 **지금 있는 브랜치로** 가져와요. 그래서 어디서 치는지가 중요해요. `login`을 `main`에 합치려면 먼저 `main`으로 이동한 뒤 `git merge login`을 쳐요. `login`에 있으면서 치면 반대 방향이 돼요.

합친 브랜치는 `git branch -d 이름`으로 지워요. 커밋은 이미 `main`에 들어가서 사라지지 않아요. 아직 합치지 않은 커밋이 있으면 `-d`는 지우지 않고 막아 줘요. 그래도 지우려면 `-D`(강제 삭제)를 쓰는데, 그 커밋을 버린다는 뜻이에요.

### ▶ 직접 해 보기 — 강의 기초 예제 뒷부분

`main`에 있는 상태에서 이어서 해요.

```bash
git merge login
ls
```

```text
Updating 58129dc..87e43a8
Fast-forward
 login.txt | 1 +
 1 file changed, 1 insertion(+)
 create mode 100644 login.txt
login.txt	main.txt
```

`main`에도 `login.txt`가 생겼어요. `Fast-forward`는 4단계에서 설명해요.

```bash
git branch -d login
git branch
```

```text
Deleted branch login (was 87e43a8).
* main
```

강의 코드의 마지막 줄 `bit branch`는 `git branch`의 오타예요. 그대로 치면 `zsh: command not found: bit`가 나와요.

**바꿔 보기**
- `git checkout -b test` → 파일 하나 커밋 → `git checkout main` → `git branch -d test`를 쳐요. `error: the branch 'test' is not fully merged`가 나와요. `main`에 합치지 않은 커밋이 있어서 막은 거예요. 버려도 되면 `git branch -D test`.
- 지금 있는 브랜치는 지울 수 없어요. `git checkout -b temp` 뒤 바로 `git branch -d temp`를 치면 `error: cannot delete branch 'temp' used by worktree at …`가 나와요. 다른 브랜치로 옮긴 뒤 지워요.

## 4단계: 갈라진 줄기를 합치기 — 긴급 수정(hotfix) 상황

3단계에서는 `login`이 갈라진 뒤 `main`에 새 커밋이 없었어요. 그래서 `main`을 `login`의 마지막 커밋으로 **앞으로 옮기기만** 하면 됐어요. 이게 `Fast-forward`예요. 새 커밋이 생기지 않아요.

그런데 두 줄기에 각각 새 커밋이 생겼으면 앞으로 옮기는 걸로는 안 돼요. 이때 Git은 두 줄기를 합친 **병합 커밋**을 새로 만들어요. 출력은 `Merge made by the 'ort' strategy.`예요. 병합 커밋에도 메시지가 필요해서, Mac 터미널에서는 **편집 화면(vim)이 열려요.** 기본 메시지 `Merge branch '…'`가 이미 적혀 있으니 `Esc` → `:wq` → Enter로 저장하고 나오면 돼요.

강의의 상황 1이 이 경우예요.

1. 운영 중인 사이트가 있다 (`main`).
2. 챗봇 기능을 만들려고 `chatbot` 브랜치에서 작업한다.
3. 사이트에 급한 버그가 생겼다. 챗봇 작업을 **커밋하고** `main`으로 돌아가 `hotfix` 브랜치를 만든다.
4. `hotfix`에서 고치고 `main`에 합친다 → `main`에만 있는 커밋이 생긴다.
5. `chatbot`으로 돌아가 마저 만들고 `main`에 합친다 → 두 줄기가 갈라져 있어서 병합 커밋이 생긴다.

### ▶ 직접 해 보기 — 강의 상황 1

새 폴더에서 해요.

```bash
mkdir -p ~/git-practice/hotfix-test
cd ~/git-practice/hotfix-test
git init

# 1. 메인 브랜치에서 시작
echo "회사 웹 사이트 코드" > main.txt
git add main.txt
git commit -m "웹 사이트 첫 버전"

# 2. 챗봇 기능 개발 시작
git checkout -b chatbot
echo "챗봇 기능 1단계" > chatbot.txt
git add chatbot.txt
git commit -m "챗봇 1단계 개발 중"

# 3. 버그 발생 → main으로 가서 hotfix 브랜치
git checkout main
git checkout -b hotfix

# 4. 버그 수정 후 main에 합치기
echo "버그 수정" > bugfix.txt
git add bugfix.txt
git commit -m "긴급 버그 수정"
git checkout main
git merge hotfix
git log --oneline --graph --all
```

```text
Updating ca452bd..963e0c8
Fast-forward
 bugfix.txt | 1 +
 1 file changed, 1 insertion(+)
 create mode 100644 bugfix.txt
* 963e0c8 (HEAD -> main, hotfix) 긴급 버그 수정
| * 50df719 (chatbot) 챗봇 1단계 개발 중
|/
* ca452bd 웹 사이트 첫 버전
```

`hotfix`가 갈라진 뒤 `main`에 새 커밋이 없어서 이번에도 `Fast-forward`예요. 그래프를 보면 첫 커밋에서 두 줄기가 갈라졌어요. `main`과 `hotfix`는 같은 커밋에 있고, `chatbot`은 다른 줄에 있어요.

```bash
git branch -d hotfix

# 5. 챗봇으로 돌아가 마저 개발 후 main에 합치기
git checkout chatbot
echo "챗봇 기능 2단계" >> chatbot.txt
git add chatbot.txt
git commit -m "챗봇 2단계 개발 완료"
git checkout main
git merge chatbot
```

여기서 vim이 열리면 `Esc` → `:wq` → Enter를 눌러요.

```text
Merge made by the 'ort' strategy.
 chatbot.txt | 2 ++
 1 file changed, 2 insertions(+)
 create mode 100644 chatbot.txt
```

```bash
git log --oneline --graph --all
```

```text
*   a36df62 (HEAD -> main) Merge branch 'chatbot'
|\
| * 49c9438 (chatbot) 챗봇 2단계 개발 완료
| * 50df719 챗봇 1단계 개발 중
* | 963e0c8 긴급 버그 수정
|/
* ca452bd 웹 사이트 첫 버전
```

맨 위에 병합 커밋 `Merge branch 'chatbot'`이 새로 생겼어요. 왼쪽 줄(`main`의 버그 수정)과 오른쪽 줄(`chatbot`의 커밋 두 개)이 여기서 만나요. 이제 `main`에 파일 네 개가 다 있어요.

강의 코드의 마지막 줄 `git git log …`는 `git`이 두 번 들어간 오타예요. 그대로 치면 `git: 'git' is not a git command.`가 나와요.

**바꿔 보기**
- `git merge chatbot`을 한 번 더 쳐요. `Already up to date.`가 나와요. 가져올 새 커밋이 없어요.
- `git checkout chatbot` → `ls`를 쳐요. `chatbot`에는 `bugfix.txt`가 없어요. 합치기는 `main` 쪽으로만 했기 때문이에요.

## 5단계: 브랜치를 옮기기 전에 커밋한다

강의가 가장 강조한 주의사항이에요. **커밋하지 않은 파일은 브랜치를 옮길 때 같이 따라와요.** 새로 만든 파일(Untracked)이든 고친 파일(Modified)이든 마찬가지예요. Git은 커밋된 것만 브랜치에 속한다고 보고, 아직 커밋 안 한 것은 "지금 폴더에 있는 작업"으로 남겨 둬요.

그래서 `login`에서 만들던 파일이 `main`으로 옮긴 뒤에도 폴더에 그대로 있어요. 그 상태로 `main`에서 `git add .`을 하면 로그인 작업이 `main`에 섞여요.

옮기면 내 변경이 덮어써지는 경우에는 Git이 아예 이동을 막아요. 이동할 브랜치의 같은 파일 내용이 다를 때예요.

```text
error: Your local changes to the following files would be overwritten by checkout:
	login.txt
Please commit your changes or stash them before you switch branches.
Aborting
```

강의의 안전한 순서는 이래요.

1. `git status`로 커밋 안 한 변경이 있는지 본다.
2. 작업이 덜 됐어도 **오류가 안 나는 상태로 정리**한다 (주석 처리 등).
3. **커밋한다.**
4. 브랜치를 옮긴다.

### ▶ 직접 해 보기

`hotfix-test`에서 이어서 해요.

```bash
git checkout -b login
echo "로그인 작업 중" > login.txt
git checkout main
ls
git status -s
```

```text
Switched to a new branch 'login'
Switched to branch 'main'
bugfix.txt	chatbot.txt	login.txt	main.txt
?? login.txt
```

`main`으로 왔는데 `login.txt`가 그대로 있어요. 커밋을 안 해서 따라왔어요. 이번에는 커밋하고 옮겨요.

```bash
git checkout login
git add login.txt
git commit -m "로그인 작업 중"
git checkout main
ls
```

```text
bugfix.txt	chatbot.txt	main.txt
```

커밋한 뒤에는 `login.txt`가 `login` 브랜치에만 있어요.

**바꿔 보기**
- 이동이 막히는 경우를 봐요: `git checkout login` → `echo "로그인 화면 수정" >> login.txt`(커밋 안 함) → `git checkout main`. 위의 `error: Your local changes … would be overwritten by checkout` 메시지가 나와요. `main`에는 `login.txt`가 없어서, 옮기면 내 수정이 사라지기 때문이에요. `git add`·`git commit` 후에 옮기면 돼요.

---

## 마무리: `git merge 브랜치`를 쳤을 때 일어나는 일

1. 지금 있는 브랜치(`HEAD`)와 가져올 브랜치를 찾는다.
2. 가져올 브랜치에 새 커밋이 없으면 `Already up to date.`로 끝낸다.
3. 지금 브랜치에 갈라진 뒤 새 커밋이 없으면, 지금 브랜치를 가져올 브랜치의 마지막 커밋으로 앞으로 옮긴다 (`Fast-forward`, 새 커밋 없음).
4. 양쪽에 새 커밋이 있으면, 두 줄기의 변경을 합친 병합 커밋을 만든다. 메시지를 쓰라고 편집 화면이 열린다 (`Merge made by the 'ort' strategy.`).
5. 두 줄기가 **같은 파일의 같은 부분을 다르게** 고쳤으면 자동으로 합치지 못하고 멈춘다 → 충돌 (05회차).
6. 가져온 브랜치는 그대로 남는다. 다 썼으면 `git branch -d`로 지운다.

## 오류가 날 때 찾아보기

| 오류 문장 · 증상 | 먼저 볼 곳 |
|---|---|
| `fatal: not a valid object name: 'main'` | 커밋이 하나도 없음 → 먼저 커밋 (1단계) |
| `fatal: a branch named 'login' already exists` | 같은 이름 브랜치가 있음 → `git branch`로 확인 (2단계) |
| `error: pathspec 'logn' did not match any file(s) known to git` | `checkout`할 브랜치 이름 오타 (2단계) |
| `merge: logn - not something we can merge` | `merge`할 브랜치 이름 오타 (3단계) |
| `zsh: command not found: bit` | 강의 코드 오타 → `git branch` (3단계) |
| `git: 'git' is not a git command.` | 강의 코드 오타 `git git log` → `git log` (4단계) |
| `error: the branch 'x' is not fully merged` | 합치지 않은 커밋이 있음 → 합치거나, 버릴 거면 `-D` (3단계) |
| `error: cannot delete branch 'x' used by worktree at …` | 지금 있는 브랜치를 지우려 함 → 다른 브랜치로 이동 후 (3단계) |
| `Already up to date.` | 가져올 새 커밋이 없음. 방향이 맞는지(`git branch`의 `*`) 확인 (3·4단계) |
| `merge` 뒤 낯선 편집 화면(vim) | 병합 커밋 메시지 → `Esc` → `:wq` → Enter (4단계) |
| `git log`에 다른 브랜치 커밋이 안 보임 | `--all`을 빠뜨림 (2단계) |
| `error: Your local changes … would be overwritten by checkout` | 커밋 안 한 변경이 있음 → 커밋 후 이동 (5단계) |
| 다른 브랜치로 옮겼는데 작업 파일이 그대로 있음 | 커밋 안 한 파일은 따라옴 → 원래 브랜치로 가서 커밋 (5단계) |
