# 개념 정리 — Git협업과정 02. git의 3가지 영역

> 날짜: 2026-11-20 · wiki: [02_3가지영역-기본명령](../../../../wiki/07_Git협업과정/02_3가지영역-기본명령.md)
> 단계별 설명문으로 쓰고, 단계 끝마다 터미널에 직접 쳐 보는 명령을 둔다. 쉬운 말, 비유 없이. 명령과 출력은 이 Mac의 Git 2.50.1(zsh 터미널)로 미리 실행해 확인했다. 01회차가 대부분 아는 내용이라 해서 설명을 짧게 했다.

## 들어가며

01회차에서 Git 설치와 이름·이메일 등록을 확인했어요. 오늘은 처음으로 저장소를 직접 만들고 버전을 기록해요.

Git에서 버전 하나가 만들어지려면 파일이 세 군데를 거쳐요. 내가 고치는 폴더(Working Directory) → 다음 버전에 넣을 것을 골라 두는 곳(Staging Area) → 버전이 저장되는 곳(Local Repository)이에요. `git add`가 첫 번째 칸을, `git commit`이 두 번째 칸을 넘겨요. `KDT학습`을 올릴 때 Claude가 `git add` → `git commit` 순서로 친 게 이 흐름이에요.

오늘 배우는 명령은 다섯 개예요: `init`, `status`, `add`, `commit`, `diff`. 이 다섯 개만으로 내 컴퓨터 안에서 기록을 남길 수 있어요. GitHub에 올리는 건 03회차예요.

---

## 🛠 시작하기 — 연습용 폴더

연습용 저장소는 **`KDT학습` 밖**에 만들어요. `KDT학습`이 이미 저장소라서, 그 안에서 `git init`을 하면 저장소 안에 저장소가 생겨요. 홈 폴더 아래 `git-practice` 폴더를 만들고, 오늘은 그 안의 `basics` 폴더를 써요.

```bash
mkdir -p ~/git-practice/basics
cd ~/git-practice/basics
pwd
```

`pwd`가 `/Users/(내 Mac 사용자 이름)/git-practice/basics`를 보여 주면 준비 끝이에요. `git-practice` 폴더 자체는 저장소로 만들지 않아요. 회차마다 그 안에 폴더를 하나씩 만들어 각각 저장소로 써요.

## 1단계: `git init`으로 폴더를 저장소로 만든다

`git init`은 지금 폴더를 Git 저장소로 만들어요. 폴더 안에 `.git`이라는 숨김 폴더가 생기고, 앞으로의 모든 기록이 여기에 저장돼요. 이 `.git`이 **Local Repository**예요. 지우면 기록이 전부 사라져요.

`.git`이 생긴 폴더(내 파일이 있는 곳)가 **Working Directory**예요. 따로 만드는 게 아니라, 원래 작업하던 폴더가 그대로 Working Directory가 돼요.

`git init`은 저장소마다 처음 한 번만 해요. 이미 저장소인 폴더에서 또 치면 `Reinitialized existing Git repository`가 나오는데, 기록은 지워지지 않아요. 문제는 **엉뚱한 폴더에서 치는 것**이에요. 홈 폴더에서 치면 홈 폴더 전체가 저장소가 되어 버려요. 그래서 치기 전에 `pwd`로 위치를 확인해요.

### ▶ 직접 해 보기

```bash
git status
```

```text
fatal: not a git repository (or any of the parent directories): .git
```

아직 저장소가 아니라서 Git이 거절해요. 이제 저장소로 만들어요.

```bash
git init
ls -a
```

```text
Initialized empty Git repository in /Users/(내 Mac 사용자 이름)/git-practice/basics/.git/
.	..	.git
```

`ls -a`는 숨김 파일까지 보여 주는 명령이에요. `.git`이 보이면 저장소가 된 거예요. Finder에서는 숨김 폴더라 안 보여요 (`Cmd + Shift + .`를 누르면 보여요).

## 2단계: 세 영역과 파일의 상태

세 영역을 다시 정리하면 이래요.

| 영역 | 무엇 | 다음으로 넘기는 명령 |
|---|---|---|
| Working Directory | 내가 파일을 만들고 고치는 폴더 | `git add` |
| Staging Area | 다음 버전에 넣을 변경을 골라 둔 곳 | `git commit` |
| Local Repository (`.git`) | 확정된 버전들이 저장된 곳 | (03회차) `git push` |

**Staging Area가 왜 따로 있을까요?** 파일을 세 개 고쳤는데 그중 두 개만 "로그인 기능"에 해당하고, 나머지 하나는 아직 덜 됐을 수 있어요. 그때 두 개만 `add`해서 "로그인 기능 추가"라는 버전으로 묶고, 나머지는 다음 버전에 넣을 수 있어요. 버전 하나에 관련된 변경만 담으려고 고르는 단계가 따로 있는 거예요. Staging Area는 눈에 보이는 폴더가 아니라 `.git` 안에 기록된 목록이에요.

파일은 이 흐름에서 상태가 바뀌어요.

- **Untracked**: 새로 만들어서 Git이 아직 모르는 파일
- **Staged**: `git add`로 다음 버전에 넣기로 고른 상태
- **Unmodified**: 커밋 직후, 마지막 버전과 똑같은 상태
- **Modified**: 커밋한 뒤 고쳐서, 마지막 버전과 달라진 상태

Untracked를 빼면 모두 Git이 관리하는 **Tracked** 상태예요. 한 번 커밋된 파일은 고치기만 해도 Git이 바로 알아채요 (Modified).

`git status`는 이 상태를 세 묶음으로 보여 줘요. 이 표가 오늘 가장 많이 볼 표예요.

| `git status` 묶음 | 상태 | 할 일 |
|---|---|---|
| `Untracked files:` | Untracked | 기록하려면 `git add` |
| `Changes not staged for commit:` | Modified | 이 변경도 넣으려면 `git add` |
| `Changes to be committed:` | Staged | `git commit`하면 버전이 됨 |
| `nothing to commit, working tree clean` | 모두 Unmodified | 할 일 없음 |

## 3단계: 첫 버전 만들기 — `add`와 `commit`

`git add 파일`은 그 파일의 지금 내용을 Staging Area에 올려요. `git commit -m "메시지"`는 Staging Area에 올라간 것 전부를 버전 하나로 확정해요. `-m` 뒤의 메시지는 "무엇을 왜 바꿨는지" 나중에 알아볼 수 있게 써요.

`add`만 하고 `commit`을 안 하면 버전은 없어요. 반대로 `add`를 안 하고 `commit`하면 Git이 넣을 게 없다고 거절해요.

### ▶ 직접 해 보기 — 강의 기초 예제

`~/git-practice/basics`에서 한 줄씩 치면서 `git status`가 어떻게 바뀌는지 봐요.

```bash
echo "Hello" > file.txt
git status
```

```text
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
	file.txt

nothing added to commit but untracked files present (use "git add" to track)
```

`echo "글자" > 파일`은 그 글자로 파일을 새로 만드는 명령이에요. 새 파일이라 Untracked예요. 괄호 안의 `(use "git add …")`는 Git이 다음에 할 일을 알려 주는 안내예요.

```bash
git add file.txt
git status
```

```text
On branch main

No commits yet

Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
	new file:   file.txt
```

Staged가 됐어요. `new file:`은 처음 기록되는 파일이라는 뜻이에요.

```bash
git commit -m "Add file.txt"
git status
```

```text
[main (root-commit) 433202d] Add file.txt
 1 file changed, 1 insertion(+)
 create mode 100644 file.txt
On branch main
nothing to commit, working tree clean
```

첫 줄의 `main`은 브랜치 이름, `root-commit`은 이 저장소의 첫 버전이라는 뜻, `433202d`는 이 버전의 번호예요(매번 달라요). `1 file changed, 1 insertion(+)`은 파일 1개에 한 줄이 추가됐다는 요약이에요. 이제 `working tree clean`, 모두 Unmodified예요.

```bash
echo "World" >> file.txt
git status
```

```text
On branch main
Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   file.txt

no changes added to commit (use "git add" and/or "git commit -a")
```

`>>`는 파일 끝에 한 줄을 덧붙여요. 커밋한 파일을 고쳤으니 Modified예요. 이 상태로 `git commit -m "…"`을 치면 같은 안내가 나오고 버전은 안 만들어져요. 강의 예제는 여기까지예요. 고친 내용을 두 번째 버전으로 만들어요.

```bash
git add file.txt
git status
git commit -m "Add World"
```

```text
On branch main
Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
	modified:   file.txt

[main ff168a0] Add World
 1 file changed, 1 insertion(+)
```

이번에는 `new file:`이 아니라 `modified:`가 `Changes to be committed:`에 나와요. 첫 버전이 아니라서 `root-commit`도 없어요.

**바꿔 보기**
- `git log --oneline`을 쳐서 버전 두 개(`Add World`, `Add file.txt`)가 쌓인 걸 봐요.

## 4단계: 무엇이 바뀌었는지 보기 — `git diff`

`git status`는 어느 파일이 바뀌었는지만 알려 줘요. 파일 안에서 어떤 줄이 바뀌었는지는 `git diff`로 봐요.

- `git diff`: Working Directory에서 고쳤지만 **아직 `add`하지 않은** 변경
- `git diff --staged`: **`add`해서 다음 버전에 들어갈** 변경

출력에서 `+`로 시작하는 줄은 추가된 줄, `-`로 시작하는 줄은 지워진 줄이에요. 앞에 기호가 없는 줄은 바뀌지 않은 주변 줄이에요.

커밋하기 전에 `git diff --staged`로 "이번 버전에 정확히 뭐가 들어가는지"를 확인하는 습관이 좋아요.

### ▶ 직접 해 보기

3단계에 이어서 `basics`에서 한 줄을 더 덧붙여요.

```bash
echo "Git" >> file.txt
git diff
```

```text
diff --git a/file.txt b/file.txt
index f9264f7..fc07847 100644
--- a/file.txt
+++ b/file.txt
@@ -1,2 +1,3 @@
 Hello
 World
+Git
```

위의 다섯 줄은 어느 파일을 비교하는지 알려 주는 머리 부분이에요. 아래가 내용이에요. `Hello`·`World`는 그대로, `Git`이 추가됐어요.

```bash
git add file.txt
git diff
git diff --staged
```

`add` 뒤의 `git diff`는 아무것도 안 나와요. 변경이 Staging Area로 넘어갔기 때문이에요. `git diff --staged`를 치면 위와 같은 `+Git`이 나와요.

**바꿔 보기**
- `file.txt`를 VS Code로 열어 `Hello`를 `Hi`로 고치고 저장한 뒤 `git diff`를 쳐요. `-Hello`와 `+Hi` 두 줄이 나와요. 한 줄을 고치면 Git은 "지우고 새로 추가"로 보여 줘요.
- 확인이 끝나면 `git add file.txt` → `git commit -m "Add Git"`으로 정리해 둬요. 6단계를 `working tree clean` 상태에서 시작하려고요.

## 5단계: `add` 뒤에 또 고치면 두 묶음에 동시에 나온다

`git add`는 파일 이름을 등록하는 게 아니라 **그 순간의 내용**을 Staging Area에 올려요. 그래서 `add`한 다음 파일을 또 고치면, 올라간 내용과 지금 내용이 달라져요. 이때 같은 파일이 `Changes to be committed`와 `Changes not staged for commit` 두 곳에 동시에 나와요.

이 상태에서 커밋하면 **`add`할 때의 내용만** 버전에 들어가요. 그 뒤에 고친 부분은 Modified로 남아요. 다 넣고 싶으면 커밋 전에 다시 `add`해요. 강의가 "스테이징한 파일을 수정하면 수정 상태가 된다, 다시 add해야 한다"고 한 게 이 내용이에요.

### ▶ 직접 해 보기 — 강의 결과 예제

새 폴더에서 해요.

```bash
mkdir -p ~/git-practice/basics2
cd ~/git-practice/basics2
git init
echo "안녕하세요" > hello.txt
git add hello.txt
echo "반갑습니다" >> hello.txt
git status
```

```text
On branch main

No commits yet

Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
	new file:   hello.txt

Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   hello.txt
```

`hello.txt`가 두 묶음에 다 있어요. 첫 줄 "안녕하세요"는 올라가 있고, 덧붙인 "반갑습니다"는 아직 안 올라갔기 때문이에요. 두 `diff`로 확인해요.

```bash
git diff
git diff --staged
```

```text
(git diff — 아직 안 올린 변경)
+반갑습니다

(git diff --staged — 올라간 변경)
+안녕하세요
```

(실제 출력에는 각각 위에 `diff --git a/hello.txt b/hello.txt` 같은 머리 줄이 함께 나와요.)

다시 `add`하고 커밋해요.

```bash
git add hello.txt
git commit -m "hello.txt 파일 생성 및 수정"
git status
```

```text
[main (root-commit) faa763f] hello.txt 파일 생성 및 수정
 1 file changed, 2 insertions(+)
 create mode 100644 hello.txt
On branch main
nothing to commit, working tree clean
```

`2 insertions(+)`, 두 줄이 다 들어갔어요.

**바꿔 보기**
- `~/git-practice/basics3` 폴더를 새로 만들어 같은 순서로 하되, 두 번째 `git add`를 빼고 바로 커밋해 봐요. `1 insertion(+)`으로 한 줄만 들어가고, 커밋 뒤 `git status`에 `modified:   hello.txt`가 남아요.

## 6단계: 여러 파일을 한 번에 `add`하기

강의는 네 가지 방법을 보여 줘요.

| 명령 | 올리는 것 |
|---|---|
| `git add 파일명` | 그 파일 하나 |
| `git add .` | 지금 폴더 아래의 바뀐 파일 전부 |
| `git add 폴더명` | 그 폴더 안의 파일 전부 |
| `git add *.txt` | 이름이 `.txt`로 끝나는 파일 |

`git add .`이 가장 편하지만, 올리면 안 되는 파일까지 같이 올라가요. Mac은 Finder로 폴더를 열면 `.DS_Store`라는 숨김 파일을 만드는데, 이것도 `git add .`에 들어가요. 그래서 `git add .` 전에 `git status`로 목록을 한 번 보는 습관이 필요해요. 올리지 않을 파일을 아예 빼는 `.gitignore`는 03회차에서 나와요.

`*.txt`는 Mac 터미널(zsh)에서 조금 다르게 동작해요. Git에 넘기기 전에 터미널이 먼저 `*.txt`를 **지금 폴더**의 파일 이름들로 바꿔요. 그래서 하위 폴더의 `.txt`는 안 들어가고, 맞는 파일이 하나도 없으면 Git까지 가지도 못하고 `zsh: no matches found: *.txt`가 나와요.

### ▶ 직접 해 보기

`~/git-practice/basics`에서 파일 몇 개를 만들고 하나씩 올려 봐요. `git status --short`(줄여서 `-s`)는 한 파일을 한 줄로 보여 줘요. `??`는 Untracked, `A`는 새로 올라간 파일이에요.

```bash
cd ~/git-practice/basics
echo "메모" > memo.txt
echo "할 일" > todo.txt
echo "<h1>hi</h1>" > index.html
mkdir docs
echo "안내" > docs/guide.txt
echo "규칙" > docs/rule.md
git status -s
```

```text
?? docs/
?? index.html
?? memo.txt
?? todo.txt
```

```bash
git add *.txt
git status -s
```

```text
A  memo.txt
A  todo.txt
?? docs/
?? index.html
```

`docs/guide.txt`도 `.txt`지만 하위 폴더라 안 들어갔어요.

```bash
git add docs
git status -s
```

```text
A  docs/guide.txt
A  docs/rule.md
A  memo.txt
A  todo.txt
?? index.html
```

```bash
git add .
git status -s
git commit -m "메모·할 일·안내 파일 추가"
```

남은 `index.html`까지 다 올라가고, 다섯 파일이 버전 하나로 기록돼요.

**바꿔 보기**
- `git add *.css`를 쳐요. `.css` 파일이 없어서 `zsh: no matches found: *.css`가 나와요.
- `git add hell.txt`처럼 없는 파일 이름을 쳐요. `fatal: pathspec 'hell.txt' did not match any files`가 나와요. 이름 오타예요.
- Finder에서 이 폴더를 열었다 닫은 뒤 `git status -s`를 쳐요. `?? .DS_Store`가 보이면 Finder가 만든 파일이에요. 아직 `add .`하지 말고 두세요 (03회차 `.gitignore`).

## 마무리: 버전 하나가 만들어지는 순서

1. Working Directory에서 파일을 만들거나 고친다. Git은 상태만 바꿔 둔다 (Untracked / Modified).
2. `git status`로 무엇이 바뀌었는지 확인한다.
3. `git add`로 다음 버전에 넣을 변경을 고른다. 그 순간의 내용이 Staging Area에 올라간다 (Staged).
4. `git diff --staged`로 들어갈 내용을 확인한다.
5. `git commit -m "메시지"`로 Staging Area의 내용 전부를 버전 하나로 확정한다. 01회차에서 등록한 이름·이메일, 시간, 메시지, 바로 앞 버전 번호가 같이 저장된다.
6. 커밋된 파일은 Unmodified가 되고, `git status`는 `working tree clean`을 보여 준다.

---

## 다음 회차와 연결

지금까지 만든 버전은 내 컴퓨터의 `.git` 안에만 있어요. 03회차에서는 GitHub에 빈 저장소를 만들고 `git remote add`로 연결한 뒤 `git push`로 올려요. 반대로 GitHub의 저장소를 내 컴퓨터로 복제하는 `git clone`도 배워요.

03회차에는 **GitHub에 연습용 저장소**가 필요해요. 공개(Public)·비공개(Private)는 직접 정하면 돼요. 연습용이라 비공개로 만들어도 실습에는 지장이 없어요.

## 오류가 날 때 찾아보기

| 오류 문장 · 증상 | 먼저 볼 곳 |
|---|---|
| `fatal: not a git repository (or any of the parent directories): .git` | 아직 `git init` 전이거나 다른 폴더에 있음 → `pwd` (1단계) |
| `Reinitialized existing Git repository` | 이미 저장소인 폴더에서 또 `init` — 기록은 그대로 (1단계) |
| `git status`에 상관없는 파일이 잔뜩 나옴 | 엉뚱한 폴더(예: 홈)에서 `init`함 → `pwd`로 저장소 위치 확인 (1단계) |
| `nothing added to commit but untracked files present` | `add` 없이 `commit` (3단계) |
| `no changes added to commit (use "git add" …)` | 고친 파일을 `add`하지 않고 `commit` (3단계) |
| `nothing to commit, working tree clean` | 바뀐 게 없음. 정상 (2단계) |
| 커밋했는데 고친 내용 일부가 빠짐, 커밋 뒤에도 `modified:`가 남음 | `add` 뒤에 또 고침 → 다시 `add` (5단계) |
| `git diff`에 아무것도 안 나옴 | 변경이 이미 `add`됨 → `git diff --staged` (4단계) |
| `error: switch 'm' requires a value` | `-m` 뒤에 메시지가 없음 (3단계) |
| `error: pathspec '커밋' did not match any file(s) known to git` | 띄어쓰기가 있는 메시지를 따옴표 없이 씀 → `-m "첫 커밋"` (3단계) |
| `git commit` 뒤 낯선 편집 화면(vim)이 열림 | `-m`을 빠뜨림 → `i`로 메시지 입력, `Esc` → `:wq` → Enter. 취소는 `Esc` → `:q!` (3단계) |
| `fatal: pathspec 'xxx' did not match any files` | 파일 이름 오타 (6단계) |
| `zsh: no matches found: *.txt` | 지금 폴더에 그런 파일이 없음 (6단계) |
| `git status`에 `?? .DS_Store` | Finder가 만든 Mac 파일 → 올리지 않음 (6단계, 03회차 `.gitignore`) |
| 한글 파일 이름이 `"\355\225\234\352\270\200.txt"`처럼 나옴 | Git이 한글을 숫자로 바꿔 보여 주는 기본 설정 → `git config --global core.quotepath false` 하면 한글로 보임 |
