# 개념 정리 — Git협업과정 01. git 설치와 환경설정

> 날짜: 2026-11-20 · wiki: [01_설치-환경설정](../../../../wiki/07_Git협업과정/01_설치-환경설정.md) · 과정 개요: [_과정개요](../../../../wiki/07_Git협업과정/_과정개요.md)
> 단계별 설명문으로 쓰고, 단계 끝마다 터미널에 직접 쳐 보는 명령을 둔다. 쉬운 말, 비유 없이. 명령과 출력은 이 Mac의 Git 2.50.1로 미리 실행해 확인했다.

## 들어가며

지금까지 만든 코드는 모두 파일로 저장했어요. 파일 저장은 마지막 상태만 남겨요. 고치기 전 코드가 어땠는지, 언제 무엇을 바꿨는지는 남지 않아요.

Git은 이 문제를 풀어요. 내가 "여기까지 기록"이라고 할 때마다 그 시점의 파일 상태를 하나씩 남겨 두고, 나중에 그 기록을 보거나 그 시점으로 돌아갈 수 있게 해요.

사실 이미 Git을 쓰고 있었어요. `KDT학습` 폴더가 Git 저장소이고, 연습을 마칠 때마다 "커밋하고 push"한 게 Git으로 기록을 남기고 GitHub에 올린 거예요. 이번 과정에서는 그 명령을 직접 쳐 보면서 무슨 일이 일어나는지 배워요.

팀 프로젝트(기본 프로젝트)에서는 여러 명이 한 저장소에 코드를 올려요. 그때 쓰는 방법이 이 과정의 마지막 06회차예요. 01~05회차는 거기까지 가기 위한 준비예요.

| 회차 | 하는 일 |
|---|---|
| **01 (오늘)** | Git이 설치되어 있는지 확인하고, 내 이름·이메일을 등록한다 |
| 02 | 내 컴퓨터 안에서 기록을 만든다 (`add`, `commit`) |
| 03 | 기록을 GitHub에 올리고 받는다 (`push`, `pull`, `clone`) |
| 04 | 기록 줄기를 나누고 합친다 (브랜치) |
| 05 | 두 사람이 같은 곳을 고쳤을 때 해결한다 (충돌) |
| 06 | 팀 저장소에 PR로 합친다 |

오늘은 새 저장소를 만들지 않아요. 설치가 되어 있는지, 내 이름·이메일과 기본 설정이 들어 있는지 확인하는 게 전부예요.

## 🛠 시작하기 — 터미널 열기

강의는 Windows의 **Git Bash**에서 명령을 쳐요. Mac에는 Git Bash가 없고, **터미널**에서 같은 명령을 그대로 쳐요.

- `Cmd + Space`로 Spotlight를 열고 "터미널"을 입력해서 열어요. VS Code나 IntelliJ 아래쪽의 터미널 창을 써도 돼요.
- 명령은 한 줄씩 붙여 넣고 Enter를 눌러요. `#`으로 시작하는 줄은 설명이라 치지 않아도 돼요.
- 출력이 화면보다 길면 맨 아래에 `:`가 보이고 멈춰요. `q`를 누르면 빠져나와요.

## 1단계: 버전과 버전 관리

**버전**은 특정 시점의 파일 상태예요. 보고서를 `초안.doc`, `수정본.doc`, `최종본.doc`로 따로 저장하면 이 세 파일이 각각 하나의 버전이에요. 코드에서는 "로그인 기능을 넣은 직후의 코드", "버그를 고친 직후의 코드"가 각각 버전이에요.

파일 이름을 바꿔 가며 저장하는 방식은 금방 문제가 생겨요. 파일이 계속 늘어나고, 어느 파일이 최신인지 헷갈리고, 두 버전 사이에 무엇이 바뀌었는지는 직접 비교해야 해요. "왜 바꿨는지"는 어디에도 남지 않아요.

**버전 관리**는 이 일을 프로그램에 맡기는 거예요. 파일은 하나만 두고, 버전을 만들 때마다 프로그램이 "언제, 무엇이, 왜 바뀌었는지"를 기록해요. 이런 프로그램을 **버전 관리 시스템(VCS)**이라고 하고, Git이 그중 하나예요.

강의가 말하는 필요한 이유는 두 가지예요. 하나는 **변경 이력 관리**예요. 언제·무엇을·왜 바꿨는지 남아 있어서, 문제가 생기면 이전 버전으로 되돌릴 수 있어요. 다른 하나는 **백업**이에요. 기록을 GitHub에도 올려 두면 내 컴퓨터의 파일을 잃어도 다시 받을 수 있어요.

참고로 프로그램에 붙는 `1.0.0` 같은 번호는 Semantic Versioning이라는 규칙이에요. 앞자리부터 큰 변화(Major) · 기능 추가(Minor) · 버그 수정(Patch)이 있을 때 올려요. 이 번호는 사람이 정해서 붙이는 이름이고, Git이 버전마다 붙이는 번호(아래 `f1ef1e7` 같은 것)와는 달라요.

### ▶ 직접 해 보기 — `KDT학습`에 쌓인 버전 보기

`KDT학습` 폴더에는 이미 버전이 쌓여 있어요. `git log`는 04회차에서 배우니까 지금은 결과만 보세요.

```bash
cd ~/personal/KDT학습
git log --oneline -5
```

```text
f1ef1e7 정리: Node 01~04 개념 정리와 Node 과정 종합 복습
f06d731 강의: Spring 000·05·06 회차와 오리엔테이션 정리, Spring 04 변경 반영
0185b75 SEO·비동기·데이터베이스 과정 wiki 추가, 07 2부·08 개념 정리
bf4a479 연습: 06 map() 다시 풀기 채점과 실력점검 갱신
331b07b 연습: React 07회차 1부 채점 마무리와 실력점검 갱신
```

(2026-11-20 오전 기준이에요. 새로 기록하면 맨 위에 줄이 늘어나요.)

한 줄이 버전 하나예요. 앞의 일곱 글자는 Git이 버전마다 붙인 번호이고, 뒤는 그때 적은 메시지예요. 메시지에 무엇을 했는지 적혀 있어서, 파일을 열지 않아도 그 버전에서 무슨 일이 있었는지 알 수 있어요.

**바꿔 보기**
- `-5`를 `-20`으로 바꿔 더 예전 기록을 봐요.
- `git log -1`을 쳐서 가장 최근 버전 하나를 자세히 봐요. `Author`(누가), `Date`(언제) 줄이 보여요. `Author`에 무엇이 들어가는지는 4단계에서 다뤄요.

## 2단계: Git과 GitHub는 다른 것이다

이름이 비슷해서 헷갈리지만 둘이 하는 일은 달라요.

**Git**은 내 컴퓨터에 설치된 프로그램이에요. 1단계에서 본 기록은 모두 내 컴퓨터의 `KDT학습/.git` 폴더 안에 있어요. 인터넷이 끊겨도 기록을 만들고 볼 수 있어요.

**GitHub**는 웹사이트예요. Git이 만든 기록을 인터넷에 올려 두고 다른 사람과 나누는 곳이에요. `KDT학습`의 기록은 `https://github.com/Jevan2310/KDT-learning`에 올라가 있어요.

그래서 순서가 정해져 있어요. 먼저 내 컴퓨터에서 Git으로 기록을 만들고(02회차), 그 기록을 GitHub에 올려요(03회차). 내 컴퓨터에서 새로 만든 기록은 올리기 전까지 GitHub에 없어요. 반대로 GitHub에 다른 사람이 올린 기록도 내가 받기 전까지는 내 컴퓨터에 없어요.

### ▶ 직접 해 보기 — 내 컴퓨터와 GitHub의 차이 보기

```bash
cd ~/personal/KDT학습
git status
```

첫 두 줄만 보세요. 아직 안 올린 기록이 있으면 이렇게 나와요.

```text
On branch main
Your branch is ahead of 'origin/main' by 2 commits.
```

`origin/main`은 내 컴퓨터가 마지막으로 확인한 GitHub의 기록이에요. "ahead by 2 commits"는 내 컴퓨터에 GitHub보다 버전이 2개 더 있다는 뜻이에요. 다 올린 뒤에는 `Your branch is up to date with 'origin/main'.`으로 바뀌어요. 그 아래에 파일 목록이 나올 수 있는데, 읽는 법은 02회차에서 배워요.

**바꿔 보기**
- 브라우저에서 GitHub 저장소를 열고, 파일 목록 위의 커밋 수(시계 모양 아이콘)를 눌러요. 1단계의 `git log`와 같은 메시지가 보여요. 내 컴퓨터에만 있는 버전은 그 목록에 없어요.

## 3단계: Git이 설치되어 있는지 확인한다

강의는 Windows에 Git을 설치하는 과정을 보여 줘요. 설치할 때 꼭 챙길 것은 두 가지예요. Git Bash를 같이 설치하는 것, 그리고 기본 브랜치 이름을 `main`으로 정하는 것(5단계)이에요. 화면별로 무엇을 고르는지는 [00_개발환경/git](../../../../wiki/00_개발환경/git.md)에 표로 있어요.

Mac은 따로 설치하지 않아도 돼요. Apple이 개발자 도구(Command Line Tools)에 Git을 넣어 두었고, 이 Mac에는 이미 깔려 있어요. 없는 Mac에서 `git`을 치면 개발자 도구를 설치하겠냐는 창이 떠요. 설치를 누르면 Git이 같이 깔려요.

설치 확인은 `git --version` 한 줄이에요. 버전이 나오면 설치된 거예요.

### ▶ 직접 해 보기

```bash
git --version
```

```text
git version 2.50.1 (Apple Git-155)
```

`Apple Git`은 Apple이 개발자 도구에 넣어 둔 Git이라는 표시예요. 강의 화면의 버전 숫자와 달라도 이 과정의 명령은 똑같이 동작해요.

**바꿔 보기**
- `git --help`를 쳐 봐요. 자주 쓰는 명령 목록에 이 과정에서 배울 `clone`, `init`, `add`, `diff`, `log`, `status`, `branch`, `commit`, `merge`, `pull`, `push`가 보여요.

## 4단계: 내 이름과 이메일을 등록한다

Git은 버전을 만들 때마다 누가 만들었는지를 같이 적어요. 1단계에서 `git log -1`로 본 `Author` 줄이에요. 여기에 들어가는 이름과 이메일은 Git이 알아서 정하지 않고, 내가 처음에 한 번 등록해 둔 값을 가져다 써요.

```bash
git config --global user.name "YourName"
git config --global user.email "your.email@example.com"
```

`git config`는 Git 설정을 바꾸거나 읽는 명령이고, `user.name`·`user.email`은 설정 이름이에요. `--global`은 이 컴퓨터의 내 계정 전체에 적용한다는 뜻이라서, 한 번만 하면 앞으로 만드는 모든 저장소에 쓰여요 (6단계).

강의는 **GitHub 계정의 이름과 이메일**로 등록하라고 해요. GitHub는 버전에 적힌 이메일을 보고 그 버전이 누구 것인지 판단해요. 이메일이 GitHub 계정과 같아야 GitHub에서 그 버전 옆에 내 프로필이 뜨고, 프로필의 활동 기록에도 잡혀요.

등록하지 않고 버전을 만들면 어떻게 될까요? 이 Mac에서 해 보니 버전은 만들어지는데, Mac 사용자 이름과 컴퓨터 이름으로 이름·이메일을 지어서 넣었어요. 그리고 "자동으로 정했으니 확인하라"는 경고(`Your name and email address were configured automatically …`)가 나왔어요. 이렇게 만든 버전은 GitHub 계정과 이어지지 않아요.

주의할 점이 하나 있어요. 공개 저장소에 올리면 버전에 적힌 이메일도 누구나 볼 수 있어요. 그래서 GitHub는 `숫자+아이디@users.noreply.github.com` 형태의 대신 쓰는 주소를 줘요 (GitHub **Settings → Emails**). 이 주소로 등록하면 GitHub 계정과는 이어지면서 진짜 이메일은 드러나지 않아요.

### ▶ 직접 해 보기 — 지금 등록된 값 확인하기

이 Mac에는 이미 등록되어 있어요. 확인만 해요.

```bash
git config user.name
git config user.email
```

첫 줄에 등록한 이름, 둘째 줄에 이메일이 나와요. 이메일이 `…@users.noreply.github.com`으로 끝나면 위에서 말한 대신 쓰는 주소예요. 이 Mac은 그 주소로 되어 있어서, `KDT-learning`에 올린 버전에도 진짜 이메일은 들어가 있지 않아요.

확인할 때는 값을 붙이지 않아요. `git config user.name "새이름"`처럼 값을 붙이면 확인이 아니라 설정이 바뀌어요.

**바꿔 보기**
- `KDT학습` 폴더에서 `git log -1`을 쳐서 `Author` 줄이 위의 이름·이메일과 같은지 봐요.
- `git config user.nam`처럼 설정 이름을 틀리게 쳐 봐요. 아무것도 안 나와요. 없는 설정을 물으면 빈 줄이 나와서, 등록을 안 한 것과 구별이 안 돼요. 빈 줄이 나오면 철자부터 봐요.

## 5단계: 기본 브랜치 이름을 main으로 정한다

**브랜치**는 버전 기록 줄기에 붙은 이름이에요. 저장소를 처음 만들면 기록 줄기가 하나 생기고, 거기에 이름이 붙어요. 줄기를 여러 개로 나누는 건 04회차에서 배우고, 오늘은 첫 줄기의 이름만 정해요. `git status` 첫 줄의 `On branch main`이 바로 이 이름이에요.

예전 Git은 첫 줄기 이름을 `master`로 붙였어요. 지금은 `main`을 쓰는 게 일반적이고, GitHub도 새 저장소를 `main`으로 만들어요. 내 컴퓨터는 `master`, GitHub는 `main`이면 올릴 때 이름이 안 맞아서 헷갈려요. 그래서 강의는 처음에 `main`으로 맞춰 두라고 해요.

```bash
git config --global init.defaultBranch main
```

`init.defaultBranch`는 "`git init`(02회차)으로 저장소를 만들 때 첫 줄기의 이름"이라는 설정이에요. 이미 있는 저장소는 바뀌지 않고, 앞으로 만드는 저장소에만 적용돼요. 이 값이 아무 데도 없으면 `git init`을 할 때 `hint: Using 'master' as the name for the initial branch.`라는 안내가 나오고 `master`로 만들어져요.

### ▶ 직접 해 보기

먼저 지금 값이 어디서 오는지 봐요. `--show-origin`은 값과 함께 그 값이 적힌 파일을 보여 줘요.

```bash
git config --show-origin init.defaultBranch
```

```text
file:/Library/Developer/CommandLineTools/usr/share/git-core/gitconfig	main
```

이 Mac은 등록하지 않았는데도 `main`이 나와요. Apple 개발자 도구 안의 기본값 파일에 이미 들어 있기 때문이에요. 그래도 강의대로 내 설정 파일에 등록해 둬요. 그러면 나중에 다른 방법(예: Homebrew)으로 Git을 설치해도 `main`이 유지돼요.

```bash
git config --global init.defaultBranch main
git config --show-origin init.defaultBranch
```

```text
file:/Users/(내 Mac 사용자 이름)/.gitconfig	main
```

값은 같지만 이번에는 내 홈 폴더의 `.gitconfig` 파일에서 왔다고 나와요. 같은 설정이 두 군데 있으면 내 설정 파일 쪽이 이겨요. 그 규칙이 6단계예요.

## 6단계: 설정이 저장되는 곳은 세 군데다

설정은 적용 범위에 따라 세 파일에 나뉘어 저장돼요.

| 옵션 | 적용 범위 | 저장 파일 |
|---|---|---|
| `--system` | 이 컴퓨터의 모든 사용자, 모든 저장소 | `/etc/gitconfig` |
| `--global` | 내 계정의 모든 저장소 | 홈 폴더의 `.gitconfig` |
| `--local` | 지금 저장소 하나 | 그 저장소의 `.git/config` |

Git은 설정을 넓은 범위부터 읽고, 같은 설정이 여러 곳에 있으면 **좁은 범위의 값**을 써요. 그래서 평소에는 `--global`로 내 이름·이메일을 쓰다가, 어떤 저장소 하나에서만 다른 이메일을 쓰고 싶으면 그 저장소 안에서 `--local`로 넣으면 돼요. 옵션 없이 `git config user.email "…"`처럼 쓰면 `--local`과 같아요.

`--local` 설정은 저장소 안에서만 의미가 있어요. `KDT학습` 저장소의 `.git/config`에는 이 저장소가 어느 GitHub 주소로 올라가는지가 적혀 있어요. 연습을 마칠 때 `git push`를 하면 `KDT-learning`으로 올라가는 건 이 설정 덕분이에요 (03회차에서 직접 연결해 봐요).

이 Mac에는 `/etc/gitconfig`가 아직 없어요. 5단계에서 본 개발자 도구 안의 파일은 Apple이 따로 넣어 둔 기본값 파일이고, 세 파일보다 먼저 읽혀서 `--global`에 같은 설정을 넣으면 그 값이 이겨요.

### ▶ 직접 해 보기 — 저장소 하나에만 있는 설정 보기

```bash
cd ~/personal/KDT학습
git config --local --list
```

```text
core.repositoryformatversion=0
core.filemode=true
core.bare=false
core.logallrefupdates=true
core.ignorecase=true
core.precomposeunicode=true
remote.origin.url=https://github.com/Jevan2310/KDT-learning.git
remote.origin.fetch=+refs/heads/*:refs/remotes/origin/*
branch.main.remote=origin
branch.main.merge=refs/heads/main
```

`core.`로 시작하는 줄은 저장소를 만들 때 Git이 자동으로 넣은 값이에요. `remote.origin.url`이 이 저장소의 GitHub 주소예요. 이름·이메일은 이 파일에 없어서, `--global`에 등록한 값을 써요.

**바꿔 보기**
- `cd ~`로 홈 폴더에 가서 `git config --local --list`를 쳐 봐요. 홈 폴더는 저장소가 아니라서 `fatal: --local can only be used inside a git repository`가 나와요.
- `git config --list --show-origin`을 쳐 봐요. 모든 설정이 어느 파일에서 왔는지 한꺼번에 보여요. 같은 이름이 두 번 나오면 아래쪽(좁은 범위) 값이 쓰여요.
- `git config --system --list`를 쳐 봐요. 이 Mac은 `/etc/gitconfig`가 없어서 `fatal: unable to read config file '/etc/gitconfig': No such file or directory`가 나와요. 고장이 아니라 파일이 없다는 뜻이에요.

## 마무리: 버전 하나를 만들 때 설정이 쓰이는 순서

02회차에서 처음으로 `git commit`을 쳐서 버전을 만들어요. 그때 오늘 등록한 설정이 이렇게 쓰여요.

1. `git commit`을 실행한다.
2. Git이 설정 파일을 넓은 범위부터 읽는다: 개발자 도구의 기본값 파일 → `/etc/gitconfig`(있으면) → 홈 폴더의 `.gitconfig` → 저장소의 `.git/config`.
3. `user.name`·`user.email`을 찾는다. 여러 곳에 있으면 가장 좁은 범위의 값을 쓴다.
4. 아무 데도 없으면 Mac 사용자 이름과 컴퓨터 이름으로 지어 넣고 경고를 띄운다.
5. 찾은 이름·이메일을 그 버전의 `Author`로 기록한다.
6. 03회차에서 GitHub에 올리면, GitHub가 그 이메일로 내 계정을 찾아 버전 옆에 프로필을 보여 준다.

`init.defaultBranch`는 `git commit`이 아니라 `git init`을 할 때 한 번 쓰여요. 저장소를 처음 만들 때 첫 줄기 이름을 정하는 데만 쓰여요.

## 오류가 날 때 찾아보기

| 오류 문장 · 증상 | 먼저 볼 곳 |
|---|---|
| `zsh: command not found: git` 또는 개발자 도구 설치 창이 뜸 | Git이 없음 → 창에서 설치 (3단계) |
| `xcrun: error: invalid active developer path` | macOS 업데이트 뒤 개발자 도구가 빠짐 → `xcode-select --install` (3단계) |
| `git config user.name`이 빈 줄 | 등록을 안 했거나 설정 이름 철자가 틀림 (4단계) |
| `error: key does not contain a section: username` | `user.name`에서 `user.`가 빠짐 (4단계) |
| 커밋할 때 `Your name and email address were configured automatically …` | 이름·이메일을 등록하지 않음 → `--global`로 등록 (4단계) |
| `Author identity unknown` / `*** Please tell me who you are.` | 이름·이메일을 등록하지 않음 (4단계) |
| GitHub에서 내 버전에 프로필이 안 뜸 | `user.email`이 GitHub 계정의 이메일(또는 noreply 주소)과 다름 (4단계) |
| `git init` 때 `hint: Using 'master' as the name for the initial branch.` | `init.defaultBranch`가 없음 (5단계) |
| `fatal: --local can only be used inside a git repository` | 저장소가 아닌 폴더에서 `--local`을 씀 (6단계) |
| `fatal: unable to read config file '/etc/gitconfig'` | `--system` 설정 파일이 없을 뿐, 고장 아님 (6단계) |
