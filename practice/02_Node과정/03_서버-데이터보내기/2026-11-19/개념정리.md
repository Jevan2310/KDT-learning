**팀 프로젝트에서**: 채팅방 목록처럼 "목록 불러오기" API는 오늘 만드는 `GET /students`와 똑같은 모양이에요. 오늘 배우는 `app.get` + `res.json`이 Node 백엔드 코드의 기본 뼈대예요. (새로 만들기 `POST`는 이 강의에는 아직 안 나와요.)

- ① Express와 첫 서버 → `server.js` (첫 버전)
- ② 주소 읽기 — `localhost`, 포트, 경로
- ③ 경로마다 다른 응답 — GET, 라우팅, `req`·`res` → `server.js` (최종 버전)
- ④ API와 JSON — `res.json()`, 데이터 vs 화면

## ① Express와 첫 서버

**🧭 맥락**: 02에서 입력 받기는 `readline-sync` 패키지에 맡겼죠. 오늘은 **요청 받기·응답 보내기**를 `express` 패키지에 맡겨요. Node.js만으로도 서버를 만들 수 있지만 코드가 길고 어려워요. Express는 그걸 몇 줄로 줄여 줘요.

| 이름 | 하는 일 |
|---|---|
| JavaScript | 코드를 쓰는 언어 |
| Node.js | 그 코드를 실행하는 프로그램 |
| npm | 패키지 설치 도구 |
| **Express** | 요청 받기·응답 보내기를 쉽게 해 주는 서버용 도구 상자 (패키지) |

```javascript
const express = require("express");      // 설치한 Express 가져오기 (02의 require와 같아요)

const app = express();                   // 서버(앱) 하나 만들기
const PORT = 3000;                       // 몇 번 창구에서 받을지

app.get("/", (req, res) => {             // "/" 주소로 요청이 오면 이 함수 실행
  res.send("안녕하세요, 한코딩 서버입니다!");   // 요청한 쪽에 응답 보내기
});

app.listen(PORT, () => {                 // 3000번에서 요청 받기 시작
  console.log(`서버 실행 중: http://localhost:${PORT}`);
});
```

> 💬 **쉽게 말하면** — Express는 **가게 운영 키트**예요. `express()`로 가게를 차리고, `app.get`으로 메뉴판에 "이 메뉴 주문이 오면 이렇게 내준다"를 적고, `app.listen`으로 문을 열고 손님을 기다려요.

파이썬 Flask를 써 봤다면 거의 같아요.

| Express | Flask |
|---|---|
| `const app = express();` | `app = Flask(__name__)` |
| `app.get("/", (req, res) => { … })` | `@app.get("/")` + `def …():` |
| `res.send("…")` | `return "…"` |
| `app.listen(3000)` | `app.run(port=3000)` |

### ▶ 붙여 넣어 보기 — `server.js` (첫 버전, 강의 코드)
```javascript
const express = require("express");

const app = express();
const PORT = 3000;

app.get("/", (req, res) => {
  res.send("안녕하세요, 한코딩 서버입니다!");

app.listen(PORT, () => {
  console.log(`서버 실행 중: http://localhost:${PORT}`);
});
```
```bash
node server.js
```
```text
서버 실행 중: http://localhost:3000
```
브라우저 주소창에 `http://localhost:3000`을 치면 `안녕하세요, 한코딩 서버입니다!`가 보여요.

**해 볼 것**
1. 터미널이 **끝나지 않고 멈춰 있어요** (명령을 칠 수 있는 줄이 안 돌아와요). 고장이 아니라 손님을 기다리는 중이에요. 02 `menu.js`의 `while (true)`처럼 계속 돌아요.
2. 문장을 바꾸고 **저장만** 한 뒤 브라우저를 새로고침 → 그대로예요. `Ctrl + C`로 끄고 `node server.js`로 다시 켠 뒤 새로고침해야 바뀌어요.
3. `Ctrl + C`로 끈 상태에서 새로고침 → **사이트에 연결할 수 없음** (`ERR_CONNECTION_REFUSED`). 가게 문이 닫힌 거예요. 다시 켜 두세요.

## ② 주소 읽기 — `localhost`, 포트, 경로

**🧭 맥락**: React 연습할 때 `http://localhost:5173`을 열었죠. 오늘은 `3000`이에요. 둘 다 내 컴퓨터인데 숫자만 달라요. 04에서는 둘을 **동시에** 켜요. 그래서 이 숫자가 무슨 뜻인지 알아야 해요.

```text
http://localhost:3000/students
```

| 부분 | 뜻 |
|---|---|
| `http` | 통신 방식 |
| `localhost` | **지금 접속하는 사람 자신의 컴퓨터** |
| `3000` | **포트** — 한 컴퓨터 안에서 어느 프로그램으로 갈지 정하는 번호 |
| `/students` | **경로** — 그 프로그램 안에서 무엇을 달라는지 |

- React 개발 서버(5173)와 API 서버(3000)는 포트가 달라서 한 컴퓨터에서 같이 켤 수 있어요.
- `localhost`는 "**나**의 컴퓨터"라서, 팀원이 같은 주소를 열면 **팀원 자기 컴퓨터**로 가요. 팀원에게 "`localhost:3000` 들어가 봐"라고 하면 내 서버가 아니라 팀원 컴퓨터의 서버를 보게 돼요.

> 💬 **쉽게 말하면** — 주소는 **택배 주소**예요. `localhost`는 "우리 집", 포트는 "몇 호", 경로는 "누구 앞으로". "우리 집"은 말하는 사람마다 다른 집이에요.

## ③ 경로마다 다른 응답 — GET, 라우팅, `req`·`res`

**🧭 맥락**: 02에서는 `while` 안에서 `if (cmd === "1") createStudent();`로 "입력에 맞는 함수"를 불렀죠. 서버에서는 `app.get("/경로", 함수)`로 "**이 주소로 요청이 오면 이 함수**"를 적어요. 이걸 **라우팅**이라고 해요. 계속 기다리는 반복(`while`)은 Express가 대신 해 줘요.

| 02 콘솔 | 03 서버 |
|---|---|
| `while (true)` + `readline.question()` | `app.listen()` (Express가 계속 기다려 줌) |
| `if (cmd === "2") printStudents();` | `app.get("/students", (req, res) => { … })` |
| `console.log(목록)` | `res.json(목록)` |

- **GET**: 데이터를 **조회**하는 요청이에요. 주소창에 주소를 치면 GET 요청이 가요.
- **`req`**: 손님이 보낸 **요청 정보**. **`res`**: 손님에게 **응답을 보내는 도구**. 이름은 내가 정한 매개변수예요.
- `(req, res) => { … }` 함수는 **Express가 요청이 올 때마다 불러 줘요.** 08에서 `onClick`에 넣은 함수를 React가 클릭할 때마다 불러 준 것과 같아요.
- **`console.log()`는 서버 터미널에**, **`res.send()`·`res.json()`은 브라우저에** 가요. `console.log()`만 쓰면 브라우저는 아무것도 못 받아요.

> 💬 **쉽게 말하면** — `req`는 손님이 낸 **주문서**, `res`는 손님에게 음식을 내주는 **쟁반**이에요. `console.log`는 주방 안 **메모**라서 손님은 못 봐요. 쟁반에 올리지 않으면(`res.send`를 안 하면) 손님은 음식을 하염없이 기다려요.

### ▶ 붙여 넣어 보기 — `server.js` (최종 버전, 전체 바꾸기)
강의 최종 코드에 비교용 경로 `/students-page` 하나를 더했어요 (④에서 써요).
```javascript
const express = require("express");

const app = express();
const PORT = 3000;

const students = [
  { id: 1, name: "한코딩" },
  { id: 2, name: "이학생" },
  { id: 3, name: "박학생" }
];

app.get("/", (req, res) => {
  res.send("안녕하세요, 한코딩 서버입니다!");
});

app.get("/hello", (req, res) => {
  console.log("GET /hello 요청이 들어왔습니다.");

  res.send("브라우저에 보내는 응답입니다.");
});

app.get("/students", (req, res) => {
  console.log("학생 목록을 요청받았습니다.");

  res.json(students);
});

// ── 비교용 (강의 밖): 같은 학생 목록을 "서버가 만든 화면(HTML)"으로 보내기 ──
app.get("/students-page", (req, res) => {
  let html = "<h1>학생 목록 (서버가 만든 화면)</h1><ul>";

  for (let i = 0; i < students.length; i++) {
    html += `<li>${students[i].id}. ${students[i].name}</li>`;
  }

  html += "</ul>";
  res.send(html);
});

app.listen(PORT, () => {
  console.log(`서버 실행 중: http://localhost:${PORT}`);
});
```
`Ctrl + C`로 끄고 다시 켜요.
```bash
node server.js
```

| 브라우저 주소 | 브라우저에 보이는 것 | 서버 터미널 |
|---|---|---|
| `http://localhost:3000` | 안녕하세요, 한코딩 서버입니다! | (없음) |
| `http://localhost:3000/hello` | 브라우저에 보내는 응답입니다. | `GET /hello 요청이 들어왔습니다.` |
| `http://localhost:3000/students` | `[{"id":1,"name":"한코딩"},…]` (JSON) | `학생 목록을 요청받았습니다.` |
| `http://localhost:3000/students-page` | 큰 제목 + 학생 목록 | (없음) |
| `http://localhost:3000/unknown` | `Cannot GET /unknown` | (없음) |

**해 볼 것**
1. `/hello`를 여러 번 새로고침 → 브라우저는 같은 문장인데, **서버 터미널에 로그가 한 줄씩 쌓여요.** 새로고침 = 요청 한 번이에요.
2. 개발자 도구(`Option + Cmd + I`) → **Network** 탭을 연 채로 새로고침 → **Status**에 `200`(성공)이 보여요. `/unknown`에서는 `404`(그런 경로 없음)예요.
3. **바꿔 보기 — 응답 안 보내기**: `/hello` 안의 `res.send(...)` 줄 앞에 `//`를 붙이고 재시작 → `/hello` 접속 → 브라우저가 **계속 로딩만** 해요. 서버 터미널에는 로그가 찍혀요. 요청은 받았는데 쟁반에 안 올린 거예요. 되돌리고 재시작해요.

## ④ API와 JSON — `res.json()`, 데이터 vs 화면

**🧭 맥락**: 01에서 "서버는 화면 대신 **데이터만** 보낼 수 있고, 그 형식이 JSON, 프론트와 백엔드가 맞추는 약속이 API"라고 했죠. 오늘 `GET /students → 학생 목록 JSON`이 바로 그 **API**예요. 04에서 React가 이 주소로 요청해서 화면을 그려요.

- **API**: "이 주소로 요청하면 이런 데이터를 줄게"라는 **약속**이에요.
- **`res.json(students)`**: JavaScript 배열·객체를 넘기면 Express가 **JSON 글자**로 바꿔서 보내요.
- **JSON 규칙**: 속성 이름과 문자열은 **큰따옴표**, 주석·함수는 못 넣어요. 코드와 브라우저를 비교해 보면:
  - 코드: `{ id: 1, name: "한코딩" }`
  - 브라우저: `{"id":1,"name":"한코딩"}` ← `id`, `name`에도 큰따옴표가 붙었어요
  - 파이썬으로 치면 `json.dumps(dict)`가 만든 글자예요. (파이썬 dict를 `print`하면 작은따옴표라 JSON이 아니에요.)
- **학생마다 `id`**: 02에서는 이름만 저장했고, 번호는 지우면 바뀌었죠. 이제 `id`는 학생에게 붙은 **고정 이름표**예요. 04에서 React가 `key={student.id}`로 써요 (06 `key`).

**같은 데이터, 두 가지 보내는 방식**

| 주소 | 서버가 보내는 것 | 화면은 누가 만드나 | 어디서 쓰나 |
|---|---|---|---|
| `/students-page` | 완성된 **HTML 화면** | 서버 | Spring 과정 Thymeleaf 방식 |
| `/students` | **JSON 데이터**만 | 받는 쪽 (React) | 이 과정, 팀 프로젝트 |

> 💬 **쉽게 말하면** — `/students-page`는 **완성된 도시락**이에요. 바로 먹을 수 있지만 모양은 못 바꿔요. `/students`는 **재료 키트**예요. 받는 쪽(React 웹, 휴대폰 앱)이 원하는 모양으로 요리해요. 그래서 API 하나로 웹과 앱이 같은 데이터를 같이 쓸 수 있어요.

**해 볼 것**
1. `/students`와 `/students-page`를 각각 열고 **페이지 소스 보기**(`Option + Cmd + U`)를 해 보세요. 하나는 JSON 글자, 하나는 `<h1>`, `<li>` 같은 HTML이에요.
2. 학생 배열에 `{ id: 4, name: "최학생" }`을 추가하고 저장 → 새로고침 (그대로) → 재시작 → 새로고침 (4명). 쉼표(`,`) 빠뜨리지 않기!

## ⑤ 다시 켜기, 응답 ≠ 저장, 오류 화면 구분

**🧭 맥락**: 서버를 다루다 보면 "고쳤는데 안 바뀜", "Cannot GET", "연결할 수 없음"을 자주 봐요. 팀 프로젝트에서 AI가 짠 서버가 안 될 때도 이 구분부터 해요.

**저장 ≠ 재시작**: `node server.js`로 켠 서버는 파일을 저장해도 그대로예요. 끄고 다시 켜야 해요.
> 💡 강의 밖 팁: `node --watch server.js`로 켜면 **저장할 때마다 알아서 재시작**해요 (Node에 들어 있는 기능). AI가 `nodemon`을 쓰라고 하면 같은 역할의 패키지예요.

**응답 ≠ 저장**: `res.json(students)`는 배열을 **보내기만** 해요. 저장하는 코드가 아니에요. 서버를 재시작하면 코드에 적힌 학생들로 돌아가요. 이 강의에는 추가·삭제 API도 아직 없어요. 진짜 저장은 데이터베이스 과정에서 해요.

**브라우저에 보이는 것으로 구분하기**

| 브라우저 | 뜻 | 볼 곳 |
|---|---|---|
| 원하는 응답 (`200`) | 정상 | — |
| `Cannot GET /students` (`404`) | 서버는 **켜져 있는데** 그 경로가 없음 | 경로 철자, `app.get`이 있나, 재시작했나 |
| 사이트에 연결할 수 없음 (`ERR_CONNECTION_REFUSED`) | 서버가 **꺼져 있거나** 포트가 틀림 | 서버 터미널, 주소의 포트 번호 |
| 계속 로딩만 | 요청은 받았는데 **응답을 안 보냄** | `res.send`·`res.json`이 빠졌나 |

**포트 충돌 — 강의 설명과 조금 달라요**
- 같은 3000번으로 서버를 두 번 켜면 강의 표에는 `EADDRINUSE` 오류가 난다고 나와요.
- 그런데 지금 설치되는 Express 5에서는 강의 코드 그대로면 **오류 없이** `서버 실행 중: http://localhost:3000`이 찍히고 **바로 꺼져요.** 켜진 것처럼 보여서 헷갈려요.
- 오류를 보려면 `app.listen`을 이렇게 써요.
```javascript
app.listen(PORT, (error) => {
  if (error) throw error;
  console.log(`서버 실행 중: http://localhost:${PORT}`);
});
```
```text
Error: listen EADDRINUSE: address already in use :::3000
```
- 해결: 다른 터미널에서 켜 둔 서버를 `Ctrl + C`로 끄거나, `const PORT = 3001;`로 바꾸고 주소도 3001로 열어요.

**바꿔 보기 — 서버 두 번 켜기**: 서버가 켜진 상태에서 터미널 **+**로 새 터미널을 열고 `node server.js` → "서버 실행 중"이 찍히고 바로 명령 줄이 돌아와요. 위 코드로 `app.listen`을 바꾸고 다시 해 보면 `EADDRINUSE`가 보여요. 확인했으면 두 번째 터미널은 휴지통 아이콘으로 닫아요.

## 팀 프로젝트에서 AI가 짠 코드가 이상할 때 볼 곳

| 증상 | 먼저 볼 곳 |
|---|---|
| `Cannot find module 'express'` | 그 폴더에서 `npm install express` 했나 |
| 사이트에 연결할 수 없음 | 서버가 켜져 있나, 포트 번호가 맞나 |
| `Cannot GET /경로` | 경로 철자, `app.get`이 있나, 재시작했나 |
| 계속 로딩만 함 | 그 경로 함수에 `res.send`·`res.json`이 있나 |
| 고쳤는데 그대로 | 재시작했나 (`node --watch`면 자동) |
| "서버 실행 중"이 뜨고 바로 끝남 | 같은 포트에 서버가 이미 켜져 있나 (다른 터미널) |
| `ERR_HTTP_HEADERS_SENT: Cannot set headers after they are sent` | 한 요청에 응답을 두 번 보냈나 (`res.send` 뒤에 또 `res.json` 등). 응답은 **한 번만** |
| `require is not defined` | `package.json`에 `"type": "module"`이 있나 |
| 추가한 데이터가 재시작하면 사라짐 | 정상이에요 (배열). 데이터베이스 과정에서 해결 |

**03 한 줄 정리**
- `express()`로 앱을 만들고, `app.get("/경로", (req, res) => { … })`로 경로마다 응답을 정하고, `app.listen(3000)`으로 켠다.
- 주소 = `http` + `localhost`(내 컴퓨터) + `3000`(포트) + `/students`(경로). 주소창 = GET 요청.
- `console.log`는 서버 터미널, `res.send`·`res.json`은 브라우저. 응답을 안 보내면 계속 로딩.
- `res.json(배열)`로 JSON 데이터를 보낸다 = API. 화면은 받는 쪽이 만든다.
- 서버는 `Ctrl + C`까지 계속 실행. 고치면 재시작. `404`는 경로 없음, 연결 불가는 서버 꺼짐.
