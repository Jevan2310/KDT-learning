# 개념 정리 — Node과정 01. 백엔드와 Node.js

> 날짜: 2026-11-19 · wiki: [01_백엔드-Node](../../../../wiki/02_Node과정/01_백엔드-Node.md)
> 진도 우선: 연습 문제 대신 **붙여 넣어 바로 돌려 보는 예시**로 확인하고 넘어간다. 2026-11-19부터 **쉬운 말 + 맥락**(왜 지금 배우는지, 앞뒤와 어떻게 이어지는지)을 함께 쓴다 (사용자 요청).

## 🧭 맥락 — 지금 어디쯤 와 있나

React 과정에서는 **화면**을 만들었어요. 마지막이 08의 할 일 앱이었죠. 그런데 그 앱에는 큰 약점이 남아 있어요. **새로고침하면 할 일이 다 사라지고**, 다른 사람과 같이 볼 수도 없어요.

이걸 해결하려면 화면 뒤에서 **데이터를 맡아 주는 쪽**이 필요해요. 그게 **백엔드**예요. 이제부터 배우는 과정은 대부분 이 백엔드 이야기예요.

| 과정 | 한 줄로 | 할 일 앱으로 치면 |
|---|---|---|
| React (끝) | 화면 만들기 | 화면은 있지만 새로고침하면 사라짐 |
| **Node (지금)** | 이미 아는 JavaScript로 서버 맛보기 | 목록을 서버가 보내 줌 (서버를 끄면 사라짐) |
| Spring | 같은 일을 하는 서버를 Java로 만들기 | 국내 회사에서 많이 쓰는 방식 |
| SEO | 검색에 잘 나오게 하기 | (백엔드와는 따로인 이야기) |
| 비동기 | 서버 응답을 "기다리는" 방법 | 응답이 느려도 화면이 멈추지 않음 |
| 데이터베이스 | 진짜 창고 | 서버를 꺼도 데이터가 남음 |

팀 프로젝트(실시간 채팅)는 **React + Node.js** 조합이라, Node 과정이 팀 프로젝트 백엔드에 바로 쓰여요.

Node 과정 4회차 안에서 오늘 위치:
```text
01 말 익히기 + 터미널에서 JavaScript 실행   ← 오늘
02 터미널에서 도는 학생 관리 프로그램
03 진짜 서버 만들기 (브라우저 주소로 데이터 받기)
04 React 화면과 서버 연결 (서버가 보낸 목록을 화면에 표시)
```

오늘은 코드를 많이 쓰지 않아요. **역할을 나누는 말**(프론트엔드, 백엔드, 요청, 응답, JSON)을 익히는 날이에요. 팀 프로젝트 회의에서 "그건 백엔드에서 검사해야죠", "API가 JSON으로 보내 줘요" 같은 말이 오가는데, 그 말들이 오늘 다 나와요.

> 💬 **쉽게 말하면** — 웹 서비스는 **식당**과 비슷해요. 손님이 보는 **홀**(메뉴판, 주문 받는 직원)이 프론트엔드, 요리하는 **주방**이 백엔드, 재료를 넣어 두는 **창고**가 데이터베이스예요. 손님은 주방에 들어가지 않고 **주문서**(요청)만 내요. 주방은 **음식**(응답)을 내줘요. React 과정에서는 홀만 만들었고, 지금부터 주방을 만들어요.

오늘 볼 개념 5묶음 (예시 파일 4개)
- ① 내 앱의 데이터는 어디 있었나 — 서버가 필요한 이유
- ② 프론트엔드 · 백엔드 · 데이터베이스, 요청과 응답 → `request-flow.js`
- ③ 백엔드를 꼭 따로 두는 이유 3가지 → `request-flow.js` 바꿔 보기
- ④ Node.js와 npm → `hello.js`, `tasks.js` (강의 코드)
- ⑤ 브라우저와 Node.js의 차이 → `browser-only.js`

## 🛠 시작하기 — Node 연습장 만들기

Node 과정은 연습장 폴더 하나(`_node연습장`)를 계속 써요. React 연습장(`_react연습장`)과 같은 방식이에요. 오늘은 설치할 게 없어서 폴더만 만들면 돼요.

```bash
mkdir -p ~/personal/KDT학습/practice/02_Node과정/_node연습장   # 폴더 만들기 (처음 한 번)
cd ~/personal/KDT학습/practice/02_Node과정/_node연습장         # 그 폴더로 들어가기
node -v    # v로 시작하는 버전 번호가 나오면 OK
npm -v     # 숫자가 나오면 OK
```
- VS Code에서 **File → Open Folder**로 `_node연습장`을 열면 터미널(`` Ctrl + ` ``)이 처음부터 이 폴더에서 열려요.
- 아래 각 절의 파일 4개를 이 폴더에 **새로 만들어** 붙여 넣어요: `request-flow.js`, `hello.js`, `tasks.js`, `browser-only.js`
- 실행은 `node 파일이름.js`예요. 파이썬의 `python3 파일.py`와 같아요. 결과는 **브라우저가 아니라 터미널**에 나와요.
- 오늘은 `npm install`로 설치할 것이 없고, 브라우저도 쓰지 않아요.

## ① 내 앱의 데이터는 어디 있었나 — 서버가 필요한 이유

**🧭 맥락**: 08 할 일 앱 끝에서 "새로고침하면 사라진다"를 봤어요. 오늘은 그 이유와 해결 방향부터 짚어요.

08에서 할 일 목록은 이 한 줄에 있었어요.
```jsx
const [tasks, setTasks] = useState([]);
```
이 데이터는 **지금 내 브라우저의 메모리**에만 있어요. 메모리는 페이지가 열려 있는 동안만 쓰는 임시 공간이에요. 그래서:
- 새로고침하면 사라져요.
- 휴대폰으로 열면 목록이 비어 있어요. (다른 기기)
- 친구 화면에는 내 목록이 없어요. (다른 사람)

`localStorage`(브라우저 저장소)를 쓰면 새로고침은 버텨요. 하지만 여전히 **그 브라우저 안에만** 있어요. 다른 기기, 다른 사람과 나누려면 모두가 접속하는 **한 곳**에 데이터를 둬야 해요. 그곳이 **서버**와 **데이터베이스**예요.

> 💬 **쉽게 말하면** — state는 내 책상 위 **포스트잇**이에요. 방을 나가면(새로고침) 치워지고, 다른 사람은 볼 수 없어요. `localStorage`는 내 **서랍**이라 오래 남지만, 여전히 내 방 안이에요. 모두가 보려면 회사 **공용 게시판**(서버)에 붙여야 해요.

**팀 프로젝트에서**: 회원 정보, 게시글, 댓글처럼 다른 사람도 봐야 하는 데이터는 전부 서버에 둬요. React state에는 "지금 화면에 보여 줄 복사본"만 들고 있어요.

## ② 프론트엔드 · 백엔드 · 데이터베이스 — 요청과 응답

**🧭 맥락**: 서버가 필요하다는 건 알았어요. 그럼 화면(React)과 서버는 일을 어떻게 나눌까요? 이 나눔이 팀 프로젝트에서 "프론트 담당 / 백엔드 담당"을 가르는 기준이에요.

| 누구 | 하는 일 | 식당으로 치면 | 이번 과정에서 |
|---|---|---|---|
| **프론트엔드** | 사용자가 보고 누르는 화면. 입력 받기, 목록 보여 주기, 로딩·오류 안내 | 홀 | React |
| **백엔드** | 요청을 받아 검사하고, 데이터를 찾거나 저장하고, 결과를 돌려주기 | 주방 | Node.js (다음 과정은 Spring) |
| **데이터베이스(DB)** | 데이터를 보관하고 찾아 주기 | 창고 | 이번 과정은 DB 대신 서버 코드의 배열 |

둘을 잇는 것이 **요청(Request)** 과 **응답(Response)** 이에요. 줄여서 `req`, `res`라고 써요. 03회차 서버 코드에 이 이름이 그대로 나와요.

```text
[프론트]  "할 일 목록 주세요"            ← 요청
   ↓
[백엔드]  요청 확인 → 창고에 목록 달라고 함
   ↓
[DB]     저장된 목록을 꺼내 줌
   ↓
[백엔드]  목록을 돌려줌                  ← 응답 (JSON)
   ↓
[프론트]  받은 목록을 화면에 그림
```

함께 알아 둘 말 4개:
- **클라이언트**: 요청을 보내는 쪽이에요. 브라우저, 휴대폰 앱이 클라이언트예요. 식당의 손님이에요.
- **서버**: 특별한 기계라는 뜻이 아니에요. **요청을 기다렸다가 응답하는 프로그램**(또는 그 프로그램이 도는 컴퓨터)이에요. 수업에서는 **내 노트북**에서 서버 프로그램을 켜고, 같은 노트북의 브라우저가 거기에 요청해요. 실제 서비스는 이 프로그램을 클라우드 컴퓨터에 켜 둬서 누구나 접속하게 해요.
- **JSON**: 서버가 보내는 데이터의 모양이에요. 서버는 화면을 통째로 보내지 않고 **데이터만** 보낼 수 있어요. 그 데이터를 어떻게 보여 줄지는 프론트가 정해요. JavaScript 객체·배열과 거의 똑같이 생겼어요. 자세한 규칙은 03회차에서 봐요.
  ```json
  [{ "id": 1, "title": "React 복습하기", "completed": false }]
  ```
- **서버 ≠ DB**: 서버를 만들었다고 데이터가 영원히 남지는 않아요. 서버 코드의 배열에만 넣은 데이터는 **서버를 껐다 켜면 처음 상태로** 돌아가요. 오래 남기는 건 DB가 하는 일이에요.

> 💬 **쉽게 말하면** — 손님(클라이언트)은 주문서(요청)만 내고 주방 안은 몰라요. 주방(백엔드)은 주문을 보고 창고(DB)에서 재료를 꺼내 요리(응답)를 내줘요. 요즘 주방은 상을 다 차려 주지 않고 **요리만**(데이터) 내주는 경우가 많아요. 어떤 그릇에 어떻게 담을지(화면 모양)는 홀(React)이 정해요. 그 요리를 담아 보내는 형식이 JSON이에요.

**팀 프로젝트에서**: 프론트 담당과 백엔드 담당이 가장 먼저 맞추는 게 "어떤 요청을 보내면 어떤 JSON이 오는지"예요. 이 약속을 **API**라고 불러요 (03회차).

### ▶ 붙여 넣어 보기 — `request-flow.js`
진짜 서버는 아니에요. 세 역할이 **어떤 순서로** 일하는지 터미널에 찍어 보는 코드예요. 함수 두 개(`frontend`, `backend`)와 배열 하나(`database`)가 홀, 주방, 창고 역할을 해요. 문법은 React 과정에서 본 함수, 객체, 배열, `if`, `trim()`뿐이에요.

```javascript
// request-flow.js — 프론트엔드 · 백엔드 · 데이터베이스가 하는 일을 흉내 낸 코드
// 진짜 서버는 아니에요. 누가 무엇을 하는지 "순서"만 보여 줘요. (진짜 서버는 03회차)

// 🗄 데이터베이스 역할: 데이터를 보관하는 창고
const database = [
  { id: 1, title: "React 복습하기", completed: true },
  { id: 2, title: "Node.js 실행하기", completed: false },
];

// 🍳 백엔드 역할: 요청을 받아 검사하고, 창고에서 꺼내거나 넣고, 결과를 돌려준다
function backend(request) {
  console.log(`   [백엔드] 요청 받음: ${request.type}`);

  if (request.type === "목록 보기") {
    console.log("   [백엔드] 창고에서 목록을 꺼냄");
    return { ok: true, data: database };
  }

  if (request.type === "추가") {
    // 서버에서도 검사한다 — 화면을 거치지 않고 요청이 올 수도 있으니까
    if (request.title.trim() === "") {
      console.log("   [백엔드] 제목이 비어 있어서 거절");
      return { ok: false, message: "제목을 입력하세요" };
    }

    const newTask = { id: database.length + 1, title: request.title, completed: false };
    database.push(newTask); // 서버 배열은 React state가 아니라서 push로 넣어요
    console.log("   [백엔드] 창고에 저장함");
    return { ok: true, data: newTask };
  }

  return { ok: false, message: "모르는 요청이에요" };
}

// 🙋 프론트엔드 역할: 요청을 보내고, 돌아온 응답을 화면에 보여 준다 (여기서는 터미널이 화면)
function frontend(request) {
  console.log(`[프론트] 요청 보냄 → ${request.type}`);
  const response = backend(request);

  if (response.ok) {
    console.log("[프론트] 응답 받음 → 화면에 표시:", response.data);
  } else {
    console.log(`[프론트] 응답 받음 → 오류 안내 표시: ${response.message}`);
  }
  console.log("");
}

frontend({ type: "목록 보기" });
frontend({ type: "추가", title: "서버 역할 이해하기" });
frontend({ type: "추가", title: "   " });
frontend({ type: "목록 보기" });
```

```bash
node request-flow.js
```

결과 (앞부분):
```text
[프론트] 요청 보냄 → 목록 보기
   [백엔드] 요청 받음: 목록 보기
   [백엔드] 창고에서 목록을 꺼냄
[프론트] 응답 받음 → 화면에 표시: [
  { id: 1, title: 'React 복습하기', completed: true },
  { id: 2, title: 'Node.js 실행하기', completed: false }
]

[프론트] 요청 보냄 → 추가
   [백엔드] 요청 받음: 추가
   [백엔드] 창고에 저장함
[프론트] 응답 받음 → 화면에 표시: { id: 3, title: '서버 역할 이해하기', completed: false }

[프론트] 요청 보냄 → 추가
   [백엔드] 요청 받음: 추가
   [백엔드] 제목이 비어 있어서 거절
[프론트] 응답 받음 → 오류 안내 표시: 제목을 입력하세요
```

**해 볼 것**
1. 출력을 위에서부터 읽어 보세요. 매번 `[프론트] 요청 보냄` → `[백엔드] …` → `[프론트] 응답 받음` 순서예요. **프론트는 `database`를 직접 건드리지 않아요.** 꼭 백엔드를 거쳐요.
2. `화면에 표시:` 뒤에 오는 건 화면이 아니라 **데이터**(배열·객체)예요. 이걸 어떻게 그릴지는 프론트가 정해요. 04회차에서 React가 이런 데이터를 받아 `map`으로 목록을 그려요.
3. 마지막 "목록 보기"에는 방금 추가한 3번 `서버 역할 이해하기`가 있어요. 이제 **한 번 더 실행**해 보세요. 첫 "목록 보기"는 또 2개뿐이에요. 지난번에 추가한 3번은 남아 있지 않아요. 프로그램이 끝나면 배열도 사라지고, 다시 켜면 처음 값부터 시작해요. **"서버 배열은 서버를 재시작하면 초기화된다"** 가 이 뜻이에요. 그래서 DB가 필요해요.

## ③ 백엔드를 꼭 따로 두는 이유 3가지

**🧭 맥락**: "그냥 React에서 다 하면 안 돼?"라는 생각이 들 수 있어요. 그런데 화면 코드는 **사용자의 브라우저로 내려가서** 돌아요. 사용자 손에 있는 코드라서 맡기면 안 되는 일이 있어요.

| 이런 일 | 왜 백엔드에서 | 예 |
|---|---|---|
| 여러 사람이 같은 데이터를 볼 때 | 내 브라우저에만 있으면 남이 못 봐요 | 게시글, 공유 일정, 댓글 |
| 중요한 판단을 할 때 | 사용자가 화면을 거치지 않고 요청을 보낼 수 있어요. **권한과 입력값은 서버에서도 검사**해요 | "내 글만 삭제 가능", "빈 제목 금지" |
| 비밀 정보를 쓸 때 | 브라우저로 내려간 코드는 누구나 열어 볼 수 있어요 | DB 비밀번호, 비공개 API 키 |

> 💬 **쉽게 말하면** — 메뉴판에 "쿠폰은 한 사람에 한 장"이라고 적어 둬도, 손님이 주방 뒷문으로 주문서를 밀어 넣으면 소용없어요. 그래서 **주방에서도** 다시 확인해요. 금고 비밀번호를 메뉴판에 적지 않는 것도 같은 이유예요. 브라우저 코드는 손님이 다 볼 수 있는 메뉴판이에요.

**화면에서 검사했다고 서버 검사를 빼면 안 돼요.** 화면 검사는 사용자를 돕는 안내이고, 진짜 문지기는 서버예요.

**팀 프로젝트에서**: AI가 짠 React 코드에 `if (title.trim() === "") return;` 같은 검사가 있어도, 백엔드에도 같은 검사가 있는지 확인해요. API 키나 비밀번호가 React 코드(`src/` 안)에 들어 있으면 공개된 것과 같아요. 백엔드로 옮겨요.

### ▶ 바꿔 보기 — `request-flow.js`로 "서버 검사" 확인
1. `backend` 함수 안의 빈 제목 검사 4줄(`if (request.title.trim() === "") {`부터 닫는 `}`까지)을 마우스로 고르고 `Cmd + /`를 눌러 주석으로 만들어요.
2. 저장하고 `node request-flow.js`를 다시 실행해요.
3. 세 번째 요청이 거절되지 않고 `{ id: 4, title: '   ', completed: false }`로 **저장돼요.** 마지막 목록에도 빈 할 일이 들어가요.
4. 이 코드의 `frontend`에는 검사가 없어요. 화면을 거치지 않고 들어온 요청이라고 생각하면 돼요. 서버 검사가 없으면 이런 데이터가 그대로 창고에 쌓여요.
5. 같은 4줄을 다시 고르고 `Cmd + /`로 주석을 풀어 되돌려요.

## ④ Node.js와 npm

**🧭 맥락**: 주방(백엔드)을 만들 언어가 필요해요. 파이썬(Django), Java(Spring), PHP(라라벨)로도 만들어요. Node 과정은 **이미 아는 JavaScript**로 만들어요. 새 언어 부담 없이 "서버가 뭔지"에 집중할 수 있어요. 다음 Spring 과정에서는 같은 일을 Java로 해요.

**Node.js**는 **브라우저 밖에서 JavaScript를 실행해 주는 프로그램**이에요. 새 언어가 아니에요. 지금까지 쓴 JavaScript 그대로예요.
- 원래 JavaScript는 브라우저 안에서만 돌았어요. 브라우저 안에는 JavaScript를 읽고 실행하는 **엔진**이 있어요 (Chrome은 V8).
- 2009년에 이 엔진을 브라우저 밖에서 쓸 수 있게 만든 게 Node.js예요. 그 뒤로 JavaScript로 서버도, 터미널 도구도 만들게 됐어요.
- 네트워크 요청처럼 **기다리는 일**을 잘 처리하도록 만들어졌어요. 이 이야기는 비동기 과정에서 자세히 봐요.

| 하고 싶은 것 | Node | 파이썬 |
|---|---|---|
| 파일 실행 | `node hello.js` | `python3 hello.py` |
| 패키지(남이 만든 코드 묶음) 설치 | `npm install 이름` | `pip install 이름` |
| 버전 확인 | `node -v`, `npm -v` | `python3 --version` |

> 💬 **쉽게 말하면** — JavaScript가 원래는 브라우저라는 **집 안에서만** 일했다면, Node.js는 JavaScript가 **집 밖에서도** 일하게 해 주는 작업장이에요. 일하는 사람(문법)은 같고 장소만 달라요. 장소가 다르니 쓸 수 있는 도구도 달라요 (⑤에서 봐요).

**우리는 이미 Node.js를 써 왔어요.** React 연습장에서 친 `npm install`, `npm run dev`가 Node.js 위에서 돌았어요. 그때 켜진 건 **Vite 개발 서버**예요.

| 프로그램 | 하는 일 | 어디서 돌아가나 |
|---|---|---|
| React 코드 | 화면 그리기 | 브라우저 |
| Vite 개발 서버 (`npm run dev`, 5173번) | 개발하는 동안 화면 파일을 브라우저에 보내 주고, 저장하면 바로 반영 | Node.js |
| 이번에 만들 API 서버 (03회차, 3000번) | 데이터 요청을 받아 JSON으로 응답 | Node.js |

Vite와 API 서버는 둘 다 Node.js 위에서 돌지만 **다른 프로그램**이에요. 04회차에서는 터미널 두 개로 둘을 같이 켜요.

**Node.js와 npm은 하는 일이 달라요**

| 도구 | 하는 일 | 명령 예 |
|---|---|---|
| Node.js | JavaScript 파일 실행 | `node hello.js` |
| npm | 패키지 설치, 프로젝트에 적어 둔 명령 실행 | `npm install express`, `npm run dev` |

- `npm run dev`는 어디서나 되는 명령이 아니에요. 그 폴더 `package.json`의 `"scripts"`에 적힌 `dev` 명령을 대신 쳐 주는 거예요. React 연습장의 `package.json`에는 `"dev": "vite"`가 적혀 있어요.
- 그래서 `package.json`이 없는 폴더에서 `npm run dev`를 치면 오류가 나요 (아래 "해 볼 것" 4번).
- `npm run`만 치면 그 프로젝트에서 쓸 수 있는 명령 목록이 나와요.

> 💬 **쉽게 말하면** — Node.js는 **요리사**(코드를 실제로 실행)이고, npm은 **장보기 + 메모 담당**이에요. 필요한 재료(패키지)를 사 오고, `package.json`이라는 메모지에 적힌 일("dev = vite 켜기")을 대신 시켜요. 메모지에 없는 일은 못 시켜요.

**팀 프로젝트에서**: 팀원 코드를 받으면 보통 `npm install` → `npm run dev` 순서로 켜요. `npm run` 뒤에 뭘 쳐야 할지 모르겠으면 `package.json`의 `"scripts"`를 보면 돼요.

### ▶ 붙여 넣어 보기 — `hello.js` (강의 코드)

## ⑤ 브라우저와 Node.js의 차이

**🧭 맥락**: 같은 JavaScript인데 어디서 돌리느냐에 따라 쓸 수 있는 도구가 달라요. 서버 코드에 화면용 코드(`document`)가 섞이면 바로 오류가 나는 이유예요. AI가 프론트와 백엔드 코드를 한꺼번에 짜 줄 때 자주 섞여요.

| | 브라우저 | Node.js |
|---|---|---|
| 변수·함수·객체·배열·`filter` | ✅ | ✅ |
| `console.log()` 결과가 나오는 곳 | 개발자 도구 Console | **터미널** |
| `document`, `window` (화면 다루기) | ✅ | ❌ 없음 |
| 파일 다루기, 서버 켜기 | 막혀 있음 | ✅ |

> 💬 **쉽게 말하면** — 브라우저는 **화면이 달린 작업장**이라 화면을 바꾸는 도구(`document`)가 있어요. Node.js는 **화면 없는 작업장**이라 그 도구가 없는 대신 파일·서버 도구가 있어요. 화면을 바꾸는 코드는 브라우저(React)에, 데이터를 다루는 코드는 서버(Node)에 둬요.

### ▶ 붙여 넣어 보기 — `browser-only.js`
```javascript
// browser-only.js — 같은 JavaScript라도 브라우저에만 있는 기능은 Node.js에 없어요

const tasks = ["React 복습하기", "Node.js 실행하기"];
const remaining = tasks.filter((task) => task !== "React 복습하기");

console.log("배열, 함수, filter 같은 JavaScript 문법은 그대로 돼요.");
console.log(`남은 할 일: ${remaining.length}개`);

// 아래 줄 맨 앞의 // 를 지우고 저장한 뒤 다시 실행해 보세요
// document.querySelector("h1");

console.log("마지막 줄까지 실행됐어요.");
```
```bash
node browser-only.js
```
```text
배열, 함수, filter 같은 JavaScript 문법은 그대로 돼요.
남은 할 일: 1개
마지막 줄까지 실행됐어요.
```

**해 볼 것**
1. **바꿔 보기**: 10번째 줄 `// document.querySelector("h1");` 맨 앞의 `// `를 지우고 저장한 뒤 다시 실행해요.
   ```text
   배열, 함수, filter 같은 JavaScript 문법은 그대로 돼요.
   남은 할 일: 1개
   /Users/…/_node연습장/browser-only.js:10
   document.querySelector("h1");
   ^

   ReferenceError: document is not defined
       at …
   ```
   - 첫 줄 끝의 `:10`은 **몇 번째 줄**에서 오류가 났는지예요. 오류가 나면 파일 이름과 줄 번호부터 봐요.
   - `ReferenceError: document is not defined` = "`document`가 뭔지 몰라요". Node.js에는 화면이 없으니까요.
   - 그 아래 `at …` 줄들은 Node.js 내부를 거쳐 온 길이에요. 지금은 무시해도 돼요.
   - "마지막 줄까지 실행됐어요."가 **안 나와요.** 오류가 나면 프로그램은 그 줄에서 멈춰요.
2. 그 줄을 `alert("안녕");`으로 바꿔도 `ReferenceError: alert is not defined`가 나와요. 브라우저 팝업도 화면 도구라서 없어요.
3. 다시 `// document.querySelector("h1");`로 되돌려요.

## 팀 프로젝트에서 AI가 짠 코드가 이상할 때 볼 곳

| 증상 | 먼저 볼 곳 |
|---|---|
| `node: command not found` | Node.js가 설치됐나, 터미널을 껐다 켜 봤나 |
| `Cannot find module '…/파일.js'` (`MODULE_NOT_FOUND`) | 터미널 위치(`pwd`)와 파일 이름 |
| `Could not read package.json` | `package.json`이 있는 폴더에서 쳤나 |
| `npm error Missing script: "dev"` | `package.json`의 `"scripts"`에 `dev`가 있나 (`npm run`으로 목록 보기) |
| 고쳤는데 결과가 그대로 | 저장했나, `node 파일.js`를 다시 쳤나 |
| `document is not defined`, `window is not defined` | 화면용 코드를 서버(Node) 파일에 넣었나 |
| 빈 값·이상한 값이 저장됨 | 화면만이 아니라 백엔드에도 검사가 있나 |
| 서버를 껐다 켜니 데이터가 사라짐 | 배열에만 넣었나 (데이터베이스 과정에서 해결) |
| React 코드에 API 키·비밀번호가 보임 | 백엔드로 옮기기 |

- **04 `npm run dev`** — Vite 개발 서버예요. 03회차에 만들 API 서버와는 다른 프로그램이에요. ([04 wiki](../../../../wiki/01_React과정/04_React시작.md))

**01 한 줄 정리**
- 프론트엔드 = 화면(홀), 백엔드 = 요청 처리(주방), DB = 보관(창고). 둘은 요청·응답으로 잇고, 데이터는 JSON으로 주고받는다.
- 서버 배열은 서버를 끄면 사라진다. 오래 남기려면 DB.
- 화면에서 검사해도 서버에서 또 검사한다. 비밀 정보는 브라우저 코드에 넣지 않는다.
- Node.js = 브라우저 밖에서 JavaScript 실행 (`node 파일.js`, 결과는 터미널). npm = 패키지 설치 + `package.json`에 적힌 명령 실행.
- Node.js에는 `document`·`window`가 없다.

다음은 **02. 콘솔 학생 관리 프로그램** — `npm init -y`로 `package.json`을 만들고, 터미널에서 입력을 받는 프로그램을 만들어요.
