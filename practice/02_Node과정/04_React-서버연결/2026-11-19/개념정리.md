## ① 출처와 CORS — 서버가 "읽어도 돼요"라고 허락하기

**🧭 맥락**: 03에서는 주소창에 `http://localhost:3000/students`를 치면 JSON이 바로 보였죠. 오늘은 5173번에 열린 React 페이지가 3000번 서버에 요청해요. 브라우저는 이걸 "**다른 집**에서 온 요청"으로 봐요. 그래서 서버의 허락이 하나 더 필요한데, 그게 CORS예요.

**출처** = 프로토콜 + 호스트 + 포트. 셋이 **모두 같아야** 같은 출처예요.

| 주소 | 프로토콜 | 호스트 | 포트 |
|---|---|---|---|
| React `http://localhost:5173` | http | localhost | **5173** |
| 서버 `http://localhost:3000` | http | localhost | **3000** |

같은 내 컴퓨터인데도 포트가 달라서 **다른 출처**예요.

- 브라우저는 안전을 위해, 페이지의 JavaScript가 **다른 출처에서 온 응답을 마음대로 읽지 못하게** 막아요.
- 서버가 응답에 "이 출처는 읽어도 돼요"라는 **표시(헤더)**를 붙여 주면 읽게 해 줘요. 이 규칙이 **CORS**예요.
- 그 표시는 `Access-Control-Allow-Origin: http://localhost:5173`이에요. `cors` 패키지가 응답마다 이걸 붙여 줘요.
- **오늘 같은 GET 요청은 서버까지 가요.** 막히는 건 돌아온 응답을 **React 코드가 읽는 것**이에요. 그래서 CORS 오류가 나도 서버 터미널에는 `학생 목록을 요청받았습니다.`가 찍혀요.
- **주소창은 되는데 React에서만 안 되는 이유**: 주소창으로 여는 건 내가 직접 그 집에 간 거라 막지 않아요. 다른 페이지의 JavaScript가 응답을 가져갈 때만 허락을 확인해요.
- **CORS는 로그인·보안 기능이 아니에요.** 브라우저가 응답을 넘겨줄지 정하는 규칙일 뿐이에요. 서버를 지키는 검사는 따로 해요 (01 ③ "서버에서 또 검사").

> 💬 **쉽게 말하면** — 브라우저는 **건물 경비원**이에요. 5173호(React)가 3000호(서버)에 심부름을 보내면, 경비원은 심부름은 보내 줘요. 그런데 돌아온 물건에 "5173호에 전달해도 됨" **도장**이 없으면 5173호에 넘겨주지 않아요. `cors` 패키지는 서버가 물건마다 그 도장을 찍게 해 줘요.

**서버에 넣은 두 부분**
```javascript
const cors = require("cors");          // 맨 위에서 가져오기

app.use(
  cors({
    origin: "http://localhost:5173"    // 허락할 React 주소 (끝에 / 없이)
  })
);
```
- `app.use()`: **모든 요청에 공통으로 할 일**을 추가해요. 위치는 `const app = express();` 아래, `app.get`들보다 **앞**이에요.
- `origin`은 React 터미널에 찍힌 주소와 **글자 하나까지** 같아야 해요. 포트가 바뀌면 여기도 고쳐요.
- 파이썬 Flask라면 `flask-cors` 패키지로 같은 일을 해요.

**해 볼 것**
1. React 페이지에서 **학생 목록 요청** 버튼을 눌러요.
   - 브라우저 Console: `(3) [{…}, {…}, {…}]`
   - 서버 터미널: `학생 목록을 요청받았습니다.`
2. 주소창에 `http://localhost:3000/students`를 직접 열면 03처럼 JSON이 보여요.
3. **바꿔 보기 — CORS 빼기**: `server.js`에서 `app.use(`부터 `);`까지 5줄을 선택하고 `Cmd + /`(주석)를 눌러요. 저장 → 서버 `Ctrl + C` → `node server.js` → 버튼.
   - 서버 터미널: `학생 목록을 요청받았습니다.` ← **요청은 도착했어요**
   - 브라우저 Console (빨간 줄):
   ```text
   Access to fetch at 'http://localhost:3000/students' from origin 'http://localhost:5173' has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present on the requested resource.
   Uncaught (in promise) TypeError: Failed to fetch
   ```
   - 응답에 도장(헤더)이 없어서 경비원이 넘겨주지 않은 거예요. 다시 `Cmd + /`로 되돌리고 서버를 재시작해요.

## ② `fetch` + `async/await` — 요청 보내고 기다리기

**🧭 맥락**: 03에서는 주소창이 요청을 보냈어요. React 코드가 요청을 보낼 때는 `fetch`를 써요. 그런데 서버 응답은 **바로** 오지 않아요 (아주 짧아도 시간이 걸려요). 그래서 "응답이 올 때까지 기다렸다가 다음 줄로 가기"를 해 주는 `async/await`가 같이 나와요. 원리는 비동기 과정에서 자세히 배우고, 오늘은 **쓰는 모양**만 익혀요.

```jsx
async function loadStudents() {             // 안에서 await를 쓰려면 async 함수
  const response = await fetch(             // ① 요청 보내고, 응답이 올 때까지 기다림
    "http://localhost:3000/students"
  );

  const data = await response.json();       // ② 응답 상자를 열어 JSON → 배열로

  console.log(data);                        // ③ 학생 배열 (브라우저 Console에)
}
```

| 코드 | 뜻 |
|---|---|
| `fetch(주소)` | 그 주소로 **GET 요청** 보내기. 브라우저에 들어 있어서 설치 필요 없음 |
| `await` | 결과가 올 때까지 **이 함수만** 잠깐 멈춤. 화면과 버튼은 계속 움직여요 |
| `async function` | "안에서 `await`를 쓸게요"라는 표시. `async` 없이 `await`를 쓰면 오류 |
| `response` | 응답 **상자** (상태 코드, 헤더, 본문). 학생 배열이 **아니에요** |
| `await response.json()` | 상자를 열어 본문(JSON 글자)을 JavaScript 배열로 바꾸기. 이것도 시간이 걸려서 `await` |

> 💬 **쉽게 말하면** — 카페 **진동벨**이에요. `fetch`로 주문하면 음료 대신 진동벨(Promise)을 받아요. `await`는 벨이 울릴 때까지 기다리는 거예요. 기다리는 건 **나(이 함수)**뿐이고 카페(화면)는 계속 돌아가요. 벨이 울리면 받는 건 **포장된 상자**(`response`)라서, 한 번 더 뜯어야(`response.json()`) 음료(`data`)가 나와요.

**파이썬 `requests`와 비교**

| 파이썬 | JavaScript |
|---|---|
| `r = requests.get(url)` | `const response = await fetch(url);` |
| `r.status_code` | `response.status` |
| `data = r.json()` | `const data = await response.json();` |

- 파이썬 `requests.get`은 응답이 올 때까지 **프로그램 전체가** 멈춰요. 브라우저가 그러면 화면이 얼어 버려요. 그래서 JavaScript는 `await`로 "이 함수만" 기다려요.
- 파이썬에도 `async def` / `await`(asyncio)가 있어요. 모양이 같아요.

**`onClick={loadStudents}`**: 함수 이름만 넘겨요. `onClick={loadStudents()}`로 쓰면 클릭 전, 화면을 그릴 때 바로 실행돼요 (07 이벤트).

**해 볼 것**
1. **바꿔 보기 — 상자 그대로 찍기**: `console.log(data);`를 `console.log(response);`로 바꾸고 저장 → 버튼.
   ```text
   Response {type: 'cors', url: 'http://localhost:3000/students', redirected: false, status: 200, ok: true, …}
   ```
   학생 배열이 아니라 **상자**예요. 여기 보이는 `status: 200`, `ok: true`는 ⑤에서 써요. 되돌려요.
2. **바꿔 보기 — `await` 빼기**: `const data = await response.json();`에서 `await`를 지우고 저장 → 버튼 → `Promise {<pending>}`. 아직 안 뜯은 진동벨을 찍은 거예요. 되돌려요.

## ③ 받은 데이터를 state에 넣어 그리기

**🧭 맥락**: 지금은 학생 배열이 Console에만 찍혀요. 화면에 그리려면 07에서 배운 **state**에 넣어야 해요. state가 바뀌면 React가 화면을 다시 그려 주니까요. 그다음은 06의 `map` + `key` 그대로예요.

```text
버튼 클릭 → fetch → response.json() → data (학생 배열)
→ setStudents(data) → React가 다시 그림 → students.map(...)으로 <li> 목록
```

- **처음 값이 빈 배열(`useState([])`)인 이유**: 응답이 오기 전에도 화면은 먼저 그려지고 `students.map(...)`이 실행돼요. 빈 배열이면 아무것도 안 그리고 넘어가요.
- **`key={student.id}`**: 03에서 서버가 학생마다 붙여 둔 고정 이름표를 그대로 써요.
- **서버 배열이 바뀌어도 열린 화면은 그대로예요.** 서버가 React에 "바뀌었어요" 하고 알려 주지 않아요. 다시 요청해야 바뀌어요.

> 💬 **쉽게 말하면** — 음식을 받아도 **테이블(state)**에 올려야 손님이 봐요. 쟁반을 들고만 있으면(`console.log`) 직원만 봐요. 그리고 주방에서 메뉴를 바꿔도, 다시 주문하기 전에는 테이블 위 음식은 그대로예요.

### ▶ 붙여 넣어 보기 — `StudentList.jsx` 2단계 (강의 실습 3, 전체 바꾸기)

2. 서버 `students`에 `{ id: 4, name: "최학생" }` 추가 → 저장 → 서버 재시작 → 화면은 아직 3명 → 버튼 → 4명.

## ④ `useEffect` — 화면이 처음 나타날 때 자동으로

**🧭 맥락**: 목록 화면에 들어갈 때마다 버튼을 눌러야 하면 불편하죠. 보통 앱은 **화면이 뜨자마자** 목록을 불러와요. "컴포넌트가 화면에 처음 나타날 때 할 일"을 적는 곳이 `useEffect`예요.

**그냥 컴포넌트 안에서 `loadStudents()`를 부르면 안 되나요?** 컴포넌트 함수는 **다시 그릴 때마다** 실행돼요. 요청 → `setStudents` → 다시 그림 → 또 요청… 끝없이 반복돼요. `useEffect(…, [])`는 "처음 한 번만"이에요.

```jsx
useEffect(() => {
  async function loadStudents() { … }   // ① 안에서 async 함수를 만들고
  loadStudents();                       // ② 바로 불러요
}, []);                                 // ③ [] = 처음 나타날 때 한 번
```

| 부분 | 뜻 |
|---|---|
| `useEffect(함수, [])` | 화면에 처음 나타난 **뒤에** 함수 실행 |
| `[]` (의존성 배열) | "다시 실행할 이유" 목록. 비어 있으면 처음 한 번만 |
| 안에 `async function` | Effect 함수 자체에는 `async`를 붙이지 않아서 안에 따로 만들어요 |

> 💬 **쉽게 말하면** — 손님이 **자리에 앉자마자** 물과 메뉴판을 갖다 주는 것과 같아요. 부르지 않아도(버튼 없이) 앉으면(화면에 나타나면) 한 번 해요. `[]`는 "앉을 때 한 번만"이라는 메모예요.

**개발 중에는 요청이 두 번 가요**: `main.jsx`의 `<StrictMode>`가 개발 중에만 "정리가 잘 되나" 확인하려고 Effect를 한 번 더 실행해요. 서버 터미널에 로그가 두 줄 찍혀도 정상이에요. Strict Mode를 지우지 않아도 돼요 (04 React시작).

### ▶ 붙여 넣어 보기 — `StudentList.jsx` 3단계 (전체 바꾸기)
강의는 2단계에서 바로 최종으로 가요. 그 사이에 `useEffect`만 넣은 단계를 하나 끼웠어요.
```jsx
import { useEffect, useState } from "react";

function StudentList() {
  const [students, setStudents] = useState([]);

  // 화면에 처음 나타날 때 한 번 요청
  useEffect(() => {
    async function loadStudents() {
      const response = await fetch(
        "http://localhost:3000/students"
      );

      const data = await response.json();

      setStudents(data);
    }

    loadStudents();
  }, []);

  return (
    <section>
      <h2>학생 목록</h2>

      <ul>
        {students.map((student) => (
          <li key={student.id}>{student.name}</li>
        ))}
      </ul>

```

**해 볼 것**
1. 저장하면 버튼 없이 바로 목록이 보여요. 서버 터미널에는 로그가 **두 줄** 찍혀요 (Strict Mode).
2. 새로고침할 때마다 두 줄씩 늘어요. 새로고침하면 컴포넌트가 화면에 새로 나타나요 (마운트).
3. **바꿔 보기 — `[]` 빼기 (잠깐만)**: `}, []);`를 `});`로 바꾸고 저장 → 화면은 멀쩡한데 **서버 터미널이 로그로 폭주해요** (테스트해 보니 1초에 수천 번). state를 바꿀 때마다 다시 그리고, 다시 그릴 때마다 Effect가 또 요청하기 때문이에요. **바로 `[]`를 되돌리고 저장**해요. 그래도 계속되면 브라우저를 새로고침해요.

## ⑤ 로딩·오류·빈 목록 — 실패해도 친절하게 (강의 최종)

**🧭 맥락**: 3단계 코드는 **잘 될 때만** 생각했어요. 실제로는 서버가 꺼져 있을 수도 있고, 주소가 틀릴 수도 있고, 학생이 0명이거나 응답이 느릴 수도 있어요. 그럴 때 화면이 그냥 비어 있으면 사용자는 "고장인가?" 해요. 상황마다 다른 문구를 보여 주는 게 오늘 최종 코드예요.

**state 3개**

| state | 처음 값 | 뜻 |
|---|---|---|
| `students` | `[]` | 받은 학생 목록 |
| `isLoading` | `true` | 지금 기다리는 중인지 (처음부터 바로 요청하니까 `true`) |
| `error` | `""` | 화면에 보여 줄 오류 문구 (빈 글자 = 오류 없음) |

**실패 잡기: `try / catch / finally`** (파이썬 `try / except / finally`와 같아요)

| JavaScript | 파이썬 | 최종 코드에서 하는 일 |
|---|---|---|
| `try { }` | `try:` | 요청 → 성공 확인 → 데이터 저장 |
| `catch (error) { }` | `except Exception as error:` | 오류 문구 저장 |
| `finally { }` | `finally:` | 성공이든 실패든 로딩 끝 |
| `throw new Error("…")` | `raise Exception("…")` | 직접 오류 내기 → `catch`로 이동 |

**`response.ok`: fetch는 404에도 "성공"이라고 해요**
- `fetch`가 알아서 `catch`로 가는 건 **응답 자체를 못 받았을 때**뿐이에요. 서버가 꺼졌거나 CORS로 막힌 경우예요.
- 서버가 `404`(그런 경로 없음)나 `500`(서버 오류)으로 **응답은 했다면**, fetch 입장에서는 성공이에요.
- 그래서 직접 확인해요. `response.ok`는 상태 코드가 200~299면 `true`예요.
```javascript
if (!response.ok) {
  throw new Error("학생 목록을 불러오지 못했습니다.");   // → catch로 이동
}
```
- 파이썬 `requests`도 똑같아요. 404에도 예외가 안 나서 `r.raise_for_status()`를 불러야 하죠. `if (!response.ok) throw …`가 그 역할이에요.

> 💬 **쉽게 말하면** — 진동벨이 울렸다고 다 성공은 아니에요. 가서 받아 보니 "재료가 떨어졌어요" 쪽지(404)일 수도 있어요. `response.ok`는 **쟁반에 진짜 음식이 있는지** 보는 거예요. 진동벨이 아예 안 울리는 경우(서버 꺼짐)는 fetch가 알아서 `catch`로 보내 줘요.

**`ignore`: 늦게 온 응답 무시하기**
```javascript
let ignore = false;
…
if (!ignore) { setStudents(data); }
…
return () => { ignore = true; };   // 정리 함수: 이 Effect가 끝날 때 실행
```
- 응답이 오기 전에 컴포넌트가 사라지거나 Effect가 다시 시작되면, 예전 요청의 응답이 **늦게** 도착할 수 있어요. 그때는 `ignore`가 `true`라서 state를 바꾸지 않아요.
- Strict Mode로 두 번 실행될 때도 첫 번째 응답은 `ignore`로 버려지고 두 번째만 화면에 들어가요.
- 요청을 **취소하는 건 아니에요.** 요청은 가고 응답도 와요. 받아서 **버릴 뿐**이에요.

> 💬 **쉽게 말하면** — 이미 **나간 손님** 몫의 음식이 늦게 나오면 그 테이블에 차리지 않는 거예요. 주방은 이미 요리했지만(요청은 감) 차리지는 않아요.

**화면 고르기: 삼항 이어 쓰기** (06 조건부 렌더링)
```text
isLoading이면          → "학생 목록을 불러오는 중입니다."
아니고 error가 있으면   → 빨간 오류 문구
아니고 0명이면          → "등록된 학생이 없습니다."
나머지                 → "전체 학생: n명" + 목록
```
위에서부터 순서대로 읽어요. 처음 맞는 하나만 보여요.

- `catch (error)`의 `error`는 이 블록에서만 쓰는 **오류 객체**예요. 화면에 보여 줄 문구는 state `error`에 따로 넣어요. 이름은 같아도 다른 값이에요.

### ▶ 붙여 넣어 보기 — `StudentList.jsx` 최종 (강의 실습 4, 전체 바꾸기)
```jsx
import { useEffect, useState } from "react";

// 컴포넌트
function StudentList() {
  const [students, setStudents] = useState([]);
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError] = useState("");

  useEffect(() => {
    let ignore = false;

    async function loadStudents() {
      try {
        const response = await fetch(
          "http://localhost:3000/students"
        );

        if (!response.ok) {
          throw new Error(
            "학생 목록을 불러오지 못했습니다."
          );
        }

        const data = await response.json();

        if (!ignore) {
          setStudents(data);
        }
      } catch (error) {
        console.error(error);

        if (!ignore) {
          setError(
            "학생 목록을 불러오지 못했습니다. 서버와 주소를 확인해주세요."
          );
        }
      } finally {
        if (!ignore) {
          setIsLoading(false);
        }
      }
    }

    loadStudents();

    return () => {
      ignore = true;
    };
  }, []);

  return (
    <section className="student-list">
      <h2>학생 목록</h2>

      {isLoading ? (
        <p role="status">학생 목록을 불러오는 중입니다.</p>
      ) : error ? (
        <p role="alert">{error}</p>
      ) : students.length === 0 ? (
        <p>등록된 학생이 없습니다.</p>
      ) : (
        <>
          <p>전체 학생: {students.length}명</p>

          <ul>
            {students.map((student) => (
              <li key={student.id}>
                {student.name}
              </li>
            ))}
          </ul>
        </>
      )}
    </section>
  );
}

export default StudentList;
```

**Network 탭으로 확인하기** (강의 11장)
- 개발자 도구 → **Network** → 새로고침 → 목록에서 `students`를 클릭해요.

| 항목 | 정상일 때 |
|---|---|
| Request URL | `http://localhost:3000/students` |
| Request Method | `GET` |
| Status Code | `200 OK` |
| Response 탭 | 학생 배열 JSON |

- 화면이 이상할 때 React 코드부터 보지 말고 **Network부터** 봐요.
  - `students` 줄이 없음 → 요청을 안 보냈어요 (React 쪽 문제)
  - `404` → 주소 경로가 틀렸어요
  - 빨간 CORS 오류 → 서버 CORS 설정 문제
  - `200`인데 화면이 이상함 → 받은 데이터를 다루는 React 코드 문제

## 🧭 다음으로 이어지는 그림

Node 과정은 여기까지예요. 오늘 만든 `StudentList.jsx`는 Spring 과정에서 **주소만 바꿔** 다시 써요.

```text
[React :5173] ── fetch("http://localhost:3000/students") ──▶ [Node Express :3000]   ← 오늘 (cors 패키지)
      │
      └──── fetch("http://localhost:8080/api/students") ───▶ [Spring :8080]         ← Spring 06 (@CrossOrigin)
```

- **Spring 06**: 같은 일을 Java 서버로 해요. CORS 허락은 `cors` 패키지 대신 `@CrossOrigin(origins = "http://localhost:5173")`로 해요.
- **비동기 과정**: 오늘 "모양만" 익힌 Promise, `async/await`가 왜 그렇게 동작하는지 배워요. 04회차에서 느린 API와 로딩 화면이 다시 나와요.
- **데이터베이스 과정**: 서버의 `students` 배열이 진짜 창고(DB)로 바뀌어요.

## 팀 프로젝트에서 AI가 짠 코드가 이상할 때 볼 곳

| 증상 | 먼저 볼 곳 |
|---|---|
| Console `blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present` | 서버에 `app.use(cors(...))`가 있나, 라우트보다 앞인가, 서버를 재시작했나 |
| Console `blocked by CORS policy: The 'Access-Control-Allow-Origin' header has a value 'http://localhost:5173' that is not equal to the supplied origin` | React가 다른 포트로 켜졌나. `npm run dev`를 두 번 켜면 두 번째는 `Port 5173 is in use, trying another one...` 뒤에 5174로 떠요 |
| 서버 터미널 `Error: Cannot find module 'cors'` | **서버 폴더**에서 `npm install cors` 했나 (React 폴더에 설치하면 소용없어요) |
| `TypeError: Failed to fetch` | 서버가 켜져 있나, 포트가 맞나. 바로 위에 CORS 오류가 같이 찍혔나 |
| `Unexpected token '<', "<!doctype "... is not valid JSON` | JSON 대신 HTML을 받았어요. `fetch("/students")`처럼 `http://localhost:3000` 없이 쓰면 5173(React)에 요청해서 React의 `index.html`이 와요. 경로가 틀려 서버의 `Cannot GET` 화면이 온 경우도 같아요 (`<!DOCTYPE`) |
| `students.map is not a function` | 받은 게 배열인가 (서버가 `{ students: [...] }`처럼 객체로 보냈나). `response.json()` 앞에 `await`가 빠졌나 |
| 화면이 하얗고 `Cannot read properties of undefined (reading 'map')` | `useState()`에 처음 값 `[]`가 빠졌나 |
| 화면이 하얗고 `useEffect must not return anything besides a function` / `destroy is not a function` | `useEffect(async () => …)`로 썼나. Effect 안에 async 함수를 따로 만들고 불러요 (`npm run lint`도 경고해요) |
| 서버 터미널에 요청 로그가 끝없이 찍힘 | `useEffect`의 `[]`가 빠졌나 |
| 요청이 두 번씩 감 | 정상이에요 (Strict Mode, 개발 중에만) |
| 서버 데이터를 바꿨는데 화면이 그대로 | 서버를 재시작하고 React를 새로고침(다시 요청)했나 |
| 로딩 문구가 안 사라짐 | `finally`에서 `setIsLoading(false)` 하나 |
| `app.use(cors())`처럼 괄호 안이 비어 있음 | 모든 출처를 허락하는 설정이에요. 연습에선 돌아가지만, 강의처럼 `origin`에 React 주소를 적는 게 기본이에요 |

- **04 React시작 `<StrictMode>`**: 요청이 두 번 가는 이유.

**04 한 줄 정리**
- 서버(3000)와 React(5173)를 터미널 두 개로 같이 켠다. 같은 컴퓨터라도 포트가 다르면 다른 출처다.
- 서버에 `npm install cors` + `app.use(cors({ origin: "http://localhost:5173" }))`(라우트 앞). 허락이 없으면 요청은 가도 React가 응답을 못 읽는다.
- `const response = await fetch(주소)` → `const data = await response.json()` → `setStudents(data)` → `map`.
- `useEffect(() => { async function load() {…} load(); }, [])`는 처음 나타날 때 한 번 실행된다. 개발 중 두 번은 Strict Mode 때문이다.
- `try/catch/finally` + `if (!response.ok) throw` + `isLoading`·`error` state로 로딩·오류·빈 목록을 나눠 보여 준다. 막히면 Network 탭부터 본다.
