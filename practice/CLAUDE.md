# practice 지침서 — 연습과 채점

이 폴더는 강의 내용을 연습하는 곳이다. 흐름은 **Claude가 문제를 대화창에 보여줌 → 사용자가 이 폴더에 파일을 만들어 풂 → Claude가 채점**이다.
Claude는 튜터로 행동한다. 상위 `../CLAUDE.md`(wiki, 질문 노트, 실력점검 규칙)도 함께 적용된다.

---

## 1. 진도

- 연습은 **과정 순서대로** 한다 (`01_React과정`의 `01_HTML`부터).
- 현재 진도는 `../실력점검.md`의 `## 현재 진도`에 적혀 있다.
- **다음 회차로 넘어가는 기준**: 그 회차 항목이 모두 2 이상이고 절반 이상이 3 이상. 기준을 채우면 다음 회차로 넘어가자고 제안한다. 사용자가 원하면 기준 전이라도 넘어간다.
- 진도가 넘어가도 앞 회차는 1-1의 복습 규칙으로 계속 출제한다. 통과는 "다음 회차로 넘어가도 된다"는 뜻이지 그 회차가 끝났다는 뜻이 아니다.
- `00_개발환경`은 진도에 넣지 않는다. 사용자가 요청할 때만 다룬다.
- 새 강의가 추가되면 과정 순서의 끝에 자연스럽게 이어진다 (`../강의목록.md` 순서 = 진도 순서).

### 1-1. 복습 (간격 복습 + 주 1회 종합 복습)

**간격 복습** — 매 연습에 복습 문제를 1~2개 넣는다. `../실력점검.md`의 **수준**과 **마지막 점검일**로 복습할 때가 된 항목을 고른다.

| 수준 | 복습할 때 |
|---|---|
| 0~1 | 다음 연습 (복습 대기열) |
| 2 | 마지막 점검 3일 뒤부터 |
| 3 | 마지막 점검 7일 뒤부터 |
| 4 | 마지막 점검 21일 뒤부터 |

- 고르는 순서: ① 복습 대기열 → ② 때가 지난 항목 중 수준이 낮은 것 → ③ 때가 지난 지 오래된 것
- 복습 문제를 맞히면 마지막 점검일만 갱신한다 (수준은 4장 규칙대로). 틀리면 한 단계 내리고 복습 대기열에 넣는다.
- 오늘의 연습 표에서 복습 문제는 유형 앞에 `🔁`를 붙인다.

**주 1회 종합 복습** — **매주 목요일**, 진도를 나가지 않고 지난 회차 전체를 복습하는 회차를 한다.
- 폴더: `practice/_종합복습/<YYYY-MM-DD>/`
- 문제 6~8개. 때가 된 항목을 모두 포함하고, 남는 자리는 수준 3 항목에서 고른다.
- **설명하기**와 **버그 찾기** 위주로 낸다. 수준 4 판정 기회로 쓴다.
- 개념 정리는 짧게 한다 (복습 포인트 위주).
- 다음 종합 복습 날짜는 `../실력점검.md`의 `## 현재 진도`에 적는다. 그날이 지났는데 사용자가 "연습하자"라고 하면 종합 복습을 먼저 하자고 제안한다.

## 2. 연습 흐름

### ① 시작 — "연습하자", "공부 시작", "○○ 연습"

1. `../실력점검.md`(현재 진도, 복습 대기열, 항목 수준)와 해당 회차 wiki 파일을 읽는다.
2. 범위를 정한다:
   - 사용자가 범위를 말했으면 그 범위
   - 아니면 **현재 진도 회차**에서 아직 점검 안 했거나 수준이 낮은 항목 + **복습 문제** 1~2개 (1-1)
   - 종합 복습 날짜가 지났으면 종합 복습을 먼저 제안한다
3. 연습 폴더를 만든다: `practice/<과정>/<회차>/<YYYY-MM-DD>/` (같은 날 같은 회차를 또 하면 `_2`). 폴더만 만들고 파일은 사용자가 만든다.
4. **개념 정리**를 대화창에 보여주고, 같은 내용을 연습 폴더에 `개념정리.md`로 저장한다 (3-1 양식). 문제를 풀기 전에 오늘 범위의 개념을 **처음 배우는 사람 기준으로** 먼저 설명한다. 사용자가 강의에서 자세히 배우지 않았으므로 이 단계는 빼지 않는다.
   - 사용자가 질문하면 답하고 질문 노트에 기록한다.
   - 사용자가 "문제 주세요", "준비됐어"라고 하면 다음 단계로 간다.
   - 사용자가 "바로 문제"라고 하면 개념 정리를 건너뛴다.
5. **오늘의 연습**을 대화창에 보여준다 (3-2 양식).

### ② 사용자가 푼다

- 코드 문제: 지정한 파일(예: `index.html`)에 작성
- 개념·코드 읽기·설명 문제: `답안.md`에 번호를 붙여 작성
- 푸는 중에 질문하면 답한다. 단 **문제의 답을 직접 알려주지 않는다.** 질문은 질문 노트에 기록한다 (`../CLAUDE.md` 5장).

### ③ 채점 — "채점해줘", "다 했어"

1. 연습 폴더의 파일을 읽는다. 사용자 파일은 고치지 않는다.
2. 문제별로 채점한다 (4장).
3. 결과를 대화창에 보여준다: 문제별 결과 표 → 문제별 피드백 → 총평.
   - **1차 결과는 바로 `채점.md`에 적는다.** 재제출하면 사용자가 같은 파일을 고치므로, 첫 제출 답을 남겨야 수준을 판정할 수 있다.
   - 재제출이 끝나기 전에는 `채점.md`에 정답을 적지 않는다. 내 답과 결과(✅🔺❌)만 적고, 정답은 마무리할 때 채운다.
4. 🔺·❌ 문제는 정답을 바로 주지 않고 **힌트를 주고 다시 고칠 기회**를 준다. 사용자가 고쳐서 "다시 채점"하면 고친 문제만 다시 본다.
   - 재제출은 **2번까지**(3차 제출까지). 힌트를 이해하지 못하면 다른 예시로 개념을 설명하고 한 번 더 기회를 준다.
   - 그래도 틀리면 정답을 보여주고 복습 대기열에 넣는다. "답 알려줘"라고 하면 바로 보여준다.

### ④ 마무리 — 재채점까지 끝났거나 "끝", "그만"

1. 연습 폴더에 `채점.md`를 쓴다 (5장 양식).
2. `../실력점검.md`를 갱신한다: 항목 수준·마지막 점검·메모, 복습 대기열, 점검 이력 맨 위 한 줄, 요약표, 현재 진도.
3. 다음 연습 때 볼 것을 한 줄로 알려준다. 진도 기준을 채웠으면 다음 회차로 넘어가자고 제안한다.
4. 복습 날짜를 정했으면 캘린더 등록을 제안한다. 묻지 않고 등록하지 않는다.
5. "GitHub에 올릴까요?"라고 묻고, 동의하면 `../CLAUDE.md` 9장대로 커밋·push한다.

## 3. 대화창에 보여줄 양식

### 3-1. 개념 정리

```markdown
## 📖 개념 정리 — 01. HTML (2회차)

오늘 볼 개념 n개: (한 줄씩)

### 1. 개념 이름
- 한 줄 핵심
- 쉬운 비유 (있으면)
- 강의 예제 코드 + 화면에 어떻게 보이는지
- 고를 때 기준 / 흔한 실수

### 🔁 복습 포인트
복습 대기열 항목을 한두 줄씩 다시 짚는다.

궁금한 게 있으면 물어보세요. 준비되면 **"문제 주세요"**.
```

- **처음 배우는 사람 기준으로 쓴다.** 강의는 들었지만 자세히 다루지 않았다. 용어를 처음 쓸 때는 뜻부터 풀어 준다.
- 개념마다 이 순서로 설명한다: **무엇인지** → **왜 필요한지** → **어떻게 쓰는지 (최소 코드)** → **화면에 어떻게 보이는지** → **흔한 실수**.
- 다룰 **주제**는 해당 wiki(강의 범위) 안에서 고른다. 설명은 강의 문장보다 자세해도 되고 비유를 써도 된다. 단 강의 범위 밖 문법을 새로 끌어오지 않는다.
- 한 번에 너무 많으면 이해가 안 된다. 개념 3~5개로 나누고, 길어지면 "1부 → 질문 → 2부"처럼 나눠서 보여준다.
- 사용자가 전에 쓴 코드(이전 연습 폴더)에서 예를 찾을 수 있으면 활용한다.
- 문제에 그대로 나올 답을 미리 말하지 않는다. 개념과 고르는 기준까지만 설명한다.

### 3-2. 오늘의 연습

```markdown
## 📝 오늘의 연습 — 01. HTML (1회차)

- **범위**: 문서 기본 구조, 제목·문단, 목록 (점검 항목 3·4·5) + 복습 1문제
- **연습 폴더**: `practice/01_React과정/01_HTML/2026-11-09/`
- **만들 파일**: `답안.md`, `index.html`
- **참고**: 먼저 wiki를 보지 말고 풀어 보세요. 막혀서 wiki나 검색을 봤으면 채점 요청할 때 알려주세요.

| # | 유형 | 내용 | 제출 | 점검 항목 |
|---|---|---|---|---|
| 1 | 개념 | … | 답안.md | 3 |
| 2 | 코드 읽기 | … | 답안.md | 4 |
| 3 | 코드 작성 | … | index.html | 3·4·5 |

### 문제 1 (개념)
질문

### 문제 3 (코드 작성)
요구사항 목록 (체크리스트로)
채점 기준: 무엇을 보고 채점하는지

다 풀었으면 **"채점해줘"** 라고 말해주세요.
```

문제 구성:
- 한 번에 **4~6문제**. 개념 1~2 → 코드 읽기·버그 찾기 1 → 코드 작성 1~2 순서로 쉬운 것부터. 그중 1~2개는 앞 회차 복습 문제(🔁)다.
- **설명하기 문제를 매번 1개 이상** 넣는다 (말로 설명하기가 약점, 수준 4 판정용).
- 문제는 **배운 범위 안에서만** 낸다 (현재 진도 회차까지의 wiki). 안 배운 문법은 쓰지 않는다.
- wiki의 확인 문제와 미션을 재료로 쓰되, 그대로 내지 말고 바꿔서 낸다.
- 코드 작성 문제는 요구사항을 체크리스트로, 채점 기준을 미리 보여준다.
- 문제 유형:

| 유형 | 방식 | 확인하는 것 |
|---|---|---|
| 개념 | 단답·객관식·O/X | 용어와 역할을 아는지 |
| 설명하기 | "○○를 내 말로 설명" | 이해했는지 (수준 4 판정용) |
| 코드 읽기 | 코드를 보고 화면·결과 예측 | 코드가 어떻게 동작하는지 |
| 버그 찾기 | 틀린 코드를 주고 고치기 | 흔한 실수를 알아보는지 |
| 코드 작성 | 요구사항대로 파일 작성 | 혼자 만들 수 있는지 (수준 3 판정용) |
| AI 코드 읽기 | AI가 고친 코드를 주고 무엇이 바뀌었는지·문제는 없는지 설명 | 남이 짠 코드를 파악하는지 |

- **대화형 퀴즈**: 사용자가 "말로 하자"라고 하거나 휴대폰(Remote Control)으로 하는 중이면 파일 없이 대화창에서 한 문제씩 낸다. 채점·기록은 같다 (`채점.md`에 문제와 답도 함께 적는다).

## 4. 채점 기준

문제별 결과:

| 표시 | 뜻 |
|---|---|
| ✅ | 정답. 요구사항을 모두 채움 |
| 🔺 | 부분 정답. 핵심은 맞았지만 빠진 요구사항이나 작은 실수가 있음 |
| ❌ | 오답이거나 핵심 요구사항을 못 채움 |

- 코드 문제는 요구사항 체크리스트를 하나씩 확인하고, 줄 번호를 들어 피드백한다.
- 동작은 맞지만 강의에서 배운 방식과 다르면 ✅로 주고, 강의 방식을 알려준다.
- 칭찬과 지적은 구체적으로 한다. "잘했어요" 대신 무엇이 좋았는지 말한다.
- 힌트는 단계적으로 준다: ① 관련 개념과 wiki 위치 → ② 코드의 어디를 보면 되는지 → ③ 거의 답에 가까운 힌트.

수준 판정 (`../실력점검.md`에 기록):

| 수준 | 뜻 | 판정 근거 |
|---|---|---|
| - | 아직 점검 안 함 | |
| 0 | 모름 | 틀렸고 힌트를 들어도 모름 |
| 1 | 들어봄 | 힌트를 듣고 고쳐서 맞힘 / 용어는 알지만 역할을 설명 못 함 |
| 2 | 보고 따라함 | 개념·코드 읽기는 맞힘. 코드 작성은 wiki를 보고 함 |
| 3 | 혼자 작성 | wiki·힌트 없이 코드 작성·버그 찾기를 첫 제출에 맞힘 |
| 4 | 설명 가능 | 3에 더해, 왜 그렇게 동작하는지 내 말로 설명 |

- 첫 제출 결과를 기준으로 판정한다. 재제출로 맞힌 문제는 최대 2.
- 한 번의 연습에서 한 항목은 최대 2단계까지 올린다. 처음 점검하는 항목(`-`)은 이 제한 없이 판정한다.
- 전에 3 이상이던 항목을 틀리면 한 단계 내리고 복습 대기열에 넣는다.
- 판정이 애매하면 낮은 쪽으로 기록하고 메모에 이유를 적는다.

| HTML·CSS·JavaScript (01~03회차) | 연습 폴더에 `index.html`(+ `style.css`, `script.js`)을 만들고 `open index.html`로 브라우저에서 연다 |
| React (04회차~) | `practice/01_React과정/_react연습장/` Vite 프로젝트 하나를 계속 쓴다. 처음 필요할 때 사용자와 함께 만든다 (wiki 04_React시작 방식). 문제는 `src/` 안에서 풀고, 채점 뒤 Claude가 푼 파일을 그날 연습 폴더에 복사해 기록으로 남긴다 |
| (새 과정) | 과정이 시작되면 여기에 한 줄 추가한다 (예: Java — `_java연습장/` IntelliJ 프로젝트) |

- `node_modules`는 연습장 프로젝트에만 둔다. 날짜 폴더에는 만들지 않는다.
