# 개념 정리 — 데이터베이스과정 06. Spring과 MyBatis — 작성한 SQL을 서비스에서 실행하기

> 날짜: 2026-11-24 · wiki: [06_Spring-MyBatis](../../../../wiki/06_데이터베이스과정/06_Spring-MyBatis.md)
> 단계별 설명문으로 쓰고, 단계 끝마다 직접 해 보는 예시를 둔다. 쉬운 말, 비유 없이. 코드는 start.spring.io에서 받은 프로젝트(Spring Boot 4.0.10 + MyBatis Starter 4.0.1, JDK 21)를 05회차까지 마친 MySQL 8.4.13 `school` DB에 연결해 실행하고, `curl`과 Node로 강의의 `fetch` 코드를 보내 응답·서버 로그를 확인했다 (확인할 때만 다른 포트를 썼고, 노트에는 8080·3306으로 적었다).

## 들어가며

**🧭 맥락 — 지금 어디쯤**

01~05에서는 DBeaver에 SQL을 직접 쳐서 실행했어요. 그런데 실제 서비스에서는 사용자가 "학생 목록" 버튼을 누를 때마다 누군가 DBeaver를 열 수 없어요. 요청을 받은 **백엔드가 SQL을 실행**해야 해요.

앞 과정에서 이 흐름의 조각들을 이미 봤어요. Node 03에서는 학생 배열을 JSON으로 돌려주는 API를 만들었고, Spring 06에서는 같은 API를 `@RestController`로 만들어 React가 `fetch`로 받아 갔어요. Spring 05에서는 JPA로 H2에 저장했는데, `save()`·`findAll()`만 부르고 SQL은 직접 쓰지 않았어요.

오늘은 Spring API가 **우리가 직접 쓴 SQL**을 MySQL `school` DB에 실행하게 만들어요. 그 연결을 해 주는 도구가 **MyBatis**예요. 요청 하나가 이렇게 흘러가요.

```text
HTTP 요청 (GET /students/1)
   ↓
StudentController.findById(1)        ← 5단계
   ↓
StudentMapper.findById(1)            ← 3단계 (Java 인터페이스)
   ↓
StudentMapper.xml의 id="findById" SQL ← 4단계
   ↓
MySQL school DB                      ← 01~05에서 만든 그대로
   ↓
Student 객체 → JSON 응답
```

파이썬에서 `sqlite3`나 `pymysql`을 써 봤다면 `cursor.execute("SELECT ... WHERE id = %s", (1,))`처럼 SQL 문자열에 자리표시를 두고 값을 따로 넘겼을 거예요. MyBatis도 같은 일을 해요. 다른 점은 SQL을 Java 코드 안이 아니라 XML 파일에 모아 두고, Java 메서드 이름으로 불러 쓴다는 거예요.

수업에서 나온 질문 두 개도 여기서 풀어요. Mapper XML의 `<delete>`가 무엇인지는 4단계, Controller가 React 컴포넌트 같은 것인지는 5단계에서 설명해요.

**강의와 버전이 달라요.** 강의 예제는 Spring Boot 3.5.x + MyBatis Starter 3.0.5예요. 지금 start.spring.io는 Spring Boot 4.x만 주고, 그중 MyBatis를 고를 수 있는 건 4.0.x뿐이에요. 그래서 이 노트는 **4.0.10 + MyBatis Starter 4.0.1**로 만들어요. Java 코드와 XML은 강의와 한 글자도 다르지 않아요. 다른 건 `build.gradle`의 줄 몇 개(1단계)와 JSON 속성 순서(5단계)뿐이에요.

오늘 API가 읽고 바꾸는 데이터는 05 개념정리 마무리의 표(학생 1·2·3·4·6번, 반 번호 1·1·2·NULL·1) 그대로예요.

## 1단계: `build.gradle` — 무엇을 넣었고, 왜 강의와 버전이 다른가

🧭 Spring 02에서 Spring Web을 골랐을 때처럼, Initializr에서 고른 의존성(가져다 쓰는 라이브러리)이 `build.gradle`의 줄이 돼요.

`dependencies`의 세 줄이 오늘의 재료예요. `spring-boot-starter-webmvc`는 **Spring Web**이에요. 요청을 받고 JSON으로 응답하는 기능이 들어 있어요. 강의와 인터넷 예제의 `spring-boot-starter-web`은 Spring Boot 3까지의 이름이에요. `mybatis-spring-boot-starter`는 MyBatis와, MyBatis를 Spring에 연결해 주는 설정을 한꺼번에 가져와요. `mysql-connector-j`는 **JDBC 드라이버**예요. Java 프로그램이 MySQL과 통신할 때 쓰는 라이브러리로, 01에서 DBeaver가 연결할 때 내려받은 드라이버와 같은 역할이에요.

MyBatis Starter는 **Spring Boot 버전에 맞는 것**을 써야 해요. Spring Boot 3.2~3.5에는 Starter 3.0.x, Spring Boot 4에는 Starter 4.0.x예요. 강의는 3.5 + 3.0.5였고, 우리는 4.0.10이라 Initializr가 4.0.1을 골라 줬어요. 강의의 `3.0.5`를 이 프로젝트에 그대로 쓰면, 5단계까지 다 만든 뒤 서버가 켜지지 않아요 (7단계 바꿔 보기). 강의의 `runtimeOnly 'com.h2database:h2'` 줄은 H2를 쓸 사람을 위한 거라 MySQL만 쓰는 우리는 넣지 않아요. Spring Data JPA도 넣지 않아요. SQL은 MyBatis로 직접 써요.

### ▶ 직접 해 보기 — 받은 `build.gradle` 확인하고 바로 실행해 보기
Initializr가 만든 `build.gradle`은 고치지 않아요. 맨 위 `plugins`에 `id 'org.springframework.boot' version '4.0.10'`, `toolchain`에 `JavaLanguageVersion.of(21)`이 있는지 보고, `dependencies`가 이렇게 생겼는지 확인해요. `test`로 시작하는 줄은 테스트용이라 오늘은 안 써요.
```groovy
dependencies {
	implementation 'org.springframework.boot:spring-boot-starter-webmvc'
	implementation 'org.mybatis.spring.boot:mybatis-spring-boot-starter:4.0.1'
	runtimeOnly 'com.mysql:mysql-connector-j'
	testImplementation 'org.springframework.boot:spring-boot-starter-webmvc-test'
	testImplementation 'org.mybatis.spring.boot:mybatis-spring-boot-starter-test:4.0.1'
	testRuntimeOnly 'org.junit.platform:junit-platform-launcher'
}
```
아무것도 안 만든 채로 ▶를 눌러 봐요. 서버가 켜지지 않고 이렇게 끝나요.
```text
***************************
APPLICATION FAILED TO START
***************************

Description:

Failed to configure a DataSource: 'url' attribute is not specified and no embedded datasource could be configured.

Reason: Failed to determine a suitable driver class
```
MyBatis Starter를 넣으면 Spring Boot가 DB 연결을 준비하려고 하는데, 어느 DB에 접속할지(`url`)를 아직 안 알려 줬기 때문이에요. 2단계에서 알려 줘요.

## 2단계: `application.properties` — 어느 DB에 어떻게 접속할지

🧭 01에서 DBeaver에 입력한 Host·Port·Username·Password를 이번에는 Spring에게 알려 줘요.

`spring.datasource.url=jdbc:mysql://localhost:3306/school`은 "내 컴퓨터(`localhost`)의 3306 포트 MySQL, 그 안의 `school` DB"라는 뜻이에요. DBeaver 연결 창의 Host·Port·Database를 한 줄로 쓴 거예요. `username`은 `root`예요.

비밀번호 줄은 `spring.datasource.password=${DB_PASSWORD}`예요. `${DB_PASSWORD}`는 "환경변수 `DB_PASSWORD`의 값을 넣어라"는 뜻이에요. **환경변수**는 프로그램을 실행할 때 밖에서 넘겨주는 `이름=값`이에요. 이 파일은 GitHub 공개 저장소에 올라가니까 비밀번호를 직접 쓰면 안 돼요. 그래서 IntelliJ 실행 설정에만 넣어요. **Run → Edit Configurations…** → 왼쪽에서 `StudentMybatisApplication` → **Environment variables** 칸에 `DB_PASSWORD=01에서 정한 root 비밀번호`를 넣고 OK. 칸이 안 보이면 **Modify options → Environment variables**를 켜요. 실행 설정은 ▶를 한 번 누르면 생겨요.

아래 두 줄은 MyBatis 설정이에요. `mybatis.mapper-locations=classpath:/mappers/*.xml`은 "SQL을 쓴 XML 파일은 `resources/mappers/` 안에 있다"는 뜻이에요. `classpath`는 빌드된 프로그램 안에서 `resources` 폴더 자리를 가리켜요. `map-underscore-to-camel-case=true`는 DB 열 이름 `registered_date`를 Java 속성 이름 `registeredDate`에 맞춰 주는 설정이에요. DB는 밑줄로, Java는 대문자로 단어를 구분하니까 이게 없으면 값이 안 들어가요 (5단계 바꿔 보기).

Spring은 서버를 켤 때 DB에 바로 접속하지 않아요. **첫 SQL을 실행할 때** 접속해요. 그래서 비밀번호가 틀려도 이 단계에서는 서버가 켜져요. 그리고 MyBatis는 테이블을 만들지 않아요. 02·05에서 만든 `students`·`classes`가 있어야 해요.

### ▶ 직접 해 보기 — 설정 넣고 서버 켜기
`src/main/resources/application.properties` 전체를 이렇게 바꾸고, 실행 설정에 `DB_PASSWORD`를 넣은 뒤 ▶.
```properties
spring.application.name=student-mybatis

spring.datasource.url=jdbc:mysql://localhost:3306/school
spring.datasource.username=root
spring.datasource.password=${DB_PASSWORD}
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver

mybatis.mapper-locations=classpath:/mappers/*.xml
mybatis.configuration.map-underscore-to-camel-case=true
```
Run 창에 이런 줄이 보이면 켜진 거예요 (줄 앞의 날짜·번호는 뺐어요).
```text
 :: Spring Boot ::               (v4.0.10)
WARN  o.m.s.mapper.ClassPathMapperScanner : No MyBatis mapper was found in '[com.hancoding.studentmybatis]' package. Please check your configuration.
INFO  o.s.boot.tomcat.TomcatWebServer     : Tomcat started on port 8080 (http) with context path '/'
INFO  c.h.s.StudentMybatisApplication     : Started StudentMybatisApplication in 0.761 seconds
```
`WARN` 줄은 "Mapper를 하나도 못 찾았다"는 안내예요. 아직 안 만들었으니 맞아요. 3단계에서 사라져요.

**바꿔 보기**: 실행 설정의 `DB_PASSWORD`를 지우고 다시 켜도 똑같이 켜져요. 아직 DB에 접속한 적이 없어서예요. 이 상태로 요청을 보내면 무슨 일이 생기는지는 7단계에서 봐요. 확인했으면 다시 넣어 둬요.

## 3단계: `Student` 클래스와 `StudentMapper` 인터페이스 — Java 쪽 준비

🧭 Spring 01에서 만든 `Student`처럼 필드·getter·setter가 있는 클래스예요. 이번에는 DB 한 행을 담아요.

**`Student`**는 `students` 테이블의 **한 행 = 객체 하나**예요. 열마다 필드가 하나씩 있어요. `id`·`classId`는 `int`가 아니라 **`Integer`**예요. 박스프링부트처럼 `class_id`가 `NULL`인 학생이 있는데, `int`는 `null`을 담을 수 없어요. `registeredDate`는 `LocalDate`예요. 시각 없이 연·월·일만 있는 Java 타입이라 DB의 `DATE`와 맞아요. 생성자를 따로 만들지 않아서 Java가 빈 생성자를 자동으로 만들어 줘요 (Spring 01 4단계). MyBatis는 이 빈 생성자로 객체를 만든 뒤 setter로 값을 넣어요. JPA를 안 쓰니 `@Entity`는 붙이지 않아요.

**`StudentMapper`**는 **인터페이스**예요. 메서드 이름·받는 값·돌려주는 값만 적고, 몸통(`{ }`)은 없어요. "이런 DB 작업이 있다"는 목록이에요. 실제로 실행할 SQL은 4단계의 XML에 써요. 파이썬의 추상 메서드처럼 모양만 정해 둔 거예요.

`@Mapper`는 "MyBatis가 SQL과 연결할 인터페이스"라는 표시예요. 서버가 켜질 때 MyBatis가 이 표시를 보고, 인터페이스를 실제로 동작하게 하는 객체를 만들어 Spring에 맡겨요. 그래서 우리는 구현 클래스를 만들지 않아요. `@Param("id")`는 넘겨받은 값을 SQL에서 `id`라는 이름으로 부르겠다는 뜻이에요. XML의 `#{id}`와 이름이 같아야 해요.

돌려주는 타입도 의미가 있어요. `findAll()`은 여러 행이라 `List<Student>`, `findById()`는 한 행이라 `Student`(없으면 `null`)예요. `insert`·`update`·`deleteById`는 `int`인데, 04에서 본 "몇 행이 바뀌었나"(`1 row affected`)를 숫자로 받는 거예요.

### ▶ 직접 해 보기 — 두 파일 만들기

## 4단계: Mapper XML — SQL을 메서드에 연결한다 (`<delete>`는 무엇인가)

🧭 01~05에서 DBeaver에 친 SQL을 이 파일로 옮겨요. 3단계의 메서드 이름표를 SQL에 붙이는 단계예요.

`src/main/resources`에 `mappers` 폴더를 만들고 그 안에 `StudentMapper.xml`을 만들어요. 2단계 `mapper-locations`가 가리키는 자리예요. 맨 위 `<?xml ...?>`과 `<!DOCTYPE mapper ...>` 두 덩어리는 "이 파일은 MyBatis Mapper 형식"이라는 선언이라 그대로 복사해요.

**`<mapper namespace="...">`** — 이 XML이 어느 인터페이스의 SQL인지 적어요. **패키지까지 포함한 전체 이름** `com.hancoding.studentmybatis.StudentMapper`를 써요.

**`<select>`·`<insert>`·`<update>`·`<delete>`** — 수업 질문이었던 `<delete>`가 여기 있어요. HTML 태그가 아니라 **MyBatis Mapper XML의 태그**예요. 안에 든 SQL의 종류에 맞춰 넷 중 하나를 골라요. MyBatis는 이 태그를 보고 SQL을 어떻게 실행하고 무엇을 돌려줄지 정해요. `<select>`는 결과 행을 받아서 `resultType` 객체로 만들어 돌려주고, `<insert>`·`<update>`·`<delete>`는 바뀐 행 수를 `int`로 돌려줘요. 그래서 `deleteById`는 `<delete>` 안에 `DELETE FROM students WHERE id = #{id}`를 쓰고, 지운 행 수(1 또는 0)를 돌려줘요. 태그를 잘못 고르면 어떻게 되는지는 7단계에서 봐요.

**`id="..."`** — 3단계 인터페이스의 **메서드 이름과 똑같이** 써요. MyBatis는 `namespace` + `.` + `id`, 예를 들어 `com.hancoding.studentmybatis.StudentMapper.deleteById`라는 이름으로 SQL을 찾아요. `studentMapper.deleteById(8)`을 부르면 이 이름의 SQL이 실행돼요. 하나라도 다르면 `Invalid bound statement (not found)` 오류가 나요 (7단계).

**`resultType`** — `<select>`에만 써요. 결과 **한 행**을 담을 클래스예요. `findAll()`이 `List<Student>`를 돌려줘도 여기에는 `List`가 아니라 `Student`를 써요. MyBatis가 행마다 `Student`를 만들어 목록으로 묶어 줘요.

**`#{...}`** — 값이 들어갈 자리예요. `#{id}`는 `@Param("id")`로 받은 값, `#{name}`·`#{email}`처럼 `Student`를 받은 메서드에서는 그 객체의 속성(`getName()`, `getEmail()`) 값이 들어가요. MyBatis는 `#{...}`를 SQL 안에서 `?`로 바꾸고 값을 따로 보내요. 그래서 문자열이어도 **따옴표를 붙이지 않아요.** 6단계 바꿔 보기에서 서버 로그에 `VALUES ( ?, ?, ?, ? )`로 찍힌 SQL을 직접 볼 수 있어요. `${...}`는 값을 SQL 글자에 그대로 이어 붙이는 다른 문법이라, 사용자가 보낸 값을 넣으면 SQL을 끼워 넣는 공격(SQL 인젝션)에 열려요. 값은 늘 `#{...}`로 넘겨요. SQL의 열 자리에는 DB 열 이름(`registered_date`), `#{}` 안에는 Java 속성 이름(`registeredDate`)을 쓰는 것도 구분해요.

**`useGeneratedKeys="true" keyProperty="id" keyColumn="id"`** — `<insert>`에 붙어 있어요. 학생을 넣으면 MySQL이 `AUTO_INCREMENT`로 새 번호를 정하는데, 그 번호를 넘겨준 `Student` 객체의 `id`에 다시 넣어 줘요. 그래서 5단계 Controller가 `student.getId()`로 새 번호를 알 수 있어요. XML 안 SQL 끝에는 `;`을 쓰지 않아요.

### ▶ 직접 해 보기 — `resources/mappers/StudentMapper.xml`
```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper
    PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
    "https://mybatis.org/dtd/mybatis-3-mapper.dtd">

<mapper namespace="com.hancoding.studentmybatis.StudentMapper">

    <select id="findAll"
            resultType="com.hancoding.studentmybatis.Student">
        SELECT
            id,
            name,
            email,
            registered_date,
            class_id
        FROM students
        ORDER BY id ASC
    </select>

    <select id="findById"
            resultType="com.hancoding.studentmybatis.Student">
        SELECT
            id,
            name,
            email,
            registered_date,
            class_id
        FROM students
        WHERE id = #{id}
    </select>

    <insert id="insert"
            useGeneratedKeys="true"
            keyProperty="id"
            keyColumn="id">
        INSERT INTO students (
            name,
            email,
            registered_date,
            class_id
        )
        VALUES (
            #{name},
            #{email},
            #{registeredDate},
            #{classId}
        )
    </insert>

    <update id="update">
        UPDATE students
        SET name = #{name},
            email = #{email},
            registered_date = #{registeredDate},
            class_id = #{classId}
        WHERE id = #{id}
    </update>

    <delete id="deleteById">
        DELETE FROM students
        WHERE id = #{id}
    </delete>

</mapper>
```
서버를 다시 켜면 아무 경고 없이 `Started StudentMybatisApplication`이 나와요. XML은 서버가 켜질 때 읽어요.

**바꿔 보기**: 맨 아래 `</delete>` 줄을 지우고 다시 켜면 서버가 켜지지 않아요. Run 창 아래쪽 `Caused by:` 줄에 이렇게 나와요. 되돌리고 다시 켜요.
```text
Caused by: java.io.IOException: Failed to parse mapping resource: 'class path resource [mappers/StudentMapper.xml]'
Caused by: org.xml.sax.SAXParseException; lineNumber: 64; columnNumber: 3; 요소 유형 "delete"은(는) 짝이 맞는 종료 태그 "</delete>"(으)로 종료되어야 합니다.
```
`lineNumber`가 XML에서 문제를 발견한 줄이에요. 태그를 열었으면 같은 이름으로 닫아요.

## 5단계: Controller — 주소와 Mapper를 잇는다 (React 컴포넌트와 무엇이 다른가)

🧭 Spring 06에서 만든 `@RestController`예요. 그때는 Java 목록을 돌려줬고, 이번에는 Mapper가 DB에서 읽은 목록을 돌려줘요.

**Controller가 하는 일**은 세 가지예요. 어떤 주소·방식(GET, POST …)의 요청을 어떤 메서드가 맡을지 정하고, 요청에서 값을 꺼내고(`@PathVariable`로 주소의 `{id}`, `@RequestBody`로 본문의 JSON), Mapper를 불러 결과를 받은 뒤 상태 코드와 본문을 정해 응답해요. `@RestController`라서 돌려준 객체는 JSON으로 바뀌어 나가요. `@RequestMapping("/students")`는 이 클래스의 모든 주소 앞에 `/students`를 붙여요.

**React 컴포넌트와는 하는 일이 달라요.** React 컴포넌트는 **브라우저**에서 실행되는 함수로, 화면의 한 부분(JSX)을 그려요. state가 바뀌면 React가 다시 불러 화면을 새로 그려요. Controller는 **서버**에서 실행되는 Java 클래스로, 화면을 그리지 않아요. 요청이 오면 Spring이 맞는 메서드를 불러 주고, 그 메서드는 데이터(JSON)와 상태 코드를 돌려줘요. 둘은 서로 반대편에서 만나요. React 컴포넌트가 `fetch("/students")`로 요청을 **보내는 쪽**이고, Controller의 `findAll()`이 그 요청을 **받아 답하는 쪽**이에요. 둘 다 "직접 부르지 않고 프레임워크가 불러 준다"는 점은 같아서 비슷해 보일 수 있어요. 비슷한 질문과 답이 [08 SSR-CSR 02 wiki 질문 노트](../../../../wiki/08_SSR-CSR과정/02_JSP-SSR화면.md)에도 있어요.

Mapper는 **생성자로 받아요.** `StudentMapper`는 인터페이스라 `new StudentMapper()`를 할 수 없어요. 3단계에서 MyBatis가 만들어 Spring에 맡긴 객체를, Spring이 Controller를 만들 때 생성자로 넣어 줘요.

응답은 `ResponseEntity`로 상태 코드를 골라요. 찾으면 `ok(student)`(200), 없으면 `notFound()`(404), 추가하면 `created(주소).body(student)`(201 + `Location` 헤더), 수정·삭제가 되면 `noContent()`(204, 본문 없음)예요. 수정·삭제는 Mapper가 돌려준 행 수가 0이면 404로 판단해요. 04의 `0 rows affected`를 여기서 써요.

응답 JSON의 속성 순서가 강의 화면과 달라요. 강의(Spring Boot 3.5)는 `id`, `name`, … 필드 순서였는데, Spring Boot 4가 쓰는 JSON 라이브러리(Jackson 3)는 이름을 알파벳 순서로 내보내서 `classId`, `email`, `id`, `name`, `registeredDate` 순서가 돼요. 이름과 값은 같아요. JSON 객체는 순서로 값을 찾지 않으니 `fetch`로 받아 쓰는 데는 차이가 없어요.

### ▶ 직접 해 보기 — `StudentController.java`, 그리고 GET 확인
```java
package com.hancoding.studentmybatis;

import java.net.URI;
import java.util.List;

import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.DeleteMapping;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.PutMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/students")
public class StudentController {

    private final StudentMapper studentMapper;

    public StudentController(StudentMapper studentMapper) {
        this.studentMapper = studentMapper;
    }

    @GetMapping
    public List<Student> findAll() {
        return studentMapper.findAll();
    }

    @GetMapping("/{id}")
    public ResponseEntity<Student> findById(
            @PathVariable("id") Integer id) {

        Student student = studentMapper.findById(id);

        if (student == null) {
            return ResponseEntity.notFound().build();
        }

        return ResponseEntity.ok(student);
    }

    @PostMapping
    public ResponseEntity<Student> insert(
            @RequestBody Student student) {

        studentMapper.insert(student);

        URI location = URI.create("/students/" + student.getId());

        return ResponseEntity.created(location).body(student);
    }

    @PutMapping("/{id}")
    public ResponseEntity<Void> update(
            @PathVariable("id") Integer id,
            @RequestBody Student student) {

        student.setId(id);

        int updatedRows = studentMapper.update(student);

        if (updatedRows == 0) {
            return ResponseEntity.notFound().build();
        }

        return ResponseEntity.noContent().build();
    }

    @DeleteMapping("/{id}")
    public ResponseEntity<Void> deleteById(
            @PathVariable("id") Integer id) {

        int deletedRows = studentMapper.deleteById(id);

        if (deletedRows == 0) {
            return ResponseEntity.notFound().build();
        }

        return ResponseEntity.noContent().build();
    }
}
```
서버를 다시 켜고 브라우저 주소창에 `http://localhost:8080/students`를 열면 JSON 글자가 그대로 보여요. 이때 Run 창에 `HikariPool-1 - Starting...` → `HikariPool-1 - Start completed.`가 찍혀요. 첫 SQL을 실행하려고 이제야 DB에 접속한 거예요.
```text
[{"classId":1,"email":"hancoding@example.com","id":1,"name":"한코딩","registeredDate":"2026-11-16"},{"classId":1,"email":"java@example.com","id":2,"name":"김자바개발자","registeredDate":"2026-11-17"},{"classId":2,"email":"react@example.com","id":3,"name":"이리액트","registeredDate":"2026-11-18"},{"classId":null,"email":"spring@example.com","id":4,"name":"박스프링부트","registeredDate":null},{"classId":1,"email":"data@example.com","id":6,"name":"정데이터","registeredDate":"2026-11-20"}]
```
DB의 `NULL`은 JSON에서 `null`, `DATE`는 `"2026-11-16"` 글자로 와요. `http://localhost:8080/students/1`은 한 명이에요.
```text
{"classId":1,"email":"hancoding@example.com","id":1,"name":"한코딩","registeredDate":"2026-11-16"}
```
`/students/5`는 5번 학생이 없어서 404예요 (02에서 번호만 쓰고 실패한 그 5번). 브라우저는 "찾을 수 없음" 화면을 보여 주고, 터미널에서 `curl -i http://localhost:8080/students/5`로 보면 상태 줄이 보여요.
```text

Content-Length: 0
```
**바꿔 보기** (하나씩 바꾸고 서버 재시작 → 확인 → 되돌리기)
- `application.properties`에서 `map-underscore-to-camel-case` 줄을 지우기 → `/students/1`이 `{"classId":null,"email":"hancoding@example.com","id":1,"name":"한코딩","registeredDate":null}`. 오류 없이 날짜·반 번호만 `null`이 돼요. `registered_date`라는 속성을 `Student`에서 못 찾아서 그냥 넘어간 거예요.
- `Student.java`의 `Integer classId`(필드·getter·setter 세 곳)를 `int`로 → `/students/4`의 박스프링부트가 `"classId":0`으로 나와요. 반이 없는 학생이 0번 반처럼 보여요. 6단계의 POST처럼 `classId: null`을 보내면 `400`이고 Run 창에 ``JSON parse error: Cannot map `null` into type `int` ``가 찍혀요.

## 6단계: 추가·수정·삭제 — Console의 `fetch`로 보내고 DBeaver로 확인한다

🧭 Spring 06에서 React가 `fetch`로 GET을 보냈어요. 이번에는 POST·PUT·DELETE도 보내요. 주소창은 GET만 보내니까 브라우저 Console에서 `fetch`를 써요.

Chrome에서 `http://localhost:8080/students`를 연 채 **개발자 도구(`Cmd + Option + I`) → Console**에서 실행해요. 지금 페이지와 같은 서버(8080)로 보내니 CORS 설정이 필요 없어요. Node 04에서 React(5173)가 서버(3000)에 보낼 때는 주소가 달라서 CORS가 필요했어요. Console에 처음 붙여 넣을 때 Chrome이 붙여 넣기를 막고 `allow pasting`을 입력하라고 하면, 그대로 입력하고 Enter를 친 뒤 다시 붙여 넣어요.

POST의 본문은 `JSON.stringify`로 만든 JSON 글자예요. `@RequestBody Student student`가 이 JSON을 `Student` 객체로 바꿔요. 속성 이름이 `registeredDate`, `classId`처럼 Java 속성 이름과 같아야 해요. 새 학생은 **8번**이 돼요. 04에서 삭제연습 학생이 7번을 쓰고 지워졌기 때문이에요.

PUT은 강의 XML의 `UPDATE`가 네 열을 모두 `SET`하기 때문에 **모든 항목을 함께** 보내요. 보내지 않은 항목은 `null`로 바뀌는데, `email`처럼 `NOT NULL`인 열이면 오류가 나요. PUT·DELETE의 성공 응답 204는 본문이 없어서 `response.json()`을 부르지 않아요.

API로 바꾼 내용은 바로 확정돼요. Mapper 메서드 하나가 SQL 하나를 실행하고, 04에서 본 자동 커밋으로 끝나요. 확인할 때 DB 연결 하나를 따로 열어 `START TRANSACTION` 중에 API로 학생을 추가하고 그 연결에서 `ROLLBACK`해 봤는데, 추가된 학생은 그대로 남았어요. 트랜잭션은 연결마다 따로라서, DBeaver의 `ROLLBACK`으로 Spring이 한 변경을 취소할 수 없어요.

**바꿔 보기** — 최마이바티스 학생이 있어야 하는 것들이에요. ④까지 끝냈다면 ①로 다시 넣고, 응답에 나온 새 번호로 ③·④의 `8`을 바꿔서 해요 (지운 번호는 다시 쓰이지 않아서 8이 아니에요). 모두 실패하거나 같은 값으로 바꾸는 요청이라 데이터는 그대로예요. 다 하고 나서 ④로 지워요.
- ① 바로 뒤에 ①을 한 번 더 실행 → `상태 코드: 500`, `응답:`에는 `status: 500`, `error: 'Internal Server Error'`, `path: '/students'`만 있어요. 진짜 이유는 Run 창에 있어요. `#{}`가 `?`로 바뀐 SQL도 함께 찍혀요. 이 실패도 번호 하나를 써서, 다음에 추가하는 학생은 번호가 하나 건너뛰어요 (02에서 본 중복 오류와 같아요. 확인할 때 8번 다음 중복 실패 → 다음 추가가 10번이었어요).

  ```text
  ### Error updating database.  Cause: java.sql.SQLIntegrityConstraintViolationException: Duplicate entry 'mybatis-practice@example.com' for key 'students.email'
  ### The error may exist in class path resource [mappers/StudentMapper.xml]
  ### SQL: INSERT INTO students (             name,             email,             registered_date,             class_id         )         VALUES (             ?,             ?,             ?,             ?         )
  ```
- ③의 `.then((response) => { ... })`를 ①처럼 `async`로 바꾸고 `await response.json()`을 넣기 → 상태는 204인데 `SyntaxError: Unexpected end of JSON input`. 본문이 없는 응답을 JSON으로 읽으려 해서예요 (Node로 확인한 문장이에요. Chrome은 `Failed to execute 'json' on 'Response':`가 앞에 붙을 수 있어요).
- ③의 `body`를 `JSON.stringify({ name: "최마이바티스수정" })`만 보내기 → 500. Run 창 `### Cause: java.sql.SQLIntegrityConstraintViolationException: Column 'email' cannot be null`. 보내지 않은 `email`이 `null`이 됐어요.
- ③의 `classId: null`을 `classId: 999`로 → 500. Run 창에 05에서 본 1452 문장이 그대로 와요. 외래키가 API에서도 막아요.

## 7단계: 연결이 끊어졌을 때 — 서버 로그로 원인 찾기

🧭 1~6단계의 파일들은 이름으로 서로를 찾아요. 이름 하나만 어긋나도 끊어지는데, 브라우저에는 늘 똑같이 `500`만 보여요.

브라우저가 받는 500 응답에는 `"error":"Internal Server Error"`뿐이고 이유가 없어요. 이유는 IntelliJ Run 창(서버 로그)에 있어요. 빨간 `ERROR` 줄에서 `Request processing failed:` 뒤를 보고, MyBatis 오류면 `### Cause:` 줄을 봐요. 여러 줄이 쌓여 있으면 맨 아래 `Caused by:`가 가장 처음 원인이에요.

자주 끊어지는 곳은 정해져 있어요. XML의 `namespace`와 인터페이스 이름, SQL `id`와 메서드 이름, `@Param` 이름과 `#{}` 이름, SQL의 열 이름과 DB의 실제 열, 그리고 DB 접속 정보예요. 각각 어떤 문장이 나오는지 실제로 일으켜 봐요. 모두 고친 뒤 서버를 재시작하고 확인한 다음, 되돌리고 다시 재시작해요.

### ▶ 직접 해 보기 — `namespace`에서 패키지 빼기
`StudentMapper.xml`의 `namespace="com.hancoding.studentmybatis.StudentMapper"`를 `namespace="StudentMapper"`로 바꾸고 재시작 → `http://localhost:8080/students`.
```text
{"timestamp":"2026-11-24T06:57:13.946Z","status":500,"error":"Internal Server Error","path":"/students"}
```
서버는 잘 켜졌는데 요청에서 500이에요. Run 창에는 이렇게 나와요.
```text
ERROR ... Request processing failed: org.apache.ibatis.binding.BindingException: Invalid bound statement (not found): com.hancoding.studentmybatis.StudentMapper.findAll] with root cause
```
`not found:` 뒤의 이름이 MyBatis가 찾은 `namespace.id`예요. XML에는 `StudentMapper.findAll`만 있으니 못 찾았어요. 되돌리고 재시작해요.

**바꿔 보기** (하나씩. 바꾸고 재시작 → 확인 → 되돌리고 재시작). DELETE를 보내는 것은 05까지의 학생이 아니라 6단계 ①로 새로 넣은 최마이바티스의 번호로 해요.
- `<delete id="deleteById">`를 `<delete id="delete">`로 → 목록 GET은 200으로 잘 되고, DELETE 요청만 500. `Invalid bound statement (not found): com.hancoding.studentmybatis.StudentMapper.deleteById`. 잘못된 `id`는 그 메서드를 부를 때까지 드러나지 않아요.
- `<delete id="deleteById">`·`</delete>`를 `<select id="deleteById">`·`</select>`로 → DELETE 요청이 500이고 `Mapper method 'com.hancoding.studentmybatis.StudentMapper.deleteById' attempted to return null from a method with a primitive return type (int).` 그런데 DBeaver로 보면 **그 학생은 지워져 있어요.** `<select>`라서 SQL은 실행했지만, 돌아온 결과 행이 없으니 `int`로 돌려줄 값이 없어서 오류가 났어요. 태그는 SQL 종류에 맞춰요. (`<update>`로 감싸면 DELETE도 204로 동작은 해요. 그래도 읽는 사람을 위해 `<delete>`를 써요.)
- `findAll`의 `registered_date,`를 `register_date,`로 → 목록만 500, `/students/1`은 200. Run 창 `BadSqlGrammarException`과 `### Cause: java.sql.SQLSyntaxErrorException: Unknown column 'register_date' in 'field list'`. 05까지 DBeaver에서 본 MySQL 오류 문장이 그대로 와요.
- `StudentMapper.java`의 `@Param("id")`를 `@Param("studentId")`로 → `/students/1`이 500. `### Cause: org.apache.ibatis.binding.BindingException: Parameter 'id' not found. Available parameters are [studentId, param1]`
- 실행 설정에서 `DB_PASSWORD`를 지우고 재시작 → 서버는 켜지고, 첫 요청이 500. `java.sql.SQLException: Access denied for user 'root'@'localhost' (using password: YES)`. 환경변수가 없으면 `${DB_PASSWORD}`라는 글자 자체가 비밀번호로 가요. 그래서 `using password: YES`예요.
- `brew services stop mysql@8.4`로 MySQL을 끄고 요청 → 500. `CannotGetJdbcConnectionException: Failed to obtain JDBC Connection` … `java.net.ConnectException: Connection refused (connect failed)`. `brew services start mysql@8.4`로 다시 켜요.
- `build.gradle`의 `mybatis-spring-boot-starter:4.0.1`을 강의의 `3.0.5`로 바꾸고 Gradle 새로고침 → 서버가 안 켜져요. 3.0.x는 Spring Boot 3용이라 4에서는 Mapper를 준비하지 못해요.
  ```text
  Description:

  Parameter 0 of constructor in com.hancoding.studentmybatis.StudentController required a bean of type 'com.hancoding.studentmybatis.StudentMapper' that could not be found.
  ```

## 마무리: 서버가 켜지고 요청 하나가 처리되기까지

1. ▶를 누르면 Spring Boot가 시작해요. `application.properties`에서 DB 주소·계정을 읽고, 비밀번호 자리에는 실행 설정의 환경변수 `DB_PASSWORD`를 넣어요.
2. MyBatis가 `mappers/*.xml`을 읽어요. XML 문법이 틀리면 여기서 멈춰요 (4단계).
3. MyBatis가 `@Mapper`가 붙은 `StudentMapper`를 찾아 실제로 동작하는 객체를 만들고, XML의 `namespace.id`로 메서드마다 SQL을 짝지어 둬요.
4. Spring이 `StudentController`를 만들면서 3의 Mapper 객체를 생성자로 넣어요. Tomcat이 8080에서 요청을 기다려요. 아직 DB에는 접속하지 않았어요.
5. 브라우저가 `GET /students/1`을 보내면, Spring이 `@RequestMapping("/students")` + `@GetMapping("/{id}")`에 맞는 `findById`를 부르고, `@PathVariable`로 `1`을 넣어요.
6. Controller가 `studentMapper.findById(1)`을 부르면 MyBatis가 `com.hancoding.studentmybatis.StudentMapper.findById` SQL을 찾아, `#{id}`를 `?`로 바꾸고 1을 따로 보내 MySQL에서 실행해요. 첫 요청이면 이때 DB에 접속해요.
7. 돌아온 한 행을 `resultType`의 `Student`로 만들어요. 빈 생성자로 만들고, `registered_date` → `registeredDate`처럼 이름을 맞춰 setter로 넣어요.
8. Controller가 `Student`가 `null`이 아니니 `ResponseEntity.ok(student)`를 돌려주고, Spring이 그 객체를 JSON으로 바꿔 200으로 응답해요.
9. POST·PUT·DELETE도 같은 길을 가요. 다른 점은 `<insert>`·`<update>`·`<delete>`가 바뀐 행 수를 돌려주고, Controller가 그 숫자로 201·204·404를 고른다는 거예요. 변경은 바로 확정돼요.

## 다음 회차와 연결

데이터베이스과정은 여기까지예요. 01에서 만든 `school` DB를 이제 DBeaver와 Spring이 함께 쓰고 있어요.

08 SSR-CSR과정의 강의 코드도 오늘과 같은 방식(MyBatis Mapper + XML + `school` DB)으로 학생을 읽어요. 그 강의 화면은 반 이름(`className`)까지 보여 주는데, 오늘의 `Student`에는 `classId`만 있어요. 반 이름을 받으려면 Mapper XML의 `SELECT`에 05의 `LEFT JOIN classes`를 쓰고, 결과를 담을 클래스에 그 속성을 더해야 해요.

오늘 API는 Mapper 메서드 하나씩 실행해서 각각 바로 확정됐어요. 학생 두 명을 함께 바꾸는 것처럼 여러 SQL을 04의 트랜잭션처럼 하나로 묶어야 할 때는, Controller와 Mapper 사이에 Service 클래스를 두고 Spring의 `@Transactional`로 묶어요. 강의는 이름만 소개했어요.
