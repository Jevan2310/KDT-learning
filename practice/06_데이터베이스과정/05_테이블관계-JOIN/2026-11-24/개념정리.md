# 개념 정리 — 데이터베이스과정 05. 테이블 관계와 JOIN 이해하기

> 날짜: 2026-11-24 · wiki: [05_테이블관계-JOIN](../../../../wiki/06_데이터베이스과정/05_테이블관계-JOIN.md)
> 단계별 설명문으로 쓰고, 단계 끝마다 직접 해 보는 예시를 둔다. 쉬운 말, 비유 없이. SQL과 출력·오류 문장은 MySQL 8.4.13에 04회차를 마친 `school` DB를 만들어 놓고 터미널 `mysql`로 미리 실행해 확인했다 (DBeaver 화면은 설명만 했다).

## 들어가며

**🧭 맥락 — 지금 어디쯤**

02에서 `students` 테이블 하나를 만들었고, 03에서 조회, 04에서 수정·삭제와 트랜잭션을 했어요. 지금까지는 테이블이 하나뿐이었어요.

05에서는 학생마다 **소속 반**을 저장해요. 가장 쉬운 방법은 `students`에 반 이름 열을 하나 더 만드는 건데, 그러면 같은 반 이름이 여러 행에 반복돼요. 그래서 반은 `classes`라는 테이블로 따로 만들고, 학생에게는 반 **번호**만 저장해요. 01 개념정리에서 본 그림의 `classes` 테이블이 오늘 생겨요.

```text
MySQL
└─ school 데이터베이스
   ├─ students 테이블   (02)  ← 오늘 class_id 열이 더해져요
   └─ classes 테이블    (05)  ← 오늘 만들어요
```

테이블을 나누면 새 문제가 생겨요. 학생 테이블에는 반 번호만 있으니, "한코딩 — 풀스택 A반"처럼 이름을 같이 보려면 두 테이블을 연결해서 조회해야 해요. 이게 **`JOIN`**이에요. 파이썬이라면 학생 리스트를 돌면서, 반 리스트에서 `class_id`가 같은 반을 찾는 이중 `for`문을 썼을 거예요. `JOIN`은 그 연결을 DB가 한 문장으로 해 줘요. 마지막에는 `COUNT`와 `GROUP BY`로 반별 학생 수를 세요.

06에서 Spring이 읽는 `Student`에는 `classId`(반 번호)가 들어 있어요. 오늘 만드는 `class_id` 열이 그거예요.

04를 마친 지금 `students` 테이블은 이래요.

| id | name | email | registered_date |
|---|---|---|---|
| 1 | 한코딩 | hancoding@example.com | 2026-11-16 |
| 2 | 김자바개발자 | java@example.com | 2026-11-17 |
| 3 | 이리액트 | react@example.com | 2026-11-18 |
| 4 | 박스프링부트 | spring@example.com | NULL |
| 6 | 정데이터 | data@example.com | 2026-11-20 |

## 🛠 시작하기 — 오늘은 구조를 바꾸는 날

1. MySQL이 켜져 있는지(`brew services list`) 보고, DBeaver에서 SQL 편집기를 열어 `USE school;` → `SELECT DATABASE();`가 `school`인지 확인해요.
2. 04에서 `START TRANSACTION;`을 하고 `COMMIT`이나 `ROLLBACK`을 안 한 채 끝냈다면, 먼저 둘 중 하나로 마무리해요. 오늘 실행하는 `CREATE TABLE`·`ALTER TABLE`은 구조를 바꾸는 문장이라, 열려 있던 트랜잭션을 자동으로 확정해 버려요 (04 7단계).
3. 1·2단계의 `CREATE TABLE`, `INSERT INTO classes`, `ALTER TABLE` 두 개는 **각각 한 번만** 실행해요. 다시 실행하면 "이미 있다"는 오류가 나요 (바꿔 보기에서 일부러 봐요). 오류가 나도 데이터는 그대로예요.
4. 테이블을 만든 뒤 왼쪽 목록에 `classes`가 안 보이면 `school`을 선택하고 새로고침(`F5`)해요.
5. SQL은 한 문장씩 선택해 `Cmd + Enter`로 실행해요. 연습한 SQL은 이 날짜 폴더에 `연습.sql`로 저장해도 돼요.

이 노트의 출력은 터미널 `mysql`에서 얻은 것이에요. DBeaver 결과 영역에도 같은 열 이름과 값이 표로 보이고, 오류는 같은 번호와 영어 문장으로 나와요.

## 1단계: 반 정보는 `classes` 테이블로 나눈다

🧭 02에서 `CREATE TABLE students`로 테이블을 만들었어요. 같은 방법으로 반 테이블을 하나 더 만들어요.

학생 테이블에 반 이름 열을 그대로 넣었다고 해 볼게요. 한코딩, 김자바개발자, 정데이터 세 행에 `풀스택 A반`이 똑같이 세 번 저장돼요. 반 이름을 `풀스택 개발 A반`으로 바꾸려면 세 행을 다 고쳐야 하고, 하나라도 빠뜨리면 같은 반인데 이름이 다른 행이 남아요.

그래서 반 이름은 `classes` 테이블에 **한 번만** 저장하고, 학생에게는 반 번호만 저장해요. 반 이름을 바꿀 때 `classes`의 한 행만 고치면 돼요.

`classes`의 `id`도 `PRIMARY KEY`(기본키)예요. 02에서 배운 대로 겹치지 않고 `NULL`이 안 되는 대표 번호예요. 그런데 이번에는 `AUTO_INCREMENT`를 붙이지 않았어요. **기본키라고 번호가 자동으로 생기지는 않아요.** 그래서 `INSERT`할 때 `id`를 1, 2, 3으로 직접 넣어요. `name`에는 `NOT NULL UNIQUE`를 걸어서 같은 반 이름이 두 번 생기지 않게 했어요.

### ▶ 직접 해 보기 — `classes` 만들고 반 세 개 넣기
```sql
CREATE TABLE classes (
    id INT PRIMARY KEY,
    name VARCHAR(50) NOT NULL UNIQUE
);

INSERT INTO classes (id, name)
VALUES
    (1, '풀스택 A반'),
    (2, '풀스택 B반'),
    (3, '풀스택 C반');

SELECT *
FROM classes
ORDER BY id ASC;
```
```text
Query OK, 0 rows affected (0.00 sec)

Query OK, 3 rows affected (0.00 sec)
Records: 3  Duplicates: 0  Warnings: 0

+----+----------------+
| id | name           |
+----+----------------+
|  1 | 풀스택 A반     |
|  2 | 풀스택 B반     |
|  3 | 풀스택 C반     |
+----+----------------+
3 rows in set (0.00 sec)
```
**바꿔 보기** (모두 오류만 나고 데이터는 그대로예요)
- `INSERT INTO classes (name) VALUES ('풀스택 D반');`처럼 `id`를 빼고 넣기 → `ERROR 1364 (HY000): Field 'id' doesn't have a default value`. `AUTO_INCREMENT`가 없으니 번호를 직접 줘야 해요.
- `CREATE TABLE classes ...`를 한 번 더 실행 → `ERROR 1050 (42S01): Table 'classes' already exists`
- 반 세 개 `INSERT`를 한 번 더 실행 → `ERROR 1062 (23000): Duplicate entry '1' for key 'classes.PRIMARY'`. 첫 행(1번)에서 바로 막혀서 세 행 모두 안 들어가요.

## 2단계: `ALTER TABLE`로 `class_id` 열과 외래키를 더한다

🧭 `students`는 02에서 이미 만들었고 데이터도 있어요. 지우고 새로 만들 수 없으니, 있는 테이블의 구조를 고쳐요.

**`ALTER TABLE`**은 이미 있는 테이블의 구조를 바꾸는 문장이에요. `ADD COLUMN class_id INT`로 반 번호 열을 더하면 기존 다섯 행은 그대로 있고, 새 열의 값은 모두 `NULL`로 채워져요. `NOT NULL`을 안 붙였으니 반이 정해지지 않은 학생은 `NULL`로 둘 수 있어요.

그런데 열 이름을 `class_id`라고 지었다고 DB가 이 열이 반을 가리킨다는 걸 알지는 못해요. 지금 상태라면 999처럼 없는 반 번호도 그냥 들어가요. 그래서 **외래키 제약 조건**을 걸어요. `FOREIGN KEY (class_id) REFERENCES classes (id)`는 "`students.class_id`에는 `classes.id`에 실제로 있는 번호나 `NULL`만 넣을 수 있다"는 규칙이에요. `fk_students_class`는 이 규칙에 붙인 이름이라, 나중에 오류 문장에 이 이름이 나와요.

두 키를 정리하면 이래요. **기본키**(`students.id`, `classes.id`)는 자기 테이블 안에서 행을 구분해요. **외래키**(`students.class_id`)는 다른 테이블의 행을 가리켜요. 반 하나(`classes`의 한 행)에 학생 여러 명(`students`의 여러 행)이 연결되니 **일대다(1:N) 관계**예요. 학생 한 명은 반 하나에만 속해요.

외래키를 걸 때 `5 rows affected`가 나오는데, MySQL이 규칙을 걸면서 기존 다섯 행을 새 구조로 옮겨 담았다는 뜻이에요. 값이 바뀐 건 아니에요. `DESCRIBE`의 `Key` 칸에 `MUL`이 생기는데, 이 열에 같은 값이 여러 번 들어갈 수 있는 색인(검색용 목록)이 생겼다는 표시예요. 외래키 열은 같은 반 번호를 여러 학생이 가지니까 `MUL`이에요.

### ▶ 직접 해 보기 — 열 추가, 외래키 추가
```sql
ALTER TABLE students
ADD COLUMN class_id INT;

SELECT *
FROM students
ORDER BY id ASC;

ALTER TABLE students
ADD CONSTRAINT fk_students_class
FOREIGN KEY (class_id)
REFERENCES classes (id);

DESCRIBE students;
```

## 3단계: 학생을 반에 배정하고, 외래키가 막는 것을 본다

🧭 04에서 배운 `UPDATE ... WHERE email = ...`로 `class_id`를 채워요.

한코딩·김자바개발자·정데이터는 A반(1), 이리액트는 B반(2), 박스프링부트는 미배정(`NULL`)이에요. 강의의 첫 `UPDATE`는 `WHERE`에 이메일 네 개를 `OR`로 이었어요. 한코딩의 이메일이 04를 했으면 `hancoding@...`, 안 했으면 `han@...`이라서 둘 다 넣은 거예요. 04를 마쳤으니 `han@...`에 맞는 행은 없고, 실제로 맞는 건 세 행이에요. `Rows matched: 3`으로 확인돼요.

외래키를 걸었으니 이제 없는 반 번호는 DB가 거부해요. 이리액트를 999번 반에 넣으려 하면 `ERROR 1452`가 나고, 이리액트의 반 번호는 2 그대로예요. 오류 문장의 `a foreign key constraint fails` 뒤에 2단계에서 붙인 이름 `fk_students_class`가 보여요. `child row`(자식 행)는 다른 테이블을 가리키는 쪽, 즉 `students`의 행을 말해요.

### ▶ 직접 해 보기 — 반 배정과 없는 반 번호
```sql
UPDATE students
SET class_id = 1
WHERE email = 'han@example.com'
   OR email = 'hancoding@example.com'
   OR email = 'java@example.com'
   OR email = 'data@example.com';

UPDATE students
SET class_id = 2
WHERE email = 'react@example.com';

UPDATE students
SET class_id = NULL
WHERE email = 'spring@example.com';

SELECT id, name, email, class_id
FROM students
ORDER BY id ASC;
```
```text

Rows matched: 3  Changed: 3  Warnings: 0

Query OK, 1 row affected (0.00 sec)
Rows matched: 1  Changed: 1  Warnings: 0

Query OK, 0 rows affected (0.00 sec)
Rows matched: 1  Changed: 0  Warnings: 0

+----+--------------------+-----------------------+----------+
| id | name               | email                 | class_id |
+----+--------------------+-----------------------+----------+
|  1 | 한코딩             | hancoding@example.com |        1 |
|  2 | 김자바개발자       | java@example.com      |        1 |
|  3 | 이리액트           | react@example.com     |        2 |
|  4 | 박스프링부트       | spring@example.com    |     NULL |
|  6 | 정데이터           | data@example.com      |        1 |

```
박스프링부트는 이미 `NULL`이라 `Changed: 0`이에요. 이제 없는 반 번호를 넣어 봐요.
```sql
UPDATE students
SET class_id = 999
WHERE email = 'react@example.com';

SELECT id, name, email, class_id
FROM students
WHERE email = 'react@example.com';
```
```text

+----+--------------+-------------------+----------+
| id | name         | email             | class_id |
+----+--------------+-------------------+----------+
|  3 | 이리액트     | react@example.com |        2 |
+----+--------------+-------------------+----------+
```
**바꿔 보기**
- 반대 방향도 막혀요. `DELETE FROM classes WHERE id = 2;` → `ERROR 1451 (23000): Cannot delete or update a parent row: a foreign key constraint fails (...)`. B반을 가리키는 학생(이리액트)이 있어서 B반을 지울 수 없어요. `parent row`(부모 행)는 가리킴을 받는 쪽, `classes`의 행이에요.

## 4단계: `INNER JOIN` — 학생 이름과 반 이름을 함께 조회한다

🧭 3단계로 학생에게 반 번호가 생겼어요. 그런데 화면에는 번호보다 "풀스택 A반" 같은 이름이 필요해요. 반 이름은 `classes`에만 있어요.

`FROM students INNER JOIN classes ON students.class_id = classes.id`는 "학생 행마다, `class_id`와 같은 `id`를 가진 반 행을 찾아 옆에 붙여라"라는 뜻이에요. **`ON`**이 붙이는 기준이에요. 학생의 `class_id`가 1이면 `classes`에서 `id`가 1인 행(풀스택 A반)이 붙어요.

두 테이블 모두 `name` 열이 있어서 `students.name`, `classes.name`처럼 **테이블 이름.열 이름**으로 어느 쪽인지 밝혀요. 결과에서도 둘 다 `name`이면 헷갈리니까 `AS student_name`, `AS class_name`으로 결과 열 이름을 붙여요. `AS`는 결과에서만 쓰는 이름이라 실제 테이블의 열 이름은 안 바뀌어요. 테이블에도 `FROM students AS s`처럼 짧은 별칭을 붙일 수 있어요. 별칭을 붙였으면 그 문장 안에서는 `s.name`처럼 별칭으로만 불러요.

**`INNER JOIN`은 짝이 맞는 행만** 돌려줘요. 박스프링부트는 `class_id`가 `NULL`이라 붙일 반이 없어서 결과에 안 나와요. 지워진 게 아니라 이번 조회 조건에 안 맞은 거예요.

### ▶ 직접 해 보기 — 학생과 반 연결하기
```sql
SELECT
    students.name AS student_name,
    classes.name AS class_name
FROM students
INNER JOIN classes
    ON students.class_id = classes.id
ORDER BY students.id ASC;

SELECT
    s.name AS student_name,
    c.name AS class_name
FROM students AS s
INNER JOIN classes AS c
    ON s.class_id = c.id
ORDER BY s.id ASC;
```
두 문장 모두 결과가 같아요.
```text
+--------------------+----------------+
| student_name       | class_name     |
+--------------------+----------------+
| 한코딩             | 풀스택 A반     |
| 김자바개발자       | 풀스택 A반     |
| 이리액트           | 풀스택 B반     |
| 정데이터           | 풀스택 A반     |
+--------------------+----------------+
4 rows in set (0.00 sec)
```
**바꿔 보기** (두 번째 문장으로 해요)
- `ON s.class_id = c.id`를 `ON s.id = c.id`로 → 오류 없이 **틀린 결과**가 나와요. 학생 번호와 반 번호를 연결해 버려서 김자바개발자가 B반, 이리액트가 C반이 돼요. 오류가 안 나서 더 위험해요.
  ```text
  | 한코딩             | 풀스택 A반     |
  | 김자바개발자       | 풀스택 B반     |
  | 이리액트           | 풀스택 C반     |
  3 rows in set (0.00 sec)
  ```
- `s.name AS student_name`을 `name`으로 → `ERROR 1052 (23000): Column 'name' in field list is ambiguous`. 어느 테이블의 `name`인지 모른다는 뜻이에요.
- `s.name`을 `students.name`으로 → `ERROR 1054 (42S22): Unknown column 'students.name' in 'field list'`. 별칭을 붙인 뒤에는 원래 이름으로 부를 수 없어요.
- `AS student_name`, `AS class_name`을 지우기 → 실행은 되지만 결과 열 이름이 둘 다 `name`이에요.
- `ON s.class_id = c.id` 줄을 지우기 → 오류 없이 **15줄**이 나와요. 붙일 기준이 없어서 학생 5명 × 반 3개를 모두 짝지었어요. 행 수가 갑자기 늘면 `ON`부터 봐요.

## 5단계: `LEFT JOIN` — 반이 없는 학생도 남긴다

🧭 4단계에서 박스프링부트가 빠졌어요. 학생 명단 전체에 반 이름을 붙이고 싶을 때는 빠지면 안 돼요.

**`LEFT JOIN`**은 왼쪽 테이블의 행을 **모두** 남겨요. 왼쪽 테이블은 `FROM` 바로 뒤에 쓴 테이블이에요. 오른쪽에 붙일 짝이 없으면 오른쪽 열을 `NULL`로 채워요. 그래서 박스프링부트도 `class_name`이 `NULL`인 채로 나와요.

이걸 이용하면 "반이 없는 학생만" 찾을 수도 있어요. `LEFT JOIN` 결과에서 오른쪽(`c.id`)이 `NULL`인 행만 남기면 돼요. 지금은 외래키 덕분에 `class_id`에 없는 번호가 들어갈 수 없으니, `WHERE class_id IS NULL`로 바로 찾아도 결과가 같아요.

어느 테이블을 `FROM`에 두느냐에 따라 결과가 달라요. `FROM classes LEFT JOIN students`로 바꾸면 이번엔 반이 기준이라, 학생이 없는 C반이 남고 반이 없는 박스프링부트는 빠져요. A반은 학생마다 한 줄씩 세 번 나와요. 반 하나에 학생이 여럿인 일대다 관계라 정상이에요.

### ▶ 직접 해 보기 — 학생 전체와 미배정 학생
```sql
SELECT
    s.name AS student_name,
    c.name AS class_name
FROM students AS s
LEFT JOIN classes AS c
    ON s.class_id = c.id
ORDER BY s.id ASC;

SELECT
    s.id,
    s.name,
    s.email
FROM students AS s
LEFT JOIN classes AS c
    ON s.class_id = c.id
WHERE c.id IS NULL
ORDER BY s.id ASC;
```
```text
+--------------------+----------------+
| student_name       | class_name     |
+--------------------+----------------+
| 한코딩             | 풀스택 A반     |
| 김자바개발자       | 풀스택 A반     |
| 이리액트           | 풀스택 B반     |
| 박스프링부트       | NULL           |
| 정데이터           | 풀스택 A반     |
+--------------------+----------------+
5 rows in set (0.00 sec)

+----+--------------------+--------------------+
| id | name               | email              |
+----+--------------------+--------------------+
|  4 | 박스프링부트       | spring@example.com |
+----+--------------------+--------------------+
1 row in set (0.00 sec)
```
`SELECT id, name, email FROM students WHERE class_id IS NULL ORDER BY id ASC;`도 같은 한 줄이 나와요.

**바꿔 보기** (첫 번째 문장으로 해요)
- `FROM students AS s LEFT JOIN classes AS c`를 `FROM classes AS c LEFT JOIN students AS s`로, `ORDER BY s.id ASC`를 `ORDER BY c.id ASC, s.id ASC`로 → 반이 기준이 돼요.
  ```text
  | 한코딩             | 풀스택 A반     |
  | 김자바개발자       | 풀스택 A반     |
  | 정데이터           | 풀스택 A반     |
  | 이리액트           | 풀스택 B반     |
  | NULL               | 풀스택 C반     |
  5 rows in set (0.00 sec)
  ```
- `ON s.class_id = c.id` 줄을 지우기 → `ERROR 1064 (42000): ... near 'ORDER BY s.id ASC'`. `INNER JOIN`과 달리 `LEFT JOIN`은 `ON`이 없으면 문법 오류예요.

## 6단계: `COUNT(*)`와 `COUNT(열)` — 무엇을 세는지가 다르다

🧭 지금까지는 행을 보여 줬어요. 이번에는 행이 몇 개인지 숫자 하나로 받아요. 반별 학생 수를 세는 7단계의 준비예요.

**`COUNT(*)`**는 결과의 **행 수**를 세요. `WHERE`를 붙이면 조건에 맞는 행만 세요. A반 학생 수는 `WHERE class_id = 1`을 붙여서 3이에요.

**`COUNT(열)`**은 그 열이 **`NULL`이 아닌** 행만 세요. `COUNT(class_id)`는 반이 배정된 학생 수라서 4예요. 박스프링부트의 `class_id`가 `NULL`이라 빠졌어요. 같은 표에서 세어도 무엇을 세느냐에 따라 5와 4로 달라져요. 파이썬으로 치면 `len(students)`와 `len([s for s in students if s["class_id"] is not None])`의 차이예요.

### ▶ 직접 해 보기 — 세 가지로 세기
```sql
SELECT COUNT(*) AS student_count
FROM students;

SELECT COUNT(*) AS student_count
FROM students
WHERE class_id = 1;

SELECT
    COUNT(*) AS total_students,
    COUNT(class_id) AS assigned_students
FROM students;
```
```text
+---------------+
| student_count |
+---------------+
|             5 |
+---------------+

+---------------+
| student_count |
+---------------+
|             3 |
+---------------+

+----------------+-------------------+
| total_students | assigned_students |
+----------------+-------------------+
|              5 |                 4 |
+----------------+-------------------+
```
**바꿔 보기**: `COUNT(class_id)`를 `COUNT(registered_date)`로 → `4`. 등록일이 `NULL`인 박스프링부트가 빠져요. `COUNT(열)`은 어느 열이든 `NULL`을 세지 않아요.

## 7단계: `GROUP BY` — 반별 학생 수

🧭 6단계는 전체를 숫자 하나로 셌어요. 반마다 따로 세려면 같은 반끼리 묶어야 해요.

**`GROUP BY class_id`**는 `class_id`가 같은 행끼리 묶어서, 묶음마다 한 줄씩 결과를 만들어요. `COUNT(*)`는 각 묶음의 행 수를 세요. `NULL`도 하나의 묶음이 돼서 미배정 1명이 따로 나와요. MySQL은 오름차순 정렬에서 `NULL`을 맨 앞에 둬요.

반 이름까지 보려면 4·5단계의 `JOIN`을 섞어요. 학생 없는 C반도 0명으로 보고 싶으니, 반을 기준으로 `FROM classes LEFT JOIN students`를 써요. 그런데 여기서 `COUNT(*)`를 쓰면 C반이 1명으로 나와요. 학생이 없는 C반도 `LEFT JOIN` 결과에서는 학생 쪽이 모두 `NULL`인 **한 행**으로 남아 있고, `COUNT(*)`는 그 행도 세기 때문이에요. 그래서 학생의 기본키 `s.id`를 세요. `COUNT(s.id)`는 `NULL`을 세지 않으니 C반이 0이 돼요. 6단계의 차이가 여기서 쓰여요.

이 결과를 더하면 3 + 1 + 0 = 4라서 전체 5명과 달라요. 반 목록을 기준으로 셌기 때문에, 반이 없는 박스프링부트는 어느 반에도 들어가지 않았어요.

`GROUP BY`를 쓰면 `SELECT`에는 묶은 열(`class_id`)이나 `COUNT` 같은 집계 결과만 쓸 수 있어요. 학생 `name`을 함께 쓰면, 한 묶음에 이름이 여러 개라 어떤 이름을 보여 줄지 정할 수 없어서 MySQL이 거부해요.

### ▶ 직접 해 보기 — 반 번호별, 반 이름별 학생 수
```sql
SELECT
    class_id,
    COUNT(*) AS student_count
FROM students
GROUP BY class_id
ORDER BY class_id ASC;

SELECT
    c.id AS class_id,
    c.name AS class_name,
    COUNT(s.id) AS student_count
FROM classes AS c
LEFT JOIN students AS s
    ON c.id = s.class_id
GROUP BY c.id, c.name
ORDER BY c.id ASC;
```
```text
+----------+---------------+
| class_id | student_count |
+----------+---------------+
|     NULL |             1 |
|        1 |             3 |
|        2 |             1 |
+----------+---------------+
3 rows in set (0.00 sec)

+----------+----------------+---------------+
| class_id | class_name     | student_count |
+----------+----------------+---------------+
|        1 | 풀스택 A반     |             3 |
|        2 | 풀스택 B반     |             1 |
|        3 | 풀스택 C반     |             0 |
+----------+----------------+---------------+
3 rows in set (0.00 sec)
```
**바꿔 보기**
- 두 번째 문장의 `COUNT(s.id)`를 `COUNT(*)`로 → C반이 `1`이 돼요. 학생이 없는데 1명으로 세어져요.
- 두 번째 문장의 `LEFT JOIN`을 `INNER JOIN`으로 → C반 줄이 사라지고 A반(3)·B반(1) 두 줄만 나와요.
- 첫 번째 문장의 `SELECT`에 `name,`을 더하기 → `ERROR 1055 (42000): Expression #2 of SELECT list is not in GROUP BY clause and contains nonaggregated column 'school.students.name' ...`
- 첫 번째 문장에서 `GROUP BY class_id` 줄을 지우기 → `ERROR 1140 (42000): In aggregated query without GROUP BY, expression #1 of SELECT list contains nonaggregated column 'school.students.class_id' ...`. `COUNT`만 있으면 전체가 한 줄로 합쳐지는데, `class_id`는 다섯 개라 하나를 고를 수 없어요.

## 마무리: 05회차를 처음부터 끝까지

1. `CREATE TABLE classes`로 반 테이블을 만들고, 번호를 직접 넣어 반 세 개를 추가해요 (`AUTO_INCREMENT` 없음).
2. `ALTER TABLE students ADD COLUMN class_id INT`로 반 번호 열을 더해요. 기존 다섯 행은 그대로이고 새 열은 `NULL`이에요.
3. `ADD CONSTRAINT fk_students_class FOREIGN KEY (class_id) REFERENCES classes (id)`로 외래키 규칙을 걸어요. 이제 `class_id`에는 있는 반 번호나 `NULL`만 들어가요.
4. `UPDATE`로 A반 3명, B반 1명을 배정하고 박스프링부트는 `NULL`로 둬요. 999번 반은 `ERROR 1452`로 막혀요.
5. `INNER JOIN ... ON s.class_id = c.id`로 짝이 있는 학생 4명과 반 이름을 함께 봐요.
6. `LEFT JOIN`으로 박스프링부트까지 5명을 보고, `WHERE c.id IS NULL`로 미배정 학생만 찾아요.
7. `COUNT(*)`(5)와 `COUNT(class_id)`(4)의 차이를 보고, `GROUP BY`로 반별 학생 수를 세요. 반 이름별로 셀 때는 `classes LEFT JOIN students` + `COUNT(s.id)`로 C반 0명까지 봐요.

여기까지 하면 `students`는 이 상태가 돼요. 06의 Spring API가 이 데이터를 읽어요.

## 다음 회차와 연결

06에서는 지금까지 DBeaver에서 직접 친 SQL을 Spring이 실행해요. MyBatis라는 도구로 Java 메서드와 SQL을 연결하고, 학생 목록·추가·수정·삭제 API를 만들어요. `SELECT`에는 오늘 더한 `class_id`가 들어가고, Java 쪽에서는 `classId`로 받아요. 박스프링부트처럼 반이 없는 학생은 `null`이 와야 해서 Java의 `int`가 아니라 `Integer`를 써요.

외래키도 그대로 동작해요. API로 학생을 수정하면서 `classId`를 999로 보내면, 오늘 본 `ERROR 1452`와 같은 문장이 Spring 서버 로그에 나와요. 06 강의의 API는 반 이름을 붙이지 않고 `classId`만 돌려줘요. 반 이름까지 주고 싶으면 Mapper XML의 `SELECT`에 오늘 배운 `LEFT JOIN`을 쓰면 돼요.

## 오류가 날 때 찾아보기

| 오류 문장 · 증상 | 먼저 볼 곳 |
|---|---|
| `ERROR 1364 ... Field 'id' doesn't have a default value` | `classes.id`는 자동 번호가 아님 → `id`를 직접 넣기 (1단계) |
| `ERROR 1050 ... Table 'classes' already exists` | 이미 만든 테이블. 지우지 말고 `SELECT * FROM classes;`로 확인 (1단계) |
| `ERROR 1062 ... Duplicate entry '1' for key 'classes.PRIMARY'` | 반 `INSERT`를 두 번 실행함 (1단계) |
| `ERROR 1060 ... Duplicate column name 'class_id'` | `ADD COLUMN`을 두 번 실행함, `DESCRIBE students;` (2단계) |
| `ERROR 1826 ... Duplicate foreign key constraint name` | `ADD CONSTRAINT`를 두 번 실행함 (2단계) |
| `ERROR 1824 ... Failed to open the referenced table 'class'` | `REFERENCES` 뒤 테이블 이름 철자 (2단계) |
| `ERROR 1452 ... Cannot add or update a child row: a foreign key constraint fails` | 넣으려는 `class_id`가 `classes.id`에 있는지 (3단계) |
| `ERROR 1451 ... Cannot delete or update a parent row` | 그 반을 가리키는 학생이 있음 (3단계) |
| `ERROR 1052 ... Column 'name' in field list is ambiguous` | 두 테이블에 같은 열 이름 → `s.name`, `c.name` (4단계) |
| `ERROR 1054 ... Unknown column 'students.name'` | 테이블 별칭을 붙였으면 별칭으로 부르기 (4단계) |
| `JOIN` 결과의 반이 이상하게 맞음 | `ON`이 `s.class_id = c.id`인지 (`s.id = c.id`가 아닌지) (4단계) |
| `JOIN` 결과 행 수가 갑자기 많음 (15줄 등) | `ON`이 빠졌는지 (4단계) |
| `LEFT JOIN`에서 `ERROR 1064 ... near 'ORDER BY ...'` | `ON` 줄이 빠졌는지 (5단계) |
| 학생이 결과에서 사라짐 | `INNER JOIN`이라 짝 없는 행이 빠짐 → `LEFT JOIN` (4·5단계) |
| 빈 반이 0이 아니라 1로 나옴 | `COUNT(*)` 대신 `COUNT(s.id)` (7단계) |
| `ERROR 1055 ... not in GROUP BY clause` | `GROUP BY`한 열과 집계만 `SELECT`에 (7단계) |
| `ERROR 1140 ... aggregated query without GROUP BY` | `GROUP BY` 줄이 빠짐 (7단계) |
