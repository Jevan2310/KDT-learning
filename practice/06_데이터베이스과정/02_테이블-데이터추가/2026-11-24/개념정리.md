# 개념 정리 — 데이터베이스과정 02. 테이블 만들고 데이터 추가하기

> 날짜: 2026-11-24 · wiki: [02_테이블-데이터추가](../../../../wiki/06_데이터베이스과정/02_테이블-데이터추가.md)
> 단계별 설명문으로 쓰고, 단계 끝마다 직접 해 보는 예시를 둔다. 쉬운 말, 비유 없이. 이 노트의 SQL(바꿔 보기 포함)을 위에서부터 순서대로 MySQL 8.4.13에 터미널 `mysql`로 실행해서 출력과 오류 문장을 확인했다.

## 들어가며

**🧭 맥락 — 지금 어디쯤**

01에서 MySQL을 켜고 DBeaver로 접속해서 `school` 데이터베이스를 만들었어요. `SHOW TABLES;`를 하면 아직 비어 있었죠. 데이터는 데이터베이스 안의 테이블에 저장돼요. 테이블이 없으면 학생을 넣을 곳이 없어요.

02에서는 `school` 안에 학생을 저장할 `students` 테이블을 만들고, 학생 다섯 명을 넣어요. 이 다섯 명을 03(조회), 04(수정·삭제), 05(반 테이블과 연결), 06(Spring에서 읽기)에서 계속 써요.

Spring 05에서 H2에 학생을 저장할 때는 테이블을 직접 만들지 않았어요. `Student` 클래스에 `@Entity`, `@Id`, `@GeneratedValue(IDENTITY)`를 붙이고 `ddl-auto=update`를 설정하면 JPA가 테이블을 만들어 줬어요. 이번에는 그 일을 SQL로 직접 해요. `@GeneratedValue(IDENTITY)`가 하던 "번호 자동으로 붙이기"가 이번 회차의 `AUTO_INCREMENT`예요. 06에서 MyBatis를 쓸 때는 JPA처럼 테이블을 만들어 주지 않아서, 오늘 만든 테이블을 그대로 써요.

## 🛠 시작하기

1. MySQL이 켜져 있는지 터미널에서 `brew services list`로 봐요. `mysql@8.4`가 `started`가 아니면 `brew services start mysql@8.4`.
2. DBeaver에서 `localhost` 연결을 마우스 오른쪽 → **SQL 편집기 → 새 SQL 스크립트**.
3. 편집기 맨 위에 아래 두 줄을 쓰고, 한 줄씩 선택해서 `Cmd + Enter`. 두 번째 결과가 `school`이면 준비 끝이에요.

```sql
USE school;
SELECT DATABASE();
```
```text
mysql> USE school;
Database changed

mysql> SELECT DATABASE();
+------------+
| DATABASE() |
+------------+
| school     |
+------------+
1 row in set (0.00 sec)
```

이 노트의 SQL은 **위에서부터 순서대로** 실행해요. 아래쪽 SQL은 위에서 만든 테이블과 데이터가 있어야 돌아가요. 이 노트의 출력은 터미널 `mysql`에서 얻은 것이고, DBeaver 결과 영역에도 같은 열과 값이 표로 보여요. `INSERT`처럼 데이터를 바꾸는 문장은 결과 표 대신 몇 행이 바뀌었는지가 나와요.

바꿔 보기의 SQL은 조회만 하거나 실패하는 문장이라 데이터가 늘지 않아요. 바꿔 보기를 끝내도 따로 되돌릴 것은 없어요.

## 1단계: 저장할 항목과 자료형 정하기

테이블을 만들기 전에 먼저 정할 게 있어요. **어떤 항목(열)을 저장할지**, 그리고 **각 항목에 어떤 규칙을 둘지**예요. 이번 학생 테이블은 이렇게 정했어요.

- `id` — 학생 번호. 직접 넣지 않고 자동으로 붙여요.
- `name` — 이름. 꼭 있어야 해요.
- `email` — 이메일. 꼭 있어야 하고, 다른 학생과 겹치면 안 돼요.
- `registered_date` — 등록일. 날짜로 저장하고, 모르면 비워 둘 수 있어요.

열마다 **자료형**(그 열에 넣을 값의 종류)을 정해요. 파이썬은 변수에 아무 값이나 넣을 수 있었지만, SQL 테이블의 열은 Spring 01의 Java 필드처럼 종류가 정해져 있어요. `private int id;`, `private String name;`처럼요. 이번에 쓰는 자료형은 세 가지예요.

`INT`는 정수예요. `1`, `2`, `100` 같은 값이에요. Java의 `int`와 같아요.

`VARCHAR(n)`은 글자(문자열)이고, 괄호 안 숫자는 **최대** 글자 수예요. `VARCHAR(50)`이면 50글자까지 넣을 수 있어요. 50글자를 채워야 한다는 뜻이 아니에요. `한코딩` 세 글자도 그대로 들어가요. 이메일은 이름보다 길 수 있어서 `VARCHAR(100)`으로 넉넉하게 잡아요.

`DATE`는 날짜예요. 연·월·일만 저장하고 시각은 저장하지 않아요. SQL에서 날짜는 `'2026-11-16'`처럼 **작은따옴표로 감싸서** 써요. 문자열도 작은따옴표예요. 숫자만 따옴표 없이 써요.

숫자로만 된 값이라고 무조건 `INT`를 쓰지는 않아요. 전화번호 `010-1234-5678`은 맨 앞 `0`과 `-`를 그대로 지켜야 하고, 더하거나 뺄 일도 없어요. 이런 값은 `VARCHAR`로 저장해요.

### ▶ 직접 해 보기 — 따옴표가 있을 때와 없을 때
테이블 없이 값만 조회해서, MySQL이 같은 글자를 따옴표 유무에 따라 어떻게 읽는지 봐요.
```sql
SELECT '010', 010;
SELECT '010-1234-5678', 010-1234-5678;
```
```text
mysql> SELECT '010', 010;
+-----+-----+
| 010 | 010 |
+-----+-----+
| 010 |  10 |
+-----+-----+
1 row in set (0.00 sec)

mysql> SELECT '010-1234-5678', 010-1234-5678;
+---------------+---------------+
| 010-1234-5678 | 010-1234-5678 |
+---------------+---------------+
| 010-1234-5678 |         -6902 |
+---------------+---------------+
1 row in set (0.00 sec)
```
따옴표가 있으면 글자 그대로 `010`이에요. 따옴표가 없으면 숫자로 읽어서 앞의 `0`이 사라지고 `10`이 돼요. 두 번째는 `-`를 빼기로 읽어서 `10 - 1234 - 5678`을 계산했어요. 전화번호를 숫자로 저장하면 안 되는 이유예요.

**바꿔 보기**: 날짜도 해 봐요. `SELECT '2026-11-16', 2026-11-16;` → 따옴표 없는 쪽은 `2026 - 11 - 16`을 계산해서 `1999`가 나와요. 날짜를 따옴표 없이 쓰면 이렇게 숫자 계산이 돼요 (4단계에서 실제로 넣어 봐요).
```text
+------------+------------+
| 2026-11-16 | 2026-11-16 |
+------------+------------+
| 2026-11-16 |       1999 |
+------------+------------+
```

## 2단계: 규칙 붙여서 테이블 만들기 — 제약 조건과 `CREATE TABLE`

자료형만으로는 막을 수 없는 실수가 있어요. 이름이 비어 있는 학생, 이메일이 같은 학생 두 명 같은 거예요. 그래서 열에 **제약 조건**(그 열의 데이터가 지켜야 할 규칙)을 붙여요. 규칙을 어기는 데이터가 들어오면 MySQL이 오류를 내고 저장하지 않아요.

**`PRIMARY KEY`(기본키)** — 행 하나하나를 구분하는 기준이 되는 열이에요. 이름으로 학생을 구분하면, 이름이 같은 다른 학생이 생겼을 때 둘을 구분할 수 없어요. 그래서 학생마다 겹치지 않는 번호 `id`를 두고 기본키로 정해요. 기본키 열은 값이 **겹칠 수 없고**, **비어 있을 수도 없어요**.

**`AUTO_INCREMENT`** — 새 행을 넣을 때 번호를 MySQL이 자동으로 1, 2, 3… 붙여 줘요. 그래서 학생을 넣을 때 `id`는 적지 않아요. 이 번호는 행을 구분하려는 것이라, 중간 번호가 빠질 수 있어요 (6단계에서 실제로 빠져요). 학생 수나 출석번호로 쓰면 안 돼요.

**`NOT NULL`** — 이 열에는 `NULL`을 넣을 수 없어요. `NULL`은 "값이 없음, 아직 모름"이라는 뜻의 특별한 값이에요. 파이썬의 `None`, Java의 `null`과 비슷해요. 주의할 점은 `NOT NULL`이 빈 글자 `''`나 공백 `'   '`은 막지 않는다는 거예요. 이것들은 `NULL`이 아니라 길이가 0이거나 공백인 글자예요. 그래서 실제 서비스에서는 Spring 04에서 `trim()`과 `isEmpty()`로 한 것처럼 서버 코드에서도 따로 검사해요.

**`UNIQUE`** — 이 열에는 이미 저장된 값과 같은 값을 넣을 수 없어요. 이메일에 붙여요.

이 규칙들을 열 이름과 자료형 뒤에 이어서 써요. 순서는 `열 이름 자료형 규칙`이에요. `CREATE TABLE students ( … );`의 괄호 안에 열을 한 줄씩 쓰고, 열과 열 사이에는 **쉼표**를 넣어요. **마지막 열 뒤에는 쉼표를 넣지 않아요.** 파이썬 리스트는 마지막 쉼표를 허용했지만 SQL은 오류가 나요.

### ▶ 직접 해 보기 — `students` 테이블 만들기
여섯 줄을 한꺼번에 선택하고 `Cmd + Enter`.
```sql
CREATE TABLE students (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) NOT NULL UNIQUE,
    registered_date DATE
);
```
```text
Query OK, 0 rows affected (0.00 sec)
```
테이블만 만들어서 바뀐 행은 0개예요. DBeaver 왼쪽 목록의 `school`을 선택하고 새로고침(`F5`)하면 `Tables` 아래에 `students`가 생겨요.

**바꿔 보기**: 테이블이 이미 있어도, 문법 오류는 그보다 먼저 검사해서 아래 오류가 나와요. 모두 실패라서 되돌릴 것은 없어요.
- 마지막 열 `registered_date DATE` 뒤에 `,` 붙이기 → 닫는 괄호 `)` 앞에서 다음 열을 기다렸다는 뜻이에요.
  ```text
  ERROR 1064 (42000): You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near ')' at line 6
  ```
- `id INT AUTO_INCREMENT PRIMARY KEY` 뒤의 `,` 지우기 → `near` 뒤가 쉼표가 빠진 다음 줄(`name …`)부터예요.
  ```text
  ERROR 1064 (42000): ... for the right syntax to use near 'name VARCHAR(50) NOT NULL,
      email VARCHAR(100) NOT NULL UNIQUE,
      registere' at line 3
  ```
- `VARCHAR(50)`을 `VARCHAR`로(길이 빼기) → MySQL의 `VARCHAR`는 최대 길이를 꼭 적어야 해요.
  ```text
  ERROR 1064 (42000): ... for the right syntax to use near 'NOT NULL,
      email VARCHAR(100) NOT NULL UNIQUE,
      registered_date DATE
  )' at line 3
  ```
- 원래 `CREATE TABLE`을 그대로 한 번 더 → 같은 이름의 테이블이 이미 있어요. 이럴 때 테이블을 지우지 말고 3단계의 `DESCRIBE`로 지금 구조를 먼저 봐요.
  ```text
  ERROR 1050 (42S01): Table 'students' already exists
  ```

## 3단계: 만든 테이블 확인하기 — `SHOW TABLES`, `DESCRIBE`

테이블을 만들었으면 정말 생겼는지, 열과 규칙이 생각한 대로 들어갔는지 확인해요. SQL은 실행해 놓고 결과를 확인하는 습관이 중요해요. 철자 하나만 틀려도 다른 이름의 테이블이나 열이 생길 수 있어요.

`SHOW TABLES;`는 지금 데이터베이스의 테이블 목록이에요. `DESCRIBE students;`는 `students`의 구조를 보여 줘요. 결과의 열은 이런 뜻이에요. `Field`는 열 이름, `Type`은 자료형, `Null`은 `NULL`을 넣을 수 있는지(`NO`면 `NOT NULL`), `Key`는 `PRI`(기본키)·`UNI`(UNIQUE), `Default`는 값을 안 넣었을 때 쓸 기본값, `Extra`는 `auto_increment` 같은 추가 설정이에요.

### ▶ 직접 해 보기
```sql
SHOW TABLES;
DESCRIBE students;
```
```text
mysql> SHOW TABLES;
+------------------+
| Tables_in_school |
+------------------+
| students         |
+------------------+
1 row in set (0.00 sec)

mysql> DESCRIBE students;
+-----------------+--------------+------+-----+---------+----------------+
| Field           | Type         | Null | Key | Default | Extra          |
+-----------------+--------------+------+-----+---------+----------------+
| id              | int          | NO   | PRI | NULL    | auto_increment |
| name            | varchar(50)  | NO   |     | NULL    |                |
| email           | varchar(100) | NO   | UNI | NULL    |                |
| registered_date | date         | YES  |     | NULL    |                |
+-----------------+--------------+------+-----+---------+----------------+
4 rows in set (0.00 sec)
```
1단계에서 정한 규칙과 하나씩 맞춰 봐요. `id`는 `PRI`와 `auto_increment`, `name`·`email`은 `Null`이 `NO`, `email`만 `UNI`, `registered_date`만 `Null`이 `YES`예요. 키워드를 대문자로 썼어도 `Type`은 소문자(`int`, `varchar(50)`)로 보여요. 같은 뜻이에요.

**바꿔 보기**: `DESCRIBE student;`(끝의 `s` 빼기) → 그런 테이블이 없어요. 오류 문장에 `school.student`처럼 데이터베이스 이름이 같이 나와서, 어느 데이터베이스에서 찾았는지도 알 수 있어요.
```text
ERROR 1146 (42S02): Table 'school.student' doesn't exist
```

## 4단계: 학생 한 명 넣기 — `INSERT INTO`

테이블은 구조일 뿐이라 만들었다고 데이터가 생기지 않아요. 행을 넣는 SQL이 `INSERT INTO`예요.

```sql
INSERT INTO students (name, email, registered_date)
VALUES ('한코딩', 'han@example.com', '2026-11-16');
```

`INSERT INTO students`는 "`students` 테이블에 넣어 줘", 괄호 안 `(name, email, registered_date)`는 "값을 넣을 열은 이 세 개야", `VALUES (…)`는 "넣을 값은 이거야"예요. 열 목록과 값은 **순서대로 짝이 맞아요**. 첫 번째 값 `'한코딩'`이 첫 번째 열 `name`에, 두 번째 값이 `email`에, 세 번째 값이 `registered_date`에 들어가요. 그래서 개수와 순서가 맞아야 해요. `id`는 `AUTO_INCREMENT`라 열 목록에서 빼요. 빼면 MySQL이 번호를 붙여요.

넣은 다음에는 `SELECT`로 확인해요. `SELECT * FROM students;`는 "`students`의 모든 열(`*`)을 보여 줘"예요. 일부 열만 보고 싶으면 `*` 대신 열 이름을 쉼표로 적어요. 조회는 03에서 자세히 해요.

### ▶ 직접 해 보기
```sql
INSERT INTO students (name, email, registered_date)
VALUES ('한코딩', 'han@example.com', '2026-11-16');

SELECT * FROM students;
SELECT name FROM students;
SELECT email FROM students;
SELECT name, email FROM students;
```
```text
mysql> INSERT INTO students (name, email, registered_date)
    -> VALUES ('한코딩', 'han@example.com', '2026-11-16');
Query OK, 1 row affected (0.00 sec)

mysql> SELECT * FROM students;
+----+-----------+-----------------+-----------------+
| id | name      | email           | registered_date |
+----+-----------+-----------------+-----------------+
|  1 | 한코딩    | han@example.com | 2026-11-16      |
+----+-----------+-----------------+-----------------+
1 row in set (0.00 sec)

mysql> SELECT name, email FROM students;
+-----------+-----------------+
| name      | email           |
+-----------+-----------------+
| 한코딩    | han@example.com |
+-----------+-----------------+
1 row in set (0.01 sec)
```
`1 row affected`는 행 1개가 추가됐다는 뜻이에요. `id`는 넣지 않았는데 `1`이 붙어 있어요. `SELECT name FROM students;`와 `SELECT email FROM students;`는 그 열 하나만 보여 줘요 (`한코딩`, `han@example.com`).

**바꿔 보기**: 모두 실패해서 저장되지 않아요. 마지막에 `SELECT * FROM students;`를 다시 하면 한코딩 한 명 그대로예요.
- 값 하나 빼기 `VALUES ('최노드', 'node@example.com')` → 열은 3개인데 값이 2개예요.
  ```text
  ERROR 1136 (21S01): Column count doesn't match value count at row 1
  ```
- 이름의 따옴표 빼기 `VALUES (최노드, 'node@example.com', '2026-11-19')` → 따옴표가 없으면 MySQL은 글자를 **열 이름**으로 읽어요. 그런 열이 없다는 오류예요.
  ```text
  ERROR 1054 (42S22): Unknown column '최노드' in 'field list'
  ```
- 값 순서 바꾸기 `VALUES ('최노드', '2026-11-19', 'node@example.com')` → 이메일 자리의 값이 `registered_date`에 들어가려다 막혔어요. 순서가 짝을 정해요.
  ```text
  ERROR 1292 (22007): Incorrect date value: 'node@example.com' for column 'registered_date' at row 1
  ```
- 날짜의 따옴표 빼기 `VALUES ('최노드', 'node@example.com', 2026-11-19)` → 1단계처럼 `2026 - 11 - 19 = 1996`을 계산해서 넣으려 했어요.
  ```text
  ERROR 1292 (22007): Incorrect date value: '1996' for column 'registered_date' at row 1
  ```
- 이름을 51글자로 `VALUES ('최노드최노드최노드최노드최노드최노드최노드최노드최노드최노드최노드최노드최노드최노드최노드최노드최노드', 'node@example.com', '2026-11-19')` → `VARCHAR(50)`보다 길어요. 50글자까지는 들어가요.
  ```text
  ERROR 1406 (22001): Data too long for column 'name' at row 1
  ```

## 5단계: 여러 명 한 번에 넣기, 값이 없을 때는 `NULL`

학생을 여러 명 넣을 때 `INSERT`를 여러 번 쓸 수도 있지만, `VALUES` 뒤에 괄호 묶음을 **쉼표로 이어서** 한 번에 넣을 수도 있어요. 묶음 하나가 행 하나예요.

같은 `INSERT`를 실수로 두 번 실행하면 두 번째는 이메일이 겹쳐서 실패해요 (6단계의 `Duplicate entry`). 그러니 실행하기 전에 이미 실행한 문장인지 확인해요.

등록일을 모르는 학생도 있어요. `registered_date`에는 `NOT NULL`을 붙이지 않았으니 `NULL`을 넣을 수 있어요. 이때 `NULL`에는 **따옴표를 붙이지 않아요.** `'NULL'`이라고 쓰면 N·U·L·L 네 글자로 된 문자열이 돼요. `''`는 길이가 0인 빈 문자열이에요. 세 가지는 모두 다른 값이에요. 값이 아예 없는 것(`NULL`)과 빈 글자(`''`)를 구분해야, 03에서 "등록일이 없는 학생"을 정확히 찾을 수 있어요.

### ▶ 직접 해 보기
```sql
INSERT INTO students (name, email, registered_date)
VALUES
    ('김자바', 'java@example.com', '2026-11-17'),
    ('이리액트', 'react@example.com', '2026-11-18');

SELECT * FROM students;

INSERT INTO students (name, email, registered_date)
VALUES ('박스프링', 'spring@example.com', NULL);

SELECT * FROM students;
```
```text
mysql> INSERT INTO students (name, email, registered_date)
    -> VALUES
    ->     ('김자바', 'java@example.com', '2026-11-17'),
    ->     ('이리액트', 'react@example.com', '2026-11-18');
Query OK, 2 rows affected (0.00 sec)
Records: 2  Duplicates: 0  Warnings: 0

mysql> INSERT INTO students (name, email, registered_date)
    -> VALUES ('박스프링', 'spring@example.com', NULL);
Query OK, 1 row affected (0.01 sec)

mysql> SELECT * FROM students;
+----+--------------+--------------------+-----------------+
| id | name         | email              | registered_date |
+----+--------------+--------------------+-----------------+
|  1 | 한코딩       | han@example.com    | 2026-11-16      |
|  2 | 김자바       | java@example.com   | 2026-11-17      |
|  3 | 이리액트     | react@example.com  | 2026-11-18      |
|  4 | 박스프링     | spring@example.com | NULL            |
+----+--------------+--------------------+-----------------+
4 rows in set (0.01 sec)
```
첫 번째 `SELECT`에서는 3명, 두 번째에서는 4명이 보여요. 박스프링의 등록일은 `NULL`로 보여요. DBeaver 결과 영역에서는 `NULL`이 `[NULL]`처럼 글자와 구분되게 보일 수 있어요.

세 값이 정말 다른지 MySQL에 물어봐요. `IS NULL`은 "값이 없는가"를 묻는 조건이에요 (03 8단계에서 자세히). `1`은 참, `0`은 거짓이에요.
```sql
SELECT NULL IS NULL, 'NULL' IS NULL, '' IS NULL;
```
```text
+--------------+----------------+------------+
| NULL IS NULL | 'NULL' IS NULL | '' IS NULL |
+--------------+----------------+------------+
|            1 |              0 |          0 |
+--------------+----------------+------------+
```
`NULL`만 "값 없음"이고, `'NULL'`과 `''`는 값이 있는 글자예요.

**바꿔 보기**: 모두 실패해서 저장되지 않아요.
- 열 목록에서 `name` 빼기 `INSERT INTO students (email, registered_date) VALUES ('node@example.com', '2026-11-19');` → 이름은 `NOT NULL`인데 넣지도 않았고, 기본값도 없어요.
  ```text
  ERROR 1364 (HY000): Field 'name' doesn't have a default value
  ```
- 없는 날짜 `'2026-11-31'` → 11월은 30일까지라서 날짜로 받아 주지 않아요.
  ```text
  ERROR 1292 (22007): Incorrect date value: '2026-11-31' for column 'registered_date' at row 1
  ```

## 6단계: 규칙이 잘못된 데이터를 막는지 확인하기

2단계에서 붙인 규칙이 실제로 일하는지 일부러 어겨 봐요. 이 과정에서 오류 문장을 읽는 법도 익혀요. 오류 문장에는 어느 값이, 어느 열의 어떤 규칙에 걸렸는지 나와요.

첫째, 이미 있는 이메일 `han@example.com`으로 다른 학생을 넣어요. `email`이 `UNIQUE`라서 `Duplicate entry`(중복 값) 오류가 나요. 이름을 바꿔도 해결되지 않아요. 겹치면 안 되는 건 이메일이니까요.

둘째, 이름에 `NULL`을 넣어요. `name`이 `NOT NULL`이라서 `cannot be null` 오류가 나요. 5단계 바꿔 보기의 `1364`는 이름 열을 아예 빼먹은 경우이고, 이번 `1048`은 열은 적었지만 값으로 `NULL`을 준 경우예요.

오류가 난 `INSERT`는 아무것도 저장하지 않아요. 그런데 번호는 다를 수 있어요. 중복 오류는 MySQL이 번호를 붙인 다음 중복을 발견해서, 그 번호를 써 버리고 돌려놓지 않아요. 그래서 다음 학생은 5가 아니라 6을 받아요. 이 노트에서 확인해 보니 `1048`·`1364`·`1292` 같은 다른 오류는 번호를 쓰지 않았어요. 어쨌든 번호가 건너뛰어도 오류가 아니에요. 2단계에서 말했듯 번호는 행을 구분할 뿐이에요.

### ▶ 직접 해 보기 — 하나씩 선택해서 실행
```sql
-- ① 같은 이메일 추가 → 오류
INSERT INTO students (name, email, registered_date)
VALUES ('최노드', 'han@example.com', '2026-11-19');

-- ② 이름에 NULL → 오류
INSERT INTO students (name, email, registered_date)
VALUES (NULL, 'noname@example.com', '2026-11-19');

-- ③ 저장 안 됐는지 확인 → 4명 그대로
SELECT * FROM students;

-- ④ 다섯 번째 학생 추가
INSERT INTO students (name, email, registered_date)
VALUES ('정데이터', 'data@example.com', '2026-11-20');

SELECT * FROM students;
```
```text
mysql> INSERT INTO students (name, email, registered_date)
    -> VALUES ('최노드', 'han@example.com', '2026-11-19');
ERROR 1062 (23000): Duplicate entry 'han@example.com' for key 'students.email'

mysql> INSERT INTO students (name, email, registered_date)
    -> VALUES (NULL, 'noname@example.com', '2026-11-19');
ERROR 1048 (23000): Column 'name' cannot be null

mysql> SELECT * FROM students;
(결과 표 생략 — 5단계 마지막 결과와 같은 4명, 4 rows in set)

mysql> INSERT INTO students (name, email, registered_date)
    -> VALUES ('정데이터', 'data@example.com', '2026-11-20');
Query OK, 1 row affected (0.01 sec)

mysql> SELECT * FROM students;
+----+--------------+--------------------+-----------------+
| id | name         | email              | registered_date |
+----+--------------+--------------------+-----------------+
|  1 | 한코딩       | han@example.com    | 2026-11-16      |
|  2 | 김자바       | java@example.com   | 2026-11-17      |
|  3 | 이리액트     | react@example.com  | 2026-11-18      |
|  4 | 박스프링     | spring@example.com | NULL            |
|  6 | 정데이터     | data@example.com   | 2026-11-20      |
+----+--------------+--------------------+-----------------+
5 rows in set (0.00 sec)
```
`1062` 오류의 `for key 'students.email'`은 `students` 테이블 `email` 열의 UNIQUE 규칙에 걸렸다는 뜻이에요. 정데이터의 번호가 `6`인 건 ①의 중복 오류가 `5`를 써 버렸기 때문이에요. 같은 `INSERT`를 여러 번 실행했거나 바꿔 보기를 더 했다면 번호가 이것과 다를 수 있어요. 03의 번호 조건 결과도 그만큼 달라져요.

**바꿔 보기**: 정데이터까지 넣은 다음에 해요. 둘 다 실패라서 학생은 5명 그대로예요.
- 기본키 번호를 직접 넣어 겹치게 `INSERT INTO students (id, name, email, registered_date) VALUES (1, '최노드', 'node@example.com', '2026-11-19');` → `id`도 열 목록에 적으면 직접 넣을 수 있는데, 이미 있는 `1`이라 기본키 규칙에 걸려요. 이번에는 `for key 'students.PRIMARY'`예요.
  ```text
  ERROR 1062 (23000): Duplicate entry '1' for key 'students.PRIMARY'
  ```
- 이메일을 대문자로만 바꿔서 `VALUES ('최노드', 'HAN@example.com', '2026-11-19')` → 이것도 중복이에요. 이 데이터베이스의 기본 설정은 글자를 비교할 때 대문자와 소문자를 같게 봐요. 이 오류도 번호를 하나 써요.
  ```text
  ERROR 1062 (23000): Duplicate entry 'HAN@example.com' for key 'students.email'
  ```

## 마무리: 처음부터 끝까지 실행 순서

1. `USE school;`로 이 편집기에서 쓸 데이터베이스를 고르고, `SELECT DATABASE();`로 확인해요.
2. `CREATE TABLE students (…)`를 실행하면 MySQL이 `school` 안에 열 4개짜리 빈 테이블을 만들어요. 열마다 자료형과 규칙(기본키, 자동 번호, NOT NULL, UNIQUE)이 같이 저장돼요.
3. `SHOW TABLES;`, `DESCRIBE students;`로 테이블과 규칙이 생각대로 들어갔는지 봐요.
4. `INSERT INTO students (name, email, registered_date) VALUES (…)`를 실행하면, MySQL이 값을 열 순서대로 짝지어 규칙을 검사하고, 통과하면 `id`에 다음 번호를 붙여 행을 저장해요. 한코딩이 1번이에요.
5. 여러 묶음을 한 번에 넣으면 김자바 2번, 이리액트 3번, 등록일 `NULL`인 박스프링 4번이 들어가요.
6. 이메일 중복 `INSERT`는 UNIQUE 검사에서 막히고(번호 5는 쓰임), 이름 `NULL`은 NOT NULL 검사에서 막혀요. 둘 다 저장되지 않아요.
7. 정데이터가 6번으로 들어가서 학생이 다섯 명이 돼요.

마지막으로, 01 1단계의 파이썬 리스트와 다른 점을 확인해요. 터미널에서 `brew services restart mysql@8.4`로 MySQL을 껐다 켜고, DBeaver에서 다시 `USE school;` → `SELECT * FROM students;`를 실행해요. 다섯 명이 그대로 있어요. DBeaver가 연결이 끊겼다고 하면 다시 연결(`Invalidate/Reconnect`)한 뒤 실행해요.
