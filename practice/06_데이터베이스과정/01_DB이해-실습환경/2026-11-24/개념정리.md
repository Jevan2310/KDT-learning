## 🛠 시작하기 — MySQL 켜기, root 비밀번호, DBeaver 연결

강의는 Windows 기준이에요. 이 Mac에는 MySQL 8.4.13이 이미 Homebrew로 설치되어 있어서 설치 과정이 다르고 더 짧아요.

| 강의 (Windows) | 이 Mac (Homebrew) |
|---|---|
| MSI 설치 파일 받아서 설치 | `brew install mysql@8.4`로 이미 설치됨 |
| MySQL Configurator에서 포트 `3306` | 따로 정하지 않아도 `3306` |
| Configurator에서 `root` 비밀번호 정하기 | 비밀번호 없이 설치됨 → 아래 3)에서 직접 정해요 |
| Windows 서비스 `MySQL84`, 자동 시작 | `brew services start mysql@8.4` |

wiki의 macOS 보충에 나오는 DMG 설치 파일은 받지 않아요. 두 번째 MySQL을 설치하면 둘이 같은 3306 포트를 쓰려고 해서 하나가 켜지지 않아요. 시스템 설정의 MySQL 항목도 DMG로 설치했을 때만 생겨요.

**1) MySQL 서버 켜기** — 터미널에서 쳐요.

```bash
brew services start mysql@8.4
brew services list
```

`brew services start`는 MySQL을 지금 켜고, 앞으로 Mac에 로그인할 때마다 자동으로 켜요. Windows 서비스의 "자동 시작"과 같은 일이에요. `brew services list`에서 `mysql@8.4` 줄의 Status가 `started`면 켜진 거예요. 수업 날에만 켜고 싶으면 `start` 대신 `brew services run mysql@8.4`를 써요. 지금만 켜지고 자동 시작은 하지 않아요. 끌 때는 `brew services stop mysql@8.4`예요.

**2) 터미널에서 접속해 보기** — 켜고 몇 초 뒤에 쳐요.

```bash
mysql --version
mysql -uroot
```
```text
mysql  Ver 8.4.13 for macos26.6 on arm64 (Homebrew)
Welcome to the MySQL monitor.  Commands end with ; or \g.
Your MySQL connection id is 9
Server version: 8.4.13 Homebrew
(저작권 안내 몇 줄)
Type 'help;' or '\h' for help. Type '\c' to clear the current input statement.

mysql>
```

`mysql`은 MySQL 서버에 접속하는 터미널 프로그램이에요. `-uroot`는 "root 계정으로"라는 뜻이에요. 프롬프트가 `mysql>`로 바뀌면 SQL을 칠 수 있어요. 나갈 때는 `exit`를 치면 `Bye`가 나와요.

`mysql@8.4`는 Homebrew에서 keg-only(자동으로 PATH에 넣지 않는 패키지)예요. 이 Mac은 지금 `/opt/homebrew/bin/mysql`로 연결되어 있어서 `mysql`만 쳐도 돼요. `command not found: mysql`이 나오면 `/opt/homebrew/opt/mysql@8.4/bin/mysql -uroot`처럼 전체 경로로 쳐요.

**3) root 비밀번호 정하기** — `mysql>` 프롬프트에서 쳐요. 따옴표 안을 내가 정한 비밀번호로 바꿔요.

```sql
ALTER USER 'root'@'localhost' IDENTIFIED BY '여기에-내가-정한-비밀번호';
```
```text
Query OK, 0 rows affected (0.00 sec)
```

`root`는 MySQL의 관리자 계정이에요. Mac 로그인 계정과 상관없는 MySQL만의 계정이에요. 비밀번호는 기억해 두되 이 노트나 `KDT학습` 폴더의 어떤 파일에도 적지 않아요. 이 폴더는 공개 GitHub 저장소예요. 06에서 Spring이 접속할 때도 비밀번호는 환경변수 `DB_PASSWORD`에만 넣어요.

비밀번호를 정한 뒤에는 `exit`로 나가고, 앞으로는 `-p`를 붙여서 접속해요. `Enter password:`가 나오면 비밀번호를 쳐요 (화면에 글자가 안 보이는 게 정상이에요).

```bash
mysql -uroot -p
```

**4) DBeaver 설치·연결**

1. 터미널에서 `brew install --cask dbeaver-community`로 설치해요. 또는 https://dbeaver.io/download/ 에서 macOS용 Community Edition을 받아요.
2. DBeaver를 처음 열 때 "인터넷에서 다운로드한 앱" 확인 창이 나오면 열기를 눌러요. 샘플 데이터베이스를 만들지 묻는 창이 나오면 건너뛰어요.
3. 상단 메뉴 **데이터베이스 → 새 데이터베이스 연결**(Database → New Database Connection) → **MySQL** → 다음.
4. Host `localhost`, Port `3306`, Database는 비워 두고, Username `root`, Password는 3)에서 정한 비밀번호를 넣어요.
5. **연결 테스트**(Test Connection)를 눌러요. 처음이면 드라이버(DBeaver가 MySQL과 통신할 때 쓰는 라이브러리)를 내려받을지 물어요. 다운로드를 누르면 돼요. 연결 성공 메시지가 나오면 확인 → 완료.
6. 왼쪽 목록에 `localhost` 연결이 생겨요.

**5) DBeaver에서 SQL 실행하는 법** — 이 과정 내내 이렇게 해요.

왼쪽의 `localhost` 연결을 마우스 오른쪽으로 누르고 **SQL 편집기 → 새 SQL 스크립트**를 열어요. 편집기에 SQL을 여러 줄 써 두고, **실행할 문장 하나를 선택한 뒤 `Cmd + Enter`**를 눌러요. 결과는 아래 결과 영역에 표로 나와요. 02부터는 편집기 맨 위에 `USE school;`을 두고 그것부터 실행해요 (7단계).

이 노트의 출력은 터미널 `mysql`에서 얻은 것이에요. DBeaver 결과 영역에도 같은 열 이름과 값이 표로 나와요. 오류는 DBeaver에서도 같은 오류 번호(예: `1049`)와 같은 영어 문장으로 나와요.

## 1단계: 변수·배열에 담은 데이터는 프로그램이 끝나면 사라진다

Node 02의 콘솔 학생 관리 프로그램을 떠올려 봐요. 학생을 추가하면 배열에 들어가고 목록에도 보였어요. 그런데 프로그램을 끄고 다시 켜면 코드에 처음 적어 둔 학생만 남아 있었어요.

이유는 배열이 **실행 중인 프로그램의 메모리**에 있기 때문이에요. 메모리는 프로그램이 실행되는 동안만 쓰는 공간이에요. 프로그램이 끝나면 그 공간이 비워지고, 다시 실행하면 코드 첫 줄부터 새로 시작해요. 그래서 배열도 코드에 적힌 처음 모습으로 다시 만들어져요.

실제 서비스는 이러면 안 돼요. 서버를 다시 켜도 회원 정보와 글이 남아 있어야 해요. 그래서 데이터를 프로그램 밖에 따로 저장해요. 파일에 저장할 수도 있지만, 데이터베이스 프로그램은 저장 말고도 해 주는 일이 많아요. 조건에 맞는 데이터 찾기, 여러 사람이 동시에 쓰기, "이메일은 겹치면 안 된다" 같은 규칙 지키기, 여러 변경을 한 번에 처리하거나 한 번에 취소하기(트랜잭션, 04에서 배워요)까지 해 줘요.

### ▶ 직접 해 보기 — `memory_test.py`
파이썬으로 같은 일을 확인해요. 아무 폴더에 `memory_test.py`를 만들고 터미널에서 두 번 실행해요.
```python
students = [
    {"id": 1, "name": "한코딩"},
    {"id": 2, "name": "김자바"},
]
print("시작할 때:", len(students), "명")

students.append({"id": 3, "name": "이리액트"})
print("추가한 뒤:", len(students), "명")
```
```bash
python3 memory_test.py
python3 memory_test.py
```
```text
시작할 때: 2 명
추가한 뒤: 3 명
시작할 때: 2 명
추가한 뒤: 3 명
```
첫 번째 실행에서 이리액트를 추가해 3명이 됐지만, 두 번째 실행은 다시 2명에서 시작해요. 첫 번째 실행에서 추가한 학생은 어디에도 남지 않았어요. 02의 마지막에서 MySQL을 껐다 켜도 학생이 남아 있는 걸 확인해요.

## 2단계: 데이터베이스·DBMS·SQL

세 낱말을 구분해야 해요.

**데이터베이스**(DB)는 체계적으로 모아서 관리하는 데이터 묶음이에요. 이번 수업에서는 학생과 반 정보를 담을 `school`이 데이터베이스예요.

**DBMS**(DataBase Management System)는 데이터베이스를 만들고 관리하는 프로그램이에요. 이번 수업에서는 **MySQL**이에요. Spring 05의 H2도 DBMS였어요. 차이는 H2는 Spring 서버 안에서 같이 실행됐고, MySQL은 혼자 따로 실행되는 **서버 프로그램**이라는 점이에요. 그래서 🛠 1)에서 MySQL을 먼저 켰어요. Spring 서버처럼 켜 두면 계속 요청을 기다려요.

**SQL**은 DBMS에 "이 데이터를 저장해 줘", "이 조건에 맞는 학생을 찾아 줘" 같은 작업을 요청할 때 쓰는 언어예요. 정리하면 이래요. "MySQL에 SQL로 명령을 보내서, `school` 데이터베이스의 데이터를 다룬다."

SQL과 MySQL은 같은 게 아니에요. SQL은 언어이고, MySQL은 그 언어를 받아서 실행하는 프로그램이에요. Oracle이나 PostgreSQL 같은 다른 DBMS도 SQL을 쓰지만, 일부 문법은 DBMS마다 달라요. 파이썬 코드를 파이썬 인터프리터가 실행하듯, SQL 문장은 DBMS가 실행해요.

### ▶ 직접 해 보기 — 서버가 켜져 있어야 SQL을 보낼 수 있다
터미널에서 접속해서 첫 SQL을 보내요.
```bash
mysql -uroot -p
```
```sql
SELECT VERSION();
```
```text
mysql> SELECT VERSION();
+-----------+
| VERSION() |
+-----------+
| 8.4.13    |
+-----------+
1 row in set (0.00 sec)
```
`SELECT VERSION();`은 "MySQL 버전을 알려 줘"라는 SQL이에요. MySQL이 받아서 처리하고, 결과를 표로 돌려줬어요.

**바꿔 보기**: `exit`로 나간 뒤 `brew services stop mysql@8.4`로 MySQL을 끄고, 다시 `mysql -uroot -p`로 접속해요. 비밀번호가 맞아도 이렇게 나와요. 접속할 서버가 없기 때문이에요.
```text
ERROR 2002 (HY000): Can't connect to local MySQL server through socket '/tmp/mysql.sock' (2)
```
`brew services start mysql@8.4`로 다시 켜고, 몇 초 뒤에 접속하면 돼요.

## 3단계: 테이블·행·열

MySQL은 **관계형** DBMS예요. 데이터를 **테이블**이라는 표 모양으로 저장한다는 뜻이에요. 테이블은 같은 종류의 데이터를 모아 두는 곳이에요. 학생은 `students` 테이블에, 반은 `classes` 테이블에 따로 저장해요.

테이블에서 세로 한 줄을 **열**(column)이라고 해요. 열은 "무엇을 저장할지", 즉 항목이에요. 학생 테이블이라면 `id`(번호), `name`(이름), `email`(이메일)이 열이에요. 열마다 숫자만 넣을지, 글자를 넣을지, 날짜를 넣을지 정해요 (02에서 해요).

가로 한 줄은 **행**(row)이에요. 행은 실제로 저장된 데이터 한 건이에요. `1 | 한코딩 | han@example.com` 한 줄이 학생 한 명이에요. 파이썬으로 보면 테이블은 딕셔너리 여러 개를 담은 리스트와 비슷한 모양이에요. 열 이름이 키, 행 하나가 딕셔너리 하나예요. 다른 점은 테이블은 모든 행이 같은 열을 가져야 하고, 열마다 넣을 수 있는 값의 종류가 정해져 있다는 거예요.

데이터베이스 하나에는 테이블을 여러 개 만들 수 있어요. 이 과정이 끝나면 이런 모양이 돼요.

```text
MySQL
└─ school 데이터베이스
   ├─ students 테이블   (02에서 만들어요)
   └─ classes 테이블    (05에서 만들어요)
```

### ▶ 직접 해 보기 — 결과도 행과 열로 나온다
아직 테이블이 없으니, SQL로 값 세 개를 바로 만들어서 결과 모양만 봐요. `AS`는 결과 열에 이름을 붙이는 말이에요 (여기서만 써요).
```sql
SELECT 1 AS id, '한코딩' AS name, 'han@example.com' AS email;
```
```text
mysql> SELECT 1 AS id, '한코딩' AS name, 'han@example.com' AS email;
+----+-----------+-----------------+
| id | name      | email           |
+----+-----------+-----------------+
|  1 | 한코딩    | han@example.com |
+----+-----------+-----------------+
1 row in set (0.00 sec)
```
맨 위 `id | name | email`이 열 이름이고, 그 아래 한 줄이 행이에요. `1 row in set`은 "행 1개"라는 뜻이에요. DBeaver 결과 영역에도 열 이름 줄과 행 한 줄이 표로 보여요. 02부터 `students` 테이블을 조회하면 이 모양에 행이 여러 개 붙어서 나와요.

## 4단계: MySQL과 DBeaver는 다른 프로그램이다

🛠에서 두 프로그램을 따로 준비했어요. 둘이 하는 일이 달라서예요.

MySQL은 데이터를 저장하고 SQL을 처리하는 **서버**예요. 화면이 없고, 켜져 있는 동안 접속해 오는 프로그램의 요청을 기다려요. DBeaver는 MySQL에 접속해서 SQL을 보내고, 돌아온 결과를 표로 보여 주는 **도구**예요. 터미널의 `mysql` 프로그램도 하는 일은 DBeaver와 같아요. 화면이 글자뿐이라는 점만 달라요.

```text
DBeaver ──→ MySQL ←── Spring (06에서)
              ↑
       터미널 mysql
```

그래서 두 가지를 기억해요. DBeaver만 설치하면 MySQL은 설치되지 않아요. 접속할 서버가 없으니 연결 테스트가 실패해요. 반대로 DBeaver를 꺼도 MySQL은 계속 켜져 있어서, 터미널이나 Spring은 그대로 접속할 수 있어요. 데이터는 DBeaver가 아니라 MySQL에 저장돼요.

### ▶ 직접 해 보기 — 두 프로그램이 같은 서버에 접속한다
DBeaver SQL 편집기와 터미널 `mysql>`에서 같은 SQL을 실행해요.
```sql
SELECT VERSION(), CURRENT_USER();
```
```text
mysql> SELECT VERSION(), CURRENT_USER();
+-----------+----------------+
| VERSION() | CURRENT_USER() |
+-----------+----------------+
| 8.4.13    | root@localhost |
+-----------+----------------+
1 row in set (0.00 sec)
```
`CURRENT_USER()`는 지금 어느 계정으로 접속했는지 알려 줘요. DBeaver 결과 영역에도 `8.4.13`과 `root@localhost`가 보여요. 같은 서버에 같은 계정으로 접속했기 때문이에요.

**바꿔 보기**: DBeaver를 완전히 끄고(`Cmd + Q`) 터미널에서 `SELECT VERSION();`을 다시 실행해요. 그대로 결과가 나와요. MySQL 서버는 DBeaver와 상관없이 켜져 있어요.

## 5단계: 접속 정보 — 호스트·포트·사용자·비밀번호

DBeaver 연결 창에 넣은 값 네 개가 각각 무엇인지 봐요. 06에서 Spring 설정 파일에도 같은 값을 넣어요.

**Host**(호스트)는 "어느 컴퓨터에 있는 MySQL인가"예요. `localhost`는 지금 쓰고 있는 내 컴퓨터를 뜻해요. 숫자 주소로는 `127.0.0.1`이에요. 이 Mac의 MySQL은 설정 파일(`/opt/homebrew/etc/my.cnf`)에 `bind-address = 127.0.0.1`이 있어서, 다른 컴퓨터에서는 접속할 수 없고 이 Mac에서만 접속돼요.

**Port**(포트)는 "그 컴퓨터의 어느 프로그램인가"를 고르는 번호예요. 한 컴퓨터에서 서버 프로그램이 여러 개 동시에 켜져 있을 수 있어서, 번호로 구분해요. 앞에서 Vite 개발 서버는 `5173`, Spring 서버는 `8080`을 썼어요. MySQL의 기본 포트는 `3306`이에요.

**Username·Password**는 "누구의 권한으로 접속하는가"예요. MySQL이 직접 관리하는 계정이에요. 지금은 관리자 계정 `root`를 쓰지만, 실제 서비스에서는 필요한 권한만 준 계정을 따로 만들어 써요.

연결 창의 **Database**는 처음 연결할 때 고를 데이터베이스예요. 아직 `school`이 없으니 비워 뒀어요.

### ▶ 직접 해 보기 — 접속 정보를 하나씩 적어서 접속하기
터미널 `mysql`도 접속 정보를 옵션으로 받아요. `-h`는 Host, `-P`(대문자)는 Port, `-u`는 Username, `-p`(소문자)는 "비밀번호를 물어봐 줘"예요.
```bash
mysql -h 127.0.0.1 -P 3306 -u root -p
```
```sql
SELECT @@port, CURRENT_USER();
```
```text
mysql> SELECT @@port, CURRENT_USER();
+--------+----------------+
| @@port | CURRENT_USER() |
+--------+----------------+
|   3306 | root@localhost |
+--------+----------------+
1 row in set (0.00 sec)
```
`@@port`는 MySQL이 어느 포트에서 기다리고 있는지 알려 줘요.

**바꿔 보기**: `exit`로 나간 뒤 접속 명령을 하나씩 바꿔서 쳐 봐요. 오류 번호가 달라서 무엇이 틀렸는지 구분할 수 있어요.
- 포트를 아무것도 없는 `-P 3399`로 → 그 포트에는 MySQL이 없어서 연결 자체가 안 돼요.
  ```text
  ERROR 2003 (HY000): Can't connect to MySQL server on '127.0.0.1:3399' (61)
  ```
- `-p`를 빼고 `mysql -u root` → 서버는 찾았지만 비밀번호 없이 들어오려 해서 거절돼요.
  ```text
  ERROR 1045 (28000): Access denied for user 'root'@'localhost' (using password: NO)
  ```
- `-p`로 접속하면서 비밀번호를 일부러 틀리게 → 같은 1045인데 끝이 `(using password: YES)`예요. 비밀번호를 보냈는데 틀렸다는 뜻이에요.
  ```text
  ERROR 1045 (28000): Access denied for user 'root'@'localhost' (using password: YES)
  ```

정리하면 `2002`·`2003`은 서버에 닿지 못한 것(서버 꺼짐, 포트 틀림)이고, `1045`는 서버에는 닿았지만 계정 확인에서 막힌 거예요. DBeaver 연결 테스트가 실패할 때도 메시지에서 이 차이를 보면 어디를 고칠지 알 수 있어요.

## 6단계: SQL 작성 기본 규칙

SQL을 쓰기 전에 몇 가지 약속을 알아 둬요.

문장 끝에는 세미콜론 `;`을 붙여요. MySQL은 `;`를 보고 "문장이 여기서 끝났다"고 판단해요. 그래서 한 문장을 여러 줄에 나눠 써도 돼요. 터미널 `mysql`은 `;` 없이 Enter를 치면 문장이 안 끝났다고 보고 `->` 프롬프트로 다음 줄을 기다려요.

SQL 키워드(`SELECT`, `CREATE` 등)는 대문자와 소문자를 구분하지 않아요. `select version();`도 실행돼요. 수업에서는 읽기 쉽게 **키워드는 대문자**, 데이터베이스·테이블·열 이름은 **소문자**로 써요.

`--`로 시작하는 줄은 **주석**이에요. 실행할 명령이 아니라 사람이 읽는 설명이에요. 파이썬의 `#`과 같아요. 단, MySQL에서는 `--` 뒤에 **공백이 한 칸 있어야** 주석으로 봐요. `--MySQL`처럼 붙이면 주석이 아니라 SQL의 일부로 읽어서 오류가 나요.

DBeaver 편집기에 문장이 여러 개 있으면, **실행할 문장을 선택하고** `Cmd + Enter`를 눌러요. 그러면 그 문장 하나만 MySQL로 가요.

### ▶ 직접 해 보기 — 주석과 문장 여러 개
DBeaver 편집기에 붙여 넣고, `SELECT` 문장을 하나씩 선택해서 `Cmd + Enter`로 실행해요.
```sql
-- MySQL 버전 확인
SELECT VERSION();

-- 버전과 현재 계정 확인
SELECT VERSION(), CURRENT_USER();
```
첫 문장은 2단계의 `8.4.13` 한 칸, 두 번째 문장은 4단계의 두 칸 결과가 나와요. 주석 줄은 결과에 아무 영향이 없어요.

**바꿔 보기**: 이번에는 터미널 `mysql>`에서 쳐요.
- 소문자로 `select version();` → 오류 없이 실행되고, 열 이름만 `version()`으로 친 그대로 나와요.
- 키워드 오타 `SELEC VERSION();` → 문법 오류예요. `near` 뒤에 MySQL이 이해하지 못한 부분부터 보여 줘요.
  ```text
  ERROR 1064 (42000): You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near 'SELEC VERSION()' at line 1
  ```
- 주석의 공백 빼기: `--MySQL 버전 확인`을 치고 Enter, 이어서 `SELECT VERSION();` → 주석으로 안 보고 두 줄을 한 문장으로 읽었어요.
  ```text
  mysql> --MySQL 버전 확인
      -> SELECT VERSION();
  ERROR 1064 (42000): You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near '--MySQL 버전 확인
  SELECT VERSION()' at line 1
  ```
- `;` 빼기: `SELECT VERSION()`만 치고 Enter → `->`가 나오며 기다려요. `;`만 치고 Enter를 누르면 실행돼요.
  ```text
  mysql> SELECT VERSION()
      -> ;
  +-----------+
  | VERSION() |
  +-----------+
  | 8.4.13    |
  +-----------+
  1 row in set (0.00 sec)
  ```

## 7단계: `school` 데이터베이스 만들기 — `CREATE DATABASE`와 `USE`

이제 수업에서 계속 쓸 데이터베이스를 만들어요.

`CREATE DATABASE`는 데이터베이스를 새로 만드는 SQL이에요. 뒤에 `IF NOT EXISTS`를 붙이면 "같은 이름이 없을 때만 만들어"라는 뜻이 돼요. 이미 있으면 아무것도 하지 않고 경고만 남겨요. 그래서 실수로 다시 실행해도 기존 `school`이 지워지거나 비워지지 않아요. `CHARACTER SET utf8mb4`는 한글과 이모지까지 저장할 수 있는 문자 방식을 쓰겠다는 뜻이에요. 학생 이름이 한글이라 꼭 필요해요.

데이터베이스는 MySQL 안에 여러 개 있을 수 있어요. 그래서 SQL을 보내기 전에 "지금부터 어느 데이터베이스에서 일할지" 골라야 해요. 그게 `USE school;`이에요. 고른 상태는 **지금 이 연결에만** 적용돼요. 터미널에서 `exit`로 나갔다가 다시 들어오면 아무것도 안 고른 상태로 돌아가요. DBeaver도 편집기마다 따로 연결할 수 있어서, 새 편집기를 열면 다시 확인해야 해요. 지금 무엇이 골라져 있는지는 `SELECT DATABASE();`로 봐요.

`SHOW DATABASES;`는 데이터베이스 목록을, `SHOW TABLES;`는 지금 고른 데이터베이스의 테이블 목록을 보여 줘요. 방금 만든 `school`에는 테이블이 없으니 `SHOW TABLES;` 결과가 비어 있어요. 오류가 아니에요.

### ▶ 직접 해 보기 — 강의 SQL을 순서대로
DBeaver 편집기에 붙여 넣고 한 문장씩 선택해서 실행해요. `CREATE DATABASE`는 두 줄이 한 문장이라 두 줄을 같이 선택해요.
```sql
-- 연결 확인
SELECT VERSION(), CURRENT_USER();

-- ① 데이터베이스 생성
CREATE DATABASE IF NOT EXISTS school
CHARACTER SET utf8mb4;

-- ② 생성 결과 확인
SHOW DATABASES;

-- ③ 사용할 데이터베이스 선택
USE school;

-- ④ 선택된 데이터베이스 확인 → school
SELECT DATABASE();

-- ⑤ 현재 테이블 확인 → 아직 비어 있음
SHOW TABLES;
```
```text
mysql> CREATE DATABASE IF NOT EXISTS school
    -> CHARACTER SET utf8mb4;
Query OK, 1 row affected (0.00 sec)

mysql> SHOW DATABASES;
+--------------------+
| Database           |
+--------------------+
| information_schema |
| mysql              |
| performance_schema |
| school             |
| sys                |
+--------------------+
5 rows in set (0.00 sec)

mysql> USE school;
Database changed

mysql> SELECT DATABASE();
+------------+
| DATABASE() |
+------------+
| school     |
+------------+
1 row in set (0.00 sec)

mysql> SHOW TABLES;
Empty set (0.00 sec)
```
`school` 말고 네 개는 MySQL이 스스로 쓰는 기본 데이터베이스예요. 고치거나 지우지 않아요. DBeaver 왼쪽 목록에 `school`이 안 보이면 연결을 선택하고 새로고침(`F5`)해요. DBeaver 버전에 따라 `Databases`나 `Schemas` 아래에 보여요.

**바꿔 보기**: 터미널 `mysql>`에서 하나씩 해 봐요.
- `CREATE DATABASE IF NOT EXISTS school CHARACTER SET utf8mb4;`를 한 번 더 → 오류 없이 경고 1개만 남아요. `SHOW WARNINGS;`로 경고를 보면 이미 있어서 안 만들었다고 해요.
  ```text
  Query OK, 1 row affected, 1 warning (0.00 sec)

  mysql> SHOW WARNINGS;
  +-------+------+-------------------------------------------------+
  | Level | Code | Message                                         |
  +-------+------+-------------------------------------------------+
  | Note  | 1007 | Can't create database 'school'; database exists |
  +-------+------+-------------------------------------------------+
  ```
- `IF NOT EXISTS`를 빼고 `CREATE DATABASE school CHARACTER SET utf8mb4;` → 이번에는 오류예요.
  ```text
  ERROR 1007 (HY000): Can't create database 'school'; database exists
  ```
- 오타 `USE shool;` → 없는 데이터베이스예요. 이때 `SELECT DATABASE();`를 해 보면 `school`이 그대로 골라져 있어요. 실패한 `USE`는 아무것도 바꾸지 않아요.
  ```text
  ERROR 1049 (42000): Unknown database 'shool'
  ```
- `exit`로 나갔다가 `mysql -uroot -p`로 다시 들어와서 `SELECT DATABASE();` → `NULL`(아무것도 안 고름)이에요. 이 상태에서 `SHOW TABLES;`를 하면 오류가 나요. `USE school;`을 하면 해결돼요. 처음부터 `mysql -uroot -p school`로 들어오면 `school`이 골라진 채로 시작해요.
  ```text
  mysql> SELECT DATABASE();
  +------------+
  | DATABASE() |
  +------------+
  | NULL       |
  +------------+
  1 row in set (0.00 sec)

  mysql> SHOW TABLES;
  ERROR 1046 (3D000): No database selected
  ```
- `exit` → `brew services restart mysql@8.4`로 MySQL을 껐다 켜고, 다시 접속해 `SHOW DATABASES;` → `school`이 그대로 있어요. 1단계의 파이썬 리스트와 다르게, MySQL에 만든 것은 서버를 다시 켜도 남아요.

## 마무리: 처음부터 끝까지 실행 순서

1. `brew services start mysql@8.4`로 MySQL 서버를 켜요. 서버는 3306 포트에서 접속을 기다려요.
2. 터미널 `mysql -uroot`로 접속해서 `ALTER USER`로 root 비밀번호를 정해요. 그다음부터는 `mysql -uroot -p`로 접속해요.
3. DBeaver에서 `localhost`·`3306`·`root`·비밀번호로 새 연결을 만들고, 연결 테스트에서 드라이버를 내려받아요.
4. SQL 편집기를 열고 `SELECT VERSION(), CURRENT_USER();`를 선택해 `Cmd + Enter`. DBeaver가 이 SQL을 MySQL로 보내고, MySQL이 `8.4.13`, `root@localhost`를 돌려주면 결과 영역에 표로 보여요.
5. `CREATE DATABASE IF NOT EXISTS school CHARACTER SET utf8mb4;`로 MySQL 안에 `school`을 만들어요.
6. `SHOW DATABASES;`로 목록에 `school`이 생겼는지 봐요.
7. `USE school;`로 이 연결에서 쓸 데이터베이스를 고르고, `SELECT DATABASE();`가 `school`인지 확인해요.
8. `SHOW TABLES;`는 아직 비어 있어요. 테이블은 02에서 만들어요.

다음 수업 날에는 1(서버가 켜져 있는지 `brew services list`로 확인) → DBeaver 연결 → `USE school;`부터 시작하면 돼요.

## 오류가 날 때 찾아보기

설치·접속 오류(서버, 포트, 계정)와 SQL 문법 오류는 따로 봐요. 재설치하기 전에 오류 문장과 접속 정보부터 확인해요.

| 오류 문장 · 증상 | 먼저 볼 곳 |
|---|---|
| `ERROR 2002 (HY000): Can't connect to local MySQL server through socket '/tmp/mysql.sock'` | MySQL이 꺼져 있음 → `brew services list`, `brew services start mysql@8.4` (🛠, 2단계) |
| `ERROR 2003 (HY000): Can't connect to MySQL server on '127.0.0.1:…'` · DBeaver `Connection refused` | 서버가 켜져 있는지, 포트 번호가 `3306`인지 (5단계) |
| `ERROR 1045 (28000): Access denied for user 'root'@'localhost' (using password: NO)` | `-p`를 빼먹음, DBeaver Password 칸이 비어 있음 (🛠 3), 5단계) |
| `... (using password: YES)` | 비밀번호가 틀림 (5단계) |
| DBeaver 연결 테스트에서 `Public Key Retrieval is not allowed` | 연결 편집 → Driver properties(드라이버 속성)에서 `allowPublicKeyRetrieval`을 `true`로 (🛠 4)) |
| `command not found: mysql` | 전체 경로 `/opt/homebrew/opt/mysql@8.4/bin/mysql`로 (🛠 2)) |
| `ERROR 1064 (42000): You have an error in your SQL syntax ... near '…'` | `near` 뒤의 첫 단어 철자, 주석 `-- ` 뒤 공백 (6단계) |
| 터미널에 `->`만 나오고 실행이 안 됨 | 문장 끝 `;` (6단계) |
| `ERROR 1007 (HY000): Can't create database 'school'; database exists` | 이미 만들었음, `IF NOT EXISTS` (7단계) |
| `ERROR 1049 (42000): Unknown database '…'` | 데이터베이스 이름 철자, 만들었는지 `SHOW DATABASES;` (7단계) |
| `ERROR 1046 (3D000): No database selected` | 이 연결에서 `USE school;`을 실행했는지 (7단계) |
| 만든 `school`이 DBeaver 왼쪽 목록에 안 보임 | 연결 새로고침(`F5`), 실제로 실행한 연결이 맞는지 (7단계) |
